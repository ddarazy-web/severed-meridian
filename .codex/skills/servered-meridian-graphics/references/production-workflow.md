# 그래픽 제작 워크플로

실제 파일 생성, Aseprite 작업, Unity 반입 또는 품질 검수 때 이 문서를 읽는다. 미술 기준과 크기는 [그래픽 결정 기록](graphics-decisions.md)을 최종 기준으로 삼는다.

## 1. 작업 분류

요청을 시작할 때 결과 상태를 하나로 분류한다.

- **콘셉트**: 방향 비교, 구도·재료·붓질 탐색, 사용자 승인 전 샘플
- **프로덕션 원본**: 승인된 방향을 논리 크기와 팔레트에 맞춘 편집 가능 파일
- **Unity 출력**: 프로덕션 원본에서 내보낸 런타임용 PNG와 메타데이터
- **검수**: 기존 에셋의 미술·기술·빌드 안전성 확인

사용자가 샘플, 시안 또는 참고용이라고 말하면 콘셉트로 처리한다. 생성형 이미지가 보기 좋다는 이유만으로 프로덕션 상태로 올리지 않는다.

## 2. 기획 맥락 확인

1. `rg`로 대상 캐릭터, 지역, 아이템, 무공 또는 UI 기능을 기획 문서에서 찾는다.
2. 직접 전투, 유닛 카드, 전투 중 아이템 사용처럼 현재 기획과 다른 전제를 만들지 않는다.
3. 이름, 단계, 품질, 무기 요구 조건과 정보 우선순위가 정해져 있으면 아트 브리프에 반영한다.
4. 정보가 없고 결과가 여러 에셋에 반복될 결정이라면 권장안 하나와 이유를 제시해 확인받는다.

## 3. 콘셉트 제작

- 저장 위치: `ArtSource/Concepts/<분류>/`
- 이름 예: `chr_protagonist_concept_01.png`, `ui_combat_material_concept_02.png`
- 같은 폴더의 README 또는 동반 명세에 목적, 승인 상태, 유지할 요소, 수정할 요소와 빌드 제외를 기록한다.
- 이미지 생성은 필요한 매체에 맞는 도구를 사용한다. 픽셀 콘셉트라도 최종 논리 그리드, 팔레트와 프레임 정확성을 생성형 출력에 기대하지 않는다.
- 생성 이미지의 가짜 문자, 수치, 아이콘 배열과 인물 배치는 사용자가 별도로 승인하지 않는 한 디자인 요구사항이 아니다.

## 4. 픽셀 프로덕션

### 공통

- 편집 원본: `ArtSource/Production/<분류>/`
- Unity 출력: `Assets/Art/Production/<분류>/`
- 확정 팔레트: `ArtSource/Concepts/Palettes/servered-meridian-master-32.gpl`
- 캐릭터·타일·아이콘은 안티앨리어싱 없이 작업한다.
- 64px 해상도는 디테일 목표가 아니다. 실제 크기에서 실루엣이 읽힌 뒤에만 필요한 재질 단서를 추가한다.

### Aseprite

현재 확인된 Steam판 실행 파일은 다음 표준 위치에 있다.

`C:\Program Files (x86)\Steam\steamapps\common\Aseprite\Aseprite.exe`

- 경로가 없으면 다른 설치 위치를 찾거나 사용자에게 확인한다. 저장소 파일에 개인 절대 경로를 런타임 의존성으로 기록하지 않는다.
- 자동화는 `--batch --noinapp`을 사용한다.
- 원본 `.aseprite`에는 팔레트, 레이어, 프레임, 태그, 슬라이스와 피벗을 보존한다.
- 내보내기 전에 대상 PNG와 JSON 경로가 정확한지 확인한다. Aseprite의 시트 출력은 기존 파일을 덮어쓸 수 있으므로 사용자 소유 출력과 충돌하면 새 경로를 선택한다.
- 캐릭터 태그는 `<action>_<direction>` 형식을 사용하고 방향은 `down`, `left`, `right`, `up` 순서를 유지한다.
- 캐릭터 원본은 128×128 셀 안에 64×96 몸체를 발밑 중앙 피벗으로 배치한다.
- 액션별 Unity 시트와 JSON 메타데이터를 내보내되, 프로젝트의 실제 소비 방식이 정해지기 전에는 새 임포터나 Addressables 정책을 도입하지 않는다.

## 5. 비도트 프로덕션

- 승인된 1단계 고정 주인공 유청운은 256×256px RGBA 프레임, 실제 알파, 발밑 중앙 피벗과 부드러운 축소 필터를 사용한다.
- 기준 이미지는 `ArtSource/Concepts/Characters/chr_protagonist_male_stage_01_walk_down_concept_01.png`이며 Unity에 직접 참조하지 않고 프로덕션 프레임 제작 기준으로만 사용한다.
- 전체 방향과 프레임에서 머리와 몸체 크기, 발 기준선, 붓선 굵기, 바구니·장부집·약초칼의 물리적 위치를 고정한다.
- 무공 카드 삽화는 512×512 투명 PNG 먹그림 레이어로 출력한다.
- 따뜻한 종이 질감은 카드 프레임 또는 바탕 레이어가 담당한다. 삽화 PNG에 종이, 문자, 수치와 등급색을 굽지 않는다.
- UI는 반복 바탕, 9-slice 프레임, 모서리 장식, 인장과 상태별 요소를 분리한다.
- UI 텍스트는 현지화 데이터와 언어별 폰트가 담당하며 이미지 생성 결과의 글자를 사용하지 않는다.

## 6. 파일명

영문 소문자 `snake_case`와 안정된 데이터 ID를 사용한다.

- 캐릭터: `chr_<id>_<action>_<direction>.png`
- 타일: `tile_<region-or-common>_<material>.png`
- 소품: `prop_<region-or-common>_<id>.png`
- 아이콘: `icon_<category>_<id>.png`
- UI: `ui_<component>_<state>.png`
- 이펙트: `fx_<family>_<action-or-status>.png`
- 카드 삽화: `cardart_<card-id>.png`
- 초상: `portrait_<character-id>_<expression>.png`

콘셉트에만 `concept_01` 같은 후보 번호를 붙인다. 프로덕션은 안정된 이름을 유지하고 Git 이력으로 버전을 추적한다.

## 7. 검수

### 픽셀

- 1배 실제 크기와 2배 최근접 확대를 모두 확인한다.
- 마스터 팔레트 밖의 RGB 색과 부분 투명 픽셀을 검사한다. 그림자와 이펙트는 허용된 예외다.
- 실루엣만 보아도 계열과 기능이 구분되는지 확인한다.
- 캐릭터 네 방향, 태그별 프레임 수, 피벗과 루프 이음새를 확인한다.
- 타일은 반복 무늬, 바깥·안쪽 모서리, 좁은 통로와 인접 타일 이음새를 실제 Tilemap에서 확인한다.

### UI와 카드

- 16:9 핵심 영역, 와이드 화면과 정사각형에 가까운 폴더블 비율에서 앵커와 Safe Area를 확인한다.
- 9-slice 모서리, 반복 종이 질감과 분리 장식이 늘어나며 찌그러지지 않는지 확인한다.
- 손패 카드가 겹친 상태에서도 비용, 이름과 계열·기능 아이콘이 상단에서 읽히는지 확인한다.
- 한국어 긴 문자열과 향후 다른 언어를 고려해 텍스트가 이미지에 굽혀 있지 않은지 확인한다.
- 색을 제거해도 품질, 상태와 선택 여부를 형태로 구분할 수 있는지 확인한다.

### 빌드 경계

- `ArtSource/Concepts`와 `ArtSource/Production`이 Unity `Assets` 밖에 있는지 확인한다.
- Scene, Prefab, ScriptableObject, Resources, StreamingAssets와 Addressables가 콘셉트 파일을 참조하지 않는지 확인한다.
- Unity 출력의 `.meta`와 GUID를 보존하고 관련 소비처를 확인한다.

## 8. 동반 제작 명세

이미지 또는 시트와 함께 다음을 기록한다.

- ID와 표시 용도
- 콘셉트, 프로덕션 원본 또는 Unity 출력 상태
- 논리 크기, 프레임 셀과 원본 크기
- 팔레트와 허용 강조색
- 시점, 피벗, 충돌 또는 9-slice 경계
- 방향, 태그, 프레임 수와 fps
- 품질·상태·언어별 변형 규칙
- 원본과 출력 저장 위치
- Unity 반입 가능 여부
- 수행한 검수와 남은 수동 확인
