# Servered Meridian 그래픽 결정 기록

이 문서는 그래픽 리소스 인터뷰에서 합의한 현재 기준을 기록한다. 최종 스킬을 작성할 때 이 문서를 사실 원천으로 사용한다. 이후 합의가 바뀌면 최신 합의로 이 문서를 갱신한다.

## 1. 작품과 시대 방향

- 본 게임 전용 그래픽 기준이다.
- 시대적 배경은 명나라 중기다.
- 무협의 표현 범위는 현실에 기반한 고무협이다. 내공, 검기, 경공은 허용하지만 자유 비행, 불로불사, 대규모 마법과 과도한 선협 표현은 피한다.
- 복식과 생활상은 명 중기 고증 약 70%, 무협적 과장 약 30%를 기준으로 한다.
- 명 중기 실루엣을 바탕으로 문파별 색, 소매, 허리 장식과 무기 비례를 과장할 수 있다.
- 청나라 변발, 일본식 갑주, 시대와 무관한 판타지 갑옷, 과도한 선협 장신구와 발광 마법 장비는 사용하지 않는다.

## 2. 전체 미술 방향

- 전체 스타일은 아기자기한 SD 픽셀 아트에 동양 채색화의 색감과 재료감을 결합한다.
- 캐릭터, 맵, 아이콘과 UI가 동일한 색·먹선·종이·여백의 언어를 공유해야 한다.
- 픽셀 리소스는 공유 마스터 팔레트 약 32색을 기반으로 한다.
- 지역과 세력에는 마스터 팔레트 안에서 최대 8개의 강조색을 추가로 배정할 수 있다.
- 개별 에셋은 보통 8~16색, 한 재질은 2~3단계 명암을 사용한다.
- 광원은 좌상단을 기본으로 한다.
- 외곽선은 완전한 검정 대신 짙은 먹색의 선택적 1픽셀 선을 쓴다. 모든 외곽을 닫지 않고 겹침이나 배경에 묻히는 부분을 중심으로 강조한다.
- 접지 그림자는 본체와 분리한다.

## 3. 콘셉트와 프로덕션 분리

- 생성 이미지와 콘셉트 참고 자료는 `ArtSource/Concepts/` 아래에 저장한다.
- `ArtSource/Concepts/`는 Unity의 `Assets` 밖에 두며 빌드에 포함하지 않는다.
- 확정된 콘셉트도 자동으로 런타임 에셋이 되지 않는다.
- 프로덕션 에셋은 논리 해상도, 픽셀 그리드와 팔레트를 사람이 정리한 뒤에만 `Assets/Art/Production/` 아래에 둔다.
- 프로덕션 분류의 기본 폴더는 `Characters`, `Tilemaps`, `Props`, `UI`, `Effects`다.
- 콘셉트 이미지는 Scene, Prefab, ScriptableObject, Resources, StreamingAssets 또는 Addressables에서 참조하지 않는다.
- 새 리소스 계열은 `콘셉트 시안 → 사용자 확정 → 논리 해상도 도트 정리 → Unity 반입` 순서를 따른다.
- 256px 생성 이미지를 축소해 그대로 프로덕션 픽셀 아트로 사용하지 않는다. 정확한 정수 배율 블록으로 설계된 경우에만 최근접 보간 축소를 허용한다.

## 4. 탐색 캐릭터

- 탐색은 실시간 2D 약한 3/4 시점 탑다운이다.
- 캐릭터 한 프레임의 논리 크기는 32×48px다.
- 비례는 약 2.5등신이다.
- 얼굴은 눈썹, 눈, 수염 등 식별에 필요한 특징만 남긴다.
- 신분과 문파는 미세한 자수보다 모자, 소매, 허리띠, 무기 실루엣과 큰 색면으로 구분한다.
- Spine은 사용하지 않고 스프라이트 애니메이션을 사용한다.
- 네 방향은 좌우 반전으로 대체하지 않고 각각 제작한다.
- 시트의 행 순서는 `하 → 좌 → 우 → 상`, 열은 시간에 따른 프레임 순서다.
- 액션별로 스프라이트 시트를 분리한다.
- 기본 프레임 수는 다음과 같다.
  - 대기: 방향당 2프레임
  - 걷기: 방향당 6프레임
  - 손 채집: 방향당 4프레임
  - 도구 동작: 방향당 4프레임
- 도끼, 곡괭이 등 도구는 교체 가능한 오버레이로 분리한다.
- 탐색 필드용 전투 액션은 제작하지 않는다.
- 기본 재생 속도는 대기 4fps, 걷기 8fps, 채집과 도구 동작 10fps다.
- 월드 이동은 부드럽게 처리할 수 있지만 렌더링은 픽셀 그리드에 맞춰 흔들림을 방지한다.

## 5. 캐릭터 리소스 등급

- 일상 NPC는 지역·직업별 32×48 공용 몸체에 머리, 색, 소품을 조합한다. 중요 서사 NPC만 고유 초상화를 갖는다.
- 일반 전투 상대는 고유 이름, 얼굴과 초상화를 갖되 진행 구간과 무기별 몸체·자세를 공유할 수 있다.
- 주인공, 13개 관문 보스, 천마십이좌 12명과 최종 천마는 고유 탐색 외형, 초상화, 상징과 카드·이펙트 정체성을 갖는다.
- 전투 화면의 인물 스탠딩은 선택적이다. 최종 전투 UI에 인물이 반드시 등장한다고 가정하지 않는다.
- 인물 스탠딩을 사용할 경우 개별 무공 애니메이션은 만들지 않으며 대기, 피격, 패배 정도의 공용 상태만 고려한다.
- 인물 초상은 128×128px SD 픽셀 흉상으로 통일한다.
- 핵심 인물은 같은 초상 규격에서 표정 변형을 추가할 수 있고, 필요한 경우 별도의 고해상도 이벤트 일러스트를 둔다.

## 6. 타일맵과 환경

- 타일 논리 크기는 32×32px다.
- 재사용 가능한 기본 타일이 약 70~80%, 지역 고유 오버레이와 랜드마크가 약 20~30%가 되도록 설계한다.
- 기본 레이어는 다음 역할로 나눈다.
  - 지면과 길
  - 전이부와 모서리
  - 벽과 건물 구조
  - 지붕과 전경 가림
  - 자원, 소품과 장식
  - 그림자
  - 충돌과 상호작용
- 일반 건물은 모듈식으로 조립하고 랜드마크는 고유 오버레이로 차별화한다.
- 환경 원본은 중립적인 낮 색상을 기준으로 제작한다.
- 시간대와 날씨는 원본 타일을 다시 그리지 않고 전역 색조와 안개·비·눈 오버레이로 표현한다.
- 지역은 공통 팔레트 안에서 주조색 1개, 건축 재료군 1개, 대표 식생 또는 소품 3종을 시각 표식으로 갖는다.
- 문파와 적 세력은 상징 문양, 대표색, 복식 실루엣 중 최소 두 요소가 함께 보이도록 한다. 색만 바꾼 복제로 구분하지 않는다.

## 7. 카메라와 화면 확장

- 게임은 가로 전용이다.
- 16:9를 핵심 안전 구도로 사용한다.
- 더 넓은 화면은 맵을 좌우로 더 보여주고, 펼친 폴더블처럼 정사각형에 가까운 화면은 위아래를 더 보여준다.
- 화면 비율이 바뀌어도 타일을 늘이거나 찌그러뜨리지 않는다.
- UI는 고정 절대 좌표가 아니라 현재 창의 Safe Area에 상대적으로 앵커링한다.
- UI 패널은 최소·최대 크기와 반응형 재배치를 사용한다.
- 접기와 펼치기 같은 런타임 화면 변경 시 Scene 재로딩이나 게임 상태 손실 없이 레이아웃을 다시 계산한다.
- 전투 중앙 구도와 패널은 화면 비율에 따라 재배치할 수 있어야 한다.

## 8. UI 재료와 구성

- UI의 기본 재료는 옅은 한지·비단 바탕, 먹색·검은 칠 또는 짙은 목재의 구조선, 제한된 주홍 인장 강조다.
- 목재 프레임은 화면을 압도하지 않도록 얇고 절제한다.
- 전체 화면을 하나의 이미지로 제작하지 않는다.
- 패널은 모서리, 변, 바탕과 장식을 분리한 9-slice 모듈로 구성한다.
- 장식은 프레임 크기에 따라 생략하거나 위치를 옮길 수 있는 별도 스프라이트로 둔다.
- 종이 질감은 늘릴 때 왜곡되지 않도록 반복 가능한 타일로 분리한다.
- 버튼과 선택 항목은 기본, 눌림, 선택, 비활성 상태를 갖는다.
- 눌림은 1~2px 이동과 음영, 선택은 인장 또는 먹선 테두리, 비활성은 대비와 문양 축소로 구분한다.
- 상태 차이를 색 하나에만 의존하지 않는다.
- 터치 영역은 시각적 버튼보다 넉넉하게 둔다.

## 9. 문자와 현지화

- 현재 기준 언어는 한국어지만 향후 다양한 언어를 지원한다.
- 제목, 이름, 설명, 버튼, 수치, 등급 등 실제 정보 문자는 이미지에 굽지 않는다.
- 모든 실제 정보는 언어별 지정 폰트와 폴백 체인으로 출력한다.
- 장식적 한자는 최소한으로만 허용한다.
- 장식 한자는 번역하지 않아도 기능 이해에 영향을 주지 않는 비정보성 요소여야 한다.
- 분위기는 타이포그래픽보다 먹선, 종이, 인장과 여백으로 만든다.

## 10. 아이콘과 품질

- 재료, 인벤토리, 제작, 장비 아이콘은 32×32px 논리 크기를 사용한다.
- 상태, 부상, 의도와 퀘스트 표식은 16×16px 논리 크기로 별도 단순화한다. 32px 아이콘을 자동 축소하지 않는다.
- UI 아이콘과 필드 자원은 같은 이미지를 재사용하지 않고 별도 에셋으로 제작한다.
- UI 아이콘은 약한 3/4 시점, 투명 배경과 중앙의 단일 실루엣을 기본으로 한다.
- 약초, 광석과 목재 같은 수량형 재료 아이콘은 2~3개 묶음으로 표현할 수 있다.
- 품질 테두리, 인장, 수량과 슬롯 배경은 아이콘에 굽지 않고 UI 레이어로 분리한다.
- 상세 화면에서는 정수 배율로 확대한다.
- 희귀하거나 서사적으로 중요한 대상만 별도의 256px 일러스트를 추가한다.
- 동일 아이템은 품질마다 새로 그리지 않고 기본 아이콘을 공유한다.
- 공통 품질은 `범품 → 양품 → 상품 → 명품 → 절품`의 5단계다.
- 품질 강조색은 `먹회 → 죽엽 녹 → 청회 → 황토금 → 주홍`의 저채도 계열을 기준으로 한다.
- 품질이 올라갈수록 테두리 굵기, 모서리 문양과 인장 형태도 함께 강화한다.
- 품질 식별을 색에만 의존하지 않는다.
- 원재료는 실제 형태를 우선한다. 약초는 잎·꽃·뿌리, 광석은 결정면과 암질, 목재는 껍질과 단면으로 구분한다.
- 가공품은 건조 묶음, 괴와 판재처럼 정돈된 형태로 바꿔 원재료와 구분한다.
- 36종 영약은 9개 경지별 용기·제형 계열과 4개 능력치별 문양·재료 실루엣을 조합해 계보가 보이게 한다.
- 영약 36개는 각각 고유한 최종 아이콘으로 다듬되 공통 계열의 특징을 공유한다.
- 치료제는 외상 `붕대·고약`, 골절 `부목·고정끈`, 내상 `탕약·침구`, 해독 `해독환·약병`의 실루엣으로 구분한다.
- 치료제의 초급·중급·상급 제조법은 재료 정제도와 포장 형태의 발전으로 나타낸다.

## 10.1 무기 아이콘

- 제조 1~5단계와 범품~절품 품질은 시각적으로도 별도 개념으로 유지한다.
- 제조 단계가 올라가면 칼날 비례, 재질, 손잡이와 장식 등 무기 본체 디자인이 발전한다.
- 편집 원본에서는 칼날, 손잡이와 장식을 레이어로 관리할 수 있다.
- 게임에서는 무기 종류와 제조 단계별로 조정해 합친 단일 32×32 아이콘을 사용한다.
- 현재 기획에 부품 외형 조합이 없으므로 런타임에 여러 부품 이미지를 겹쳐 무기를 조립하지 않는다.
- 품질은 무기 본체를 다시 그리지 않고 UI 테두리와 인장으로 표시한다.
- 검은 곧은 양날과 대칭 검격, 도는 외날 곡선과 비대칭 손잡이·도배를 핵심 실루엣으로 삼는다.
- 작은 아이콘의 판독성을 위해 칼날 폭과 곡률을 약간 과장할 수 있다.
- 거대 검, 과도한 톱날과 보석 발광 같은 판타지 장식은 피한다.

## 11. 무공 카드 삽화

- 무공 카드 삽화는 실제 무협지의 무공서처럼 동작을 먹으로 기록한 간결한 그림을 기준으로 한다.
- 따뜻한 종이 위에 먹색과 먹회색만 사용하며 삽화 내부에 청색, 주홍색 등 분류색을 넣지 않는다.
- 큰 붓선, 거친 붓결, 마른 붓의 끊김과 먹 고임을 살린다.
- 한 장에는 한 인물과 하나의 핵심 동작 또는 기운 흐름만 두고 복잡한 배경을 피한다.
- 공격과 방어는 마지막으로 확정된 거친 붓질 샘플을 기준으로 한다.
- 내공은 인물 주변의 큰 원형 먹 흐름으로 기가 모이거나 뿜어져 나오는 인상을 주는 확정 샘플을 기준으로 한다.
- 카드 삽화는 도트화하지 않고 붓결이 보존되는 512×512 고해상도 투명 PNG 레이어로 제작한다.
- 종이 바탕, 프레임, 문자와 수치는 삽화와 분리한다.
- 같은 삽화를 카드, 도감과 상세 화면에서 재사용할 수 있어야 한다.

## 12. 전투 이펙트

- 실제 전투는 캐릭터 직접 조작 전투가 아니라 별도 1대1 카드 전투다.
- 무공은 개별 캐릭터 애니메이션보다 카드 삽화와 공용 이펙트로 전달한다.
- 권, 장, 검, 도, 방어와 회피 같은 동작 이펙트는 먹색과 먹회색 붓질을 중심으로 한다.
- 상태 전달에는 이펙트당 하나의 제한된 저채도 보조색을 사용할 수 있다.
- 예시는 출혈·위험의 주홍, 내공·강화의 옥색 또는 청회색, 방어·기절의 황토 계열이다.
- 카드 삽화 자체는 보조색으로 채색하지 않는다.
- 상태는 색뿐 아니라 형태와 아이콘으로도 구분한다.
- 이펙트는 적의 의도, 상태와 수치를 오래 가리거나 전투 판독을 방해하지 않게 짧게 유지한다.
- 권은 짧고 응축된 먹점과 파열, 장은 넓게 밀어내는 번짐, 검은 가늘고 곧은 절단선, 도는 굵고 휘어진 획을 기본 문법으로 삼는다.

## 12.1 소형 상태·부상·의도 아이콘

- 16×16 아이콘은 축소 삽화가 아니라 먹으로 찍은 단순 상형 표식으로 만든다.
- 인체 부위, 무기 방향 또는 기의 흐름 중 하나의 핵심 형태만 남긴다.
- 글자와 숫자는 넣지 않으며 필요한 경우 상태 보조색 한 가지만 사용한다.
- `ArtSource/Concepts/Icons/status-injury-intent-pictogram-concept-01.png`의 먹도장형 방향을 채택한다.
- 해당 샘플은 방향 승인 상태일 뿐 프로덕션 원본이 아니다. 내상과 중독처럼 복잡한 표식은 실제 16×16 작업에서 더 단순화한다.

## 13. Unity 반입 기준

- 픽셀 에셋은 32 Pixels Per Unit을 기본으로 한다.
- 타일 한 칸은 월드 1유닛이다.
- 픽셀 에셋은 Point 필터, 압축 없음, 밉맵 없음을 기본으로 한다.
- 확대와 화면 합성은 정수 배율을 우선한다.
- 캐릭터와 세워진 오브젝트의 피벗은 발밑 중앙이다.
- 바닥 타일은 셀 중앙, UI와 아이콘은 중앙 피벗을 기본으로 한다.
- 충돌 영역은 그림 전체가 아니라 발판, 기둥 밑면처럼 실제로 지면에 닿는 부분을 기준으로 한다.

## 14. 기본 산출물 형식

새 그래픽 리소스를 만들 때 이미지만 출력하지 않는다. 다음 제작 명세를 함께 남긴다.

- 용도와 표시 맥락
- 콘셉트 또는 프로덕션 상태
- 논리 크기와 원본 크기
- 사용 팔레트와 강조색
- 피벗과 충돌 기준
- 애니메이션 방향, 프레임 수와 fps
- UI 상태 또는 품질 변형 규칙
- 저장 위치
- Unity 반입 가능 여부
