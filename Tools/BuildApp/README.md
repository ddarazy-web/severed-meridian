# Moon Rabbit 외부 빌드 도구

Windows용 독립 WPF 앱입니다. Unity 내부 `Match → Build → 빌드 도구` 및 BAT와 같은 프로필·옵션·실행기를 사용합니다. 앱에 빌드 엔진을 복제하지 않습니다.

## 실행 준비

프로젝트의 `Tools/BuildApp`에서 다음 명령으로 **외부 앱만** 컴파일합니다. 게임이나 Addressables를 빌드하는 명령이 아닙니다.

```powershell
dotnet build BuildApp.csproj
& .\bin\Debug\net8.0-windows\MoonRabbit.BuildApp.exe
```

현재 로컬 검증 대상은 .NET 8 Windows Desktop입니다. 개발에는 .NET 8 SDK, 실행에는 해당 Desktop Runtime과 프로젝트 버전에 맞는 Unity 및 플랫폼 모듈이 필요합니다. .NET 8은 2026-11-10 지원 종료 예정이므로 장기 배포 전에 .NET 10 전환을 검토해야 합니다. 이 도구가 SDK나 런타임을 자동 설치하지는 않습니다. [Microsoft 지원 정책](https://dotnet.microsoft.com/en-us/platform/support/policy).

로컬 실행 폴더를 만들 때는 `powershell -NoProfile -ExecutionPolicy Bypass -File Tools/BuildApp/Publish-Local.ps1`을 실행합니다. 프로젝트 `Build/BuildApp/<시각>`에 앱과 안내, SHA256 manifest를 생성합니다. 기존 폴더를 덮어쓰지 않으며 공개 업로드·Unity 제품 빌드는 하지 않습니다. 런타임은 포함하지 않으므로 대상 PC에는 지원되는 .NET 8 Windows Desktop Runtime이 필요합니다.

## 설정하고 검사하기

앱 시작 시 프로젝트별 마지막 조회 결과를 즉시 표시합니다. 캐시가 있으면 Unity 실행·컴파일·자동 재조회 없이 열립니다. 왼쪽에 저장된 조회 시각이 표시되며, 최신 설정이 필요할 때 **프로젝트 → 프로필 불러오기(F5)**를 누르세요. 캐시가 없거나 손상된 최초 실행 및 수동 재조회 때만 반투명 로딩 안내를 표시합니다. 조회 실패 시 이전 캐시는 보존합니다.

캐시는 프로젝트 `UserSettings/MatchBuildAppProfiles.json`에 저장하며 다른 프로젝트와 공유하지 않습니다. 버전·옵션·서명 설정 저장 성공 시 반환된 정보도 반영합니다. 저장되지 않은 편집값이나 비밀번호는 캐시에 넣지 않습니다. 저장·검사·빌드 시에는 Unity에서 원본 revision을 확인하므로 외부에서 설정이 바뀌었다면 덮어쓰지 않고 F5 재조회를 안내합니다.

외부 앱은 시작 시나 빌드 시작 전에 사용자 로그를 자동 정리하지 않습니다. 상단 **로그 정리** 메뉴에서 로그 관리 화면을 열고, 후보 미리보기 후 직접 정리하세요. 메뉴를 여는 것만으로 조회나 삭제를 실행하지 않습니다. 초기 대기 시간에는 Unity 실행과 스크립트 컴파일·프로필 조회가 포함됩니다.

1. 상단 **프로젝트 → 프로젝트 폴더 선택**에서 `Assets`, `ProjectSettings`, `Tools/Build`가 있는 폴더를 고릅니다. 현재 프로젝트 경로도 같은 메뉴에서 확인합니다.
2. 프로젝트 버전의 Unity 경로를 자동 탐색합니다. 찾지 못하면 **프로젝트 → Unity 경로 변경**으로 지정합니다. 현재 Unity 실행 파일은 같은 메뉴에서 확인합니다.
3. **프로젝트 → 프로필 불러오기(F5)** 후 왼쪽 빌드 프로필을 선택합니다. 왼쪽 영역은 프로필 선택 전용입니다. 같은 프로젝트가 Unity에 열려 있으면 작업을 마친 뒤 닫아 주세요. 다른 프로젝트의 Unity는 종료할 필요가 없습니다.
4. 제품 정보에서 Version Name과 지원되는 Version Code/Build Number를 입력하고 옵션을 선택합니다. **설정 저장(Ctrl+S)**은 빌드를 실행하지 않습니다.
5. **사전 검사(F6)**로 저장된 설정을 확인합니다. 검사가 통과해도 실제 빌드·서명 성공을 의미하지 않습니다.
6. **빌드 시작(Ctrl+B)**은 별도 확인 후 실제 제품 빌드를 요청합니다. 출력 위치·버전·옵션을 확인하세요. 현재 2단계 검증은 모의 실행이며 실제 제품 빌드 결과는 아직 검증하지 않았습니다.

버전은 Unity 프로필, 옵션은 기존 `UserSettings/MatchBuildTool.json`에 저장합니다. 외부에서 설정이 바뀌면 저장을 거절하며, 다시 불러오기 전에 현재 입력을 확인하도록 안내합니다. 저장하지 않은 변경은 프로필 전환·재조회·종료 시 확인합니다.

## Android 서명

저장 후 비밀번호 입력칸은 비워지지만 각 칸 아래에 **✓ 암호화 저장됨**이 표시됩니다. 탭·프로필을 옮기거나 다시 조회해도 저장 상태를 표시하며, 빌드할 때는 저장된 비밀번호를 사용하므로 재입력이 필요 없습니다. Keystore 경로나 Alias를 바꾸면 기존 저장 표시가 사라집니다. 서명을 변경·저장하거나 Alias를 다시 조회할 때는 비밀번호를 입력합니다.

Android 프로필에서는 서명 영역이 가장 먼저 표시됩니다. 사용자 Keystore 사용을 켜고 파일과 Keystore 비밀번호를 입력한 뒤 **Alias 조회**로 키를 고릅니다. 키 비밀번호를 입력하고 **서명 설정 저장**을 누릅니다. 버전·옵션 변경이 남아 있으면 먼저 저장합니다.

비밀번호는 마스킹된 입력에만 표시되고 현재 Windows 계정의 DPAPI로 암호화합니다. 기존 Unity 도구와 같은 컨텍스트·저장소를 사용합니다. 일반 JSON·명령행·사용자 앱 설정에는 평문을 저장하지 않습니다. 저장 여부 표시는 유효한 비밀번호인지 검사했다는 뜻이 아닙니다. 입력을 전달한 암호화 파일은 요청 완료·실패 시 제거하며, 살아 있는 호스트가 사용하는 파일은 보호합니다. 강제 종료 후 남은 파일은 아래 복구 탭에서 확인합니다.

## 진행과 취소

조회·검사·빌드는 Unity를 별도 프로세스로 시작하므로 최초 시작과 컴파일에 시간이 걸립니다. 작업 중 UI는 진행 상태와 최근 로그를 표시하며, 중복 작업·프로젝트 변경을 막습니다. 결과 없는 종료는 실패로 표시하고 자동 재빌드하지 않습니다.

**취소 요청**은 기존 실행기가 허용하는 안전한 지점에서 처리합니다. 동기 Player 빌드 중 즉시 중단을 보장하지 않습니다. 작업 중 창을 닫아 Unity를 강제 종료하지 않으며, 완료 또는 취소 처리 후 닫을 수 있습니다. **로그 폴더 / 출력 폴더**는 실제 생성된 경로를 엽니다.

## 로그 정리

**로그 관리** 탭은 선택 제품뿐 아니라 현재 프로젝트 `Logs` 전체를 대상으로 합니다.

1. 보관 기간을 입력합니다. 기본 7일, 허용 범위 1~3650일입니다.
2. **미리보기**로 후보 경로·용량·보호 항목을 확인합니다. 아직 삭제하지 않습니다.
3. **정리 실행**에서 프로젝트·기간·예상 용량을 확인한 뒤 실행합니다. 프로젝트나 기간을 바꾸면 다시 미리보기가 필요합니다.
4. 실제 삭제량과 보호·실패 항목을 확인합니다. `보류`는 사용 중인 프로젝트 또는 미완료 작업을 보호해 삭제하지 않았다는 뜻입니다. 일부 실패를 전체 성공으로 표시하지 않습니다.

기존 `Clean-Logs.ps1`의 보호 조건을 실행 시 다시 검사합니다. 로그 밖 경로, 링크 대상, 잠긴 파일, 미완료·실행 중 기록은 삭제하지 않습니다. `Builds`, `ContentData`, `Library`는 이 기능의 삭제 대상이 아닙니다. 수동 보관 기간은 기존 자동 빌드 전 7일 정리 정책을 변경하지 않습니다.

## 작업 위치와 키보드

마지막 프로젝트·Unity 경로·제품·창 위치·크기·최대화 상태는 `%LocalAppData%/MoonRabbit/BuildApp/workspace.json`에 저장합니다. 화면 밖 창은 현재 작업 영역으로 보정합니다. 버전·옵션·비밀번호 원본은 이 파일에 넣지 않습니다.

Tab/Shift+Tab으로 입력을 이동하고 Space로 체크 항목을 바꿀 수 있습니다. 작은 창에서는 왼쪽 제품 영역과 오른쪽 설정 영역을 각각 스크롤합니다. 최소 창은 1000×700 DIP이며 OS 작업 영역이 더 작으면 그 범위로 보정합니다. 모니터별 DPI에 대응하며 저장된 물리 위치·크기를 해당 모니터의 작업 영역 안에 복원합니다. 100%·150% 실제 모니터에서 재실행·최대화 복원을 검사했습니다. 200% 실제 환경과 물리적 모니터 분리는 아직 미검증입니다.

## 이전 작업 / 복구

앱을 다시 열어도 빌드를 자동 재시작하지 않습니다. **이전 작업 / 복구** 탭은 요청 결과, 프로세스 PID와 시작 시각, 실행 잠금을 확인하며 상태를 주기적으로 갱신합니다.

- **실행 중**: 기존 호스트 또는 Unity 작업이 살아 있습니다. 새 작업을 시작하지 말고 완료를 기다립니다. 앱을 강제 종료했던 경우에도 기존 호스트를 다시 시작하지 않습니다.
- **결과 없음 / 손상된 결과**: 실행 로그와 결과를 확인하세요. **검토 완료 표시**는 확인 기록만 남기며 빌드하거나 Unity 기록을 수정하지 않습니다.
- **기존 실행기 확인 필요**: Unity의 `Match → Build → 빌드 도구`에서 미완료 요청을 확인합니다. 이 상태에서는 외부 확인 버튼으로 실행기 잠금을 해제할 수 없습니다.
- **남은 암호화 파일 정리**: 24시간 이상 지난 일회성 전송 파일 중 프로세스·잠금에 의해 보호되지 않은 파일만 삭제합니다. 사용자 서명 저장소와 로그는 삭제하지 않습니다. 손상된 소유 기록은 안전을 위해 보호합니다.

요청·결과 기록은 진단을 위해 유지합니다. **사용 안내**는 Markdown 연결 프로그램 없이 앱 내부 창에서 읽을 수 있습니다.

## 연결 파일과 검증 범위

요청·결과·진행·취소 파일은 `Library/MatchBuildApp/<requestId>`에 둡니다. Unity가 시작할 때 정리하는 `Temp`를 통신 폴더로 쓰지 않습니다. 실행 로그는 기존 `Logs/ExternalBuild`에 남습니다. 한 프로젝트는 기존 실행 잠금으로 보호합니다.

개발 검사는 `Tools/Testing/BuildApp.Tests`와 `ExternalBuildAppHost.Tests.ps1`을 사용합니다. 실제 계정 비밀번호와 실제 사용자 로그는 검사에 사용하지 않습니다. Windows 앱은 iOS 설정을 다룰 수 있으나 macOS/Xcode 서명·아카이브 작업을 대신하지 않습니다.
