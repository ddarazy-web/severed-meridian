# Match 통합 작업창

## 결정과 범위

2026-09-28 사용자 승인: 별도 도구를 한 창의 탭으로 통합한다. 새 개발 단계 번호를 부여하지 않고 창 구성 → 상태 관리 → 회귀 검증 순서로 작업한다.

- `Match/통합 작업창`에서 레벨 편집, 플레이 테스트, 초기 보드·진단을 제공한다.
- 기존 Match 메뉴도 같은 창의 해당 탭을 연다. 레벨 선택은 창 상단에서 공유한다.
- 편집 화면과 두 시험 패널은 각자의 UI와 상태를 소유한다. 플레이·진단은 같은 패널 구현을 사용하되 인스턴스와 시험용 보드는 분리한다.
- 기존 공통 시뮬레이터를 그대로 사용한다. 런타임 규칙, 레벨 저장 형식, 원본 에셋은 변경하지 않는다.

## 대안과 선택 이유

1. Unity 기본 도킹: 변경은 적지만 도구별 레벨 선택과 초기 보드/플레이 모드 전환 시 상태 소실 문제를 해결하지 못한다.
2. 기존 창을 숨겨서 내용만 부착: 변경은 적지만 숨겨진 창의 수명과 이벤트 해제에 의존한다.
3. 통합 창 + 일반 C# 패널: 창 수명과 UI 패널 수명을 명시적으로 관리하며 기존 실행 로직을 재사용한다. 이 방식을 선택한다.

## 상태 규칙

- 탭 이동은 테스트 종료가 아니다. 편집 선택·스크롤, 각 시험의 시드·보드·진행 상태를 유지한다.
- 다른 탭에서는 해당 시험의 시작 후보 검색과 자동 연쇄를 일시정지한다. 복귀하면 진행하던 처리를 재개한다. 아이템 선택과 미완료 편집 드래그는 해제한다.
- 공통 레벨을 바꾸면 두 시험을 모두 초기화한다. 같은 레벨을 다시 여는 것으로는 초기화하지 않는다.
- 원본 레벨 변경은 기존 fingerprint 검사로 감지한다. 이전 시험을 무효화하고 다시 구성하라는 안내를 표시한다. 시험 결과를 원본에 저장하지 않는다.
- 창 닫기와 UI 재생성/스크립트 재컴파일은 예약 처리를 해제하고 시험을 폐기한다. 도메인 재로드 후 선택 레벨·탭·시드는 복원하되 시험은 다시 시작한다.
- 같은 시드/새 시드 재시작과 상세 단계 실행은 기존 동작을 유지한다.

## 변경 및 검증 순서

1. 기존 LevelEditorWindow를 통합 창으로 유지하고 공통 헤더와 탭 추가.
2. 기존 LevelInitialStateWindow 구현을 LevelInitialStatePanel로 분리. 기존 정적 메뉴 진입점은 통합 창으로 연결.
3. 탭 전환, 공통 레벨 변경, 원본 수정, 도메인 재로드의 상태 정책 검증.
4. 기존 수동 플레이, 초기 보드, 연결 편집과 공통 규칙 회귀 검증.

분리 창, 자동 봇·통계 탭은 이번에 추가하지 않는다. 동시 비교 요구가 실제로 생기면 분리 보기를 재검토한다.

## 완료 및 검증

구현과 실제 Unity 6000.3.10f1 검증을 완료했다. 최종 검사 **246개 통과, 실패 0개**:

| 검사 | 통과 |
|---|---:|
| 수동 플레이·탭 전환·선택/스크롤 보존 | 42 |
| 수동 플레이 독립 재시작·원본 보존 | 6 |
| 실제 도메인 재로드·탭/레벨/시드 복원 | 7 |
| 발전기·통로·낙하 경로·합류 편집 | 116 |
| 초기 보드 데이터·UI | 63 |
| 초기 보드 독립 재시작 | 12 |

검증 중 발견한 직렬화 시점 UI 생성 문제는 CreateGUI에서 생성하도록 수정했다. 연결 검사에서는 ShowUtility가 저장된 좁은 창 크기를 복원하므로 표시 후 검증 크기를 지정하도록 수정했다. 재검사에서는 모두 통과했다.

증거는 `Logs/MatchWorkspaceVerification`의 `final-counts.json`, 각 결과 파일, Unity 로그 및 화면 캡처에 보관한다. 시뮬레이터·레벨 정의·기존 레벨 데이터의 작업 전후 해시가 동일하며, 이동한 패널 파일의 기존 meta/GUID를 보존했다. 검증용 임시 에셋은 정리했다. 이전 단계 전체 테스트를 이번에 전부 재실행한 것은 아니다.
