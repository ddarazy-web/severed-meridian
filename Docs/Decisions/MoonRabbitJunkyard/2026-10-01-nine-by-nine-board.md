# 9×9 보드 전환 — ADR-2026-10-01

작성일: 2026-10-01. 상태: 구현·Editor 검증 완료. [검증 결과](../../Verification/MoonRabbitJunkyard/WorldGameScreen/2026-10-01-nine-by-nine-board.md).

## 결정과 이유

보드를 10×10에서 **9×9(81칸)**으로 줄이고 블록을 약 10% 크게 표시한다. 화면에서 보드가 차지하는 외곽 영역과 HUD 배치는 유지한다. 작은 맵은 같은 화면 조건의 셀 크기를 유지하고 활성 영역을 중앙에 배치한다.

| 항목 | 이전 | 현재 기준 |
| --- | --- | --- |
| 보드 | 10×10, 100칸 | 9×9, 81칸 |
| 표시 좌표 | 행·열 1~10 | 행·열 1~9 (내부 0~8) |
| Editor 편집 보드 셀 | 40px | 44px |
| Editor 시뮬레이터 셀 | 43px | 48px |
| 월드 카메라 기본 orthographic size | 5.3 | 4.8 (셀 표시 약 10.4% 확대) |
| 게임 화면 목업 | 10행·10열 | 9행·9열, 외곽 CSS 크기 유지 |

## 기존 데이터

레벨 스키마 **4**, MemoryPack 포맷과 필드 순서는 유지한다. 자동 변환은 현재 스키마의 10×10·100칸 정상 배열에만 적용한다. 구버전 스키마와 칸 수가 맞지 않는 손상 배열은 그대로 남겨 기존 전환·검사 절차에서 다룬다. 기존 오류 데이터를 정상 데이터처럼 자동 복구하지 않는다.

기존 레벨·등록 모양은 왼쪽 위 9×9를 보존하고 마지막 행과 마지막 열을 제거한다. 단순히 목록의 끝 19개를 자르지 않고 기존 행 우선 좌표를 기준으로 다시 구성한다. 보존 영역의 셀 설정을 유지하며 경계 데이터는 다음과 같이 처리한다.

- 범위 밖 블록·덮개·먼지·회수 부품·생성구·중력·도착 바닥은 제거한다. 2×2 본체는 일부만 경계 밖에 걸쳐도 전체를 제거한다.
- 양끝 본체 중 하나가 제거된 전선과 보드 경계 밖 정점을 가진 전선은 제거한다. 벽과 합류 후보에서도 제거된 칸의 참조를 정리한다.
- 잘린 칸으로 향하던 직접 경로는 남은 칸에서 멈춘다. 출구만 잘린 통로도 남은 입구를 경로 끝으로 바꿔 기본 중력에 의한 새 합류·순환을 만들지 않는다.
- 레벨 미션·이동 수 등 난이도 값은 자동 보정하지 않는다. 목표 대상이 잘리거나 공급이 달라진 레벨은 후속 검사·플레이 검수가 필요하다.

## 문서와 검증의 해석

현재 콘텐츠 명세와 사용 안내는 이 결정을 따른다. 과거 계획·목표·검증 기록의 10×10 또는 100칸은 당시 조건이며, 기록된 시간·성공 수·PASS 결과를 9×9 검증으로 간주하지 않는다. 매뉴얼의 기존 캡처도 촬영 당시 화면을 보존한다. 이 결정은 보드 크기 관련 부분을 대체하며 다른 게임 규칙은 유지한다.

검증 대상은 81칸 생성·좌표 경계, 기존 데이터 변환, 편집·등록 모양·플레이·월드 입력의 일치, 셀 표시 크기와 화면 영역 보존이다. 실행 결과는 위 검증 기록을 따른다. 플레이어 및 Addressables 콘텐츠 빌드는 수행하지 않았다.
