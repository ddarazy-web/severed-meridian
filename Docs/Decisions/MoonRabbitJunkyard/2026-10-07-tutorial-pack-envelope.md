# 레벨 튜토리얼 저장 — 기존 팩을 감싸는 팩3

날짜: 2026-10-07. 상태: 1단계 적용.

## 결정

기존 PackedLevel/LevelPack과 PackedElementLevel/ElementLevelPack의 필드 순서·버전 계약을 변경하지 않는다. 튜토리얼이 있는 구간에만 TFPK 헤더(버전3, 예약 바이트0)와 MemoryPack 봉투를 사용한다. 봉투에는 기존 팩2 바이트, 구간 시작 번호, 레벨 번호별 튜토리얼 값이 들어간다.

혼합 구간의 모든 내부 레벨에 메타데이터 항목을 하나씩 둔다. 튜토리얼 없는 레벨은 null 값으로 기록해 번호 중복·누락을 검출한다. 최소 하나는 튜토리얼이어야 한다. 복원은 내부 팩2 및 튜토리얼 정적 검사와 참조 정의 폐쇄를 모두 검증한다.

튜토리얼 없는 구간은 기존 팩2를 사용하고 구형 스냅샷 정책도 유지한다. 기존 50레벨 주소·Addressables 그룹·ECPK 요소 팩·제작 SO 배포 제외는 변경하지 않는다. 명시적인 팩1/2 쓰기에 튜토리얼이 있으면 거절해 정보 손실을 막는다.

튜토리얼의 공급·발동 대상·결과 조건 및 생성 본체 참조도 내부 정의 표에 포함한다. 튜토리얼 있는 입력의 지문은 팩3 바이트로 계산하며, 없는 입력의 지문 공식은 그대로 유지한다.

## 이유와 대안

기존 DTO에 필드를 덧붙이는 방식은 이미 배포한 명시적 필드 순서 계약에 영향을 준다. 별도 튜토리얼 Addressables 파일은 로딩 수명과 레벨/튜토리얼 버전 동기화 부담을 늘린다. 봉투는 기존 파서를 재사용하고 한 레벨 입력의 전달·사본·시험 경계를 유지한다.

팩3은 봉투와 내부 팩을 검증하므로 변환 비용이 조금 늘어난다. 보드 프레임 갱신 경로에서 변환하지 않는다. 동작 변경 없이 저장만 추가하는 1단계에서는 시드/공급 값이 저장되며 실제 튜토리얼 실행 적용은 2단계 책임이다.
