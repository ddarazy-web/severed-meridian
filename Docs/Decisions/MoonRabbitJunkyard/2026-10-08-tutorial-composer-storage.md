# 조합형 튜토리얼 저장 경계

상태: 1~2단계 구현 기준. 실제 검증 결과는 composer-01-progress와 composer-02-progress에 기록한다.

## 이유

기존 팩3의 단계 DTO에 MemoryPack 직렬화 필드를 바로 추가하면 배포된 팩 읽기와 기존 사본 경로에 영향을 준다. 기존 레벨의 바이트와 GUID를 보존하면서 조합 조건을 저장해야 한다.

## 결정

- 기존 팩3 직렬화 레이아웃은 유지한다. 새 조건 목록/All·Any/자동 강조 설정은 Unity 제작 데이터에 저장하되 기존 MemoryPack 단계 필드에서는 제외한다.
- 조합 데이터가 없는 레벨 구간은 기존 팩3을 그대로 쓴다.
- 조합 데이터가 있으면 팩4 봉투에 기존 팩3 바이트와 레벨 번호/단계 인덱스별 확장 데이터를 함께 저장한다.
- 팩4 읽기는 기존 팩3을 읽고 확장을 복원한 후 전체 조건을 검사한다. 중복/누락 참조, 범위 밖 인덱스, 미지원 조건을 거절한다.
- 런타임은 복원된 같은 Tutorial 데이터와 진행기를 사용한다. 별도 조합 전용 게임 엔진을 만들지 않는다.
- 3단계에서 전체 전환할 때 구형 제작/실행 분기를 정리한다. 기존 팩 읽기 호환성은 콘텐츠 실행 경로 이중 유지와 구분한다.
- 완료 기록 ID 전환은 3단계의 명시적 레벨 매핑으로 수행한다. 이번 단계에서 플레이어 완료 기록을 자동 초기화하지 않는다.

## 2단계 확장

- 팩5는 팩4 바이트와 조건/단계 세부 확장을 포함한다. 팩3/4의 직렬화 순서는 변경하지 않는다.
- 조건 세부값은 대상·집계·허용 원인·파워/방향·생성 연결·아이템·미션 식별값이다. 단계 세부값은 무료 횟수·조작 영역·생성 개체 조작 참조다.
- 중첩 데이터는 모든 확장을 복원한 뒤 전체 의미를 검사한다. 독립 구형 팩 읽기의 검사는 유지한다.
- 누락·중복·null·범위/버전 오류와 잘린 팩은 거절한다. 새 확장이 없는 기존 자료는 기존 버전을 유지한다.
- 개발 중인 팩5 계약을 이번2단계에서 완성했으며 출시 팩을 재생성하지 않았다. 이후 배포된 계약 변경은 새 버전으로 설계한다.
- 50레벨 분할과 Addressables에는 팩만 포함하는 기존 정책을 변경하지 않는다.

## 비용과 대안

팩4가 기존 내용을 봉투로 포함하므로 코드가 조금 늘어난다. 대신 실제 저장 자료로 팩3 읽기와 재인코딩 동일성을 증명할 수 있고 기존 작성 자료를 임의로 재작성하지 않는다. DTO 전부를 복제하거나 JSON을 런타임 저장 형식으로 도입하지 않는다.
