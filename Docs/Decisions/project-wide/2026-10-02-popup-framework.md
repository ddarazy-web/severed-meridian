# 공통 팝업과 선택적 씬 복원 — ADR-2026-10-02-01

작성일: 2026-10-02. 상태 갱신: 2026-10-03 · 사용자 설계 승인(“진행해”) · 1~2단계 구현·검증 완료 · 3단계 미구현.

[설계서와 완료 조건](../../Systems/project-wide/2026-10-02-popup-framework-design.md)

## 배경

현재 PuzzleScreenView가 결과·일시정지·설명 UI의 활성 상태와 입력을 개별 관리한다. 중첩·중간 제거·최상위 키 입력·선택적 씬 복원과 팝업 추가 패턴을 공통으로 관리해야 한다.

사용자는 원래 씬으로 돌아올 때 필요한 경우만 복원하도록 요청했다. 씬 이동 호출자가 이번 이동의 보관 여부를 결정하며 씬/게임 문맥이 다르면 폐기한다.

## 결정

기존 uGUI 위에 공통 서비스·씬별 표시 영역·메모리 복원 저장소를 둔다. 실제 팝업과 이전 씬 콜백을 유지하지 않고 순서와 값 데이터로 다시 생성한다.

- 고유 핸들로 중간 팝업만 제거하고 나머지 순서를 보존한다.
- 아래 팝업은 보이되 최상위만 모든 입력을 받는다.
- 같은 종류는 기존 것을 맨 위로, 지정한 종류만 복수 허용한다.
- 입력 차단과 팝업별 정지 요청을 분리하며 외부 차단/정지 소유권을 보존한다.
- 복원 가능 등록과 이번 이동의 보관 선택을 함께 적용한다.
- 원래 씬의 동일 논리 게임 문맥에서만 새 뷰에 데이터를 적용한다.
- 관리 창·등록 검증·템플릿을 제공하고 기존 세 팝업을 전환한다.

## 대안과 비용

| 대안 | 장점 | 비용/판단 |
| --- | --- | --- |
| 전역 Canvas와 실제 팝업 유지 | 인스턴스 복원이 단순함 | 씬 세션/카메라 참조와 해제 수명이 얽히므로 미채택 |
| 씬별 독립 관리자 | 씬 내부가 단순함 | 정책/등록 중복과 공통 복원/조회 부담으로 미채택 |
| 공통 서비스 + 씬 표시 + 데이터 복원 | 정책 통일과 씬 수명 분리 | 팝업별 캡처/새 문맥 연결이 필요하지만 요구에 적합하여 권장 |

## 영향과 경계

기존 직접 활성화/독립 키 처리를 관리 API로 전환하고 프리팹 생성 도구도 연결을 보존해야 한다. 게임 기능은 문맥과 현재 세션 연결을 제공한다. 팝업 복원은 게임 진행 데이터 복원이 아니다.

앱 실행 중 메모리 복원만 제안하며 앱 재실행 저장·신규 Addressables 정책·시각 재설계·외부 UI 일괄 전환은 제외한다. 신규 패키지·asmdef·전역 DI 교체는 도입하지 않는다. 빌드·커밋·푸시는 수행하지 않는다.

구체 계약은 연결한 설계서에서 검토하고 구현 계획 승인 후 소스를 변경한다. 이 ADR은 구현 완료를 의미하지 않는다.

## 2단계 구현에서 확정한 수명주기

이동 ticket으로 캡처와 확정/취소를 분리한다. 목적지 준비 동안 원래 Host를 유지하고 Commit 뒤 해제한다. 실제 이동과 입력 차단은 호출 기능이 소유한다. 읽기 전용 IsPending으로 소비/Host 종료 후 불필요한 Rollback을 피한다.

Restore는 비활성 후보 전체를 준비한 뒤 목록/입력을 적용한다. 비활성 후보에서 OnDestroy만 의존한 해제가 실패했으므로 명시 ReleaseRestore를 추가했다. 확장 구현은 반복 안전·비예외 해제를 제공한다. 캡처 중 Host 종료도 가드와 충돌하지 않도록 캡처 종료 경로가 표시를 정리한다. 값 상태만 보관하며 게임 세션/실제 뷰를 영속화하지 않는다.
