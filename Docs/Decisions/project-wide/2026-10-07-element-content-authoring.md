# 요소 제작 원본과 MemoryPack 배포 데이터

- 날짜: 2026-10-07
- 상태: 사용자 요청에 따라 적용
- 근거: 현재 블록·장애물 데이터를 ScriptableObject로 작성하고 레벨처럼 MemoryPack으로 배포하며, 새 콘텐츠는 기획을 근거로 생성한다.

## 결정

기존 요소 정의·행동 등록 구조를 유지하고 현재18종의 정의 SO와 규칙/표현 카탈로그 SO를 생성한다. 레벨 제작 원본은 카탈로그를 참조하고 배포 팩에는 Unity 객체 참조 없이 값만 기록한다.

독립 ECPK 버전1 콘텐츠 팩은 규칙과 표현 메타데이터를 저장한다. 기존50레벨 구간의 팩2는 사용하거나 생성할 규칙의 닫힌 집합을 유지한다. Addressables에는 bytes를 등록하고 제작 SO4종이 씬·Resources·번들 의존성으로 남으면 거절한다. 실제 이미지와 프리팹은 기존 아틀라스 및 레벨별 리소스 준비 경로를 따른다.

기존 플레이어/Addressables 빌드 전 변환 경로에서 두 팩을 갱신한다. 수동 갱신 메뉴도 같은 변환을 사용한다. Editor의 에셋 모드는 현재 제작 값을, MemoryPack 모드는 마지막으로 내보낸 값을 사용한다.

## 제약과 비용

여러 제작 카탈로그에서 같은 ID나 시각 키의 의미가 다르면 출시 데이터 병합을 거절한다. 기본 규칙과 표현 메타데이터를 한 번 읽지만 미사용 장애물의 이미지까지 준비하지 않는다. 카탈로그 규모가 커져 메타데이터 로딩 비용이 문제가 되면 측정 후 별도 분할을 검토한다.

실행 표현 DTO는 JSON 호환 때문에 유지한다. Unity 제작 원본에는 효과 프레임이 다시 효과를 포함하지 않는 유한한 구조를 저장한다. 이는 기존 효과 검증 계약과 같으며 Inspector 저장 시 재귀 타입의 깊이 제한을 피한다.

기획 문서 존재와 근거 항목 입력을 검사한다. 수치·행동의 의미 일치는 자동 추론하지 않으므로 제작자가 기획과 대조한다. 기존 원본을 덮어쓰는 자동 초기화나 미확정 콘텐츠 생성은 하지 않는다.

기획 경로인 Docs/Contents는 저장소의 기존 ignore 대상이다. 다른 개발 환경에서도 배포 데이터 갱신을 하려면 해당 기획 문서를 제공해야 한다. 이 작업에서 기존 문서의 Git 관리 정책은 변경하지 않는다.
