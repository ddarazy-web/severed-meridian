# 레벨 탐색 개선 2단계 — 대량 문서 준비 비용

상태: 계획 확정 / 미착수. 1단계 완료 결과를 반영했으며 별도 실행 요청 후 착수한다.

## 목표와 경계

가상 목록은 화면에 생성되는 행을 줄인다. 그러나 프로젝트 열기와 편집 세션은 여전히 전체 문서 준비·복사 비용을 부담할 수 있다. 2단계는 이 비용을 측정하고 실제 병목만 줄인다. 검색 UI를 다시 만들거나 JSON 콘텐츠 형식을 변경하는 단계가 아니다.

1단계 1만 건 메타데이터 검색 중앙값은 정상 실행 3회 모두 1ms 미만이었다. 이는 전체 레벨 문서의 디스크 읽기·검증·세션 생성 시간을 포함하지 않는다. 전체 프로젝트 시작 성능은 별도로 측정해야 한다.

## 작업 묶음

### A. 실제 문서 기준 측정

- 기존 제작 저장소 형식으로 1천/1만 레벨 임시 프로젝트를 생성한다. 실제 사용자 폴더는 사용하지 않는다.
- 파일 읽기, JSON 해석·참조 검증, 세션 준비, 화면 첫 표시, 다른 레벨 열기, 저장·복구 비용을 구분한다.
- 최초 실행과 워밍업 후 3회 결과를 구분하고 중앙값·p95·최댓값, 메모리 및 할당량을 기록한다.
- 데이터 크기와 문서 종류를 명시한다. 빈 문서 복제만으로 실제 제작 프로젝트 성능을 대표하지 않는다.

### B. 측정된 병목 축소

- 목록 조회에는 ID·번호·이름만 전달하고 불필요한 문서 복사 요청을 제거한다.
- 편집 표시 준비는 선택 레벨과 실제 참조 문서에 집중한다. 기존 불변 문서 공유·버전 조회 경계를 우선 재사용한다.
- 화면 갱신에서 전체 ID 배열·목록을 반복 생성하는 부분은 측정으로 비용이 확인된 곳만 변경한다.
- 저장·검증에서 반드시 필요한 전체 참조 검사는 생략하지 않는다. 최초 로딩을 늦춘 결과 저장이나 오류 탐지가 불안정해지는 변경은 허용하지 않는다.
- 파일별 지연 로딩, 새 인덱스 파일, 비동기 편집 모델이 필요하다면 구현 전에 비용·호환성·실패 복구 정책을 설명하고 확정한다. 이번 계획만으로 이를 자동 승인하지 않는다.

### C. 회귀와 종료

- 같은 fixture와 실행 조건으로 변경 전후 수치를 비교한다. 성능 개선이 없는 복잡성은 남기지 않는다.
- 레벨 탐색, 부분 취소, 공유 참조, Undo/Redo, 수동 저장, ZIP 전달, MemoryPack 입력과 복구의 기존 동작을 검사한다.
- 대량 프로젝트 첫 표시 및 레벨 전환 화면을 확인하고 오래 걸리는 작업의 진행 표시·취소 가능 여부를 보고한다.
- 소유한 임시 사본만 정리한다. 검증 결과와 실제 작업 데이터는 보존한다.

## 완료 판단

측정으로 확인된 병목이 감소하고 저장·편집 계약이 유지되어야 한다. 절대 시간 목표는 A의 실제 기준값과 환경을 보고 확정한다. 숫자를 맞추기 위해 검증을 생략하거나 완료 기준을 임의로 완화하지 않는다.

제품 빌드·커밋·푸시·HTML 매뉴얼 갱신은 하지 않는다. 질문은 시간제한 없는 문답으로 한다.
