# 레벨 탐색·안전한 편집 전환 1단계 구현 계획

> 구현 담당: `superpowers:executing-plans`로 작업 묶음별 검증을 수행한다. 커밋·푸시하지 않는다.

**상태:** 2026-10-21 1단계 완료 / Editor 검증 완료 · 실기기 제외  
**목표:** 대량 목록에서 검색 후 명시적으로 레벨을 열고, 현재 레벨만 변경을 버리며 다른 작업을 보존한다.  
**구조:** 목록 인덱스/가상 표시, 공통 열기 요청, 세션의 레벨별 변경 처리, 최근 목록 저장을 분리한다. 기존 프로젝트 저장 경로는 유지한다.  
**기술:** C#, UI Toolkit, 기존 제작 세션 및 JSON 사용자 설정.  
**명세:** [통합 계획](2026-10-21-integrated-plan.md) · [완료 조건](../../../Goals/MoonRabbitJunkyard/LevelToolLevelBrowser/2026-10-21-stage01-goal.md)

## 변경 담당 영역

경로는 저장소 기준이다. 신규 파일명은 제안이며 구현 전에 기존 책임과 중복되는지 확인한다.

| 파일/영역 | 책임 |
| --- | --- |
| `Assets/Scripts/Features/LevelTool/Runtime/LevelToolScreen.cs` 및 `.Layout.cs`, `.Refresh.cs` | 전량 버튼 생성 제거, 검색·최근 목록 배치, 편집 표시 갱신 |
| 같은 폴더 `LevelToolScreen.LevelBrowser.cs` (신규안) | 목록 바인딩, 탐색 상태, 공통 `RequestOpenLevel(id)` 및 확인 UI |
| `Assets/Scripts/Features/LevelAuthoring/Editing/LevelBrowserIndex.cs` (신규안) | ID/번호/이름 인덱스, 검색 해석·결과 정렬. Unity 화면과 분리 |
| 같은 폴더 `AuthoringEditSession.cs`, `.State.cs`, `.LevelChanges.cs` (신규안) | 현재 레벨 dirty/부분 취소, 이력·복구 계약 보존 |
| `Assets/Scripts/Features/LevelAuthoring/Storage/RecentLevelStore.cs` (신규안) | 프로젝트별 최근 20개 ID의 원자적 저장·복원 |
| `LevelToolScreen.ManualSave.cs`, `.Recovery.cs`, `.TutorialSharing.cs` | 대기 입력/저장 실패/공유 초안/복구와 목록 전환 일관성 |
| `Tests/Editor/Features/LevelAuthoring/` | 부분 취소, 검색, 최근 기록, UI·대량 목록 검증 |

`RecentProjectStore`는 프로젝트 목록의 기존 책임을 유지한다. 레벨 최근 목록을 그 목록에 혼합하지 않는다. 새로운 범용 프레임워크나 외부 검색 서비스를 추가하지 않는다.

## 작업 A — 현재 레벨만 변경 버리기와 안전한 열기

- [x] 현재 `Discard`, 전체 상태 Undo/Redo, 복구 직렬화, 신규 레벨 생성/삭제, 공유 적용 호출부를 확인한다.
- [x] A/B 레벨과 공유 문서를 수정한 뒤 A만 버리는 실패 재현 검사를 먼저 작성한다. B/공유의 값·dirty·Undo/Redo와 A 변경 재등장 여부를 검사한다.
- [x] 세션의 레벨별 변경 조회·취소 경계를 최소 범위로 추가한다. 저장 기준과 현재 문서만 비교하며 불필요한 전체 JSON 복사를 피한다.
- [x] 여러 문서 원자적 변경, 저장 전 신규 레벨, 삭제·공유 참조, 복구 세션에서 안전하게 가능한 처리를 확정한다. 의미가 달라지는 미확정 사항은 시간제한 없는 질문으로 확인한다.
- [x] 편집 버튼/최근 목록이 공통 열기 경로를 사용하도록 구성한다. 미반영 입력을 포함해 판단하며, 같은 레벨은 그대로 둔다.
- [x] 통합 계획의 세 버튼 문구와 저장 범위 안내를 적용한다. 저장 실패·취소·부분 취소 실패 시 기존 화면을 보존한다. 중복 열기 요청을 막는다.

**통과 조건:** 다른 레벨·공유 데이터 및 유효한 이력을 보존한다. 전체 `Discard()` 호출 또는 전체 이력 삭제로 대체하면 실패다. 이 경계가 해결되기 전에는 변경 버리기 기능을 완료로 처리하지 않는다.

## 작업 B — 검색 인덱스와 가상 목록

- [x] 숫자 정확 검색, 포함 범위, 이름 부분 검색, 빈 검색, 잘못된/역전 범위, 중복 번호의 테스트를 작성한다. 숫자 오버플로도 오류 안내로 처리한다.
- [x] 번호 조회와 정렬 메타데이터를 캐시한다. 이름 검색은 메타데이터만 조회한다. 이름/번호/추가/삭제/프로젝트 교체에만 관련 인덱스를 갱신한다.
- [x] UI Toolkit 가상 목록을 적용한다. 재사용 행의 이벤트가 이전 레벨 ID를 열지 않도록 바인딩·해제를 검증한다.
- [x] 왼쪽 영역 안에 검색, 개수, 최근 편집, 현재 레벨 찾기를 배치한다. 상단 공통 툴바 높이를 늘려 보드를 좁히지 않는다.
- [x] 행 클릭은 탐색 강조만 변경한다. 각 행 편집 버튼, 현재 편집 표시, 긴 이름 말줄임/툴팁을 제공한다.
- [x] Enter는 검색 확정만 수행한다. 버튼 포커스·키보드 활성화, 터치 스크롤 중 오작동, 검색 취소/0건에서도 현재 편집 보존을 검사한다.
- [x] 보드 선택/줌에서 목록 키 전량 조합·정렬·행 전량 생성이 재실행되지 않도록 계측한다. 남은 전체 문서 순회 비용은 2단계 항목으로 별도 기록한다.

## 작업 C — 최근 20개와 화면 상태 유지

- [x] 최근 목록의 중복/최대 개수/프로젝트 격리/재실행/삭제 ID 필터/이름 변경 검사를 작성한다.
- [x] 성공한 열기만 MRU 순서로 기록한다. 실패·계속 편집하기·검색·행 탐색은 기록하지 않는다.
- [x] 사용자별 도구 설정으로 원자적 저장한다. 손상 파일은 실제 제작 데이터에 영향 없이 안내하고 원본을 보존한다.
- [x] 프로젝트 키의 경로 정규화와 플랫폼별 대소문자 처리를 검증한다. 같은 프로젝트 ID를 복사한 폴더도 분리한다.
- [x] 최근 드롭다운 선택에도 작업 A의 확인을 적용한다. 공유 초안·튜토리얼 대상 선택 등 기존 전환 제한을 함께 적용한다.
- [x] 같은 프로젝트에서 검색/스크롤 유지, 현재 레벨 찾기, 복구 화면 복원을 연결한다. 목록 설정 저장이 콘텐츠 dirty를 만들지 않게 한다.

## 작업 D — 성능·회귀·UI 확인

- [x] `Tests/README.md`의 기존 실행 방식으로 관련 검사를 수행한다. 새 검사 진입점은 실제 구현 후 실행 기록에 정확히 남긴다.
- [x] 1천/1만 메타데이터 fixture로 최초 인덱스, 검색, 스크롤, 실제 행 개수, 레벨 열기 비용을 분리 측정한다. 준비/워밍업을 제외한 정상 실행 3회 중앙값·p95·최댓값과 환경을 기록한다.
- [x] 계획 목표: 1만 건 검색 중앙값 200ms 이내(입력 debounce 별도), 1280×800/1920×1080에서 생성 행 40개 이내. 미달 시 원인과 잔여 작업을 보고하고 임의로 완료 기준을 낮추지 않는다.
- [x] 목록/인덱스 재구성 횟수를 계측하여 보드 선택·줌 반복에서 0회인지 확인한다. 기존 편집·튜토리얼·공유 적용 성능 검사도 변경 전후 비교한다.
- [x] Editor에서 최소 창 크기, 긴 이름, 결과 없음, 다이얼로그, 드롭다운, 마우스/키보드 및 좁은 화면 레이아웃을 확인한다. 실제 Android 터치 미검증은 구분해 보고한다.
- [x] 신규 테스트 임시 사본만 자동 정리한다. 실제 작업 데이터와 검증 결과는 보존한다. 제품 빌드는 수행하지 않는다.
- [x] 검증 문서에 완료/미완료·측정·제한을 기록하고 2단계 계획·목표·실행문을 작성한다. 다음 단계 구현은 시작하지 않는다.

## 핵심 회귀 조합

| 상황 | 기대 결과 |
| --- | --- |
| A 수정 후 B 행 클릭 | A 유지, 확인창 없음, 탐색 강조만 변경 |
| A 수정 후 B 편집/최근 선택 → 계속 편집하기 | A 입력·선택·스크롤 유지, 최근 기록 변화 없음 |
| 저장하고 B 열기 → 저장 실패 | A 유지, 오류 표시, 최근 기록 변화 없음 |
| A/B/공유 수정 → A만 버리고 B 열기 | A 저장 기준 복원, B/공유 수정·dirty 유지 |
| 위 작업 뒤 Undo/Redo/복구 | 버린 A 변경이 재등장하지 않으며 B/공유 이력 보존 |
| 다른 레벨/공유만 dirty | 현재 레벨을 버릴 필요 없이 열기, 다른 변경 보존 |
| 지연 입력 중 다른 레벨 열기 | 입력 유실 없이 동일 확인 경로 사용 |
| 최근 21번째 서로 다른 레벨 열기 | 가장 오래된 항목만 제거, 재시작 후 동일 순서 |
| 가상 행 재사용 후 편집 | 화면에 표시된 ID의 레벨을 정확히 열기 |
