# 9단계 미션 수집·진행·승패 피드백 Implementation Plan

> 실행 스킬: `superpowers:executing-plans`로 아래 5개 작업을 순서대로 직접 실행한다. 자동 커밋하지 않는다.

**목표:** 실제 수집과 진행 결과를 HUD·시작·라스트팡·승패 표시로 전달한다.
**구조:** 실행 전후 스냅샷과 실제 미션 갱신 기록으로 표시 전용 진행을 만든다. 기존 세션의 시간·취소 경계에 수집 비행과 HUD 강조를 연결하고 규칙 결과는 변경하지 않는다.
**기술:** Unity 6000.3.10f1, C#, SpriteRenderer, 기존 uGUI·UniTask·Addressables·Editor 검사.
**명세:** [목표·완료 조건](../../../Goals/MoonRabbitJunkyard/WorldGameScreen/stage-09-progress-feedback-goal.md).

상태: 5개 작업 구현·Editor 검증·독립 리뷰 수정 후 전체 재검사 완료 (2026-10-01). [실행 기록](../../../Verification/MoonRabbitJunkyard/WorldGameScreen/stage-09-progress.md). 새 검사 349개·관련 회귀 1,526개 통과, 완료 조건 15개별 증거를 기록했다. 빌드·실기기 검증은 수행하지 않았다.

## 공통 제약

목표 문서의 보존·제외 조건을 모든 작업에 적용한다. 먼저 dirty 기준을 기록한다. 이전 드론 시험 방식이나 낙하 속도로 되돌리지 않는다. 필요한 이미지·번들이 없으면 해당 한계를 기록하며 빌드나 개별 텍스처 로드로 우회하지 않는다.

## 우선 검토할 실패 조건

| 조건 | 기대 동작 | 담당 작업 |
| --- | --- | --- |
| 동일 종류 미션이 여러 개이거나 한 공격이 여러 미션에 기여 | 미션별 실제 증가량만 전달하고 같은 기록을 두 번 소비하지 않음 | 1 |
| 8개를 넘는 수집과 연속 연쇄 | 표시 수만 제한하며 수집량 보존, 다음 보드 연쇄를 기다리게 하지 않음 | 2 |
| 시작 표시·수집 중 pause와 화면 회전 | 시간 정지, 재개 후 실제 HUD 아이콘 위치로 도착 | 2·3 |
| 마지막 이동에서 목표 달성 및 라스트팡 | 최종 효과와 HUD 반응 정리 후 결과 패널 한 번 표시 | 4 |
| 비동기 준비 중 취소와 다시하기 반복 | 이전 세션의 콜백·객체·입력 잠금이 새 세션에 남지 않음 | 5 |

각 작업의 검사에 위 조건을 포함한다. 검사 이름·실행 진입점은 구현 시 기존 Editor 검사 구조를 확인한 뒤 실행 기록에 확정하며, 계획상의 예상 검사 수를 실적으로 기재하지 않는다.

## 작업 1 — 실제 진행 기록과 HUD 수치 경계

- [x] 지원 미션 종류별 갱신 지점을 조사한다. 색/장애물/덮개/먼지/회수/곰팡이 및 발전기 간접 제거, 중복 미션의 원점·증가량·시점을 표로 기록한다. 실제 표시 시각 연결 검증은 작업 2에서 수행한다.
- [x] 연출 중 HUD 갱신 중단과 실제 상태가 먼저 확정되는 흐름을 재현한다. 표시의 조기 완료·이중 집계가 실패하도록 검사부터 작성한다.
- [x] 실행 전후 값 또는 실제 일회성 기록으로 미션별 표시 진행을 연결한다. 합계만 있는 변화에 가짜 원점을 만들지 않고 HUD 반응으로 처리한다.
- [x] 무효 행동·중복 대상·복수 미션·초과 진행·초기 완료를 검사한다. 최종 표시 값이 실제 값과 일치해야 한다.

## 작업 2 — 수집 비행·도착·완료 반응

- [x] 기존 미션 아이콘과 원점 이미지를 사용해 실제 변화 시점에서 월드→HUD 비행을 연결한다. UI 변환은 Canvas 카메라/스케일·회전·안전 영역을 반영한다.
- [x] 비행 0.25~0.40초, HUD 강조 0.15초부터 시작한다. 보드 연출과 병행하며 기존 낙하를 기다리게 하지 않는다.
- [x] 미션별 묶음을 사용해 동시 표시 객체를 최대 8개로 제한한다. 증가량과 도착 수치의 일치, 완료 반응 한 번을 검사한다.
- [x] pause·회전·Reset·반복 수집 후 객체 재사용과 원래 UI 축척·색 복원을 확인한다.

## 작업 3 — 이동 수·연쇄·시작 피드백

- [x] 실제 이동 소비와 새 매칭 라운드의 경계를 조사하고 무효 교환·단순 정착에 강조가 발생하면 실패하는 검사를 만든다.
- [x] 이동 수 강조·간단한 연쇄 표시를 기존 UI에 연결한다. 연쇄를 중력 Batch나 표시 프레임으로 계산하지 않는다.
- [x] 준비 완료 후 짧은 시작 표시를 넣고 완료 전 보드 입력을 차단한다. pause·회전·재시작 중 상태가 맞는지 확인한다.

## 작업 4 — 라스트팡·승패·수집 정리

- [x] 실제 마지막 파워와 최종 승패 상태에서 결과 UI가 열리는 경계를 기록한다. 연출 중 조기 결과 패널 노출을 재현 검사로 막는다.
- [x] 기존 라스트팡 파워 표시를 활용하고 최종 보드·수집·HUD 반응이 정리된 뒤 기존 결과 패널을 한 번 표시한다. 추가 규칙 행동을 만들지 않는다.
- [x] 수집 표시 대기를 기존 `IsPresenting`에 무조건 합쳐 다음 연쇄를 직렬 차단하지 않는다. 보드 진행과 최종 결과 준비 경계를 필요한 범위에서 구분한다.
- [x] 승리·이동 소진·마지막 수 성공·라스트팡 복수 미션·재시작·실패·취소를 검사한다.

## 작업 5 — 실제 씬 통합 검수와 인계

- [x] Asset/MemoryPack, 단독 파워·지원 10조합·아이템·자동 연쇄·회수·2×2·레이어를 대표 사례로 검증한다. 미션 종류별 순수 검사는 지원 전체를 다룬다.
- [x] 가로/세로·안전 영역·pause/resume·다시하기 5회·준비 취소·씬 종료/재진입을 확인한다. 풀 개수·소유 핸들·입력 잠금·늦은 콜백·원본 레벨 보존을 감사한다.
- [x] 직접 실행기와 최종 보드·미션·난수·이동 수·공급·승패 동등성을 검사하고 영향받는 기존 검사만 실행한다. 빌드를 내부 호출하는 진입점은 제외한다.
- [x] 시작/수집 출발/도착/완료/라스트팡/결과 캡처와 로그를 남긴다. `Docs/Verification/.../stage-09-progress.md`, `Docs/Guides/.../stage-09-progress-feedback-usage.md`에 실적·한계를 작성하고 목표의 15개 조건에 증거를 대응시킨다.

10단계 소리과 11단계 최종 안정화는 자동으로 진행하지 않는다.
