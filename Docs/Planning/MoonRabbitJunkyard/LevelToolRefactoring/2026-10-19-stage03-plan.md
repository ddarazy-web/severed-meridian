# 레벨툴 리팩토링 3단계 — 기능별 화면 책임 분리

> 실행자는 `superpowers:executing-plans`로 진행한다. 상태: 구현·관련 회귀 완료. 사용자의 3단계 실행 지시에 따라 현재 work 브랜치에서 작업한다. 커밋·푸시는 하지 않는다.

**목표:** 보드 표시·기본 속성·공급·튜토리얼 화면을 독립적인 책임으로 분리하면서 기존 UI와 편집 동작을 유지한다.

**구조:** 화면 조립자는 패널의 생성·갱신·해제를 담당한다. 패널은 현재 편집 세션 조회와 필요한 명령만 받으며, 2단계의 문서 편집 API를 사용한다. 세션·복구 데이터·선택을 패널마다 복제하지 않는다.

**기술:** 현재 UI Toolkit, 공통 Editing/Runtime 서비스, 기존 외부 Tests 하네스. 새로운 프레임워크나 패키지를 추가하지 않는다.

**기준:** [통합 계획](2026-10-19-integrated-plan.md), [3단계 목표](../../../Goals/MoonRabbitJunkyard/LevelToolRefactoring/2026-10-19-stage03-goal.md).

## 전제와 범위

- 2단계 일반 튜토리얼 UI 검사는 개별 항목 PASS 후 Unity 종료가 지연됐다. 3단계 시작 시 이 기준 검사의 종료 상태부터 확인한다. 정상 종료된 10종과 구분하고 종료 문제를 숨기기 위해 assertion을 제거하지 않는다.

- 1단계 `LevelToolBoardInput`은 입력과 제스처 수명주기를 유지한다. 표시 분리 과정에서 입력 규칙을 다시 만들지 않는다.
- 2단계 `AuthoringEditSession.EditLevel`, `LevelDocumentEditing`, `SupplyDocumentEditing`, `TutorialDraftEditing`을 재사용한다.
- UI 구조·이름·USS class·툴팁·단축키·보드 확대 범위를 유지한다. 이번 단계는 시각 디자인 개편이 아니다.
- 메뉴·파일 전달·시험 실행·기록·창 모드·복구 기능 전체를 동시에 재작성하지 않는다. 패널 경계에 연결되는 호출부만 수정한다.
- 파일을 다른 partial 클래스로 옮기는 것만으로 완료하지 않는다. 패널이 다른 패널의 필드나 화면 전체를 받으면 책임 분리로 인정하지 않는다.

## 변경 위치와 책임

기존 경로는 `Assets/Scripts/Features/LevelTool/Runtime/`이며 새 패널은 실제 역할이 모이는 `Presentation/` 아래에 배치한다. 새 폴더와 파일의 meta를 함께 생성하고 기존 에셋 GUID는 유지한다.

| 대상 | 책임 |
|---|---|
| `LevelToolScreen.cs`, `.Layout.cs`, `.Navigation.cs` | 패널 조립·현재 탭·전체 갱신·상태 전환 조정 |
| `.Board.cs`, `.Artwork.cs`, `.FlowOverlay.cs`, `.ConnectionOverlay.cs` | 표시와 편집 호출을 구분해 보드 표시 책임 추출 |
| `.Supply.cs`, `.Shapes.cs` 및 Board의 속성 부분 | 기본 속성·선택 요소·공급 UI 분리. 이미 공통인 편집 규칙 유지 |
| `.Tutorial*.cs` | 조건·대상·공유 흐름·샘플·안내 표시의 소유권과 이벤트 연결 분리 |
| `.MobileLayout.cs`, `.MobileViewport.cs`, `.Recovery*.cs` | 패널 이동·복구 시 연결되는 참조만 조정 |
| 신규 `Presentation/LevelToolBoardView.cs` | 셀/오버레이 표시와 비동기 아트 결과의 화면 수명 관리 |
| 신규 `Presentation/LevelToolPropertiesPanel.cs` | 레벨 기본 속성·선택 요소 속성·미션 UI |
| 신규 `Presentation/LevelToolSupplyPanel.cs` | 일반/튜토리얼 공급 표시와 공통 공급 명령 연결 |
| 신규 `Presentation/LevelToolTutorialPanel.cs` 및 필요 책임별 파일 | 튜토리얼 화면 조정. 조건/대상 편집은 `LevelToolTutorialConditionsPanel.cs`에 분리 |

나머지 튜토리얼 UI의 세부 분리 파일은 시작 시 실제 상태·호출 표를 작성한 뒤 확정한다. 화면 한 개를 위해 의미 없는 인터페이스/상속 체계를 만들지 않는다.

## 상태·인터페이스 계약

| 상태 | 소유자 |
|---|---|
| 프로젝트·열린 폴더·저장 | AuthoringToolWorkspace |
| 콘텐츠·선택 셀·Undo/Redo | AuthoringEditSession |
| 진행 중 포인터·핀치·줌 보정 | LevelToolBoardInput |
| 현재 탭·패널 표시·단축키·전체 모달 | 화면 조립자 |
| 해당 패널의 VisualElement·콜백 | 해당 패널 객체 |
| 공유 튜토리얼 편집 사본 | 기존 SharedTutorialDraft 경로 |

- 각 패널은 `Root`를 노출하고, 명시적인 `Refresh()`와 `Dispose()` 수명주기를 제공한다. 실제 API는 현재 호출부 조사 후 생성자 계약과 함께 계획서에 기록한다.
- 현재 세션은 `Func<AuthoringEditSession>` 같은 좁은 조회로 얻거나 갱신 시 전달한다. 오래된 세션을 콜백에 고정해 프로젝트 전환 후 쓰지 않도록 한다.
- 문서 수정은 공통 명령을 통해 실행하고, 성공/실패 후 갱신과 오류 표시를 화면에 요청한다. 일반 `Action<LevelToolScreen>`이나 모든 상태를 노출하는 거대 context는 금지한다.
- 보드 View는 셀 크기·문서 조회·선택 표시를 받는다. 현재 root/board가 교체될 때 입력 객체의 재연결 순서를 명확히 한다. 뷰 교체로 동일 입력이 두 번 등록되면 안 된다.
- 비동기 아트 로딩은 해제된 패널이나 이전 레벨에 적용되지 않게 기존 취소/버전 확인을 유지한다. 화면 표시만 위해 새 캐시를 추가하지 않는다.
- 필드의 임시 문자열·포커스·지연 입력을 잃지 않도록 기존 입력 확정과 복구 경로를 그대로 연결한다.
- 실제 세 곳 이상 반복되는 필드 생성만 공통화한다. 게임 전체 UI 프레임워크를 만들지 않는다.

## 진행 단위

### 실행 기록과 경계 조사

- 시작 상태: work 브랜치, 작업 트리 깨끗함. 2단계 소스는 현재 HEAD에 반영되어 있다.
- 실행 기록은 이 계획과 검증 문서에 유지한다. 사용자 지시에 따라 커밋 기반 스킬 장부 및 별도 워크트리 전환은 사용하지 않는다.
- 선행 조사: 일반 튜토리얼 UI 검사에서 종료 요청 전후·Play Mode 상태·EditorApplication.Exit 진입을 기록해 종료 지연 위치를 확인한다. assertion은 변경하지 않는다.
- A→B/C 경계: 보드 View는 셀·이미지·흐름/연결 오버레이와 이미지 요청 수명만 소유한다. 패널은 View 필드에 직접 접근하지 않으며 보드 선택 요청은 화면이 연결한다.
- B→C 경계: 일반/튜토리얼 공급은 같은 공급 패널에 편집 대상을 명시해 전달한다. 튜토리얼은 공급 패널 내부를 참조하지 않는다.
- 화면은 AuthoringEditSession과 AuthoringToolWorkspace를 계속 소유한다. 패널의 콜백은 현재 세션을 조회하고, 변경·오류 표시·전체 갱신은 기존 화면 진입점으로 전달한다.
- 수명주기: 화면 OnEnable에서 패널을 생성하고 OnDisable에서 Dispose한다. 보드 Root는 기존 입력 객체에 전달하며, 비동기 이미지 결과는 보드 세대 번호와 해제 여부를 확인한다.

보드 계약: `LevelToolBoardView(VisualElement root, Action<string> show, Action<int> selectVertex, Func<bool> blocked)`는 표시 Root와 이미지 수명을 소유한다. `Refresh(AuthoringEditSession session, string folder, IReadOnlyDictionary<string,JObject> definitions, string layer, float cellSize, LevelToolBoardOverlayState overlay)`는 현재 표시 입력을 받는다. overlay는 흐름/연결/모바일 표시 값만 전달하며 경로 배열은 화면에서 복사한다. `Clear()`는 이전 이미지 요청의 결과 반영을 무효화하고, `Dispose()`는 취소·리소스 해제 후 재사용을 거절한다. 화면은 View 내부 상태를 읽지 않는다. 새 View는 화면/다른 패널 객체를 받지 않는다.

### A. 보드 표시 경계

- [x] 화면·입력·보드 표시의 참조 및 비동기 로딩 수명주기 표를 작성한다.
- [x] Viewport/Touch/Artwork 관련 기존 검사를 실행해 기준을 확보한다. 2단계 Touch 정상 통과 기록과 이번 단계 분리 전 Viewport를 기준으로 사용한다.
- [x] 보드 표시 책임을 View로 분리하고 기존 입력 객체를 연결한다.
- [x] 레벨 전환·비활성화 중 아트 결과, 확대·화면 맞춤·오버레이 선택을 검사한다.

### B. 기본 속성·공급 패널

- [x] 생성자에 필요한 상태 조회·명령·갱신 계약을 기록한다.
- [x] 기본 속성·미션·공급 패널을 분리하고 2단계 API로 연결한다.
- [x] 이름·이동 수·내구도·색·방향·공급 목록 수정의 Undo/Redo를 검사한다.
- [x] 모바일에서 패널을 옮기거나 닫았다 열어도 지연 입력과 선택이 유지되는지 확인한다.

### C. 튜토리얼 패널과 통합

- [x] 조건·대상 편집부터 분리하고 공통 흐름/레벨별 수치/샘플/피커의 적용 대상을 보존한다.
- [x] 패널 간 통신을 화면의 명시적 연결로 정리한다. 패널 간 직접 내부 참조를 제거한다.
- [x] 공유 원본 사본 적용·취소, 보드 대상 선택, 탭 복귀·Undo를 검사한다.
- [x] 전체 UI 회귀와 자체 의존성 검토 후 결과를 보고한다. 4단계 계획·목표·실행문을 작성하되 구현은 자동 시작하지 않는다.

A/B/C는 하나의 3단계 안에서 각각 동작 가능한 상태로 진행하는 구현 단위이며 별도 단계 숫자를 늘리지 않는다.

## 검증과 완료 판단

- 기존 `LevelToolViewportVerification`, `LevelToolInputVerification`, `LevelToolShortcutVerification`, `LevelToolTouchVerification`, `LevelToolAdvancedVerification`의 해당 실행 메서드를 확인해 사용한다.
- 보드 표시의 아트·모바일 튜토리얼 전환은 기존 Artwork/MobileTutorialViewport 검사를 함께 확인한다. 내부 reflection 위치 변경만으로 테스트를 삭제하지 않는다.
- Windows 1280×800 및 기존 네 해상도, 세로/가로 모바일 viewport에서 패널 잘림·겹침·포커스·선택을 확인한다.
- 실행 결과·화면 캡처와 실기기 미검증을 구분한다. 배치 캡처의 스킨 흰색 제한으로 실제 시각 품질을 과장하지 않는다.
- 제품 빌드·커밋·푸시·HTML 갱신·실제 사용자 데이터 변경은 금지한다. 씬/프리팹을 코드로 편집하지 않는다.

## 검토 초점

1. 프로젝트/레벨 전환 후 이전 패널 콜백이 이전 또는 새 문서를 잘못 수정하는가.
2. 패널 갱신이 마지막 지연 입력 문자·포커스·스크롤을 잃는가.
3. 모바일 reparent 또는 재활성화로 이벤트가 중복되는가.
4. 비동기 아트 결과가 해제된 보드에 적용되는가.
5. 공유 튜토리얼 사본과 레벨별 설정이 잘못된 저장 대상에 반영되는가.

### B 구현 계약

- `LevelToolSupplyPanel(Func<AuthoringEditSession>, Action<string,Action<JObject>>, LevelToolSupplyState)`는 세션 조회·기존 편집 명령·공급 추가용 임시 입력만 받는다. `Refresh(JObject, IReadOnlyDictionary<string,JObject>, bool tutorial)`로 일반/튜토리얼 공급 대상을 구분한다. 상태 객체는 화면 재활성화 사이에도 유지하며 문서·선택·Undo는 포함하지 않는다.
- `LevelToolPropertiesPanel(Func<AuthoringEditSession>, Action<string,Action<JObject>>, Func<LevelToolPropertiesOptions>, LevelToolPropertiesActions)`는 기본 속성·선택 요소·미션 UI를 소유한다. Options는 현재 배치 도구/색/방향/줌/시험 설정의 읽기 값이며 원본 상태를 소유하지 않는다. Actions는 색·방향·줌·화면 맞춤·이동 시작·시험 시드/모드에만 한정한다. 파일·복구·다른 패널은 노출하지 않는다.
- 속성 `Refresh(level, definitions, selectedIds, selectionReason)`는 기존 선택 해석 결과를 표시한다. 문서 수정은 기존 Change/EditLevel과 공통 문서 편집 API를 그대로 사용한다.
- 두 패널은 Root/Refresh/Clear/Dispose를 제공한다. 화면 갱신 시 Clear로 이전 세대를 무효화하며 세션/레벨/해제 여부를 함께 검사한다. 패널 Root는 축소하지 않고 기존 ScrollView에 연결한다.
- 필드 공통화는 기존 여러 화면에서 이미 사용하는 Choice/Number와 단순 Button 생성에 한정한다. 기존 Screen의 Choice/Number 전달 함수는 아직 분리하지 않은 흐름·모양·튜토리얼 호출을 보존한다.
### C 구현 계약과 상태 소유권

- `LevelToolTutorialPanel`은 단계·안내·공유 구성 표시·레벨별 바인딩·샘플·공유 파라미터 UI를 조립한다. `LevelToolTutorialConditionsPanel`은 조건 목록·필드와 조건별 대상 편집 표시를 소유한다. 부모가 조건 패널의 Root/Refresh/Clear/Dispose만 사용한다.
- `LevelToolTutorialTargetFields`는 조건과 공유 바인딩에서 실제로 사용하던 대상 필드 구성을 한곳에 둔다. 변경 명령과 선택 칸 조회를 인자로 받아 데이터 소유권을 갖지 않는다.
- `LevelToolTutorialState`는 단계 번호·추가할 조건·선택 샘플·샘플 입력·공유 구성 선택만 보관한다. 화면이 한 인스턴스를 유지하며 재활성화 시 새 패널에 연결한다. 기존 복구 JSON의 tutorialStep/newTutorialCondition 키는 그대로 유지한다.
- `SharedTutorialDraft`의 실제 소유자는 화면이다. 전체 Undo/Redo·저장·이탈 팝업과 같은 사본을 사용하며 패널은 조회, 편집 실행, 사본 시작/적용/버리기 명령만 받는다.
- `LevelToolTutorialActions`는 현재 세션/사본 조회, 기존 Edit/Refresh, 강조 표시 상태, 편집 층 조회, 보드 피커 요청, 공유 사본 명령에 한정한다. 화면 전체, 파일 저장소, 다른 패널 또는 보드 View 내부는 전달하지 않는다.
- `RefreshView`가 화면을 재구성하고 `Clear`가 이전 세대의 콜백을 무효화한다. 현재 세션·레벨·공유 사본 참조도 확인한다. 렌더 중 단계 번호 보정은 새 버튼을 무효화하지 않으며 단계 전환은 화면 갱신 세대로 구분한다.
- 보드 피커의 시작/확정/취소, 강조 오버레이, 공유 사본 이탈 모달은 화면 연결 책임으로 유지한다. 문서 변경은 기존 TutorialDraftEditing과 AuthoringEditSession을 사용한다.
