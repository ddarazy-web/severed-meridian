# 레벨툴 리팩토링 4단계 — 데이터 흐름 회귀와 구조 마무리

> 실행자는 `superpowers:executing-plans`로 진행한다. 상태: 완료. 전송/복구 입력 유실 수정과 통합 회귀·구조 문서화를 마쳤다. 대량 복구 성능은 측정 완료, 최적화는 미수행이다. 하위 에이전트는 별도 승인 없이 사용하지 않는다. 기존 work 브랜치의 사용자 변경을 보존한다.

**목표:** 분리된 레벨툴에서 편집·저장·전달·변환·시험의 연결을 검증하고, 상태 소유권과 기능 확장 위치를 개발 문서로 남긴다.

**구조:** `AuthoringToolWorkspace`와 `AuthoringEditSession`, 기존 저장/변환 서비스를 유지한다. UI는 화면 조립자·보드 입력·보드 View·속성/공급/튜토리얼 패널로 분리된 3단계 결과를 사용한다. 새로운 프레임워크나 파일 형식을 도입하지 않는다.

**기술:** Unity 6000.3.10f1, UI Toolkit, Newtonsoft JSON, MemoryPack, 기존 Tests/Editor 하네스.

**기준:** [통합 계획](2026-10-19-integrated-plan.md), [3단계 검증](../../../Verification/MoonRabbitJunkyard/2026-10-19-level-tool-refactor-stage03.md), [4단계 목표](../../../Goals/MoonRabbitJunkyard/LevelToolRefactoring/2026-10-19-stage04-goal.md).

## 범위와 제약

- 구현 단위는 아래 A/B/C 세 묶음으로 진행한다. 단계 번호를 더 늘리지 않는다.
- 제품 빌드, 커밋·푸시, HTML 매뉴얼 갱신, 코드에 의한 프리팹 편집, 실제 사용자 이력 삭제는 하지 않는다.
- JSON 스키마·ID·저장 위치·MemoryPack 형식·Addressables 키를 변경하지 않는다. 사용자 원본/정식 리소스/선택 원본 설정은 변경하지 않는다.
- 검사는 `Logs/LevelToolRefactorStage04/<고유 실행 ID>/` 등 격리된 경로에서 수행한다. 기존 검사에 하드코딩된 실제 후보 폴더·최신 fixture 포인터·등록 리소스 경로가 있으면 먼저 조사한다. 필요한 시험 입력은 복사하거나 새로 만들고 출력도 격리한다.
- Unity 검사는 하나씩 실행한다. 하네스가 연결되는 동안 Assets뿐 아니라 Tests 원본도 수정하지 않는다. 연결 기록과 복사본이 다르면 보존하고 실제 소유/원본 동일성을 확인한다.
- 일반 튜토리얼 UI 검사에서 사용하는 임시 이력 정리는 제품 복구 성능 해결이 아니다. 복구 부하는 B에서 별도로 측정한다.
- 질문이 필요한 경우 제한시간 없는 문답으로 진행한다.

## 대상과 변경 시작점

| 위치 | 확인할 책임 |
|---|---|
| `Assets/Scripts/Features/LevelTool/Runtime/LevelToolScreen*.cs` | 화면 조립·전체 명령·파일 전달·복구 연결 |
| `Assets/Scripts/Features/LevelTool/Runtime/Presentation/` | 보드와 패널의 표시·콜백·수명주기 |
| `Assets/Scripts/Features/LevelAuthoring/Editing/AuthoringToolWorkspace*.cs` | 프로젝트 저장·열기·복구 소유권 |
| `Assets/Scripts/Features/LevelAuthoring/Editing/AuthoringEditSession.State.cs` | 문서·선택·Undo/Redo 내보내기/복원 |

| `Assets/Scripts/Features/LevelAuthoring/Editor/JsonPackPublication.cs`, `JsonPackRegistration.cs`, `Editor/Import/` | 변환 결과 게시·원본 선택·이력 보호 |
| `Tests/Editor/Features/LevelAuthoring/` | 기존 회귀 재사용 및 실제 부족한 경계 보강 |

실행 시작 시 경로와 실제 호출부를 다시 확인한다. 위 파일 전체를 일괄 수정하라는 의미는 아니다.

## A. 편집에서 시험까지 연결 검증

- [x] 현재 diff·브랜치·기존 검사 입력/출력 경로를 확인하고 원본 및 정식 리소스의 보호 대상을 기록한다.
- [x] 격리된 프로젝트에서 기본 속성·공급·독립 튜토리얼·공유 구성의 레벨별 값을 편집한다. Undo/Redo와 저장 후 재로드가 동일한 JSON 의미를 유지하는지 확인한다.
- [x] ZIP 내보내기→새 작업 폴더 가져오기 후 문서 ID·참조·선택 레벨·튜토리얼 연결을 비교한다. 취소/읽기 실패/저장 실패는 기존 원본을 바꾸지 않아야 한다.
- [x] 같은 스냅샷을 MemoryPack 바이트로 변환하고 격리 출력에 게시한다. 50레벨 구간, 콘텐츠 참조, 원본 작성 자료의 런타임 리소스 제외, 실패 시 이전 출력 복원을 검사한다.
- [x] JSON 입력과 해당 팩 입력의 시험 결과를 비교한다. 공식 게임 진행/저장 데이터는 변경하지 않는다. 기존 게임 시험 검사가 정식 팩을 필요로 하면 사용자 리소스를 덮어쓰지 말고 테스트 주입 경계를 사용하거나 좁게 보강한다.
- [x] 현재 원본·최신 정상 복구/변환 결과를 보호하는 히스토리 정리 검사를 시험 폴더 안에서 수행한다. 실제 사용자 이력 정리는 실행하지 않는다.

기존 검사 후보: `JsonWorkspaceVerification.Run`, `LevelToolTransferRecoveryVerification.RunAll`, `JsonPackConversionVerification.Run`, `JsonPackPublicationVerification.Run`, `ContentImportHistoryVerification.Run`, 기존 팩 시험 검사. 호출 전 fixture와 출력 경로를 읽어 적합한 검사를 선택한다. `ProjectTransferWorkflowVerification.RunWindows`는 실제 파일 선택 창과 후보 폴더를 사용하므로 자동 회귀로 무조건 실행하지 않는다.

## B. 대량 편집 이력의 복구 비용 분리 측정

- [x] UI 검사의 종료 보완과 제품 복구 저장을 구분해, ExportState→ToolDraftStore.Save→Read/복원의 실제 비용을 측정할 작은 검사를 기존 하네스에 둔다.
- [x] 동일한 격리 프로젝트에서 10/30/60회 편집 이력으로 점진 측정한다. 각 표본의 문서 수·Undo/Redo 수·직렬화 크기·경과 시간·프로세스 메모리를 기록한다. 첫 표본부터 과도하면 큰 표본은 실행하지 않는다.
- [x] 측정용 보호 한도는 단일 표본 30초 또는 검사 Unity 작업 메모리 8GiB로 둔다. 한도 도달은 제품 합격 기준이 아니라 PC 자원 보호를 위한 중단 조건이다. 초과 표본은 성공으로 표시하지 않고 확인된 수치와 미완료 범위를 남긴다. 중단 시 정확히 해당 검사 PID만 식별한다.
- [x] 정상 범위 표본은 최종 문서·선택·Undo/Redo와 복원 결과를 비교한다. 이 검사에서는 성공을 만들기 위해 검증 전에 이력을 비우지 않는다.
- [x] 원인과 대응안을 정리한다. 이번 분리에서 생긴 회귀면 해당 변경만 수정한다. 기존 복구 설계의 최적화가 필요하면 별도 후속 범위와 기준을 제안하며 저장 형식 변경이나 이력 축소를 자동 적용하지 않는다.

## C. 구조 문서와 최종 검토

- [x] `Docs/architecture/MoonRabbitJunkyard/level-tool-structure.md`에 실제 폴더 구조, 간단한 의존 다이어그램, 상태 소유권, 생성/갱신/해제 순서를 작성한다.
- [x] 새 기본 속성, 새 공급 설정, 새 튜토리얼 조건을 추가할 때 수정할 위치와 재사용해야 할 편집 API를 예시로 설명한다. 게임 규칙 등록과 편집 UI 등록은 혼동하지 않게 구분한다.
- [x] 1~3단계 분리 때문에 실제로 새로 미사용이 된 경로/중복만 정리한다. 원래 있던 무관한 레거시와 새로운 범용 추상화는 건드리지 않는다.
- [x] A/B/C에서 변경된 경계의 관련 검사만 추가로 실행하고 `git diff --check`, meta GUID 보존, 정식 데이터/리소스/에셋/설정 미변경을 확인한다.
- [x] `Docs/Verification/MoonRabbitJunkyard/2026-10-19-level-tool-refactor-stage04.md`에 실행 명령·로그·수치·실제 기기 미검증을 기록한다. 통합 계획과 목표 상태를 실제 증거에 맞춰 갱신한다.
- [x] 완료 내용·남은 위험·간략한 커밋 메시지를 보고한다. 추가 개선이 필요해도 자동 구현하지 않는다.

## 검증 실행 형식

```powershell
& Tools/Testing/ProjectTests.ps1 -Action Run -Method LevelAuthoring.Editor.LevelToolTransferRecoveryVerification.RunAll
```

위 명령은 경로/fixture 안전성을 확인한 뒤 실행할 기존 검사 예시다. 제품 빌드 명령이 아니며 전체 검사를 한꺼번에 실행하는 명령도 아니다.

## 검토 초점

1. 다른 프로젝트로 이동한 뒤 이전 UI 콜백이 새 문서에 쓰는지.
2. ZIP 취소/실패 또는 변환 중단 시 기존 원본과 최신 정상 결과가 보존되는지.
3. 공유 사본·레벨별 설정·복구본의 저장 대상이 섞이지 않는지.
4. 대량 복구 부하를 UI 테스트의 이력 정리로 감추지 않는지.
5. 구조 문서가 실제 타입과 의존 방향을 설명하며, 남아 있는 화면 책임도 솔직하게 기록하는지.
