# 레벨툴 리팩토링 2단계 — 문서 편집 경계 정리

> 실행자는 `superpowers:executing-plans`로 진행한다. 상태: 구현 완료. 회귀 10종 정상 통과, 일반 튜토리얼 UI는 개별 항목 통과 후 종료 미확인. 상세 제한은 검증 기록을 참조한다.

**목표:** 화면에 남은 JSON 쓰기 규칙을 기존 문서 편집 기능으로 모으고, 사용자 동작당 Undo 단위와 실패 시 원상태 보존을 유지한다.

**구조:** `AuthoringEditSession`은 변경 트랜잭션을, `LevelDocumentEditing` 및 기존 기능별 Editing 클래스는 문서 변경 규칙을 소유한다. 화면은 사용자 입력과 갱신만 조정한다. 이미 공통화된 튜토리얼 편집·클립보드 경로는 재사용한다.

**기술:** 기존 C#, Newtonsoft JSON, 외부 테스트 하네스. 새 패키지·asmdef·프레임워크 없음.

**기준:** [통합 계획](2026-10-19-integrated-plan.md), [2단계 목표](../../../Goals/MoonRabbitJunkyard/LevelToolRefactoring/2026-10-19-stage02-goal.md).

## 확인된 출발점

- `LevelToolScreen.Change`는 선택 레벨의 schemaVersion 5 확인과 `Session.Apply` 호출을 수행한다.
- `LevelToolScreen.Board.cs`는 레벨 이름·번호·이동 횟수·색상, 선택 요소 내구도·색·방향을 직접 JSON에 쓴다.
- `BoardTouch.cs`는 선택 영역 배치와 다른 층 보존 규칙을 직접 수행한다. 2×2 요소를 작은 요소로 교체할 때 원본 선택을 기준으로 대상 중복을 제거하는 의미를 보존해야 한다.
- `LevelDocumentEditing`, `MissionDocumentEditing`, `SupplyDocumentEditing`, `FlowDocumentEditing`, `ConnectionDocumentEditing`이 이미 존재한다. 이 규칙들을 다시 만들지 않는다.
- `TutorialDraftEditing.EditLevel/EditFlow/EditFlowSteps`는 편집 사본을 사용해 필요한 tutorial 필드만 반영한다. 튜토리얼 화면의 typed setter 자체를 JSON 직접 쓰기로 오인하지 않는다.

모든 대상 파일을 반드시 수정하는 것은 아니다. 호출을 기존 서비스에 위임하는 경로는 유지하고, 직접 JSON 쓰기·스키마 검사·중복 변경 규칙이 있는 부분만 수정한다. 저장소·씬·프리팹·빌드 설정은 수정하지 않는다.

## 편집 계약

1. `AuthoringEditSession.EditLevel(string label, Action<JObject> edit)`를 기존 `Apply` 위에 추가한다. 선택 레벨의 기존 형식 제한을 이 경로에서 처리한다. 일반 문서 전체에 쓰는 `Apply`는 유지한다.
2. `LevelDocumentEditing`에 필요한 레벨 속성 변경 함수를 추가한다. 후보 계약은 `SetName(JObject level, string value)`, `SetNumber(JObject level, int value)`, `SetMoveCount(JObject level, int value)`, `SetColorEnabled(JObject level, string color, bool enabled)`이다. 동일 역할의 기존 함수가 발견되면 그 함수를 사용한다.
3. 요소 속성은 인스턴스 ID를 기준으로 변경한다. `SetElementDurability(JObject level, string instanceId, int value)`와 `SetElementAppearance(JObject level, string instanceId, string color, string direction)`를 기존 정의·호환 규칙에 맞춰 제공한다. 별도의 요소 사본을 화면에 장기 보관하지 않는다.
4. 선택 배치·교체는 기존 Place/Erase/Clipboard를 재사용하는 일괄 명령으로 이동한다. 호출부 조사 후 정확한 인수를 문서에 기록한다. 2×2 원본의 중복 점유 칸, 층 보존과 오류 조건은 기존 동작과 같아야 한다.
5. 화면의 `Change`는 갱신·오류 표시를 위한 얇은 연결로 남길 수 있다. JSON 키·배열 조작·스키마 판정은 그 내부에서 제거한다. 단순 데이터 읽기를 모두 DTO로 바꾸지 않는다.
6. 한 번의 사용자 동작은 기존과 동일한 한 번의 Undo 단위다. 하위 함수를 호출할 때 중첩 Apply 또는 여러 Undo를 만들지 않는다.
7. 작성 중 허용되던 불완전한 문서를 새 setter에서 임의로 거부하거나 자동 보정하지 않는다. 저장·시험 시 기존 검증을 유지한다. 기존 UI에 있던 clamp와 오류 메시지의 의미도 유지한다.
8. 튜토리얼은 이미 있는 typed draft 편집 경계를 유지한다. 직접 JSON 쓰기가 없다면 확인 결과만 기록한다. 공유 흐름 수정과 레벨별 수치 수정의 적용 대상을 바꾸지 않는다.

## 실행 순서

### 조사 결과와 확정 계약

| 경로 | 분류·조치 |
|---|---|
| Screen.Change | schemaVersion 검사와 Apply를 `AuthoringEditSession.EditLevel`로 이동 |
| Board 기본·선택 속성 | JSON setter를 LevelDocumentEditing에 이동. 음수 초안 등 기존 허용 범위 유지 |
| Board 영역 배치·삭제 / BoardTouch 선택 교체 | 공통 PlaceSelection/EraseSelection/PlaceOnLayer로 이동. 각 UI의 교체 의미는 유지 |
| Screen/Shapes의 새 레벨 template.catalogId | `LevelToolDocuments.NewLevel(catalogId)`로 이동 |
| Board 형식 전환 | `LevelToolDocuments.UpgradeSelectedLevel(session)`로 이동. 현재 선택 문서를 다시 읽음 |
| Supply | 신규 고정 생성구·항목 추가·항목 수정·삭제/이동을 SupplyDocumentEditing으로 이동 |
| Flow/Connections | 이미 전용 Editing 함수에 위임. 선택·경로 임시 상태와 조회 코드는 유지 |
| Tutorial* | typed TutorialDraftEditing/SharedTutorialDraft 경로 사용. JSON은 picker의 임시 상태이며 레벨 JSON 직접 쓰기 아님 |
| Recovery/RecoveryInputs, 시험 기록 | UI 복구·출력 문서이며 레벨 콘텐츠 편집 아님. 변경 제외 |
| Shapes 이름·생성·삭제 | 기존 DocumentEditing/ShapeDocumentEditing 재사용. 이름 입력 검증과 읽기 UI 유지 |

선택 API는 `PlaceSelection(JObject level, IReadOnlyDictionary<string,JObject> definitions, string definitionId, IEnumerable<int> cells, bool replace, string color, string direction, string protectedLayer = null)`, `PlaceOnLayer(JObject level, IReadOnlyDictionary<string,JObject> definitions, string definitionId, int cell, bool replace, string layer, string color, string direction)`, `EraseSelection(JObject level, IReadOnlyDictionary<string,JObject> definitions, string layer, IEnumerable<int> cells)`로 확정한다. protectedLayer가 지정된 터치/작업 메뉴는 다른 층을 보존하며 원본 본체별 교체 대상 중복을 제거한다. 일반 영역 배치와 마우스는 기존 Place 의미를 유지한다. 원자성은 외부 세션 트랜잭션이 보장한다.

공급 API는 `PlaceTutorialSources(level, cells)`, `AppendItem(level, definitions, indices, definitionId, count, color, direction, durability)`, `SetItemProperty(level, definitions, sourceIndex, itemIndex, field, value)`, `ReorderItem(level, definitions, sourceIndex, itemIndex, remove)`를 추가해 기존 SetItems 검증을 재사용한다. 튜토리얼 조회용 사본은 `TutorialPreview(level)`로 제공한다. 문자열 field는 기존 공급 편집 API 관례를 유지하며 신규 범용 JSON 경로 편집기를 만들지 않는다.

진행 원칙: 기존 1단계 변경은 사용자에 의해 스테이징된 상태이므로 인덱스를 조작하지 않는다. 이번 변경은 현재 work 브랜치의 작업 트리에만 추가한다. 이전 테스트 fixture는 읽기만 하며 신규 테스트는 Logs 아래 격리된 프로젝트를 생성한다.

1. [x] 모든 `Session.Apply`, `Change`, JSON 할당 호출을 읽어 직접 쓰기/기존 Editing 위임/typed tutorial 편집으로 분류하고 목록을 계획서에 기록한다. 선택 배치 API의 정확한 계약을 확정한다.
2. [x] 기존 관련 검사를 실행해 변경 전 JSON 의미·Undo 횟수·오류 시 상태를 확보한다. 신규 검사는 정상 편집, 실패하는 영역 배치, 다른 층 보호, 무변경 조작을 다룬다.
3. [x] 레벨 기본 속성과 공통 형식 판정을 이동하고 해당 UI를 연결한다. 이름·번호·이동 횟수·색 선택 및 저장 재로드 검사를 수행한다.
4. [x] 선택 요소 속성·영역 배치·교체·삭제 규칙을 이동한다. 기존 클립보드와 흐름·공급·연결 편집을 재사용하고 남은 JSON 직접 쓰기를 정리한다.
5. [x] 튜토리얼 공유 흐름·레벨별 조건 값·Undo가 기존과 같은지 확인한다. 규칙이 이미 공통에 있으면 불필요한 래퍼를 추가하지 않는다.
6. [ ] 관련 UI 입력과 문서 편집 검사를 통합 실행하고 저장→재로드 JSON 의미를 비교한다. 기존 사용자 작업 데이터는 검사에 쓰지 않고 격리된 복사본으로 수행한다.
7. [x] 변경·검증·잔여 직접 쓰기와 이유를 보고한다. 3단계 계획·목표·실행문을 작성하되 구현은 시작하지 않는다.

검사는 `Tools/Testing/ProjectTests.ps1 -Action Run -Method <실제 진입점>`을 사용한다. 구현 시 각 파일의 namespace와 실행 메서드를 확인해 정확한 명령을 기록한다. 제품 빌드는 실행하지 않는다.

## 검토 초점

- 영역 배치 중 마지막 칸에서 실패해도 앞 칸 변경이 남지 않아야 한다.
- 2×2 교체는 원본 인스턴스당 한 번이며, 다른 층을 지우지 않아야 한다.
- 편집 중 유효하지 않은 값의 허용 시점과 저장 시 검증이 달라지지 않아야 한다.
- 레벨 전환 후 이전 레벨 참조에 변경을 쓰지 않아야 한다.
- 공유 튜토리얼 수정을 레벨별 값 변경으로, 또는 그 반대로 바꾸지 않아야 한다.

커밋·푸시, 제품 빌드, HTML 매뉴얼 갱신, 실제 이력 삭제는 금지한다. 소스 구조 정리 외의 UX·게임 규칙 변경은 별도 작업으로 남긴다.
