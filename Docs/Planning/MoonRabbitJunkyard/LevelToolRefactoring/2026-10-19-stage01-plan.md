# 레벨툴 리팩토링 1단계 — 보드 입력 분리

> 실행자는 `superpowers:executing-plans`로 진행한다. 상태: 2026-10-19 구현·자동 검증 완료. 실기기·제품 실행 파일 수동 검사는 별도.

**목표:** 보드 제스처와 이벤트 수명주기를 분리하면서 기존 편집 UX를 보존한다.

**구조:** `LevelToolScreen`이 입력 객체를 생성·해제한다. 입력 객체는 포인터의 임시 상태만 소유하고, 보드 편집·선택은 기존 세션 경로에 위임한다.

**기술:** 기존 UI Toolkit과 외부 Tests 하네스. 새 라이브러리 없음.

**기준:** [통합 계획](2026-10-19-integrated-plan.md), [목표·완료 조건](../../../Goals/MoonRabbitJunkyard/LevelToolRefactoring/2026-10-19-goals.md).

## 변경 후보와 책임

- 수정: `Assets/Scripts/Features/LevelTool/Runtime/LevelToolScreen.cs` — 입력 객체 생성·해제 및 레벨 전환 시 취소 연결.
- 수정: 같은 폴더의 `LevelToolScreen.BoardTouch.cs` — 포인터/휠 등록과 제스처 처리 이동. 툴바 생성과 기존 편집 의미는 유지.
- 호출부 확인: `LevelToolScreen.Board.cs`, `LevelToolScreen.MobileInput.cs`, `LevelToolScreen.MobileViewport.cs`, `LevelToolScreen.Shortcuts.cs` — 보드 입력과 공유하는 부분만 조정.
- 생성: 같은 Runtime 폴더의 `LevelToolBoardInput.cs`와 `.meta` — 등록·해제·취소 및 제스처 임시 상태. Unity 직렬화 필드는 이동하지 않는다.
- 검사: `Tests/Editor/Features/LevelAuthoring/LevelToolInputVerification.cs`, `LevelToolTouchVerification.cs`, `LevelToolViewportVerification.cs`, `LevelToolShortcutVerification.cs`의 관련 사례. 내부 접근 테스트가 있다면 행동 검증을 유지하며 접근 지점만 바꾼다.

## 계약

- `internal sealed class LevelToolBoardInput : IDisposable`.
- `Attach()`는 현재 root와 보드 viewport에 한 번만 등록한다.
- `Cancel()`은 진행 중 포인터·롱터치·핀치 상태를 해제하고 문서를 변경하지 않는다.
- `Dispose()`는 등록한 콜백·예약 작업을 해제하며 재호출해도 편집을 발생시키지 않는다.
- 생성 시 실제 입력 코드가 요구하는 최소 조회·명령을 전달한다. `LevelToolScreen` 전체를 넘기지 않는다. 구체 생성자 인수는 아래 1번 호출부 표로 확정한다.
- 선택 셀·문서·Undo 상태의 소유자는 `AuthoringEditSession` 그대로다. 화면과 입력 객체 양쪽에 같은 제스처 상태를 두지 않는다.

## 실행 순서와 검사

### 구현 전 확정한 소유권·계약

| 항목 | 소유자 / 연결 |
|---|---|
| 포인터 목록·시작 위치·후보 셀·영역 시작·취소 상태 | `LevelToolBoardInput` |
| 줌 보정 예약·피벗·진행 여부 | `LevelToolBoardInput` |
| 선택 도구·추가 선택·교체 옵션 | 화면의 복구 가능한 설정 그대로 유지 |
| 문서·선택·Undo | `AuthoringEditSession` 그대로 유지 |
| Android 뒤로가기·앱 일시중지·포커스 | 화면이 입력 객체의 Tick/Reset을 호출 |
| 화면 해제 | 입력 Dispose로 포인터 캡처·모든 입력 콜백·줌 예약 해제 |

생성자는 root/scroll/board 참조와 `Func<Context>` 조회, 셀 실행·꼭짓점 선택·셀 선택 및 갱신·작업 메뉴 열기·힌트 갱신·크기 적용 콜백만 받는다. Context는 입력 허용 여부, 현재 도구, 피커/연결 편집 여부, 모바일 여부, 셀 크기, 교체 옵션의 읽기 스냅샷이다. 화면 객체 자체는 전달하지 않는다.

마우스 셀 이벤트는 보드 입력 객체에서 처리한다. 셀 내부 요소의 클릭만 받아 연결 오버레이의 독립된 꼭짓점 조작은 보존한다. `Zoom`은 기존 화면 툴바에서도 호출할 수 있게 하며, 화면은 실제 보드 재그리기를 담당한다.

진행 기록: 기존 work 브랜치를 유지하며 커밋하지 않는다. 승인된 범위가 기존 작업 경로이므로 별도 worktree를 만들지 않는다. 동작 보존 검사는 변경 전후 실행하고, 해제되지 않은 geometry 콜백은 별도 실패 재현 검사로 확인한다.

1. [x] 포인터·휠·예약 작업·등록/해제 경로를 읽고 상태 소유자와 호출부 표를 이 문서에 보완한다. 이 단계에서 생성자 계약을 확정한 뒤 소스를 수정한다.
2. [x] 기존 검사 메서드의 실제 namespace와 진입점을 확인해 입력·뷰포트 검사를 실행한다. 기존 실패가 있으면 리팩토링 회귀와 구분해 기록한다.
3. [x] 재활성화 후 1회 입력이 1회만 처리되는 사례, 드래그 중 레벨 전환/모달 진입 후 후속 편집이 없는 사례를 기존 검사에 추가한다. 현재도 통과하는 동작 보존 검사는 억지로 실패시키지 않는다.
4. [x] 입력 객체로 상태와 처리기를 이동한다. 익명 이벤트·예약 작업도 해제 가능하도록 소유권을 명시한다. 보드 도구 버튼, 선택 의미, 확대 수치는 바꾸지 않는다.
5. [x] 기존 마우스/터치, Ctrl+휠과 일반 휠, 키보드, 레벨 전환, 화면 재활성화 검사를 수행한다. 화면 배치 및 32~144 확대 범위를 보존한다.
6. [x] diff로 범위 밖 파일·사용자 데이터 변경이 없는지 확인하고 결과를 보고한다. 2단계 상세 계획·목표·실행문을 작성하되 구현은 시작하지 않는다.

검사 실행 형식: `& Tools/Testing/ProjectTests.ps1 -Action Run -Method '<실제 namespace.Type.Method>'`. 기존 진입점 확인 후 정확한 명령과 결과 경로를 보고서에 기록한다. Unity 에디터가 열려 있으면 임의 종료하지 않는다. 테스트 하네스 실행은 제품 빌드와 구분한다.
