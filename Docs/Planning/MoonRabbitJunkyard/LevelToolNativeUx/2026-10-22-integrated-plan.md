# Android·Windows 레벨툴 UX 개선 통합 계획

> 구현 담당: `superpowers:executing-plans`로 단계별 구현·검증한다. 이 문서는 계획이며 구현 완료 보고가 아니다.

**목표:** 처음 사용하는 사람도 프로젝트 생성, 첫 레벨 편집, 미션·튜토리얼 작성, 시험·저장을 쉽게 찾을 수 있게 한다.

**구조:** 기존 Unity 레벨툴의 편집 세션·명령·파일 입출력을 재사용한다. 화면 흐름은 공통으로 관리하고 Windows 폴더 선택과 Android 내부 프로젝트·문서 선택은 기존 플랫폼 구현에 위임한다. HTML 목업은 화면과 동작의 참고 자료이며 브라우저 제품으로 배포하지 않는다.

**기술:** Unity 6000.3.10f1, 기존 UI Toolkit 레벨툴, JSON 제작 데이터, 기존 MemoryPack 시험·변환, UniTask.

**근거:** [확정 UX 및 웹 철회](../level-tool-web-ux-decisions-2026-10-22.md), [HTML 목업](../../../MoonRabbitJunkyard/Mockups/level-tool-web.html).

## 적용 원칙

- 지원 제품은 Android Level Editor와 Windows Level Editor다. 웹 프로필·서버·계정·동기화를 추가하지 않는다. 게임 앱 제품 구성은 변경하지 않는다.
- 기존 JSON/ZIP과 레벨 1~15의 튜토리얼을 보존한다. 저장 형식 개편과 전면적인 아키텍처 교체는 범위 밖이다.
- 레벨 편집은 메모리+dirty로 처리하고 명시적 저장을 유지한다. 프로젝트 컨테이너 생성 및 설정 저장과 반복 편집 자동 저장은 구분한다.
- 기존 경량 목록, 검색, 재사용 셀, 프로젝트별 최근 편집 20개를 재사용한다. 화면 표시를 위해 전체 레벨 JSON을 열거나 전체 문서를 복제하지 않는다.
- UI 때문에 기존 기능을 삭제하지 않는다. 고급 기능은 별도 메뉴로 정리하되 접근 경로를 보존한다.
- 현재 스킨·아틀라스와 실제 블록·장애물 이미지를 재사용한다. 프리팹을 편집하는 Editor 자동 생성 스크립트를 추가하지 않는다.
- HTML 매뉴얼 갱신, 커밋·푸시는 하지 않는다. 제품 빌드·설치·실기기 조작은 별도 승인 범위로 구분한다.
- 질문은 시간제한 없는 일반 문답으로 진행한다. 답이 필요한 핵심 결정은 임의 확정하지 않는다.

## 네이티브로 다시 정리한 UX

| 영역 | 적용할 동작 |
|---|---|
| 시작 | 새 프로젝트 / 프로젝트 열기 / ZIP 가져오기 / 최근 프로젝트를 시작 화면에서 구분 |
| 생성 | 프로젝트 이름을 먼저 입력. Windows는 기존 폴더 선택으로 저장 위치 지정, Android는 기존 내부 프로젝트 저장소 사용. 취소·중복 위치에 대한 안내 제공 |
| 첫 레벨 | 프로젝트 생성 후 레벨 0개 상태와 ‘첫 레벨 만들기’. 9×9 기본 또는 현재 레벨 복제, 번호·이름 제안 |
| 레벨 전환 | 행의 ‘편집’으로 열기. 미저장은 ‘저장하고 열기 / 현재 레벨 변경 버리고 열기 / 계속 편집’. 현재 레벨 외 변경은 유지 |
| 화면 | 넓은 화면은 좌우 패널, 좁은 세로는 하단 패널, 좁은 가로는 측면 패널. 최소한의 상단과 보드 중심 구성 |
| 보드 | 선택·배치·지우기·이동 구분. Ctrl+휠·두 손가락은 보드만 확대/축소. 메뉴 크기 유지, 핀치 중 오배치 방지 |
| 소재 | 분류·검색·최근 사용, 이미지와 이름, 자동 편집 층 선택. 지우개는 해당 층만, 전체 삭제는 별도 |
| 집중 | 패널 숨김/복원, 도구·실행 취소 접근 유지. 재시작은 일반 화면으로 시작 |
| 미션 | 목적→대상→수량, 쉬운 요약과 수정 연결. 설정 완료와 실제 시험 완료를 구분 |
| 튜토리얼 | 목적→보드 선택→필수 설정 팝업→단계·공급→시험→완료. 내부 조립식 구조 유지 |
| 파일 | 기존 Windows 폴더와 Android 문서 선택기를 사용. 프로젝트 ZIP 내보내기로 백업·기기 이동. 자동 동기화 없음 |

목업의 가상 데이터·가짜 저장·시험 버튼은 실제 구현의 근거로 사용하지 않는다. 목업 배율 50~300%는 참고값이며 실제 보드 확대 상한을 임의로 축소하지 않는다. Windows 창 비율·최소 크기·Alt+Enter/F11·위치 복원 정책은 유지한다.

## 총 4단계

| 단계 | 작업 단위 | 사용자에게 보이는 결과 | 핵심 검증 |
|---|---|---|---|
| 1. 시작과 첫 레벨 | 시작 화면, 이름 중심 프로젝트 생성, 빈 프로젝트, 첫 레벨/복제, 기존 최근 목록·dirty 전환 연결 | 메뉴를 찾아 헤매지 않고 첫 9×9 보드까지 도달 | 생성·취소·빈 프로젝트 재열기·레벨 전환·기존 데이터 보존 |
| 2. 보드 중심 편집 | 상단 정리, 반응형 패널, 집중 모드, 소재·층별 도구, 우클릭/롱터치, 보드 전용 줌, 단축키 표시 | PC와 휴대폰 모두 보드 공간을 확보하고 실수 없이 배치 | 네 화면 크기, 회전·키보드·핀치·패널 복원, 목록/편집 성능 회귀 |
| 3. 미션과 튜토리얼 | 제작 체크리스트, 쉬운 미션 요약, 목적 기반 튜토리얼 조립, 필수값 팝업, 완료/전체 취소 경계 | 기존 튜토리얼의 목적·순서를 이해하고 직접 조립 | 매칭·생성/사용·조합·내구도·공급, 연결 오류, 기존 수정 취소 복원 |
| 4. 시험·저장과 통합 검증 | 시험 복귀 상태, 오류 수정 연결, ZIP 백업/이동 흐름, 전체 기능 접근·플랫폼 회귀 | 만들기→시험→저장→다른 기기에서 열기까지 일관된 흐름 | JSON/ZIP 왕복, 원본 불변, 취소·실패, 승인 시 실제 Windows/Android 시험 |

각 단계는 사용할 수 있는 상태로 끝낸다. 뒤 단계 기능은 기존 UI를 유지하고, 새 흐름이 검증된 뒤 해당 중복 UI만 정리한다. 단계 2~4의 상세 문서는 직전 단계 결과를 반영해 작성하며 지금 미리 고정하지 않는다.

## 튜토리얼의 중요한 보존 조건

- 동작·조건·대상·수치·안내·공급을 조립한다. 장애물마다 전용 구현을 추가하지 않는다.
- 대상을 먼저 고르고 필수 수치만 팝업에서 설정한다. 대상 종류에 따라 불필요한 칸 선택은 생략한다.
- 단계는 쉬운 문장, 위치 보기, 수정, 여기까지 시험으로 표시한다. 시험은 처음부터 선택한 단계까지 진행한다.
- 완료/전체 취소 전 일반 작업 전환을 막는다. 신규 취소는 새 튜토리얼 제거, 기존 수정 취소는 시작 상태 복원. 함께 변경한 보드·공급도 복원한다.
- 완료는 메모리 편집 반영이다. 필수값·연결 검사는 필수, 실제 플레이 시험은 선택이며 미시험 상태를 표시한다.
- 다른 레벨·공유 데이터의 기존 변경을 지우지 않는다. 이 경계는 3단계의 핵심 회귀 검사다.

## 검증 및 단계 인계

- 기존 검사 진입점은 `Tools/Testing/ProjectTests.ps1` 및 `Tests/Portable`에서 확인해 관련 범위만 실행한다. 명령/검사 이름을 존재 확인 없이 만들어 보고하지 않는다.
- UI 검사는 Windows 1280×800·1440×900, 휴대폰 세로 390×844·가로 844×390, 태블릿 820×1180 상당의 가용 영역에서 수행한다. Android는 실제 픽셀보다 Canvas/UI 논리 크기·밀도·안전 영역을 함께 기록한다.
- 시뮬레이션 통과를 Android 실기기 통과로 표시하지 않는다. 기존 사용자 프로젝트 대신 격리된 검사 사본을 사용한다.
- 목록 진입 시 전체 JSON 읽기 여부, 반복 화면 갱신과 문서 복사 비용을 변경 전후 같은 조건에서 확인한다. 가상화 셀 수가 전체 레벨 수에 비례하지 않아야 한다.
- 매 단계 종료 시 변경·검증·미검증·남은 문제를 보고하고 다음 단계 계획/목표/복사용 실행문을 작성한다. 자동으로 다음 단계 구현에 들어가지 않는다.
- 단계 구현 완료 보고에 간략한 복사용 커밋 메시지를 제공하되 실제 커밋·푸시는 하지 않는다.

## 검토 위험

1. 레벨 0개에서 선택 ID·최댓값 계산·미리보기·저장이 실패하는 경로: 1단계에서 검사.
2. 목록 갱신 때문에 전체 JSON을 읽거나 공유 데이터 dirty가 사라지는 경로: 1·2단계에서 검사.
3. 모바일 키보드·회전·팝업이 완료/취소 버튼을 가리는 경로: 각 단계 신규 화면 및 4단계에서 검사.
4. 튜토리얼 전체 취소가 작업 이전의 편집까지 지우는 경로: 3단계에서 검사.
5. 시험·ZIP 오류가 미저장 작업을 덮어쓰는 경로: 4단계에서 검사.
