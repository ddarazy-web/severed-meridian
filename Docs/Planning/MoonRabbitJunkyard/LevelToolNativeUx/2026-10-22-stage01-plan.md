# 네이티브 레벨툴 UX 1단계 계획 — 시작과 첫 레벨

> 구현 담당: `superpowers:executing-plans`로 아래 작업과 검증을 수행한다. 상태: 2026-10-22 구현 및 Editor 검증 완료. 실기기/운영체제 입력 검증은 보고서의 제한 참고.

**목표:** 사용자가 시작 화면에서 프로젝트를 생성하거나 열고 첫 레벨을 명시적으로 만들어 편집할 수 있게 한다.

**구조:** 기존 Workspace와 AuthoringEditSession을 데이터 소유자로 유지하고 시작/빈 프로젝트/편집 상태만 화면에서 구분한다. 저장·ZIP·목록·dirty 명령은 기존 경로를 호출한다.

**기술:** 기존 Unity UI Toolkit, JSON, 플랫폼별 파일 선택, UniTask.

**근거:** [통합 계획](2026-10-22-integrated-plan.md)의 공통 제약과 [확정 UX](../level-tool-web-ux-decisions-2026-10-22.md)의 최신 플랫폼 결정.

## 확인한 현재 코드와 변경 경계

| 대상 | 확인 내용 / 이번 책임 |
|---|---|
| `Assets/Scripts/Features/LevelTool/Runtime/LevelToolDocuments.cs` | `NewProject()`가 레벨을 자동 생성함. 이름을 받는 빈 프로젝트 구성으로 변경하며 기존 호출부를 확인 |
| `LevelToolScreen.cs` | `AddLevel()`의 `Max()` 및 선택 레벨 카탈로그 접근이 레벨 존재를 전제로 함. 빈 상태·명시적 번호/이름·복제 처리 |
| `LevelToolScreen.Storage.cs` | 현재 폴더 선택 중심 생성. 이름 입력→플랫폼 저장 위치→기존 Workspace 연결 |
| `LevelToolScreen.Layout.cs`, `Navigation.cs`, `Refresh.cs` | 시작/빈 상태 표시, 기존 편집기 진입. 전체 보드 레이아웃 개편은 2단계 |
| `LevelToolScreen.LevelBrowser.cs`, `ManualSave.cs`, `FileTransfer.cs` | 경량 목록·최근 편집·dirty 확인·ZIP 명령 재사용 |
| `LevelToolScreen.MobileLayout.cs`, `MobileInput.cs`, `LevelToolProjectAccess.cs` | 새 화면의 Android 가용 영역, 뒤로가기·키보드·내부 프로젝트 접근 |
| `Assets/Scripts/Features/LevelAuthoring/Editing/AuthoringEditSession.cs` 및 연결된 Workspace/DocumentEditing | 레벨 0개 생성·저장·재열기 지원 범위만 점검·수정 |

별도 시작 화면 코드가 필요하면 같은 Runtime 기능 폴더에 책임을 한정한 `LevelToolScreen.Start.cs`로 분리한다. 새 전역 관리자나 두 번째 편집 세션은 만들지 않는다. 기존 프리팹 자동 생성/편집 코드를 추가하지 않는다.

## 작업 A — 빈 프로젝트와 첫 레벨 데이터 경계

- [x] 관련 기존 검사와 호출부를 찾아 레벨 0개 생성/재열기, 번호 제안, 첫 레벨 추가의 실패 사례를 먼저 확보한다.
- [x] 이름 있는 프로젝트를 레벨 없이 생성한다. 기존 기본 정의·리소스 참조는 유지한다.
- [x] 레벨 0개에서는 보드·속성·시험을 비활성화하고 새 레벨 만들기를 허용한다. 빈 프로젝트가 손상된 것으로 오인되지 않게 한다.
- [x] 번호는 빈 프로젝트에서 1, 기존 목록에서는 메타데이터로 미사용 다음 번호를 제안한다. 이름 기본값은 ‘레벨 N’. 충돌·유효하지 않은 번호는 생성 전에 안내한다.
- [x] 기본 레벨은 9×9와 기존 공급 기본값을 사용한다. 현재 레벨이 없는 경우 복제를 제공하지 않는다. 복제는 보드·미션·이동 횟수·튜토리얼을 보존하며 식별자는 기존 복제 로직을 따른다.
- [x] 빈 프로젝트와 새 레벨의 저장/재열기, 기존 레벨 사본 비교 검사를 통과한다. 마지막 레벨 삭제 정책 변경은 이번 범위에 포함하지 않는다.

## 작업 B — 시작 화면과 프로젝트 진입

- [x] 프로젝트가 없을 때 ‘새 프로젝트 / 프로젝트 열기 / ZIP 가져오기 / 최근 프로젝트’를 표시한다. 편집 중에는 프로젝트 메뉴에서 다시 접근할 수 있게 한다.
- [x] 프로젝트 생성은 이름부터 입력한다. Windows는 기존 폴더 선택으로 저장 위치를 지정하고 Android는 기존 앱 내부 프로젝트 저장소를 사용한다. 기존 폴더 덮어쓰기는 임의로 허용하지 않는다.
- [x] 최근 프로젝트는 기존 기록을 재사용한다. 기록이 없으면 명확한 빈 안내를 표시한다. 경로가 없거나 접근이 실패하면 이유와 다시 열기 경로를 제공한다.
- [x] 생성 직후 ‘아직 만든 레벨이 없습니다’와 ‘첫 레벨 만들기’를 표시한다. 생성 버튼 반복 입력·파일 선택 취소·실패에서 기존 작업을 보존한다.
- [x] 기존 정상 프로젝트가 자동으로 열리는 승인된 동작은 강제로 폐지하지 않는다. 해당 경우 편집/목록으로 진입하고 시작 화면은 프로젝트 메뉴에서 접근한다. 명시적 씬 전달로 열린 레벨도 보존한다.
- [x] 작업 중 로딩은 진행 중임을 화면에 표시하고 중복 명령을 차단한다. 단순 화면 열기에서 전체 데이터 재로드를 유발하지 않는다.

## 작업 C — 첫 레벨과 안전한 전환

- [x] ‘첫 레벨 만들기/새 레벨’에서 기본 9×9 또는 현재 레벨 복제를 선택하고 번호·이름을 확인한 뒤 ‘만들고 편집하기’로 진입한다. 미션 입력을 강제하지 않는다.
- [x] 기존 목록의 편집 버튼과 최근 편집 20개를 그대로 연결한다. 행 선택만으로 편집 레벨을 바꾸지 않는다.
- [x] 레벨 전환 확인 문구는 ‘저장하고 열기 / 현재 레벨 변경 버리고 열기 / 계속 편집’을 사용한다. 공유 데이터·다른 레벨 변경을 보존한다.
- [x] 프로젝트 변경은 현재 프로젝트 전체 작업에 영향을 준다는 기존 경계를 별도 안내한다. 레벨 전환의 ‘현재 레벨만 버리기’를 프로젝트 전환에 잘못 재사용하지 않는다.
- [x] 편집은 dirty만 표시하고 파일 저장은 기존 명시적 저장 흐름으로 수행한다. 새 프로젝트 컨테이너 생성 시 쓰기는 허용하지만 매 배치마다 자동 저장하지 않는다.

## 작업 D — 검사와 인계

- [x] Windows 키보드 Tab/Enter/Esc, Android 뒤로가기·키보드 표시 시 새 대화상자의 적용/취소 접근을 확인한다.
- [x] 통합 계획의 화면 크기에서 시작/빈 상태/새 레벨 대화상자 스크린샷과 결과를 기록한다. 시뮬레이션과 실기기를 구분한다.
- [x] 기존 프로젝트 사본에서 열기·편집·저장·다시 열기, 복제, ZIP 가져오기 취소 및 기존 튜토리얼 보존을 검사한다.
- [x] 큰 목록은 메타데이터로 표시하고 선택한 레벨만 필요 시 읽는지 확인한다. 최소 1,000개 목록 사례에서 전체 JSON 열기 회귀가 없어야 한다.
- [x] 관련 기존 자동 검사와 Unity 컴파일 결과를 남긴다. 검증용 사본·임시 파일은 정리하되 실제 데이터·검증 결과는 보존한다.
- [x] 완료/미완료를 [목표 문서](../../../Goals/MoonRabbitJunkyard/LevelToolNativeUx/2026-10-22-stage01-goal.md)에 반영하고, 2단계 계획·목표·실행문 및 짧은 커밋 메시지를 제시한다. 다음 단계 구현은 시작하지 않는다.

제품 빌드·설치, 웹 기능, 보드 전체 재배치, 미션·튜토리얼 작성 흐름 개편, HTML 매뉴얼 갱신, 커밋·푸시는 이번 단계에서 수행하지 않는다. 데이터 사양 변경이 필요한 것으로 확인되면 최소 대안과 영향부터 설명한다.
