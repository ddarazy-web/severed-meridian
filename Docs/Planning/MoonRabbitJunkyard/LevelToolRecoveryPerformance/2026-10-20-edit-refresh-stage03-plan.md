# 편집 성능 개선 3단계 — 대표 조작·반복 편집 최종 검증

> 실행 담당: `superpowers:executing-plans`로 직접 진행한다. 별도 승인 없이 하위 에이전트·커밋·푸시를 사용하지 않는다.

**Goal:** 화면 갱신과 대상 문서 복사 개선이 실제 편집 조합에서도 응답·메모리·데이터 안전성을 유지하는지 판정한다.

**Architecture:** 1·2단계 구현과 기존 검사 harness를 재사용한다. 검사는 격리 작업 사본에서 수행하고, 회귀가 발견되면 해당 원인만 수정한다. 전면 UI 개편이나 새로운 저장 구조는 도입하지 않는다.

**Tech Stack:** C#, Unity UI Toolkit, 기존 `Tools/Testing/ProjectTests.ps1`.

**Spec:** [통합 계획](2026-10-20-edit-refresh-performance-plan.md), [3단계 목표](../../../Goals/MoonRabbitJunkyard/LevelToolRecoveryPerformance/2026-10-20-edit-refresh-stage03-goal.md), [2단계 결과](../../../Verification/MoonRabbitJunkyard/2026-10-20-level-tool-edit-refresh-stage02.md).

상태: 검증 완료(2026-10-20). [최종 결과](../../../Verification/MoonRabbitJunkyard/2026-10-20-level-tool-edit-refresh-stage03.md). 이름 편집 동기 중앙값 목표는 충족했으며, 튜토리얼·공유 적용·보드 재구성·붙여넣기·저장 비용은 후속 후보로 남긴다.

## 공통 제약

- 기존 데이터·소스 변경 보존. 제품 빌드·커밋·푸시·HTML 갱신·코드로 씬/프리팹 편집 금지.
- 편집 중 자동 저장·복구 기록을 추가하지 않는다.
- JSON/ZIP/MemoryPack 형식과 게임 규칙을 변경하지 않는다.
- 질문은 제한시간 없는 문답으로 한다. 미검증을 통과로 표현하지 않는다.

## 작업 1 — 대표 조작 응답과 표시 최신성

대상: `Tests/Editor/Features/LevelAuthoring/LevelToolManualSavePerformanceVerification.cs`, `LevelToolRefreshPerformanceVerification.cs`, `LevelToolEditingBoundaryVerification.cs`. 필요한 추가 시나리오는 이 검사들의 책임에 맞춰 확장한다.

- [x] 2단계 최종 결과와 잔여 병목을 읽고 이미 통과한 검사와 새로 필요한 검사 범위를 구분한다.
- [x] 고정 38문서 입력의 해시를 통합 계획과 비교한다. 이름 편집 10회 정상 표본 3회의 최신 결과를 기준으로 사용한다. 소스가 바뀌었다면 다시 측정한다.
- [x] 셀 배치/삭제, 공급 설정, 튜토리얼 단계 수정, 공유 적용, 선택·줌을 각각 분리해 측정한다. 준비·저장·이력 직렬화 비용을 편집 구간에 섞지 않는다.
- [x] 동기 명령 시간과 다음 표시 준비까지의 시간을 함께 기록한다. 무관한 패널 인스턴스, 문서 버전, 선택·포커스·스크롤 유지도 검사한다.
- [x] 셀·공급·공유 적용 후 Undo/Redo 및 숨김 패널 재진입에서 실제 최신 내용을 확인한다.

## 작업 2 — 반복 편집과 남은 비용

대상: 위 성능 검사와 `AuthoringEditSession.cs`, `LevelToolScreen.Refresh.cs`. 구현 변경은 재현된 회귀 또는 최종 목표의 직접적인 병목에 한정한다.

- [x] 격리 사본에서 100회 편집을 10회씩 나누어 측정한다. 묶음마다 working set·관리 힙·이력 수·최대 지연을 기록한다.
- [x] 이력 보존에 따른 정상 메모리 증가와 이벤트/화면 객체 누적을 구분한다. 새 세션으로 전환한 뒤 이전 화면·캐시 참조 해제를 확인한다.
- [x] 전체 문서 복사 호환 경로, 튜토리얼 그래프 구성, 저장소 검증 비용을 별도 표본으로 측정한다. 해결 범위를 확대해야 하면 근거와 후속안을 보고한다.
- [x] 각 표본의 30초·8GiB 보호를 유지한다. 지원되지 않는 누적 할당량은 null, Editor update 간격은 렌더 FPS와 구분한다.
- [x] 자동 프로젝트/복구 쓰기는 0회여야 한다. 명시적 저장은 성공/실패를 구분하며 실패 시 메모리 편집을 보존한다.

## 작업 3 — 화면 크기·전달·최종 판정

- [x] `LevelToolMobileVerification.RunRefreshViewports`의 실제 선언과 검사 범위를 확인한 뒤 1280×800·360×780·412×915·800×1280에서 입력·패널·스크롤 회귀를 확인한다.
- [x] JSON/ZIP/MemoryPack/게임 시험·복구 사본 저장은 2단계 증거를 재사용하고, 추가 변경의 영향 경로만 재검사한다.
- [x] 1단계 기록의 780×360 보드 높이 문제 및 오프스크린 흰색 렌더 문제를 신규 회귀와 구분한다. 실제 기기·물리 IME·최종 렌더가 확인되지 않았으면 명시한다.
- [x] 이름 편집 정상 3회 각각 중앙값 100ms 이하를 최종 목표로 판정한다. 대표 조작의 중앙값·최대값과 남은 저장 비용도 따로 보고한다.
- [x] 보호 파일 diff, 고정 입력 해시, 검사 연결 해제를 확인하고 `Docs/Verification/MoonRabbitJunkyard/2026-10-20-level-tool-edit-refresh-stage03.md`에 증거를 정리한다. 실제 작업일이 바뀌면 결과 파일 날짜를 맞춘다.
- [x] 전체 목표의 달성/미달, 미검증, 후속 후보와 간략한 커밋 메시지를 보고한다. 새로운 개선 단계는 자동 착수하지 않는다.

검사는 실제 선언을 확인한 메서드를 `Tools/Testing/ProjectTests.ps1 -Action Run -Method <진입점>`으로 순차 실행한다. 소스 변경 시 관련 컴파일 및 회귀를 함께 수행한다.

## 검토 중점

- 지연 표시로 시간만 짧아지는 문제: 작업 1의 표시 준비 완료 시간.
- Undo/Redo 뒤 오래된 캐시: 작업 1의 내용·버전 확인.
- 장기 편집 후 메모리 누적: 작업 2의 묶음별 측정과 세션 해제.
- 자동 저장 재도입: 작업 2의 파일 쓰기 감시.
- 기존 화면 결함을 새 회귀 또는 통과로 오인: 작업 3의 기준 기록 비교.
