# 레벨툴 대량 이력 복구 성능 개선 계획

> 후속 정책 변경: 자동 복구 저장의 추가 최적화 대신 [메모리 편집·수동 저장 전환 계획](2026-10-19-manual-save-plan.md)을 따른다. 아래 구현·측정 결과는 과거 기록으로 보존하며, 자동 저장을 다시 도입하는 근거로 사용하지 않는다.

> 상태: 1·2단계 구현 및 3단계 통합 검증 완료. 전체 성능 목표 미달과 큰 이력 검사의 보호 종료는 검증 기록을 따른다. 실행 시 `superpowers:executing-plans`를 적용한다. 추가 개선을 자동 실행하지 않는다. 하위 에이전트는 별도 승인 없이 사용하지 않는다.

**목표:** Undo/Redo와 손상 복구 보호를 유지하면서 복구 저장·읽기·재구성의 반복 작업과 메모리 사용을 줄인다.

**구조:** 기존 Workspace/Session/ToolDraftStore 책임을 유지한다. 먼저 중복 검증과 재구성을 줄이고, 다음으로 내부 이력 사본의 중복을 줄인다. 저장 형식 변경이나 별도 저장 프레임워크를 먼저 도입하지 않는다.

**기술:** Unity 6000.3.10f1, C#, Newtonsoft JSON, UniTask, 기존 Tests 하네스.

**기준:** [4단계 검증 기록](../../../Verification/MoonRabbitJunkyard/2026-10-19-level-tool-refactor-stage04.md), [구조 문서](../../../architecture/MoonRabbitJunkyard/level-tool-structure.md), [목표·완료 조건](../../../Goals/MoonRabbitJunkyard/LevelToolRecoveryPerformance/2026-10-19-goal.md).

## 확인된 문제와 선택한 방향

38문서/10회 편집 표본에서 ExportState 약 6.25초, Save 약 18.61초, 상태 문자열 26,414,289바이트였다. Read 중 누적 30.02초 보호 한도에 도달했으며 당시 전체 Unity 작업 메모리는 약 7.33GB였다. 30/60회 표본은 미실행이다. 이 메모리는 복구 기능만의 할당량이 아니다.

- ToolDraftStore.Save는 입력, 기록한 임시 파일, 기존 정상 파일을 검증하면서 Workspace를 반복 생성한다. Read에서 검증한 뒤 화면도 다시 복원하며, RestoreRecovery는 복원한 Workspace를 재직렬화한 다음 다시 복원한다.
- Session.Apply/Capture/Undo/Redo는 문서 전체 사본을 만든다. ExportState도 모든 이력의 JSON 트리를 구성한다.
- ContentDocument.Data는 수정 가능한 JObject다. 참조를 단순 공유하면 과거 이력과 저장 기준이 오염될 수 있으므로 불변 객체라고 가정하면 안 된다.
- 저장을 백그라운드로 옮기는 것만으로는 총 비용이 줄지 않는다. 이미 Save 일부는 백그라운드지만 ExportState와 종료 Flush는 동기 경로에 남아 있다.

**권장:** 3단계로 진행한다. 1단계에서 가장 직접적인 중복 재구성을 제거하고, 2단계에서 사본 비용을 줄이며, 3단계에서 실제 종료·자동 저장까지 통합 검증한다. 이력 개수 제한, 자동 복구 제거, 저장 주기 연장으로 성능 문제를 숨기지 않는다.

## 공통 제약

- 사용자 원본·후보·정식 팩·설정·이력을 변경하거나 삭제하지 않는다. 격리된 Logs 하위 고유 폴더를 사용한다.
- JSON 작성 데이터, MemoryPack, Addressables 키, 복구 v1 파일 형식과 이전 기록 읽기 호환성을 유지한다. 형식 변경이 필요하면 근거와 이관안을 보고하고 별도로 결정한다.
- Undo/Redo 순서·횟수·선택 셀·선택 레벨·dirty·저장 기준·미확정 입력·공유 튜토리얼 초안을 보존한다. 잘못 작성 중인 문서를 복구에서 임의로 정상화하지 않는다.
- 제품 빌드·커밋·푸시·HTML 갱신·프리팹/씬 코드 편집을 하지 않는다. Unity 컴파일과 격리 자동 검사는 허용한다.
- Unity 하네스는 순차 실행한다. 연결 중 Assets/Tests 원본을 수정하지 않는다. 기존 사용자 변경을 보존한다.
- Windows/Android 공용 코드는 플랫폼 중립으로 유지한다. Windows 전용 메모리 측정 API는 Tests에만 둔다. Android 실기기 결과가 없으면 별도로 미검증 표시한다.
- 질문이 필요하면 제한시간 없는 문답으로 제시한다.

## 1단계 — 검증·복원 중복 제거

**결과:** 같은 복구 자료를 검증/적용할 때 불필요한 Workspace 재생성과 JSON 왕복을 줄인다. 파일 안전성 검사 자체를 삭제하지 않는다.

**수정 후보와 책임**

| 경로 | 책임 |
|---|---|
| `Assets/Scripts/Features/LevelAuthoring/Storage/ToolDraftStore.cs` | 입력 검증, 임시 파일 검증, 원자적 교체, 이전 정상 기록 보호 |
| `Assets/Scripts/Features/LevelAuthoring/Editing/AuthoringToolWorkspace.cs` | 복원 검증과 상태 채택 경계 |
| `Assets/Scripts/Features/LevelAuthoring/Editing/AuthoringEditSession.State.cs` | 기존 v1의 동일한 오류 검출 의미 |
| `Assets/Scripts/Features/LevelTool/Runtime/LevelToolScreen.Recovery.cs` | 읽기→복구 선택→적용의 중복 직렬화 제거, 수명주기 보호 |
| `Tests/Editor/Features/LevelAuthoring/LevelToolRecoveryCostVerification.cs` | 구간별 비용·호출 횟수·메모리 측정 |
| `Tests/Editor/Features/LevelAuthoring/LevelToolTransferRecoveryVerification.cs` | 손상·실패·취소·종료 입력 보호 회귀 |

기존 공개 Save/Read/RestoreState 호출부를 먼저 조사한다. 내부에서 검증된 결과를 재사용할 필요가 있으면 좁은 결과 타입/채택 경계를 사용한다. 수정 가능한 JObject나 Workspace를 전역 캐시에 보관하거나 검증 전에 현재 세션을 바꾸지 않는다. 화면의 Workspace 객체 정체성과 이를 참조하는 패널 계약을 보존한다.

- [x] 실행 전 diff와 보호 대상 해시를 기록한다. 기존 성능 기록과 동일한 입력을 복사·고정하고 문서 수/해시/편집 동작을 기록한다. 과거 입력과 다르면 직접 비교로 표시하지 않는다.
- [x] 저장 전 검증, 임시 파일 검증, 현재 파일 검사, Read, 화면 적용 각각의 재구성 횟수와 비용을 분리 측정한다. 기존 보호 종료를 재현하기 위해 큰 실패 표본을 반복 실행하지 않는다.
- [x] 손상된 workspace/view/공유 초안, 누락 문서·중복 ID·선택 오류·잘못된 Undo 상태, 이전 정상 파일 복귀 검사를 먼저 확보한다. 예외 시 현재 세션 전체 불변을 확인한다.
- [x] 동일한 검증 결과를 재사용하여 복원→ExportState→RestoreState 왕복을 제거한다. 파일 검증을 자료구조 검증으로 분리한다면 기존 Restore의 모든 거절 조건을 같은 사례로 비교한다.
- [x] 임시 파일의 실제 기록 결과와 입력의 일치 검증, Flush(true), 교체 실패 처리, 손상된 현재 파일이 정상 previous를 덮지 않는 보호를 유지한다. 경로/sequence만으로 파일이 검증됐다고 간주하지 않는다.
- [x] 저장 순서 역전, 취소, 화면 비활성화/프로젝트 변경 후 늦은 결과 적용 방지를 검사한다. 최종 입력을 패널 Dispose 전에 보존하는 기존 수정도 유지한다.
- [x] 관련 회귀와 소형/10회 비용 검사를 실행한다. 복원 결과 전체와 실제 Undo/Redo를 비교한다. 1단계 성과와 남은 병목을 보고하고 2단계 상세 계획을 갱신한다.

**검증 가능한 산출물:** 같은 데이터/오류에 대해 의미가 같고, 읽은 자료를 화면에 적용하기 위한 재직렬화 왕복이 사라졌다는 호출/측정 증거. 1단계만으로 전체 성능 목표 달성을 주장하지 않는다.

## 2단계 — 이력의 문서 사본과 직렬화 비용 절감

**결과:** 변경되지 않은 문서의 중복 사본을 줄이되 외부 수정이 과거 이력을 바꾸지 못한다.

수정 후보: `AuthoringEditSession.cs`, `AuthoringEditSession.State.cs`, 실제 문서 조회/편집 호출부. ContentDocument의 전역 계약 변경보다 Session 내부 소유권 경계를 우선한다.

- [x] Get/Apply/EditLevel/Fork/Publish/Discard와 외부 콜백의 JObject 보관 가능성을 조사하고 수정 후 참조 오염 재현 검사를 만든다.
- [x] 내부 전용 불변 사본 또는 변경 시 복사 방식을 비교한다. 변경되지 않은 문서는 내부 이력끼리만 공유하고 외부 반환값·편집 콜백과는 분리한다. 선택 배열도 별도 소유한다.
- [x] 같은 문서 반복 편집, 여러 문서 편집, 추가/삭제, 저장 후 Undo, Undo 후 새 편집, 공유 튜토리얼 사본·취소에서 이력과 dirty 의미를 검증한다.
- [x] 기존 v1 출력 의미를 유지하며 큰 중간 JObject 트리나 중복 DeepClone을 줄인다. 스트리밍은 측정상 필요할 때만 적용하고 손상 검증·취소·기록 완전성을 보존한다.
- [x] 10회→30회→60회로 점진 측정한다. 한도 도달 시 큰 표본을 중단한다. 구조 공유가 직렬화 파일 크기까지 줄인다고 주장하지 않는다. v1은 중복 문서를 계속 기록할 수 있다.

세부 구현과 공개 API 변경 여부는 1단계 측정 결과를 반영해 착수 전에 구체화한다. 목표 미달 때문에 복구 v2/압축/차분 저장을 자동 도입하지 않는다.

## 3단계 — 실제 자동 저장·종료·복원 통합 검증

**결과:** 개별 함수 속도뿐 아니라 실제 화면 정지와 종료 기록 보존을 검증한다.

- [ ] 고정 fixture로 정상 표본 3회 측정의 중앙값·최댓값을 남긴다. 최초 실행과 워밍업 결과를 구분한다. 보호 한도에 걸린 표본은 반복하지 않는다.
- [ ] Export/Save/Read/Restore/화면 적용과 메인 스레드 최대 정지 시간, 전체 및 시작 대비 메모리 증가, 파일 크기, 문서/Undo/Redo 수를 기록한다.
- [ ] 자동 저장 중 새 편집·Undo·프로젝트 전환·종료, 저장 실패·손상 파일·previous 복귀, 재활성화와 미확정 한글/잘못된 숫자 입력 보존을 확인한다.
- [ ] JSON 저장·ZIP 왕복·MemoryPack·게임 시험 관련 회귀와 컴파일을 수행한다. 사용자 보호 파일 해시와 변경 범위를 최종 비교한다.
- [ ] 구조 문서/검증 기록/목표 상태를 갱신하고, 성능 목표 달성·미달·실기기 미검증을 구분하여 보고한다. 다음 개선을 자동 실행하지 않는다.

## 성능 판정과 보호 한도

아래 수치는 이번 개선의 **제안 목표**이며 현재 달성 수치나 전 플랫폼 보장값이 아니다. 같은 PC·Unity·동일 fixture 기준으로 판정한다.

| 항목 | 제안 최종 목표 |
|---|---|
| 38문서/10회 편집 | Export+Save+Read+Restore 합계 5초 이하 |
| 38문서/60회 편집 | 동일 합계 15초 이하, 전체 편집 포함 표본 30초 보호 한도 안에서 완료 |
| 일반 자동 저장 메인 스레드 정지 | 100ms 이하를 지향하며 실제 최댓값 기록; 미달이면 UI 체감 개선 완료로 표현하지 않음 |
| 메모리 | 10회 전체 프로세스 최대 4GiB 이하를 목표로 하되 시작 메모리·증가분을 함께 표시; 60회도 8GiB 보호 한도 미만 |
| 기능 | 저장/복원/Undo/Redo 의미 동일, 손상/실패 보호 회귀 모두 통과 |

보호 한도는 표본 전체 30초 또는 Unity 작업 메모리 8GiB다. 보호 종료는 성공이 아니다. 해당 검사 프로세스만 종료하고 하네스 해제를 확인한다. Windows 전용 측정 수치를 Android의 메모리 예산으로 해석하지 않는다. 목표 미달 시 관측 결과와 추가 대안을 보고하며 합격 수치를 사후 완화하지 않는다.
