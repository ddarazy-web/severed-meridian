# 레벨툴 수동 저장 전환 2단계 — 저장 상태 UX 정리

상태: 2단계 구현·검증 완료(2026-10-20).

기준: [통합 계획](2026-10-19-manual-save-plan.md), [2단계 목표](../../../Goals/MoonRabbitJunkyard/LevelToolRecoveryPerformance/2026-10-19-manual-save-stage02-goal.md).

## 결과물

처음 사용하는 사람이 현재 입력이 저장됐는지, 저장이 필요한 이유와 다음 행동을 제목·상태·버튼·팝업에서 일관되게 알 수 있는 레벨툴. 1단계의 메모리 편집·수동 JSON 저장 정책은 유지한다.

## 작업 범위

1. **상태 표현과 갱신 시점 통일**
   - `저장됨 / 저장하지 않음 / 입력 확인 필요 / 저장 중 / 저장 실패`를 구분한다. 공유 사본 미적용과 복구본 사본 저장 필요는 별도 설명으로 표시한다.
   - 제목 `*`, 저장 버튼, 폴더 상태, 오류 안내가 서로 모순되지 않도록 현재 상태 계산을 한 곳에서 사용한다. 매 프레임 전체 문서 비교나 이력 직렬화는 하지 않는다.
   - 저장 실패 문구가 화면 갱신만으로 사라지거나 성공으로 바뀌지 않도록 하되, 재시도 성공 후에는 정상 상태로 바뀐다.
2. **이탈·복구·ZIP 문구 정리**
   - 종료·프로젝트 전환·다시 읽기·과거 기록 복원의 목적에 맞는 제목과 계속 버튼을 사용한다. 현재 전환 확인에서 재사용하는 ‘종료’ 표현을 분리한다.
   - 공유 사본 적용은 부모 프로젝트 저장과 다르다는 점을 짧게 설명한다. 복구본은 사본 저장이 필요함을 안내한다.
   - ZIP은 ‘저장 후 ZIP 내보내기’로 표현한다. 파일 선택을 취소했어도 앞서 완료한 JSON 저장을 되돌렸다고 표현하지 않는다.
   - 자동 저장하지 않으며 강제 종료 시 미저장 변경은 사라질 수 있음을 저장 툴팁에 유지한다.
3. **실제 화면과 입력 흐름 검증**
   - Windows 1280×800, 모바일 논리 폭 360·412 및 태블릿 폭에서 긴 경로/한글 오류/공유 사본 상태가 잘리지 않는지 확인한다.
   - 저장 실패→수정→재시도, 취소→포커스/선택 범위 복귀, 숨긴 입력 저장, 저장 중 중복 실행 차단을 검사한다.
   - 색만으로 상태를 구분하지 않는다. 모바일에는 키보드 단축키만 안내하지 않는다.

## 관련 코드와 경계

- `Assets/Scripts/Features/LevelTool/Runtime/LevelToolScreen.ManualSave.cs`: 미저장 및 상태 표현.
- 같은 디렉토리의 `Storage.cs`, `Recovery.cs`, `Commands.cs`, `TutorialSharing.cs`, `FileTransfer.cs`: 실제 작업 결과와 문구 연결.
- `Navigation.cs`, `Shortcuts.cs`, `MobileInput.cs`: 제목과 포커스 복귀. 필요한 변경만 한다.
- 현재 UI 생성 경로를 사용한다. 프리팹·씬·HTML 매뉴얼은 편집하지 않는다.
- 저장 포맷, 게임 규칙, 자동 저장, 신규 서비스/백그라운드 저장 체계는 범위 밖이다.

## 검증과 종료 기준

- 1단계 수동 저장·미확정 입력·공유 사본·전환 실패 회귀를 재사용하고, 새 상태 전이와 화면 표본만 추가한다.
- 고유 시험 폴더를 사용하고 기존 복구/원본 데이터는 보존한다. Unity 검사는 순차 실행하고 연결 해제를 확인한다.
- 실제 Android 기기를 사용할 수 없으면 에디터의 화면 크기 검증과 구분해서 미검증으로 보고한다.
- 결과 보고 후 3단계 반복 성능·최종 회귀 계획/목표/복사용 실행문을 갱신한다. 자동으로 다음 단계에 착수하지 않는다.
- 제품 빌드·커밋·푸시·HTML 갱신은 금지한다. 하위 에이전트는 별도 승인 없이 사용하지 않는다.
