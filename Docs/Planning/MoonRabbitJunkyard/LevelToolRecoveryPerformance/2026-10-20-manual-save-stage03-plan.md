# 수동 저장 전환 3단계 — 성능 측정과 최종 회귀

상태: 3단계 측정·회귀 검증 완료(2026-10-20). 편집 100ms 목표 미달. 후속 최적화는 자동 진행하지 않는다.

## 목적과 범위

자동 복구 저장을 제거한 레벨툴에서 편집 반응성과 수동 저장 비용을 분리해 측정하고, 데이터 제작·전달·시험 기능이 유지되는지 확인한다. 새 자동 저장 방식이나 전체 구조 리팩토링은 추가하지 않는다.

기준: [통합 계획](2026-10-19-manual-save-plan.md), [2단계 계획](2026-10-19-manual-save-stage02-plan.md), [3단계 목표](../../../Goals/MoonRabbitJunkyard/LevelToolRecoveryPerformance/2026-10-20-manual-save-stage03-goal.md).

## 실행 단위

### 1. 동일 조건의 성능 비교

- 기존 38문서 fixture를 격리된 폴더에 준비한다. 사용자 제작 데이터와 과거 복구 파일은 변경하지 않는다.
- 준비/첫 실행 비용과 정상 반복 비용을 구분하고, 같은 편집·Undo·Redo·유휴·저장·종료 순서를 정상 표본 3회 실행한다.
- 편집 응답, 메인 스레드 정지 구간, 할당/메모리 증가, 수동 JSON 저장 시간을 각각 기록한다. 단순 파일 쓰기 시간만으로 화면 응답을 평가하지 않는다.
- 자동 checkpoint 쓰기·전체 이력 Export·종료 복구 Flush가 0회임을 확인한다. 환경 설정과 사용자가 명시한 시험 결과 기록은 구분한다.
- 편집 응답 100ms 이내를 지향하되 미달이면 원인과 측정 조건을 기록한다. 이전 자동 복구 저장 시간과 현재 JSON 저장 시간을 같은 작업처럼 비교하지 않는다.
- 표본 30초 또는 Unity working set 8GiB 한도를 넘으면 해당 표본을 중단하고 실패로 기록한다. 안전 한도를 넘기는 반복 실행은 하지 않는다.

### 2. 제작·전달·게임 시험 회귀

- 저장/Ctrl+S, 잘못된 숫자·미확정 입력, 공유 사본 적용, 취소·버리기·전환·실패 후 재시도와 Undo/Redo 유지 확인.
- JSON 저장/다시 읽기, ZIP 내보내기·가져오기·취소·오류, MemoryPack 변환 및 해당 데이터의 게임 시험을 기존 격리 검사로 확인한다.
- 과거 v1 복구본은 사용자의 명시적인 열기와 사본 저장에서만 읽히는지 확인한다. 과거 파일은 보존한다.
- Windows/모바일 입력 검증과 실제 기기 미검증을 구분한다. 제품 빌드는 하지 않는다.

### 3. 완료 판정 및 남은 병목 보고

- 관련 컴파일·회귀 결과, 보호 파일 해시, 검사 하네스 연결 해제, 변경 diff를 확인한다.
- 개선 전후 조건과 수치, 목표 달성/미달/미검증을 기록한다. 남은 병목은 영향과 우선순위를 제안하되 별도 승인 없이 범위를 확대하지 않는다.
- 완료 보고와 복사 가능한 커밋 메시지를 제공한다. 커밋·푸시는 하지 않는다.

## 공통 제약

기존 미커밋 변경과 사용자 데이터 보존. 순차 Unity 검사 중 Assets/Tests 수정 금지. 제품 빌드·HTML 갱신·코드로 프리팹/씬 편집 금지. 하위 에이전트는 별도 승인 없이 사용하지 않는다. 질문은 제한시간 없는 문답으로 한다.
