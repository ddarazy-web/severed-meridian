# 레벨툴 성능 개선 — 메모리 편집·수동 저장 전환 계획

> 상태: 1·2단계 구현 및 3단계 측정·회귀 검증 완료(2026-10-20). 편집 100ms 목표는 미달이며 후속 최적화가 필요하다. 실행 시 `superpowers:executing-plans`로 단계별 진행한다. 하위 에이전트는 별도 승인 없이 사용하지 않는다. 제품 빌드·커밋·푸시·HTML 갱신은 하지 않는다.

**목표:** 편집할 때마다 전체 복구 이력을 저장하는 비용을 없애고, 메모리에서 편집하면서 미저장 표시와 명시적 저장으로 작업을 관리한다.

**구조:** 기존 AuthoringEditSession의 메모리 상태·Undo/Redo와 AuthoringToolWorkspace의 JSON 저장을 유지한다. 화면의 자동 checkpoint 생산·자동 복구 읽기를 제거하고 기존 저장 명령과 이탈 확인 흐름을 통합한다. 증분 복구 형식, 새 저장 프레임워크, 자동 저장 주기 설정은 도입하지 않는다.

**기술:** Unity 6000.3.10f1, C#, UI Toolkit, 기존 JSON 저장·UniTask·Tests 하네스.

**요구 근거:** 사용자가 확정한 “매번 저장하지 말고 dirty 표시로 저장을 유도하며, 저장 전에는 메모리에서만 유지” 정책. [이전 측정](../../../Verification/MoonRabbitJunkyard/2026-10-19-level-tool-recovery-performance-stage03.md), [이번 목표·실행문](../../../Goals/MoonRabbitJunkyard/LevelToolRecoveryPerformance/2026-10-19-manual-save-goal.md).

## 방향 변경과 확인된 비용

이전 대안인 백그라운드 전체 직렬화·변경분 복구 저장은 이번 작업에서 추진하지 않는다. 자동 저장 자체가 필요 없다는 새 정책을 우선한다. 기존 이력 공유와 v1 호환 개선은 유지한다.

38문서/10회 표본의 자동 저장 동기 구간은 약 650ms, 저장 완료까지 약 6.63초, 종료 Flush는 약 11.25초였다. 이 경로를 없애는 것이 첫 번째 개선이다. 모든 UI 지연의 원인이 복구 저장이라고 단정하지 않으며, 제거 후 남는 편집·레이아웃·dirty 계산 비용은 측정해서 보고한다.

## 확정 동작

| 상황 | 동작 |
|---|---|
| 블록 배치·속성 변경·튜토리얼 편집·Undo/Redo | 메모리에서만 처리. 자동 복구 파일을 기록하지 않음 |
| 포커스 이동·최소화·Pause·OnDisable | 복구 저장/전체 이력 직렬화 없음. 동일 프로세스의 입력·세션 유지와 리소스 정리는 유지 |
| 저장 / Ctrl+S | 미확정 입력을 검증·확정하고 현재 제작 데이터를 JSON으로 저장. Undo 전체를 복구 파일로 추가 저장하지 않음 |
| 저장 성공 | 저장 기준 갱신 후 clean 표시. 같은 세션의 Undo/Redo는 유지 |
| 저장 실패·검증 실패 | 현재 편집·이력·입력 보존. 미저장 상태 유지, 실패 원인 표시 |
| 종료·프로젝트 전환·다시 불러오기 | 변경이 있으면 저장 / 버리기 / 취소. 저장 실패 시 이탈하지 않음 |
| 일반 재실행 | 명시적으로 저장한 제작 JSON을 사용. 이전 앱 실행의 Undo/Redo를 자동 복원하지 않음 |
| 과거 복구본 | 파일을 삭제·덮어쓰지 않음. 시작 때 큰 파일을 자동 파싱하지 않고, 사용자가 요청할 때만 기존 읽기·손상 보호 경로로 확인 |
| ZIP·사본 저장·새 프로젝트·가져오기 | 사용자 명령에 따른 파일 생성은 허용. 자동 checkpoint는 추가하지 않음 |

- 미확정 한글/잘못된 숫자/미적용 공유 튜토리얼 사본은 Session.IsDirty만으로 판단할 수 없다. **문서 변경**, **입력 미확정**, **공유 사본 미적용**을 함께 안내하고 이탈 시 누락하지 않는다.
- 단순 보드 선택·줌·스크롤 변경은 제작 데이터 dirty로 만들지 않는다. Undo로 저장 상태에 돌아오면 문서 dirty도 해제되어야 한다.
- 미확정 입력을 강제로 정상 숫자로 바꾸거나 저장 실패를 성공으로 표시하지 않는다. 공유 사본은 기존 적용/버리기 절차를 거친다.
- 비정상 종료·OS 강제 종료 시 마지막 수동 저장 이후 변경은 유실될 수 있다. Android 앱 전환 때 이를 우회하는 자동 저장은 넣지 않는다. 저장 안내/툴팁에서 정책을 설명한다.
- 창 위치·크기 등 기존 가벼운 환경 설정, 사용자가 실행한 시험의 결과 기록까지 일괄 중단하는 작업이 아니다. 대량 편집 상태와 복구 이력의 자동 기록을 대상으로 한다.
- ZIP 내보내기는 현재 내부 JSON 저장을 먼저 수행한다. 기존 계약을 보존하되 확인 화면에 **저장 후 ZIP 내보내기**를 명시하고, ZIP 선택 취소 후에도 이미 완료된 내부 저장은 구분해 안내한다.

## 작업 단위: 3단계

각 단계는 구현과 해당 회귀 검증까지 묶는다. 첫 단계만 상세히 정하고, 다음 단계 착수 시 실제 결과를 반영해 상세 계획·목표를 보완한다. 다음 단계를 자동 시작하지 않는다.

### 1단계 — 자동 저장 제거와 안전한 수동 저장

결과물: 자동 checkpoint가 없는 상태에서도 저장·취소·종료가 안전하게 동작하는 레벨툴.

주요 파일과 책임:

- `Assets/Scripts/Features/LevelTool/Runtime/LevelToolScreen.Recovery.cs`: Update의 자동 기록, FlushRecovery, OnDisable/Leave의 숨은 기록 제거. 종료 확인·해제·취소 등 다른 책임은 유지.
- `LevelToolScreen.RecoveryInputs.cs`, `BoardTouch.cs`, `Shortcuts.cs`, `Storage.cs`, `FileTransfer.cs`(동일 디렉토리): Pause/Focus/전환/파일 작업의 CheckpointOnInterruption 제거. 입력 보류·복원과 리소스 해제를 함께 삭제하지 않음.
- `LevelToolScreen.cs`, `Batch.cs`, `Bot.cs`, `MultiTrial.cs`(동일 디렉토리): checkpointPending 생산자 정리와 미저장 표시 연결. Update의 봇·시험·터치 갱신은 유지.
- `LevelToolScreen.Commands.cs`, `Storage.cs`: 저장/Ctrl+S와 저장·버리기·취소의 동일 정책 적용. 과거 복구본 확인은 기존 파일 메뉴 명령 체계에 연결하고 사용자가 선택한 경우에만 읽음.
- `Assets/Scripts/Features/LevelAuthoring/Editing/AuthoringToolWorkspace.cs`: 현재 JSON 저장 계약 재사용. 필요하지 않으면 변경하지 않음.
- `Assets/Scripts/Features/LevelAuthoring/Storage/ToolDraftStore.cs`: 과거 기록 호환 읽기·검증 유지. 자동 기록을 제거한다는 이유로 외부 사용처 조사 없이 타입·v1 코덱 삭제 금지.

작업 및 검증:

- [x] 기존 파일과 자동 저장 호출부를 기록하고 격리된 fixture/보호 해시를 준비한다.
- [x] 기존 동작에서 실패하는 “편집·대기·포커스 이탈·Pause·OnDisable 동안 draft/current/previous 신규 생성·수정 없음” 검사를 추가한다. 기존 복구본이 있는 경우와 없는 경우를 나눠 검사한다.
- [x] 자동 저장 생산자·호출·필드를 제거한다. 단순히 주기만 늘리거나 쓰기를 막은 채 ExportState를 계속 호출하는 방식은 금지한다.
- [x] 시작 시 EnableRecovery의 대량 자동 읽기를 명시적 과거 복구본 확인으로 전환한다. 파일 존재 확인 정도만 허용하고 과거 기록이 최신 JSON 위에 자동으로 나타나지 않게 한다. 손상 기록 확인 취소 시 현재 세션을 보존한다.
- [x] 수동 저장은 현재 문서 스냅샷만 저장하고 입력 확정→검증→저장→성공 시 clean 순서를 보장한다. 작업 중 새 편집을 허용하지 않는 기존 busy 경계를 유지한다.
- [x] 기본 `*`/미저장 표시와 저장 버튼 상태를 연결한다. 기존 IsDirty와 입력 보류 상태를 사용하며, 표시 갱신을 위해 매 프레임 전체 문서/이력을 JSON으로 만들지 않는다.
- [x] 종료/다른 프로젝트 열기/다시 불러오기/공유 사본/잘못된 숫자/한글 입력의 저장·버리기·취소를 검사한다. 무효 입력에서 저장은 막되 사용자가 명시적으로 버리기·취소를 선택할 수 있어야 한다.
- [x] 저장 실패 시 기존 파일·세션·UndoRedo 보존, 버리기/취소 시 추가 파일 쓰기 없음, 저장 성공 이후 Undo/Redo로 dirty가 올바르게 바뀌는지 검사한다.
- [x] 기존 자동 복구를 전제로 한 UI 검사만 새 정책으로 갱신한다. ToolDraftStore의 과거 기록 호환/손상 보호 테스트는 유지한다.

검사 파일: 기존 `Tests/Editor/Features/LevelAuthoring/LevelToolTransferRecoveryVerification.cs`, `LevelToolMobileVerification.cs`, `LevelToolRecoveryPreparedVerification.cs`를 재사용하고, 새 정책 검사는 같은 폴더의 `LevelToolManualSaveVerification.cs`에 분리한다. 기존 자동 저장 성능 검사는 과거 비교용으로 구분하거나 새 정책에 맞게 대체하여 사용 불가능한 진입점을 남기지 않는다. 메타 GUID 보존.

완료 기준: 10회 편집/UndoRedo/대기/일시정지/정상 종료의 자동 checkpoint 쓰기와 전체 이력 Export 호출이 0회이며, 수동 저장과 이탈 보호가 작동한다. JSON 저장·ZIP·게임 시험을 임의로 변경하지 않는다.

### 2단계 — 저장 상태 UX 정리

- 제목 `*`와 **저장하지 않음 / 입력 확인 필요 / 저장 중 / 저장됨 / 저장 실패**를 구분한다. 색만으로 상태를 전달하지 않는다.
- 저장 버튼·Ctrl+S·툴팁·이탈 팝업의 문구와 상태 판단을 통일한다. 공유 사본 미적용 상태는 따로 설명한다.
- 실패 후 재시도, 팝업 취소 후 입력/선택/포커스 복귀, 저장 중 중복 입력을 확인한다.
- Windows 및 Android 화면 폭에서 표시가 잘리지 않는지 검사한다. OS 강제 종료에 저장 확인 팝업을 보장한다고 안내하지 않는다.
- HTML 매뉴얼은 갱신하지 않는다. 런타임 프리팹/씬을 코드로 편집하지 않으며 기존 UI 생성 경로 안에서 작업한다.

### 3단계 — 체감 성능과 회귀 검증

- 같은 38문서 fixture에서 편집/Undo/Redo/유휴/수동 저장/종료를 분리해 정상 표본 3회 측정한다.
- 자동 복구에 사용되던 약 650ms 동기 구간이 호출되지 않는지 확인한다. 정상 편집의 입력 지연은 100ms 이내를 지향하되 다른 병목으로 초과하면 원인과 미달을 기록한다.
- 이미 clean인 정상 종료에서 복구 Flush 비용 0회 확인. 실제 앱/엔진 종료 시간 전체가 0초라는 목표는 아니다.
- 수동 JSON 저장의 시간·메모리와 실패 보호를 측정한다. 기존 전체 Undo 복구 저장의 11초 수치를 수동 JSON 저장 시간으로 혼동하지 않는다.
- 메모리 이력은 남으므로 큰 편집에서 CPU/메모리 증가를 따로 확인한다. 이전 보호 종료 표본을 근거 없이 반복 강제 실행하지 않는다. 표본 30초/Unity working set 8GiB 한도 유지.
- JSON·ZIP·MemoryPack·게임 시험 회귀, 과거 v1 복구본의 명시적 열기/사본 저장, 보호 해시·컴파일·하네스 해제를 확인한다.
- 성능 목표 달성/미달/미검증과 남은 병목을 보고한다. 새 복구 저장 방식이나 추가 리팩토링은 자동 착수하지 않는다.

## 공통 제약과 검토 초점

- 사용자 원본·후보·정식 리소스·과거 복구본·이력 파일은 삭제하지 않는다. 모든 쓰기 검사는 고유 시험 폴더에서 진행한다.
- 소스의 기존 미커밋 변경은 보존한다. 제품 빌드·커밋·푸시·HTML 갱신은 금지한다.
- Unity 검사 연결 중 Assets/Tests를 수정하지 않고 순차 검사한다. 새 테스트 프레임워크는 도입하지 않는다.
- “dirty 해제”가 저장 실패나 ZIP 전송 성공만으로 발생하지 않는지, 미확정 입력만 있을 때도 이탈 확인이 나오는지 중점 검토한다.
- 기존 복구 파일은 남아 있어도 새 실행에 자동 반영하지 않는다. 새 정책에서 이전 Undo를 자동 복원하지 않는 것은 의도된 변경이다.
- 단계 완료 시 수정 내용·검증 결과·남은 항목과 복사 가능한 커밋 메시지를 보고하고 다음 단계 계획·목표·실행문을 제공한다. 실제 커밋·푸시는 하지 않는다.
