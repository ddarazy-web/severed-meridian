# 복구 성능 개선 3단계 — 실제 화면·종료 통합 검증

> 상태: 3단계 검증 완료. 성능 목표는 미달이며 미검증 범위를 결과에 명시했다. 반복 성능과 실제 화면 복구를 측정했고 성능 목표 미달을 확인했다. 실행 시 `superpowers:executing-plans` 적용. 하위 에이전트는 별도 승인 없이 사용하지 않는다.

**목표:** 개선된 이력 처리의 반복 성능과 실제 화면 자동 저장·종료·복원 동작을 검증하고, 달성한 성능과 미달한 기준을 구분해 마무리한다.

**구조:** 기존 Session/Workspace/ToolDraftStore와 PreparedDraft 경계를 유지한다. 정상 동작의 통합 검증이 중심이며, 발견된 회귀만 좁게 수정한다. 새 복구 형식·이력 축소·별도 프레임워크는 도입하지 않는다.

**기술:** Unity 6000.3.10f1, C#, Newtonsoft JSON, UniTask, 기존 Tests 하네스.

**기준:** [통합 계획](2026-10-19-plan.md), [2단계 기록](../../../Verification/MoonRabbitJunkyard/2026-10-19-level-tool-recovery-performance-stage02.md), [3단계 목표](../../../Goals/MoonRabbitJunkyard/LevelToolRecoveryPerformance/2026-10-19-stage03-goal.md).

## 전제와 잔여 위험

- 2단계의 고정 10회 표본은 동일 v1 입력에서 저장 약 6.12초, 읽기 약 5.05초, 적용 약 0.51ms였다. 상태/Redo/Undo 검증을 포함한 전체는 14.74초, 프로세스 표본 최대 약 3.47GB였다.
- 이는 단일 표본이며 Export를 포함한 전체 5초 목표를 달성했다는 뜻이 아니다. 파일 크기는 v1 유지 때문에 줄지 않는다.
- UI 자동 기록 시 Export는 여전히 메인 스레드에서 실행하고 종료 Flush도 동기 경로다. 백그라운드 Save만 보고 UI가 부드럽다고 결론 내리지 않는다.
- 2단계 실제 38문서/10회는 편집·검증 포함 20.71초로 통과했지만, 30회는 Read 중 전체 30.10초 보호 종료했고 60회는 미실행이다. 실제 10회 복구 경로 합계는 약 11.80초다. 30/60회는 이번 단계에서 조건 변경 근거 없이 다시 강제 실행하지 않는다.
- 2단계에서 보호 종료된 표본은 검증 기록을 확인한다. 같은 큰 표본을 반복 강제 실행하지 않는다. 실제 기기 결과가 없으면 Android 성능은 미검증이다.

## 제약

- 제품 빌드·커밋·푸시·HTML 갱신·코드에 의한 프리팹/씬 편집 금지.
- 사용자 원본·후보·정식 팩·Addressables·설정·이력 변경/삭제 금지. 로그와 fixture는 새 고유 폴더에 둔다.
- Unity 검사는 순차 실행한다. 연결 중 Assets/Tests를 수정하지 않는다. 모든 결과는 정상 종료/보호 종료/실패/미실행으로 구분한다.
- 복구 v1/전체 UndoRedo/선택/dirty/미확정 입력/공유 초안/previous 보호 유지.
- 질문은 제한시간 없는 문답으로 한다. 목표 미달을 이유로 측정 한도나 합격 기준을 사후 완화하지 않는다.

## A. 반복 비용과 실제 UI 정지 측정

대상: `Tests/Editor/Features/LevelAuthoring/LevelToolRecoveryCostVerification.cs`, 기존 전송/복구 UI 검사, `LevelToolScreen.Recovery.cs`의 호출 경계.

- [x] 보호 해시와 입력 fixture 해시를 기록하고 현재 구현·검사 상태를 확인한다.
- [x] 동일 PC/Unity/입력에서 정상 표본만 3회 측정한다. 최초 실행과 워밍업을 구분하고 중앙값/최댓값을 기록한다.
- [x] 10/30/60회 편집은 이전 표본이 정상 완료한 범위까지만 수행한다. 한 표본 30초 또는 전체 Unity 작업 메모리 8GiB에서 해당 검사 프로세스만 종료하며 큰 표본을 중단한다.
- [x] Export/Save/Read/Apply 및 상태 검증 비용, 시작/최대 메모리와 증가분, 파일 크기/문서 수/UndoRedo 수를 구분한다. 소형과 실제 38문서 입력을 혼동하지 않는다.
- [x] 실제 화면에서 자동 저장 시 입력/프레임 정지, 종료 Flush 시간, 복구 프롬프트까지의 시간을 계측한다. Scene 원본을 저장하거나 프리팹에 시험 설정을 적용하지 않는다.
- [x] 비동기로 넘길 수 없는 가변 세션/UI 접근을 무작정 작업 스레드로 이동하지 않는다. 큰 정지가 남으면 원인·개선 대안을 보고하고 별도 승인 없는 구조 변경을 하지 않는다.

## B. 자동 저장·전환·종료·복원 경계

- [x] 자동 저장 도중 새 편집/Undo/Redo와 순서 역전에서 최신 sequence가 보존되는지 검사한다.
- [x] 프로젝트 전환·모달 취소·화면 비활성화 후 이전 읽기/저장 결과가 새로운 세션에 적용되지 않는지 확인한다.
- [x] 마지막 미확정 한글·잘못된 숫자·커서/선택·공유 튜토리얼 사본을 종료 전 저장하고 재실행에서 복원한다. 저장본으로 돌아가기는 명시적인 버리기 동작일 때만 수행한다.
- [x] 저장 실패/잠금/손상 current/손상 previous/둘 다 손상/파일 누락에서 원본과 마지막 정상 기록, 화면의 기존 세션을 보존한다.
- [x] 재활성화·취소 후 콜백 중복/입력 잠금 잔류/복구 결과 이중 적용이 없는지 검사한다.

## C. 호환성·최종 감사

- [x] 실제 변경된 경계에 해당하는 JSON 저장·ZIP·MemoryPack·게임 시험 회귀를 기존 격리 fixture로 확인한다. 실제 원본을 변환하거나 등록하지 않는다.
- [x] 내부 소유권·전체 UndoRedo·과거 v1 파일 호환·가변 반환값 격리 검사를 유지한다.
- [x] 컴파일·diff·GUID·보호 파일 해시·하네스 해제·생성 시험 파일 범위를 확인한다.
- [x] 구조 문서/전체 목표/검증 기록을 갱신하고 성능 목표별 달성 여부를 표로 보고한다. 제품 빌드/실기기 미검증도 명시한다.
- [x] 남은 성능 문제가 있으면 측정 근거와 다음 선택지를 제시하되 추가 단계를 자동 생성·구현하지 않는다. 간략한 커밋 메시지를 복사 가능하게 제공한다.

## 판정 기준

통합 계획의 제안 목표를 유지한다: 38문서/10회 Export+Save+Read+Restore 5초 이하, 60회 15초 이하, 일반 자동 저장의 메인 스레드 최대 정지 100ms 지향, 10회 프로세스 최대 4GiB 목표. 기준 미달이면 기능 검증 완료와 성능 목표 미달을 함께 보고한다. 3단계 검사가 끝났다고 모든 성능 문제가 해결됐다고 표현하지 않는다.
