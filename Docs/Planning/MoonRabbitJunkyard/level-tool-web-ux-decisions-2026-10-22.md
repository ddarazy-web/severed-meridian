# 레벨툴 UX 확정 사항 및 웹 전환 철회

## 최종 플랫폼 결정 (2026-10-22)

- 웹 빌드는 사용하지 않고 기존 Android·Windows 레벨툴만 유지한다. 아래 웹 전환 관련 문구는 당시 검토 이력이며 이 결정으로 대체한다.
- Web Level Editor 빌드 프로필, 자동 생성 등록, 선택 메뉴와 전용 Addressables 프로필을 제거한다. 게임 앱 플랫폼은 변경하지 않는다.
- 공통 UX 결정과 HTML 목업은 Android·Windows 개선 참고 자료로 유지한다. 브라우저 저장·웹 배포 계획은 진행하지 않는다.
- 추가 요청에 따라 기존 웹 빌드 산출물(Builds/Web/LevelTool)은 삭제하고 로컬 시험 서버를 종료한다. 검사 기록과 HTML 목업은 보존한다. 커밋·푸시와 HTML 매뉴얼 갱신은 하지 않는다.

- 정리일: 2026-10-22
- 상태: 사용자 문답으로 확정한 UX + 검토용 HTML 목업. 제품 구현 계획/완료 보고가 아님.
- 적용 대상: 달토끼 레벨 제작 도구. 게임 앱의 플랫폼 구성 변경은 포함하지 않음.
- 목업: [웹 레벨툴](../../MoonRabbitJunkyard/Mockups/level-tool-web.html)
- 현재 결정: PC·모바일 공통 목업을 먼저 검토한 후 구현 범위와 단계별 계획을 정한다.

## 1. 방향과 작업 경계

Windows·Android별 레벨툴 배포의 불편과 빌드 부담을 줄이기 위해 웹 빌드 방향으로 전환한다. Windows Chrome과 Android Chrome에서 접근하고, 마우스·키보드·터치 입력을 모두 고려한다. Unity의 기존 레벨 제작 및 시험 로직을 웹에서 어떻게 사용할지는 호환성 확인 후 구현 계획에 반영한다.

2026-10-22 후속 확정: 앞으로 레벨툴의 빌드·검증 대상은 Web Level Editor로 한다. Android·Windows 레벨툴은 차후 삭제 예정이며, 명시적인 삭제 작업 전까지 기존 프로필과 소스는 유지한다. 게임 앱의 Android·Windows 빌드 정책은 변경하지 않는다. 이번 후속 작업은 실제 웹 빌드와 Chrome 실행 검증까지 승인되었고 커밋·푸시는 금지한다.

웹 접속과 데이터 동기화는 별개다. 동일 URL로 접속해도 프로젝트 파일이 자동으로 다른 기기에 나타나는 것으로 확정하지 않았다. 브라우저 저장 위치, 파일 접근, ZIP 이동, 클라우드 동기화는 별도 결정 대상이다. 기존의 Windows 폴더/Android 앱 내부 저장소에 관한 초기 합의는 그대로 웹 구현 사양으로 사용하지 않는다.

이번 작업은 목업과 결정 기록만 작성한다. 실제 Unity 소스·씬·프리팹·빌드 프로필을 변경하지 않으며, 제품 빌드·커밋·푸시·HTML 매뉴얼 갱신은 하지 않는다. 기존 네이티브 레벨툴을 삭제하거나 빌드 프로필을 제거하는 작업도 승인 범위에 포함하지 않는다.

## 2. 프로젝트와 레벨 시작

1. 빈 편집기 대신 시작 화면을 제공한다. 새 프로젝트, 프로젝트 열기, ZIP 가져오기, 최근 프로젝트를 구분한다.
2. 새 프로젝트 생성의 필수 입력은 이름이다. 저장 위치/브라우저 권한 관련 상세 흐름은 웹 저장 방식 결정 후 보완한다.
3. 생성 직후 레벨을 자동 생성하지 않는다. ‘아직 만든 레벨이 없습니다’와 ‘첫 레벨 만들기’를 보여준다.
4. 새 레벨은 번호와 이름을 기본 제안하고 ‘만들고 편집하기’로 진입한다. 기본 보드는 9×9다. 이동 횟수·미션 등을 시작부터 긴 마법사로 요구하지 않는다.
5. 새 레벨의 출발점은 ‘기본 9×9 보드’ 또는 ‘현재 레벨 복제’다. 복제 시 보드·미션·이동 횟수·튜토리얼을 가져오고 원본은 유지한다. 미사용 다음 번호를 제안한다.

## 3. 편집 화면과 반응형 배치

- 보드가 주 작업 영역이다. 상단 메뉴가 과도하게 높아 보드 공간을 잠식하지 않게 한다.
- 넓은 PC·태블릿에서는 보드 중심에 좌우 도구 패널을 둔다.
- 휴대폰과 좁은 태블릿에서는 보드를 우선하고 필요한 패널만 연다. 세로는 하단 패널, 가로는 측면 패널을 사용한다. 가로·세로 모두 지원하는 방향이다.
- 상단은 현재 레벨 이름, 미저장 표시, 저장, 시험, 프로젝트 메뉴 중심이다.
- 제작 체크리스트는 보드 구성, 이동 횟수·미션, 플레이 확인, 저장을 안내한다. 강제 순서가 아니며 ‘설정됨’과 ‘시험으로 확인됨’을 구분한다.
- 체크리스트에서 할 일을 누르면 해당 설정으로 연결한다. 작은 화면에서는 다음 할 일을 간단히 표시하고 전체 목록을 열 수 있게 한다.
- ‘보드 집중’으로 패널을 숨기되 메뉴 복원, 실행 취소/다시 실행, 현재 도구는 접근 가능하게 한다. 펼칠 때 선택과 설정을 유지한다.
- 재실행 시에는 숨긴 집중 모드를 복원하지 않고 일반 반응형 화면으로 시작한다.
- 복잡한 기능은 보드·미션 중심 흐름과 구분한다. 튜토리얼은 단순히 메뉴를 숨기는 대신 아래의 목적 기반 작성 흐름으로 재구성한다. 추가 설정 전체의 최종 배치는 목업 검토 대상이다.

## 4. 보드 조작과 소재

- 기본 터치: 한 손가락은 편집, 두 손가락은 이동·확대/축소. 두 손가락 제스처로 전환할 때 대기 중 배치를 오작동으로 확정하지 않는다.
- 한 손 조작을 위해 별도 ‘이동’ 도구를 제공한다. 이동 중에는 배치하지 않는다.
- 소재 선택은 종류별 분류 + 검색 + 최근 사용을 기본으로 한다. 아이콘과 이름을 함께 표시한다.
- 휴대폰은 소재 선택 후 큰 선택창을 접고 현재 소재와 작은 도구줄을 남긴다. 넓은 화면은 소재 패널을 고정할 수 있다. 단순 보드 터치만으로 임의로 숨기지 않는다.
- 소재를 선택하면 해당 편집 층을 자동 선택한다. 같은 층은 교체하고 다른 층의 항목은 유지한다. ‘바닥 배치 중’처럼 현재 작업을 표시한다.
- 지우개는 현재 편집 층만 지운다. ‘바닥 지우기’처럼 대상을 표시한다. 전체 칸 비우기는 별도 기능이다.
- 길게 누르기/PC 우클릭으로 해당 칸의 층별 내용을 확인하고 삭제할 수 있게 한다.
- ‘선택’과 ‘배치’를 명확히 구분한다. 선택 도구로 기존 항목을 누르면 속성을 편집하고, 소재를 고르면 배치 도구가 된다.

## 5. 미션, 시험, 오류 안내

- 미션은 ‘무엇을 목표로 할까요?’에서 시작한다. 그림과 설명으로 목표를 고르고 대상·수량을 지정한다. 예: 일반 블록 수집 → 파란 블록 → 30개.
- 만든 미션은 쉬운 요약으로 보여주고 바로 수정·삭제할 수 있게 한다.
- 미저장 상태도 현재 편집 내용으로 시험할 수 있다. 시험 결과는 제작 데이터에 반영하지 않는다.
- 편집으로 복귀하면 보드 위치·확대율·선택 도구 등 편집 상태를 유지한다.
- 문제가 있는 항목에서 이유와 수정 진입점을 제공한다. 시험을 막는 오류만 실행을 차단하고 권장사항은 시험을 막지 않는다. 자세한 검사 결과는 필요할 때 펼친다.

## 6. 레벨 목록과 저장·내보내기

- 상단 현재 레벨 이름을 누르면 목록을 연다. 검색, 새 레벨 만들기, 최근 편집을 함께 제공한다.
- PC는 왼쪽 고정 목록, 작은 화면은 필요할 때 열고 편집 진입 후 닫는 방식이다.
- 목록 행을 누르는 것만으로 편집 레벨을 바꾸지 않는다. 명시적인 ‘편집’ 버튼을 사용한다.
- 최근 편집 20개를 프로젝트별로 보존하고 다시 실행해도 유지하는 요구는 유지한다. 웹에서의 영속 저장 수단은 추후 결정한다.
- 미저장 레벨을 바꿀 때 저장하고 열기 / 현재 레벨 변경 버리고 열기 / 계속 편집의 세 선택을 제공한다. 다른 레벨과 공유 데이터는 버리지 않는다.
- 수천·수만 레벨을 고려해 모든 JSON을 열지 않는다. 경량 목록 정보와 재사용 셀·검색 구조라는 기존 성능 요구를 유지한다. 웹의 목록 데이터 형식은 추후 설계한다.
- 저장은 명시적으로 하고, 그 전 변경은 메모리와 dirty 상태로 관리한다. 반복 편집마다 파일을 저장하지 않는다.
- ‘프로젝트 내보내기’ 하나로 ZIP 백업·다른 기기로 전달하는 용도를 설명한다. 미저장 변경이 있으면 저장하고 내보내기 / 취소를 제공한다.
- Android 네이티브에서 논의한 공유창 연동은 웹에서 지원 여부를 확인해야 한다. 공유 가능 시 공유, 그 외 다운로드 등 구체적인 대체 동작은 아직 확정하지 않았다.

## 7. 튜토리얼의 조립식 구조 유지

튜토리얼 내부는 공통 동작·조건·대상·안내·단계 연결을 조립하는 구조를 유지한다. 장애물 종류마다 독립된 튜토리얼 코드를 만드는 구조로 바꾸지 않는다.

- 동작 예: 두 칸 교환, 파워블록 사용.
- 조건 예: 매칭, 로켓/폭탄 등 생성, 지정 원인에 의한 내구도 감소, 남은 내구도 정확히 N.
- 구성 요소: 대상 칸/개체/영역, 횟수·수치, 안내문, 강조, 단계 연결, 필요한 신규 블록 공급.
- 목적 선택은 필요한 조립 항목을 제안하는 시작 도우미다. 완성된 튜토리얼을 강제로 만들지 않는다. 대상과 수치는 사용자가 결정한다.
- 기존의 인정 원인·조건 조합 정책은 UX 목업에서 임의로 넓히거나 변경하지 않는다.

## 8. 튜토리얼 작성 흐름

**목적 선택 → 보드 대상 선택 → 필수 설정 팝업 → 단계 추가·공급 설정 → 시험 → 완료**

1. ‘무엇을 가르칠까요?’에서 교환·매칭, 파워블록 생성, 파워블록 사용·조합, 장애물 내구도 감소 등을 고른다. 직접 조립 경로도 유지한다.
2. 보드를 보며 한 항목씩 안내받는다. 지금 해야 할 일을 쉬운 문장으로 표시하고 선택 결과를 강조한다. 이전 설정으로 돌아갈 수 있다.
3. 특정 위치가 필요한 경우 팝업 전에 보드 대상을 먼저 선택하도록 유도한다. 이미 적절한 대상을 선택했다면 재사용한다. 보드 전체/앞 단계 결과 대상이면 불필요한 칸 선택을 생략한다.
4. 정해진 수를 고르면 필수 설정 팝업을 자동으로 연다. 하나의 장애물은 1개 선택 후, 교환은 두 칸 선택 후 연다. 자유 영역 선택만 ‘선택 완료’를 누른다.
5. 선택 가능한 대상만 강조한다. 잘못된 칸은 선택하지 않고 이유를 짧게 설명한다. 대상이 없으면 배치로 안내한다.
6. 필수 설정이 있는 조건의 추가·변경에만 팝업을 사용한다. 누락 이유를 표시하고 필수값이 유효해야 적용할 수 있다. 취소는 항상 가능하다. 안내문 같은 간단한 수정까지 무조건 팝업으로 강제하지 않는다.
7. 기본 조건부터 보여주고 세부 조건은 펼친다. 적용된 세부 조건은 접혀 있어도 문장으로 요약한다.
8. 앞 단계 결과와 연결할 수 있으면 대상을 제안한다. ‘앞 단계에서 만든 로켓’처럼 설명하고 사용자가 확인·변경한다.
9. 앞 단계 수정으로 연결이 맞지 않게 되면 뒤 단계 내용을 자동으로 바꾸지 않는다. ‘확인 필요’와 수정 위치를 표시한다. 연결 오류는 완료 전 검사에서 해결하도록 한다.

### 기존 튜토리얼을 열었을 때

ID·조건 필드보다 순서와 목적을 먼저 보여준다. 예: ‘1. 두 블록을 교환해 3개 맞추기’, ‘2. 만들어진 로켓 사용하기’. 각 단계에서 위치 보기, 수정, 여기까지 시험을 제공한다. 수정도 동일한 안내 흐름으로 진행한다.

‘여기까지 시험’은 해당 단계의 보드를 인위적으로 만들어 시작하지 않는다. 처음부터 직접 진행하며 선택한 단계까지 확인한다. 중간 상태 저장/점프 실행은 이번 결정 범위에 포함하지 않는다.

## 9. 튜토리얼 작업의 완료·취소 경계

- 작업을 시작하면 완료 또는 전체 취소 전까지 다른 작업으로 전환하지 않는다. 내부의 보드 선택·배치·공급 설정·시험은 허용한다.
- 나가려 하면 ‘계속 작성 / 튜토리얼 작업 전체 취소’를 안내한다. 중간 초안을 남겨 나중에 이어 쓰는 흐름은 채택하지 않는다.
- 신규 작성 취소: 작성한 튜토리얼을 제거한다. 기존 튜토리얼 수정 취소: 수정 시작 전 상태로 복원한다.
- 작성 중 필요한 보드 배치와 공급 변경도 같은 작업 범위에 포함한다. 전체 취소 시 함께 복원한다. 작성 전의 다른 레벨·공유 데이터는 건드리지 않는다.
- 완료 전 필수값과 단계 연결 검사는 필수다. 실제 플레이 시험은 선택이며 미시험 상태는 ‘플레이 확인 필요’로 남긴다.
- 완료는 레벨의 편집 상태에 반영하는 동작이다. 파일 저장과 동일하지 않다.
- 앞선 논의의 ‘미완성 연결 상태 저장 가능’은 이후 확정된 작업 잠금·전체 취소·완료 검사 정책으로 대체한다. 일반 편집으로 미완성 튜토리얼을 넘겨 저장하지 않는다.
- 신규 공급은 ‘다음에 내려올 블록 지정’이라는 목적 중심 설명으로 기존 기능을 연결한다. 필요한 열과 순서를 사용자가 지정하고 필요하지 않으면 생략한다.

## 10. 목업 범위와 검증

목업은 단일 HTML이며 CSS·JavaScript·기존 블록 이미지가 내장되어 있다. 외부 폰트나 CDN 없이 열 수 있다. 기존 HTML 매뉴얼과 별개이며 제품 데이터는 읽거나 변경하지 않는다.

구현한 예시 조작: 프로젝트 생성과 빈 상태, 기본/복제 레벨 진입, 목록 검색과 편집 버튼, dirty 확인, 소재 선택과 배치/지우기/실행 취소, 미션 추가, 튜토리얼 목적·대상 선택·필수 설정·단계 요약·전체 취소 복원, 집중 모드, 반응형 패널.

완제품 기능으로 구현하지 않은 항목: 실제 JSON/ZIP 입출력·영속 저장·기기 간 동기화, 실제 매칭 시험, 모든 종류의 조건 검사/연결, 실제 공급 편집, 수만 건 목록 가상화, 우클릭/롱터치 층별 메뉴, 완전한 단축키 체계. 목업은 일부 대표 흐름을 검토하는 용도이며 전체 합의가 구현됐다는 의미가 아니다. 최근 목록·레벨 데이터도 데모 상태다.

Chrome 자동 검사와 캡처 검토:

| 화면 | 크기 | 확인 |
|---|---|---|
| PC | 1440×900 | 좌우 패널, 보드 81칸 표시 |
| 휴대폰 세로 | 390×844 | 하단 메뉴·패널, 필수 설정 팝업 |
| 휴대폰 가로 | 844×390 | 측면 패널, 보드 81칸 표시 |
| 태블릿 | 820×1180 | 반응형 도구 접근, 보드 표시 |

두 칸 선택 후 팝업, 필수값 누락 시 적용 차단, 단계 추가, 잘못된 장애물 대상 거부, 전체 취소 시 보드·단계·도구 상태 복원, JavaScript 오류 없음 확인. 보드 컨테이너 기준으로 모든 81칸이 들어오는지 검사했다. 추가로 보드 전용 Ctrl+휠 및 두 손가락 확대·축소/이동을 목업에 연결했다. 배율 범위는 목업 기준 50~300%이며 배율 버튼으로 100% 복원한다. Chrome 터치 이벤트 검사에서 메뉴 크기·페이지 배율 유지, 핀치 중 오배치 방지, 한 손가락 탭 배치, 확대·축소 및 초기화를 확인했다. Android 실기기/Unity 웹 플레이어 실행 검증은 하지 않았다.

## 11. 아직 결정할 사항과 다음 작업

1. 사용자가 PC·휴대폰 목업에서 화면 배치와 흐름을 확인한다.
2. 웹 작업 데이터의 저장·백업·기기 간 전달 방식을 결정한다. 로컬 브라우저 저장과 명시적 파일 내보내기를 기본으로 할지, 서버 저장/동기화를 도입할지는 미확정이다.
3. Unity 웹 빌드에서 현재 레벨툴·파일 기능·게임 시험의 호환성을 확인한다. WebGL/웹 빌드와 일반 HTML 목업은 동일한 실행 제품이 아니다.
4. 호스팅·접근 권한·업데이트·브라우저 종료 시 미저장 처리·기존 네이티브 버전 유지 기간을 결정한다.
5. 위 결과를 반영해 통합 가이드와 적당한 크기의 단계별 계획/목표를 작성한다. 전체 세부 구현 계획을 지금 한꺼번에 확정하지 않는다.

질문은 시간제한 없는 번호 선택 문답을 유지한다. 추가 논의 중 변경되는 사항은 이 문서의 기존 결정을 명시적으로 수정하며, 매 답변마다 문서를 반복 저장하지 않는다.
