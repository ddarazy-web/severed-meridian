# 레벨 튜토리얼 — 통합 개발 계획

상태: 1단계 완료, 2단계 준비. 2026-10-07.

기준: [확정 기획](../../../Contents/MoonRabbitJunkyard/13_레벨튜토리얼.md). 합의한15개 결정을 유지한다. 기획 문서의 과거 저장 설명보다 현재 소스의 스키마4/5·팩1/2·별도 요소 콘텐츠 팩을 저장 기준으로 삼는다.

## 목표와 구조

레벨 에디터에서 설명·지정 교환·파워 교환 발동·아이템 체험을 작성하고, 게임 진입 시 같은 실제 보드에서 순서대로 진행한다. 종료 시 보드를 재생성하지 않고 일반 플레이 또는 기존 승리 흐름으로 이어간다.

레벨 SO는 제작 데이터를 소유하고 배포는 기존50레벨 MemoryPack과 Addressables를 재사용한다. 별도 튜토리얼 기능이 진행 상태를 소유한다. 교환·피해·낙하·미션·아이템 효과는 기존 BoardActionExecutor를 사용하며 UI는 진행 상태를 표시한다.

## 3개 큰 단계

| 단계 | 작업 묶음 | 완료 시 확인할 결과 |
|---|---|---|
| 1. 데이터·저장·레벨 에디터 | 단계/조건/고정 공급, MemoryPack 호환, 대상 선택, 정적 검사와 Undo | 에디터에서 작성·저장·재로드하고 팩에서 동일 정보를 읽음 |
| 2. 실제 퍼즐 진행 제어 | 재현 가능한 준비·공급, 허용 행동, 결과/연출 대기, 무료 체험 권한, 조기 승리 보류 | 지정 조작만 진행되며 같은 보드에서 튜토리얼을 끝내고 일반 진행으로 복귀 |
| 3. 안내 화면·기록·최종 연결 | 강조/말풍선/손가락, 완료 저장, 시험3모드, 대표 레벨 적용과 통합 검증 | 실제 안내 진행, 완료 생략·중단 재시작·시험 기록 분리 확인 |

현재 단계만 상세화한다. 내부 항목마다 새 단계 번호/문서를 만들지 않는다. 단계 완료 후 실제 결과에 맞춰 다음 계획·목표·복사용 실행문을 작성하고 완료 보고한다. 다음 구현은 사용자 실행 지시 후 시작한다.

## 현재 소스에서 확인한 설계 결정

- 팩2의 PackedElementLevel/ElementLevelPack은 명시적 필드 순서 계약이다. 기존 DTO를 보존하고 새 외부 팩3에 기존 팩2 바이트와 레벨 번호별 튜토리얼 메타데이터를 담는다. 팩1/2는 튜토리얼 없음으로 읽으며 요소 ECPK 팩은 바꾸지 않는다.
- 튜토리얼 없는 구간과 스냅샷은 기존 포맷·바이트·지문을 유지한다. 튜토리얼 있는 구간은 같은 levels-XXXXXX 주소의 팩3을 쓴다. 구형 쓰기로 튜토리얼 정보를 조용히 버리는 경우는 거절한다.
- EndStableTurn은 미션 달성 즉시 승리와 라스트팡을 시작한다. 2단계에서는 팝업만 숨기지 않고 종료 결정 자체를 마지막 단계와 연출 완료까지 보류한다. 오류·실패·이동 소진을 무조건 성공으로 바꾸지 않는다.
- 생성·발동·제거 조건은 해당 행동의 실제 기록으로 판정한다. 보충 후 다시 채워진 칸이 비었는지 확인하는 것으로 제거를 판정하지 않는다.
- 입력 제한은 PuzzleBoardInput과 PuzzleGameSession 명령 경계에 함께 적용한다. 직접 명령으로도 우회하지 못하게 하며 일시정지/나가기는 유지한다.
- 현재 게임 아이템 실행에는 보유량 조회·차감이 없다. 지정 단계의 무료 사용 권한을1회로 제한하고 일반 사용과 구분한다. 계정·상점·전체 인벤토리는 새로 만들지 않는다. 보유량 연동이 생겨도 무료 체험은 소모 경계를 호출하지 않게 한다.
- 안내는 기존 Canvas의 uGUI 오버레이로 표시한다. 지정 보드 입력까지 막는 전체 모달 팝업으로 만들지 않는다. 일시정지/결과 팝업은 기존 프레임워크를 쓰고, 위에 팝업이 뜨면 튜토리얼 입력·연출을 중지한다.

## 단계별 검사

1단계는 네 단계 종류·참조 ID·고정 공급·좌표/벽/초기 대상/최소 이동 수, 원본/사본/팩 왕복, 구형 읽기,1/50/51/100/101 경계와 Undo를 확인한다. 후속 단계에서 생성될 파워를 초기 보드에 없다고 거절하지 않는다. 미래 보드 상태 검증은2단계의 재생 검사가 담당한다.

2단계는 실제 지시 행동을 재생하고 연쇄·낙하·드론 연출 완료를 기다린다. 다음 대상 소실과 고정 공급 부족을 단계별로 진단한다. 임의 공급이나 자동 섞기로 오류를 숨기지 않는다. 재진입 재현, 조기 미션 달성, 잔여 이동0에서 마지막 설명/완료, 체험 권한 소진·거절 시 미소비, 같은 보드 복귀와 기존 일반 플레이를 확인한다.

3단계는 자동/항상 실행/실행 안 함, 완료 생략, 중단 재시작, 재시작/다음 레벨/씬 종료, 팝업 중첩·구독 해제, 가로/세로·카메라 좌표 변화와 Asset/MemoryPack 진입을 확인한다. 대표 사례는 기본 교환, 로켓 생성→교환 발동, 지정 아이템 체험이다. 소개 번호1·2~5·9는 기획을 유지하지만 없는 출시 레벨을 임의 생성하거나 기존 배치를 전체 교체하지 않는다. 실제 적용 레벨과 필요한 배치 변경은3단계 계획에서 명시한다.

## 완료 기록과 공통 제약

실제 완료 기록은 레벨 번호로 관리하고 마지막 단계 및 관련 연출 완료 후에만 저장한다. 중간 단계는 저장하지 않는다. Editor 시험은 별도 시험 기록을 사용하고 실제 기록을 읽어 쓰지 않는다. 저장 수단은3단계 시작 때 실제 저장 계층을 확인하여 정하며 전체 계정 저장 설계로 확대하지 않는다.

work의 현재 HEAD/WIP와 원본 레벨·팩·이미지·GUID를 보존한다. 검사는 먼저 메모리 또는 소유한 임시 fixture를 쓴다. 출시 팩 재생성은 검증 후 명시적인 데이터 갱신 경로에서 수행한다. 과거 검사 출력은 백업·별도 결과 보관 후 원문을 복원한다.

Unity6000.3.10f1·9×9·기존 패키지/asmdef를 유지한다. 테스트는 Tests/Editor와 ProjectTests.ps1를 사용한다. 플레이어/Addressables 번들 빌드·자동 커밋/푸시·사용자 Unity 종료·임의 씬 저장은 하지 않는다. 새 이미지 제작과 상세 매뉴얼은 별도 작업이다.
