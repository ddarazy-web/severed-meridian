# 레벨 튜토리얼 — 통합 개발 가이드라인

상태: 공통1~4단계 및 후속5단계 완료. 2026-10-07 실제1레벨 기본 매칭·2레벨 로켓 콘텐츠 적용과 검증 반영. 6단계는 계획만 작성.

## 재계획 이유와 유지할 내용

기존 계획은 진행·입력·공급·종료를 다뤘지만 행동/조건의 등록 구조와 확장 검사를 명시하지 않았다. 기존 2단계의 엔진과 게임 연결을 분리한다. 전체 4단계 중 1단계는 완료 상태로 유지하고, 남은 작업은 2~4단계다. 이전 ‘2단계 실제 게임 연결’은 새 3단계, ‘3단계 안내·기록’은 새 4단계로 이동한다. 완료 기록의 과거 번호는 당시 계획을 뜻한다.

기획의 15개 결정, 9×9 보드, 실제 퍼즐 규칙, 제작 SO와 50레벨 MemoryPack/Addressables 배포를 유지한다. 완료된 데이터·팩3·제작 패널을 되돌리지 않는다. 기획 문서의 과거 구현 상태보다 현재 소스와 1단계 검증을 구현 기준으로 사용한다.

## 확장 구조와 책임

~~~text
레벨 데이터 → 종류별 등록 목록 → 현재 단계의 행동/조건 처리기
                              ↓
                   공통 진행 엔진·읽기 전용 상태
                              ↕
               게임 연결부 → 기존 실제 퍼즐 실행·결과
                              ↓
                 안내 화면 / 완료 기록 / 시험 결과
~~~

| 구성 | 소유하는 책임 | 확장 방법 |
|---|---|---|
| 공통 진행 엔진 | 순서, 행동 승인, 결과/연출 대기, 완료·오류·중단 | 새 행동마다 중앙 분기를 추가하지 않음 |
| 행동 처리기 | 설명 확인, 일반 교환, 파워 교환, 지정 아이템의 허용·성공 판정 | 행동 종류로 등록; 아이템은 필요한 경우 아이템 종류로 추가 조회 |
| 조건 판정기 | 생성·발동·제거 기록의 ID·좌표·수량 판정 | 조건 종류로 등록 |
| 게임 연결부 | 실제 명령, 시드·공급, 연출 완료, 종료 보류, 세션 수명 | 기존 BoardActionExecutor와 세션 경계에 연결 |
| 표현 모듈 | 강조·말풍선·손가락·무료 체험 표시 | 읽기 전용 상태에서 조합; 진행 로직은 소유하지 않음 |
| 제작·검사 | 지원 여부, 공통 배치 검사, 종류별 설정 검사·참조 수집 | 실행과 검사에서 같은 종류별 규칙 사용 |

- 기능 소유의 명시적 조립 지점에서 등록하고 실행 중 변경하지 않는다. 전역 가변 목록, 매 프레임 리플렉션·전체 처리기 탐색은 사용하지 않는다. 중복/미등록 종류는 오류다.
- 현재 단계의 행동 처리기와 지정된 조건 판정기만 조회한다. 공유 규칙과 실행별 진행/집계 상태를 분리하여 시험 세션끼리 상태를 공유하지 않는다.
- 오브젝트마다 처리기를 만들지 않는다. 같은 특성은 요소 ID·좌표·수량으로 공통 처리한다. 실제 블록·장애물·미션 기능을 튜토리얼에 재구현하지 않는다.
- 입력은 공통 진행부에서 허용을 받고 게임 연결부가 실행한다. 관련 행동/연쇄 기록과 연출 완료만 해당 단계에 반영한다. 지난 단계·취소 세션의 지연 결과가 현재 단계를 완료시키지 못한다.
- 현재 네 단계·세 결과 종류로 구조를 검증한다. 임의 문자열 플러그인, 범용 워크플로 엔진, 새 패키지·DI 체계·asmdef는 만들지 않는다.
- 기존 enum 값과 MemoryPack 필드 순서는 유지한다. 새 종류는 값 추가·등록·지원 검사, 필요시 제작 UI 변경을 동반한다. 새 저장 항목은 별도 팩 호환성 검토가 필요하다. 모든 기능을 데이터만으로 추가한다는 의미가 아니다.
- MVVM 전체 프레임워크 대신 진행 상태와 표현을 분리한다. UI는 상태를 읽고 명령을 요청하며 퍼즐 데이터와 진행 상태를 직접 변경하지 않는다.

## 단계별 진행

| 단계 | 범위 | 검증 가능한 결과 |
|---|---|---|
| 1. 데이터·저장·레벨 에디터 — 완료 | 단계/조건/고정 공급, 팩 호환, 대상 선택, 정적 검사·Undo | 작성·저장·재로드·Asset/팩 복원이 동일함 |
| 2. 확장 가능한 진행 엔진 — 완료 | 등록 목록, 처리기·판정기, 공통 진행, 검사 규칙 공유, 확장 검사 | 게임 UI 없이 기존 종류가 진행되고 중앙 진행 수정 없이 처리기를 등록 가능 |
| 3. 실제 게임 연결·재생 검사 — 완료 | 입력/세션, 실제 기록, 시드/공급, 연출·종료·수명, 에디터 재생 검사 | 지정 조작만 실제 보드에서 실행되고 같은 보드에서 일반 플레이로 복귀 |
| 4. 안내 화면·기록·최종 적용 — 완료 | 강조/말풍선/손가락, 완료 저장, 시험 3모드, 대표 레벨 적용·통합 검증 | 안내·생략·중단 재시작·시험 기록 분리와 실제 플레이 확인 |

### 2단계의 작업 묶음

A. 등록/처리 계약과 종류별 규칙 → B. 진행 엔진과 결과 판정 → C. 정적 검사 연결과 확장 검증.

네 단계·세 아이템·세 결과를 등록한다. 기존 데이터와 검사 결과를 보존한다. 소유한 시험 입력과 결과/연출 신호로 엔진을 검사한다. 이 단계가 끝나도 실제 게임 자동 튜토리얼은 아직 제공되지 않는다. 상세 범위는 [2단계 계획](stage-02-runtime-plan.md)과 [목표](../../../Goals/MoonRabbitJunkyard/Tutorial/stage-02-runtime-goal.md)에 둔다.

### 3단계의 작업 묶음과 완료 기준

A. 세션 준비·명령 경계 → B. 실제 결과·연출·종료·일반 공급 복귀 → C. 실제 행동 재생 검사와 에디터 연결.

- 레벨 정의 파기 전에 튜토리얼 사본을 확보한다. 고정 시드·공급으로 중단 후 재진입을 재현하고 원본 SO를 변경하지 않는다.
- PuzzleBoardInput과 PuzzleGameSession 직접 명령에 같은 허용 검사를 둔다. 시작 부스터/임의 아이템은 차단한다. 무료 체험은 지정 단계 성공 시 한 번 소진하며 전체 재고 시스템은 만들지 않는다.
- 실제 행동/연쇄의 생성·발동·제거 기록을 공통 계약으로 전달한다. 재보충 후 빈칸 여부로 제거를 판단하지 않고 2×2 제거를 피해 칸 수만큼 중복 집계하지 않는다.
- 논리 연쇄와 드론·낙하·피해·수집 표시 완료 후 진행한다. 팝업/일시정지는 진행을 멈추고 나가기는 유지한다. 실제 연출 지연 검사는 모의 신호 검사와 별도로 수행한다.
- EndStableTurn의 승리/라스트팡·이동 소진/자동 섞기를 필요한 동안 보류하고 완료 후 한 번 재평가한다. 곰팡이 턴 종료를 중복 적용하지 않는다. 이동 0의 마지막 설명/무료 아이템 경계를 검사하고 설정 오류/실패를 성공으로 바꾸지 않는다.
- 공급 부족·미등록 생성구·불가능한 후속 교환·대상 소실을 단계 경로로 진단한다. 무작위 기본 공급·임의 시드·자동 섞기로 오류를 숨기지 않는다.
- 일반 공급 복귀 시 보드/내구도/누적 미션/이동/턴/난수를 보존하고 공급 전환 자체로 블록을 만들지 않는다. 재시작/다음 레벨/실패/취소/파기의 대기·구독을 해제한다.
- 실제 BoardActionExecutor를 사용하는 재생 검사를 에디터/실행 전 검사에 연결한다. 시험 사본만 사용하고 플레이어용 자동 진행 버튼은 추가하지 않는다.
- 기본 교환, 로켓 생성→교환 발동, 망치/교환/섞기의 fixture로 성공·거절·재진입·조기 승리·이동 0·직접 명령 우회·연출 지연·팝업을 확인한다. Asset/팩3 동등과 일반 플레이·저장·드론·결과/팝업 회귀를 확인한다.

### 4단계의 작업 묶음과 완료 기준

A. 안내 표현 → B. 완료 기록·에디터 시험 3모드 → C. 대표 레벨 적용과 통합 검증.

- 기존 Canvas의 uGUI 오버레이로 강조·말풍선·손가락·다음·무료 체험을 표시한다. 지정 보드 입력을 막는 전체 모달로 만들지 않는다. 표현 모듈은 읽기 전용 상태를 사용하고 입력 판정은 재구현하지 않는다.
- 마지막 단계와 관련 연출 완료 후 레벨 번호 기준으로 완료 기록을 저장한다. 중간 진행은 복원하지 않는다. 저장 수단은 당시 실제 저장 계층에서 정하고 전체 계정 시스템으로 확대하지 않는다.
- 자동/항상 실행/실행 안 함 시험 모드를 연결하고 시험 기록을 실제 기록과 분리한다. 완료 생략·중단 재시작·재시작/다음 레벨/씬 종료·팝업 중첩·구독 해제를 확인한다.
- 가로/세로·카메라 변경 시 강조/손가락 좌표·입력 전달·UI 해제를 확인한다. 기획의 소개 순서를 유지한다. 적용 레벨과 배치 변경은 4단계 상세 계획에서 정하며 없는 레벨을 임의 생성하거나 기존 배치를 전체 교체하지 않는다.
- 실제 화면과 Asset/MemoryPack 진입을 검증한다. 제작 SO는 배포하지 않으며 승인된 데이터 갱신 경로에서만 팩을 갱신한다. 번들/플레이어 빌드는 하지 않는다.

## 문서·실행·검증 원칙

현재 단계만 상세 계획·목표·복사용 실행문으로 작성한다. 내부 A~C를 별도 단계/문서로 쪼개지 않는다. 완료 시 변경·실제 검증·미완료/제약을 보고하고 다음 단계의 세 문서를 작성한다. 다음 구현은 사용자 실행 지시 후 시작한다. 변경된 계약은 이유와 영향 범위를 기록한다.

팩1/2/3·50레벨 주소·ECPK·제작 SO 배포 제외를 보존한다. 원본 레벨/팩/이미지/GUID/HEAD·WIP를 유지하고 메모리 또는 소유한 fixture로 검사한다. 과거 검사 출력은 보관 후 복원한다.

Unity6000.3.10f1과 기존 패키지/asmdef를 유지한다. Tests/Editor와 Tools/Testing/ProjectTests.ps1를 사용하고 테스트 해제 후 게임 소스 컴파일을 확인한다. 실제 화면/기기/연출 검증을 못하면 완료로 표현하지 않는다.

빌드·번들 생성·자동 커밋/푸시·하위 에이전트·사용자 Unity 종료·임의 씬 저장·출시 데이터 덮어쓰기는 하지 않는다. 고물탑·새 이미지·상세 매뉴얼은 이 범위가 아니다.

## 완료 후 콘텐츠 작업

공통 시스템 개발 1~4단계는 완료했다. 후속 5단계는 기존 시스템을 사용하는 실제 2레벨 청소로켓 콘텐츠 제작이다. 로켓 생성→교환 발동의 한 레벨만 작성·적용·검증하고, 기존 1레벨은 보존한다. 문서 작성 시점에는 새 레벨/팩/소스를 변경하지 않는다.

[5단계 계획](stage-05-rocket-content-plan.md) · [목표](../../../Goals/MoonRabbitJunkyard/Tutorial/stage-05-rocket-content-goal.md) · [복사용 실행문](../../../Commands/MoonRabbitJunkyard/Tutorial/stage-05-command.md).

이후 콘텐츠는 기존 소개 순서에 따라 단계 완료 시 다음 범위만 상세 계획한다. 모든 후속 계획을 지금 작성하거나 3~5/9레벨을 동시에 생성하지 않는다.

### 후속 5단계 완료와 다음 범위

5단계에서 실제 전체9×9 Level_02와 같은 구간 팩, 가로4매칭→세로로켓 생성/교환 발동 5단계 안내를 적용했다. Asset/MemoryPack 실제 에디터 진입과 UI/포인터·모드·기록·1→2 전환을 검증했고 게임 소스 단독 컴파일을 확인했다. 기존 드론 종합 시간 검사 실패와 실기기 미검증은 [5단계 완료 보고](../../../Verification/MoonRabbitJunkyard/Tutorial/stage-05-progress.md)를 따른다. 위 이전 시점의 ‘없는2레벨’ 설명은 당시 계획의 전제다.

다음6단계는 실제3레벨 ㄱ 매칭 달 폭탄 하나의 생성→인접 교환3×3 발동 콘텐츠다. 후보·재생, 저장·실제 UI, 기록·회귀·인계의 세 작업 묶음으로 직접 진행한다. 새3레벨/팩 변경은 다음 실행 지시 후 시작한다.
