# 레벨 튜토리얼 2단계 — 실제 퍼즐 진행 제어

상태: 준비. 1단계 검증 결과를 전제로 수행하며 자동 착수하지 않는다.

[통합 계획](integration-guideline.md) · [기획](../../../Contents/MoonRabbitJunkyard/13_레벨튜토리얼.md) · [목표](../../../Goals/MoonRabbitJunkyard/Tutorial/stage-02-runtime-goal.md) · [실행문](../../../Commands/MoonRabbitJunkyard/Tutorial/stage-02-command.md).

## 목표와 범위

1단계의 레벨 정의·팩3·제작 패널을 사용해 지정 행동과 실제 결과로 튜토리얼을 진행한다. 동일 보드에서 끝내고 일반 플레이로 돌아간다. 이번 단계는 진행 엔진과 게임 세션 연결이다. 말풍선·손가락·완료 영구 저장·에디터 3모드·출시 레벨 적용은 3단계에 남긴다.

별도 가짜 퍼즐을 만들지 않는다. 교환·아이템·연쇄·낙하·피해·미션은 기존 BoardActionExecutor가 실행한다. 튜토리얼은 허용 행동, 단계 진행, 공급 전환과 종료 보류의 시점을 소유한다. 레벨 번호별 분기는 추가하지 않는다.

## 현재 코드에서 확인한 연결 지점

- PuzzleGameSession.PrepareAsync는 StartingBoardSearch로 초기 상태를 만든 뒤 레벨 정의를 파기한다. 튜토리얼 제작 값을 세션 소유 사본으로 확보하고 초기 준비·재시작·다음 레벨 전환에 같은 정책을 적용해야 한다.
- PuzzleBoardInput은 입력을 받지만 직접 TrySwap/TryActivate/TryUseItem 호출도 가능하다. 세션 명령 경계에도 허용 검사를 둔다. 기존 팝업/화면 차단과 일시정지를 유지한다.
- BoardActionExecutor.EndStableTurn은 목표 달성 즉시 Outcome과 라스트팡을 시작하고, 이동 소진과 자동 섞기도 처리한다. 안내 팝업만 늦추는 것으로는 충분하지 않다. 튜토리얼 진행 중 종료·자동 섞기 결정을 명시적으로 보류하고 완료 시 한 번만 재평가한다.
- PuzzleGameSession에는 IsPresenting·HasProgressFeedback·IsStartingFeedback 등 실제 표시 대기가 있다. 논리 상태가 안정됐다는 이유만으로 드론·낙하·수집 연출이 끝나기 전에 다음 단계로 넘기지 않는다.
- RuntimeSupply는 공급 커서·생성 본체 정의를 보유한다. 공급만 전환하면서 현재 셀·장애물 내구도·미션·이동·난수·턴을 보존하는 경계를 정한다. 미등록 생성구의 무작위 기본 공급도 튜토리얼 중 허용하지 않는다.
- 현재 아이템 명령은 보유량을 조회·차감하지 않는다. 지정 체험 권한을 성공 시 1회 소진하는 범위로 구현하며 전체 인벤토리는 만들지 않는다.

## 작업 묶음

내부 A~D는 작업 순서이며 별도 단계 번호나 문서를 만들지 않는다. 실패 사례를 먼저 확보하고 각 묶음을 검증한 뒤 다음으로 진행한다.

### A. 진행 상태와 결과 판정

- [ ] Tutorial/Runtime에 진행 상태 소유자를 추가한다. 설명 대기·행동 대기·연출 대기·완료·설정 오류를 구분하고 현재 단계/허용 입력/실패 원인을 읽을 수 있게 한다.
- [ ] 설명은 명시적인 다음 요청, 조작은 지정 대상/아이템/파워 ID의 성공으로 진행한다. 교환 방향을 반대로 입력했을 때의 허용 여부는 제작의 첫→둘째 안내와 실제 스와이프 기준을 확인하여 일관되게 정한다.
- [ ] 생성·발동·제거 조건은 해당 행동과 연쇄의 실제 기록을 모아 ID·선택 좌표·수량으로 판정한다. 이미 채워진 칸이 빈칸인지로 제거를 판정하지 않는다. 2×2 본체를 여러 피해 셀 때문에 여러 개 제거한 것으로 세지 않는다.
- [ ] 거절된 행동은 단계/권한/난수/이동/미션을 바꾸지 않는다. 중복 완료 신호도 다음 단계를 두 번 넘기지 않는다. 설명·섞기에는 불필요한 대상 칸을 요구하지 않는다.

### B. 준비·고정 공급·같은 보드 복귀

- [ ] 초기 튜토리얼 시드를 사용하고, 원본 SO와 보통 플레이용 공급은 변경하지 않는다. 중단 후 재진입·다시하기가 같은 순서를 재현한다.
- [ ] 튜토리얼의 고정 공급 정의/커서를 실제 공급에 연결한다. 무작위 기본 생성, 임의 시드 변경, 자동 섞기로 설정 오류를 숨기지 않는다. 소진 시 부족한 생성구와 단계를 식별한다.
- [ ] 완료 시 일반 플레이 공급으로 전환한다. 현재 보드를 재생성하거나 누적 미션·이동·피해·턴·난수를 초기화하지 않는다. 공급 전환 자체로 블록을 만들지 않는다.
- [ ] 시작 부스터 및 임의 아이템은 차단하고 지정 무료 체험만 허용한다. 기존 일반 플레이와 튜토리얼 없는 레벨에는 변경된 제한을 남기지 않는다.

### C. 게임 세션·연출·종료 연결

- [ ] PuzzleGameSession과 PuzzleBoardInput에 허용 행동을 연결한다. 직접 명령 우회, 연출 중 연속 입력, 지정하지 않은 제자리 파워 발동도 차단한다. 다음 버튼용 명령과 현재 단계의 읽기 전용 상태를 제공한다.
- [ ] 실제 연쇄 완료와 관련 드론·피해·낙하·수집 표시 완료를 함께 기다린다. 팝업/일시정지 중에는 안내 시간과 입력을 멈추고 나가기는 유지한다.
- [ ] 조기 목표 달성 시 승리·라스트팡을 보류한다. 마지막 단계의 연출까지 끝나면 한 번만 기존 종료 흐름을 실행한다. 곰팡이 턴 종료 처리를 두 번 적용하지 않는다.
- [ ] 마지막 교환 후 이동 0에서도 마지막 설명/완료를 진행한다. 추가 교환은 허용하지 않는다. 이동 0에서 필요한 마지막 무료 아이템 체험의 허용 경계를 실제 종료 규칙과 함께 검사한다. 설정 오류/실패를 성공으로 바꾸지 않는다.
- [ ] 체험 권한은 해당 아이템 단계에서만 1회이며 성공 시 소진한다. 거절·취소·일시정지·다른 단계에 넘기지 않는다. 보유량 연동이 없는 현 코드에서는 재고 시스템을 가정해 만들지 않는다.
- [ ] 재시작/다음 레벨/파기 시 진행 상태·대기·이벤트를 해제한다. 시작 실패·취소도 같은 수명 규칙을 사용한다.

### D. 재생 검사와 인계

- [ ] Tutorial/Validation에 실제 지정 행동을 재생하는 검사를 추가한다. 미래 대상 소실·불가능한 교환·결과 불일치·공급 부족을 단계 경로로 반환한다. 실제 보드/연출 대기의 검사와 정적 검사를 구분한다.
- [ ] 1단계 제작 패널과 실행 전 검사에 재생 결과를 연결한다. 원본을 수정하지 않고 소유한 시험 사본에서 실행한다. 실제 플레이를 자동 진행시키는 디버그 단추는 사용자용 UI에 추가하지 않는다.
- [ ] 기본 교환·로켓 생성→교환 발동·망치/교환/섞기 체험의 소유한 fixture로 성공/거절/재진입/조기 승리/이동 0/팝업/연출 지연을 검사한다. 후속 생성 파워를 초기 보드에 요구하지 않는다.
- [ ] Asset/팩3 동등, 일반 플레이·저장·배치·드론·결과/팝업 회귀와 테스트 해제 후 게임 소스 컴파일을 확인한다. 기록을 남기고 3단계 계획·목표·복사용 실행문을 작성하여 보고한다. 3단계 구현은 자동 시작하지 않는다.

## 파일 경계와 제약

신규 진행/준비 코드는 Assets/Scripts/Features/Tutorial/Runtime, 실제 재생 검사는 Tutorial/Validation, 검사는 Tests/Editor/Features/Tutorial에 둔다. 기존 세션·입력·종료·공급에서 필요한 호출부만 수정한다. 타입과 세부 분할은 실제 행동 기록/취소 경계를 확인하며 조정하고 이 계획에 기록한다. 범용 상태 머신·전역 관리자·신규 패키지/asmdef는 추가하지 않는다.

1단계의 팩1/2/3 계약·50레벨 주소·ECPK·제작 SO 배포 제외와 원본/GUID/WIP를 보존한다. 빌드·번들 생성·커밋·푸시·하위 에이전트·사용자 Unity 종료·임의 씬 저장·출시 레벨/팩 덮어쓰기는 하지 않는다. 과거 검사 결과 파일은 보관 후 복원한다. 상세 매뉴얼은 이번에 작성하지 않는다.
