# 튜토리얼 후속 5단계 — 2레벨 청소로켓 콘텐츠

> 실행 방식: `superpowers:executing-plans`로 이 세션에서 직접 진행한다. 문서 작성 시점에는 구현하지 않는다. 빌드·커밋·푸시·하위 에이전트는 사용하지 않는다.

상태: 완료. 2026-10-07. 최종 근거·회귀 범위·제약은 stage-05-progress.md를 따른다.

목표: 실제 2레벨에서 직선 4매칭으로 청소로켓을 만들고, 생성된 로켓을 인접 블록과 교환해 발동한 뒤 같은 보드로 자유 플레이를 이어간다.

구조: 완료된 1~4단계의 제작 데이터·등록 처리기·실제 실행기·안내 UI·완료 기록을 그대로 사용한다. 이번은 공통 시스템의 미완료 단계가 아니라 첫 후속 콘텐츠 작업이다.

기술: Unity6000.3.10f1, 9×9, 기존 C#/uGUI/UniTask/MemoryPack/Addressables, 50레벨 구간 저장.

## 전제와 결정

- 현재 제작 에셋은 Level_01 하나다. 2레벨은 새 콘텐츠로 제작하며, 1레벨을 수정하거나 검사용 좁은 RocketBoard를 출시 보드로 복사하지 않는다.
- 2레벨은 기본 9×9 활성 보드, 장애물 없는 색상 수집 미션을 사용한다. 최초 후보의 색상·미션·이동 횟수는 현재 1레벨의 일반 설정을 기준으로 가져온다. 튜토리얼 배치·시드·공급은 새로 작성한다. 이번은 전체 초반 난이도 조정 작업이 아니다.
- 신규 제작은 현재 요소 정의/카탈로그와 제작 도구의 schema5 경로를 따른다. 1레벨의 구형 제작 스키마를 이유로 기존 데이터를 일괄 마이그레이션하지 않는다.
- 대표 생성은 가로 직선 4매칭 → 세로 로켓 한 종류다. 세로 직선 4매칭 → 가로 로켓 규칙도 기존 회귀로 보존하되 별도 강제 안내를 추가하지 않는다.
- 안내 순서는 설명 → 지정 교환으로 로켓 생성 → 생성 결과 설명 → 새 로켓의 지정 교환 발동 → 종료 설명이다. 성공한 두 교환은 각각 이동 1회를 소비한다.
- 설명 예시: “같은 색 4개를 한 줄로 맞추면 청소로켓이 생겨요.” / “가로로 맞춰서 세로 청소로켓이 생겼어요. 옆 블록과 바꿔 보세요.” / “이제 남은 달토끼를 모아 보세요.” 실제 확정 배치의 방향과 문구를 일치시킨다.
- 생성된 로켓의 좌표/방향과 후속 인접 칸은 실제 실행 조회·재생으로 확정한다. 생성 단계는 `Generated power.rocket`, 발동 단계는 `Activated power.rocket` 결과 조건을 사용한다. 생성 칸을 원래 배치만 보고 추정하지 않는다.
- 고정 시드는 12345를 최초 후보로 사용한다. 후보 실패를 숨기기 위해 실행 중 임의 시드로 대체하지 않는다. 다른 후보가 필요하면 실제 재생 근거와 함께 하나를 확정해 저장한다.
- 튜토리얼 중 생성구마다 필요한 고정 공급을 선언한다. 낙하·연쇄로 다음 대상이 사라지지 않는 것을 먼저 증명하고 실제 소비량과 필요한 여유만 남긴다.
- 새 2레벨 에셋/메타와 해당 1~50 구간 팩 갱신은 이 단계 실행문을 사용자가 실행할 때 허용한다. 현재 문서 요청만으로 생성하지 않는다.

새 검사 계약은 `public static void Preview()`(메모리 후보, 출시 저장 없음), `public static void Apply()`(검증 성공한 후보만 저장/구간 인코딩), `public static void Run()`(저장된 실제 콘텐츠와 UI 검증)이다. 결과는 `Logs/Tutorial/Stage05`에 남기고 성공 exit 0, 실패 exit 1로 종료한다. 적용 전에 Run이 `2레벨 출시 에셋 없음`으로 실패하는 근거를 확보하고 저장 후 같은 검사가 통과하는 것을 확인한다. 이미 사용자 2레벨이 있다면 부재 검사를 위해 삭제하지 않는다.

## A. 실제 출시 보드 후보와 재생 증명

- [x] HEAD/WIP, 현재 1레벨/구간 팩/기존 GUID/주소/카탈로그를 기록하고 보호 해시를 확보한다. 기존 2레벨이 생겼다면 사용자 변경을 덮어쓰지 않고 현재 데이터를 먼저 평가한다.
- [x] 새 검사 `Preview`에서 메모리의 전체 9×9 후보를 구성한다. 출시 데이터 저장 없이 실제 `StartingBoardBuilder`, `ActionQuery`, `BoardActionExecutor`, `LevelTutorialReplayValidator`를 사용한다.
- [x] 중앙 부근의 고정 일반 블록으로 지정 4매칭을 구성하고 생성 위치·세로 방향·발동 교환 상대를 실제 결과로 확인한다. 생성→낙하→설명→발동→표시 완료까지 후속 대상이 유지되는 후보만 채택한다.
- [x] 선언한 고정 공급으로 끝까지 재생한다. 무작위 공급, 공급 누락, 다른 교환, 제자리 발동은 해당 단계의 실패/거절 사례로 검사한다.
- [x] 결과에 선택된 좌표/방향/시드/생성구·소비량/단계별 이동·미션 진행을 남긴다. 실패 시 데이터 후보를 고치며 공통 엔진에 특별 처리를 추가하지 않는다.

검사 명령: `& Tools/Testing/ProjectTests.ps1 -Action Run -Method TutorialRocketLevelVerification.Preview`.

통과 결과: 출시 에셋은 아직 없거나 그대로이며, 전체 보드 후보의 정적/실제 재생 오류 0. 정확히 로켓 하나 생성, 지정 로켓 발동, 두 번의 정상 이동 차감이 확인된다. 검증용 정상/실패 후보를 분리해 불가능한 안내를 통과시키지 않는다.

## 제한과 검토 초점

1. 생성 로켓이 연쇄로 소실되거나 이동한 경우 — 재생에서 거절하고 다음 단계의 실제 좌표를 재설계한다.
2. 잘못된 방향 설명/위치 — 생성 결과와 실제 제거 행/열, 문구·손가락을 함께 대조한다.
3. 기존 구간의 다른 레벨 누락 — 원래 구간 목록/논리 내용을 비교하고 레벨 1을 보존한다.
4. 중단/완료/시험 기록이 다른 레벨에 전이 — 실제 레벨 2 재진입과 레벨별 분리 검사로 확인한다.
5. 보드가 정상 진행 가능하지만 말풍선이 입력 경로를 가림 — 두 화면 비율에서 실제 포인터와 캡처로 확인한다.

빌드·번들·커밋·푸시·하위 에이전트·사용자 Unity 종료·임의 씬 저장을 하지 않는다. 3~5/9 등 다른 출시 레벨, 새 이미지, 무료 아이템 소개, 전체 해금/인벤토리/계정 시스템, 전체 밸런스 조정·상세 매뉴얼·고물탑은 포함하지 않는다. 이번 문서 작성으로 게임 데이터/소스는 바꾸지 않는다.
