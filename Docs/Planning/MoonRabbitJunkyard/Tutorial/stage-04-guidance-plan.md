# 레벨 튜토리얼 4단계 — 안내·완료 기록·최종 적용

> 실행 방식: 이 세션에서 executing-plans 절차로 직접 수행한다. 빌드·커밋·푸시·하위 에이전트는 사용하지 않는다.

상태: 준비. 3단계는 완료했으며 이 문서는 다음 사용자 실행 지시의 범위다. 아직 4단계 소스를 구현하지 않았다.

목표: 실제 보드에서 안내를 보고 조작하게 하고, 완료한 레벨 튜토리얼은 재입장 시 생략한다. 제작자는 실제 기록을 변경하지 않고 세 모드로 시험한다.

기술: Unity6000.3.10f1, 기존 C#/UniTask/uGUI/MemoryPack/Addressables. 9×9 및 기존 패키지·asmdef 유지.

## 전제와 유지할 계약

- `TutorialProgress`와 등록된 행동/결과 처리기를 재사용한다. 안내 화면은 `PuzzleGameSession.TutorialState`를 읽고 다음 요청은 `TryAdvanceTutorial`로 전달한다. 별도 진행 엔진·블록별 분기·MVVM 프레임워크를 만들지 않는다.
- 3단계의 고정 시드/공급, 실제 결과 식별, 입력 승인, 무료 체험, 표시 완료, 종료 보류, 원래 공급 복귀 및 수명 격리를 보존한다. UI는 권한을 다시 판정하거나 결과를 가짜로 보고하지 않는다.
- 현재 제작 레벨은 `Assets/Data/Levels/Level_01.asset` 하나다. 기존 팩에 레벨 2가 없다. 기획 순서는 1 기본 매칭, 2~5 로켓/폭탄/드론/자석, 9 로켓 조합이다. 없는 출시 레벨을 임의 생성하거나 모든 소개를 1레벨로 옮기지 않는다.
- 3단계의 논리 재생은 화면 검사가 아니다. 4단계는 실제 안내·입력·팝업·완료 기록까지 Play Mode에서 따로 확인한다.

## 책임과 변경 영역

| 영역 | 책임 |
|---|---|
| Tutorial/Runtime/Presentation — 신규 | 말풍선·강조·손가락·무료 표시. 진행 판정 없이 전달받은 상태/화면 좌표 표시 |
| Tutorial/Runtime/Completion — 신규 또는 기존 저장 계층 연결 | 레벨 번호별 완료 조회/기록. 실제 기록과 시험 기록 분리 |
| GameScreen/Runtime/Tutorial — 신규 연결부 | 세션/보드/카메라와 안내 연결, 다음 버튼, 무료 아이템 선택, 변경/해제 구독 |
| GameScreen/Runtime/Session/PuzzleGameSession.Tutorial.cs 및 준비/재시작/전환 경계 | 실행 정책을 준비 전에 결정. 실행 시 기존 adapter, 생략 시 기존 일반 경로 사용 |
| GameScreen/Editor의 실행 요청·레벨 에디터 시험 진입 | 자동/항상 실행/실행 안 함 옵션 전달. 런타임에서 Editor 타입 참조 금지 |
| Assets/Prefabs/UI/Puzzle/TutorialOverlay.prefab — 신규, 기존 UI 프리팹 연결 | 기존 Canvas/uGUI 스타일과 한글 폰트 재사용. Game 프리팹과 구분 |
| Tests/Editor/Features/Tutorial — 신규 통합 검사 | 안내/기록/시험 모드/방향/수명/원본 및 기존 회귀 |
| 기존 Level_01.asset 및 해당 구간 MemoryPack | 기본 매칭 안내 메타데이터만 대표 적용. 기존 갱신 도구와 주소 사용 |

파일명은 구현 시작 시 기존 담당 파일을 확인해 확정하고 검증 기록에 남긴다. 필요한 역할만 나누고 전역 관리자나 새 DI/asmdef를 추가하지 않는다.

## A. 실제 안내 표현과 입력 연결

1. 기존 `PuzzleScreenView`, `PuzzlePopupBinding`, 아이템 버튼, 카메라/레이아웃과 세션 변경 이벤트를 조사한다. 기존 UI 프리팹의 스타일을 유지하며 전용 안내 프리팹과 연결부를 만든다.
2. 설명에는 문구와 다음 버튼을 표시한다. 조작에는 선언된 대상 강조와 교환 손가락을 표시하고, 결과/표시 대기에는 추가 행동을 유도하지 않는다. 최초 진행에 건너뛰기를 추가하지 않는다.
3. 주변 어둡게 하기/강조는 지정 보드 입력을 가로채는 전체 모달로 만들지 않는다. 버튼 영역 외 장식의 raycast를 끄고 허용 여부는 기존 입력/세션 API에 맡긴다. 드론의 실제 목적지는 미리 표시하지 않는다.
4. 지정 아이템 버튼에 `무료 체험`을 표시한다. 망치/교환은 기존 아이템 선택 후 보드 대상 입력, 섞기는 기존 버튼 실행을 사용한다. 별도 재고를 만들거나 실제 보유량을 소비하지 않는다.
5. 보드 transform·카메라·Canvas·Safe Area를 이용해 좌표를 변환한다. 가로/세로 및 화면 크기 변경에도 강조/손가락/말풍선이 맞아야 한다. 매 프레임 새 목록/클로저를 만들지 않는다.
6. 팝업 중첩·일시정지 중에는 다음/조작을 보류한다. 키 이벤트는 기존 최상위 팝업 정책을 지키며 일시정지와 나가기를 유지한다. 재시작/전환/실패/파기 때 이전 안내와 구독을 제거한다.

검증: 실제 UI 버튼과 포인터 입력으로 설명→지정 교환→로켓 생성/발동→무료 아이템을 재생한다. 비지정 입력 거절, 표시 대기, popup 중간 제거/최상위 입력, 두 방향 및 카메라 변경을 검사한다.

## B. 완료 기록과 시험 세 모드

1. 실제 저장 계층을 먼저 확인한다. 기존 수단이 있으면 재사용한다. 없으면 레벨 번호별 완료 여부만 저장하는 작은 로컬 저장으로 제한한다. 계정·클라우드·전체 세이브 프레임워크를 추가하지 않는다.
2. 마지막 단계와 관련 표시가 완료된 뒤 완료를 1회 기록한다. 중단/실패/취소에는 기록하지 않고 중간 단계를 복원하지 않는다. 재입장은 처음부터 고정 재현한다.
3. 실행 여부는 보드 구성 전에 결정한다. 일반 게임의 기본값은 자동: 미완료이면 실행, 완료이면 일반 시드/공급으로 진입한다. 완료 생략 때문에 원본 튜토리얼 데이터를 삭제하거나 임시로 비활성화하지 않는다.
4. 에디터 시험 옵션은 자동/항상 실행/실행 안 함이다. 항상 실행은 완료 여부와 무관하게 고정 튜토리얼, 실행 안 함은 일반 플레이 경로다. 무효 데이터의 저장/형식 오류를 성공으로 숨기지 않는다.
5. 시험은 분리된 완료 기록을 사용하고 실제 기록을 쓰거나 지우지 않는다. 옵션은 실행 요청으로 전달하며 제작 SO/팩의 콘텐츠 계약에 불필요한 필드를 추가하지 않는다.
6. 재시작/다음 레벨에서도 같은 실행 정책과 저장 문맥을 유지한다. 이전 세션의 완료 알림이 새 레벨이나 실제 기록을 변경하지 않도록 세션/레벨 소유권을 확인한다.

검증: 미완료 자동 실행→완료 1회 저장→재입장 일반 플레이, 중단 후 처음부터 재현, 실제 보유량 유지, 시험 3모드, 앱/씬 재생성 후 완료 유지, 시험 전후 실제 저장 값 동일, 재시작/전환/파기 구독 및 늦은 신호 격리.

## C. 대표 데이터 적용·통합 검증·인계

1. 기존 1레벨의 고정 칸과 실제 실행 조회를 기준으로 기본 매칭 소개를 작성한다. 설명→지정 3매칭→종료 안내를 우선하며 대상 좌표/시드는 현재 배치의 실제 재생 성공으로 확정한다. `LevelTutorialDataVerification.Populate`는 정적 왕복용 fixture이므로 출시 안내로 복사하지 않는다.
2. Level_01에는 튜토리얼 필드만 추가한다. 기존 보드/미션/이동/색상/흐름/GUID를 유지한다. 고정 공급은 실제 필요한 생성구와 소비량을 재생해 작성하며 무작위 대체를 사용하지 않는다.
3. 사용자에게 이 4단계 실행 지시를 받은 경우에만 해당 50레벨 구간 MemoryPack을 기존 갱신 도구로 갱신한다. 기존 구간의 다른 레벨을 누락하지 않고 주소/팩 호환/ECPK/제작 SO 배포 제외를 유지한다. Player/Addressables 번들 빌드는 하지 않는다.
4. 없는 2~5/9레벨의 출시 배치나 팩을 생성하지 않는다. 이 단계의 로켓/폭탄/드론/자석/조합 안내 표현은 소유한 임시 fixture로 검증하고, 실제 소개 레벨은 해당 레벨 제작 때 같은 패턴으로 추가한다.
5. `TutorialGuidanceVerification.Run`을 새 통합 엔트리로 제공한다. 실제 UI/영구 기록/시험 기록/Asset·팩3/방향/수명 검사를 논리 및 모의 검사와 구분해 기록한다. 기존 1~3단계·일반 플레이·드론·팝업/결과 회귀를 실행한다.
6. 테스트 연결 해제 후 게임 소스만 컴파일한다. 예상한 UI/튜토리얼 메타데이터/해당 팩 외의 변경, GUID, 구간 포함 레벨, 과거 검사 출력과 HEAD/WIP를 확인한다.

완료 시 `Docs/Verification/MoonRabbitJunkyard/Tutorial/stage-04-progress.md`에 실제 검증 근거·제약과 확장 방법을 기록한다. 상세 매뉴얼은 별도 정리 시 작성한다. 튜토리얼 4단계 이후는 완료 결과를 기준으로 제안하며 다른 기능을 자동 시작하지 않는다.

## 제한

4단계만 구현한다. 기존 퍼즐 규칙·도감·고물탑·사운드·신규 이미지·재고/계정 시스템으로 범위를 넓히지 않는다. 빌드·번들·커밋·푸시·하위 에이전트·사용자 Unity 종료·임의 씬 저장을 하지 않는다. 위에서 지정한 1레벨 튜토리얼과 해당 팩 외 출시 데이터를 변경하지 않는다.
