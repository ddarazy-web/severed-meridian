# 경량 로비 1단계 — 목록 인덱스와 재사용 목록 UI

> 구현 담당: `superpowers:executing-plans`로 아래 작업 묶음을 순서대로 진행한다. 제품 빌드·커밋·푸시·HTML 매뉴얼 갱신은 하지 않는다.

**상태:** 1단계 구현·검증 완료 (2026-10-21)
**현재 확인:** 인덱스·게시·로더·실제 씬/프리팹·가상 목록을 구현했다. 데이터 회귀와 실제 UI 재사용·리사이즈·키보드·취소 수명 검사를 통과했다. 상세 근거와 남은 조건은 [검증 기록](../../../Verification/MoonRabbitJunkyard/2026-10-21-lobby-stage01.md)을 따른다. 검증 기록의 항목별 감사와 미검증 범위를 함께 확인한다.
**목표:** 등록된 레벨을 경량 목록 데이터로 조회하고, 게임 리소스를 읽지 않는 로비에서 재사용 셀로 표시한다.
**구조:** 제작 시 인덱스를 게시하고 런타임은 세대 정보와 인덱스만 읽는다. uGUI ScrollRect의 보이는 범위만 셀에 바인딩한다.
**기술:** 기존 Unity/uGUI/UniTask/Addressables/MemoryPack. 신규 패키지·전역 프레임워크·asmdef 도입 없음.
**상위 설계:** [통합 계획](2026-10-21-lightweight-lobby-plan.md).

## 이번 단계의 경계

포함: 목록 인덱스 생성·게시·등록·읽기, Lobby 씬, 경량 UI 프리팹, 가상 목록, 선택 요청 이벤트, 빈/로딩/실패/재시도, 데이터·UI·의존성 검사.

제외: 게임 씬 전환, 게임에서 로비 복귀, 게임 프로필의 시작 씬 변경, 런타임 팩 최적화, 튜토리얼 사전 재생 제거, 음원/텍스처 전면 최적화. 이 항목들은 2단계 이후다.

플레이 버튼은 목록 항목의 ID/번호/세대를 선택 요청으로 내보내는 경계까지만 구현한다. 1단계 단독 실행에서는 전환이 미연결임을 화면에 짧게 안내하며 게임 시작 성공으로 표시하지 않는다. 검사용 콜백으로 올바른 항목 전달을 확인한다. 이 임시 안내는 2단계에서 실제 전환 상태로 교체한다.

게임 프로필의 시작 씬을 아직 바꾸지 않으므로 이번 단계만으로 기존 APK 시작 속도가 개선됐다고 보고하지 않는다.

## 착수 전 확인

- [x] git 상태와 기존 변경을 확인하고 사용자 변경을 보존한다.
- [x] 통합 계획, 프로젝트 규칙, 기존 JsonContentPackBuild/JsonPackPublication/JsonPackRegistration, content-generation 계약을 확인한다.
- [x] 현재 채택 원본의 등록 레벨 번호·ID·이름을 확인한다. 1~15는 고정 규칙이 아니다.
- [x] 지원되는 Unity 편집 도구 연결 상태를 확인한다. 임시 Editor 생성 스크립트로 씬/프리팹을 편집하지 않는다.
- [x] 기존 Addressables 설정에 미저장 수정이 있으면 덮어쓰거나 임의 저장하지 않는다. 게시 검사는 소유한 사본으로 먼저 수행하고 실제 등록을 못 한 경우 구분해 보고한다.

## 작업 A — 로비 인덱스와 게시 계약

### 데이터

`LevelLobbyIndex`의 제안 필드:
- FormatVersion
- Entries: LevelId, LevelNumber, DisplayName

주소 `Levels/lobby-index`, 출력 `Assets/Data/LevelPacks/lobby-index.bytes`를 기준으로 한다. 기존 MemoryPack 생성 규칙을 따른다. 세대는 기존 content-generation을 사용하고 상호 해시 순환을 만들지 않는다.

- 제작 시 채택 원본의 level 문서에서 ID와 표시용 값만 투영한다. 제작 변환의 기존 전체 검사 과정에 합류하며 런타임 전체 스캔으로 옮기지 않는다.
- 레벨 번호는 양수·중복 없음, ID는 비어 있지 않고 중복 없음. 번호 오름차순으로 직렬화한다.
- 빈 표시 이름은 번호만 표시한다. 긴 이름은 셀에서 말줄임하고 데이터 자체를 자르지 않는다.
- 인덱스의 source ID↔번호 매핑을 원본과 검사하고, 번호 집합은 실제 출력 팩과 비교한다. 기존 팩에 없는 ID 필드를 비교한다고 가정하지 않는다.
- 인덱스는 자체적으로 빈 배열을 읽을 수 있도록 하되, 현재 ‘레벨이 없는 정식 프로젝트 발행 금지’ 규칙은 이번 단계에서 바꾸지 않는다. 빈 UI는 검사 입력으로 검증한다.

### 게시

- [x] 기존 결과 사전에 인덱스를 넣은 다음 content-generation을 생성한다.
- [x] 기존 트랜잭션에 인덱스 파일/meta/주소 등록을 포함하고 실패 복원·오래된 출력 정리를 보존한다.
- [x] Level Packs의 PackSeparately 정책을 사용해 인덱스를 레벨 본문과 별도 번들로 등록한다.
- [x] 인덱스 누락·변조·다른 세대·번호 중복과 게시 중간 실패 검사를 작성하고 구현 후 통과시킨다.
- [x] 게임 JSON, 기존 레벨/요소 팩 포맷, 50레벨 구간 규칙은 유지한다. 이전 generation을 로비가 읽을 때 인덱스가 없으면 데이터 갱신 안내로 실패한다.

## 작업 B — 런타임 로더와 가벼운 화면

- [x] content-generation과 lobby-index만 비동기로 읽고 해시·버전·항목을 확인한다. 실패 시 레벨 본문 전량 조회로 대체하지 않는다.
- [x] 인덱스 DTO는 인스턴스 수명 동안 재사용한다. 목록 표시·스크롤·선택에서 파일을 다시 읽지 않는다.
- [x] 핸들은 로드 완료/실패/취소 정책에 따라 소유자가 한 번만 반환한다. 씬 종료 후 늦게 도착한 완료가 UI를 갱신하지 않게 한다.
- [x] 요청 세대 또는 취소 토큰으로 재시도 경합을 방지한다. 여러 번 누른 재시도가 핸들과 이벤트를 중복 생성하지 않도록 한다.
- [x] Lobby 씬에는 카메라, 최소 Canvas/EventSystem, 로비 화면과 필요한 참조만 둔다. 게임 세션·보드·게임 UI·오디오 프리팹을 넣지 않는다.
- [x] 제목·번호·이름·플레이 버튼과 상태 안내만 구성한다. 무거운 배경, 썸네일, 별도 이미지 생성은 하지 않는다.
- [x] 한글을 포함한 등록 이름을 올바르게 표시하는 가장 작은 기존 폰트 구성을 조사한다. 큰 게임 폰트를 그대로 직접 참조하지 않고, 필요한 글리프 범위/경량 폰트와 라이선스를 확인한다. 서브셋을 쓰면 게시 이름 변경 시 글리프 검사도 포함한다. 작은 폰트가 준비되지 않았으면 글자 누락으로 완료 처리하지 않는다.
- [x] safe area, 세로·가로, 작은 휴대폰/태블릿·PC 크기에서 목록과 버튼이 잘리지 않는지 확인한다.

## 작업 C — 실제 셀 재사용

- [x] 고정 행 높이로 `첫 표시 인덱스 = floor(스크롤 오프셋 / 행 높이)`를 계산한다. 탄성 스크롤의 범위 밖 값은 보정한다.
- [x] 콘텐츠 높이만 전체 개수에 맞추고 셀 수는 `min(항목 수, ceil(뷰포트 높이 / 행 높이) + 4)` 이내로 유지한다. 여유는 위·아래 각 2개다.
- [x] 이동 때 새로 보이는 인덱스만 기존 셀에 바인딩한다. 마지막 페이지와 항목 수보다 큰 뷰포트도 빈 셀을 표시하지 않는다.
- [x] 화면 크기가 바뀔 때만 풀 필요 수를 재계산한다. 정상 스크롤 동안 Instantiate/Destroy 및 전체 항목 정렬·레이아웃 재구성을 금지한다.
- [x] 셀은 현재 바인딩된 ID/번호를 보관하고 클릭 이벤트를 한 번만 연결한다. 풀 재사용 후 이전 항목이 선택되지 않는지 검사한다.
- [x] 드래그 중 버튼 클릭을 취소하고, 키보드/마우스휠/터치 기본 조작을 지원한다. 선택 요청만 발생하며 레벨 팩을 읽지 않는다.
- [x] 보이지 않는 1천/1만 셀을 생성해 비활성화하는 방식은 사용하지 않는다.

## 작업 D — 검증과 결과 정리

- [x] 데이터: 0/1/15/1천/1만, 비연속 번호, 긴 한글 이름, 중복 ID/번호, 손상·잘못된 버전/세대 검사.
- [x] 게시: 원본·인덱스·팩의 일치, 중간 실패 뒤 기존 generation과 파일/주소 보존, 레벨 삭제·이름 변경 반영 검사.
- [x] 로드 경계: 허용 주소 외 로드를 실패시키는 검사에서 목록·스크롤·선택이 성공해야 한다. 허용은 Addressables 자체 카탈로그 의존성과 generation/index, 최소 로비 UI뿐이다.
- [x] 의존성: Lobby 씬/프리팹에서 게임 세션·보드·아틀라스·게임 전용 UI·음원·레벨툴 리소스로 이어지는 직접/간접 참조가 없는지 확인한다. 본문 팩이 없는 검사 환경에서도 로비를 열 수 있어야 한다.
- [x] UI: 실제 씬에서 최초 표시, 첫/중간/끝 스크롤, 재사용 셀 선택, 빈/실패/재시도, 리사이즈를 확인한다. 자동 이벤트·렌더 검사와 물리 입력 검사를 구분한다.
- [x] 성능: 실제 인덱스 1천/1만에서 최초 1회+정상 3회 시간·할당·셀 수를 기록한다. 메타데이터 준비와 전체 게임 진입 시간을 혼동하지 않는다. 정상 스크롤 중 생성/파괴 0회, 본문 읽기 0건을 필수 조건으로 둔다.
- [x] 종료: 검사 전용 사본·임시 스크립트를 정리하고 실제 데이터·결과·스크린샷을 보존한다. 제품 빌드 없이 확인한 범위와 번들/기기 미검증 범위를 명시한다.

실제 번들 크기·Android 첫 화면 시간·GPU 메모리는 제품 빌드/기기 검증 없이 완료로 주장하지 않는다. Addressables 논리 등록과 Editor 로드 성공만으로 최종 APK 의존성이 증명됐다고 보고하지 않는다.

## 완료 보고

변경·검증·미검증, 목록 개수와 실제 셀 수, 로드 주소, 리소스 의존성, 측정 조건을 보고한다. 간략한 복사용 커밋 메시지는 구현 완료 후 제시한다. 1단계 완료가 확인되면 통합 계획을 기준으로 2단계 계획서·목표·복사용 실행 명령을 작성하되 2단계 구현을 자동 시작하지 않는다.
