# 경량 로비 3단계 — 시작 성능과 실제 환경 검증

상태: Editor 범위 완료. 제품 빌드·설치 및 Android 실기기 검증은 미승인·미실행으로 남긴다. 상세 경과는 [3단계 검증 기록](../../../Verification/MoonRabbitJunkyard/2026-10-21-lobby-stage03.md)을 따른다.

## 목표와 범위

로비와 선택 게임 진입의 시작 시간·메모리를 같은 조건에서 측정하고, 확인된 병목만 개선한다. 2단계의 선택 요청, 한 구간 캐시, 필요한 자원 계획과 시험 실행 경계를 유지한다. 새 로비 기능이나 퍼즐 규칙 변경은 포함하지 않는다.

2단계 Editor 관찰값은 로비 목록 준비 약 704ms, 게임 아틀라스 순차 943ms→최대 4개 동시 준비 297ms였다. 단일 환경 비교이며 기기 성능 목표나 보장값으로 사용하지 않는다. 원본은 [2단계 검증 기록](../../../Verification/MoonRabbitJunkyard/2026-10-21-lobby-stage02.md)을 따른다.

## 작업 묶음 1 — 재현 가능한 기준 측정

- 앱 실행/첫 로비 프레임/목록 준비/게임 첫 표시/조작 가능 시점을 구분한다. Editor에서 측정할 수 없는 엔진 시작 구간은 명확히 분리한다.
- 15개 실데이터와 1천·1만 개 목록 전용 사본을 사용한다. 정식 JSON과 팩을 덮어쓰지 않는다.
- 최초 실행 1회와 정상 반복 3회를 구분한다. 해상도, 실행 환경, 데이터 세대, 캐시 조건을 결과에 남긴다.
- 목록 셀 수, 스크롤 할당, 읽은 주소, 피크/복귀 후 메모리, 단계별 시간을 표로 기록한다. 인덱스만으로 목록을 구성하고 레벨 본문은 선택 전 읽지 않는다.

검증: 셀 수는 화면에 필요한 수와 여유분을 넘지 않으며, 목록 개수에 비례하는 GameObject 생성이나 스크롤 중 전체 재생성이 없다.

## 작업 묶음 2 — 자원 경계와 반복 실행

- 일반 레벨과 장애물·공급·미션 자원이 있는 대표 레벨을 비교한다. 실제 로드 주소를 ElementResourcePlan과 대조한다.
- 게임 진입/복귀 10회, 재시작, 다음 등록 레벨, 취소·실패 후 재선택의 잔류 객체·핸들·메모리를 확인한다.
- 2단계에서 게임 준비 후 로비 씬을 해제하고 복귀 시 재생성하도록 수정했다. 재생성 시 목록 준비 비용, 보존한 스크롤 위치, 취소된 목록 읽기의 완료 후 해제 시간도 별도로 측정한다.
- 한 구간 안 재사용과 다른 구간 전환을 구분하고, 새 구간이 이전 구간의 해석 결과를 대체하는지 확인한다.
- 폰트·UI·오디오의 직접 참조와 아틀라스 단위 포함 비용을 따로 기록한다. 게임 폰트 교체나 요소 팩 분할은 실측 근거 없이 확대하지 않는다.
- 병목이 확인되면 가장 작은 변경으로 개선하고 같은 조건으로 전후를 비교한다. 기능을 제거하거나 검증을 생략하여 수치만 낮추지 않는다.

## 작업 묶음 3 — 승인된 제품/기기 검증과 정리

- 제품 빌드와 기기 설치는 별도 명시적 승인 후에만 한다. 승인 전에는 Editor 검사만 진행한다.
- 승인된 Android 환경에서 세로/가로, 뒤로가기, 백그라운드 복귀, 로딩 중 반복 입력을 확인한다.
- 빌드·기기가 없으면 PC 결과와 미검증 항목을 분리하고 실기기 완료로 표시하지 않는다. 이번 단계에 iOS/Steam 배포를 자동 포함하지 않는다.
- 실제 데이터와 결과는 보존하고 소유한 검사 사본만 정리한다. 완료 보고에는 변경점, 전후 측정값, 미검증 항목과 복사용 커밋 메시지를 포함한다.

커밋·푸시·HTML 매뉴얼 갱신은 하지 않는다. 질문은 제한시간 없는 문답으로 한다. 씬·프리팹은 임시 Editor 생성 스크립트로 수정하지 않는다.
