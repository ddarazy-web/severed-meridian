# 경량 로비·레벨 선택·게임 진입 통합 계획

> 구현 담당: `superpowers:executing-plans`에 따라 단계별로 진행한다. 이 문서는 설계안이며 구현 완료를 의미하지 않는다. 제품 빌드·커밋·푸시·HTML 매뉴얼 갱신은 별도 요청 전까지 하지 않는다.

**상태:** 1·2단계 완료 / 3단계 계획 확정·미착수 (2026-10-21)
**목표:** 가벼운 로비를 먼저 표시하고, 1천 개 이상의 등록 레벨을 셀 재사용 목록으로 탐색한 뒤 선택한 레벨의 매치 게임으로 진입한다.
**구조:** 로비 목록용 인덱스 / 선택 요청·씬 전환 / 게임 데이터·자원 준비를 분리한다. 기존 MemoryPack, Addressables, 게임 세션, 리소스 계획을 활용한다.
**기술:** Unity 6000.3.10f1, 기존 uGUI, UniTask, Addressables, MemoryPack. 새 UI 패키지나 전역 서비스 프레임워크는 도입하지 않는다.
**요구 근거:** 사용자의 현재 로비 요청 및 [Android 시작 지연 진단](../../../Verification/MoonRabbitJunkyard/2026-10-21-android-game-startup-diagnosis.md).

## 1. 화면과 범위

- 로비에는 제목과 등록된 레벨 목록만 둔다. 상점·재화·프로필·도감·보상·대형 배경·썸네일·검색은 이번 범위에서 제외한다.
- 각 행은 `레벨 번호`, `표시 이름`, 명확한 `플레이` 버튼으로 구성한다. 표시 이름이 없으면 번호만 표시한다.
- 번호 오름차순으로 표시한다. 번호가 건너뛰어도 실제 등록된 레벨만 표시한다. 해금 정책 없이 등록 레벨 모두 선택 가능하게 한다.
- 스크롤 중 손을 떼는 동작을 플레이 클릭으로 처리하지 않는다. 터치와 마우스를 지원한다.
- 목록을 읽는 동안 단순한 준비 안내를 표시한다. 실패하면 오류와 다시 시도를 제공하고, 빈 목록은 빈 상태로 안내한다.
- 게임의 기존 일시정지/결과 팝업에 최소한의 `로비로` 동선을 연결한다. 로비로 돌아왔을 때 현재 실행 중인 판은 종료한다. 기존 미완료 판 확인 흐름이 있다면 재사용한다.
- 로비 복귀 시 같은 실행 세대의 목록 위치를 유지한다. 앱 재실행까지 스크롤 저장하는 기능은 추가하지 않는다.
- 첫 UI를 보여주기 위해 게임 프리팹이나 한글 전체 폰트를 선로드하지 않는다. 글꼴은 등록된 이름 표시를 지원하는 경량 구성으로 정하고, 글자 누락을 허용하지 않는다. 대형 폴백이 무조건 로드되는 연결을 검사한다.

## 2. 목록은 게임 본문과 분리

### 제작 시 생성하는 목록 인덱스

- 채택된 JSON에서 MemoryPack을 생성하는 기존 경로에 작은 `LevelLobbyIndex` 출력을 추가한다.
- 데이터는 인덱스 버전, 안정적인 레벨 ID, 레벨 번호, 표시 이름으로 제한한다. 보드·튜토리얼·요소 카탈로그·이미지 참조는 넣지 않는다. 팩 주소는 기존 번호 구간 규칙에서 구한다.
- 예시 Addressables 주소: `Levels/lobby-index`. 별도 번들로 묶으며 게임 팩/아틀라스/게임 UI에 대한 의존성을 갖지 않는다.
- 인덱스를 기존 content-generation의 주소·해시 목록에 포함한다. 인덱스·레벨 팩·요소 팩은 같은 게시 트랜잭션으로 교체하고 실패 시 함께 복원한다.
- 목록과 실제 팩의 번호·ID 집합 일치, 중복·누락, 표시 이름 변경, 순서를 제작 단계에서 검증한다.
- 현재 1~15레벨은 생성 결과의 예이지 하드코딩하지 않는다.

### 로비에서 읽는 것

- 로비 씬과 최소 UI 리소스.
- Addressables 초기화에 필요한 카탈로그, content-generation, 작은 로비 인덱스.
- 1천/1만 항목의 작은 메타데이터 배열은 한 번 읽는다. 레벨 본문 전체 읽기와는 다르다.
- 레벨 팩, 요소 데이터 팩, 보드 아틀라스, 효과음, 튜토리얼 본문, 시험용 JSON은 읽지 않는다.
- 인덱스가 없거나 손상돼도 전체 레벨 팩을 뒤져 목록을 만드는 우회는 금지한다. 데이터 갱신 필요 오류를 표시한다.

## 3. 재사용 목록 셀

기존 uGUI `ScrollRect`와 고정 높이 셀을 사용한다. 전체 행 GameObject를 만들고 숨기는 방식이 아니라 실제 가상 목록으로 구현한다.

- 생성 수: `ceil(뷰포트 높이 / 행 높이) + 위·아래 여유 각 2개`를 기본 상한으로 한다.
- 콘텐츠 높이만 전체 개수에 맞추고, 스크롤 위치로 첫 표시 인덱스를 계산해 기존 셀의 데이터와 위치를 바꾼다.
- 화면 크기·방향 변경 시 풀 크기를 보이는 수에 맞춰 조절한다. 한글 이름은 1줄 말줄임으로 고정 높이를 유지한다.
- 셀 재바인딩 시 이전 항목 ID와 클릭 처리를 교체한다. 오래된 인덱스 캡처나 이벤트 중복 등록을 막는다.
- 스크롤마다 전체 목록 정렬, LINQ 전량 순회, 전체 레이아웃 재구성, Instantiate/Destroy를 수행하지 않는다.
- 새로 보이는 셀만 갱신한다. 콘텐츠에는 전량 자식 배치를 계산하는 LayoutGroup/ContentSizeFitter를 사용하지 않는다.

## 4. 로비 → 게임 → 로비 전환

1. 로비에서 플레이를 누르면 중복 요청을 막고 최소 전환 안내를 먼저 표시한다.
2. 전달 정보는 선택 레벨 ID/번호·콘텐츠 세대·실행 시드뿐이다. 로비에서 LevelDefinition이나 PuzzlePlayRequest 전체 스냅샷을 만들지 않는다.
3. 로비의 첫 표시를 게임 준비 작업이 막지 않도록 프레임을 실제로 그린 뒤 비동기 게임 씬 전환을 시작한다.
4. 게임 씬은 요청을 한 번 소비하고 선택 레벨을 시작한다. 기존 Start의 기본 1레벨 시작과 경쟁하여 두 세션이 실행되지 않게 한다.
5. 현재 세대가 목록 세대와 다르면 임의로 다른 콘텐츠를 시작하지 않는다. 로비에서 목록 갱신 후 다시 선택하도록 안내한다.
6. 게임 준비 성공 후 로비의 셀/Canvas를 해제한다. 필요한 것은 작은 목록 위치·선택 상태뿐이다. 단순한 전환 표시만 준비 완료까지 유지할 수 있다.
7. 준비 실패 시 선택 정보를 보존하고 로비로 복귀하며, 게임 씬·Addressables 핸들·중간 객체를 정리한다.
8. 로비로 돌아갈 때 보드·효과·게임 UI·세션이 소유한 핸들을 해제한다. 게임 리소스를 보관하는 무제한 DontDestroyOnLoad 캐시는 만들지 않는다.

씬 전환 담당은 요청 전달과 로딩 상태만 소유한다. 퍼즐 규칙·튜토리얼 상태·보드 준비는 기존 PuzzleGameSession에 둔다. 기존 레벨툴/Unity 편집기에서의 직접 시험 실행은 계속 지원하며 로비를 강제하지 않는다.

## 5. 게임 진입 시 필요한 만큼 로딩

### 데이터

- 선택 레벨이 속한 기존 **50레벨 단위 팩 하나**만 읽는다. 다른 구간을 미리 읽지 않는다.
- 현재 포맷상 한 팩을 역직렬화하면 해당 구간의 DTO가 함께 만들어질 수 있다. 이를 ‘선택 레벨 바이트만 읽는다’고 설명하지 않는다. 이번 단계에서 1레벨별 새 포맷은 만들지 않는다.
- 팩을 여러 번 해석하지 않고 한 번 해석한 결과를 사용한다. 실행 객체·튜토리얼·시작 보드는 선택 레벨만 만든다.
- 제작 시 전체 검증과 게임 실행 시 무결성·버전·필수 참조 검증을 구분한다. 기존 파일 손상 감지·세대 일치 보호는 제거하지 않는다.
- 검증된 배포 팩의 튜토리얼 전체 사전 재생은 제작 검증으로 옮기는 방향으로 설계한다. 레벨툴의 미검증 초안 시험과 같은 정책으로 처리하지 않는다. 잘못된 안내에 대한 실행 중 오류 보호는 유지한다.
- 공통 요소 팩은 선택 레벨의 표현/규칙에 필요한 공통 데이터로서 게임 진입 후에만 읽는다. 현재 단일 공통 팩 구조를 숨기지 않으며, 그 정의를 이유로 모든 장애물 이미지를 읽지 않는다. 요소 수가 대량 증가할 때의 샤딩은 실측 후 별도 결정한다.

### 이미지·오브젝트

- 기존 ElementResourcePlan의 현재 배치·공급·생성 가능 요소 및 미션 참조 계산을 재사용한다.
- 초기 보드에 없더라도 매칭으로 생성 가능한 로켓·폭탄·드론·자석과 필요한 효과는 준비 대상이다.
- 해당 레벨에 등장할 수 없는 장애물 아틀라스는 읽지 않는다. 선택된 아틀라스 내부 다른 그림까지 함께 로드되는 단위 제약은 측정에 표시한다.
- 필요한 아틀라스는 제한된 동시 로딩을 검토한다. 병렬화 수만 늘리지 말고 초기 지연과 최대 메모리를 비교한다.
- 게임 UI 프리팹의 직접 참조가 불필요한 보드·장애물·툴 리소스를 끌어오는지 의존성 검사로 확인한다.
- 기존 보드 셀/효과 풀을 재사용한다. 모든 종류를 사전 생성하는 풀은 추가하지 않는다.
- 음원 사전 생성·텍스처 압축 전면 변경은 이번 로비 구축의 필수 범위가 아니다. 계측상 필요하면 후속 성능 항목으로 분리한다.

## 6. 세 단계 진행

### 1단계 — 경량 목록 데이터와 로비 화면

- [x] 기존 게시 경로에 인덱스 생성/등록/세대 검증/실패 복원을 연결한다.
- [x] Lobby 씬과 최소 uGUI 화면, 고정 높이 가상 목록·셀 재사용을 구현한다.
- [x] 레벨 번호·이름·플레이 버튼, 목록 준비/실패/빈 상태를 구현한다.
- [x] 0/1/15/1천/1만 개, 중간 번호 누락, 긴 이름, 터치 드래그, 화면 크기 변경을 검사한다.
- [x] 게임 팩·요소 팩·보드 아틀라스 로드 함수를 실패하도록 막아도 로비 목록이 정상 표시되는지 검사한다.

**완료:** 실제 등록 레벨과 목록이 일치하고, GameObject 셀 수가 전체 개수에 비례하지 않으며, 로비에서 게임 데이터·리소스를 로드하지 않는다. 이 단계만으로 실제 플레이 진입 완료라고 보고하지 않는다.

### 2단계 — 선택 레벨 씬 전환과 게임 로딩 경계

- [x] 선택 요청 전달, 중복 클릭 방지, 로딩 표시, 실패 복귀, 로비 복귀를 연결한다.
- [x] 게임 씬 기본 자동 시작과 요청 기반 시작을 정리하고 정식 플레이/툴 시험 정책을 보존한다.
- [x] 구간 팩 단일 해석, 선택 레벨 실행 준비, 제작 검증과 런타임 검증 분리를 적용한다.
- [x] 기존 자원 계획을 사용해 필요한 아틀라스만 준비하고 성공/취소/실패/복귀 시 소유권을 검증한다.
- [x] Android/iOS/Windows Steam 게임 프로필의 첫 씬을 Lobby, 두 번째를 PuzzleGame으로 구성한다. Windows/Android 레벨툴 프로필은 그대로 유지한다.
- [x] 기존 Unity 레벨 편집·레벨툴 게임 시험, 재시작·다음 레벨, 튜토리얼 완료 기록을 회귀 검사한다. 번호가 건너뛴 목록의 다음 레벨은 인덱스의 다음 등록 항목으로 결정하고 마지막이면 로비 동선을 제공한다.

**완료:** 1/2/15 및 비연속 번호에서 선택한 레벨이 정확히 시작한다. 다른 구간·무관한 장애물은 읽지 않는다. 실패해도 재선택 가능하고 반복 왕복 후 게임 객체/핸들이 누적되지 않는다.

### 3단계 — 모바일 첫 화면·대량 목록·메모리 검증

- [ ] 앱 실행→로비 첫 프레임→목록 준비→게임 첫 표시→조작 가능 시점을 분리 기록한다.
- [ ] 1천/1만 메타데이터에서 시작·스크롤·선택 시간, 셀 수, 갱신 할당, 메모리를 측정한다.
- [ ] 같은 조건의 최초 1회와 정상 3회, 게임 진입/로비 복귀 10회에서 읽은 주소·최대/잔류 메모리·해제 상태를 확인한다.
- [ ] 기본 레벨과 장애물/공급이 있는 대표 레벨의 필요 자원 목록을 비교하고 누락/과잉 로드를 검사한다.
- [ ] Android 기기에서 세로/가로, 뒤로가기, 백그라운드 복귀, 로딩 중 입력을 확인한다. 실제 빌드·설치는 별도 승인 후 진행한다.
- [ ] 실제 작업 데이터·검증 결과를 보존하고 검사 전용 사본만 정리한다.

**완료:** 허용하지 않은 로드 0건, 셀 수 상한 준수, 프레임별 전체 목록 재생성 없음, 반복 왕복 누수 없음. 실기기가 없으면 PC 검증까지의 상태와 모바일 미검증을 구분해 남긴다. 측정되지 않은 ‘첫 화면 N초 보장’은 제시하지 않는다.

파일명은 구현 시 기존 책임과 충돌하지 않도록 확정한다. 범용 목록 프레임워크·신규 DI·새 asmdef는 미리 만들지 않는다. 씬/프리팹은 사용자의 기존 지시대로 임시 Editor 생성 스크립트로 편집하지 않고 지원되는 Unity 편집 도구로 작업한다. 아트 생성·복잡한 UI 장식은 별도 요청 전 추가하지 않는다.

## 8. 위험·결정 기준

- 로비는 Unity가 첫 프레임을 그릴 수 있는 이후부터 효과가 있다. 엔진 이전 빈 화면에는 Android 시작 화면/초기화 계측이 별도로 필요하다. 로비만으로 그 구간이 해결됐다고 보고하지 않는다.
- 로비 경량화의 핵심은 작은 씬 이름이 아니라 실제 의존 리소스 분리다. 숨겨진 게임 오브젝트나 비활성 프리팹도 직접 참조된 채 로비에 넣지 않는다.
- 인덱스와 게임 팩 세대 불일치, 빠른 중복 선택, 전환 중 실패, 비연속 번호, 재활용된 셀의 오래된 콜백, 주소 핸들 중복 해제를 우선 회귀 대상으로 둔다.
- 기존 실시간 조작 성능은 정상이라는 사용자 관찰을 유지한다. 이번 작업에서 드론 연출·낙하·매칭 규칙 등을 변경하지 않는다.
- 1단계 구현·검증을 완료했다. 이후 각 단계 착수 시 상세 계획·목표·실행 명령을 확인하고, 완료 시 결과와 미검증 항목을 보고한다.
