# 경량 로비 2단계 — 선택 레벨의 게임 진입과 복귀

상태: 구현·Editor 검증 완료. 최종 리뷰의 로비 UI 해제 지적을 반영하고 1/2/15의 10회 왕복 및 기록/손상/회귀 검사를 통과했다. 상세 증거와 미검증 범위는 [2단계 검증 기록](../../../Verification/MoonRabbitJunkyard/2026-10-21-lobby-stage02.md)을 따른다.

## 목표와 경계

로비에서 선택한 ID·번호·제작 세대를 게임 진입 요청으로 전달하고, 해당 레벨에 필요한 데이터와 자원을 준비한 뒤 게임을 시작한다. 게임에서 로비로 돌아오면 게임 소유 리소스를 해제한다. 기존 Unity 편집기와 Windows/Android 레벨툴의 시험 실행은 보존한다.

제품 빌드·커밋·푸시·HTML 매뉴얼 갱신은 하지 않는다. 실기기 시작 시간과 최종 번들 검사는 3단계에서 별도 승인 후 수행한다. 1단계의 한글 경량 폰트를 게임 전체에 적용하는 작업은 포함하지 않는다.

## 작업 묶음 1 — 요청과 씬 전환 연결

1. 기존 게임 시작·재시작·다음 레벨·툴 시험 진입 호출부를 확인한다. 기본 자동 시작과 로비 요청 기반 시작이 동시에 실행되지 않도록 진입 경계를 정한다.
2. LobbyScreen의 선택 이벤트를 연결한다. 요청은 ID·번호·세대를 함께 유지하고, 진입 중 중복 클릭을 막으며 화면에 로딩 상태를 표시한다.
3. 선택 요청을 게임 씬에 전달하고 준비 완료 후 조작을 허용한다. 실패·취소하면 소유 자원을 반환하고 로비에서 재선택할 수 있게 한다.
4. 게임 종료/로비 복귀 동선을 연결한다. 임시 선택 안내를 실제 전환 상태로 교체한다.

검증: 1·2·15 및 비연속 번호의 요청이 정확한 레벨로 연결된다. 두 번 누르기·로딩 중 취소·읽기 실패가 중복 게임 세션을 만들지 않는다. 세대 불일치를 무시하지 않는다.

## 작업 묶음 2 — 선택 레벨의 준비 비용 줄이기

1. 기존 LevelPackLoader·게임 세션·ElementResourcePlan의 실제 흐름을 계측한 뒤 수정한다. 50레벨 팩 단위를 유지하면서 해당 구간만 읽고, 팩 해석 결과를 재사용한다.
2. 실행 객체·시작 보드·튜토리얼은 선택한 레벨만 준비한다. 배포 데이터의 전체 튜토리얼 사전 재생은 제작 검증과 분리한다. 초안 시험 검증과 손상·버전·세대·필수 참조 검증은 유지한다.
3. 기존 자원 계획으로 배치·공급·매칭 생성·미션에 필요한 아틀라스만 준비한다. 등장할 수 없는 장애물과 레벨툴 자원은 로드하지 않는다.
4. 성공·실패·취소·복귀의 데이터/Addressables/게임 오브젝트 소유자를 명확히 하고, 현재 취소 후 완료·해제 정책을 보존한다. 불필요한 전역 캐시나 전면적인 로더 프레임워크는 만들지 않는다.

검증: 선택 구간 외 본문 팩 읽기 0건, 불필요한 장애물 자원 읽기 0건. 아틀라스 내부의 비선택 그림까지 포함되는 단위 제약은 별도 표기한다. 조작 가능 시점 이전의 데이터 읽기·해석·자원 준비 시간을 구분한다.

## 작업 묶음 3 — 프로필 연결과 회귀

1. Android/iOS/Windows Steam 게임 프로필의 첫 씬을 Lobby, 다음 씬을 PuzzleGame으로 구성한다. Windows/Android 레벨툴 프로필의 씬·패키지·아이콘·옵션은 유지한다.
2. 다음 레벨은 번호+1 대신 인덱스의 다음 등록 항목을 사용한다. 마지막 레벨 완료 시 로비 동선을 제공한다.
3. 로비↔게임 반복 10회, 재시작, 다음 레벨, 튜토리얼 기록, Unity 편집기 시험, 레벨툴 JSON/MemoryPack 시험을 회귀 검사한다.
4. 검증 사본·임시 스크립트를 정리하고 결과와 실제 작업 데이터를 보존한다. 3단계 계획·목표·명령문은 2단계 완료 결과를 근거로 작성한다.

씬/프리팹은 지원되는 Unity 편집 도구로 수정한다. 임시 Editor 생성 스크립트로 작성하지 않는다. 구현 도중 범위 변경이 필요하면 근거와 영향을 보고한다.
