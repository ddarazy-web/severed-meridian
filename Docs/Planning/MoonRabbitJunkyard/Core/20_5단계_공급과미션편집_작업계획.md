## 목표

제작자가 **Match → 레벨 에디터**에서 생성 위치별 공급 종류·순서·수량을 편집하고, 회수 부품과 1~4개 미션을 설정하며, 공급 충돌과 명백한 목표 수량 부족을 확인할 수 있게 한다. 복사·붙여넣기, Undo/Redo, 저장 후 별도 Unity 재시작에서도 설정을 유지한다.

예를 들어 생성구 두 곳에 서로 다른 고정 공급 목록을 쌓고 한쪽 목록을 다른 생성구에 복사한다. 또는 고철 최초 2개·유지 2개·추가 최대 6개를 설정하고 제거 목표 9개가 수량 부족 오류로 표시되는 것을 확인한다. 이 단계에서는 블록을 실제로 공급하거나 퍼즐을 실행하지 않는다.

## 착수 당시 구조

- Unity `6000.3.10f1`, UI Toolkit 기반 `LevelEditorWindow`를 사용한다.
- `LevelDefinition.CurrentSchemaVersion`은 3이다. 보드·초기 블록·장애물·덮개·먼지·흐름·발전기 연결을 저장한다. 생성구·공급·미션·회수 부품 데이터는 아직 없다.
- 고철은 기존 장애물 데이터로 배치한다. 공급 모델을 추가한다는 이유로 기존 고철 배치를 다른 배열로 옮기지 않는다.
- `InitialBlockKind`에는 일반/파워 블록 값 0~5가 있다. 저장된 열거형 값을 재배열하지 않는다.
- 기존 `LevelSchemaUpgrade`는 v1/v2→v3에서 흐름을 초기화하고 장애물 ID를 생성한다. 이를 그대로 v3→v4에 적용하면 흐름·전선·ID가 손실된다. 버전별 전환 분리가 필요하다.
- 현재 UI는 왼쪽 배치/흐름/목록, 오른쪽 선택 속성/레벨 설정, 접이식 검사 영역이다. 제목과 드롭다운은 한 줄이다. 이 구조와 스타일을 유지한다.

## 접근과 설계 제안

Inspector 배열만 늘리는 방식은 순서와 생성 위치를 혼동하기 쉽다. 별도 그래프 창은 기존 보드와 선택 상태를 중복 관리하게 된다. **기존 보드와 오른쪽 속성 패널 확장**을 사용하고, 공급 목록은 Unity 기본 목록 UI와 명시적 이동 버튼을 재사용한다. 새 프레임워크나 범용 매니저는 만들지 않는다.

아래 저장 형태와 세부 UI 정책은 구현 제안이다. 확정 게임 규칙을 바꾸지 않으며, 이 문서를 참조한 Goal 실행 요청 시 제안 범위를 포함해 진행한다.

### 생성구와 공급 목록

- 활성 칸에 생성구를 놓는다. 내부 칸도 가능하며 중력 변경으로 생성구를 자동 추가하지 않는다. 별도의 공급 방향 필드는 없다.
- 같은 칸의 중력·경로·초기 블록은 보존한다. 생성구와 도착 바닥 중첩, 중복 생성구, 범위 밖·비활성 좌표를 검사한다. 초기 블록 점유만으로 생성구를 오류로 취급하지 않는다.
- 새 레벨의 기본 보드에는 최상단 생성구를 둔다. 기존 레벨 전환에서는 생성구를 몰래 추가하지 않고, 빈 신규 설정으로 전환한 뒤 명시적인 ‘상단 생성구 추가’로 설정하게 한다. 이 일괄 작업도 한 번의 Undo로 복원한다.
- 공급 방식은 일반 무작위 / 고정 목록 / 고철 유지 / 회수 부품 유지로 구분한다. 선택한 방식에 필요한 속성만 보여준다.
- 고정 목록에는 일반·파워 블록·고철·회수 부품을 넣는다. 고정 장애물·덮개·먼지를 목록에 넣지 않는다. 레벨의 미사용 색, 잘못된 방향·내구도·0 이하 수량을 검사한다.
- 목록의 **아래쪽이 생성구에 가깝고 먼저 공급**된다는 표시를 고정한다. 순서 번호도 공급 순서와 일치시킨다. 내부 직렬화 순서는 한 가지로 통일하고 UI 순서 변환을 한 곳에서 처리한다.
- 항목 추가·삭제·복제, 드래그 재정렬과 위/아래 이동을 제공한다. 종류별 속성은 선택 항목에만 표시한다. 전체 펼침으로 패널이 길어지지 않게 한다.
- 생성구 선택 시 위치별 총 수량과 순서를 보인다. N개 위치의 총 M개 수량은 목록 합계로 계산하고, 자동 분배하거나 다른 위치로 옮기지 않는다.
- 최초 보드 배치와 공급 목록을 별도로 유지한다. 목록 소진 후 중단/레벨 색 균등 무작위 전환을 저장한다. 실행 중 소비 위치·잔량은 이번 데이터에 넣지 않는다.

### 유지 방식과 충돌

- 고철 유지 목표·추가 생성 한도·동일 내구도는 레벨 단위다. 여러 생성구가 같은 한도를 공유하며 위치 수만큼 한도를 중복 합산하지 않는다.
- 고철 고정 목록과 고철 유지 방식은 생성 위치가 달라도 같은 레벨에서 금지한다. 서로 다른 위치의 고정 목록은 함께 사용할 수 있다.
- 고철 유지와 회수 부품 유지는 같은 레벨에 둘 수 있지만 생성구를 공유하지 않는다. 필요 없는 시점의 일반 블록 공급은 기존 규칙을 따른다.
- 회수 부품 유지의 공급 상한은 남은 회수 목표와 보드 잔량으로 결정된다. 미션이 없거나 유효한 담당 생성구가 없으면 설정 오류로 표시한다. 별도 임의의 추가 한도 필드는 만들지 않는다.
- **충돌 회피 제안:** 회수 부품도 고정 목록 공급과 유지 방식을 한 레벨에서 혼용하지 않는다. 고정 순서와 잔여 목표 기반 공급 간 우선순위는 아직 정해지지 않았으므로 이 단계에서 암묵적으로 실행 순서를 만들지 않는다. 이는 고철에 대해 명시된 기존 제한을 회수 부품에 적용하는 제안이다.

### 복사·붙여넣기와 공통 속성

- 생성구 여러 개는 생성구 도구에서 Ctrl/Cmd+클릭으로 선택한다. 다른 종류와 혼합된 범용 다중 선택은 만들지 않는다.
- 같은 값은 실제 값, 다른 값은 혼합 상태로 표시한다. 수정한 속성만 선택 생성구에 적용한다. 레벨 공통 유지 목표는 위치별 독립 값처럼 복제하지 않는다.
- 순서 목록은 다중 인스펙터에서 동시에 수정하지 않는다. 원본 하나에서 복사하고 선택 대상들에 **전체 교체 / 뒤에 추가**로 적용한다.
- 공급 목록은 깊은 복사한다. 원본을 수정해도 붙여넣은 목록이 바뀌지 않아야 한다. 항목 복제도 독립 값이다.
- 클립보드는 버전·종류를 구분하는 작은 데이터 형식으로 처리한다. 잘못된 형식·현재 레벨의 미사용 색·방식 충돌은 이유를 보여주고 원본을 유지한다. 교체/추가가 공급 방식을 암묵적으로 바꾸지 않는다.
- 다중 붙여넣기는 모든 대상의 적용 가능성을 먼저 확인한다. 한 대상이라도 부적합하면 전체 변경 없이 대상과 이유를 표시한다. 성공은 한 번의 Undo로 되돌린다. 이 원자적 처리 방식은 생성구 공급 목록에 한정한 제안이다.

### 미션 편집과 정합성

- 오른쪽 레벨 설정에서 1~4개를 입력한다. 색별 수집은 각각 1개이고 동일한 대상의 중복 목표는 거절한다. 수량 목표는 양수다. 작업 중 0개나 잘못된 수량이 있는 에셋도 읽고 저장하되 오류를 표시한다.
- 확정 규칙이 있는 색상 수집, 나무상자·거미줄·고철·먼지·금고·자물쇠·대형 폐가전 제거, 곰팡이 전부 제거, 부품 회수를 제공한다. 발전기·고철 벽 등 제거 미션으로 확정되지 않은 종류를 임의로 추가하지 않는다.
- 곰팡이는 고정 수량 입력 대신 ‘전부 제거’로 표시한다. 다른 제거 미션은 내구도 합계가 아니라 개체/칸 수를 센다. 2×2 폐가전은 본체 하나, 자물쇠는 색 구분 없이 합산한다.
- 목표 옆에 최초 배치 수량·고정 목록 추가량·유지 추가 상한·합계 근거를 표시한다. 같은 공급 항목과 레벨 공통 한도를 중복 계산하지 않는다.
- 유한한 제거/회수 목표가 가능한 최대 수량을 넘으면 오류다. 고철 최초 2 + 추가 한도 6에서 목표 8은 수량 검사 통과, 9는 실패해야 한다.
- 회수 목표에 유효한 도착 바닥이 없으면 오류다. 회수 유지가 유효할 때는 목표 기반 추가 상한임을 표시하고 별도의 유한 고정 목록처럼 오해시키지 않는다.
- 색상 수집은 초기 수량만으로 불가능 판정을 하지 않는다. 균등 무작위 공급과 실제 플레이를 고려하지 않은 단순 숫자로 클리어 가능성을 보장하지 않는다. 동적 곰팡이 목표도 초기 수량을 고정 최대치로 삼지 않는다.
- 구조 오류와 수량 부족만 판정한다. 경로 도달 가능성·이동 횟수 충분성·시작 매칭·유효 교환·난이도는 아직 미검사라고 표시한다.

## UI 유지 조건

- 왼쪽 배치 탭에 생성구·회수 부품을 카테고리 드롭다운으로 추가한다. 제목·드롭다운은 한 줄을 유지한다.
- 목록 탭에는 기존 장애물 목록과 구분한 생성구 목록을 둔다. 좌표·방식·공급 합계를 간결하게 표시하고 클릭하면 보드와 속성을 함께 선택한다.
- 오른쪽 선택 속성에서 생성구의 목록/정책을, 레벨 설정에서 미션과 레벨 공통 유지 설정을 편집한다. 탭과 패널 접기, 접이식 검사, 보드 중앙 정렬을 유지한다.
- 목록 선택·속성 변경·외부 수정·Undo·에셋 전환 후 오래된 대상에 붙여넣거나 수정하지 않는다. 미완료 드래그는 Esc·포커스 상실·창 닫기 등 기존 취소 규칙을 따른다.
- 보드 표시는 이미지 없이 생성구·회수 부품 기호를 사용한다. 기존 흐름·전선·2×2 본체를 가리지 않도록 표시 우선순위를 확인한다.

## 형식 전환과 비파괴 원칙

- 저장 버전은 v4로 확장하는 것을 제안한다. 수정 전 실제 v3 에셋과 전체 필드/GUID 스냅샷을 확보한다.
- v1/v2는 기존 전환 의미를 보존하고, v3→v4는 신규 필드만 추가한다. 기존 흐름·전선·장애물 ID를 초기화하거나 재발급하지 않는다.
- 기존 미션을 추측해서 생성하지 않는다. 전환 후 미션 미설정 오류는 작업자가 입력해서 해결한다. 이전 오류·잘못된 값·중복 배치도 보존한다.
- 읽기·OnEnable·OnValidate·검사 중 자동 전환/정규화하지 않는다. 예상 밖 신규 필드와 미래 버전은 임의 변환하지 않고 이유를 알린다.
- 명시적 전환은 한 번의 Undo/Redo, 저장, 별도 재시작으로 검증한다. 기존 enum 숫자와 meta/GUID를 유지한다.

## 진행 순서와 검증

1. 기존 원본·테스트 기준을 확보하고 모델·버전별 전환 경계를 정리한다. 원본 보존을 먼저 검증한다.
2. 생성구·공급 목록·회수 배치·유지 설정의 조회/편집/정합성을 추가한다. 다중 위치와 전역 충돌을 확인한다.
3. 미션과 수량 근거 계산을 연결한다. 유한/목표 기반/동적 수량을 구분해 경계값을 검증한다.
4. 기존 보드·탭·한 줄 메뉴에 UI를 통합한다. 복사/복제/붙여넣기와 생성구 공통 속성을 실제 Editor에서 조작한다.
5. Undo/Redo·원본 불변 검사·별도 프로세스 재시작·관련 기존 회귀를 수행하고 사용 방법과 증거를 목표 문서에 기록한다.

Goal 실행 시 승인 범위에 맞춰 위 순서를 구체적인 작업 의존성과 완료 증거로 기록한다. 공유 창과 직렬화 모델을 수정하므로 기본은 순차 진행이다.

주요 실패 사례: 다른 생성구로 목록이 섞임, 전역 추가 한도의 위치별 중복 합산, v3 전환 시 연결 삭제, 붙여넣기 중 일부만 변경, 목록 표시와 실제 저장 순서 역전, 미션 미설정 기존 에셋을 자동 수정하는 동작이다. 각각 독립적인 회귀 사례를 남긴다.
