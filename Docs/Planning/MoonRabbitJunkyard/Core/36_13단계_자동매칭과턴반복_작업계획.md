## 목표와 확인된 상태

정착 후 자동 매칭을 처리하고 효과→낙하·공급→자동 매칭을 보드가 안정될 때까지 반복한다. 안정된 보드에서는 지원하는 다음 사용자 행동을 받을 수 있게 한다. 한 사용자 행동과 전체 후속 연쇄를 한 턴으로 취급한다.

현재 코드는 `BoardActionExecutor.Settle()`에서 `WaitingForAutomaticMatch`로 전환한다. `MatchResolution.Select()`는 교환 좌표를 생성 위치로 사용하므로 자동 매칭에 그대로 호출할 수 없다. `TurnEffectContext`는 보호 파워와 상자 피해 기록을 가지고 있고 정착 시 보호 좌표를 이동한다. 이 구조를 확장하며 별도 게임 실행기를 중복 구현하지 않는다.

이 계획의 최초 작성 시점에는 12단계가 완료 검증 전이었다. 이후 12단계 목표 문서에 완료 감사가 기록됐다. 13단계 실행 시에도 선행 검증 기록과 현재 소스를 확인하고, 선행 작업이 미완료면 별도 활성 Goal을 덮어쓰거나 완료로 간주하지 않는다.

## 범위 선택

| 방식 | 장점 | 한계 | 판단 |
|---|---|---|---|
| 자동 매칭 한 번만 추가 | 변경이 작음 | 연쇄 종료와 다음 수의 상태 초기화를 검증할 수 없음 | 부족 |
| 지원 범위 안에서 자동 연쇄와 다음 행동 연결 | 턴 경계와 반복 플레이를 검증 가능 | 아직 완성된 퍼즐 플레이는 아님 | 채택 |
| 미션·승패·모든 파워·장애물까지 동시 구현 | 전체 플레이에 가까움 | 새 규칙이 과도하게 결합되고 실패 원인 추적이 어려움 | 후속 분리 |

## 포함 및 제외 범위

포함:

- 정착한 일반 블록의 3/4/5 직선, ㄱ·ㄴ·T, 2×2 자동 매칭.
- 기존 중첩 우선순위와 선택 패턴만 제거하는 규칙.
- 도착 기록에 따른 파워 생성 위치, 동일 도착 시점의 재현 가능한 무작위 선택.
- 기존 로켓/폭탄 효과·상자 피해와 12단계 이동/기본 공급을 연결한 연쇄 반복.
- 같은 턴의 보호·피해 기록 유지와 다음 유효 행동에서 새 턴 시작.
- 기존 Match 창의 한 단계 실행과 연쇄 끝까지 실행, 결과 요약과 진단.

제외:

- 드론/자석 발동과 파워 조합, 추가 장애물 반응, 고철/회수 공급·유지와 회수 처리.
- 미션 진행·승패·라스트팡·자동 재배치·아이템·부스터·주문 연동.
- 게임용 화면·애니메이션·저장 복구·봇·난이도 분석·랜덤 추천.

드론/자석은 매칭 생성·보드 유지·낙하까지 지원한다. 발동이나 피격 연쇄가 필요하면 명시적으로 미지원으로 멈춘다. 파워를 일반 블록으로 바꾸거나 해당 효과를 무시하지 않는다. 지원 제약 때문에 중단한 시험을 패배로 표시하지 않는다.

## 확정 규칙

1. 효과와 낙하·공급이 모두 끝난 후 자동 매칭한다. 이동 중에는 매칭하지 않는다.
2. 자동 매칭은 이동 횟수를 추가 차감하거나 턴 번호를 증가시키지 않는다.
3. 무지개 자석 > 달폭탄 > 청소로켓 > 수거드론 순으로 중첩을 해소한다. 같은 우선순위는 블록 수, 그마저 같으면 무작위다. 선택된 패턴 밖의 블록은 제거하지 않는다.
4. 독립 패턴은 각각 처리하며 파워 블록은 일반 매칭에 참여하지 않는다.
5. 자동 생성 파워는 마지막 도착 칸에 놓고 동시 도착 후보 사이에서 무작위로 선택한다.
6. 이번 수에서 매칭으로 생성한 모든 파워는 전체 연쇄가 끝날 때까지 보호한다. 공급 파워에는 보호를 붙이지 않는다.
7. 기존 로켓/폭탄은 피격 시 즉시 연쇄 발동한다. 낙하 후로 예약하지 않는다.
8. 나무상자는 동일 사용자 수와 전체 연쇄를 합쳐 최대 1회 피해를 받는다. 다음 사용자 수에서는 다시 피해받을 수 있다.
9. 남은 이동 수가 0이어도 진행 중인 연쇄는 끝까지 처리한다. 이번 단계는 그 이후의 승패를 판정하지 않는다.

## 구현 정책 제안

아래는 확정 규칙을 구현하기 위한 정책이다. 이 문서를 지정한 Goal 실행 요청에 포함하며, 확정 규칙과 충돌하면 근거를 기록하고 조정한다.

### 자동 매칭 선택과 도착 기록

- 중첩 패턴 선택과 실제 제거/변환은 기존 `MatchResolution`을 재사용한다. 교환 생성 위치와 자동 생성 위치의 결정만 분리한다. 호출부에 가짜 교환 좌표를 넣지 않는다.
- 정착 시 이동/공급 묶음 번호를 현재 점유자의 최종 도착 정보로 환산한다. 선택 패턴 안의 현재 일반 블록 중 가장 늦은 도착 시점을 후보로 삼는다. 지나갔으나 이미 비워진 좌표의 기록을 후보에 쓰지 않는다.
- 한 턴 안에서는 정착 회차와 묶음 번호를 함께 비교한다. 서로 다른 정착의 동일 묶음 번호가 동시 도착으로 취급되지 않게 한다.
- 같은 턴에 움직이지 않은 블록의 이전 도착 정보는 유지한다. 점유자 제거·변환·교환·이동·공급 때 정보의 소유자를 함께 갱신한다. 영구 블록 ID나 저장 스키마 확장 없이 실행 전용 메타데이터로 해결한다.
- 도착 이력이 없는 초기 점유자는 동일한 기준 시점으로 취급한다. 중첩에서 남은 패턴 등 모든 후보가 같은 시점인 경우 선택 패턴의 일반 블록 중 무작위 선택한다. 이 처리에는 별도 정답 사례를 둔다.
- 동률이 없으면 난수를 소비하지 않는다. 후보 좌표의 기준 순서를 고정하고 조회/화면 갱신은 난수를 소비하지 않는다.

### 실행 상태와 원자적 반영

- 기존 행동→`WaitingForFall`→정착→`WaitingForAutomaticMatch`의 단계 실행을 유지한다.
- 자동 매칭 단계는 모든 패턴을 읽고 중첩을 선택한 뒤 새 파워 보호를 등록하고 매칭 피해와 효과를 처리한다. 성공하면 다시 낙하 대기다.
- 매칭이 없으면 턴 종료 경계로 간다. 남은 수와 실행 가능한 행동에 따라 다음 행동 대기 또는 시험 정지 사유를 표시한다.
- 한 단계마다 보드·난수·커서·보호·피해·도착 기록을 작업 사본에서 처리하고 성공 시 함께 반영한다. 실패한 단계의 부분 변경은 버린다.
- 연쇄 끝까지 실행도 같은 단계 명령을 반복 호출한다. 실패하면 마지막으로 성공한 단계의 상태와 기록을 남기고 중단한다. 이미 성공한 사용자 행동이나 앞선 연쇄까지 되돌리지 않는다.
- 잘못된 단계 호출·중복 클릭·잘못된 교환·미지원 행동은 이동 수, 턴, 난수와 문맥을 소비하지 않는다.

### 턴 문맥과 다음 행동

- 자동 매칭으로 생성된 파워 보호를 기존 문맥에 누적한다. 매 연쇄마다 새 문맥으로 바꿔 이전 보호나 상자 피해 기록을 잃지 않는다.
- 효과에서 소모한 파워의 좌표 기록이 다음 정착 후 다른 점유자의 발동을 막지 않도록 기존 12단계 정책을 유지한다.
- 안정된 보드에서는 이전 턴 결과를 조회할 수 있다. 다음 유효 사용자 행동의 작업 사본에서 새 턴 문맥을 만들고 성공 시 턴 번호를 한 번 증가시킨다. 실패한 입력은 이전 문맥을 그대로 둔다.
- 현재 `StartConditionReport`를 다음 수마다 최초 보드 조건으로 강제하지 않는다. 공급이 없어 남은 빈칸을 정상 지원하고, 기존 시작 조건 검사는 새 시험의 초기 구성에 사용한다. 다음 수는 안정 상태·남은 수·행동 적법성·현재 지원 범위로 검사한다.
- 남은 수 0은 `이동 수 소진 · 승패 판정 미지원`으로 멈춘다. 행동이 없으면 `재배치 필요 · 이번 단계 미지원`, 가능한 행동이 모두 미지원 파워에 해당하면 `지원 가능한 행동 없음`으로 구분한다. 자동 섞기나 패배 처리를 대신 넣지 않는다.

### 종료와 진단

- 매칭·대기 효과·낙하가 모두 없는 상태만 안정으로 판단한다.
- 같은 상태의 무진행 반복과 난수 공급에 의한 과도한 연쇄를 구분한다. 내부 연쇄 한도를 두되 도달을 정상 완료로 표시하지 않는다. 정상적인 긴 연쇄 사례로 한도를 검증하고 근거를 기록한다.
- Unity 창을 장시간 막지 않도록 끝까지 실행은 단계 사이에 Editor에 제어권을 돌려준다. 원본/시드/모드 변경·초기화·창 종료 시 예약 실행과 상태 참조를 해제한다. 일반 작업 스케줄러는 만들지 않는다.
- 결과에는 턴·연쇄 회차·선택/제외 패턴·파워 위치 및 선택 근거·효과·이동/공급 요약·난수 전후·정지 이유를 남긴다. 기록 조회는 실행 상태를 바꾸지 않는다.

## 구성과 작업 순서

스크립트는 `Assets/Scripts/Simulation`과 `Assets/Scripts/Editor/Levels`의 기존 책임별 구성을 따른다. 새 게임명 폴더·패키지·asmdef·범용 상태 머신은 추가하지 않는다. 레벨 정의 v4와 기존 에셋/GUID/meta를 유지한다.

| 작업 | 의존 | 변경 책임 | 검증 |
|---|---|---|---|
| T1 선행 확인 | 없음 | 12단계 증거·현재 소스·보존 기준 대조 | 완료 여부, 지원 범위와 기준 해시 기록 |
| T2 자동 매칭 선택 | T1 | MatchResolution과 실행 전용 도착 정보 | 우선순위·최종 점유자·동률·조회 무변경 |
| T3 자동 효과 단계 | T2 | 실행기와 TurnEffectContext | 보호 누적·상자 턴 제한·미지원 원자적 거절 |
| T4 연쇄 및 다음 수 | T3 | 기존 실행기의 단계 연결 | 여러 회차·수 0·다음 턴·실패/한도 경계 |
| T5 Match UI | T4 | 기존 실행 시험 UI | 단계/끝까지 실행·결과·좁은 창·무효화 |
| T6 완료 검증 | T5 | Editor 검증 및 문서 | 독립 재현·회귀·보존·완료 감사 |

동일 실행 상태와 문맥을 공유하므로 기본 순서는 T1→T2→T3→T4→T5→T6이다. UI에 매칭/효과 규칙을 중복 구현하지 않는다.

## 필수 검증 사례

- 모든 기본 패턴과 중첩 우선순위, 직선 5와 2×2 중첩 시 직선 밖 보존, 독립 패턴 동시 처리.
- 늦게 도착한 칸, 같은 묶음 도착 동률, 여러 번 이동한 블록, 중간 통과 좌표 재점유, 여러 정착 회차, 이력 없는 잔여 패턴.
- 두 번 이상 이어지는 자동 매칭→효과→정착과 추가 수/턴 차감 없음.
- 최초 매칭과 후속 자동 매칭에서 생성된 파워의 누적 보호·이동, 공급 파워 비보호, 다음 유효 수의 보호 해제.
- 상자가 같은 턴 여러 연쇄에는 1피해, 다음 턴에는 다시 1피해. 실패한 행동에서는 문맥 유지.
- 마지막 수 0에서도 모든 지원 연쇄 완료, 공급 없는 빈칸이 남은 안정 보드에서 다음 적법 행동 허용.
- 드론/자석 피격 등 미지원 효과의 단계 전체 보존, 연쇄 중 실패 시 앞선 성공 단계 유지.
- 무매칭 즉시 종료, 행동 없음/미지원 행동만 존재/수 소진의 구분, 무진행 반복과 처리 한도 진단.
- 한 단계 실행 반복과 끝까지 실행의 최종 상태·난수·공급 커서·보호·피해·선택 결과 일치.
- 동일 정의·시드·행동 열·알고리즘 버전으로 독립 Unity 프로세스에서 여러 턴 재현.
- 실제 Match 버튼 조작, 1000px/680px 폭의 버튼·결과 접근, 초기화와 변경/창 종료 시 실행 해제.
- Unity 컴파일, 8~12단계 영향 회귀, 원본 JSON/dirty·v4·GUID/meta 보존, 임시 검증 에셋과 프로세스 정리.

손으로 정한 예상 좌표와 결과를 기준으로 검증한다. 같은 구현을 두 번 호출해 일치하는 것만으로 정답을 증명하지 않는다. 과거 검사 수를 이번 검증 수에 합산하지 않는다.

## 완료 후 경계

지원 범위 내에서 반복 조작하는 에디터 실행 시험이 가능해진다. 미션·승패와 전체 장애물/파워가 없는 만큼 완성된 플레이 테스트나 난이도 평가로 표현하지 않는다. 후속 후보는 드론·자석과 조합 효과이며, 그 이후 장애물·미션·승패를 연결한다.
