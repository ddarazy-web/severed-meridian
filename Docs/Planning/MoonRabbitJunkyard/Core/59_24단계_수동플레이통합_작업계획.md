## 목표와 현재 상태

사용자가 편집한 레벨을 검사하고 사본으로 한 판 플레이한 뒤, 같은 조건 또는 새 조건으로 재시작하거나 편집으로 돌아올 수 있게 한다. 공통 규칙의 개별 시험을 실제 제작 흐름으로 연결하는 단계다.

현재 `LevelEditorWindow`와 `LevelInitialStateWindow`는 별도 창이다. 후자는 초기 후보 구성·시작 조건 검사·실행 시험·낙하·연쇄 버튼을 제공하며, `BoardActionExecutor`에 명령을 전달한다. 원본 지문 변경 감지, 연쇄 예약 해제, 아이템·부스터 선택과 판 종료 처리는 이미 존재한다. 그러나 기본 진입점은 여전히 `Match/초기 보드 확인`이며 플레이까지 여러 조작을 요구한다. 이 구조를 재사용하고 필요한 연결과 안내만 보완한다.

## 선택한 방식과 대안

| 방식 | 이점 | 비용·한계 | 판단 |
|---|---|---|---|
| 기존 시험 창에 수동 플레이 흐름 통합 | 공통 실행기·진단·스타일을 재사용하고 변경 범위가 작음 | 기본 조작과 상세 진단을 구분해야 함 | 채택 |
| 독립적인 새 플레이 창 제작 | 화면 구성 자유도가 높음 | 같은 입력·세션 수명·진단을 중복 관리 | 제외 |
| 출시용 씬과 런타임 UI부터 제작 | 실제 게임 표현까지 확인 가능 | 아트·프리팹·연출 작업으로 범위가 확대 | 후속 범위 |

기존 로드맵의 수동 통합 방향을 구체화한다. 자동 플레이 봇·통계·난이도 추천, 랜덤 레벨 생성, 신규 장애물, 상점·광고·재화·해금 타이머, 앱 강제 종료 복구, 출시용 화면·애니메이션은 포함하지 않는다. 시각적인 게임 완성도와 규칙 플레이 가능 여부를 구분한다.

## 사용자 흐름

1. 레벨 에디터 상단의 **플레이 테스트**로 현재 선택 레벨의 미저장 편집 내용까지 전달한다. 편집을 강제로 저장하지 않는다.
2. 원본 구조 검사 → 실행 지원 여부 검사 → 시작 보드 구성 순서로 검사한다. 오류는 이유와 가능한 경우 위치를 표시한다. 미지원 요소를 무시하거나 제거한 사본으로 실행하지 않는다.
3. 시작 전에는 레벨 번호·시드·부스터 세 종류와 시작 버튼을 보여준다. 최초 진입은 새 시드를 사용하고 현재 값을 표시한다. 시드 지정과 단계 진단은 상세 영역으로 모은다.
4. 시작 후에는 보드·남은 이동·미션 진행·아이템·현재 상태가 중심이다. 정상 명령 후 낙하·공급·연쇄·종료 처리를 자동 진행해 다음 입력 가능한 경계까지 도달한다.
5. 결과는 성공·이동 수 소진·진행 불가·실행 오류를 구분한다. 성공 결과와 라스트팡 진행을 구별하며, 라스트팡 때문에 확정된 성공 결과를 바꾸지 않는다.
6. **같은 시드로 다시**, **새 시드로 다시**, **편집으로 돌아가기**를 제공한다. 재시작은 시작 전 화면으로 돌아가며 23단계의 부스터 선택 초기화 정책을 유지한다. 동일 재현에는 동일한 부스터 선택과 조작이 필요함을 안내한다.

기존 `Match/초기 보드 확인` 진입점은 진단 용도로 보존한다. 새 메뉴를 추가할 경우에도 `Match` 아래에 둔다. 사용자가 옵션을 다수 설정하지 않아도 기본 플레이를 시작할 수 있어야 한다. 상세 영역에서 기존 한 단계 실행·연쇄 끝까지·조회 기능을 유지하되 일반 플레이와 동시에 보드를 조작하지 못하게 한다.

## 세션과 입력 계약

- 레벨 정의 → 검증 → 시작 상태 사본 → 공통 실행기 → 화면 표시의 단방향 흐름을 유지한다. Editor가 보드를 직접 수정하거나 별도 매칭·피해·낙하 코드를 만들지 않는다.
- 실행 중에는 일반 교환·파워·아이템 입력을 차단하고 안정 경계에서 다시 허용한다. 실패한 교환이나 취소는 기존 이동 수·난수·사용 기록 정책을 보존한다.
- 자동 진행은 기존 Editor 업데이트 기반 연쇄 실행을 재사용한다. 동기 반복으로 Editor를 멈추게 하지 않으며, 지연된 콜백이 재시작한 새 세션을 조작하지 못하게 한다.
- 연쇄 도중 재시작·편집 복귀·레벨 변경·창 닫기는 예약과 선택을 먼저 해제한 뒤 세션을 폐기한다. 편집 복귀는 시험 종료이며 플레이 결과를 원본에 반영하지 않는다.
- 원본 내용이나 시드가 바뀌면 기존 변경 감지 방식으로 세션을 무효화하고 다시 시작하도록 안내한다. 이전 결과를 변경된 레벨의 결과로 표시하지 않는다.
- 창 포커스 상실 시 아이템 선택 해제는 유지한다. 포커스 상실 자체를 레벨 실패로 처리하지 않는다. 도메인 재로드 후 세션 복구는 구현하지 않으며 재시작이 필요함을 표시한다.
- 정상 종료·사용자 시험 종료·실행 오류를 혼동하지 않는다. 사용자 편집 복귀를 일반 패배로 새로 집계하지 않는다.

## 지원 범위와 통합 검수

착수 시 실제 정의 타입·검증기·실행기를 대조해 지원표를 작성한다. 아래 묶음마다 정의 값, 실행 담당, 대표 재현 사례, 통과/미검증/미지원 상태를 기록한다. 기존 단위 검사 통과만으로 전체 플레이 완료를 선언하지 않는다.

| 묶음 | 필수 통합 경계 |
|---|---|
| 일반 매칭·파워 | 3/4/5·ㄱㄴT·2×2, 우선순위·생성 위치·새 파워 보호, 단독 발동·10종 조합 |
| 장애물·덮개·바닥 | 상자·고철·거미줄·먼지·곰팡이·금고·자물쇠·대형 폐가전, 피해 제한과 동적 미션 |
| 발전기·장치 | 충전과 연결 대상 반응, 여러 칸 본체, 연결 표시 및 대상 상태 |
| 이동·공급·회수 | 기본/구역 중력·대각선·직접 경로·합류·이동통로·위치별 공급·유지 공급·도착 회수 |
| 판 종료 | 마지막 수 성공·이동 수 소진·자동 재배치·진행 불가·처리 오류·라스트팡 |
| 시험 보조 | 세 아이템, 세 시작 부스터, 후보 부족 대기·배치, 종료 우선·재시작 초기화 |

모든 종류를 한 거대 보드에 억지로 넣지 않는다. 좁은 대표 사례와 두세 시스템을 결합한 사례를 사용한다. 구조 오류·잘못된 참조·지원하지 않는 정의는 시작을 막고, 실행 중에 발견되는 오류는 진단과 마지막 유효 상태를 보존한다. 지원되지 않는 확정 요소가 발견되면 완료 장애로 기록한다. 큰 신규 시스템이 필요하면 별도 후속 범위를 보고하며 몰래 범위를 확대하거나 완료로 처리하지 않는다.

## 완료 검증과 위험

- 실제 UI로 편집→오류 수정→시작→정상 플레이→결과→재시작→복귀를 수행한다. 코드 호출 검사와 화면 조작 검사를 구분한다.
- 같은 정의·시드·부스터·명령 기록에 대해 단계 실행과 자동 연쇄의 보드·미션·공급 커서·난수·아이템/부스터·종료 기록을 비교한다. 별도 Unity 프로세스에서도 재현한다.
- 새 시드는 직전 시드와 달라야 한다. 결과 보드까지 반드시 다르다고 검사하지 않는다. 같은 시드 재시작도 부스터 선택이나 조작이 다르면 결과 일치를 요구하지 않는다.
- 원본 JSON·미저장 dirty 상태·GUID/meta·공급 목록, 기존 연결 포트·이동통로·경로·합류 컨텍스트 초기화·Undo/Redo를 보존한다. 기존 변경을 되돌리지 않는다.
- 연쇄 예약 중 재시작으로 옛 콜백이 새 세션에 적용되는 위험, 원본 변경 후 낡은 결과 표시, 좁은 창에서 입력 접근 불가를 우선 검증한다.
- 수정한 책임과 호출부를 기준으로 회귀 범위를 정하고 이전 단계 전체 검사 숫자를 이번 실행 통과 수로 재사용하지 않는다. 컴파일 실패·미검증·미지원은 따로 기록한다.

24단계 완료는 에디터에서 규칙에 따른 수동 시험 흐름을 검증했다는 뜻이다. 출시용 게임 UI 또는 봇·난이도 평가 완성을 뜻하지 않는다.
