## 목표와 현재 상태

Match 수동 시험에서 발전기를 충전하고, 완충 시 연결 장애물을 즉시 제거하며, 직접 파괴한 대상의 연결 해제와 발전기 자동 철거까지 공통 실행기로 처리한다. 드론은 연결된 미션 목표를 근거로 발전기를 선택하고 네 칸을 하나의 충전 대상으로 예약한다.

계획 작성 시 19단계 완료 감사의 2,214 PASS/0 FAIL, 완료 조건20개, 최종 소스 해시 차이0을 확인했다. 현재 Goal은 없다. 이번 요청은 문서 작성이며 Goal 생성이나 구현 실행을 포함하지 않는다.

현재 `RuntimeObstacle.Charge`, 불변 `RuntimeConnection`, 연결 ID/경로 검사와 편집 화면의 전선 그리기는 존재한다. 실행기의 발전기 반응·연결 대상 제거는 미지원이다. 기존 내구도 감소 경로에 발전기를 그대로 포함하면 내구도0인 발전기를 이미 제거된 본체로 취급할 수 있으므로 충전과 피해를 구분해야 한다. 수동 시험은 충전값/연결 목록을 일부 표시하지만 살아 있는 연결의 전선 표시와 실행 반응이 필요하다.

## 범위와 확정 규칙

| 항목 | 이번 단계의 동작 |
|---|---|
| 본체 | 2×2 고정, 교환·낙하·섞기 대상 제외. 네 칸과 하나의 충전값 공유 |
| 충전량 | 제작자가 필요한 횟수3~5 지정. 일반 매칭의 외곽 상하좌우 접촉 또는 파워 직접 타격으로 충전 |
| 수 제한 | 한 수의 전체 자동 연쇄에서 발전기별 최대1회. 다음 유효 수에서 다시 충전 가능 |
| 완충 | 현재 효과 처리 중 살아 있는 연결 대상을 잔여 내구도와 무관하게 제거하고 발전기도 제거 |
| 제거 범위 | 대상 본체만 제거. 폐가전 네 칸을 함께 제거하되 미션은 본체당1개. 주변 추가 폭발 없음 |
| 정착 | 현재 효과 처리를 끝낸 뒤 기존 낙하·공급·자동 매칭 순서로 진행 |
| 연결 | 발전기당1~3개, 상자·금고·색깔 자물쇠·폐가전만 허용. 대상 하나는 발전기 하나에만 연결 |
| 직접 파괴 | 해당 연결/전선/대상 단자 해제. 다른 대상으로 대체하지 않음. 마지막 대상 소멸 시 발전기도 충전 없이 자동 철거 |
| 드론 | 남은 미션 목표에 연결된 발전기를 우선 후보로 조회. 이번 수 충전한 본체는 제외. 네 칸 전체를 단일 예약 |
| 화면 | 필요한 수만큼 충전 표시등, 활성 전선과 색·모양이 짝지어진 단자, 충전 시 짧은 빛 표시 |

기존 벽의 인접 판정과 파워 관통 규칙을 유지한다. 자석 색 제거의 인접 예외는 색깔 자물쇠에만 적용하며 발전기 충전으로 확대하지 않는다. 자석+자석 등 실제 직접 타격은 공통 반응을 따른다. 고물 망치도 직접 충전 가능하다는 규칙은 유지하지만 망치 입력·수량·UI 구현은 23단계다.

회수/도착 실행, 승패·자동 섞기·라스트팡 완성, 아이템·부스터, 봇·통계·난이도 추천, 출시 아트·주문 화면·앱 복구는 제외한다. 신규 장애물이나 발전기 미션을 추가하지 않는다.

## 구현 설계안

다음은 확정 게임 규칙을 실현하기 위한 기술 설계다. 이 계획을 지정한 Goal 실행 요청을 받으면 구현한다.

### 상태와 연결 수명

- 기존 불변 연결 정의를 보존하고 **발전기와 대상의 실제 보드 점유 여부**로 활성 연결을 조회한다. 제거된 본체가 런타임 목록에 남아 있어도 활성으로 판단하지 않는다. 발전기의 생존 여부를 내구도로 판정하지 않는다.
- 별도 가변 연결 목록을 정의/상태/화면에 중복 저장하는 방법은 사본과 연결 해제의 불일치 위험이 있어 우선 채택하지 않는다. 상태에서 파생하는 작은 공통 조회를 효과 실행·드론·화면에서 재사용한다.
- 제거 경로는 기존 본체 제거와 발전기의 강제 제거가 공유한다. 본체 생존 확인→전체 점유 해제→해당 미션1회 반영→연결 수명 반영을 일관되게 처리한다. 이미 사라진 대상에 대기 중인 타격이 도착해도 중복 집계하지 않는다.
- 마지막 연결 대상 직접 제거 시 자동 철거한다. 완충 처리 중 마지막 대상이 제거되어도 발전기 작동/철거 기록을 이중 발생시키지 않는다. 발전기는 연결 대상이 될 수 없으므로 일반 그래프 실행 프레임워크는 만들지 않는다.
- 기존 `LevelConnectionRules`의 연결 수·대상 종류·중복 ID·경로·벽·교차 검사를 재사용한다. 레벨 저장 형식 v4와 원본 연결 경로/GUID를 변경할 필요가 없는 방향을 우선한다.

### 충전과 효과 실행

- 종류별 충전 가능 여부와 반응 사유는 Simulation 규칙이 소유한다. 충전 증가를 내구도 감소나 색 미션 진척으로 기록하지 않는다.
- `TurnEffectContext`에 발전기별 충전 이력을 명시적으로 관리한다. 사본에 복사하며 다음 수에 초기화하고, 무효 입력/실패 실행은 원본의 충전·이력·난수를 변경하지 않는다.
- 외곽의 여러 매칭 칸, 네 칸을 덮는 폭발, 여러 드론과 후속 자동 연쇄가 겹쳐도1회만 충전한다. 다른 발전기는 각각 충전할 수 있다.
- 완충 반응은 효과 실행 중 즉시 적용한다. 이후 대기 효과는 갱신된 보드를 읽고, 모든 효과 종료 뒤 정착한다. 별도 낙하 실행기나 예약된 다음 턴 발동은 만들지 않는다.
- 충전 전후 값, 완충 작동, 연결 대상 제거, 직접 파괴에 따른 연결 해제, 자동 철거를 재현 가능한 기록으로 남긴다. UI 애니메이션의 시간은 규칙 결과에 영향을 주지 않는다.

### 드론 기여와 예약

- 매니저는 후보 캐시·추천·예약 수명을 담당하고 발전기 종류 규칙을 내부에 몰아넣지 않는다. 규칙 조회는 실제 보드/미션/충전값을 변경하지 않는다.
- 아직 완충이 아닌 타격도 남은 미션 장애물에 연결되어 있으면 유효한 간접 기여다. 예상 충전과 예상 미션 완료 수를 구분한다. 미완충 예약만으로 연결 대상을 이미 제거될 대상으로 계산하지 않는다.
- 다음1회 충전이 완충이면 살아 있는 연결 대상의 예상 제거를 본체별로 계산한다. 직접 타격과 연결 제거가 같은 대상을 가리켜도 중복 합산하지 않고 미션 잔여량을 초과해 완료량을 예약하지 않는다.
- 발전기 본체는 네 칸 전체가 한 예약 단위다. 포인트·로켓·폭탄의 직접 범위 안에 포함된 발전기도 같은 충전 제한을 적용한다. 범위의 필연적 겹침을 추가 충전으로 계산하지 않는다.
- 직접 대상 예약으로 제거가 예상되는 경우 다른 미해결 연결 대상의 기여를 다시 조회한다. 실제 파괴/충전/예약 취소로 후보가 바뀌면 캐시와 예상량을 갱신한다.
- 도착 시 후보가 무효면 남은 미션 후보를 다시 찾고, 더 없을 때 일반 블록을 무작위 선택한다. 예약은 실제 미션을 변경하지 않으며 사본·실패·취소 시 서로 누출되지 않는다.

### Match 화면과 파일 배치

기존 `Assets/Scripts/Simulation`의 반응·효과·미션·예약 계층에 연결한다. 발전기 연결 규칙이 독립 책임을 가질 만큼 필요하면 같은 폴더의 작은 규칙 파일로 분리한다. 새 게임명 폴더, 패키지, 어셈블리, 범용 이벤트 버스를 추가하지 않는다.

`Assets/Scripts/Editor/Levels`의 수동 시험 화면에는 실제 활성 연결을 표시한다. `LevelFlowOverlay`의 기존 좌표 변환/그리기 방식을 참고하되 편집 도구의 입력 상태를 플레이 화면에 의존시키지 않는다. 필요한 그리기만 재사용한다. 전선은 칸 사이 경로, 벽은 굵은 경계로 구분하고 전선이 보드 입력을 가로채지 않게 한다. 동일 연결의 양 끝 단자는 색과 모양이 일치한다.

발전기 충전등과 상세 정보, 충전/철거 로그를 제공한다. 전선은 선택하지 않아도 보이며 대상이 사라지면 단자와 함께 없어져야 한다. 충전 빛은 짧은 표시 효과이며 단계 진행이나 난수를 소비하지 않는다. 1000/680폭, 스크롤, 초기화, 레벨 변경, 창 닫기에서 좌표와 콜백 수명을 확인한다. 별도 이미지 제작은 필요 없다.

## 작업 순서와 검증

| 작업 | 선행 | 작업/검증 산출물 |
|---|---|---|
| T1 기준 확인 | 19단계 완료 | 완료 감사/현재 해시/Goal 확인, 원본 보존 기준, 발전기 미지원 경로와 기존 검증 목록 |
| T2 연결 수명·제거 | T1 | 활성 연결 조회, 공통 본체 제거, 직접 제거/마지막 연결 자동 철거/미션·먼지 보존 검사 |
| T3 충전·완충 실행 | T2 | 3~5충전, 수당1회, 효과 중 즉시 작동, 정착 순서, 사본·실패·다음 수 검사 |
| T4 드론 연동 | T3 | 간접 기여, 본체 예약, 직접/간접 중복 예측, 캐시 무효화·재탐색 검사 |
| T5 수동 화면 | T4 | 전선·단자·충전등·기록, 실제 Match 조작 및 화면 크기/수명 검증 |
| T6 재현·회귀·감사 | T5 | 독립 Unity 재현, 영향 회귀, 조건별 증거, 변경 책임·임시 정리·완료 기록 |

핵심 사례는 연결1/3개와 충전3/5, 매칭 외곽/벽 차단, 한 범위의 네 칸/별개 효과/연쇄/다음 수, 완충으로 내구도9 폐가전 제거, 직접 파괴와 완충의 처리 순서 양쪽, 일부 연결/마지막 연결 제거, 여러 발전기의 독립성이다. 남은 미션 없음·부분 충전·완충 직전·다른 드론 예약·도착 직전 대상 소멸도 검사한다.

실제 Match UI에서 편집한 레벨 사본으로 충전→완충 제거→낙하를 확인한다. 같은 시드/행동의 단계 진행과 끝까지 실행, 독립 Unity 프로세스 결과를 비교한다. 보드·충전·활성 연결·미션·난수·수 이력·드론 예약을 포함한다.

발전기를 미지원 오류 사례로 쓰던 기존 검사는 실제 남은 미지원 요소로 바꿔 실패 원자성 검증을 유지한다. 지원 범위가 바뀌었다는 이유로 검사를 삭제하거나 실패를 무시하지 않는다. 파워10조합과 8~19단계 영향 회귀를 수행하며 최종 유효 결과만 중복 없이 집계한다. 실제 UI/독립 재현을 못 했으면 완료로 표시하지 않는다.

완료 시 목표 문서의20조건에 검사/화면/재현 증거를 대응시키고 실제 수치·한계·알고리즘 버전을 기록한다. 소스·에셋·기획 문서·무관 변경의 보존을 감사하고 소유한 임시 자원만 정리한다. 다음 단계는 계획 요청 전 자동 진행하지 않는다.
