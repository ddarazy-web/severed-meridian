봇이 보는 정보와 실제 조작 규칙은 두 전략이 같다. 계획 전략도 실제 미래 공급·곰팡이 내부·게임 시드·난수 상태를 읽지 않는다. 예상 결과는 가정이며 실제 다음 판을 보장하지 않는다. 계획 봇이 모든 레벨에서 기본 봇보다 잘해야 한다는 목표는 두지 않는다.

## 정보와 책임 경계

흐름은 `실제 판 → 공개 관찰 → 가정 생성 → 가정용 공통 실행기 → 탐색 평가 → 첫 행동 선택 → 실제 세션 재검증`이다.

- 실제 판을 읽는 변환기는 기존 공개 관찰만 전달한다. 계획 요청은 이 관찰과 공개 계약에서 계산한 값만 받는다.
- 가정 상태 생성기는 실제 실행기·원본 레벨·게임 시드·공급·진단 로그를 받지 않는다. 실제 판을 복사한 뒤 일부 필드를 지우는 방법도 금지한다.
- 가정 처리 어댑터 내부에서만 새 가정용 실행 상태와 공통 실행기를 소유한다. 실제 세션의 객체와 참조를 공유하지 않는다. 탐색 정책에는 공개 결과와 평가값을 돌려준다.
- 실제 게임 난수와 가정 난수는 인스턴스·시드 유래 모두 분리한다. 가정 시드는 공개 관찰의 정규화된 값, 가정 규칙 버전, 표본 번호로 결정한다. 프로세스별로 달라지는 기본 GetHashCode, 현재 시간, 실제 시드·정의 지문을 사용하지 않는다.
- 공개 후보의 순서가 달라도 정규화·동점 처리가 같아야 한다. 숨은 정보만 달라진 두 판은 탐색 내용·점수·첫 행동까지 같아야 한다.
- 가정 생성 후 분기를 복사하는 것은 허용한다. 복사 원본이 처음부터 공개 정보만으로 만들어졌음을 검사한다.
- 공통 실행기는 실제 세션과 동일한 명령 비용·피해·낙하·연쇄를 사용한다. 가정 실행의 승리/막힘/오류는 실제 판 결과를 바꾸지 않는다.

새 일반 프레임워크나 별도 asmdef를 기본으로 만들지 않는다. 두 전략 선택에 필요한 최소 계약만 추출한다. 가정 실행 때문에 상태 구성 경계를 추가해야 하면 기존 생성자를 먼저 확인하고, 공개 값 전용 진입점의 입력·불변 조건을 기록한다. 실제 상태를 전략에 넘기는 우회로 해결하지 않는다.

## 알려진 값과 모르는 값의 처리

| 정보 | 처리 원칙 |
|---|---|
| 노출 블록·빈칸·장애물·덮개·바닥·전선·도착/통로 | 공개 관찰의 현재 값을 유지한다. 시작 배치나 초기 내구도로 되돌리지 않는다. |
| 곰팡이 내부 | 공개 입력은 Unknown 유지. 가정 내부의 대체 내용은 별도 표본으로 만들고 실제 내용이라고 표시하지 않는다. |
| 미래 공급·사용 색 목록 | 원본 설정을 조회하지 않는다. 공개된 게임 규칙의 색 집합을 사용하는 가정 정책을 명시한다. 현재 보이는 색만 실제 전체 공급 색이라고 단정하지 않는다. |
| 중력·직접 경로·합류·생성 위치 | 제작 설정을 몰래 읽지 않는다. 공개 계약으로 확정할 수 없는 부분은 명시적 가정 정책으로 구성하고 불확실한 평가임을 표시한다. |
| 실제 피해 이력·드론 예약·생성 보호 | 관찰은 안정 경계에서만 받는다. 가정 실행의 이력·예약은 가정용 실행기가 새로 소유한다. |
| 미션 진행 | 현재 남은 목표를 기준으로 가정 진행량을 비교한다. 곰팡이 증가 등으로 목표량이 달라지는 경우도 공통 규칙으로 계산한다. |

가정 모델의 초기안은 알려지지 않은 흐름은 기본 아래 방향, 알려지지 않은 공급은 보드 형태에서 정한 가정 생성구의 일반 블록 공급, 숨은 내용은 일반 블록 표본으로 구성하는 방식이다. 이는 실제 레벨 설정의 복원이 아니다. 공개된 벽·통로·도착과 충돌하면 우선 공개 조건을 보존하고, 유효한 가정 구성이 불가능하면 그 원인을 남긴다. 세부 생성 정책은 구현 착수 때 공통 상태 구성/검증 제약과 대조해 한곳에 고정하고 버전으로 관리한다.

이 모델은 특수 공급·특수 흐름에서 부정확할 수 있다. 실제 경로를 읽어 정확도를 가장하는 것보다 불확실성을 드러내는 방식이 사용자와 같은 정보 조건에 맞다. 확정 모델과 가정 모델의 차이는 문서와 선택 이유에 남긴다. 임의로 공개 계약을 확대해야 하는 제품 결정이 생기면 grill-me로 확인한다.

## 탐색 방식과 한도

구현 시작값은 **깊이 2수, 첫 후보 최대 6개, 다음 후보 최대 6개, 가정 표본 3개**다. 사용자 조절 옵션으로 늘어놓지 않고 코드의 한 정책에 둔다. 이 수치는 성능 검증 결과가 아니며, 대표 레벨 측정에 따라 조정하고 최종 값/근거를 기록한다. 깊이 1 평가에 이름만 붙여 계획 전략이라고 완료하지 않는다.

1. 원래 공개 관찰의 유효 행동을 기본 평가와 고정 좌표 순서로 정렬한다. 기본 봇의 최선 후보를 포함하여 탐색 대상을 제한한다.
2. 각 첫 후보에 같은 규칙의 가정 표본을 적용한다. 후보마다 유리한 표본만 골라 쓰지 않는다.
3. 가정용 공통 실행기로 첫 행동과 전체 후속 처리를 진행한다. 안정된 가정 판에서 다음 행동 후보를 조회하고 두 번째 행동까지 살펴본다.
4. 실제 미션 잔여량 변화와 완료 여부를 우선 비교하고, 다음 선택의 파워/직접 기여를 보조값으로 사용한다. 첫 수와 둘째 수의 같은 완료량을 중복 합산하지 않는다. 이동 비용도 같은 기준으로 반영한다.
5. 표본 전체의 누적 목표 기여를 공통 분모로 비교한다. 동점은 첫 행동의 기본 평가, 종류·좌표 순으로 결정한다. 구체 점수 구성·종료값·오류 표본 처리 규칙을 한곳에 고정하고 검증한다. 가정의 무작위 한 번 성공을 확정 성공으로 표시하지 않는다.
6. 선택한 계획의 **첫 행동만** 실제 세션에 제출한다. 다음 수는 새 실제 관찰로 다시 계획한다. 가정에서 얻은 둘째 행동을 실제 판에 예약하지 않는다.

최대 후보 수만으로 계산량이 제한되었다고 보지 않는다. 가정 생성 배정·공통 연쇄 단계·후보 확장 각각에 결정적 처리량 한도를 둔다. 프레임마다 일정 작업 단위만 처리하고 중지 요청을 확인한다. 시간 측정은 성능 진단에 사용하며 기기 속도나 프레임 분할 때문에 결과가 달라지는 종료 기준으로 쓰지 않는다.

예산 소진 시에는 모든 첫 후보에 공평하게 끝낸 표본 묶음만 비교한다. 완료된 비교가 없거나 가정을 만들 수 없으면 현재 관찰의 기본 전략으로 전환하고 이유를 표시한다. 일부 후보만 더 오래 살펴본 결과를 동일 조건 비교라고 하지 않는다. 코드 예외·계약 위반·실제 실행 오류는 조용히 기본 전략으로 숨기지 않고 오류로 구분한다.

## 한 판 실행과 UI

- 기존 봇 영역에 `전략: 기본 / 계획` 선택을 추가한다. 기본 선택은 기존 기본 전략으로 유지한다. 실행 중 전략을 바꿔 현재 판의 의사결정을 섞지 않는다.
- `새 봇 시험`은 새 시드, `같은 조건으로 다시`는 마지막 시험의 시작 조건과 시드를 재사용한다. 새로 선택한 전략으로 재시험할 수 있다. 전략 이름과 같은 조건 여부를 표시한다.
- 같은 조건 재시험은 같은 시작 정의·시드·게임 버전임을 실행 경계에서 확인한다. 원본이 바뀌면 이전 비교 조건을 무효화하고 새 시험을 안내한다. 시드와 원본은 전략 입력이 아니다.
- 두 전략의 결과를 한 번씩 확인하는 최소 흐름만 만든다. 자동으로 200판을 시작하거나 통계 화면을 만들지 않는다.
- `한 수 진행`은 계획 계산, 실제 첫 행동 적용, 낙하·연쇄 완료까지다. 한 판 실행에서는 이를 반복한다.
- 탐색 중에는 `계획 계산 중`, 살펴본 범위, 선택 이유와 가정/불확실성을 표시한다. 기존 보드·버튼 영역을 유지하고 필요하면 상세 이유를 접는다.
- 실제 행동 제출 전 중지는 가정 작업을 즉시 폐기하며 실제 이동 수·난수를 소비하지 않는다. 이미 제출한 행동은 25단계와 같이 안정 경계까지 처리한 뒤 중지한다.
- 탭 이탈도 같은 중지 원칙을 따른다. 원본 수정·레벨 변경·창 종료·재로드는 가정 상태와 갱신 예약을 정리한다. 늦게 끝난 탐색 결과를 새 판에 적용하지 않는다.
- 도움말 아이콘의 툴팁과 클릭 연결, 한국어 HTML 설명서의 전략/가정/재시험 사용법을 보완한다.

## 기능별 구조

기존 `Assets/Scripts/Features/AutoPlay/` 안에서 `Runtime/Observation`, `Runtime/Strategy`, `Runtime/Execution`, `Editor/Presentation`, `Editor/Tests`를 유지한다. 탐색 작업과 가정 실행이 실제로 분리될 만큼 커질 때 해당 역할 내부에 하위 폴더를 둔다. 가정 실행 어댑터는 실행 역할, 후보/표본 평가와 탐색 정책은 전략 역할이다. 빈 인터페이스·공통 Manager·예상용 폴더는 만들지 않는다.

복잡한 부분에는 한국어 주석으로 실제/가정 상태의 소유자, 가정 난수 유래, 처리량 한도, 부분 탐색 비교와 중지 경계를 설명한다. 런타임에는 Editor API를 넣지 않는다.

## 작업 순서와 검증

| 작업 | 산출물 | 검증 |
|---|---|---|
| T1 정보·가정 계약 감사 | 실제 참조 금지표, 현재 규칙의 가정 가능 범위, 초기 측정용 사례 | 25단계 증거·최신 코드·보존 해시, 상태 생성 경계 확인 |
| T2 가정 상태와 공통 실행 연결 | 공개 값에서만 새 가정 상태 생성, 가정 전용 난수·기록 | 숨은 값만 다른 쌍의 동일 가정, 실제 상태/난수 불변, 규칙 일치 |
| T3 제한된 두 수 탐색 | 증분 탐색, 결정적 한도·동점·가정 집계, 이유 | 준비 수가 유리한 사례, 탐색 한도·불확실성·대체/오류 구분 |
| T4 실행 세션 연결 | 전략 선택·오래된 결과 거절·탐색 중지 | 실제 명령 재검증, 한 수 비용·종료/라스트팡, 수명주기 |
| T5 Match UI·개별 비교 | 실제 선택/한 수/한 판/중지/같은 조건 재시험, 도움말 | 실제 UI·최소 크기·원본 편집/재로드·새 시드/같은 시드 경계 |
| T6 독립 재현·회귀·완료 감사 | 버전/가정 정책/측정 기록·조건별 증거 | 별도 Unity 재현, 같은 수동 명령 결과, 기본 전략/에디터 회귀·원본 보존 |

T6의 측정은 소요 시간·최대 작업 수·갱신당 처리량 등 기술 검증이다. 사용자용 난이도 통계를 선행 구현하지 않는다.

## 필수 검증 사례

- 공개 관찰과 후보는 같고 실제 시드·난수·공급·곰팡이 내부·이력만 다른 쌍: 가정 상태, 탐색 점수·이유·첫 선택까지 동일.
- 가정 구성/분기/평가/취소 전후 실제 JSON·상태·이동 수·난수·드론 예약·원본 dirty 불변. 실제 명령 제출 이후만 변경.
- 같은 가정 입력과 가정 시드에서 공통 실행기와 가정 어댑터의 규칙 결과 일치. 별도 봇 규칙 엔진 없음.
- 확정 가능한 좁은 사례에서 즉시 기여는 적지만 다음 수의 파워 조합/미션 기여가 큰 준비 수를 선택. 기본 전략과 실제 선택 차이 및 두 번째 수의 기여를 확인한다.
- 상자/고철/금고/자물쇠/폐가전, 덮개·먼지, 발전기, 회수·도착·통로·가정 공급을 대표 사례로 점검한다. 가정 불가능 사례는 이유와 대체 경로를 검증하고 지원으로 위장하지 않는다.
- 무작위 표본이 다른 경우, 후보 열거 순서 변경, 한 프레임 처리량 변경에서도 명시한 결정적 조건을 만족한다. 예산 부족이 앞쪽 후보 편향을 만들지 않는지 검사한다.
- 탐색 중 중지·탭 이탈, 실제 행동 후 중지, 원본 수정·레벨 변경·창 닫기·실제 재로드, 완료 직후 오래된 결과 제출을 분리 검증한다.
- 성공·이동 소진·막힘·실행 오류·사용자 중지와 라스트팡 후속 오류를 유지한다. 가정 판의 종료가 실제 판에 전파되지 않는다.
- 두 전략의 같은 시작 조건 재시험과 별도 Unity 프로세스의 같은 계획 선택/행동/결과를 검증한다. 실제 동일 명령열의 수동 결과와도 비교한다.
- 기존 기본 전략의 대표 선택, 저장 단축키·dirty·등록 맵·연결 편집·최소 창 크기·도움말·수동 아이템/부스터가 유지된다.

증거는 `Logs/BotPlanningVerification/`에 보관한다. 착수 기준 해시·실행 버전·가정 정책/탐색 한도·정의 지문·실행 전용 시드·선택/실행 기록·실제 UI 캡처·측정 조건·중복 없는 검사 집계를 기록한다. 사용자 Unity는 임의 종료하지 않고 소유 검증 객체만 정리한다.

## 대안과 미확정 사항

실제 상태를 복제해 정확히 탐색하는 방법은 쉽지만 숨은 정보 조건을 위반한다. 별도 간이 게임 엔진은 유지비와 규칙 불일치가 커서 채택하지 않는다. 공개 정보로 가정 상태를 만들고 공통 실행기를 쓰는 방식을 선택한다.

깊이·후보·표본 시작값, 가정 생성 정책의 구체 구성과 평가 계수는 구현 기본안이다. 현재 측정하지 않은 속도나 성공률을 약속하지 않는다. 구현 시 공개 정보만으로 공통 실행기를 안전하게 구성할 수 없는 핵심 제약이 발견되면 근거를 기록하고 그 쟁점만 확인한다. 정보 유출이나 깊이 1로 범위를 몰래 축소하여 완료 처리하지 않는다.
