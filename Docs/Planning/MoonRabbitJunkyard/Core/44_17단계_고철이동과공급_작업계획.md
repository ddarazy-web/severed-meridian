## 목표와 확인한 현재 상태

Match 실행 시험에서 고철 뭉치를 교환·낙하시키고, 매칭/파워로 손상·제거하며, 지정 생성구의 고정 목록 또는 개수 유지 방식으로 보충한다. 고철 제거 미션과 드론 목표 조회에 연결하고 기존 상자·거미줄·먼지·파워 동작을 보존한다.

문서 작성 시 16단계 완료 조건 20개와 검사 1,569개 PASS를 [완료 감사](../../../../Logs/LayerVerification/completion-audit.json)에서 확인했다. 최종 소스 해시와 현재 파일 불일치 0건, 활성 Goal 없음이다. 실행 시 다시 대조한다.

현재 구현의 중요한 경계:

- `ActionQuery`는 이미 고철의 일반 교환 후보와 자석 교환 금지를 일부 판단한다. 실제 실행기는 상자 외 장애물과 고철 미션을 거절한다.
- `MovementQuery`는 일반/파워만 이동시키며, 교환·정착의 점유자 이동도 Content/Color/RocketDirection만 옮긴다. 고철 허용만 추가하면 ObstacleIndex가 따라가지 않는다.
- 파워 교환 발동 위치 계산은 상대가 일반 블록인 경우를 전제로 한다. 고철과 파워의 입력 양방향에서 실제 교환 후 파워 위치를 따르도록 확인해야 한다.
- `RuntimeObstacle`은 최초 배치 정의와 내구도를 가진다. 현재 Obstacles는 초기 배열의 읽기 전용 목록이며 공급 중 본체를 추가하는 경로가 없다. Definition.Coordinate는 최초 배치 좌표이므로 이동 후 현재 위치로 사용하면 안 된다.
- `RuntimeSupply`에는 ScrapTarget/ScrapLimit/ScrapDurability/ScrapGenerated가 있다. 정착은 MaintainScrap과 고정 목록의 Scrap을 아직 거절한다.
- `MissionProgressRules`와 `DroneTargetManager`는 종류별 기여와 본체 인덱스/좌표를 이용한다. 고철은 새 엔진 대신 이 경로에 연결할 수 있다.
- Match 셀 표시에 초기 CurrentState의 장애물 목록을 참조하는 부분이 있다. 새로 공급된 본체는 실행 상태 목록에서 조회해야 한다.

## 범위와 접근 선택

| 대안 | 장점 | 한계 | 판단 |
|---|---|---|---|
| 최초 고철 이동/피해만 구현 | 변경이 작음 | 공급에서 새 개체를 만드는 핵심 모델 검증이 뒤로 밀림 | 대안 |
| 이동·피해·두 공급 방식을 한 목표로 순차 구현 | 고철 개체의 생성부터 이동·제거까지 검증 | 본체 식별과 공급 순서 검사가 필요 | 채택 계획 |
| 모든 이동 오브젝트와 생성 방식을 범용화 | 확장 폭이 큼 | 회수 도착 판정까지 범위가 늘고 기존 처리 중복 위험 | 제외 |

지원 보드는 일반/파워4종/상자/거미줄/먼지에 고철을 추가한다. 미션 종류에 고철 제거를 추가하되 한 레벨의 미션 수는 기존 1~4개다. 공급은 기존 Random/Fixed에 Fixed의 Scrap과 MaintainScrap을 더한다.

회수 부품과 MaintainRecovery, 곰팡이·금고·자물쇠·대형 폐가전·발전기, 승패·라스트팡·아이템/부스터·자동 섞기·봇·난이도 분석·해금 레벨·아트/런타임 연출은 제외한다. 아이템으로 고철을 옮기거나 섞기에서 제외한다는 기획은 유지하되 이번에 아이템 시스템을 만들지는 않는다.

## 확정 게임 규칙

### 이동과 교환

- 고철은 내구도 1~5의 한 칸 이동 장애물이다. 일반 블록과 같은 수직/대각선·구역 중력·지정 경로·통로·합류 규칙을 따른다. 상자는 계속 고정이다.
- 고철끼리 또는 일반 블록과 섞여 매칭되지 않는다. 일반 블록과 교환해 일반 매칭이 완성되면 유효하며, 그렇지 않으면 이동 수·난수·상태를 보존해 거절한다. 빈칸과 교환하지 않는다.
- 로켓/폭탄/드론과의 직접 교환은 매칭 없이 파워를 발동하고 한 수를 소비한다. 자석과의 직접 교환은 무비용 취소한다. 고철을 두 번째 파워로 취급하지 않는다.
- 이동 시 내구도와 본체 식별이 따라가고 바닥 먼지는 좌표에 남는다. 고철에는 거미줄을 배치하지 않는다.

### 피해·미션·드론

- 인접 일반 매칭 또는 직접 파워 타격으로 1피해. 파워가 옆 일반 블록을 지운 것만으로 고철에 인접 피해를 주지 않는다. 벽과 파워 관통은 기존 규칙을 유지한다.
- 같은 고철은 한 수의 전체 연쇄에서 최대 1피해다. 피해 후 낙하·교환되어도 같은 개체의 기록이 유지된다. 다음 수에는 다시 피해받는다.
- 완전히 제거된 고철 본체 1개를 고철 미션 1개로 집계한다. 생성만으로 미션 목표 수량을 늘리지 않는다.
- 제거 미션이면 내구도와 관계없이 드론 후보가 될 수 있다. 이번 수에 이미 피해받은 고철은 제외한다. 예상 손상과 예상 완전 제거를 구분한다.
- 자석+자석은 고철에 1피해를 준다. 자석 단독의 색 선택이나 자석+파워의 색 변환 대상에는 넣지 않는다.
- 고철 손상/제거만으로 아래 먼지를 손상하지 않는다. 이후 들어온 일반 블록의 실제 소비/변환은 기존 먼지 규칙을 따른다.

### 고정 공급과 개수 유지

- 고정 목록은 생성구별 지정 순서·수량·내구도로 공급한다. 막힌 생성구의 항목을 다른 곳으로 넘기거나 건너뛰지 않는다. 최초 보드 구성에서 소비하지 않는다.
- 목록 소진 뒤 Stop 또는 일반 달토끼 Random 전환을 유지한다. 고철이 아닌 일반/파워 항목과 섞인 목록도 지원한다. 회수 부품 항목은 계속 미지원이다.
- 개수 유지는 현재 보드의 살아 있는 고철이 ScrapTarget보다 적고 추가 한도가 남아 있을 때 보충한다. 최초 고철은 추가 한도에서 제외한다.
- 실제 생성 가능한 MaintainScrap 생성구 중 무작위로 하나씩 배정한다. 부족량·사용 가능한 칸·남은 추가 한도를 넘지 않는다. 막힌 동안에는 한도와 난수를 소비하지 않는다.
- 기존 이동/통로 유입을 먼저 처리하고, 그래도 빈 생성구에 새 블록을 공급한다. 고철이 필요하면 일반 블록보다 우선하며 목표 충족/한도 소진 후에는 일반 달토끼를 공급한다.
- 고정 고철 목록과 고철 개수 유지는 생성구가 달라도 한 레벨에서 혼용하지 않는다. 기존 에디터 검증과 실행 지원 경계를 일치시킨다.

## 실행 세부 정책

이 계획을 지정한 개발 요청에 아래 정책을 포함한다. 실제 기존 계약과 충돌하면 근거를 기록하고 해결한다.

1. **본체 식별:** 기존 ObstacleIndex를 실행 중 안정적인 본체 키로 우선 재사용한다. 제거된 슬롯을 같은 레벨 실행 중 다른 본체에 재사용하거나 살아 있는 인덱스를 당겨 정렬하지 않는다. 새 고철은 새 키를 갖는다. 별도 전역 ID 서비스는 만들지 않는다.
2. **현재 위치:** 점유 셀의 ObstacleIndex를 현재 위치의 기준으로 사용한다. 불변 최초 정의 좌표를 이동마다 바꾸지 않는다. 현재 위치를 찾는 실제 호출부만 수정하고 좌표의 두 원본을 만들지 않는다.
3. **점유자 이동:** 교환/직선/대각선/경로/통로/합류에서 본체 참조를 함께 옮기고 출발 칸의 참조를 비운다. 내용물과 바닥을 분리한다. 공급·제거 후 고아 참조와 이중 점유가 없어야 한다.
4. **실행 사본:** 본체 목록의 동적 추가와 내구도, 셀, 공급 커서, 생성량, 미션, 난수, 턴 피해가 사본별로 독립적이어야 한다. 외부에는 읽기 전용 접근을 유지한다. 공급 본체의 최소 생성 경로를 추가하되 레벨 원본에 런타임 장애물을 덧쓰지 않는다.
5. **공급 배정:** 한 정착 배치에서 기존 이동을 우선한다. 빈 유지 생성구를 좌표순으로 모은 뒤 부족량만큼 위치를 무작위 선택하고 후보에서 제거한다. 단일 후보는 선택 난수를 쓰지 않는다. 고철 배정 후 남은 생성구의 일반/고정 공급은 기존 좌표순을 따른다. 생성 성공 때만 유지 생성량을 증가시킨다.
6. **카운터 구분:** ScrapGenerated/ScrapRemaining은 개수 유지 방식의 추가 한도를 의미한다. 고정 목록은 자체 커서/항목 소비량으로 관리한다. 최초 배치를 추가 생성으로 세지 않는다. 살아 있는 고철 수는 실제 보드 점유 본체 기준으로 계산한다.
7. **피해 수명:** 본체 기반 기존 턴 피해 기록을 재사용한다. 같은 좌표에 나중에 공급된 새 고철은 이전 본체의 피해 기록을 물려받지 않는다. 예약 해제로 실제 피해 제한을 풀지 않는다.
8. **조회와 기록:** 이동/행동/피해/미션 후보 조회는 상태·난수·공급량을 바꾸지 않는다. 드론에는 현재 위치와 본체 키의 일치, 완전 제거/부분 피해를 전달한다. UI는 실행 상태의 새 본체까지 표시한다.
9. **실패와 재현:** 미지원 보드/공급/혼용은 가능한 한 실행 전에 거절한다. 정착 도중 실패해도 본체 추가·커서·생성량까지 폐기하고 직전 성공 상태를 보존한다. 기존 정착/연쇄 한도 진단을 유지하며 새로운 사용자 옵션을 추가하지 않는다. 결과가 바뀌는 알고리즘 버전은 갱신한다.

주요 검증 사례:

- 내구도1~5의 일반 교환 성립/불성립, 빈칸/고철끼리 거절, 로켓·폭탄·드론 교환 양방향, 자석 교환 무변경.
- 네 방향 중력·대각선·지정 경로·통로·합류·끝칸·벽·막힌 칸에서 이동 키/내구도/바닥 보존. 상자의 고정 동작 회귀.
- 동일 고철이 피해 후 낙하해 재피격되어도 턴1피해, 다음 턴 재피해. 이전 고철 제거 자리의 새 고철은 새 개체로 피해 가능.
- 매칭 인접 피해와 파워 직접 피해 구분, 파워4종/조합10종, 먼지 중첩, 거미줄과의 배치 금지.
- 고철 완전 제거만 미션 진행, 드론의 부분 손상/완전 제거 예상량·범위 예약·중복/소실/해제·대체 목표.
- 두 생성구의 혼합 고정 목록 순서와 내구도, 한쪽 막힘, 소진 Stop/Random, 초기 구성 비소비, 원본 목록 보존.
- 최초2/목표2/추가한도6, 목표0·한도0·목표초과 최초 배치, 부족량보다 적거나 많은 생성구, 전체/부분 막힘, 후보1개 무난수, 다중 후보 동일 시드 재현.
- 유지 목표/한도 소진 후 일반 공급, 고정 고철/개수 유지 혼용 거절, 회수 부품 공급 미지원 거절.
- 여러 번 제거·생성 후 모든 살아 있는 본체가 정확히 한 칸을 점유하고 키가 재사용되지 않음. 사본/초기화/실패 뒤 고아 참조·공유 변경 없음.
- 실제 유효 편집 레벨로 Match 실행, 내구도/커서/생성량 표시와 1000/680 폭, 초기화/입력 변경/닫기 해제, 마지막 수 및 다음 수, 단계/끝까지 결과 일치.
- 동일 정의·시드·행동열·버전의 동적 본체·점유·내구도·공급 커서/카운터·미션·난수·턴 기록·예약을 독립 Unity 프로세스에서 재현.
- Unity 컴파일 및 8~16단계 영향 회귀, 원본/v4/GUID/meta·무관 파일 보존, 소유 임시 자원 정리. 과거 결과와 이번 재실행 수를 구별한다.

## 후속

17단계 완료 뒤 확산형 곰팡이 또는 특수 타격 고정 장애물 중 다음 범위를 정한다. 회수 부품은 도착 지점·회수 집계까지 함께 다룰 별도 단계로 남긴다. 이 단계 완료를 전체 게임 플레이나 봇 평가 완료로 표현하지 않는다.
