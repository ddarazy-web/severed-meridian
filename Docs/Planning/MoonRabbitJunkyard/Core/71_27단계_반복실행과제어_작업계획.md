## 현재 확인한 상태

26단계는 20개 완료 조건과 최종 3,750 PASS / 0 FAIL 검증을 마쳤다. 계획 작성 후 사용자가 별도로 Goal 실행을 요청하여 27단계 구현과 검증을 마쳤다. 기존 작업 트리의 변경을 보존했다. 아래는 실행에 사용한 계획이며 최종 결과는 완료 검증 문서에 기록했다. 26단계 검사 수는 선행 근거이며 27단계 신규 검증 수에 합산하지 않는다.

착수 기준 버전은 계획 `planning-bot-v2`, 가정 `public-assumption-v1`, 세션 `bot-session-v3`, 기본 전략 `basic-bot-v1`, 관찰 v1, 공통 실행기 `board-action-items-v13`이다. 착수 시 실제 코드와 대조하고 변경된 버전은 실행 기록에 남긴다.

현재 `BotPlaySession`은 한 판을 소유하고 `Advance`로 조금씩 처리한다. 기본/계획 전략, 공개 관찰 경계, 한 판 중지와 기록을 이미 제공한다. `LevelInitialStatePanel.Bot.cs`에는 한 판 시험과 같은 조건 재시험 UI가 있다. 27단계는 이 한 판 실행을 순서대로 관리하는 기능을 붙인다. 착수할 때 26단계 최종 코드·버전·검증 기록을 다시 확인한다.

## 목적과 범위

제작자가 만든 레벨을 기본 봇과 계획 봇으로 여러 번 시험하고, 긴 실행을 일시정지·재개·중지할 수 있게 한다. 두 전략의 시작 조건은 같게 유지하며 완료된 판의 기록은 중지 후에도 남긴다.

포함하는 것은 반복 실행, 시드 묶음, 진행률, 실행 제어, 최소 결과 요약, 완료 기록 저장과 같은 조건 재시험이다. 기본 횟수는 **전략별 100회, 합계 200회**이며 제작자가 횟수를 바꿀 수 있다. 한 번에는 한 레벨, 한 판만 실행한다.

상세 성공률 분석·그래프·사례 재생·수정 전후 분석 이력은 28단계, 난이도 추천은 29단계, 전체 제작 흐름 검수는 30단계다. 병렬 실행, 자동 레벨 생성, 아이템·부스터·광고 사용은 추가하지 않는다.

## 실행 순서와 비교 조건

1. 현재 편집 내용을 검사하고, 저장 여부와 무관하게 실행용 값 복사본과 정의 지문을 고정한다. 이후 원본 수정이 실행 중 사본에 섞이지 않아야 한다.
2. 요청 횟수 N개만큼 서로 다른 시드를 만든다. 새 실행에서는 새 묶음을 생성하며 직전 묶음을 그대로 재사용하지 않는다. 과거 모든 묶음과의 영구적인 시드 중복 금지는 요구하지 않는다.
3. 시드 1의 기본→계획, 시드 2의 기본→계획 순서로 실행한다. 중간 중지 시 두 전략의 실행 수가 크게 벌어지지 않는 장점이 있다. 미완성 쌍은 별도로 표시한다.
4. 두 전략에 같은 정의 사본·시드를 전달하되 서로 독립된 한 판 세션을 만든다. 한 전략의 상태·난수 소비·드론 예약·계획 탐색을 다음 판으로 넘기지 않는다.
5. 한 판의 종료 처리를 마친 후 기록을 확정하고 다음 판을 시작한다. 같은 판을 두 번 기록하지 않는다.
6. 같은 조건 재시험은 저장된 정의 사본과 시드 묶음을 사용한다. 현재 편집 내용이 달라졌다면 과거 조건임을 표시한다. 버전이 달라지면 완전한 재현이라고 표시하지 않는다.

시드와 내부 기록은 실행 관리 영역에서만 사용한다. 전략은 기존 공개 관찰만 받는다. 같은 시드라도 행동이 달라지면 이후 판은 달라질 수 있으며, 두 전략의 최종 판이 같아야 한다는 조건은 두지 않는다.

## 상태와 제어 — 구현 기본안

아래는 이번 계획의 기본안이다. 기존 확정 규칙과 충돌하면 해당 쟁점만 grill-me로 확인하고 변경 근거를 기록한다.

| 상태·요청 | 처리 |
|---|---|
| 준비 중·실행 중 → 일시정지 | 현재 `Advance` 호출이 끝난 지점에서 후속 호출과 다음 판 시작을 멈춘다. 시작 보드 검색·계획 탐색·연쇄의 진행 객체를 유지한다. |
| 일시정지 → 재개 | 같은 객체·난수·진행 위치에서 계속한다. 새 시드나 새 판을 만들지 않는다. |
| 일시정지 → 중지 | 재개할 필요 없이 중지한다. 현재 미완료 판은 중단 기록으로 구분한다. |
| 실행 중 → 중지 | 다음 처리 단위로 넘어가지 않고 미완료 판을 중단한 뒤 실행 객체를 해제한다. 이미 확정된 완료 기록은 유지한다. |
| 완료·중지됨 | 같은 묶음의 실행을 자동 재개하지 않는다. 같은 조건 재시험은 별도 실행으로 시작한다. |
| 한 판 실행 오류 | 오류 이유와 판 정보를 남기고 묶음을 중지한다. 같은 결함으로 나머지 판을 반복 실행하지 않는다. |

일시정지는 살아 있는 세션의 갱신을 멈추는 방식으로 시작한다. 기존 `RequestStop`을 일시정지 대신 호출해 계획 탐색을 버리지 않는다. UI에 표시된 판은 연쇄 도중일 수 있으므로 ‘처리 중 멈춤’을 구분한다. 다시 진행한 최종 행동열과 결과가 멈추지 않은 실행과 같아야 한다.

반복 실행의 중지는 해당 미완료 판을 폐기하는 제어다. 기존 한 판 시험의 ‘제출한 행동을 안정 경계까지 처리하고 중지’ 동작을 임의로 바꾸지 않는다. 승리가 정해졌더라도 라스트팡 등 후속 처리가 남았으면 정상 완료 기록으로 조기 확정하지 않는다.

편집 탭 이동은 반복 실행을 자동 일시정지하고 복귀 시 명시적으로 재개한다. 다른 레벨 선택·원본 변경은 과거 사본 실행임을 표시하고 자동으로 새 정의로 교체하지 않는다. 창 종료·도메인 재로드·Editor 종료 시에는 완료 기록을 보존하고 현재 판과 묶음을 중단으로 남긴다. 프로세스 재시작 후 진행 중 판의 실시간 복원은 이번 범위가 아니다.

## 기록과 최소 결과 화면

묶음에는 식별자, 정의 사본·지문, 시드 목록, 전략과 실행/관찰/가정 규칙 버전, 요청 횟수, 시작·종료 시각, 실행 상태를 저장한다. 판별로 시드 순번·전략·종료 종류·사용/남은 이동 수·남은 미션·행동 기록·오류 또는 중단 이유를 남긴다. 내부 진단은 전략에 전달하지 않는다.

정상 성공, 이동 수 소진, 정상 막힘, 실행 오류, 사용자 중단을 구분한다. 처리 한도·미지원 조건·유효하지 않은 데이터는 일반 패배로 집계하지 않는다. 정상 종료한 판 수, 오류 수, 중단 수, 미실행 수가 예정 수와 맞아야 한다. 중지된 묶음에는 ‘일부 실행’을 표시하며 진행률을 100%로 만들지 않는다.

완료한 판을 확정할 때 프로젝트의 로컬 시험 결과 영역에 기록한다. `Assets`를 매 판 변경하여 가져오기와 도메인 재로드를 일으키지 않는다. 기존 저장 수단을 우선 조사하고, 없다면 `Library/Match/AutoPlay`의 버전 있는 JSON 기록을 기본안으로 사용한다. 임시 파일에 쓴 뒤 교체하고, 저장 실패는 표시하고 실행을 멈춰 누락을 숨기지 않는다. 이 기록은 프로젝트 로컬 캐시이며 Library 삭제 시 소실될 수 있음을 도움말에 표시한다. 장기 분석 이력·내보내기는 28단계에서 다룬다.

한 번에 한 판만 메모리에 유지하고 확정한 상세 기록은 파일에 남긴다. 횟수만큼 살아 있는 게임 상태를 보관하지 않는다. 레벨 하나의 정의 사본은 묶음에서 공유하고 판마다 중복 저장하지 않는다.

## 화면과 구조

기존 Match 통합 창의 자동 시험 영역을 확장한다. 기본 화면에는 **전략별 횟수, 새 시험, 같은 조건 재시험, 일시정지/재개, 중지, 진행률, 간단한 결과**를 둔다. 전략별 현재 완료 수와 현재 실행 중인 전략·판 번호를 보여준다. 한 판 시험과 반복 시험이 동시에 같은 화면의 입력을 소유하지 않게 한다.

반복 시험은 고속 처리를 기본으로 하되 UI 갱신당 처리량을 제한한다. 시간 한도는 화면 응답성을 위한 양보에만 쓰며 봇의 결정·표본 채택·실패 판정 기준으로 쓰지 않는다. 일반/고속 진행의 동일 결과를 확인하고 현재 단계식 화면 갱신을 출시용 연출 완성으로 표현하지 않는다.

26단계의 정상 10×10 판에서는 계획 봇 한 수가 약 9.92초, 최대 단일 처리가 약 104ms였다. 인위적인 한도 사례에서는 최대 단일 처리가 약 353ms였다. 따라서 기본 200판이 짧은 시간에 끝난다고 가정하지 않는다. 갱신당 반복 횟수 제한만으로 한 번의 긴 `Advance` 호출까지 짧아지는 것은 아니므로 실제 최대 갱신 지연과 일시정지·중지 반응 시간을 함께 측정한다. 시간이 오래 걸린다는 이유로 표본 수나 탐색 깊이를 조용히 줄이지 않는다. 처리 분할이 필요하면 결정 순서·난수 소비·결과를 유지하는 범위에서 보완하고 재현 검증을 수행한다.

`Assets/Scripts/Features/AutoPlay` 안에서 실행 관리는 Runtime/Execution, 값 기록은 기존 역할에 맞는 Data 또는 Results, 화면은 Editor/Presentation, 검증은 Editor/Tests로 나눈다. 이름과 파일 수는 착수 시 최종 코드를 보고 정한다. 반복 관리자만 한 판 세션을 소유하고, 화면은 실행 제어와 표시를 맡는다. 게임 규칙이나 봇 평가를 반복 관리자에 복사하지 않는다. 별도 서비스 프레임워크·스레드·패키지·빈 확장 인터페이스를 만들지 않는다.

설명 아이콘의 툴팁과 기존 HTML 매뉴얼 링크를 유지하고 사용법을 보완한다. 최소 창 크기에서도 필수 버튼·진행 상태가 가려지지 않아야 한다.

## 작업 순서와 검증

| 작업 | 내용 | 검증 |
|---|---|---|
| T1 기준 확인 | 26단계 완료 증거, 최신 세션/UI 호출부, 원본 보존 기준, 상태·기록 계약 확정 | 선행 미완료면 27단계 구현 착수 금지. 의존성과 결정 기록 |
| T2 반복 실행 | 정의 사본, 시드 묶음, 두 전략의 순차 한 판 실행 | 시드 중복·교차 오염·누락·중복 기록·다른 시작 조건 검사 |
| T3 제어 | 일시정지·재개·중지·오류·수명 종료 처리 | 준비/계획/연쇄/라스트팡/판 사이 각 경계와 멈추지 않은 실행 비교 |
| T4 보존 | 판별 결과 확정·로컬 저장·중단 표시·같은 조건 재시험 | 저장 실패, 손상 기록, 재로드, 정의·버전 차이, 독립 프로세스 재현 |
| T5 화면 | 실행 버튼·진행률·요약·도움말 | 실제 Unity에서 최소 크기, 탭 이동, 연속 입력, 원본 변경, 응답성 확인 |
| T6 감사 | 대표 레벨 100개 시드×두 전략, 영향 회귀와 문서 | 전체 200판 및 중지 사례, 시간·최대 갱신 지연·메모리 측정, 완료 조건별 증거 |

작은 고정 묶음으로 경계 문제를 먼저 검증한 후 기본 200판을 실제 실행한다. 모든 판의 승리를 요구하지 않으며 정상 패배는 정상 결과다. 오류를 패배로 치환하거나 필요한 실행 횟수를 줄여 기본 부하 검증으로 보고하지 않는다. 독립 프로세스에서는 동일 정의·시드·버전의 행동열과 종료 결과를 대조하고, 처리 속도와 일시정지 횟수만 바꾼 결과도 비교한다.

26단계와 기존 수동 시험·저장/dirty·맵 목록·연결 편집·도움말의 영향 회귀를 수행한다. JSON·에셋/GUID/meta·설정/패키지 보존, 이벤트 구독과 소유 임시 자원 정리를 확인한다. 사용자 Unity를 종료하거나 같은 프로젝트 Unity를 중복 실행하지 않는다. 검증하지 못한 내용은 완료로 표시하지 않는다.
