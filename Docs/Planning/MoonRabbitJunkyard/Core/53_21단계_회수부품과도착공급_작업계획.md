## 문제와 완료 모습

회수 부품·도착 바닥·고정/유지 공급은 에디터에서 설정하고 초기 상태로 구성할 수 있지만, 현재 공통 실행기는 회수 부품과 회수 미션을 미지원으로 거절한다. 편집한 회수 레벨을 실제 시험할 수 있도록 교환·낙하·즉시 회수·보충·미션을 연결한다.

완료 후 Match 수동 시험에서 회수 부품을 이동시키고 도착 바닥에서 회수되는 과정, 남은 목표와 공급 변화를 확인할 수 있어야 한다. 이번 단계는 미션 진행까지이며, 모든 미션 달성을 판 승리로 확정하는 기능은 22단계다.

## 현재 코드와 보존 기준

- `LevelStateBuilder`는 초기 회수 부품을 `RuntimeContent.Recovery`로 구성하며, `RuntimeFlow.Arrivals`와 `RuntimeSupply.RecoveryTarget`도 존재한다. 새 레벨 형식을 만들지 않는다.
- `ActionQuery`에는 회수 교환과 자석 거절의 일부 조건이 있다. 실제 실행과 조회의 차이를 먼저 확인한다.
- `MovementQuery`의 이동 가능 판정, `SettlementResolution`의 정착/공급, `BoardActionExecutor` 및 `PowerEffectResolution`의 미지원 미션 검사, `DamageReaction`의 회수 피해 거절을 함께 조사한다. 미지원 차단만 삭제하고 일반 블록처럼 처리하지 않는다.
- `MissionProgressRules`와 `DroneTargetManager`의 기존 조회·추천·예약 경계를 유지한다.
- 20단계 최종 증거는 2,448 PASS/0 FAIL이다. 그 이후 발전기/통로 연결·후보 강조·낙하 경로 드래그·합류 목록 편집이 추가됐다. 최신 편집 검증은 `Logs/MergeEditingVerification`의 116 PASS/0 FAIL이다. 이 수치를 서로 합산하거나, 20단계 해시와 달라졌다는 이유로 후속 편집 작업을 되돌리지 않는다.
- 착수 시 현재 Scripts/Data/기획/기존 무관 변경을 새 기준으로 기록한다. 검증 로그가 없는 환경에서는 현재 코드에서 재검증하고 과거 결과를 새 결과로 보고하지 않는다.

## 적용할 게임 규칙

근거는 [게임 규칙](../../../Contents/MoonRabbitJunkyard/04_게임규칙.md)의 회수 부품·도착 바닥·공급 및 [규칙 조회](../../../Contents/MoonRabbitJunkyard/11_규칙조회와목표관리.md)다.

1. 회수 부품은 매칭 대상이 아니며 파워로 파괴되지 않는다. 파워의 관통·다른 칸 효과를 막는 벽으로 취급하지 않는다.
2. 일반 블록과 교환해 일반 매칭이 성립하면 유효하다. 실패 시 보드·이동 수·난수·미션이 원상태여야 한다. 로켓·폭탄·드론과의 교환은 해당 파워를 발동하고 자석과는 비용 없이 취소한다.
3. 회수 부품도 기존 중력·직접 경로·합류 우선순위·통로·대각선 이동 규칙을 따른다. 별도 낙하 엔진을 만들지 않는다.
4. 어느 도착 바닥이든 같은 회수 부품을 받는다. 회수 부품만 제거하고 미션을 1회 진행하며, 일반·파워·고철에는 기존 흐름을 적용한다.
5. 도착은 정착 전체 완료까지 미루지 않는다. 회수로 생긴 빈칸에 후속 이동/공급을 계속한다. 교환으로 도착한 경우와 같은 처리 묶음의 여러 부품도 누락·중복 없이 처리한다.
6. 초기 배치가 도착 바닥 위인 경우도 검증한다. 읽기 전용 초기 후보 구성은 보존하고, 실행 시작 시 공통 정규화 경계에서 한 번만 회수하도록 연결한다. 원본 에셋을 고치거나 플레이어의 첫 수를 강제로 요구하지 않는다.
7. 최초 배치, 생성구별 고정 공급 목록, 회수 개수 유지 공급을 지원한다. 고정 목록은 지정 생성구에서만 순서대로 소모하고 기존 소진 후 정지/일반 공급 설정을 따른다.
8. 유지 공급 부족분은 `max(0, min(설정 유지 개수, 남은 회수 목표) - 현재 보드의 회수 부품 수)`를 기준으로 계산한다. 여러 생성구가 같은 부족분을 중복 채우지 않도록 실제 공급마다 갱신한다. 보충이 불필요하면 일반 블록을 공급한다.
9. 남은 목표 제한은 유지 공급에 적용한다. 고정 목록을 임의로 건너뛰거나 이미 있는 부품을 목표 초과라는 이유로 삭제하지 않는다. 생성구 선택·공급 순서·난수 소비는 기존 정착 규약을 따른다.
10. 기존 배치/공급 검사에서 금지한 중첩은 유지한다. 생성구와 도착 바닥, 통로 입출구와 도착 바닥을 겹치게 만들지 않는다. 새 덮개 조합이나 신규 미션 종류를 추가하지 않는다.

## 실행 구조와 드론 연동

`Assets/Scripts/Simulation`의 기존 상태·행동·정착·미션 계층에 구현한다. 회수 반응의 책임이 분리될 만큼 필요하면 같은 구성 안의 작은 규칙 파일로 나눈다. Editor는 표시와 명령 전달을 담당한다. 새 게임명 폴더, 별도 시뮬레이터, 패키지, 범용 이벤트 시스템은 추가하지 않는다.

- 공통 회수 처리에서 실제 점유 해제·미션 집계·회수 기록을 함께 수행한다. 조회나 예약만으로 미션을 줄이지 않는다.
- 상태 복사와 실패 원자성을 보존하고, 같은 부품을 이동·회수·파워 효과 등 여러 경로에서 중복 집계하지 않는다. 회수 이력과 공급 커서 등 재현에 필요한 상태를 기록한다.
- 드론은 파괴 불가능한 회수 부품 자체를 파괴 목표로 선정하지 않는다.
- 이번 단계의 간접 기여 구현 기준: 현재 확정된 이동 경로에서 부품의 다음 이동을 직접 막는 점유자를 제거하거나 약화시키는 효과를 후보로 조회한다. 벽·경로 끝·비활성 칸은 제거 후보가 아니다. 대각선·합류는 기존 이동 조회가 허용하는 경우만 사용한다.
- 위 간접 기여 범위는 새 게임 규칙이 아니라 이번 구현의 보수적 예측 범위다. 장애물별 반응 조회에서 설명 가능하게 제공하고 매니저에 장애물 종류 분기를 몰아넣지 않는다. 미래 공급·추가 연쇄·실제 난수를 미리 실행하지 않는다.
- 길을 여는 것과 실제 회수를 구분한다. 길이 열려도 회수가 보장되지 않는 경우 예상 회수 완료량을 올리지 않는다. 직접 효과 범위의 칸/본체 예약을 재사용하고 같은 방해 요소의 중복 예약을 피한다.
- 이동·회수·방해 요소 변화 시 후보를 갱신한다. 무효 목표는 미션 후보 재검색 후 일반 블록 대체 규칙을 유지한다.

## Match 수동 시험 화면

회수 부품과 도착 바닥은 숫자/모양/간단한 도형으로 구분한다. 별도 이미지 제작은 필요 없다. 보드와 상세 기록에서 회수 위치·누적/남은 목표·보드 잔여 부품·유지 공급 부족분·고정 목록 진행을 확인할 수 있게 한다. 단순 미션 완료를 승리 화면으로 표시하지 않는다.

최근의 편집 연결·드래그 경로·합류 순서로 만든 레벨을 사본 실행하고, 편집 복귀 후 정의가 그대로인지 확인한다. 1000/680폭, 스크롤, 단계 실행/연쇄 끝까지, 같은 시드 재시작, 레벨 전환, 창 종료를 검사한다. 화면 표시가 실행 순서나 난수를 바꾸지 않아야 한다.

## 작업 순서와 검증

| 작업 | 선행 | 작업 및 검증 산출물 |
|---|---|---|
| T1 기준과 계약 확인 | 20단계·후속 편집 완료 | 현재 상태 감사, 미지원 호출부 목록, 규칙/처리 시점/불변 조건, 보존 기준 |
| T2 교환·이동·불파괴 | T1 | 조회/실행 일치, 유효/무효 교환, 자석 취소, 파워 관통, 모든 기존 이동 경로 |
| T3 도착 회수·미션 | T2 | 초기/교환/낙하 도착, 다중 회수, 빈칸 후속 정착, 사본 독립·중복 방지 |
| T4 고정·유지 공급 | T3 | 목록 소모, 부족분/목표 제한, 여러 생성구, 혼합 공급, 소진·재시작 |
| T5 드론·수동 화면 | T4 | 간접 후보·예약·재검색, 실제 Match 표시와 편집 원본 보존 |
| T6 통합 재현·감사 | T5 | 독립 Unity 재현, 영향 회귀, 조건별 증거와 소유 임시 자원 정리 |

핵심 검사는 4방향·직접 끝·합류·통로·대각선, 마지막 이동 수의 회수, 동시에 여러 도착, 여러 생성구가 부족분 1개를 보충하는 경우, 유지 3/남은 목표 1/보드 1, 목표 0, 막힌 생성구, 회수 뒤 즉시 재공급, 고철 유지와 회수 유지의 독립성이다.

같은 정의·시드·행동으로 단계 진행과 끝까지 실행, 새 Unity 프로세스의 결과를 비교한다. 보드·미션·회수 이력·공급 커서·난수·턴 이력·드론 예약이 같아야 한다. 컴파일과 영향받는 초기 구성/교환/파워10조합/정착/장애물/발전기 검사를 수행한다. 지원 확대 때문에 기존 미지원 실패 검사를 삭제하지 말고 다른 실제 미지원 입력으로 실패 경계 검증을 유지한다.

## 제외 범위와 완료 기록

승패·자동 섞기·라스트팡은 22단계, 망치/자리 바꾸기/부스터 입력은 23단계다. 봇·통계·난이도 추천·랜덤 레벨 생성·장애물 해금 레벨·상점/광고/결제·출시 아트·서버/앱 복구 구현은 제외한다.

완료 시 목표 문서의 조건별 증거, 실제 검사 수, 수정 실패, 알고리즘 버전, 변경 파일 책임, 원본/무관 변경 보존, 남은 한계를 기록한다. 검증하지 못한 항목은 완료로 표시하지 않으며 다음 단계는 자동 실행하지 않는다.
