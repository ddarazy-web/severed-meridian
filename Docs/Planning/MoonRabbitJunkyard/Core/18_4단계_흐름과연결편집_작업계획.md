## 목표와 완료 모습

제작자가 **Match → 레벨 에디터**에서 흐름 방향과 경로, 칸 사이의 벽, 통로 입·출구, 회수 도착 바닥, 발전기 전선을 직접 편집하고 잘못된 연결 위치를 확인할 수 있게 한다. 편집·구조 검사·Undo/Redo·저장·재시작 보존까지가 이번 단계다.

예를 들어 보드 일부를 오른쪽 중력으로 칠하고 직접 경로를 합류시킨 뒤, 유입 순서를 정하고 다른 위치로 이어지는 통로를 놓을 수 있다. 발전기를 선택해 장애물과 연결하고 칸 사이로 전선을 그릴 수 있다. 이 상태를 저장한 뒤 다시 열어도 같은 설정이 유지되어야 한다.

## 현재 프로젝트에서 확인한 사항

- Unity 버전은 `6000.3.10f1`이다. 기존 창은 UI Toolkit을 사용한다.
- `LevelDefinition` 저장 버전은 2다. 일반/파워 블록·장애물·덮개·먼지 목록과 10×10 보드를 보유한다.
- `BoardDefinition`은 크기·활성 칸을 관리하며 중력·경로·통로·벽 데이터는 아직 없다.
- `ObstaclePlacementDefinition`에는 종류·기준 좌표·내구도·색·필요 충전량이 있다. 연결을 유지할 개체 식별자는 아직 없다.
- `LevelSchemaUpgrade`는 현재 버전 1→2 전환만 다룬다. 버전 상수만 올리면 기존 전환 코드가 신규 형식을 건너뛸 수 있으므로 전환 절차도 함께 수정해야 한다.
- `LevelEditorWindow`, `LevelBoardView`, `LevelEditorToolPanel`, `LevelEditorPlacementPanel`이 창·보드·메뉴·속성을 나눈다. 기존 직렬화/Undo 편집, 비파괴 검사, 실제 Editor 검증 코드를 재사용한다.
- 왼쪽 카테고리 드롭다운과 실제 배치에서 계산하는 현재 사용 목록을 유지한다. 새 기능 때문에 종류별 버튼을 다시 길게 나열하지 않는다.

## 데이터와 책임 제안

원본 설정은 레벨 에셋 하나가 소유한다. 편집 도구는 원본을 명시적으로 변경하고, 조회·검사는 원본을 수정하지 않는다. 시각화용 그래프·사용 목록은 원본에서 계산하며 저장하지 않는다.

| 영역 | 저장 내용과 책임 |
| --- | --- |
| 중력 설정 | 칸별 방향 예외 목록. 기록이 없으면 아래 방향. 구역 칠하기는 여러 칸에 같은 값을 적용 |
| 직접 경로 | 출발 칸과 다음 칸 또는 명시적 끝 칸. 한 출발 칸에 하나의 기록만 허용 |
| 합류 설정 | 목적 칸별 유입 출발 칸의 순서. 통로 유입도 같은 목록에 포함 |
| 고철 벽 | 상하좌우로 인접한 두 칸의 공통 경계. 순서를 바꿔도 같은 경계로 판정 |
| 통로 | 입구와 선택적인 출구를 가진 한 쌍. 미연결 상태도 저장·오류 표시 가능 |
| 도착 바닥 | 회수 도착 칸 목록. 이번 단계에는 부품 종류·미션 수량 필드를 만들지 않음 |
| 장애물 식별자 | 레벨 안에서 고유한 안정적 ID. 연결 시 배열 인덱스나 위치를 식별자로 사용하지 않음 |
| 발전기 연결 | 발전기 ID·대상 ID·양 끝 단자·순서 있는 전선 경로. 본체 이동 후에도 연결 대상 유지 |

- 장애물 ID는 새 장애물 배치/명시적 구버전 전환 시 생성하고 이동·속성 수정·목록 순서 변경·저장에서는 유지한다. 중복/누락 ID는 자동 수리하지 않고 검사한다. 기존 오류 배치도 삭제하지 않는다.
- 두 칸의 경계와 전선 경로는 보드 좌표에서 계산한다. 화면 픽셀 좌표를 저장하지 않는다.
- 전선 경로 제안: 칸 모서리의 격자 꼭짓점과 인접 꼭짓점을 잇는 선분, 외곽 경계의 단자를 사용한다. 양 끝만 본체 외곽으로 진입한다. 2×2 내부를 통과하지 않는다.
- 전선끼리 선분을 공유하거나 꼭짓점에서 만나 교차하지 않도록 검사한다. 같은 발전기의 여러 전선도 별도 단자를 사용한다. 이 보수적인 기준과 외곽 보드 선 사용 허용은 편집 구현 제안이다.
- 저장된 잘못된 값은 원본 Inspector에서 확인할 수 있게 한다. 검사 중 좌표 보정·중복 제거·ID 재생성을 하지 않는다.

## 중력·경로·합류 편집

1. 바닥 카테고리에서 상·하·좌·우 중력을 선택해 클릭/드래그로 칠한다. 사각 구역 지정도 지원하되 중력 도구 안의 입력으로 제한한다. 지우면 기본 아래 방향으로 돌아간다.
2. 직접 경로 도구는 시작 칸을 고르고 상하좌우 인접 칸을 순서대로 클릭해 미리보기를 만든다. 완료 버튼 또는 Enter로 확정하고 마지막 칸을 명시적 끝 칸으로 기록한다. Esc는 미완료 입력만 취소한다.
3. 마지막 칸을 기존 경로에 합류시키면 기존 이후 경로를 유지한다. 기존 경로를 다른 방향으로 덮어쓰지 않고 명시적 수정·삭제 후 다시 연결한다. 새 연결의 출발 칸에 두 갈래가 생기는 입력은 거절한다.
4. 경로 삭제는 선택한 출발 칸의 명시 설정을 제거해 그 칸의 중력으로 복귀시킨다. 다른 출발 칸의 연결을 몰래 삭제하지 않는다. 필요한 후속 오류를 표시한다.
5. 합류 칸의 오른쪽 속성에서 유입 후보를 좌표·통로 여부로 보여주고 위/아래 버튼으로 우선순위를 정한다. 후보는 한 번씩 모두 포함해야 한다. 후보가 달라지면 기존 순서를 임의 확정하지 않고 재설정 필요를 표시한다.
6. 흐름 해석 순서는 **통로 입구 → 명시적 경로/끝 칸 → 해당 칸의 중력**이다. 통로 입구와 명시적 경로 설정의 신규 중첩은 금지하고 기존 중첩 오류는 보존한다. 통로 출구에는 이후 중력 또는 직접 경로를 지정할 수 있다.
7. 기본 중력이 보드 끝·비활성 칸·벽에서 막히면 종점으로 본다. 이를 잘못된 명시적 연결과 구분한다. 명시적 경로가 비활성 칸·보드 밖·벽을 통과하면 오류다.

순환 검사에는 기본/구역 중력의 직선 연결·직접 경로·통로 연결을 합쳐 사용한다. 일시적으로 놓인 블록·제거 가능한 장애물은 연결을 지우는 근거로 쓰지 않는다. 도착 바닥도 일반 블록은 통과하므로 무조건 종점으로 취급하지 않는다. 자동 대각선 이동은 점유 상태에 따른 보조 이동으로, 이번의 정적 합류 순서에 섞지 않는다. 이 검사만으로 실제 낙하의 완전한 종료나 플레이 가능성을 보장한다고 표시하지 않는다.

## 벽·통로·도착 바닥 편집

- 고철 벽은 지형 카테고리에서 선택하고 칸 경계를 클릭/드래그한다. 보드 내부의 유효한 인접 경계를 대상으로 하고 한 경계는 한 번만 저장한다. 2×2 본체 내부 경계는 거절하고 외곽은 허용한다.
- 벽과 이미 있는 명시적 경로/전선이 충돌하는 신규 입력은 거절한다. 외부 수정으로 발생한 충돌은 원본을 유지하고 두 위치를 알려준다. 기존 2×2 배치·이동도 내부 벽을 함께 검사한다.
- 통로는 입구를 놓고 출구를 지정하는 두 단계로 편집한다. 입구만 둔 상태도 작업 중 저장할 수 있다. 같은 칸이 여러 쌍 또는 입구/출구를 겸할 수 없고 자기 자신으로 연결할 수 없다.
- 입구·출구는 같은 색과 문양/번호로 표시한다. 출구 이동·삭제는 선택한 쌍을 명시적으로 수정한다. 출구만 삭제하면 입구와 미완성 기록을 남기고, 쌍 삭제는 양 끝을 한 번에 삭제한다.
- 통로 바닥 위의 고정 장애물·먼지는 허용한다. 블록 점유와 바닥 기능을 혼동하지 않는다.
- 도착 바닥은 활성 칸에 배치하고 통로 양 끝과 중첩할 수 없다. 먼지·중력은 보존한다. 생성구와의 충돌 검사는 생성구가 도입되는 5단계에 추가한다.
- 칸 비활성화는 기존 바닥·벽·연결을 자동 삭제하지 않는다. 활성/참조 오류로 표시하고 다시 활성화했을 때 원래 설정을 유지한다.

## 발전기 연결과 전선 편집

1. 발전기 본체 또는 현재 사용 목록에서 발전기를 선택한 뒤 연결 대상 추가를 누른다.
2. 나무상자·잠긴 고물 금고·색깔 자물쇠·대형 폐가전 중 하나를 선택한다. 발전기당 1~3개, 대상당 발전기 하나 규칙을 적용한다. 고철 뭉치·덮개·먼지·발전기는 대상이 아니다.
3. 출발/도착 본체 외곽 단자와 칸 사이 경로를 순서대로 지정한다. 경로 미완료는 연결 설정 오류로 남기고 저장을 허용한다. 자동 우회는 하지 않는다.
4. 전선은 항상 옅게 표시하고 선택한 연결은 강조한다. 벽은 두꺼운 각진 선, 전선은 가는 선과 단자로 구분한다. 색 외에도 단자 문양/번호를 제공한다.
5. 발전기 또는 대상 이동은 ID 연결을 유지한다. 기존 전선 좌표도 임의 재작성하지 않고 새 단자와 맞지 않는 경로를 재지정 필요로 표시한다.
6. 발전기 삭제는 연결·전선을 함께 삭제하고 대상은 유지한다. 대상 삭제는 해당 연결·전선만 삭제한다. 한 번의 Undo로 본체와 연결을 모두 복원한다.
7. 연결 대상이 0개인 발전기는 에디터 오류로 남긴다. 게임에서의 자동 철거를 에디터 삭제 동작으로 적용하지 않는다.

## 메뉴·선택·표시와 취소

- 최상위 메뉴는 계속 `Match`다. 왼쪽은 기존 카테고리 드롭다운을 확장하고 지형 카테고리를 필요한 만큼 추가한다. 바닥에는 중력·경로·통로·도착 기능, 장치 속성에는 발전기 연결 편집을 둔다.
- 현재 사용 중인 장애물 목록의 기존 기능을 유지한다. 흐름/통로/전선은 별도 연결 목록으로 구분해 양 끝과 오류 여부를 표시하며 클릭 시 보드와 오른쪽 속성으로 이동한다. 목록은 원본에서 계산한다.
- 활성 도구에 따라 칸/경계/단자 입력 대상을 명확히 표시한다. 전선·벽을 클릭하려다 블록을 칠하는 일이 없어야 한다.
- 중력 화살표·경로·통로·전선은 기본 표시를 유지한다. 흐름과 발전기 연결을 번갈아 주기적으로 강조한다. 주기 수치는 UI 상수로 시작하고 별도 설정 화면을 만들지 않는다.
- 입력 미리보기는 에셋을 변경하지 않는다. 완료된 칠하기·연결·이동·삭제·우선순위 변경은 각각 Undo 한 단위다. 무변경 조작은 기록하지 않는다.
- Esc, 포커스/캡처 상실, 도구·층·레벨 전환, 외부 변경, Undo/Redo, 저장·검사, 창 닫기에서 미완료 입력만 취소한다. 통로/전선의 이미 확정한 미완성 기록은 유지한다.
- 넓고 좁은 창에서 편집·목록·오류·취소·저장에 접근 가능해야 한다. 주기적 강조는 창이 닫히면 중단하고 이벤트를 해제한다.

## 저장 형식과 호환성 제안

- 저장 버전을 3으로 올리는 안이다. 버전 1·2는 읽기·검사·보기만으로 바뀌지 않는다. 현재 에셋의 명시적 전환 후 새 편집을 허용한다.
- 버전 1은 기존 1→2 보존 절차와 새 2→3 절차를 순서대로 수행한다. UI에서는 한 번의 전환/Undo로 처리한다. 버전 2는 신규 설정을 비어 있는 상태로 추가하고 기존 장애물에 ID를 부여한다.
- 기존 필드·오류 값·좌표·순서·GUID를 보존하고 새 흐름의 기본값은 아래다. 기존 발전기는 연결 없음 오류가 새로 드러나지만 자동 연결하지 않는다.
- 구버전에 예상 밖 신규 데이터가 있거나 미지원 미래 버전이면 자동 정리·강제 전환하지 않는다. 오류 이유와 원본 확인 방법을 제공한다.
- 불완전하거나 오류가 있는 작업 상태도 저장한다. 저장 성공을 플레이 가능 판정으로 표시하지 않는다.

## 예상 코드 구성과 의존 방향

모든 스크립트는 `Assets/Scripts` 아래 기존 기능별 위치를 사용한다. 아래 파일명은 책임을 설명하는 제안이며 실제 구현 중 중복 없이 조정할 수 있다.

| 위치/타입 | 책임 |
| --- | --- |
| `Board/BoardEdge` 등 최소 좌표 값 타입 | 경계/격자 위치 비교와 유효성 |
| `Levels/LevelFlowDefinition`, `LevelConnectionDefinition` | 중력·경로·합류·벽·통로·도착·발전기 연결의 직렬화 기록 |
| `Levels/LevelFlowRules`, `LevelConnectionRules` | 유효 흐름 조회·순환/참조/경로 검사. Editor API 미참조 |
| 기존 `LevelDefinition`, `ObstaclePlacementDefinition` | 신규 설정과 안정적 ID 보유 |
| 기존 `LevelDefinitionValidator`, `LevelValidationIssue` | 기존 오류와 신규 구조 오류 통합, 칸/경계/연결로 이동할 최소 식별 정보 |
| `Editor/Levels/LevelFlowEditing`, `LevelConnectionEditing` | 입력 확정·Undo·원자적 수정·관련 연결 정리 |

흐름은 `Editor 입력 → 편집 적용 → 레벨 원본 → 공통 규칙 조회/검사 → UI 표시`다. 발전기 연결 수명 관리와 낙하 그래프 검사는 서로 다른 책임으로 나누되 범용 그래프 프레임워크나 단일 구현용 인터페이스는 만들지 않는다. 씬·런타임 UI·플랫폼 설정·패키지는 변경하지 않는다.

## 승인 후 진행 순서와 검증

이 순서는 실행 제안이다. 실제 Task DAG와 파일별 작업 배분은 Goal 승인 후 현재 코드를 재확인하여 목표 문서 실행 기록에 확정한다. 공유 모델과 편집 창을 함께 수정하므로 순차 진행하며 에이전트 분배는 기본으로 하지 않는다.

1. **모델·호환성**: 변경 전 버전 1·2 정상/오류 에셋을 확보하고 전환·ID·기본값·Undo 보존을 확인한다.
2. **중력·벽·경로**: 칠하기·경계 입력·경로 끝·합류·순환 검사를 구현하고 보드 표시와 일치하는지 확인한다.
3. **통로·도착 바닥**: 미완성 쌍·중첩·통로 포함 순환·합류 검사를 통합한다.
4. **발전기 연결**: 대상 수·종류·고유 연결·전선 기하·벽 충돌·이동/삭제/Undo를 확인한다.
5. **UI 통합·재시작·회귀**: 메뉴·목록·오류 이동·주기 강조·실제 입력 취소·좁은 창·저장 보존과 기존 1~3단계 기능을 검증한다.

### 반드시 포함할 검증 사례

- 기본 아래, 네 방향 구역, 꺾이는 경로, 위로 흐르는 경로, 명시적 끝, 경로 합류와 중력/통로 혼합 합류.
- 서로 마주 보는 중력, 세 구역 순환, 경로와 통로가 만드는 순환. 장애물로 잠시 막힌 순환도 놓치지 않음.
- 잘못된 합류 순서의 누락·중복·후보 변경, 경로 분기·비인접 연결·비활성·범위 밖·벽 통과.
- 2×2 내부 벽 거절·외곽 허용, 기존 벽 위로 본체 이동 거절, 먼지·덮개·기존 배치 보존.
- 통로 미연결·자기 연결·역할 중복·도착 바닥 중첩·여러 쌍, 출구 뒤 중력 및 경로.
- 발전기 0/1/3/4개 대상, 금지 대상, 중복/누락 ID, 동일 대상 복수 발전기, 배열 재정렬에도 대상 유지.
- 전선 벽 충돌·선분 중첩·교차·본체 내부 침범·단자 불일치·미완성, 본체 이동 후 연결 유지 및 재지정 안내.
- 발전기/대상 삭제와 Undo/Redo, 외부 Inspector 변경, 목록 갱신, 오래된 선택의 오작동 방지.
- 버전 1/2 읽기 비파괴·전환·Undo/Redo·오류 데이터 보존, 모든 새 필드의 저장/별도 재시작 JSON·GUID 비교.
- 실제 UI에서 드롭다운·칸/경계/단자 입력·취소·오류 위치 선택·넓은/좁은 창, Editor 종료 후 이벤트 정리.

## 위험과 제한

- 정적 흐름 검사와 실제 낙하를 혼동하기 쉽다. 대각선 이동·동적 점유·생성구 공급은 아직 미지원이라고 표시한다.
- 전선과 벽은 같은 틈을 사용한다. 입력 모드를 구분하고 충돌을 검사하며 색만으로 구분하지 않는다.
- 안정적 ID 도입은 저장 호환성에 영향을 준다. 읽기 중 자동 생성하지 않고 명시적 전환·신규 배치에만 한정한다.
- 본체 이동 후 자동 전선 재작성은 의도하지 않은 경로를 만들 수 있다. 연결은 보존하고 경로 재지정을 요구한다.
- 임시 검증 에셋은 소유 경로를 확인해 정리한다. 수행하지 못한 검증은 완료로 기록하지 않는다.

승인된 4단계 구현과 검증을 완료했다. 실제 결과와 재현 명령은 [목표 문서](../../../Goals/MoonRabbitJunkyard/Core/19_4단계_개발목표.md)에 기록했다. 5단계와 게임 실행 로직은 시작하지 않았다.
