## 목표와 단계 선정 이유

여러 상자의 내구도를 한 번에 바꾸고, 같은 종류의 블록에 설정값을 복사하며, 기존 레벨을 독립 에셋으로 복제해 다음 레벨을 제작할 수 있게 한다. 원본·연결·공급 목록을 보존하고 변경을 예측할 수 있는 편집 동선을 완성한다.

[최초 개발 계획](12_1단계_레벨데이터기반_작업계획.md)은 6~7단계를 공통 편집·복제·연결 수정·통합 검수로 구분했다. 연결 수정과 여러 Undo 검사는 4~5단계에서 이미 구현했다. 따라서 6단계는 **남은 공통 편집과 레벨 복제**, 이후 단계는 전체 제작 동선의 잔여 검수로 이어가는 것을 추천한다. 공통 게임 실행부와 수동 테스트 플레이, 봇/분석은 그 뒤의 별도 범위다. 이미 완료한 기능을 다시 만드는 단계로 삼지 않는다.

## 현재 코드에서 확인한 사실

- `LevelDefinition`은 v4이며 공급·회수·미션까지 저장한다. 이번 기능은 편집 상태와 에셋 작업이므로 저장 형식 변경이 필요하지 않다.
- `LevelEditorWindow`/`LevelEditorPlacementPanel`의 일반 선택 속성은 한 칸/한 본체 중심이다. 생성구만 `LevelEditorSupplyPanel`에서 Ctrl/Cmd 다중 선택과 공통 속성 편집을 지원한다.
- `LevelAssetOperations`에는 생성·레벨 번호 중복 검사가 있다. 에디터 안에서 현재 레벨을 복제하는 전용 동선은 없다.
- `LevelObstacleEditing.Commit`과 `SerializedObject`를 통한 Undo, 변경 전 원본 스냅샷 확인, 공급 붙여넣기 사전 검사 패턴이 있다. 이를 재사용한다.
- 장애물 ID와 발전기 연결 조회는 같은 `LevelDefinition` 안에서 이루어진다. 전체 레벨 복제 시 내부 ID/연결을 그대로 복사해도 원본 레벨을 참조하지 않는다. Unity 에셋 GUID는 별개다.
- 기존 배치/흐름/목록 탭, 선택 속성/레벨 설정 탭, 한 줄 제목·드롭다운과 USS 스타일을 유지한다.

## 다중 선택과 공통 속성

### 선택 동작

- 기존 **선택** 도구에서 일반 클릭은 단일 선택, Ctrl/Cmd+클릭은 추가/해제한다. 현재 편집 층 안에서만 선택한다. 다른 종류가 섞인 선택은 설정 붙여넣기의 대상 필터링을 위해 허용한다.
- 같은 종류는 `편집 층 + 종류`로 판정한다. 고정 색 일반 블록끼리는 색이 달라도 같은 종류다. 무작위 일반 블록과 고정 색 일반 블록은 구분하여 암묵적으로 종류를 바꾸지 않는다.
- 2×2 본체 어느 칸을 눌러도 본체 하나로 선택한다. 네 칸을 중복 집계하지 않으며 본체 전체를 강조한다.
- 단일 선택을 전제로 하는 이동·연결 수정·삭제 버튼은 다중 선택 중 실행하지 않는다. 선택 개수와 제한 이유를 간결하게 표시한다. 기존 단일 선택 기능은 유지한다.
- 층·레벨·주요 도구를 바꾸면 이전 선택을 정리한다. Undo/Redo·외부 수정 뒤에는 현재 존재하는 대상만 다시 확인한다. 배열 인덱스를 다른 객체에 그대로 재사용하지 않는다.
- 오래된 화면에서 수정하면 최신 원본과 선택을 확인하여 작업을 거절하고 다시 선택하도록 안내한다. 중복 좌표/ID 등 대상을 유일하게 식별할 수 없는 데이터는 임의로 선택하지 않는다.

### 편집 가능한 값

| 대상 | 공통 편집/설정 복사 값 |
| --- | --- |
| 고정 색 일반 블록 | 레벨에서 사용하는 색 |
| 청소로켓 | 제거 방향 |
| 나무상자·고철·금고·폐가전 | 해당 종류의 내구도 |
| 색깔 자물쇠 | 내구도, 색 |
| 발전기 | 필요 충전량. 연결 대상/전선 제외 |
| 거미줄·곰팡이 | 기존 규칙 범위의 내구도. 곰팡이는 현재 고정값 1 유지 |
| 먼지 | 내구도 |
| 무작위 일반 블록·달폭탄·드론·자석·회수 부품 | 복사할 가변 속성이 없다고 표시. 의미 없는 필드를 추가하지 않음 |
| 생성구 | 5단계의 공급 방식/소진 정책 공통 편집과 공급 목록 복사를 그대로 사용 |

- 같은 값은 실제 값을 표시하고 서로 다르면 `—`/Unity 혼합 값 표시를 사용한다. 혼합 상태를 0이나 첫 대상의 값으로 자동 확정하지 않는다.
- 한 필드를 수정하면 그 필드만 모든 선택 대상에 적용한다. 예: 자물쇠 내구도를 바꿔도 각 자물쇠의 색·ID·위치·연결은 그대로다.
- 다른 종류가 섞였으면 종류별 선택 수를 간단히 표시하고 공통 속성 입력은 하지 않는다. 설정 붙여넣기는 아래 규칙으로 사용할 수 있다.
- 값 범위·사용 색 등은 기존 규칙 조회를 재사용한다. 하나의 논리적 편집을 한 번의 Undo/Redo로 처리하고 변경 없는 입력은 불필요한 변경 기록을 만들지 않는다.

## 설정값 복사·붙여넣기

- 한 요소를 선택했을 때 **설정 복사**, 선택 대상이 있을 때 **설정 붙여넣기**를 제공한다. 기존 공급 목록 복사 버튼과 구분한다. 새 단축키나 별도 관리 창은 만들지 않는다.
- 클립보드는 종류와 버전을 가진 값 데이터다. 종류별 위 표의 속성만 담는다. 좌표·배치 종류 변경·ID·전선·배열 인덱스·다른 층·레벨 번호를 복사하지 않는다.
- 다른 레벨에도 붙여넣을 수 있으나 대상 레벨의 사용 색/범위를 다시 검사한다. 원본을 수정해도 클립보드나 이미 붙여넣은 값이 변하지 않는다.
- 일반 설정 복사는 [기존 기획](../../../Contents/MoonRabbitJunkyard/09_레벨에디터.md)에 따라 **같은 종류 대상에만 적용하고 다른 종류는 건너뛴다**. 적용/제외/변경 없음 개수를 표시한다. 예: 상자 설정을 상자 3개+금고 1개에 붙이면 상자 3개에 적용하고 금고 1개는 제외한다.
- 같은 종류로 판정된 대상 중 잘못된 값·중복 배치·오래된 선택 등 적용 불가가 있으면 해당 일괄 변경 전체를 거절한다. 서로 다른 종류를 건너뛰는 것과 유효한 대상들 중 일부만 실패하는 것을 구분한다.
- 생성구 공급 목록은 **5단계의 전체 대상 사전 검사·하나라도 부적합하면 전체 거절**을 유지한다. 일반 설정 복사 정책을 공급 목록에 덮어쓰지 않는다.
- 잘못된 JSON/종류/버전/값, 적용 대상 0개는 원본을 변경하지 않고 이유를 표시한다. 미지원 값을 조용히 보정하거나 다른 종류로 변환하지 않는다.

## 독립 레벨 복제

- 기존 상단 새 레벨/저장과 가까운 위치에 **레벨 복제**를 둔다. 좁은 창에서는 기본 드롭다운/메뉴 배치로 정리하여 보드·속성을 밀어내지 않는다. 최상위 메뉴 이름은 Match를 유지한다.
- 복제 대상은 현재 선택한 에셋의 **메모리상 편집 상태**다. 미저장 변경을 원본에 강제 저장하지 않는다. 디스크 파일만 복사해 현재 변경을 잃지 않는다.
- Unity 기본 저장 경로 UI와 작은 번호 입력 동선을 사용한다. Assets 내부 새 `.asset` 경로와 양수 레벨 번호를 지정한다. 현재 번호 다음부터 사용하지 않는 번호를 제안하되 사용자가 변경할 수 있다. 번호 계산 범위를 넘으면 명시적 입력을 요구한다.
- 최종 생성 직전에 경로/중복 번호를 다시 검사하고 기존 에셋을 덮어쓰지 않는다. 취소·실패하면 원본의 JSON·GUID·dirty 상태와 기존 대상 파일을 보존하고 이번 작업이 만든 미완성 사본만 정리한다.
- 복제본은 새 Unity GUID를 갖는다. 새 레벨 번호 이외에 초기 배치·공급 목록·순서·공통 한도·회수·미션·흐름·연결·내부 ID와 오류 값은 그대로 복사한다. 목록을 원본과 공유하지 않는다.
- 장애물 ID는 레벨 내부 식별자이므로 **전체 레벨 복제에서는 유지**한다. 다른 레벨의 객체와 연결되지 않음을 검증한다. 향후 부분 배치 복제는 새 ID 재매핑이 필요한 별도 기능이다.
- 구버전/미래 버전/미완성/오류 데이터도 알려진 필드를 자동 전환·정규화하지 않고 복제한다. 현재 코드로 손실 없이 복제할 수 없는 형식이면 거절하고 이유를 알린다. 구버전은 복제 후에도 기존 읽기 전용·명시적 전환 규칙을 따른다.
- 성공하면 복제본을 열고 새 경로/번호를 표시한다. 원본의 미저장 상태는 보존한다. 전환 전 미완료 포인터 입력은 취소한다.
- 에셋 파일 생성은 일반 속성 Undo와 구분한다. 이번 제안에서는 파일 생성 취소용 독자 Undo 시스템을 만들지 않는다. 복제본 삭제는 Unity Project 창의 기본 에셋 작업을 사용하며, 에디터의 Undo는 편집 값 변경을 대상으로 함을 안내한다.

| `LevelAssetOperations`와 상단 UI | 메모리 복제, 경로/번호 검사, 독립 에셋 생성과 취소/실패 정리 |
| 기존 검증 코드와 필요한 소규모 추가 검증 | 다중 편집·복제·보존·실제 UI/재시작 |

파일명은 구현 시 기존 책임/크기에 맞춰 정한다. 직렬화 모델·enum·저장 버전은 v4 그대로 유지한다. 범용 선택 프레임워크, 명령 버스, 새 asmdef는 도입하지 않는다. 생성구 구현을 재사용할 수 있어도 일반 설정 복사와 공급 목록의 서로 다른 적용 정책은 명시적으로 구분한다.

## 권장 진행 순서와 검증

1. 기존 선택/Undo/복제 관련 코드와 원본 기준을 확인하고 종류별 속성 목록을 고정한다. 실제 없는 기능만 추가한다.
2. 층별 다중 선택과 2×2 단일 본체 선택, 같은 종류 공통 속성을 연결한다. 두 자물쇠의 색을 유지하면서 내구도만 바꾸는 사례로 검증한다.
3. 설정 클립보드를 연결한다. 혼합 종류 제외, 유효 대상 일괄 거절, 사용 색 불일치, 원본 독립과 한 번 Undo를 검증한다.
4. 현재 메모리 상태의 레벨 복제를 구현한다. 미저장 정상/오류/구버전 데이터, 새 GUID, 원본 dirty 보존, 중복 번호/경로·취소를 확인한다.
5. 실제 넓은/좁은 Editor에서 기존 단일 선택·생성구·연결 도구와 함께 조작한다. 저장 후 별도 프로세스에서 원본·사본 전체 필드와 GUID를 비교하고 관련 회귀를 실행한다.

실행 요청 후 이 순서를 구체적인 작업 의존성·수정 파일·완료 증거로 목표 문서에 확정한다. 공유 선택/창을 변경하므로 기본은 순차 작업이다. 승인 전 구현이나 에이전트 분배를 시작하지 않는다.

## 위험과 완료 증거

- 선택 배열 인덱스가 이동해 다른 대상이 변경됨 → 원본 스냅샷/유일한 대상 확인, 삭제·Undo·에셋 전환 직후 재현 검사.
- 다중 편집이 무관한 색·위치·ID까지 복사함 → 변경 전후 전체 데이터 비교와 허용 필드만 변경됐는지 확인.
- 2×2가 네 번 집계됨 → 네 점유 칸으로 선택/해제하고 본체 수·적용 수·Undo를 검증.
- 일반 설정 복사의 제외 정책이 공급 복사의 원자성을 깨뜨림 → 두 종류의 혼합 대상 테스트를 별도로 유지.
- 에셋 복제가 미저장 값·연결을 잃거나 원본까지 저장함 → 원본 JSON/GUID/dirty, 사본 전체 값·연결의 내부 조회, 별도 재시작 비교.
- 기존 다중 선택/단일 이동/전선 조작이 깨짐 → 기존 3~5단계 검증을 영향 범위에 맞게 실행하고 미실행 항목은 통과로 기록하지 않음.

결과에는 실제 변경 파일·사용법·최종 로그·화면·전후 보존 비교·재시작 증거를 기록한다. 테스트 개수 자체를 목표로 하지 않는다. 완료는 편집 생산성과 데이터 보존 범위이며 게임 실행 가능 판정이 아니다.
