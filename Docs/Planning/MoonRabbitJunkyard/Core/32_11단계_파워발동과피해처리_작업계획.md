## 목표와 현재 상태

현재 실행 시험은 일반 블록 교환, 첫 매칭 선택·제거·파워 생성, 이동 수 차감까지 처리하고 낙하 대기에서 멈춘다. 파워 발동과 장애물 피해는 실행하지 않는다.

이번 단계에서는 청소로켓·달폭탄의 단독 발동, 두 종류 사이의 피격 연쇄, 나무상자 피해를 독립 실행 상태에 적용한다. 기존 Match 확인 화면에서 범위·피해·보호·거절 이유를 확인할 수 있게 한다. 효과 처리가 끝나면 여전히 낙하 대기에서 멈춘다. 전체 턴이나 연속 플레이를 완성하는 단계는 아니다.

## 범위 선택

| 대안 | 장점 | 한계 | 판단 |
|---|---|---|---|
| 파워 범위와 일반 블록 제거만 구현 | 가장 작다 | 내구도와 턴별 피해 제한을 검증할 수 없다 | 제외 |
| 모든 파워·조합·장애물을 함께 구현 | 지원 범위가 넓다 | 드론 목표 선정, 덮개, 충전 등의 복잡성이 한 번에 결합된다 | 후속 단계로 분리 |
| 청소로켓·달폭탄 + 나무상자 + 공통 피해 처리 | 실제 내구도와 연쇄를 검증하면서 범위를 제한한다 | 다른 효과는 명확히 미지원 처리해야 한다 | 채택 |

## 포함 범위

1. 기존 일반↔일반 교환과 모든 매칭 파워 생성 동작 보존.
2. 노출된 청소로켓 또는 달폭탄의 제자리 발동과 일반 블록과의 교환 발동.
3. 청소로켓의 한 줄 제거, 달폭탄의 중심 포함 3×3 제거.
4. 기존 청소로켓·달폭탄이 피격되면 낙하 전에 즉시 단독 효과로 연쇄 발동.
5. 매칭으로 이번 턴에 생성된 파워의 피격 제거·발동 방지.
6. 나무상자 내구도 1~6, 인접 일반 매칭 피해, 직접 파워 피해, 턴당 최대 1 피해와 파괴.
7. 읽기 전용 반응 판단과 실제 적용의 규칙 공유, 결과 기록, 기존 실행 시험 화면 연결.

## 지원 경계

| 항목 | 이번 실행 지원 |
|---|---|
| 일반 블록, 빈칸, 비활성 칸 | 지원 |
| 노출 청소로켓·달폭탄 | 단독 발동과 피격 연쇄 지원 |
| 수거드론·무지개 자석 | 기존 배치와 매칭 생성 보존. 발동·피격 연쇄는 미지원 |
| 나무상자 | 고정 단일 칸, 내구도 1~6 지원 |
| 거미줄·곰팡이·먼지·회수 부품·그 밖의 장애물 | 해당 요소가 있는 보드는 실행 전 미지원으로 거절 |
| 파워끼리 직접 교환 | 모든 조합 미지원. 기본 효과 둘로 대체하지 않음 |
| 벽·흐름·통로·생성구 | 기존 데이터 보존. 파워는 좌표 범위에 적용하며 이동·공급은 실행하지 않음 |

기존 드론·자석이 효과 범위에 들어와 발동이 필요해지면 작업 사본 전체를 폐기하고 행동을 거절한다. 일부 피해나 이동 수 차감만 남겨서는 안 된다. 다만 이번 매칭으로 생성되어 보호 중인 파워는 보호 판단을 먼저 하므로 종류와 관계없이 피격을 무시한다. 범위 밖의 기존 파워는 그대로 보존한다.

## 확정 규칙

- 청소로켓은 방향을 유지하며 행 또는 열의 끝까지 관통한다. 중간 장애물·벽·비활성 칸에 막히지 않는다. 비활성 칸 자체에는 피해를 적용하지 않는다.
- 달폭탄은 중심 포함 3×3에 적용한다. 보드 밖과 비활성 칸은 제외하며 벽은 폭발을 막지 않는다.
- 기존 파워는 피격 시 낙하 전에 즉시 연쇄 발동하며 각각 한 번만 발동하고 소모된다. 영역 피해로 파워 여러 개를 맞혀도 조합 효과가 되지 않는다.
- 이번 턴의 매칭으로 생성된 파워는 그 턴에 피격 제거·발동되지 않는다. 다음 턴 보호 해제 및 실제 낙하는 후속 구현 범위다.
- 나무상자는 고정이며 인접 일반 블록의 매칭 또는 직접 파워 피해로 내구도가 1 줄어든다. 같은 턴에는 여러 번 맞아도 총 1만 줄어든다.
- 파워가 주변 일반 블록을 제거했다는 이유로 상자에 인접 매칭 피해를 주지 않는다. 벽은 인접 매칭 피해를 차단한다.
- 효과와 기존 파워 연쇄를 모두 처리한 뒤에만 낙하 단계로 넘어갈 수 있다.

## 이번 계획의 구현 정책 제안

아래는 확정 규칙을 코드에 연결하기 위한 제안이다. 이 계획을 지정한 Goal 실행 요청은 아래 정책을 포함하며, 기존 기획과의 충돌이 발견되면 근거를 기록하고 해결한 뒤 구현한다.

1. **교환 발동 위치:** 교환 후 실제 파워가 도착한 칸을 발동 중심으로 사용한다. 선택 순서가 일반→파워여도 동일하다.
2. **교환 중 생긴 매칭:** 파워↔일반 교환으로 새로운 매칭도 완성되면 매칭 선택·제거·생성을 먼저 처리하고 새 파워 보호를 등록한 뒤 교환 파워를 발동한다. 기존 읽기 전용 `SwapPower` 결과의 매칭 목록이 비어 있다는 이유로 매칭을 생략하지 않는다.
3. **인접 매칭 피해:** 선택된 매칭에 속한 일반 블록의 제거 또는 파워 변환을 매칭 사건으로 취급한다. 제외된 패턴 전용 칸은 피해 원인이 아니다.
4. **연쇄 순서:** 범위 좌표를 행·열 오름차순으로 순회하며 기존 파워를 만나면 그 효과를 이어 처리한다. 이미 발동한 파워는 먼저 소모/등록해 중복과 순환을 방지한다. 명시적인 처리 스택 등으로 순서를 고정하고 무제한 재귀를 피한다.
5. **행동 단위 원자성:** 검증 후 실행 상태 사본에서 전체 효과를 완성한다. 중간 미지원이나 실패는 사본을 폐기한다. 성공 시 한 번만 반영하고 이동 수를 정확히 1 차감한다. 연쇄마다 수를 차감하지 않는다.
6. **턴별 기록:** 새 파워 보호, 이미 발동한 파워, 이미 피해를 받은 상자를 해당 행동의 처리 문맥으로 관리한다. 향후 낙하 후 자동 매칭까지 같은 턴에서 기록을 유지할 수 있도록 턴 경계를 명시하되 이번 단계에서 후속 처리는 구현하지 않는다.
7. **상자 파괴:** 내구도가 0이면 점유 칸을 비운다. 런타임 장애물 기록은 안정적인 인덱스/식별자를 유지하고, 원본 정의나 다른 장애물 인덱스를 변경하지 않는다.
8. **난수:** 범위·반응 조회와 기본 발동은 난수를 소비하지 않는다. 기존 매칭 동률 선택이 필요한 경우에만 기존 계약대로 소비한다. 늦은 거절도 난수 상태를 복원한다.

## 모델과 파일 책임

실제 파일명은 착수 시 기존 구조와 대조해 확정한다. 모든 스크립트는 `Assets/Scripts`의 구성별 폴더에 둔다.

| 위치/책임 | 역할 |
|---|---|
| `Simulation/BoardActionExecutor` | 현재 상태 검증, 작업 사본, 교환/제자리 입력, 결과 반영, 낙하 대기 |
| `Simulation/MatchResolution` | 기존 패턴 선택·생성 보존, 선택 매칭 사건과 새 파워 좌표 제공 |
| `Simulation`의 파워 효과 처리 | 로켓/폭탄 범위, 발동 순서와 중복 방지 |
| `Simulation`의 피해 반응 처리 | 원인과 대상 분류, 일반 블록 제거, 보호, 상자 반응 판단과 적용 |
| `Simulation`의 행동 결과 | 발동 위치·종류, 피해 원인, 내구도 전후, 파괴/보호/거절 사실 |
| `Editor/Levels` 기존 실행 시험 | 입력·강조·한국어 결과 표시와 초기화 |
| `Editor/Levels` 검증 코드 | 정답 예제, UI 검증, 재현과 회귀 |

피해 원인은 일반 매칭 인접 피해와 직접 파워 피해를 구분한다. 대상별 반응 판단을 읽기 전용으로 조회할 수 있게 하고 실제 적용도 같은 판단을 사용한다. 조회 자체가 내구도·난수·턴별 피해 기록을 변경하면 안 된다. 파워 범위 계산과 장애물 반응을 거대한 매니저 하나에 합치지 않는다.

이번 단계만을 위해 범용 등록 시스템, DI, 이벤트 버스, 별도 패키지/asmdef를 만들지 않는다. 드론 목표 후보·예약 매니저와 미션 기여도 평가는 후속 단계다. 기존 결과 필드는 보존하고 필요한 효과 기록만 추가한다.

## 에디터 사용 흐름

- 메뉴는 기존 `Match → 초기 보드 확인`을 사용한다.
- 시작 조건 구성에 성공한 상태에서 실행 시험을 켠다. 기존 시작 조건을 완화하지 않는다.
- 두 칸 선택 후 `교환 실행`, 단일 파워 선택 후 `제자리 발동`을 제공한다. 제자리 버튼은 검증 도구이며 실제 게임의 더블터치 UI 구현은 아니다.
- 결과에 이동 수, 선택 매칭, 파워 발동 위치, 피해·상자 내구도 변화, 보호 및 거절 이유를 표시한다.
- 처리 완료 후 `낙하 대기`를 명시하고 다음 행동을 막는다. 같은 시드 초기화로 반복 검증한다.
- 원본/레벨/시드/모드 변경이나 창 종료 시 오래된 실행 결과를 폐기한다. 좁은 창에서도 입력과 결과에 접근할 수 있게 한다.

## 작업 순서와 검증

| 순서 | 작업 | 완료 증거 |
|---|---|---|
| T1 | 현재 코드·규칙·10단계 완료 증거 대조, 지원표와 파일 책임 확정 | 착수 기록, 원본 보존 기준 |
| T2 | 피해 원인/반응, 행동별 보호·피해 기록과 결과 모델 | 읽기 전용 조회, 내구도 제한 정답 검사 |
| T3 | 로켓·폭탄 단독 발동과 즉시 연쇄 | 범위·순서·중복·보호 정답 검사 |
| T4 | 일반 매칭 상자 피해, 교환/제자리 실행과 원자적 반영 | 이동 수·늦은 거절·난수 보존 검사 |
| T5 | 기존 실행 시험 화면 연결 | 실제 Unity 조작과 화면 증거 |
| T6 | 독립 재현, 영향 범위 회귀와 완료 감사 | 이번 실행의 결과 보고 및 임시 자료 정리 |

T2→T3→T4 의존성을 따른다. 코어 결과가 검증된 뒤 UI에 연결한다.

### 핵심 정답 사례

- 가로/세로 로켓의 중앙·가장자리 발동, 구멍·벽·상자를 지나 끝까지 제거.
- 폭탄의 중앙·변·모서리 범위와 비활성 칸 제외.
- 로켓→폭탄→로켓 연쇄, 겹친 범위에서 기존 파워는 각각 한 번만 발동.
- 상자 내구도 1~6, 서로 다른 상자는 각각 피해, 같은 상자는 매칭+여러 폭발에도 턴당 1 피해.
- 벽 너머 인접 매칭은 상자 피해 없음. 직접 파워 피해는 벽 무시. 파워로 옆 일반 블록만 제거하면 상자 피해 없음.
- 새 파워는 범위에 들어와도 유지되고 발동하지 않음. 기존 파워와 신규 파워를 구분.
- 교환 선택 순서 반대, 파워의 도착 위치, 교환으로 완성한 매칭과 새 파워 보호.
- 영역 안 기존 드론/자석을 늦게 발견한 경우 전체 거절. 앞서 제거한 블록·상자 피해·수·난수까지 보존.
- 지원하지 않는 직접 조합과 보드 요소, 무효 입력, 이동 수 0, 낙하 대기 중 재입력 거절.
- 동일 시드·입력·알고리즘 버전의 상태와 효과 순서를 독립 Unity 프로세스에서 재현.

손으로 정한 예상 좌표·내구도를 사용하며 구현 함수를 다시 호출해 정답으로 삼지 않는다. 실제 사용자 입력으로 만들기 어려운 처리 상태는 별도 구성 사례임을 명시하고, 정상 교환/발동 통합 사례도 함께 검증한다.

기존 10단계 교환·매칭·생성, 9단계 조회/시작 조건, 8단계 독립 상태·초기 보드 중 변경 영향 범위를 회귀 검증한다. 과거 검사 수를 이번 실행 결과에 합산하지 않는다. 원본 JSON/dirty, v4, GUID/meta, 미션·공급 상태와 무관 파일 보존을 확인한다.

## 제외 범위와 다음 의존성

이번에는 드론·자석 발동, 전용 파워 조합, 다른 장애물, 낙하·대각선·통로·공급, 자동 매칭 반복, 미션 진행·승패·라스트팡, 아이템·부스터, 저장 복구, 봇·난이도 분석을 구현하지 않는다.

이후에는 낙하·공급 및 턴 반복, 나머지 파워·대상별 장애물 반응, 미션과 종료 판정 등을 의존성에 맞춰 나눠야 한다. 이번 완료만으로 자동 플레이나 난이도 평가가 가능해졌다고 표현하지 않는다.
