## 목표와 확인한 상태

현재 Match 실행 시험에 곰팡이의 덮개 제거·내용물 보존·동적 미션·드론 후보·턴 종료 확산을 추가한다. 수동 플레이 전체 완성의 첫 후속 단계이며 봇이나 난이도 계산은 아직 만들지 않는다.

계획 시 17단계 완료 감사의 1,872 PASS/20조건과 최종 소스 해시 차이0, 활성 Goal 없음을 확인했다. 실행 시 다시 확인한다.

계획 작성 당시 코드에서 확인한 사실(착수 전 기준):

- CoverKind.Mold와 편집/배치 검증, 초기 곰팡이 수를 미션 Target에 반영하는 모델은 있다.
- ActionQuery와 MatchQuery는 덮인 조작·매칭을 제한한다. 실행기, DamageReaction, SettlementResolution은 곰팡이를 미지원으로 거절한다.
- 자석 조작 가능 조회에는 곰팡이 제외가 있으나, PowerEffectResolution의 실제 색 선택/범위와 PowerCombinationResolution의 색 선택/변환은 아직 같은 조건으로 거르지 않는다.
- 자동 매칭이 없으면 BoardActionExecutor.Cascade는 바로 다음 행동/이동 수 소진/재배치 필요 상태를 결정한다. 전체 연쇄 후 곰팡이 확산을 한 번 처리할 위치가 필요하다.
- RuntimeMission은 Target/Progress/Remaining을 가진다. 곰팡이는 초기 수량 고정 수집과 다른 동적 목표이므로 확산/제거에 일관된 갱신이 필요하다.
- 현재 UI의 셀 텍스트와 색 클래스는 덮개 안의 색/파워를 드러낼 수 있다. 공통 규칙과 표시 양쪽을 확인해야 한다.

## 범위와 선택

2026-09-27 완료: 곰팡이 실행·UI·독립 재현·회귀 및 완료 조건20개 검증을 마쳤다. 최종 결과는 2,045 PASS/0 FAIL이며 상세 근거와 제한은 목표 문서의 완료 기록을 따른다. 후속 단계는 별도 Goal로 진행한다.

곰팡이 제거만 먼저 구현하면 턴 종료 결과가 실제 규칙과 달라진다. 따라서 제거와 확산을 한 단계에 포함한다. 모든 장애물/승패/봇까지 동시에 구현하는 방식은 제외한다.

지원 범위는 기존 일반·파워4종·상자·고철·거미줄·먼지와 공급에 곰팡이를 추가한다. 고정 장애물 추가 종류, 발전기, 회수 부품, 승패 화면·라스트팡·자동 재배치, 아이템/부스터, 봇/통계/난이도, 실제 기기 저장 복구는 후속이다. 단, 모든 미션 달성 시 확산 생략과 마지막 수 확산은 이번 규칙에 반드시 포함한다.

## 확정 규칙

1. 곰팡이는 내구도1의 덮개다. 안의 일반 색/파워 종류/로켓 방향과 바닥 먼지를 보존한다. 교환·낙하·매칭은 막는다.
2. 벽 없는 상하좌우 인접 일반 매칭 또는 직접 파워 타격으로 제거한다. 파워가 옆 일반 블록을 제거한 사실만으로 인접 매칭 피해를 주지 않는다.
3. 덮개를 벗기는 한 타격은 내용물을 소모·변환·발동하지 않는다. 이후 별도 타격은 노출 내용물에 적용하며 신규 매칭 파워 보호를 보존한다.
4. 노출 내용물은 이후 정상 낙하·정착·자동 매칭을 한다. 처리된 패턴 기록 때문에 새로 드러난 유효 매칭이 누락되지 않는지 검사한다.
5. 자석의 색 선택·색 제거·색 기반 변환에서 숨은 일반 블록을 모두 제외한다. 해당 색 효과로 곰팡이만 벗기지도 않는다. 자석+자석의 보드 직접 타격은 덮개만 제거한다.
6. 곰팡이 미션은 남은 곰팡이 전부 제거다. 확산 시 남은 수가 늘고 제거 시 줄어든다. 드론은 내용물과 무관하게 덮개 제거 기여를 조회한다.
7. 이동 수를 소비한 조작에서 곰팡이를 하나도 제거하지 않았을 때만 전체 연쇄 후 한 칸 확산한다. 하나라도 제거했으면 생략한다. 최초 구성·조회·무효 입력·단계 버튼 반복은 새 확산을 만들지 않는다.
8. 기존 곰팡이에 상하좌우 인접한 덮개 없는 일반/파워 칸만 후보다. 벽 너머·원격 통로 출구·고철/상자/회수·빈칸·거미줄은 제외한다. 먼지는 허용하며 동일 후보는 중복하지 않는다.
9. 곰팡이나 후보가 없으면 무확산이다. 전부 제거한 판에서 자연 재생성하지 않는다. 확산은 보드 전체 한 칸이며 새 곰팡이가 같은 수에 추가 확산하지 않는다.
10. 전체 연쇄 후 모든 미션 달성을 먼저 확인하여 확산을 생략한다. 미션이 남은 마지막 수는 확산까지 반영한 뒤 기존 수 소진 상태로 간다. 확산 후 행동 조회로 재배치 필요를 판단하되 실제 재배치는 22단계다.

## 구현 정책과 책임

다음 정책은 이 계획을 지정한 Goal 실행 요청의 구현 제안이다. 기존 계약과 충돌하면 근거를 기록하고 해결한다.

- Simulation의 기존 TurnEffectContext에 이번 수 곰팡이 제거 여부와 턴 종료 처리 여부를 최소 상태로 둔다. NextTurn에서 초기화하고 사본에는 복사한다. 조회/드론 예약 해제가 실제 제거 기록을 초기화해서는 안 된다.
- 자동 매칭이 없는 안정 지점에서 성공적으로 이동 수를 소비한 수에 한해 종료 처리를 한다. 작업 사본에서 후보 선택·덮개/미션 갱신·종료 기록을 함께 적용한다. 반복 명령이나 실패 재시도로 확산/난수 소비가 두 번 발생하지 않도록 한다.
- 확산 후보를 좌표순 정렬 후 기존 SimulationRandom으로 하나 선택한다. 후보0/1개는 선택 난수를 쓰지 않는다. 새로운 난수 엔진/전역 상태는 만들지 않는다.
- 기존 Target/Progress 모델을 유지하는 경우 초기 Target=최초 곰팡이 수, 제거마다 Progress+1, 확산마다 Target+1로 Remaining=현재 수를 유지한다. UI는 누적 목표 대신 ‘남은 곰팡이’를 보여준다. 다른 미션의 목표량은 변경하지 않는다.
- 곰팡이 없음/후보 없음/이번 수 제거/모든 미션 달성/확산 성공을 기록한다. 모든 미션 달성 검사는 확산 순서를 위한 공통 조회로 두고, 이번 단계에서 임의의 승리 화면이나 보상 처리를 만들지 않는다.
- DamageReaction/LayerDamageRules에서 덮개 반응을 공유하고 MissionProgressRules에 종류별 기여를 추가한다. 인접 매칭의 기존 ‘본체만’ 조건 때문에 곰팡이가 누락되지 않도록 호출 경로를 확인한다.
- 자석 단독/피격/조합이 동일한 노출 색 대상 조건을 사용하게 한다. 거미줄은 기존 포함 규칙을 유지한다. 드론의 후보 캐시/공유 예약은 제거·확산 후 필요한 시점에 무효화한다.
- 사용자용 실행 보드에서는 숨은 내용물의 텍스트·색 클래스·아이콘·툴팁을 가린다. 원본 배치 편집 인스펙터는 제작자가 설정을 확인할 수 있다. 진단 상세가 필요하면 사용자 관찰과 명확히 구분하며 봇에 전달하지 않는다.
- Assets/Scripts/Simulation 및 Editor/Levels의 기존 책임 구성을 유지한다. 별도 게임명 폴더·새 패키지·asmdef·범용 확산 프레임워크는 추가하지 않는다. 처리 결과가 바뀌는 알고리즘 버전을 갱신한다.
- 원본 레벨/v4/GUID/meta를 보존한다. 순수 상태 재현과 실패 원자성을 검증하되 실제 앱 강제 종료 복구를 구현했다고 보고하지 않는다.

작업은 같은 실행 상태를 공유하므로 순차 진행한다. 구현 전에 확정 규칙별 정답 사례를 만든다. 수동 시험 UI와 봇 개발은 분리하고, 기존 테스트의 곰팡이 미지원 기대는 다른 미지원 종류로 바꾸거나 새 지원 기대를 명시한다.

필수 사례: 일반/파워4종 덮기와 방향 보존, 먼지 중첩, 인접 벽 차단·파워 관통, 한 타격 보존/다음 타격 처리, 노출 후 낙하·매칭, 숨은 색만 존재하는 자석, 자석+자석, 드론 중복·소실·부분 기여, 복수 곰팡이 중복 후보·후보0/1/N, 1수의 여러 연쇄 중 한 번이라도 제거, 마지막 수 미션 달성/미달성, 곰팡이 미션이 없는 전체 미션 달성, 원본/실행 사본 격리, 같은 종료 단계 재호출, 실패 상태 무변경, 동일 정의/시드/행동 전체 재현.

실제 유효 편집 레벨에서 Match 메뉴 진입·교환/발동·단계/끝까지·다음 수·초기화·레벨/시드 변경·닫기를 검증한다. 1000/680폭의 숨김 표시와 기록 접근을 확인한다. 컴파일과 8~17단계 영향 회귀를 실행하고 결과 수의 중복을 제외한다. 완료 조건별 증거·미검증 항목·소유 임시 에셋 정리 결과를 목표 문서에 남긴다.
