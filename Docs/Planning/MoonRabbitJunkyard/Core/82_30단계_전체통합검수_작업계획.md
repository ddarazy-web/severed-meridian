## 2026-09-29 재개 계획

최종 범위 결정: 사용자가 **HTML 브라우저 배치 검수만 후속으로 이관**했다. 로컬 파일 접근에 대한 브라우저 도구 정책을 우회하지 않으며, 이 항목의 미검증을 통과로 바꾸지 않는다. 나머지 실제 Unity 화면·도킹·정적 문서 연결·기능·성능·보존 검수는 완료 기록에 연결했다.

다음 실행 대상은 아직 끝나지 않은 **30단계의 남은 통합 검수**다. 현재 로드맵의 마지막 단계이므로 완료 전에 임의의 31단계를 추가하지 않는다. 이번 갱신은 계획과 실행문 정리이며 기존 활성 Goal을 교체하지 않는다.

확인한 증거는 `Logs/LevelWorkflowVerification` 아래에 있다. 기본 구성은 신규 200판 이후 사례 선택 오류가 발생했고, 수정 후 별도 `basic-result-check-results.txt`에서 실제 재생을 확인했다. 최초 실패 기록은 그대로 보존한다. 이동통로 구성은 `flow-results.txt`에서 신규 200판과 재생·원본 보존까지 통과했다. 발전기 구성과 후속 검사 대기열은 재개 시 최신 프로세스·결과 파일로 상태를 확인한다. 진행 파일의 판 수만으로 완료를 판단하지 않는다.

| 순서 | 남은 작업 | 종료 판단 |
|---|---|---|
| R1 | 같은 프로젝트의 실행 중 검사와 대기열 상태, 기존 결과 확인 | 중복 Unity 실행 없이 진행 중/완료/실패 구분 |
| R2 | 발전기 대표 구성 결과 확보와 세 대표 기록 정리 | 각 100시드×두 전략의 완료 기록, 정의·버전·재생 증거 연결 |
| R3 | 등록 맵·저장·화면·난이도 영향 회귀 확인 | 신규 결과 파일과 실패 이력 보존, 사례 선택 수정의 영향 확인 |
| R4 | 공통 편집·복사·공급·경로·컨텍스트 및 중단/재시작의 미확인 조건 검사 | 아래 완료 범위를 누락 없이 연결하고 실제 미검증은 별도 표시 |
| R5 | 10×10·기록 규모·도움말·매뉴얼 및 보존 대조 | 측정 조건·한계, 원본과 기존 기록 보존 결과 확보 |
| R6 | 완료 조건 20개 감사와 제작자 인수인계 | 조건별 증거가 충족된 경우에만 Goal 완료 |

이미 끝난 시험을 단순히 횟수를 늘리려고 반복하지 않는다. 변경 영향이 있는 경로 또는 부족한 증거만 보완한다. 기존 실행이 진행 중이면 기다리면서 문서 대조 등 독립 작업을 수행한다. 후속 게임 화면·주문·콘텐츠 제작은 30단계 완료 후 별도 범위로 결정한다.

## 목적과 범위

제작자가 Match 통합 작업창에서 레벨을 만들고 저장한 뒤, 직접 플레이하고 봇으로 반복 시험하여 통계·예상 난이도를 확인하는 흐름을 검수한다. 개별 기능의 기존 통과 횟수를 합산하는 대신 기능 사이에서 상태·저장 내용·실행 조건이 제대로 이어지는지 확인한다.

이번 단계는 기존 기획의 연결 오류와 회귀를 찾아 필요한 범위만 수정한다. 새로운 장애물, 봇 전략, 난이도 산식, 추천 맵 자동 생성, 서버 동기화, 유료 결제, 실제 게임 화면 제작과 출시 검증은 포함하지 않는다. 에디터 검수가 끝났다는 이유로 게임 전체 개발이 끝났다고 표시하지 않는다.

29단계 미완료 항목을 30단계 완료로 대신 처리하지 않는다. 시작 시 선행 검증이 부족하면 부족한 조건을 보고하고 선행 완료 후 진행한다. 기존 사용자 변경·레벨·등록 맵·시험 기록은 모두 보존 기준에 포함한다.

## 검수할 작업 흐름

| 순서 | 실제 작업 | 확인할 결과 |
|---|---|---|
| 1 | 새 레벨 생성 또는 등록 맵 모양 선택 | 원본을 보존한 새 데이터, 선택한 모양과 사용 장애물 참고 정보 |
| 2 | 칸·장애물·미션·공급·경로·연결 편집 | 공통 인스펙터, 복사·붙여넣기, 연결 후보 표시, 컨텍스트 초기화와 정합성 검사 |
| 3 | 이름 변경·Ctrl+S 저장·다시 열기 | dirty 표시와 실제 저장 내용 일치, GUID·참조 보존, 취소 시 데이터 유지 |
| 4 | 수동 플레이·재시작·편집 복귀 | 편집 원본과 시험 사본 분리, 공통 규칙 실행, 결과 및 입력 상태 일치 |
| 5 | 기본/계획 전략 반복 시험 | 같은 묶음 내 동일 시드 비교, 새 시험의 새 묶음, 일시정지·재개·중지 |
| 6 | 통계·난이도·사례 재생 확인 | 정상/오류/일부 실행 구분, 근거와 기준 버전, 저장 행동 재현 |
| 7 | 레벨 수정·재시험·이력 비교·보관 후 열기 | 과거 정의와 현재 정의 구분, 같은 조건 비교와 기록 보존 |

생성구 파워블록 공급과 등록 맵 이름 변경 등 후속 추가 기능도 검수에 포함한다. 편집 규칙의 정답은 최신 확정 문서와 구현 계약을 대조해 정하며, 서로 충돌하는 중요한 사항은 grill-me로 한 번에 하나씩 확인한다.

## 대표 시나리오와 검사 규모

기본 매칭 중심, 흐름·공급 중심, 복합 장애물·연결 중심의 서로 다른 레벨 최소 3개를 사용한다. 기존 검증용 정의가 적합하면 재사용하고 실제 사용자 레벨을 덮어쓰지 않는다. 모양·미션·공급·연결 구성과 선택 이유를 기록한다.

각 레벨에서 편집→저장→수동 시험→자동 시험→결과 확인을 실제 Unity 창으로 수행한다. 고정 행동·시드 검사는 재현성 확인용이며 새 무작위 시험과 구분한다. 자동 시험은 각 레벨에서 기본/계획 전략에 같은 시드 100개씩 적용한 완료 기록을 확보한다. 29단계의 호환 기록은 분석·재생 검사에 재사용할 수 있지만, 최소 한 레벨은 최종 코드에서 UI로 새 100개 시드×두 전략을 실행해 전체 연결을 확인한다. 실행 코드가 변경되면 영향받는 기존 기록으로 새 실행 검증을 대체하지 않는다.

모든 장애물을 한 보드에 억지로 넣지 않는다. 대표 흐름에서 다루지 못한 기능은 기존 개별 검사를 보완 실행하고 요구사항별 검증표에 연결한다. 모든 5등급을 실제 게임에서 얻을 때까지 레벨을 조작하지 않는다. 등급 경계는 합성 검사, 실제 게임은 연결과 기록 일치 검증으로 구분한다.

## 중단·복귀·오류 검사

- 실행 중 탭 이동, 레벨 선택 변경, 창 닫기, 재컴파일과 Editor 재시작에서 기존 계약대로 중단·보존·복귀하는지 확인한다. 재시작 후 진행 중 판이 반드시 이어져야 한다는 새 규칙을 만들지 않는다.
- 일시정지 후 재개/중지, 일부 완료 기록, 정합성 오류, 손상·누락·비호환 기록을 구분한다. 오류가 정상 패배나 현재 레벨의 난이도로 표시되지 않아야 한다.
- 과거 원본 레벨의 이름 변경·삭제는 별도 임시 복사본으로 시험한다. 저장된 정의로 조회·재생 가능한 범위와 버전 제한을 확인한다.
- 오류 주입은 전용 임시 기록에만 수행한다. 내보내기 취소·실패·중복 대상에서도 원본 기록과 기존 대상이 보존되어야 한다.

## 화면·성능·구조

실제 Match 창의 네 탭을 이동하며 탭별 최소 크기, 좁은 도킹 영역의 스크롤, 긴 이름·설명, 도움말 i 아이콘과 HTML 연결을 확인한다. 편집에서 시험으로 넘어갈 때 별도 옵션을 불필요하게 늘리지 않는다.

최대 보드 크기 10×10과 기존 지원 기록 규모에서 대표 조작의 응답 시간, 시험 소요 시간, 결과 읽기·재생 지연을 측정한다. 동일 조건의 선행 측정값과 비교하고 단일 작업의 긴 정지와 취소 응답도 기록한다. 측정 없이 임의 성능 합격선을 만들거나 최대 규모를 무제한 지원으로 표현하지 않는다. 기존 재생 한 단위의 지연 등 알려진 한계는 재확인하고 사용에 주는 영향을 명시한다.

공통 게임 실행기, 공개 관찰을 사용하는 봇, 통계·난이도 계산, Editor 화면의 의존 경계를 확인한다. 분석 정보나 숨은 공급 순서가 봇 입력으로 유입되지 않아야 한다. 수정은 `Assets/Scripts/Features`의 해당 기능·역할 폴더에 두며 신규 공통 프레임워크나 패키지를 추가하지 않는다. 복잡한 상태 전환과 오류 처리에는 한국어 주석을 보강한다.

## 작업 순서

| 작업 | 내용 | 완료 증거 |
|---|---|---|
| T1 | 선행 완료·기획/구현 대조·보존 기준 확정 | 조건별 증거 목록, 변경 전 파일 상태·해시, 미정/제외 범위 |
| T2 | 대표 레벨과 전체 작업 흐름 검수 | 정의·시드·버전·행동·원시 기록 경로, 실제 UI 캡처 |
| T3 | 중단·복귀·오류·버전 경계 검사 | 재현 절차와 기대/실제 결과, 데이터 보존 비교 |
| T4 | 발견 결함의 최소 수정 | 원인·영향 범위·수정 전 재현·수정 후 검사 |
| T5 | 영향 회귀·화면·성능 확인 | 수정된 경로 재실행, 측정 조건·시간·잔여 한계 |
| T6 | 매뉴얼·인수인계·완료 감사 | 기능별 증거표, 사용 순서, 미검증 목록, 20조건 대조 |

기존 검사를 모두 매번 반복하지 않는다. 먼저 필요한 범위를 실행하고 새 변경·실패·미확인 위험이 있으면 확대한다. 재사용 증거, 신규 검사 발생 횟수, 실제 게임 판 수, 합성 입력 수를 따로 기록한다.

완료 기록에는 조건 번호·검사 방법·증거 경로·결과·남은 한계를 연결한다. 필수 조건 실패나 미검증은 완료로 표시하지 않는다. 외부 제약으로 확인하지 못한 화면·플랫폼은 명시하고, 별도 합의 없이 필수 조건에서 제외하지 않는다. HTML 매뉴얼은 기존 카테고리 구조와 왼쪽 바로가기, 쉬운 한국어 안내를 유지한다.
