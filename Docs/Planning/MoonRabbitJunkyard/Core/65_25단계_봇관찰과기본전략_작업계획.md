## 목적과 완료 모습

사용자가 만든 레벨을 기본 봇이 공개된 정보만 보고 한 판 진행한다. 봇은 행동을 선택하고, 실제 교환·파워 발동·낙하·연쇄·승패는 수동 플레이와 같은 실행기가 처리한다. Match에서 선택 이유와 판 결과를 확인할 수 있어야 한다.

이번 단계의 핵심은 높은 성공률이 아니라 정보 접근 제한, 조작의 동등성, 한 판 진행과 재현이다. 봇이 모든 레벨을 클리어해야 하는 것은 아니다. 정상 패배와 프로그램 오류를 분리한다.

## 범위와 후속 단계

포함: 공개 관찰 데이터, 안전한 행동 후보 전달, 기본 전략, 한 판 실행 제어, 최소 진단 기록, Match 시험 UI, 정보 차단·재현·회귀 검증.

제외: 여러 수를 가정하는 계획 전략(26), 두 전략 반복 실행·시드 묶음·사용자용 일시정지/재개 및 부분 결과 관리(27), 집계 통계·사례 재생 화면·분석 이력(28), 난이도 등급 추천(29), 전체 통합 검수(30). 이번 한 판의 안전한 중지와 숨겨진 탭의 실행 정지는 반복 실행 기능과 별개로 포함한다.

아이템·시작 부스터·광고 이어하기는 봇 평가에서 사용하지 않는다. 수동 시험의 무제한 아이템 기능은 유지한다. 자동 맵 생성, 새 장애물, 상점·재화·결제·앱 복구·출시용 연출은 추가하지 않는다.

## 정보 경계

흐름은 `실제 실행 상태 → 공개 정보 변환 → 기본 봇 → 조작 요청 → 공통 실행기`다. 내부 실행 기록은 검증·진단으로 보내며 봇으로 되돌리지 않는다.

### 공개 관찰 데이터

- 안정된 입력 가능 시점의 읽기 전용 값 복사본을 만든다. 실행 상태나 정의 객체, 가변 컬렉션 참조를 포함하지 않는다.
- 칸 좌표·활성 여부, 화면에 드러난 일반 블록 색·파워 종류/방향, 보이는 장애물·덮개·내구도·발전기 충전 상태, 남은 이동 수와 미션 진행을 포함한다.
- 화면에 표시되는 벽·통로·도착 바닥·전선 등만 공개한다. 에디터에서만 아는 경로 우선순위·설정값을 자동으로 공개하지 않는다. 필드마다 플레이어에게 보이는 근거를 적은 허용표를 만든다.
- 곰팡이 아래의 내용은 `알 수 없음`으로 표현한다. 빈칸이나 무작위 색으로 바꾸지 않으며 숨은 색·파워 방향·본체 참조가 중첩 필드로 새지 않아야 한다.
- 고정 공급 목록·소진 위치·앞으로 나올 블록·실제 시드·난수 상태/추출 횟수·원본 레벨 참조·정의 지문·실행 로그는 제외한다. 진단 화면에 시드가 보인다는 이유로 봇에도 공개하지 않는다.
- 동일 공개 상태라면 숨은 내용과 미래 공급을 바꾸어도 관찰값, 후보, 평가점수, 선택 결과가 같아야 한다.

### 행동 후보와 실행

`ActionQuery`를 실행 경계 안에서 재사용하되, 원본 `ActionCandidate`를 봇에 직접 넘기지 않는다. 공개 조건으로 설명 가능한 좌표·조작 종류·매칭 정보만 값으로 복사한다. 후보의 존재 여부 자체가 숨은 정보를 누설하는지도 검사한다. 조회에 문제가 있으면 관련 공개 판정만 최소 범위로 분리하고, 봇용 매칭 엔진을 복제하지 않는다.

봇이 반환하는 값은 조작 종류와 대상 좌표다. 세션은 관찰 시점과 현재 판이 같은지 확인하고 공통 실행기에 다시 검증받는다. 오래된 요청, 잘못된 좌표, 실행 중 요청은 거절하며 이동 수와 난수 상태를 변경하지 않는다.

조회 후보가 없다는 이유만으로 봇이 패배를 선언하거나 직접 섞지 않는다. 자동 재배치와 종료는 공통 실행기의 안정 경계에서 처리한다. 계속 진행 중인데 후보가 없으면 진단 가능한 불일치로 종료하며 일반 패배에 합치지 않는다.

## 기본 전략 — 이번 단계의 구현안

정확한 미래 실행 결과를 미리 계산하지 않는 한 수 평가를 사용한다. 아래 순서는 구현 기본안이며 사람의 실력이나 검증된 난이도 산식이 아니다.

1. 공개 정보로 확인 가능한 미션 기여를 먼저 비교한다. 색 수집, 노출된 목표의 유효 피해, 발전기 충전 및 회수 경로 정리 등은 해당 규칙의 조건을 지켜 평가한다. 장애물 옆이라는 이유만으로 모두 같은 점수를 주지 않는다.
2. 파워 생성·활용과 눈앞에서 확인 가능한 제거 범위를 비교한다. 기존 파워 생성 우선순위는 게임 규칙을 그대로 따른다.
3. 동점이면 조작 종류·좌표의 고정 순서로 결정한다. 기본 전략은 실제 게임 난수를 사용하지 않는다.

기여를 확정할 수 없는 드론의 임의 도착, 자석의 무작위 색, 새 공급 이후 연쇄 등은 불확실한 것으로 남긴다. 실제 실행기로 후보마다 미래를 시험하고 가장 좋은 결과를 고르는 방식은 금지한다. 점수의 세부 항목과 우선순위는 한곳에 고정하고 버전을 기록한다. 레벨마다 점수 옵션을 입력하게 만들지 않는다.

규칙별 미션 기여 조건은 기존 장애물·피해·회수 규칙과 대조한다. 이미 순수한 조회 기능이 있으면 재사용한다. 필요한 종류별 판단을 한 거대 조건문에 모으거나 드론 목표 매니저의 내부 예약 상태를 봇에 노출하지 않는다. 관찰만으로 판단할 수 없는 항목은 근거를 기록하고 보수적으로 평가한다.

## 한 판 실행과 Match 화면

- 기존 플레이 테스트 탭 안에 접을 수 있는 `기본 봇 시험` 영역을 두는 안을 사용한다. 별도 EditorWindow나 통계 탭은 만들지 않는다.
- 기본 조작은 `한 수 진행`, `한 판 실행`, `중지`와 선택 이유·현재 진행·판 결과다. 한 수 진행도 실제 효과·낙하·연쇄가 안정될 때까지 포함한다.
- 봇 시험은 현재 레벨의 별도 사본으로 시작하고 아이템·부스터를 비운다. 기존 수동 세션 도중 소유자를 몰래 바꾸지 않는다. 새 시험 시작과 기존 시험 종료를 화면에서 구분한다.
- 시작 조건 검사와 자동 재배치·라스트팡은 공통 실행 경계를 따른다. 봇은 입력 가능 상태에서 한 번만 선택하고, 후속 처리 중 다시 선택하지 않는다.
- Editor를 막는 긴 while 루프 대신 갱신별 제한된 처리를 사용한다. 수동 입력·단계 실행·봇 입력 중 하나만 실행기를 소유한다.
- 중지는 완료한 행동 기록을 보존한다. 효과 처리 중 요청하면 다음 일관된 경계에서 중지하고, 공통 실행기의 처리 한도/오류가 발생하면 오류 상태를 남긴다. 승리·패배와 사용자 중지를 구분한다.
- 탭 이탈 시 봇 진행을 멈추고 복귀 후 사용자가 다시 실행하도록 한다. 원본 수정·레벨 전환·창 종료·재로드에서는 오래된 세션과 예약을 폐기하고 이유를 표시한다. 원본과 미저장 편집은 보존한다.
- 같은 입력·시드·전략 버전이면 같은 행동과 결과를 재현한다. 새 실행의 시드와 재현용 시드는 실행 세션만 소유한다.

## 스크립트 구성과 대안

`Assets/Scripts/Features/AutoPlay/` 아래에 기능을 모으고 내부를 역할로 나눈다. 아래 이름은 책임 배치안이며 빈 파일이나 아직 쓰지 않는 인터페이스를 미리 생성하지 않는다.

| 위치 | 책임 |
|---|---|
| `Runtime/Observation` | 공개 관찰 값과 조작 요청 값 |
| `Runtime/Strategy` | 공개 정보만 받는 기본 전략과 선택 근거 |
| `Runtime/Execution` | 실제 상태를 읽는 변환기, 실행기 호출, 한 판 진행과 내부 기록 |
| `Editor/Presentation` | Match에 붙이는 봇 시험 UI |
| `Editor/Tests` | 정보 차단·조작 동등성·재현·실제 UI 검증 |

전략의 메서드 인자·필드·참조에서 `LevelRuntimeState`, `LevelDefinition`, `BoardActionExecutor`, 난수와 로그에 접근하지 않도록 검사한다. 이는 같은 프로세스 안의 구조적 분리이며 악의적 코드에 대한 보안 샌드박스는 아니다. 이 작업만을 위해 별도 프로세스, 새 패키지, asmdef 분리나 기존 전체 네임스페이스 변경을 하지 않는다.

대안 비교: 상태를 통째로 복사해 넘기는 방법은 간단하지만 숨은 정보를 포함하므로 채택하지 않는다. 별도 봇용 게임 엔진은 규칙 불일치와 유지 비용 때문에 제외한다. 필요한 공개 값만 변환하고 기존 실행기를 호출하는 방식으로 범위를 제한한다.

## 필수 검증 사례와 증거

- 숨은 색/파워·공급 순서·난수 상태만 다른 쌍: 공개 관찰·후보·선택 동일. 실행 후 결과가 달라지는 것은 정상이다.
- 관찰 객체의 값을 바꾸려는 시도가 실행 상태를 바꾸지 않음. 관찰 후 상태 변경도 과거 관찰값을 바꾸지 않음.
- 후보 조회와 점수 계산이 실제 난수·이동 수·드론 예약을 소비하거나 변경하지 않음.
- 동일 명령열을 수동 경로와 봇 경로에 넣었을 때 규칙 결과·이동 수·미션·난수 진행이 일치함.
- 일반 교환·제자리 파워·조합, 상자/고철/금고/자물쇠/폐가전, 거미줄/먼지/곰팡이, 발전기, 회수/도착/공급/통로의 좁은 대표 사례. 한 거대 레벨만으로 대체하지 않는다.
- 성공·이동 수 소진·막힘·실행 오류·사용자 중지, 시작부터 종료된 판, 후보 없음, 오래된 요청, 재로드의 중복 실행 방지.
- 선택 이유가 실제 사용한 평가 항목과 일치함. 점수로 예측한 기여와 실제 판 결과를 혼동하지 않음.
- 같은 정의 사본·시드·전략/실행 버전·행동 기록의 독립 Unity 재현. 내부 기록은 봇 입력에서 제외한다.
- `Ctrl+S`, dirty 표시, 수동 아이템/부스터, 등록 맵 목록, 탭 최소 크기/도움말, 연결 편집의 영향 회귀.

증거는 `Logs/BotBasicVerification/` 등 이번 단계 전용 경로에 보관한다. 정의 지문·버전·실행기 전용 시드·행동/선택 이유·종료 원인·검사 결과를 기록하되 통계 제품이나 장기 보관 시스템으로 확대하지 않는다. 검사 건수는 실제 결과에서 집계한다. 사용자 Unity를 임의 종료하거나 사용자 에셋을 검증용으로 변경하지 않는다.

## 결정 상태와 한계

사용자와 이미 확정한 정보 제한·구조적 분리·같은 실행기 사용은 필수 조건이다. 기본 평가의 구체 수치, Editor 갱신당 처리량과 기록 상한은 구현 시 대표 사례와 측정으로 정하고 근거·버전을 남긴다. 근거 없는 성공률·속도·인간 체감 난이도 목표를 약속하지 않는다. 25단계 완료로 전체 자동 평가 기능을 완료 처리하지 않는다.
