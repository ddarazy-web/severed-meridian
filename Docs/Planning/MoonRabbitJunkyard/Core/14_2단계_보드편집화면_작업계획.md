# 2단계 작업 계획 — 보드 편집 화면

- 작성일: 2026-09-27
- 상태: 2026-09-27 승인 범위 구현·검증 완료. 실제 결과와 사용 방법은 [2단계 개발 목표](../../../Goals/MoonRabbitJunkyard/Core/15_2단계_개발목표.md)의 실행 기록을 참고한다.
- 작업 위치: 현재 `ServeredMeridian` Unity 프로젝트.
- 기준: [레벨 에디터 기획](../../../Contents/MoonRabbitJunkyard/09_레벨에디터.md), [1단계 결과](../../../Goals/MoonRabbitJunkyard/Core/13_1단계_개발목표.md), [2단계 개발 목표](../../../Goals/MoonRabbitJunkyard/Core/15_2단계_개발목표.md).
- 원칙: `unity-project-conventions`, `deep-planning`, `ponytail`을 적용한다. 기존 Unity 기능과 코드를 우선하고 이번 편집 기능에 필요한 구조만 추가한다.

## 1. 목표와 현재 기반

**제작자가 목록의 좌표를 일일이 입력하지 않고 보드를 보며 기본 레벨 구성을 편집할 수 있게 한다.** 완료의 기준은 실제 편집 창에서 배치·수정·실행 취소·저장·다시 열기가 되는 것이다.

현재 코드에서 확인한 기반은 다음과 같다.

- `LevelDefinition`: 레벨 번호·이동 횟수·사용 색·보드·초기 일반 블록 배치를 저장하는 ScriptableObject.
- `BoardDefinition`: 기본 10×10, 행 우선 칸 목록, 활성 여부와 좌표 조회.
- `InitialBlockDefinition`: 고정 색 또는 무작위 일반 블록. 무작위는 저장 시 색을 결정하지 않는다.
- `LevelDefinitionValidator`와 `LevelValidationIssue`: 원본을 변경하지 않고 오류 코드·필드 경로·좌표를 반환한다.
- `LevelAssetOperations`: 기본 경로 에셋 생성과 에셋 간 레벨 번호 중복 검사.
- 기존 UI Toolkit Inspector와 속성 Drawer, Unity Undo/Redo·저장·재시작 검증 코드.
- 1단계 마지막 검증 기록은 66개 통과다. 2단계 구현 시 현재 코드와 검증 환경을 다시 확인한다.

새 저장 형식이나 게임 실행용 보드를 만들 필요는 없다. 기존 에셋을 편집하는 창을 추가한다.

## 2. 범위

| 이번 단계에 포함 | 후속 단계로 유지 |
| --- | --- |
| 전용 EditorWindow, 레벨 선택·생성·저장 | 전용 레벨 브라우저·복제 관리 화면 |
| 10×10 보드, 행·열 번호, 상태 구분 | 임의 크기 변경, 확대·축소, 별도 카메라 |
| 한 칸 선택과 선택 칸 속성 표시 | 다중 선택·공통 속성 일괄 편집 |
| 칸 활성/비활성 칠하기 | 바닥 기능·먼지·중력·벽·통로 편집 |
| 고정 색·무작위 일반 블록 배치와 지우기 | 파워 블록·장애물·2×2 요소 배치 |
| 클릭·드래그, 한 번의 드래그를 한 Undo로 처리 | 복사·붙여넣기·공급 목록·영역 채우기 |
| 기존 오류 검사 표시와 해당 칸 강조 | 게임 실행·시작 매칭 검사·봇·난이도 분석 |

다중 선택 등의 기존 기획을 삭제하는 것이 아니라 구현 순서를 분리한다. 이번에는 한 칸 속성 편집까지만 제공한다. 다른 단계의 빈 버튼이나 등록 체계를 미리 만들지 않는다.

## 3. 화면과 조작 제안

아래 세부 조작은 기존 기획에 맞춘 **이번 계획의 제안**이다. Goal 실행으로 이 계획을 승인하면 구현 기준으로 사용한다.

| 영역 | 내용 |
| --- | --- |
| 상단 | 레벨 에셋 ObjectField, 새 레벨, 저장, 검사, 수정 여부 |
| 왼쪽 | 선택, 칸 활성화, 칸 비활성화, 고정 색, 무작위 `?`, 일반 블록 지우기 |
| 가운데 | 10×10 보드와 1부터 시작하는 행·열 번호, 선택·오류·드래그 미리보기 |
| 오른쪽 | 레벨 번호·이동 횟수·사용 색, 선택한 칸의 좌표·활성 여부·일반 블록 유형과 고정 색 |
| 아래 | 검사 상태, 오류 목록과 원인·위치 |

- 게임 전용 도구는 최상위 `Match` 메뉴에 모은다. 레벨 에디터는 `Match/레벨 에디터`에서 열며, 기존 Inspector에는 현재 에셋으로 편집 창을 여는 버튼을 추가한다.
- 창은 하나의 편집 대상을 가진다. 다른 Project 항목 선택만으로 대상을 자동 변경하지 않고 ObjectField나 열기 버튼으로 명시적으로 변경한다.
- 레벨이 없으면 선택·생성 안내를 표시하고 보드 편집을 비활성화한다.
- 이미지 리소스는 필요 없다. 다섯 고정 종류를 구분하는 임시 색상과 숫자 1~5를 함께 사용하며 `?`, 빈칸, 비활성 칸을 별도 표시한다. 임시 색상은 최종 달토끼 아트 확정이 아니다.
- 비활성 칸에 보존된 블록은 흐리게 표시하고 오류 표시를 겹친다. 블록을 지운 것처럼 표시하지 않는다.
- 보드는 사각 셀 UI로 구현한다. 창이 좁으면 ScrollView로 접근 가능하게 하고 좌표·도구·속성이 잘리지 않게 한다. 세부 픽셀 크기는 구현 중 확인한다.
- 선택 도구로 한 칸을 선택한다. 칠하기 도구에서는 현재 도구에 맞는 클릭·드래그 작업을 수행한다.
- 고정 색 도구에는 레벨에서 선택한 종류만 사용 가능하게 한다. 사용 색 변경으로 기존 배치가 잘못되어도 배치를 자동 변환하지 않는다.

## 4. 편집 데이터 계약

| 작업 | 데이터 변화 |
| --- | --- |
| 칸 활성화/비활성화 | 해당 칸의 활성 여부만 변경. 초기 배치는 보존 |
| 활성 빈칸에 일반 블록 배치 | 해당 좌표의 초기 배치 항목 한 개 추가 |
| 기존 일반 블록 위에 배치 | 해당 항목의 유형/색만 변경. 같은 좌표에 새 항목을 중복 추가하지 않음 |
| 무작위 배치 | 무작위 유형 저장. 실제 색 결정 없음, 기존 고정 색 보존 규칙 유지 |
| 일반 블록 지우기 | 해당 좌표의 일반 블록 배치만 제거. 칸 활성 여부 유지 |
| 한 칸 속성 편집 | 선택 칸에만 반영. 다른 배치·레벨 값 유지 |

- 비활성 칸에는 일반 블록을 새로 칠하지 않는다. 기존 배치는 선택해 확인하거나 명시적으로 지울 수 있다.
- 없는 블록 지우기, 이미 같은 상태인 칸 칠하기는 데이터와 수정 상태를 바꾸지 않으며 빈 Undo 기록을 만들지 않는다.
- 같은 칸을 한 드래그에서 반복 방문해도 한 번만 처리한다. 빠른 이동에서도 두 포인터 위치 사이에 지나간 칸이 빠지지 않도록 한다. 보드 밖 구간은 칠하지 않는다.
- 선택 칸의 위치는 보드 좌표로 결정한다. 우측 속성에서 좌표 자체를 바꾸는 이동 도구는 이번에 추가하지 않는다.
- 지원하지 않는 형식 버전이나 보드 크기·칸 수 불일치는 보드 칠하기를 막고 원인과 기존 Inspector로 확인할 경로를 제공한다. 데이터를 자동 보정하지 않는다.
- 한 좌표에 이미 여러 배치가 있는 경우 그 칸을 충돌로 표시한다. 칠하기/지우기로 임의 항목을 선택하거나 여러 항목을 묵시적으로 삭제하지 않는다. 기존 Inspector의 원본 목록에서 수정하도록 안내한다.
- 범위 밖 좌표와 미정의 유형도 목록과 오류에 남긴다. 정상 위치의 편집 때문에 이런 기록이 없어져서는 안 된다.

## 5. 드래그·Undo·저장 경계

**추천: 드래그 중 방문 칸을 창의 임시 상태로 모아 미리보기하고, 정상적으로 놓을 때 한 번 적용한다.** 데이터마다 수정하면서 별도 실행 취소 기록을 재구현하지 않는다.

- 포인터를 캡처하여 보드 밖에서 놓아도 앞서 보드 안에서 방문한 칸을 한 작업으로 완료한다. 밖을 지나 재진입하면 밖의 경로를 보드 안의 직선으로 잘못 연결하지 않는다.
- 한 번의 클릭 또는 완료된 드래그는 한 번의 Undo로 원상복구하고 Redo로 재적용한다. 변경 없는 작업은 기록하지 않는다.
- 창 포커스 상실·예기치 않은 캡처 상실·창 닫기·레벨 전환 시 **아직 적용하지 않은 드래그만 취소**한다. 이미 완료한 편집은 유지한다.
- 드래그 도중 저장·검사·도구 전환·Undo/Redo·외부 Inspector 변경이 발생하면 미리보기를 먼저 취소하고 해당 동작을 처리한다. 다른 에셋이나 변경 전 데이터에 뒤늦게 적용하지 않는다.
- 실제 데이터 편집은 Unity 직렬화/Undo API를 사용한다. 별도의 명령 히스토리, 저장 복사본, 자동 저장 체계는 만들지 않는다.
- 완료된 편집은 에셋의 메모리 상태에 반영하고 dirty 상태를 표시한다. 저장 버튼은 현재 에셋을 저장한다. 오류가 있어도 저장한다.
- 창을 닫거나 편집 대상을 바꿔도 완료한 편집을 원복하지 않는다. 아직 디스크에 저장하지 않은 변경은 Unity 에셋 저장 흐름을 따른다.
- 창을 다시 열면 선택한 에셋에서 보드를 다시 구성한다. 도구·선택 칸·드래그 미리보기는 레벨 데이터에 저장하지 않는다. 창 재생성 시 선택 칸과 진행 중 드래그를 초기화해도 된다.
- Undo/Redo와 기존 Inspector의 편집이 보드에 반영되도록 변경 시 갱신한다. 매 프레임 전체 에셋 검색을 수행하지 않는다.

## 6. 검증 표시와 오류 이동

- 기존 `LevelDefinitionValidator.Validate`와 `LevelAssetOperations.FindNumberConflicts`를 재사용한다. 규칙을 화면에 다시 구현하지 않는다.
- 검사 버튼으로 최신 결과를 표시한다. 편집 또는 다른 에셋 변경으로 결과가 오래되면 재검사 필요 상태를 표시하고 오래된 오류 강조를 제거한다.
- 보드 안의 오류를 클릭하면 해당 칸을 선택·스크롤 이동·강조한다. 같은 칸의 오류가 여러 개여도 데이터는 변경하지 않는다.
- 보드 밖 좌표나 레벨 전체 오류는 원문 좌표·필드 경로를 표시한다. 가까운 칸으로 좌표를 보정하거나 엉뚱한 칸을 강조하지 않는다.
- 오류가 없는 경우에도 문구는 ‘구조 오류 없음’으로 유지한다. 테스트 플레이 버튼이나 플레이 가능 판정은 추가하지 않는다.

## 7. 구조 선택과 최소 구현

| 방식 | 판단 |
| --- | --- |
| 기본 Inspector 목록만 확장 | 코드가 적지만 보드에서 클릭·드래그한다는 목표를 충족하지 못함 |
| 씬 GameObject 또는 Tilemap을 편집 원본으로 사용 | 별도 상태·씬 동기화·저장 변환이 필요해 이번 범위에 불필요 |
| UI Toolkit EditorWindow에서 기존 에셋 편집 | 기존 Inspector와 기술을 공유하고 저장 변환이 필요 없어 추천 |

제안 파일 구성은 다음과 같다. 구현에서 책임이 작으면 합칠 수 있으며 파일 개수 자체가 목표는 아니다.

```text
Assets/Scripts/Editor/Levels/
  LevelEditorWindow.cs          창 구성·편집 대상·선택/도구·저장/검사 연결
  LevelBoardView.cs             셀 표시·포인터 입력·임시 드래그·오류 강조
  LevelBoardEditing.cs          기존 직렬화 데이터에 배치/활성/삭제를 한 작업으로 적용
  LevelEditorVerification.cs    이번 단계 편집과 저장의 재현 가능한 검사
```

- 기존 `LevelDefinitionInspector.cs`에는 열기 진입점만 필요한 만큼 추가한다. 기존 에셋 생성·검사·Drawer는 가능한 범위에서 그대로 사용한다.
- 단일 EditorWindow와 100칸의 기본 VisualElement를 우선한다. 별도 UI 프레임워크·범용 그래프·도구 플러그인 등록소·서비스 계층을 만들지 않는다.
- USS 등 분리 파일은 실제 스타일 중복이나 가독성상 필요할 때만 추가한다. 별도 이미지 생성과 런타임 UI는 필요 없다.
- 저장 모델의 필드·열거형 값·스키마 버전은 유지한다. 편집 목록 조회용 인덱스가 필요하면 원본에서 계산하는 임시 값으로 두며 영구 저장하지 않는다.
- 스크립트는 `Assets/Scripts` 기능별 경로를 유지한다. 중간 게임명 폴더·새 패키지·새 asmdef는 추가하지 않는다.
- 검증 코드도 새 범용 테스트 기반을 만들지 않고 기존 Editor 검증 방식으로 필요한 사용자 동작을 확인한다.

## 8. 구현 순서 제안

아래는 승인 전 작성한 순서 제안이다. 실제 작업 의존 관계와 완료 증거는 목표 문서의 실행 기록에 남겼다.

| 순서 | 작업 | 확인할 결과 |
| --- | --- | --- |
| 1 | 창·레벨 선택·기존 Inspector 진입점 | 선택한 에셋이 그대로 연결되고 열기만으로 데이터가 변하지 않음 |
| 2 | 보드 표시와 단일 칸 선택 | 좌표·빈칸·비활성·고정·무작위·오류 상태 구분 |
| 3 | 클릭 편집과 한 칸 속성 | 활성/배치/지우기가 해당 요소에만 작용, Undo/Redo 확인 |
| 4 | 드래그와 중단 처리 | 빠른 이동·중복 방문·경계 이탈·전환에도 한 작업의 경계 유지 |
| 5 | 저장·검사·오류 이동·외부 변경 동기화 | 정상/오류 데이터 보존, 오래된 검사 표시 방지 |
| 6 | 실제 창 검증과 1단계 회귀 | 사용자 입력·저장·재시작 증거 기록, 임시 에셋 정리 |

## 9. 완료 조건과 검증 방법

| 항목 | 필요한 증거 |
| --- | --- |
| 컴파일·기존 데이터 | Unity 컴파일, 기존 1단계 검증 재실행, 저장 형식 불변 |
| 진입·전환 | 메뉴/Inspector 버튼으로 열기, A/B 에셋 전환 후 독립성, 미선택/삭제 대상 안전 처리 |
| 표시 | 실제 창에서 100칸·좌표·각 상태·선택·오류 구분. 좁은 창에서 스크롤 접근 |
| 클릭·속성 | 활성 토글, 고정/무작위 추가·교체·지우기, 비활성 배치 보존과 재활성화 |
| 드래그 | 여러 칸·빠른 이동·반복 방문·보드 밖에서 놓기, 한 번의 Undo/Redo로 전체 복구 |
| 작업 중단 | 포커스/캡처 상실·대상 전환·창 닫기에서 임시 미리보기 취소, 이전 완료 편집 유지 |
| 무변경 작업 | 같은 상태 칠하기·빈칸 지우기로 에셋 dirty나 새 Undo가 생기지 않음 |
| 검사·오류 이동 | 최신 검사 결과, 보드 안 오류 클릭 강조, 보드 밖 오류 원문 유지, 검사만으로 변경 없음 |
| 오류 보존 | 중복/범위 밖 배치·미사용 색·칸 수 오류가 창 열기/그리기/정상 칸 편집/저장으로 사라지지 않음 |
| 저장·동기화 | 창과 기존 Inspector가 같은 에셋 상태를 표시. 저장·재로딩·별도 Editor 재시작 후 동일 |
| 정리 | 새 스크립트의 meta 보존, 임시 에셋 제거, 무관한 씬·패키지·사용자 파일 불변 |

편집 적용 메서드 검사만으로 포인터 조작 검증을 대체하지 않는다. 실제 Editor 패널의 포인터 이벤트·캡처·바인딩을 통해 드래그와 중단 경로를 검사한다. 레이아웃은 실제 창 화면으로 확인한다. 환경상 못한 항목은 구체적으로 미완료로 남긴다.

## 10. 주요 위험과 대응

- **목록 순서 변경 후 다른 항목 편집:** 선택은 좌표 기준으로 두고 매 적용 시 원본에서 해당 항목을 찾는다. 중복이면 임의 선택하지 않는다.
- **드래그 중 대상 변경:** 미리보기는 원본과 분리하고 전환 시 취소한다. 이전 대상에 지연 콜백이 쓰지 않도록 한다.
- **다른 Inspector와 상태 불일치:** 에셋을 하나의 원본으로 사용하고 외부 변경·Undo 시 조회와 표시를 갱신한다.
- **잘못된 데이터의 자동 소실:** 오류가 있어도 원본을 유지한다. 손댈 수 없는 칸은 이유를 보여주고 기존 목록 편집 경로를 제공한다.
- **보드 편집과 게임 규칙 구현 혼합:** 매칭·난수 결정·낙하를 실행하지 않는다. 다음 단계에서도 같은 레벨 에셋을 사용한다.
