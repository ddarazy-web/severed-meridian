## 현재 상태와 착수 조건

현재 코드에는 `BotBatchStatistics`, `BotRecordReplay`, `BotAnalysisReader`, `LevelAnalysisPanel`이 추가되어 있다. 전략별 성공률·이동 수·잔여 미션·같은 시드 비교를 난이도 추천의 입력으로 재사용할 수 있다. 다만 28단계 목표의 완료 체크는 아직 미확정이며 활성 Goal도 28단계다. 코드 존재를 단계 완료로 취급하지 않는다.

이번 요청은 후속 문서 작성이다. 기존 Goal을 변경하거나 29단계를 구현하지 않는다. 실행 요청 시 28단계 완료 증거를 먼저 대조하고, 미완료라면 남은 조건을 알린다. 이전 단계의 검사 수를 29단계 실적으로 가져오지 않는다.

## 목표와 범위

제작자가 결과·이력 화면에서 **예상 난이도, 그렇게 판단한 수치, 판단할 수 없는 이유**를 함께 확인하도록 한다. 결과가 나쁘다는 이유만으로 오류를 어려운 레벨로 평가하지 않는다. 추천은 제작을 돕는 참고 정보이며 레벨 구성이나 이동 횟수를 자동 변경하지 않는다.

포함: 5단계 예상 난이도, 표본 충분성·판단 보류, 설명과 조건부 태그, 평가 기준 버전, 과거 결과 구분, HTML 사용법과 검증.

제외: 봇 전략 변경, 인간 플레이 데이터 수집·보정, 자동 맵 생성·수정, 레벨별 복잡한 평가 옵션, 서버 분석, 학습 모델, 30단계 전체 제작 흐름 통합 검수. 통계·재생·파일 보관 기능은 28단계를 재사용한다.

## 평가 순서

1. 기록 무결성과 정의·실행 버전·시험 조건을 확인한다.
2. 오류·중단·미실행 및 정상 종료 수를 구분한다. 성공률 분모는 기존처럼 정상 종료만 사용한다.
3. 평가 가능한 표본인지 판단한다. 보류 사유가 여러 개면 함께 보여준다.
4. 전략별 성공률과 같은 시드 비교를 읽고 예상 등급을 계산한다.
5. 성공 판의 이동 여유와 정상 패배의 잔여 목표를 설명한다. 이를 실패의 원인으로 단정하지 않는다.
6. 근거가 충족된 태그만 붙이고 기준 버전·표본 수·과거 기록 여부를 표시한다.

분석기는 기록을 읽기만 한다. 비공개 진단 정보나 추천값을 봇 관찰 입력으로 전달하지 않는다. 원본 레벨·기록 파일·수동 시험·진행 중 봇 세션을 변경하지 않는다.

## 등급 기준 — 구현 초안

기존 기획은 5단계 이름만 확정했으며 수치 기준은 미정이다. 아래는 **봇 결과를 일관되게 분류하기 위한 초기 기준안**이다. 인간 체감 난이도와 일치한다고 주장하지 않으며 대표 레벨 결과를 보고 조정한 뒤 적용 기준과 이유를 기록한다. 중요한 기존 결정과 충돌하면 grill-me로 해당 쟁점 하나를 확인한다.

| 항목 | 초안 |
|---|---|
| 대표 성공률 | 기본·계획 전략 중 높은 성공률. 두 전략을 합쳐 200판 독립 표본처럼 취급하지 않음 |
| 매우 쉬움 | 대표 성공률 80% 이상 |
| 쉬움 | 60% 이상, 80% 미만 |
| 보통 | 40% 이상, 60% 미만 |
| 어려움 | 20% 이상, 40% 미만 |
| 매우 어려움 | 0% 초과, 20% 미만 |
| 최소 표본 | 두 전략 모두 정상 종료 100판 이상이며 예정 묶음이 완료된 경우 |

높은 쪽을 쓰는 이유는 한 전략이 놓친 풀이를 곧바로 레벨 자체의 어려움으로 판단하지 않기 위해서다. 대신 어떤 전략을 대표로 사용했는지와 두 성공률을 반드시 함께 보여준다. 계획 전략이 항상 더 잘한다고 가정하지 않는다. 대표 전략이 바뀌면 비교 화면에서 드러낸다.

등급 계산에는 반올림 전 성공률을 사용한다. 경계값 바로 아래·정확히 일치·바로 위를 검증한다. 남은 이동 수는 등급에 임의 가중치로 합산하지 않고 보조 근거로 제공한다. 기준을 한 곳에서 관리하되 레벨마다 조정할 설정 화면이나 새 설정 에셋은 만들지 않는다.

## 판단 보류와 표본의 한계

다음 경우 숫자 통계는 참고로 표시하되 등급은 `난이도 판단 보류`로 한다.

- 정합성 문제, 실행 오류, 손상·누락 등 입력 기록 검증 실패.
- 일부 실행·중단·미실행, 한 전략 누락, 전략별 정상 종료 수 부족.
- 양쪽 모두 성공 0판. `이번 시험에서 성공 사례 없음`으로 표시하며 해결 불가능 또는 매우 어려움으로 확정하지 않는다.
- 필요한 평가 입력이 없거나 지원하지 않는 기록·규칙 버전인 경우. 과거 통계 조회와 현재 기준 평가 가능 여부는 별개로 판단한다.

레벨이 수정되면 이전 결과는 저장된 과거 정의에 대한 추천으로만 표시한다. 현재 레벨의 난이도로 승격하지 않는다. 새 검사가 필요한 이유를 안내하되 자동 실행하지 않는다.

신뢰도를 임의 백분율로 표시하지 않는다. `정상 종료 기본 100판 / 계획 100판`, `같은 시드 비교 100쌍`, `사람의 체감 난이도는 미검증`처럼 확인 가능한 정보를 제공한다. 표본 수가 많아도 봇의 한계가 사라지지는 않는다. 새 시드 묶음에서 등급이 달라질 수 있다는 안내를 유지한다.

## 판단 근거와 태그

| 표시 | 필요한 근거와 한계 |
|---|---|
| 등급 근거 | 대표 전략·정상 종료/성공 수·정확한 성공률·적용 구간·평가 기준 버전 |
| 계획 요구 | 같은 시드 정상 종료 쌍에서 계획만 성공한 수와 기본만 성공한 수를 비교. 단순 성공률 차이만으로 인과관계나 인간의 계획 능력을 단정하지 않음 |
| 이동 여유 부족 | 성공 판의 남은 이동 수와 최초 이동 수를 사용. 행동 개수나 라스트팡 표시 수로 대체하지 않음 |
| 무작위 영향 큼 | 현재 기록에서 공급 조건의 영향을 다른 원인과 분리할 근거가 있는지 먼저 검토. 성공/실패가 섞였다는 사실만으로 붙이지 않음 |
| 실패 시 남은 목표 | 정상 패배의 미션별 잔여 수를 기존 집계로 표시. 중복 미션과 동적 목표를 합치거나 초기 목표로 잘못 정규화하지 않음 |

태그 초기 후보 기준은 `계획 요구`: 정상 쌍 100개 이상, 계획만 성공−기본만 성공 비율 차이 20%p 이상, 서로 다른 결과의 쌍 20개 이상이다. `이동 여유 부족`: 대표 전략 성공 표본 20판 이상, 남은 이동 수 중앙값이 최초 이동 수의 10% 이하이다. 모두 검증된 인과 지표가 아닌 제작용 휴리스틱 초안이며 실제 표본에서 오탐을 검토하고 최종 기준을 기록한다.

`무작위 영향 큼`은 근거가 부족하면 태그를 숨기고 미지원 이유를 문서에 남긴다. 이 태그 하나를 위해 공급 시뮬레이터나 대규모 추가 실험 체계를 만들지 않는다. 보류 상태에서는 단정적인 태그를 붙이지 않는다. 추천 화면에서 기존 사례 목록과 재생으로 이동해 근거를 확인할 수 있도록 한다.

## 구조·버전·화면

- `Assets/Scripts/Features/AutoPlay/Runtime/Analysis`에 평가 계산과 결과를 둔다. 순수 계산이 파일·Editor·봇 실행을 의존하지 않게 한다. 기존 통계를 재계산하는 별도 집계기를 만들지 않는다.
- `AutoPlay/Editor/Presentation`의 결과·이력 화면에 작은 추천 요약 영역을 추가한다. 등급 또는 보류 이유, 근거 펼치기, 관련 사례 확인 순으로 배치한다.
- 기준 버전은 등급 구간·표본 조건·태그 기준을 함께 식별한다. 기준 변경 시 버전을 올리고 비교할 때 명시한다. 같은 기록·같은 기준은 같은 결과를 내야 한다.
- 기본은 기존 원시 기록에서 추천을 다시 계산한다. 과거에 저장하지 않은 추천을 당시 추천이라고 표시하지 않는다. 현재 기준 재계산임을 명시하고 기록 내보내기 형식을 불필요하게 변경하지 않는다.
- 전략/게임 버전과 평가 기준 버전을 구분한다. 서로 다른 실행 버전 기록을 합치거나 차이를 레벨 변경 효과로 단정하지 않는다.
- 최소 창 크기, 긴 사유의 줄바꿈·스크롤, 탭 이동, 기록 선택 변경을 확인한다. `i` 아이콘의 툴팁과 클릭 시 해당 HTML 설명 연결을 제공한다.
- 판단 보류의 우선순위, 분모, 경계값, 대표 전략 선택과 버전 처리는 상세한 한국어 주석으로 설명한다.

## 작업 순서와 검증

| 순서 | 작업 | 완료 확인 |
|---|---|---|
| T1 | 선행 완료·입력 계약·기준 초안 확인 | 28단계 완료 증거, 코드/기획 대조, 보존 대상과 기준 결정 기록 |
| T2 | 평가 가능 여부와 5등급 계산 | 수기 기대값, 0판/전부 오류/전부 실패/일부 실행/전략 누락, 모든 등급 경계 |
| T3 | 근거·태그·기준 버전 | 표본 누락과 태그 경계, 계획 전략 역전, 같은 입력 재현, 과거 기록 구분 |
| T4 | 결과·이력 UI 연결 | 실제 Unity 최소 크기, 긴 설명, 기록/탭 이동, 사례 연결, 도움말 |
| T5 | 대표 레벨 시험과 조정 | 최소 3개 서로 다른 레벨, 각 100개 시드×두 전략. 정의·시드·버전·소요 시간 기록 |
| T6 | 회귀·문서·완료 감사 | 통계/재생/내보내기 보존, 원본·사용자 변경 보존, 조건별 증거·한계·사용법 |

대표 레벨은 쉽게 성공하는 구성, 이동 여유가 적은 구성, 복합 장애물 구성을 포함한다. 원하는 등급이 나오도록 결과를 꾸미지 않는다. 동일 레벨 하나는 새 시드 묶음으로 한 번 더 시험해 등급·태그 변화와 표본의 한계를 기록한다. 호환되는 기존 기록은 재사용 가능하지만 신규 실행과 분리하여 보고한다. 모든 5등급·오류 경계는 작은 합성 표본으로 검사하고 실제 게임 실행과 혼동하지 않는다.

실제 사람의 평가가 없으면 인간 체감 보정 완료로 표시하지 않는다. 수치 조정의 사유·전후 차이·기준 버전을 남기고, 적절성을 입증하지 못한 태그는 보류한다. 이번 단계는 추천 기능과 설명 가능성을 검증하며 전체 제작 흐름 종합 검수는 30단계로 유지한다.
