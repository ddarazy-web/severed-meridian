## 목표와 착수 전 확인 상태

두 파워 블록을 직접 교환하여 조합 10종의 전용 효과를 실행하고, 기존 Match 실행 시험에서 효과·목표 예약·미션 진행·후속 연쇄를 확인한다. 15단계는 하나의 목표이며 내부 작업을 범위 조합, 드론 조합, 자석 조합, 통합 검증으로 나눈다.

14단계는 완료 조건 20개와 검사 924개를 통과했다. 실행 전 문서 갱신 당시 `Logs/TargetPowerVerification/final-source-hashes.json`과 소스 불일치 0건, 활성 Goal 없음을 확인했다. 아래 현재 구조 설명은 착수 전 기준이다. [14단계 완료 감사](../../../../Logs/TargetPowerVerification/completion-audit.json)를 선행 증거로 사용했고 15단계 착수 때 다시 대조했다.

현재 `ActionQuery`는 `SwapCombination`을 구분하지만 `BoardActionExecutor.Supports`는 조합만 거절한다. `PowerEffectResolution`은 파워 4종의 단독/피격 발동과 드론 요청·착탄 큐를 처리한다. `MissionProgressRules`가 실제 색상/상자 진행량과 대상 기여를 계산하고 `DroneTargetManager`가 한 칸 목표의 후보·예약·재탐색을 담당한다. 따라서 이번 핵심 변경은 **조합 전용 효과 구성과 드론 예약의 한 칸→직접 효과 범위 확장**이다.

기준 실행 버전은 `board-action-targeting-v4`, `power-effects-targeting-v2`다. 조합 지원으로 결과가 달라지므로 구현 시 관련 알고리즘 버전을 갱신하고 재현 기록에 남긴다.

## 확정된 조합 효과

조합 종류는 입력 순서와 무관하지만 효과 중심은 **첫 번째로 선택해 움직인 블록의 도착 칸, 즉 두 번째 선택 칸**이다. 입력 순서를 뒤집으면 중심이 달라질 수 있다. 로켓의 가로/세로는 별도 조합 종류가 아니다.

| 조합 | 효과 |
|---|---|
| 청소로켓 + 청소로켓 | 중심을 지나는 가로 1줄 + 세로 1줄. 원래 방향과 무관 |
| 청소로켓 + 달 폭탄 | 중심 기준 가로 3줄 + 세로 3줄 |
| 달 폭탄 + 달 폭탄 | 중심 기준 5×5 |
| 청소로켓 + 수거드론 | 중심 `+` 5칸 처리 후 목표 선정, 도착 칸에서 원래 로켓 방향의 1줄 |
| 달 폭탄 + 수거드론 | 중심 `+` 5칸 처리 후 목표 선정, 도착 칸에서 3×3 |
| 수거드론 + 수거드론 | 중심 3×3 처리 후 드론 3대가 각각 목표 한 칸 타격 |
| 무지개 자석 + 청소로켓 | 존재하는 일반 블록 색 하나를 무작위 선택, 해당 색 모두 로켓 변환·발동. 각 로켓 방향은 별도 무작위 |
| 무지개 자석 + 달 폭탄 | 선택 색 일반 블록을 모두 폭탄 변환·발동 |
| 무지개 자석 + 수거드론 | 선택 색 일반 블록을 모두 드론 변환·발동. 각 자리 `+` 후 추가 목표 한 칸 |
| 무지개 자석 + 무지개 자석 | 활성 보드 전체 칸에 직접 타격 1회씩 |

- 조합은 사용자 직접 교환에서만 발생한다. 피격된 기존 파워는 단독 효과를 발동한다.
- 입력 파워 두 개는 조합 재료로 한 번씩 소모한다. 두 재료의 단독 효과를 추가 발동하지 않는다. 유효한 조합은 이동 횟수 1회만 소비한다.
- 비활성/보드 밖은 타격에서 제외한다. 로켓은 비활성 칸을 넘어 끝까지 관통하며 벽은 파워 범위를 막지 않는다. 벽을 사이에 둔 교환 자체는 기존대로 금지한다.
- 일반 블록이 없으면 자석+자석은 허용한다. 자석+다른 파워는 거절하며 교환·이동 수·난수를 보존한다.
- 자석의 색은 현재 존재하는 일반 블록의 서로 다른 색 중 균등 선택한다. 단일 색은 색 선택 난수를 소비하지 않는다.
- 자석 변환 파워는 매칭 생성 파워 보호의 예외로 즉시 발동한다. 기존 매칭 생성 보호를 전체적으로 해제하지 않는다.
- 일반/조합 드론 모두 남은 미션 우선, 없으면 타격 가능한 일반 블록, 그것도 없으면 추가 타격 없이 끝낸다. 다른 드론의 예약과 실제 턴 피해 제한을 반영한다.
- 모든 효과와 드론 착탄이 끝난 뒤 정착하고 자동 매칭을 진행한다. 상자는 전체 턴에서 최대 1피해를 유지한다.

## 실행 시 채택할 세부 정책 제안

아래 내용은 확정 기획의 실행 순서 빈틈을 채우는 제안이다. 이 계획을 지정한 개발 실행 요청에 포함하되, 착수 시 실제 14단계 구조 및 확정 규칙과 충돌하면 근거를 제시하고 해결한다.

### 공통 조합 진입

1. 기존 행동 조회로 좌표·인접·벽·이동 수·실행 단계·지원 보드를 검사한다.
2. 작업 사본에서 교환 전 종류와 로켓 방향을 보존하고 교환 중심을 두 번째 좌표로 확정한다. 조합 종류 정규화 과정에서 입력 좌표를 정렬해 중심을 바꾸지 않는다.
3. 두 재료를 조합 소모로 등록한 뒤 전용 효과를 실행한다. 두 파워의 교환으로 일반 색 매칭을 새로 생성하지 않는다.
4. 피해·미션 집계·기존 파워 피격 연쇄는 공통 처리로 전달한다. 각 조합이 보드를 직접 별도 규칙으로 지우지 않는다.
5. 성공 시 상태를 반영하고 이동 수 1회·턴 1회를 소비한다. 실패 시 해당 행동의 보드·미션·난수·예약·턴 문맥을 모두 폐기한다.

가로/세로 범위가 겹치는 중심은 한 직접 효과 안에서 좌표 중복을 제거한다. 이후 기존 파워가 만든 별도 효과는 정상 처리하되 중복 발동 방지와 상자 피해 제한을 공유한다. 자석+자석의 직접 전판 타격과 이에 따른 피격 연쇄를 기록에서 구분한다.

### 드론 조합과 범위 예약

- 14단계의 즉시 효과 스택·드론 요청·착탄 대기 순서를 재사용한다. 로켓/폭탄 조합은 국소 `+`와 즉시 연쇄 후 요청하고, 드론+드론은 국소 3×3 후 요청 3개를 등록한다.
- 드론+드론의 추가 3대는 한 칸 타격 요청이다. 출발지에 `+`를 세 번 더 만들지 않는다.
- 요청은 한 칸/가로줄/세로줄/3×3의 실제 도착 효과를 포함한다. 로켓 방향은 교환 전 재료에서 보존한다.
- 후보 조회는 직접 도착 범위의 반응과 남은 미션 기여를 합산한다. 범위에 미션 대상이 있다는 이유로 빈칸이나 임의 파워를 새로운 조준 후보로 만들지 않는다. 현재 지원 대상의 유효 조준 칸을 기준으로 평가한다.
- 조준 칸과 직접 범위 안에서 타격할 미션 대상을 함께 예약한다. 추가 연쇄의 미래 피해는 예약하지 않는다. 실제 진행과 예상 진행을 구분하고 같은 대상의 예상 기여를 중복 집계하지 않는다.
- 예약 필터는 도착 효과 종류·로켓 방향까지 구별한다. 한 칸 후보 캐시를 3×3 후보로 그대로 재사용하지 않는다. 상태 변경 시 전체 재평가하는 14단계 방식을 유지한다.
- 범위에 다른 예약 대상이 겹치면 그 대상을 신규 예약/예상량에서 제외한다. 남은 미예약 기여가 없다면 미션 후보로 추천하지 않는다. 실제 타격 범위를 예약 때문에 잘라내지는 않는다. 앞선 착탄이 다른 목표를 제거하면 해당 드론은 착탄 전에 재탐색한다.
- 무효화 시 자기 예약과 예상량만 반환하고 미션 후보부터 재탐색한다. 방향과 효과 종류는 유지한다. 실제 턴 피해 기록은 해제하지 않는다.
- 14단계에서 보완한 소실 예약의 예상량 재평가를 범위의 각 대상에 적용한다. 조준 칸이 남아 있어도 범위 내 미션 대상이 사라지거나 실제 목표가 완료되면 기여를 다시 계산한다. 예상량은 대상 좌표별로 관리하여 겹치는 범위의 같은 상자를 두 번 제거 예정으로 세지 않는다.

### 자석 변환과 발동

- 두 조합 재료 소모 후 존재 색을 선택하고 해당 색의 일반 블록 좌표 목록을 고정한다. 좌표 순서는 행·열 순으로 고정한다.
- 첫 폭발 전에 대상 모두를 변환하고 로켓 방향을 확정한다. 처리 도중 공급되거나 다른 경로로 생긴 블록까지 변환 대상에 추가하지 않는다.
- 모든 변환 파워를 공통 효과 처리에 발동 예약한다. 먼저 피격되어 이미 발동한 파워의 원래 예약은 중복 발동하지 않는다. 각 변환 파워는 정확히 한 번 발동한다.
- 변환한 일반 블록의 원래 색은 14단계 소비 정책과 일관되게 1회 수집으로 집계한다. 변환 파워 발동 시 같은 색을 다시 집계하지 않는다. 원래 있던 파워에는 색을 부여하지 않는다.
- 자석+드론의 모든 요청과 기존 파워 연쇄에서 나온 드론은 같은 목표 관리자를 공유한다. 변환만으로 미션이 완료되면 최신 진행량으로 목표를 정한다.
- 거미줄 비변환/한 단계 피해, 곰팡이 은폐 제외는 향후 해당 보드 지원 때 적용한다. 이번에는 사전 미지원으로 처리하며 기획을 바꾸지 않는다.

| `Assets/Scripts/Editor/Levels` | 기존 Match UI의 조합/중심/색/방향/예약 기록 및 검증 |

조합 효과 구성은 `Assets/Scripts/Features/PowerBlocks/Runtime/PowerCombinationResolution.cs`를 책임 분리 후보로 두고 착수 시 기존 처리와의 경계를 확정한다. 조합마다 별도 매니저/실행 엔진을 만들지 않는다. 새 패키지·asmdef·게임명 폴더·전역 관리자·범용 효과 프레임워크를 추가하지 않는다. 원본 레벨 정의, v4 저장 형식, GUID/meta, 기존 에셋과 무관 파일을 보존한다. 런타임 프리팹·플랫폼 설정 변경은 필요하지 않다.

## 실행 승인 후 작업 순서

| 순서 | 작업 | 입력 → 산출물 | 완료 검증 |
|---|---|---|---|
| 1 | 선행 확인 | 14단계 기록/소스 → 착수 기준·파일 책임·정책 기록 | 실제 완료 증거, 회귀 기준, 보존 해시 |
| 2 | 범위 조합 3종 | 기존 효과 처리 → 로켓+로켓/폭탄, 폭탄+폭탄 | 중심·범위·중복·재료 소모·비용 |
| 3 | 드론 조합 3종 | 2 및 14단계 목표 관리 → 범위 요청·드론 3대 | 국소 후 조준·방향·범위 예약·재탐색 |
| 4 | 자석 조합 4종 | 2~3 → 일괄 변환/전판 타격 | 색·방향 난수·발동 1회·진행량 |
| 5 | Match 통합 | 2~4 → 조회/실행/표시·후속 연쇄 | 실제 입력·다음 수·단계/끝까지 일치 |
| 6 | 완료 감사 | 전체 변경 → 정답·재현·회귀 기록 | 목표 문서 조건별 근거·임시 자원 정리 |

공유 효과 처리와 목표 관리 변경이 겹치므로 순차 수행한다. 단계마다 정답 사례를 먼저 확보하고 구현·검증한다. 실패하면 원인을 수정하고 해당 검사와 영향 검사를 재실행한다. 선행 단계 미완료를 15단계 완료로 덮지 않는다.

## 검증 기준

- 10종 각각 입력 양방향, 이동 수 1회, 재료 2개 소모, 두 번째 좌표 중심. 로켓 방향 변형과 비대칭 보드로 중심 오류 검출.
- 3종 범위 조합의 정확한 좌표 집합. 모서리·구멍·벽·분리 구역·10×10에서 로켓 관통과 범위 겹침 검증.
- 드론 국소 타격 후 남은 미션 조회, 실제 조합으로 복수 예약, 목표 부족/없음, 부분 기여, 범위 겹침·목표 소실·재탐색·해제.
- 서로 다른 도착 효과의 캐시 구별, 조회 무변경, 실제 상태 변경 후 갱신, 예상 기여의 중복 방지.
- 조준 칸 보존/범위 내 대상 소실, 다른 예약의 부분 무효화, 겹친 상자 예상 제거 수와 실제 턴 피해 제한을 함께 검증한다.
- 자석 실제 존재 색/단일 색/색별 개수 불균등, 일반 블록 없는 교환 예외, 모든 대상 선변환, 로켓별 방향 난수, 피격 선발동 중복 방지.
- 자석+드론에서 변환 집계 뒤 최신 미션 조회 및 공유 예약. 변환/피격/착탄 소비 집계와 상자 완전 제거만 진행량 반영.
- 보호된 매칭 파워 유지, 변환 파워 즉시 발동, 기존 파워의 단독 연쇄, 한 턴 상자 1피해, 마지막 수의 모든 효과 완료 후 정착.
- 실패 단계의 보드/미션/난수/예약 보존, 앞선 성공 단계 유지, 내부 처리 한도 진단. 사용자 옵션 추가 없음.
- 실제 Match 창에서 10종 교환, 1000/680 폭 기록 가독성, 변경/초기화/창 닫기 중 실행 해제. 조합만 가능한 보드의 지원 가능 행동 판정.
- 동일 정의·시드·행동열·알고리즘 버전의 전체 상태, 변환 방향, 예약/착탄 순서와 미션을 독립 Unity 프로세스에서 재현.
- Unity 컴파일 및 8~14단계 영향 회귀. 이전 조합 거절 검사는 새 허용 규칙으로 갱신하되 일반 블록 없는 자석 거절과 무변경 검사를 유지한다. 과거 검사 수를 이번 결과로 합산하지 않는다.
- 원본 정의/dirty/v4/GUID/meta·무관 파일 보존과 소유 임시 에셋/프로세스 정리. 검증 못 한 항목을 완료로 표시하지 않는다.

## 후속

이번 단계 완료 후 장애물별 실제 반응·미션 지원을 확장하고 승패까지 연결할 다음 범위를 정한다. 파워 조합 완료만으로 전체 게임 플레이 또는 봇 난이도 평가가 완료됐다고 표현하지 않는다.
