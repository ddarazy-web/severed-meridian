> `superpowers:executing-plans`로 직접 실행한다. 하위 에이전트·커밋·푸시는 사용하지 않는다.

상태: 완료. A 데이터3종, B 실제 제작500개/반복 시간·할당/native 준비·실행, C 새 행동/필요 정책, D 현재85종692682 PASS/FAIL0·전량 논리/보존 감사·추가 안내·전체 목표20개 연결을 완료했다. 2026-10-07.

**Goal:** 기존 행동을 사용하는 새 종류와 새 고유 행동의 추가 절차를 실제로 검증하고, 500개 제작 정의의 도구·저장·실행·준비 비용을 확인한다.

**Architecture:** 1~4단계의 영구 ID, 불변 규칙/시각 카탈로그, 등록 행동, 선택 정책, 제작 도구와 공통 표시 슬롯을 사용한다. 콘텐츠 추가와 새로운 행동 구현을 구분하며 검증된 중복만 정리한다. 전체 실행기나 UI 프레임워크를 다시 설계하지 않는다.

**Tech Stack:** Unity 6000.3.10f1, 기존 C#·UI Toolkit·SerializedObject/Undo·uGUI·Addressables·MemoryPack·asmdef.

## 시작 기준과 제약

- 시작 시 work의 실제 HEAD·미커밋 변경·4단계 완료 감사와 보존 manifest를 기록한다. 4단계 시작 HEAD b03ac0539e0286bd67763c88fcbd16f8316ac452로 임의 복원하지 않는다. 1~4단계와 기존 WIP를 보존한다.
- 규칙 스키마5/팩2·구형4/1·50레벨 구간·9×9·기존 enum 숫자·원본 GUID·위치·연결·규칙 난수와 드론 상승/개별 호버/돌진/재탐색을 유지한다. 아트 값은 룰 팩/지문과 분리한다.
- 빌드·Addressables 콘텐츠 빌드·디스크 레벨 팩 재생성·전체 원본 변환·이미지 생성/수정·커밋·푸시·하위 에이전트·사용자 Editor 종료·임의 씬 저장은 금지한다. 저장 검증은 임시 제작 에셋과 메모리 팩으로 수행하고 복원한다.
- 새 패키지/asmdef·범용 정책 언어·생산 리플렉션·전면 MVVM·새 UI 프레임워크·봇 전략/승률 개선·팝업/튜토리얼/고물탑 구현은 제외한다.
- 500개는 실제 제작 입력을 통해 구성하는 검사 콘텐츠다. 500종의 새 이미지나 출시 콘텐츠를 자동 생산하지 않는다. 기존 이미지의 명시적 공유 별칭을 사용한다.
- 검사 과정의 원문·실제 종료·입력/출력 복원·소스 경계를 보존한다. 4단계의 검사 계약 보정과 기존 실패를 새 런타임 결함이나 통과 근거로 혼동하지 않는다.

## A. 데이터만으로 새 종류 3개 추가

- [x] 서로 다른 기존 행동을 쓰는 신규 영구 ID3개를 제작 입력과 명시적 시각 정의/공유 별칭으로 구성한다. 기존 enum·규칙 클래스·종류별 조건문을 추가하지 않는다.
- [x] 편집 선택→배치→저장/메모리 왕복→게임 실행에서 배치·피해·제거·미션·공급·세 보드 표시를 실제로 확인한다. 이 중 최소 하나는 2×2, 하나는 층 요소로 기존 본체/칸 집계 경계를 포함한다.
- [x] 누락/중복 ID·미지원 상태/이미지·생성 참조·행동 불일치를 명시적으로 거절하는 사례를 포함한다. 미등록값을 일반 종류로 대체하지 않는다.
- [x] 새 종류 추가에 필요한 데이터/코드 변경 수를 기록한다. 데이터 사례 때문에 런타임을 바꿨다면 확장 결함의 실패→최소 수정→통과 근거를 제시한다.

## B. 실제 제작 카탈로그 500개와 비용

- [x] 단순 메모리 ID 배열이 아닌 기존 제작 입력으로 500개 정의를 구성한다. 본체·층·공급·생성 참조·표현 별칭을 섞고 정순/역순 ID 조회·중복/누락 검사를 수행한다.
- [x] 실제 카탈로그 도구의 검색·필터·선택·검증·저장/복원·Undo/Redo·구독 해제를 확인한다. 가상화 목록의 표시 수와 썸네일 준비 수를 기록해 전체 이미지/편집 UI 선생성을 피한다.
- [x] Asset과 메모리 팩2의 동등성, 50→51 경계, 원본 제외 계약·규칙 지문 독립을 확인한다. 디스크 배포 팩을 다시 만들지 않는다.
- [x] 일부 종류만 쓰는 레벨과 공급/행동으로 추가 종류가 생기는 레벨에서 실제 native 주소 요청, 슬롯 생성/반환, 준비 용량 안 반복의 추가 생성0을 비교한다.
- [x] 제작/검색/검증/저장/실행·준비의 시간과 할당을 같은 환경에서 측정한다. 측정 API·표본/워밍업·보드 크기·종류 수·Editor/Play Mode를 기록한다. 기준 없이 성능 통과나 모바일 성능을 주장하지 않는다. 보드 행동마다 전체500개 카탈로그를 검색하지 않는 호출 경계를 확인한다.

## C. 새 행동 등록과 필요한 드론 정책

- [x] 기존 행동 조합으로 표현할 수 없는 최소 새 행동의 검사 사례를 먼저 정의한다. 공식 게임 규칙에 넣는 동작 변경이 필요하면 그 의미만 논의하고 A/B는 계속한다. 검사 전용 행동을 출시 규칙에 자동 편입하지 않는다.
- [x] 실제 행동 구현·등록·제작 정의·검증으로 확장을 증명한다. 공통 교환·매칭·낙하·연쇄·피해/미션 실행기를 복제하거나 새 종류 분기를 추가하지 않는다.
- [x] 기존 정책에 맞지 않는 목표만 필요한 선택 정책을 등록한다. 등록된 다수 정책 중 활성 미션/대상에 해당하는 정책만 호출하고 같은 후보 검색은 공유한다. 호출 횟수와 후보 검색 횟수를 기록한다.
- [x] 미션 완료·새 공급/생성·연쇄·예약 변경·착탄 재검증 및 공개 동일 입력 쌍을 확인한다. 비활성 정책 호출0·규칙 난수 의미·숨은 정보 차단을 유지한다.

## D. 검증된 중복 정리와 인수인계

- [x] 사용처와 구형4/1 읽기 경계를 먼저 확인한다. 동일 결과가 증명된 중복 규칙/표현 분기/임시 어댑터만 제거한다. 삭제 후보마다 현재/구형 호출부와 전후 동등성 근거를 기록한다. 제거할 근거가 없으면 유지 이유를 남긴다.
- [x] A~C에서는 관련 검사만 실행한다. 최종 런타임에서 기존30종·드론9종·제작/저장12종·그래픽3종·4단계 신규22종/수명3종과 5단계 신규 사례의 실제 종료0/FAIL0을 확인한다. 실제 변경/실패 없이 통과한 전체 검사를 반복하지 않는다.
- [x] 전량 논리 비교, 원본/팩/에셋/GUID/과거 증거/WIP 보존을 감사한다. 표현/식별자의 의도적 차이와 실제 규칙 차이를 분리한다.
- [x] 데이터 콘텐츠 추가와 새 행동/정책 추가의 절차·필수 검사·파일·호환 경계·복구 방법을 사용 안내에 정리한다. 상세 튜토리얼/고물탑 매뉴얼은 포함하지 않는다.
- [x] 전체 목표의 각 완료 조건을 1~5단계 현재 증거와 연결하고 미검증 항목을 구분한다. 완료 보고에 실제 측정치·플랫폼 한계·남은 문제를 포함한다. 후속 구현을 자동 시작하지 않는다.

## Review Focus

1. 500개 메모리 색인만으로 실제 제작·도구·저장 규모 검증을 대체하지 않았는가.
2. 데이터만 추가한다면서 enum/실행 분기를 늘리거나 모든 이미지/풀을 미리 준비하지 않았는가.
3. 새 행동이 공통 실행기를 복제하거나 공식 규칙을 승인 없이 바꾸지 않았는가.
4. 정책 등록 수와 실제 호출 수·공유 검색 수를 구분했는가. 예약·생성·미션 완료 후 갱신을 검증했는가.
5. 삭제한 어댑터에 구형 저장/실제 화면 호출이 남거나 봇에 비공개 데이터가 전달되지 않는가.
6. 시간/할당·Editor/native 검증을 실기기 성능/빌드 보증으로 확대하지 않았는가.

## 완료와 검증 경계

[최종 기록](../../../Verification/MoonRabbitJunkyard/ElementFramework/phase-05-progress.md)의 실제 종료·원문·현재 소스 경계로 판정했다. 수백 종류 제작/실행과 필요한 주소만 준비하는 native 범위를 확인했고, 실기기/새 번들/픽셀 동등성을 완료로 확대하지 않았다. 작성자가 직접 자체 검토했으며 사용자 지시대로 하위 에이전트와 커밋을 사용하지 않았다. 후속 구현은 자동 시작하지 않는다.
