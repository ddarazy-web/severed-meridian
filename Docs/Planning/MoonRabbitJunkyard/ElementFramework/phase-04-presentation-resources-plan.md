상태: 완료. A~D·최종79종691470 PASS/0 FAIL·실제 종료0, 전량 논리/원본 보존 감사를 확인했다. 2026-10-07. 검사 계약 변경과 한계는 [완료 기록](../../../Verification/MoonRabbitJunkyard/ElementFramework/phase-04-progress.md)에 보존했다. 다음5단계는 문서만 작성했다.

**Tech Stack:** Unity 6000.3.10f1, 기존 C#·UI Toolkit Editor·uGUI·SpriteRenderer·Addressables·MemoryPack·asmdef.

**Spec:** [통합 설계](../../../Systems/MoonRabbitJunkyard/2026-10-04-element-framework-design.md) · [통합 가이드](integration-guideline.md).

## A. 시각 정의와 공통 조회

대상: `Elements/{Data,Runtime,Editor}/`, `LevelEditor/Editor/Presentation/Board/`, `PuzzlePlay/Editor/Presentation/`, `GameScreen/Runtime/World/`의 기존 아트 조회와 실제 보드 표시 호출부.

권장 책임: `ElementVisualDefinition`/제작 원본과 배포 값, 불변 `ElementVisualCatalog`, `ElementVisualState`, `ElementVisualResolver`, Editor의 시각 정의 검사. 기존 책임과 겹치면 파일/이름을 조정하고 이유를 기록한다.

인터페이스: `Resolve(ElementId, ElementVisualState)`는 이미지/프레임 키·피벗·크기·정렬·효과 키를 반환한다. 상태에는 표시할 색·내구도·충전/필요충전·방향·프레임·논리 크기가 들어간다. 규칙/난수/원본을 변경하지 않는다. 기존 enum 경로는 구형 시각 정의를 구성하는 호환 어댑터 한 곳에서만 사용하고 새 ID는 등록된 값으로 조회한다.

- [x] 같은 행동의 서로 다른 두 ID가 서로 다른 시각 키를 선택하고, 여러 ID가 하나의 시각 정의를 공유하는 실패 검사를 확보한다. 중복/누락 ID·상태·프레임·자원 키를 해당 ID와 함께 보고한다.
- [x] 내구도·색·충전·방향·프레임·실제 점유 크기를 데이터로 조회한다. 기존 아트가 없는 상태는 명시적 상태 매핑/공유 프레임으로 표현하거나 준비 전에 거절한다. 숫자를 몰래 잘라 마지막 이미지로 대체하지 않는다. 새 이미지는 만들지 않는다.
- [x] 편집 보드·플레이 테스트 보드·게임 월드 보드의 실제 조회를 연결한다. 선택 팔레트 디자인은 바꾸지 않는다. 기존 로켓 가로/세로 비율·중심, 드론4컷, 2×2 크기·레이어·정렬·덮개/바닥을 보존한다.
- [x] 제작 입력/배포 배열을 바꾸거나 원본을 파기해도 구성된 카탈로그가 유지된다. 표현 편집 때문에 룰 팩/규칙 지문·게임 실행 값이 변하지 않는지 검증한다.

## B. 필요한 리소스 집합과 소유권

대상: `PuzzleArtwork`, `BoardSpriteAtlas`, `PuzzlePowerPlayback`의 준비, `PuzzleGameSession`/게임 진입의 후보 준비·교체·종료 호출부.

인터페이스: 리소스 계획은 초기 배치, 고정/랜덤/유지 공급, 미션 아이콘, 매칭/부스터/파워 조합, 정의의 행동·생성 참조에서 필요한 시각/효과 키를 수집한다. 방문 집합으로 순환을 종료하고 아틀라스 주소를 중복 제거한다. 계획 계산과 실제 로드/소유권을 분리한다.

- [x] 초기판에 없는 공급 대상·랜덤 선택·연결/행동 생성 대상·효과, 중복/순환 참조 사례를 확보한다. 미등록 참조는 ID 오류이며 카탈로그 전체를 그림 로드 대상으로 순회하지 않는다.
- [x] 계산된 주소 집합과 native Addressables 실제 요청을 비교한다. 미사용 장애물/효과의 별도 주소 요청0, 필요한 주소 누락0을 확인한다. 기본 파워/공유 아틀라스에 동반 포함된 프레임은 따로 기록한다.
- [x] 시작/다시하기/레벨 전환에서 후보 준비 성공 후 소유권을 교체하고, 실패/취소 후보만 반환한다. pending 로드 완료와 Addressables 지연 콜백 이후 실제 해제를 확인한다. 두 소유자의 공유 핸들과 독립 Sprite 클론을 함께 검사한다.
- [x] 배포 데이터에는 제작 원본 참조가 없고, 기존 아틀라스 주소/그룹 분할·로드/반환 계약을 유지한다. 빌드/재패킹 없이 메모리 입력과 기존 실제 자원으로 검증한다.

## C. 표시 슬롯·효과 풀의 공통 재사용

대상: `PuzzleWorldBoard`, 기존 보드 이미지/공급/마스크/효과 슬롯, `PuzzleBoardSnapshot`, 교환·제거·정착·파워 Playback과 세션 Reset 경계.

원칙: 고정 보드 슬롯과 필요량만 증가하는 효과 슬롯을 기능별로 재사용한다. 정의별 프리팹·풀을 늘리지 않는다. 현재 Draw가 색/회전/order를 모두 초기화하지 않고 Reset에 의존하는 사실은 [EF-11](../../../Verification/MoonRabbitJunkyard/ElementFramework/stage-11-progress.md)의 기준으로 다룬다.

- [x] 실제 renderer를 고의로 오염한 뒤 다른 ID·색·내구도·방향·시트/단일 프레임으로 재사용하는 검사를 먼저 확보한다.
- [x] 반환/다음 사용에서 Sprite·프레임·색·크기·위치·회전·정렬·마스크·효과·콜백·취소/예약 상태를 초기화한다. 선택/스와이프의 최상위 order와 손을 놓은 뒤 복원을 유지한다. Atlas 소유 자원을 슬롯 반환 때문에 해제하지 않는다.
- [x] 정상 종료·중간 취소·다시하기·전환·Destroy/메모리 씬 Unload의 실제 객체/마스크 수명을 확인한다. 준비된 용량 안의 같은 사용 반복에서 추가 생성0과 잔상0을 확인하고 최초 증가/반환 수를 기록한다.
- [x] 기존 낙하 동시 실행과 속도, 드론 상승→개별 호버→돌진·무효 목표 재선정·표적 예고 부재·프로펠러를 보존한다. 풀 개수 검사를 실기기 메모리 누수/프레임 성능 보증으로 확대하지 않는다.

## D. HUD 표시 상태·봇 공개 특성과 최종 통합

대상: `PuzzleHudView`/세션 HUD 갱신, 기존 입력/아이템 연결, `AutoPlay/Runtime/Execution/BotObservationBuilder`와 공개 DTO/소비 호출부.

인터페이스: Presenter가 읽기 전용 `PuzzleHudState`를 구성하고 View는 필요한 값과 기존 명령만 받는다. 미션은 기존 `DisplayedMissionProgress`에 해당하는 연출 진행값을 사용한다. 봇에는 허용된 공개 행동 특성만 새 값으로 복사한다. 런타임 정의·시각 정의 객체를 전달하지 않는다.

- [x] HUD 수집 연출 전/후·시작·일시정지·실패·다시하기·입력/아이템 잠금과 Presenter 구독/해제를 검사한다. 숫자가 최종 시뮬레이션 값으로 미리 바뀌지 않고 기존 프리팹 바인딩이 유지돼야 한다.
- [x] 새 ID가 종류별 피해 알고리즘 복제 없이 공개 행동 특성으로 관찰된다. 곰팡이 아래는 Unknown과 기존 마스킹을 유지한다. 전략/승률이나 실제 규칙 실행을 바꾸지 않는다.
- [x] ID/제작명/GUID·내부 인덱스/생성 이력·숨은 내용물·공급 순서·예약·난수만 다른 공개 동일 입력 쌍의 관찰/후보가 동일한지 확인한다. DTO 수정 불가·복사 독립성·원본/난수 무변경을 검사한다.
- [x] A~C 변경 중에는 관련 검사를 실행하고 최종 구현에서 한 번 전체 회귀를 수행한다. 기존30종·드론9종·3단계12종·그래픽3종 및 새 표현/자원/풀/HUD/공개 관찰 검사의 실제 종료0/FAIL0과 전량 논리 비교·원본 보존을 확인한다. 새 실패/실질 변경 없이 같은 전체 검사를 반복하지 않는다.
