## 목표와 시작 기준

남은 미션과 활성 요소의 특성에 필요한 목표 선택 정책만 등록 키로 조회한다. 모든 드론의 연출을 발동 위치 상승→시간차 호버→돌진으로 통일한다. 돌진 중 목표가 사라지면 현재 위치에서 멈춰 호버하고 다시 선택한 목표로 돌진한다. 선회와 목표 예고는 제거한다.

1단계 최종 기준은 신규4종819 PASS와 기존30종687011 PASS, 전체18182행·188팩·225팩 상태 동일이다. 이는 보존 기준이며 2단계 실행 결과로 재사용 표기하지 않는다. work 브랜치의 완료분과 기존 WIP를 유지한다.

## 실제 책임과 설계 경계

- `PowerBlocks/Runtime/DroneTargetManager.cs`: 작업 사본별 후보 캐시·요청별 예약·재검증·미션 기여·선택 난수 소유. Query는 읽기 전용, Reserve만 선택 난수를 소비한다.
- `PowerBlocks/Runtime/PowerEffectResolution.cs`: 효과와 착탄을 작업 사본에서 동기 해결한다. 논리 결과를 화면 프레임마다 다시 실행하지 않는다.
- `GameScreen/Runtime/World/PuzzleEffectTimeline.cs`: 논리 효과 기록을 표시 시간과 연결한다.
- `PuzzlePowerPlayback.Clips.cs`와 `PuzzlePowerPlayback.cs`: 비행 위치·프로펠라·시각적 보드를 재생한다. 시작 시점에는 3기 이하 단독만 LiftOnly이고 나머지에는 선회 분기가 남아 있었다.

시작 시점의 착탄 기록은 최종 표적과 Retargeted 여부 중심이었다. 이미 해결된 final 보드는 기존 목표도 제거된 상태일 수 있어, 이를 비행 중 표적 유효성 판정에 사용하면 안 된다. 기존 예약/해제/재탐색 기록과 효과 순서에서 출발 목표·소실 시점·재선택 목표를 확인하고, 부족한 정보만 실행 기록에 추가한다. 실제 피해와 미션은 기존 효과 실행기가 소유하며 표시기가 상태를 다시 변경하지 않는다.

정책 등록표는 행동 키 직접 조회를 사용한다. 남은 미션 종류와 실제 활성 정의의 반응/미션 특성으로 필요한 키 집합을 구성하고, 공통 후보 수집과 요청별 예약을 재사용한다. 모든 정책을 순회하여 Supports를 묻거나 드론마다 보드 전체를 독립 검색하지 않는다. 캐시는 기존 변경 근거/효과 문맥에 맞게 무효화한다. 새 범용 이벤트 버스나 정책 DSL은 만들지 않는다.

### B. 논리 기록과 비행 구간 연결

## 검증 진입점과 운영

현재 공개 진입점은 `Levels.Editor.TargetPowerVerification.Data`, `Supplemental`, `FinalChecks`, `Regression` 및 UI `Start`/`Restart`, `GameScreen.Editor.PuzzlePowerAnimationVerification.Run`/`RunScene`이다. 실행 전 실제 소스와 출력 경로를 다시 확인한다. 기존 선회 기대만 확정 요구에 맞는 실패 검사로 대체하고 목표 선택/피해/미션 검사를 약화하지 않는다.

Run은 임시 씬 Play Mode, RunScene은 실제 게임 씬을 연다. EditorApplication.Exit을 사용하는 검사는 별도 검사 Editor에서만 실행한다. 사용자 Editor를 닫거나 씬을 임의 저장하지 않는다. 그래픽 검증을 nographics 데이터 검사 통과만으로 대체하지 않는다. 기존 로그를 백업하고 새 증거는 `Logs/ElementFramework/Phase02`, 보고는 `Docs/Verification/MoonRabbitJunkyard/ElementFramework/phase-02-progress.md`에 둔다.

빌드·Addressables 콘텐츠 빌드·팩 파일 재생성·이미지 생성·커밋·푸시·하위 에이전트는 사용하지 않는다. DTO/저장 버전/50레벨 구간/9×9/enum 숫자/밸런스와 기존 매칭·낙하 엔진을 유지한다. UI 제작/MVVM 시범은 구간3, 표현·리소스·풀 전환은 구간4로 남긴다. 목표 우선순위나 논리 타격 순서 변경이 필요하면 근거를 제시하고 그 변경만 논의한다.

## 사용자 확정 — 반복 실제 재선택 우선 (2026-10-06)

사용자가 첫 번째 선택지인 여러 차례 실제 재선택을 우선하고 논리 결과 차이를 기록하는 방식을 확정했다. 기존 일괄 해결의 최종 Land 한 번뿐인 검증 대신 실제 효과마다 활성 예약을 같은 정책/예약/규칙 난수로 검증한다. 이로 인한 목표 선택·예약 이력·난수 소비·후속 명중/미션/결과 차이는 승인된 행동 변경으로 원문 대조하여 보고한다. 다른 미션/피해/저장/팩 계약은 변경하지 않으며 일반 논리 차이를 무조건 동일로 표기하거나 정규화해 숨기지 않는다. 최초/최종 목표만 기록하는 것 또는 반복 재선택을 후속 단계로 제외하는 것으로 대체하지 않는다.
