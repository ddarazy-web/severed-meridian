# Windows 레벨툴 UI·UX 개선 — 4단계 통합 가이드

> 2026-10-09 · 1단계 구현·Unity 검증 완료, 2단계 계획 작성/구현 대기. 기존 게임·제작 도구 분리 1~6단계와 별개인 UI 개선 작업이다.

**Goal:** 기존 레벨툴 기능을 보존하면서 목업의 작업 중심 화면과 Windows 편집 도구의 익숙한 조작 방식을 적용한다.
**Architecture:** 기존 UI Toolkit 씬, AuthoringToolWorkspace/AuthoringEditSession 및 실행 어댑터를 재사용한다. 화면 배치와 명령 진입을 정리하며 저장 형식·퍼즐 규칙을 재작성하지 않는다.
**Tech Stack:** Unity 6000.3.10f1, C#, Runtime UI Toolkit, 기존 JSON·MemoryPack·Addressables.
**Spec:** 사용자가 승인한 [Windows 목업](../../MoonRabbitJunkyard/Mockups/level-tool-windows.html), 이번 문서의 UX·단축키 계약.

## 확정 요구와 범위

- 실제 `Assets/Scenes/LevelTool.unity`의 UI를 목업 형식으로 바꾼다. HTML을 게임 안에 삽입하지 않는다.
- 상단 작업 탭, 왼쪽 레벨/소재, 중앙 보드, 오른쪽 속성, 하단 검사·상태 구조를 적용한다.
- 복사·붙여넣기·저장·화면 조절 등 익숙한 단축키, 메뉴의 단축키 표시, 툴팁과 앱 내 도움말을 제공한다.
- 반복 작업의 편의, 한국어 용어, 상태 구분, 입력 포커스·스크롤·선택 유지, 잘못된 조작의 복구를 우선한다.
- 사소한 간격·문구·대비·포커스 개선은 구현하면서 반영한다. 저장 의미·기존 교체/손상 규칙·공유 데이터 소유권이 바뀌는 변경은 설명하고 논의한다.
- 기존 기능 대응 기준: [이전 기능 대응표](../../Verification/project-wide/game-authoring-stage-05-feature-matrix.md). 목업에 단순화된 연결·모양·공급·봇·기록·복구·공유 사본을 누락하지 않는다.
- 이번 문서는 통합 가이드다. 상세 계획·목표는 단계별 직전에 작성하고, 한 단계 완료 후 다음 단계 문서를 만든다. 다음 단계 구현은 자동 시작하지 않는다.

## 네 단계

| 단계 | 구현 범위 | 독립 완료 모습 |
|---|---|---|
| 1. 화면 틀·메뉴·공통 명령 | 화면 재배치, 작업별 진입, 저장 상태, 메뉴/단축키 공통 정의, 도움말, 화면 맞춤 기반과 도구 전용 창 설정 | 실제 씬에서 모든 기존 기능에 접근하며 공통 메뉴·키가 같은 동작 수행 |
| 2. 보드 편집 UX | 이미지 소재·검색·분류, 선택/배치/삭제, 2×2 전체 선택, 다중 선택, 복사/잘라내기/붙여넣기, 확대/이동, 편집 단축키 | 보드 편집의 일상 작업을 메뉴·마우스·키보드로 일관되게 수행 |
| 3. 튜토리얼 제작 UX | 단계 목록, 동작 샘플, 보드 대상 선택, 조건 조립, 생성 블록 지정, 공유 흐름/레벨별 값, 단계 복제·이동 | 초보자가 화면 안내에 따라 튜토리얼 구성·수정·강조 확인 |
| 4. 시험·저장·검사 통합 검수 | 시험 설정·봇·기록 화면 완성, 오류 이동, JSON/팩 구분, 복귀·복구, 전체 화면 전환, 해상도/포커스/단축키 회귀 | 제작→검사→시험→수정→저장의 일관된 완성 화면 |

1단계에서도 기존 기능은 사용할 수 있어야 한다. 후속 단계는 상세 UX를 개선하는 것이며, 기능을 비활성화하고 후속으로 넘기는 이유가 아니다. 단계별 세부 문서를 지금 전부 만들지 않는다.

## 화면과 메뉴 계약

- 항상 보이는 핵심: 레벨 이름, 작업 폴더 식별, 미저장/복구/공유 사본 상태, 저장, Undo/Redo, 게임 시험, 편집 층/도구 상태.
- 메뉴: **파일 / 편집 / 보기 / 시험 / 도움말**. 항목 이름 왼쪽, 단축키 오른쪽 정렬. 바로가기 버튼에도 같은 설명과 키를 툴팁으로 표시한다.
- 작업 탭: **보드 편집 / 흐름·공급 / 튜토리얼 / 검사·봇 시험 / 시험 기록**.
- 보드 편집에는 모양·생성구, 흐름·공급에는 흐름·공급·연결을 하위 항목으로 제공한다. 튜토리얼에는 기존 공급/바인딩/공유/샘플 기능을 연결한다.
- 일반 사용자는 친숙한 이름을 먼저 본다. 내부 ID·고급 옵션은 접을 수 있게 한다.
- 메뉴/버튼/단축키는 같은 명령 상태를 공유한다. 사용 불가 이유를 도움말/상태 안내로 제공한다. 후속 신규 기능을 작동하는 빈 버튼으로 표시하지 않는다.
- `도움말 > 단축키 안내`는 앱 안의 검색 가능한 창이다. 동작, 키, 적용 영역, 제한 이유를 설명하고 구현된 항목만 실행 가능으로 표시한다.
- 한국어 입력 중인 상태와 숫자/문자 입력을 마치지 않은 상태에서 손실이 없어야 한다.

## 단축키 기본안과 담당 단계

키 배치는 Windows용 기본값이다. 사용자별 키 재설정 UI는 이번 범위가 아니다. 테스트에서 충돌이 확인되면 대안을 기록하고 메뉴/도움말을 함께 수정한다.

| 명령 | 기본 키 | 적용 영역·의미 | 단계 |
|---|---|---|---|
| 작업 폴더 열기 | Ctrl+O | 미저장 확인 후 기존 폴더 선택 | 1 |
| 저장 | Ctrl+S | 현재 입력 확정·검증 후 기존 저장 경로 사용 | 1 |
| 사본 저장 | Ctrl+Shift+S | 새 JSON 작업 폴더에 사본 저장 | 1 |
| 실행 취소 | Ctrl+Z | 텍스트 편집 중에는 텍스트 Undo, 그 외 활성 제작 세션 Undo | 1 |
| 다시 실행 | Ctrl+Y / Ctrl+Shift+Z | 세션 Redo. 텍스트 필드에서는 해당 필드의 지원 동작 우선 | 1 |
| 단축키 안내 | F1 | 도구에 키보드 포커스가 있을 때 앱 내 도움말 | 1 |
| 진행 중 조작 취소 | Esc | 맨 위 메뉴/모달 → 대상 지정 → 현재 도구. 한 번에 한 단계만 닫기 | 1 |
| 게임 시험 | F5 | 기존 BeginPlay, busy/모달/검증 제한 동일 적용 | 1 |
| 보드 영역 넓게 / 복원 | Shift+Space | 보드 포커스에서 좌우 패널 접기/복원. OS 창 크기와 다름 | 1 |
| 복사 / 잘라내기 / 붙여넣기 | Ctrl+C / Ctrl+X / Ctrl+V | 텍스트 필드에서는 텍스트, 보드에서는 현재 편집 층의 선택 요소 | 2 |
| 전체 선택 | Ctrl+A | 텍스트 필드에서는 텍스트, 보드에서는 편집 가능한 보드 영역 | 2 |
| 삭제 | Delete | 보드 포커스에서 현재 층 선택만 삭제. 한 번 Undo로 복구 | 2 |
| 선택 / 배치 / 지우개 | V / B / E | 보드 편집 문맥, 문자 입력 중 작동 금지 | 2 |
| 선택 해제 | Ctrl+Shift+A | 보드 선택만 해제 | 2 |
| 확대 / 축소 / 맞춤 | Ctrl++ / Ctrl+- / Ctrl+0 | 보드 포커스. Ctrl+= 및 숫자패드 키도 고려 | 2 |
| 보드 확대·이동 | Ctrl+휠 / Space+드래그 | 보드에서만 처리. 다른 패널은 원래 스크롤 유지 | 2 |
| 단계 복제 | Ctrl+D | 튜토리얼 단계 목록에 포커스가 있을 때만 | 3 |
| 전체 화면 / 창 모드 | F11 | Windows 독립 도구에서만. Unity Editor 자체 창에는 적용하지 않음 | 4 |

신규 보드 클립보드 명령은 2단계에서 연결한다. 1단계의 텍스트 필드 복사·붙여넣기는 기본 동작을 보존한다. 도움말에서 텍스트 복사와 보드 요소 복사의 범위를 혼동시키지 않는다. 안내에 미래 구현 키를 나열할 경우 별도 개발 예정 영역으로 분리하며 일반 명령 메뉴에는 작동하는 것만 둔다.

## 보드 클립보드의 기본 방향

- 일반 텍스트 클립보드를 가로채지 않는다. 보드 데이터는 버전이 있는 식별 가능한 전용 형식으로 구분한다.
- 현재 편집 층의 선택 요소를 복사한다. 2×2는 일부 칸만 선택해도 전체 오브젝트 한 번으로 처리한다. 기본 복사에 다른 층을 몰래 포함하지 않는다.
- 붙여넣기는 상대 배치 미리보기 → 위치 확정 → 하나의 편집 명령/Undo로 처리한다. Esc 취소 시 원본·클립보드 내용·현재 문서에 변경이 없어야 한다.
- 새 배치에는 새 instance ID를 부여한다. 참조 대상 누락, 보드 경계 밖, 장애물 일부 겹침, 지원하지 않는 문서는 미리 설명하고 전체 적용을 막는다. 일부만 적용하지 않는다.
- 잘라내기는 클립보드 쓰기와 삭제 검증에 성공해야 원본을 변경한다. 공급·연결·튜토리얼 참조에 미치는 영향과 같은/다른 레벨 붙여넣기는 2단계 상세 계획에서 기존 규칙에 맞춰 확정한다.

## 창 크기와 보드 크기를 구분

- Windows 창 테두리/최대화/Windows 스냅은 OS 기능이다. Win+방향키·Alt+Space 같은 OS 키를 앱이 재등록하지 않는다. 도움말에서 앱 단축키와 별도 구분한다.
- 조사한 전역 PlayerSettings는 `resizableWindow: 0`, 기본 1024×768이다. 구현 시 **Windows Level Editor 프로필의 실제 값도 재확인**하고 도구에만 크기 조절 가능한 창 모드·기본 1280×800을 설정한다. 게임·다른 세 프로필·전역 설정을 바꾸지 않는다.
- 1단계: 창 크기에 반응하는 레이아웃, 패널 최소 폭/접기, 보드 맞춤, 도구 프로필 설정 검증.
- 2단계: 확대·팬·맞춤과 단축키를 다듬는다. 4단계: F11과 창 모드 복원, 모니터 작업 영역 제약을 검증한다.
- Unity 내부에서는 Game View 크기를 바꿔 레이아웃을 검사한다. 독립 Windows 네이티브 창 조절·최대화·F11의 실제 OS 동작은 빌드 금지 상태에서 검증했다고 보고하지 않는다.

## 입력·상태 보호 공통 규칙

1. 최상위 모달/메뉴가 먼저 입력을 받는다. 배경 보드 편집·저장·시험이 동시에 실행되지 않는다.
2. 텍스트·숫자·멀티라인·IME 조합 중에는 타이핑과 필드의 복사/붙여넣기/선택/Undo를 우선한다. 문자 키로 보드를 바꾸지 않는다.
3. Ctrl+S처럼 문서 명령이 입력 중 허용되는 경우 delayed field의 값을 안전하게 확정한 후 저장한다. 파싱 실패나 조합 중이면 저장을 보류하고 입력을 보존한다.
4. 공유 사본·대상 지정·파일 작업 중·실제 시험 중에는 기존 제한을 그대로 사용한다. disabled 메뉴와 단축키의 허용 여부가 달라지지 않는다.
5. 키를 누르고 있어도 비동기 저장/시험이 중복 시작되지 않는다. Enable/Disable·도메인 재로드 후 이벤트가 중복 등록되지 않는다.
6. Tab/Shift+Tab은 포커스 이동이다. 패널 접기 용도로 가로채지 않는다. 파일 열기·레벨 전환·앱 비활성화 시 남은 드래그/누른 키 상태를 해제한다.
7. Unity 안에서는 해당 레벨툴/Game View에 포커스가 있을 때만 처리한다. 전역 Unity 메뉴 단축키를 재정의해 다른 프로젝트/창을 건드리지 않는다. 호스트가 먼저 소비하는 키는 검증 결과와 제한을 기록한다.

## 운영

ServeredMeridian만 작업한다. 기존 미커밋 변경·원본·GUID 보존. 커밋·푸시·Player/Addressables 빌드·HTML 매뉴얼 변경 금지. Unity 컴파일·필요한 Play Mode 검사는 허용한다. 질문은 제한시간 없는 일반 채팅 문답으로 한다. 필요하면 하위 에이전트를 사용할 수 있으나 Unity 실행과 공유 파일 수정은 순차 통제한다.

각 단계 종료 시 변경/검증/미검증/개선점을 보고하고 다음 단계 계획·목표·복사용 실행문을 작성한다. 커밋 메시지는 해당 구현·검증 완료 후에만 복사용으로 제시한다.
