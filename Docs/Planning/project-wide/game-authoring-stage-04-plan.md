# 게임·제작 도구 분리 4단계 — 실행용 레벨툴 기본판

> 2026-10-09 구현·검증 완료(Unity Play Mode 기본판). [진행 기록](../../Verification/project-wide/game-authoring-stage-04-progress.md)을 따른다.

**목표:** Unity Play Mode의 레벨툴 씬에서 JSON 열기 → 기본 편집 → 실제 퍼즐 시험 → 편집 복귀 → 저장을 수행한다.

[목표·완료 조건](../../Goals/project-wide/game-authoring-stage-04-goal.md) · [실행문](../../Commands/project-wide/game-authoring-stage-04-command.md) · [통합 계획](2026-10-08-game-and-authoring-products-plan.md)

## 전제와 경계

- 3단계의 `AuthoringEditSession`, JSON 저장소, 배치·흐름·미션·공급 편집 연산과 `JsonPuzzlePlayAdapter`를 재사용한다. 기존 Editor 콜백을 런타임 화면으로 그대로 복사하지 않는다.
- 화면은 실행용 코드로 작성하고 `UnityEditor`, `SerializedObject`, `AssetDatabase`에 의존하지 않는다. 런타임 UI 방식은 기존 프로젝트 UI 자산과 1단계 기술 결정을 확인한 뒤 필요한 범위에서 확정한다.
- 기존 창은 유지한다. 이번 기본판에서 기존 메뉴로 레벨툴 씬을 열 수 있게 하고, 5단계의 기능 동등성 검증 이후 기본 편집 화면을 바꾼다.
- 튜토리얼·고급 공급·연결/흐름 제작 화면의 완전한 이식은 5단계다. 기본판에 없는 기능은 명확하게 안내하며 기존 자료를 삭제하거나 초기화하지 않는다.
- 전체 SO 원본 이관, 정식 게임 입력 전환, 네 제품의 최종 배포 검수는 6단계다. 50레벨 MemoryPack과 Addressables의 기존 동작을 보존한다.
- 커밋·푸시·Player/Addressables 빌드·요청 전 HTML 수정 금지. 하위 에이전트 사용 가능. 질문은 제한시간 없는 일반 대화로 한다.

## A. 실행용 작업 화면과 저장 경계

**결과:** Editor API 없이 같은 JSON 문서를 열고 저장하는 기본 화면.

1. 3단계 검증 기록의 미완료/제약과 기능 목록을 확인한다. 레벨툴 시작 씬 및 기존 실행 진입을 확인하고 실제 필요한 화면/서비스 경계를 정한다.
2. 작업 폴더 선택·현재 경로·레벨 목록·미저장 표시·새로 만들기·복제·저장·사본 저장·다시 읽기를 공통 세션/저장소에 연결한다. Windows 폴더 선택은 좁은 플랫폼 어댑터로 분리하고 Editor 전용 선택창에 의존하지 않는다.
3. 외부 수정 충돌, 미지원 버전, 읽기/쓰기 실패, 이전 정상본 복구, 저장/버리기/취소를 제공한다. 실패했을 때 초안과 현재 선택을 유지한다.
4. Unity 기존 메뉴에서 씬으로 진입하는 경로를 추가하되 열려 있는 씬과 미저장 작업을 보존한다. LevelTool 제품 진입점에 연결한다.

**검증:** 실행용 코드의 Editor API 의존 검사, 새 폴더/기존 폴더 왕복, 저장 실패와 취소, 재시작 후 저장본 재열기.

## B. 기본 보드 편집

**결과:** 실제 제작자가 기본 레벨을 수정할 수 있는 화면.

1. 9×9 보드·층·선택·영역·기본 블록/장애물 팔레트·배치·더블클릭 교체·삭제·2×2 이동을 공통 편집 API로 연결한다.
2. 레벨 번호/이름/이동 횟수/색, 요소 내구도·색·방향, 기본 미션과 기본 생성구를 편집한다. 한 사용자 동작당 Undo/Redo 한 번을 유지한다.
3. 실행용 표현 리소스 카탈로그를 연결한다. 선택한 레벨에 필요한 이미지를 읽고 누락 리소스는 대체 표시와 원인을 제공한다. JSON에 Unity 객체 참조를 넣지 않는다.
4. 지원하지 않는 고급 필드는 그대로 보존한다. 튜토리얼이 있는 레벨을 기본판에서 저장했다고 튜토리얼 정보가 사라지지 않도록 한다.

**검증:** 기존 창과 같은 문서/행동의 결과 비교, 같은 층 교체·2×2 점유·연결 ID 보존, Undo/Redo, 고급 필드 보존, 확대/창 크기 변경 시 조작 가능 여부.

## C. 실제 퍼즐 시험과 복귀

**결과:** 현재 미저장 편집값으로 게임을 시험하고 다시 제작한다.

1. 현재 문서 스냅샷·시드·시험 튜토리얼 정책을 `PuzzlePlayRequest`와 `CreateTest`에 전달한다. 정식 진행/보상/학습 기록을 쓰지 않는다.
2. 공통 게임 보드·연출·입력을 사용하고 종료/실패/취소 시 편집 화면으로 돌아온다. 작업 폴더·선택·스크롤·미저장·Undo/Redo를 유지한다.
3. 실제 JSON 입력과 고정 공급/파워/2×2/튜토리얼이 있는 대표 레벨을 비교한다. 누락 리소스·잘못된 데이터 실패 후에도 재편집 가능하게 한다.
4. 검증 결과와 남은 기능을 기록하고 5단계 계획·목표·복사용 실행문을 작성한다. 자동으로 5단계 구현을 시작하지 않는다.

**검증:** Play Mode에서 제작→시험→복귀→수정→재시험, 원본 JSON과 SO·정식 저장 불변, 자원 및 임시 객체 해제.

빌드를 하지 않으므로 완료 보고는 **Unity Play Mode에서 확인한 실행용 기본판**으로 한정한다. Windows exe 배포·실기 검증 완료로 표현하지 않는다.
