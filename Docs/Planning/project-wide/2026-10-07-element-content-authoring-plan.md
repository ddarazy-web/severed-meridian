# 퍼즐 요소 제작 데이터와 배포 팩

사용자 요청에 따라 현재 확정된 퍼즐 요소를 종류별 ScriptableObject로 관리하고 빌드 전 MemoryPack으로 내보낸다. 기존 요소 제작·레벨 팩 파이프라인을 확장한다. 실제 게임/Addressables 번들 빌드와 커밋은 하지 않는다.

## 데이터 범위

- 기존 ID를 유지한 18개 정의: 고정 본체6, 덮개2, 바닥1, 일반 공급2, 파워4, 고철 공급1, 회수 공급1, 무작위 파워 공급1.
- 일반 블록 색과 로켓 방향은 기존대로 배치 상태다. 임의의 신규 규칙이나 미확정 콘텐츠를 생성하지 않는다.
- 기본 표현 카탈로그에는 확정된 상태 이미지·시트·애니메이션·효과 주소를 저장한다. 이미지 파일 자체는 기존 아틀라스로 유지한다.
- 각 정의와 표현 원본에 Docs/Contents의 기획 출처를 기록한다. 새 출하 정의는 실제 기획 문서 출처가 없으면 변환을 거절한다.

## 구현과 검증

- [x] 제작 원본을 생성하는 Editor 메뉴와 기존 원본을 덮어쓰지 않는 초기화 경로를 만든다.
- [x] 독립 콘텐츠 MemoryPack의 헤더·버전·정의·표현을 검증하고 Addressables에 bytes만 등록한다.
- [x] 기존 레벨 팩에 사용 정의를 포함하는 경로를 재사용한다. 새 레벨과 기존 제작 레벨을 기본 카탈로그에 연결한다. 기존 번호·배치·GUID는 유지한다.
- [x] 런타임은 콘텐츠 팩의 표현과 레벨 팩의 정의를 사용한다. 구형 팩은 콘텐츠 팩 정의를 연결하는 호환 경로를 유지한다.
- [x] 제작 원본4종이 빌드 의존성에 포함되면 거절한다. 기획 출처 누락·잘못된 팩·중복 정의·표현 누락을 검사한다.
- [x] 실제 에셋 생성·재실행 보존·MemoryPack 왕복·레벨 사용·Addressables 로딩·대표 기존 회귀를 확인한다.

기획 근거는 게임 규칙과 Art 문서를 함께 사용한다. 회수 캡슐과 금속기둥 상자는 과거 내부 enum 이름을 호환용으로 유지하며 옛 금고/세탁기 이미지는 생성하지 않는다. 공급/미션/교환/피해의 고유 실행 알고리즘은 기존 등록 행동을 유지한다.
