# Android 레벨툴 3단계 — 터치 편집·공통 명령

2026-10-11 · 3단계 구현·자동 검증 완료. 사용자가 제외한 실제 Android 검사는 미검증으로 남긴다. 검증 근거는 [완료 기록](../../Verification/project-wide/android-level-tool-stage-03-progress.md)을 확인한다.

[통합 가이드](2026-10-11-android-level-tool-plan.md) · [목표·완료 조건](../../Goals/project-wide/android-level-tool-stage-03-goal.md) · [목표 실행문](../../Commands/project-wide/android-level-tool-stage-03-command.md)

**Goal:** Android에서 일반/파워 블록·장애물·바닥·덮개를 손가락으로 선택·배치·교체·수정하고, Windows와 같은 편집 명령·Undo·JSON 결과를 사용한다.
**Architecture:** 터치 의미 판정은 화면 입력 경계에 둔다. 선택 대상과 편집 요청은 기존 AuthoringEditSession의 공통 명령으로 전달하며 Android 전용 편집 도메인을 복제하지 않는다. 2단계 화면과 상태 보존을 유지한다.
**Tech Stack:** 기존 Unity 6000.3.10f1, C#, 런타임 UI Toolkit·Input System, 공통 JSON 편집 세션과 외부 Tests.
**Spec:** [5단계 통합 가이드](2026-10-11-android-level-tool-plan.md)의 3단계. 터치 입력과 공통 명령을 연결하며 외부 파일 전송·최종 실기기 검수는 후속 단계로 남긴다.

> 실행자는 `superpowers:executing-plans` 또는 `superpowers:subagent-driven-development` 절차로 아래 작업 단위를 순차 검증한다. 하위 에이전트는 독립 작업에 사용할 수 있지만 Unity 검사·에셋 변경·프로필 전환은 겹치지 않는다. 커밋·푸시는 하지 않는다.

## 전제와 범위

- 1·2단계 진행 기록과 실제 코드부터 확인한다. 다음 단계 문서가 있다는 이유로 제품·화면·실기기 검증이 완료됐다고 가정하지 않는다.
- 포함: 손을 뗄 때 확정하는 탭, 롱터치, 명시적 교체, 영역/추가 선택, 확대/이동, 선택 대상 작업 메뉴, 필요한 공통 복사·잘라내기·붙여넣기·삭제 명령.
- 기존 Windows 마우스·키보드·16:10 데스크톱 화면과 JSON 스키마를 보존한다. Windows 씬 메뉴와 기존 EditorWindow 문맥 메뉴의 관련 명령은 같은 편집 의미로 연결한다.
- 외부 파일 선택기·프로젝트 ZIP·최근 프로젝트·중단 복구는 4단계다. 이번 단계의 앱 중단 처리는 진행 중 제스처를 취소하는 데 한정한다.
- 흐름·공급·연결·모양·튜토리얼 대상 지정의 정밀 모바일 조작과 시험 화면 마무리는 5단계다. 공통 입력 판정을 통과하도록 연결하되 모든 고급 화면을 재작성하지 않는다.
- 질문은 제한시간 없는 일반 채팅으로 진행한다. 필요하면 하위 에이전트를 사용하되 Unity 검사·에셋 변경·프로필 전환은 순차 실행한다.
- 커밋·푸시, Player/APK/Addressables 빌드, HTML 매뉴얼 갱신, 플러그인·SDK 설치는 별도 새 요청 없이 하지 않는다.

## 조작 계약

| 입력 | 결과 |
|---|---|
| 짧은 한 손가락 탭 | 유효한 대상에서 손을 뗄 때 한 번만 선택 또는 현재 도구 실행 |
| 롱터치 | 대상 작업 메뉴 표시. 누르는 동안과 메뉴 이후 손을 뗄 때 배치 없음 |
| 영역 선택 도구 | 시작/끝 지정으로 범위 선택, 추가 선택 옵션으로 누적. Shift 필수 아님 |
| 교체 명령/배치 옵션 | 현재 층의 대상을 명시적으로 교체. 더블탭 필수 아님 |
| 두 손가락 핀치/드래그 | 보드 확대/축소·이동만 실행. 첫 손가락의 미확정 탭도 취소 |
| 이동 도구의 한 손가락 드래그 | 보드 이동만 실행 |
| +/−·작업·취소 버튼 | 제스처를 쓰지 않아도 확대·작업 메뉴·진행 중 조작 취소 가능 |

롱터치 0.6초는 초기 검증값이다. 이동 허용 범위는 UI 배율을 반영하고 최종값은 검사 결과로 정한다. 이동·두 번째 손가락·팝업 전환·포인터 취소/캡처 상실·회전·앱 중단은 미확정 조작을 취소한다. 두 손가락 중 하나가 먼저 떨어져도 남은 손가락을 새 탭으로 처리하지 않는다. 새 탭은 모든 손가락을 뗀 뒤 새로운 입력부터 시작한다.

제스처 미리보기는 문서/dirty/Undo를 변경하지 않는다. 확정된 편집 하나는 공통 명령과 하나의 Undo로 처리한다. 이번 단계에서 자유 브러시나 별도 연속 페인트 기능을 추가하지 않는다. 기존 연속 편집 경로를 연결해야 한다면 미리보기→한 번의 확정/취소 계약을 먼저 확인한다.

## 작업 1. 터치 판정과 취소 경계

- [x] `LevelToolScreen.Board.cs`, 포인터 콜백·캡처·팝업 경로와 기존 특수 대상 지정 호출부를 조사한다. 터치 PointerDown이 실제 편집을 실행하는 경로를 식별한다.
- [x] 터치 시작은 대상 후보와 시각적 미리보기만 유지하고 탭/롱터치/이동/다중 터치를 구분한 뒤 한 번만 명령을 실행한다. Windows 마우스 클릭의 기존 동작은 회귀로 확인한다.
- [x] 롱터치 메뉴와 제스처 취소 후 PointerUp이 보드 편집을 다시 실행하지 않게 한다. 패널·메뉴 위의 포인터가 보드로 관통하지 않도록 한다.
- [x] 취소 버튼과 Android 뒤로가기 입력으로 진행 중 제스처/작업 메뉴를 먼저 취소한다. 저장·앱 종료·복구 정책 전체는 4단계에 남긴다.

검증: 짧은 탭, 임계시간 전/후, 이동 후 떼기, 롱터치 후 떼기, 두 번째 손가락 추가, 포인터 취소, 회전·팝업·앱 중단의 이벤트 순서를 재생한다. 기대 문서 변경 횟수는 탭 확정에서만 1, 나머지 미확정/취소에서 0이며 Undo 증가도 비교한다. 실제 UI 콜백 연결도 별도로 검사한다.

## 작업 2. 보드 이동·확대와 선택 도구

- [x] 기존 보드 좌표 변환과 스크롤·확대 상태를 재사용해 핀치/두 손가락 이동을 연결한다. 확대 후 탭 대상이 보이는 칸과 일치해야 한다.
- [x] 명시적인 이동 도구와 +/− 버튼을 제공하고 입력 판정·뷰 변환이 편집 명령을 실행하지 않게 한다. 핀치 중심과 경계의 동작은 대표 화면에서 확인한다.
- [x] 영역 선택의 시작/끝·취소, 추가 선택 상태를 화면에 표시한다. 층 변경·팝업 전환의 진행 중 선택 취소 규칙을 정하며 기존 확정 선택/문서를 불필요하게 지우지 않는다.
- [x] 2×2 장애물의 어느 점유 칸을 선택해도 같은 개체로 해석한다. 일부 칸을 별개 장애물로 처리하지 않으며 범위 선택의 포함 정책을 공통 선택 의미에 맞춘다.
- [x] 회전/재배치 중에는 진행 중 터치를 취소하되 확정 선택·편집 층·도구·세션·Undo를 유지한다.

검증: 확대 전/후 같은 칸 선택, 가장자리 이동, 두 손가락 시작/끝 순서, +/−, 영역/추가 선택·취소, 모든 점유 칸에서 2×2 선택을 확인한다. 이동·확대 전후 문서·dirty·Undo가 동일해야 한다.

## 작업 3. 작업 메뉴와 공통 편집 명령

- [x] 현재 층·선택·도구·클립보드·편집 가능 여부에 맞는 작업 메뉴를 제공한다. 롱터치와 선택 후 작업 버튼이 같은 명령 목록을 사용한다.
- [x] 일반/파워 블록·장애물·바닥·덮개의 선택·배치·교체·수정·삭제를 기존 검증/명령에 연결한다. 명시적인 교체에서만 기존 동일 층 대상을 교체하고 다른 층은 보존한다.
- [x] 공통 복사·잘라내기·붙여넣기가 없다면 기존 편집 규칙을 활용한 최소 명령으로 추가한다. Android/Windows별 구현, OS 클립보드·외부 전송 형식, JSON 스키마 확장은 하지 않는다.
- [x] 처음에는 같은 작업 세션의 복사본을 대상으로 한다. 정의·레벨 참조와 개체 식별자의 기존 계약을 보존하고 붙여넣기에 필요한 개체 ID만 기존 생성 규칙으로 정한다. 프로젝트 간 정의 병합은 후속 범위다.
- [x] 2×2 장애물을 통째로 복사/삭제/이동하고 경계 밖 배치·충돌·유효하지 않은 참조는 기존 검증으로 거절한다. 잘라내기 자료를 먼저 확보하고 실패 시 원본을 지우지 않으며 붙여넣기는 전체 검증 후 원자적으로 확정한다.
- [x] Windows 씬 메뉴·관련 단축키와 기존 EditorWindow 메뉴의 같은 명령을 연결한다. 기존 메뉴의 고유 동작이나 무관한 EditorWindow 구조는 바꾸지 않는다.

검증: 같은 초기 JSON과 선택으로 터치 메뉴/Windows 경로의 명령 결과·ID/참조·Undo/Redo를 비교한다. 층별 교체·삭제, 2×2 부분 선택, 경계·충돌·참조 실패, 복사 후 원본 수정, 잘라내기/붙여넣기·취소에서 문서의 원자성과 참조 보존을 검사한다.

- [x] 검사 후 임시 연결·프로필·콘텐츠 선택을 복원한다. `Docs/Verification/project-wide/android-level-tool-stage-03-progress.md`에 변경·통과 검사·미검증·제약을 기록한다.
- [x] 완료 후 4단계 상세 계획·목표·복사용 실행문을 작성하고 자동 구현하지 않는다. 실제 변경·검증 결과에 맞는 짧은 커밋 메시지만 마지막 코드 블록으로 제공한다.

## 예상 변경 경계와 완료 판정

화면 입력·뷰 이동·작업 메뉴는 `Assets/Scripts/Features/LevelTool/Runtime/`의 기존 partial과 필요한 작은 파일에 둔다. 명령은 `Assets/Scripts/Features/LevelAuthoring/Editing/`의 기존 책임을 따른다. UI 자산과 외부 Tests는 관련 범위만 변경하며 정확한 경로·검사 진입점은 구현 전 조사로 확정한다.

Editor의 이벤트 재생·공통 명령·실제 UI 연결 검사는 그 범위의 근거다. 실제 Android 터치 감도·포인터 이벤트·OS 뒤로가기·기기 회전을 검사하지 않았으면 미검증으로 기록한다. 빌드 금지 상태에서 실기기 완료를 주장하거나 검증 결과를 사전에 채우지 않는다.
