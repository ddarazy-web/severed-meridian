# 제품 빌드 도구 2단계 — 실행 연결·결과 관리 계획

> 2026-10-16 · 구현·모의/재로드/조회 회귀 검사 완료. 실제 제품 빌드 미수행.
> 구현 담당: `superpowers:executing-plans`로 아래 세 묶음을 순차 진행한다. 실행 코드 구현과 실제 제품 빌드 승인은 구분한다. 별도 승인 전까지 검증은 모의 실행·상태 검사로 수행한다.

**Goal:** 1단계의 읽기 전용 화면에 명시적인 빌드 실행을 연결하고, 프로필 전환·재컴파일·결과·실패 정리를 공통 흐름으로 관리한다.

**Architecture:** `MatchBuildToolWindow`는 요청·결과만 표시한다. 공통 실행기가 요청 상태를 소유하고 기존 플랫폼 등록표와 제품 정의를 사용하며, 실제 Unity 빌드 호출은 얇은 백엔드에 모은다. 테스트는 같은 실행기에 모의 백엔드를 연결한다. 옵션의 설정 적용·전후처리 수명주기는 3단계로 남긴다.

**Tech Stack:** Unity 6000.3.10f1 / Build Profiles / UI Toolkit / 기존 ProductProfiles·콘텐츠 콜백 / 외부 Tests.

**Spec:** [통합 계획](2026-10-15-build-tool-plan.md) · [1단계 진행 기록](../../Verification/project-wide/build-tool-stage-01-progress.md) · [2단계 목표](../../Goals/project-wide/build-tool-stage-02-goal.md) · [복사용 실행문](../../Commands/project-wide/build-tool-stage-02-command.md)

## 1. 선행 상태·유지할 계약

- 1단계의 목록 선택·새로고침·사전 검사는 계속 읽기 전용이다. 설정 변경은 사용자가 빌드를 명시적으로 요청한 뒤에만 시작한다.
- 진입 메뉴는 `Match → Build → 빌드 도구`다. 공통 실행기에 플랫폼별 switch를 만들지 않는다.
- 프로필 GUID와 기존 `ProductDefinition`을 기준으로 제품을 식별한다. 두 레벨툴의 공통 심볼만으로 판정하지 않는다.
- 원본 프로필은 기존 다섯 제품 정의를 사용한다. 복제·별도 경로 프로필은 기존 `ProductProfiles.Select`가 원본을 선택한다는 제약이 있으므로, 이 단계에서는 원본 사용을 안내하고 실행을 차단한다. 임의 복제 프로필 실행 지원으로 범위를 확대하지 않는다.
- 기존 고정 출력 경로 계약을 유지한다. 출력 경로 편집·Development Build·GPG·플러그인 옵션·자동 배포·복수 제품 대기는 포함하지 않는다.
- 실제 Player/APK/AAB/iOS 출력·Addressables 빌드는 별도 승인 전까지 실행하지 않는다. 모의 검사 완료와 실제 빌드 성공을 구분해 보고한다.

## 2. 현재 재사용 위치와 조사할 호출 순서

| 기존 코드 | 연결·주의점 |
|---|---|
| `BuildToolProfiles`, `BuildToolPreflight` | 실행 직전에 GUID로 다시 읽는다. 화면에 남은 과거 검사 결과만 믿지 않는다. |
| `BuildToolPlatforms`와 세 처리기 | 실행 시 플랫폼 지원·출력 종류·고유 제약을 제공하도록 필요한 계약만 확장한다. 같은 Unity 빌드 API는 공통 백엔드로 공유한다. |
| `ProductProfiles.Select` | Addressables 선택·경로와 활성 프로필·출력 설정을 변경한다. 재로드 전후에 실제 적용 상태를 다시 확인하고 중간 실패의 소유 설정을 정리해야 한다. |
| `ProductBuildGuard` | 선택 제품과 타깃·고정 출력·콘텐츠·원본 제외를 빌드 전 검사한다. UI용 약식 검사로 대체하지 않는다. |
| `LevelToolAtlasBuild` | `BuildPlayerProcessor` -1100. 기존 아틀라스 생성·포함 처리와 중복 실행하지 않는다. |
| `LevelToolManualBuild` | `BuildPlayerProcessor` -1000. 레벨툴에만 매뉴얼을 동봉한다. |
| `LevelPackBuild` | `BuildPlayerProcessor` -950. 채택 JSON에서 MemoryPack을 생성·등록한다. |
| Addressables 빌더·설정 | 실제 Player 빌드와 Addressables 생성의 현재 연결·데이터 생성 시점을 조사한다. 도구에서 무조건 별도 번들을 먼저 생성해 중복 빌드하지 않는다. |

위 순서는 확인한 콜백별 값이다. 서로 다른 Unity 콜백 종류 사이의 실행 순서를 숫자만으로 단정하지 않는다. 실제 엔진 API·기존 빌더를 조사해 연결 지점을 기록한다. `BuildPipeline.BuildPlayer(BuildPlayerWithProfileOptions)` 사용 가능 여부와 지원 필드는 설치된 Unity의 API로 확인하고, 프로필을 우회하는 임의 씬 빌드로 대체하지 않는다.

## 3. 예정 파일과 연결

위치는 `Assets/Scripts/Features/Products/Editor/BuildTool/`를 유지한다.

| 예정 파일 | 책임 |
|---|---|
| `BuildToolRequest.cs` | 실행 ID, 프로필 GUID·경로·제품·플랫폼·고정 출력과 요청 시각의 확정 정보 |
| `BuildToolRunner.cs` | 검사→선택→대기→재검사→실행→결과·정리의 공통 상태 진행. 실행 중복·상태 불일치 차단 |
| `BuildToolRunStore.cs` | 진행 기록·세션 소유권·완료 결과를 로컬 저장. 재로드와 에디터 재시작 구별 |
| `UnityProfileBuildBackend.cs` | 기존 제품 선택·Unity 빌드·BuildReport 변환의 좁은 실행 경계. 검사에서는 모의 백엔드 사용 |
| `MatchBuildToolWindow.cs` 수정 | 빌드 요청, 실행 요약, 진행 상태, 취소 가능 시점, 결과·로그·출력 열기 |
| 플랫폼 처리기 최소 확장 | 출력 파일/디렉터리와 플랫폼 고유 실행 제약. 실행 전체 흐름은 복제하지 않음 |
| `Tests/Editor/Features/Products/BuildToolExecutionVerification.cs` | 모의 백엔드 기반 상태·실패·중복·정리 검사 |
| `Tests/Editor/Features/Products/BuildToolExecutionReloadVerification.cs` | 진행 기록과 세션 경계·재로드 복원·재실행 방지 검사 |

작은 단위마다 인터페이스를 늘리지 않는다. Unity 실제 호출과 모의 실행의 교체 경계만 명시한다. 진행 기록은 로컬 설정과 분리하며 `Library/MatchBuildTool` 같은 Git 제외 위치를 사용한다. 인증정보는 보관하지 않는다.

## 4. 작업 A — 요청 확정·프로필 준비

- [x] 빌드 버튼 클릭 때 대상 제품·플랫폼·출력과 실제 빌드가 수행됨을 분명히 표시한다. 조회·검사 버튼이 실행을 시작하면 안 된다.
- [x] 최신 프로필을 읽어 차단 오류, 복제 프로필, 미설치 모듈, Play Mode·컴파일·이미 진행 중인 빌드를 거절한다. SDK 등 실제 빌드 전에는 확정할 수 없는 항목은 그대로 미확인으로 표시한다.
- [x] 요청을 로컬에 먼저 기록하고 상태 변경을 시작한다. GUID가 같은 에셋의 설정도 실행 도중 달라졌다면 재검사하고 조용히 새 값으로 진행하지 않는다.
- [x] 제품 선택과 콘텐츠 경로를 기존 경로로 적용하고 도메인 재로드·플랫폼 전환을 기다린다. 실행 전에 실제 활성 프로필·타깃·출력·콘텐츠 선택을 다시 확인한다.
- [x] 선택 도중 부분 실패하면 적용한 상태를 파악하고 정리한다. 외부에서 바뀐 상태를 원래 값이라며 무조건 덮어쓰지 않는다.

검증: 활성 상태가 이미 일치하는 경우, 다른 플랫폼, 선택 실패, 사라진 GUID, 실행 중 재설정, 연속 클릭을 모의 백엔드로 확인한다. 현재 조회 무변경 검사는 계속 통과해야 한다.

## 5. 작업 B — 실행·재로드·결과

- [x] 공통 상태를 준비·전환 대기·재컴파일 대기·실행 직전·빌드 중·정리·성공/실패/취소로 표시한다. 등록된 플랫폼 처리기를 통해 차이를 적용한다.
- [x] 같은 에디터 세션의 재로드는 요청 단계와 실제 상태를 대조해 이어간다. 에디터 재실행은 자동 실행하지 않고 미완료 기록을 안내한다.
- [x] 빌드 API 호출 전에 ‘호출 시작’을 기록한다. 호출이 시작된 요청을 재로드 뒤 다시 호출하지 않는다. 완료 증거가 없으면 성공/실패를 추측하지 말고 ‘결과 확인 필요’로 남긴다.
- [x] 현재 콘텐츠·빌드 콜백을 그대로 연결하고 중복 데이터 생성·번들 빌드를 방지한다. 가짜 결과를 실제 BuildReport로 표시하지 않는다.
- [x] 결과에 제품·프로필·플랫폼·출력·시작/종료 시각·소요 시간·완료 상태·오류 요약·로그 위치를 남긴다. 모의 결과에는 모의 검사임을 표시한다.
- [x] 출력 경로가 실제 존재할 때만 ‘출력 폴더 열기’를 제공한다. 실패 후 부분 산출물은 정상 결과로 표시하거나 임의 삭제하지 않는다.
- [x] 빌드한 제품을 활성 상태로 유지한다. 임시 실행 설정의 복원과 원래 활성 제품으로 돌아가는 작업을 혼동하지 않는다.

검증: 성공·실패·예외·컴파일 실패·재로드 경계·종료 후 재실행, API 중복 호출 0회/1회, 실제 결과 없는 중단 기록을 확인한다. 모의 백엔드 외 실제 빌드 함수를 호출하지 않는 검증 경로를 제공한다.

## 6. 작업 C — 중단·회귀·보고

- [x] 취소는 안전하게 중단할 수 있는 준비·대기 단계에서 제공한다. 동기 Unity 빌드를 언제나 즉시 중단할 수 있다고 약속하지 않고, 지원 가능한 취소와 정리를 구분한다.
- [x] 결과·예외·취소 모두 소유한 임시 상태를 정리하고, 정리 실패는 원래 실패와 함께 기록한다. 정상화하지 못한 상태에서 자동 재시도하지 않는다.
- [x] 순수 모의 검사에서는 활성 프로필·플랫폼·원본 설정을 바꾸지 않는다. 실제 선택 검사가 필요하면 상태를 기록·복원하고 사전에 범위를 구분한다.
- [x] 1단계 검사와 실행 검사를 통과하고, 추가한 실행 버튼이 조회 명령의 무변경 계약을 깨뜨리지 않는지 확인한다.
- [x] 실제 제품 빌드를 하지 않았으면 미검증으로 보고한다. iOS Unity 출력과 macOS Xcode 배포, Steam 실행·스토어 연결, Android 실기 설치를 별개로 남긴다.
- [x] `Docs/Verification/project-wide/build-tool-stage-02-progress.md`에 진행 결과를 작성한다. 3단계 계획·목표·복사용 실행문을 만들고 자동 구현하지 않는다.

## 7. 제한

커밋·푸시·HTML 매뉴얼 갱신·SDK/플러그인 설치·스토어 업로드는 하지 않는다. 질문은 제한시간 없는 채팅으로 한다. 단계 종료 보고에는 모의 실행 검증과 실제 산출물 검증을 반드시 나누어 적는다.
