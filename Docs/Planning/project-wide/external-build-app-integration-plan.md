# Windows 외부 빌드 앱 — 통합 계획

2026-10-16 · 1단계 연결부 구현·검증 완료. 2단계 WPF UI 미착수.

**Goal:** Unity 내부 도구와 같은 프로필·옵션·설정으로 빌드하고 로그를 정리하는 Windows UI 앱을 제공한다.

**Architecture:** WPF 앱은 화면·요청·진행 표시를 담당한다. Unity가 프로필 해석, 설정 검증·저장, 기존 BuildToolRunner 실행을 담당하며 BAT도 같은 연결부를 사용한다.

**Tech Stack:** C# WPF, 버전이 있는 JSON 요청/응답, 기존 PowerShell 실행·로그 정리, Unity 6000.3.10f1. WPF 대상 .NET은 2단계 시작 시 설치 SDK와 배포 조건을 확인하여 고정한다.

[1단계 계획](external-build-app-stage-01-plan.md) · [목표](../../Goals/project-wide/external-build-app-stage-01-goal.md) · [실행문](../../Commands/project-wide/external-build-app-stage-01-command.md)

## 공통 원칙

- 기존 Unity 메뉴 `Match → Build → 빌드 도구`와 BAT를 유지한다. 외부 앱 사용에 BAT 창을 띄우거나 직접 명령을 입력할 필요는 없다.
- 플랫폼 switch를 UI에 복제하지 않는다. 기존 플랫폼 처리기와 옵션 등록부에서 지원 항목·설명·현재값을 제공한다.
- 버전은 프로필 PlayerSettings, 옵션은 기존 BuildToolPreferences, 비밀번호는 기존 Windows DPAPI 저장소를 기준으로 한다. 외부 앱 전용으로 빌드 설정을 이중 저장하지 않는다.
- 외부 앱이 Unity `.asset` YAML을 직접 수정하지 않는다. 저장과 빌드는 서로 구분된 요청이다. 조회와 사전 검사는 설정을 저장하지 않는다.
- 같은 프로젝트가 Unity에서 열려 있거나 다른 외부 작업이 실행 중이면 변경·실행을 차단하고 이유를 표시한다. 다른 프로젝트의 Unity까지 막지 않는다.
- 실제 Player·Addressables 빌드는 별도 승인 후 검증한다. 커밋·푸시·배포·HTML 매뉴얼 갱신은 하지 않는다. 기존 미커밋 변경을 보존한다.
- 단계가 끝날 때 변경·검증·미검증을 보고하고, 다음 단계 계획·목표·복사용 실행문을 작성한다. 다음 단계 구현을 자동 시작하지 않는다.

## 현재 기반과 필요한 차이

| 현재 구현 | 재사용 / 보완 |
|---|---|
| `Tools/Build/Build.ps1`, `BuildToolBatch.cs`의 list/check/build | 기존 v1 요청을 유지하면서 UI용 현재 설정 조회·저장 계약 추가 |
| `BuildToolOptions`, `BuildToolPreferences` | 옵션 설명·지원 여부·기본값·저장값·해석 결과를 외부에 전달 |
| `BuildToolVersionSettings` | Android Name/Code, iOS Name/Build Number, Windows Name을 동일 규칙으로 조회·저장 |
| Android 서명·DPAPI 저장 | 별도 비밀번호 저장소를 만들지 않고 외부 입력 연결 추가 |
| `BuildToolRunner`, 요청 이력, 결과 파일 | 중복 실행 방지·복원·후처리 재사용, 진행/취소 요청을 외부 연결 |
| `Clean-Logs.ps1`, 자동 7일 정리 | UI에서 미리보기·보관 기간·실행 결과를 제공 |

## 3단계 개발 범위

| 단계 | 개발 내용 | 완료 시 사용 가능한 것 |
|---|---|---|
| 1. 공통 연결 계약 | 현재 설정 조회, 명시적 저장, v1 호환, 구조화된 로그 정리 응답, 모의/회귀 검사 | UI가 사용할 연결부와 안전 규칙. WPF 화면은 아직 없음 |
| 2. 외부 UI와 실행 연결 | WPF 프로젝트, 프로젝트/Unity 경로, 프로필·버전·옵션·서명 편집, 검사·실행·진행·로그 정리 화면 | 외부 앱에서 기존 빌드 흐름 조작. 모의 실행까지 검증 |
| 3. 운영 검증·배포 준비 | 취소·재실행·중단 복구, 설정 기억, 경로/배율 대응, 승인된 실제 빌드 비교, 앱 배포 패키징 | 검증 범위를 명시한 사용 가능한 Windows 빌드 앱 |

후속 단계 상세 계획은 직전 단계 결과를 반영하여 작성한다. 단계 내부는 조회/저장, 화면/실행, 복구/검증 정도의 작업 묶음으로 나누며 별도 수십 단계로 늘리지 않는다.

## 외부 화면의 기본 구성

- 왼쪽: 프로젝트·Unity 경로와 제품 프로필 목록. 최초 조회는 Unity 시작 시간이 걸린다는 상태 표시, 이후 캐시에는 조회 시각과 갱신 버튼 표시.
- 오른쪽: Android 서명 우선, 선택한 제품 정보에 버전 입력 통합, 플랫폼에 맞는 빌드 옵션과 툴팁.
- 하단: 설정 저장, 사전 검사, 빌드, 취소, 진행 상태, 로그/출력 폴더 열기. 사전 검사 통과를 실제 빌드 성공처럼 표시하지 않는다.
- 로그 관리: 보관 기간(기본 7일), 삭제 후보·용량 미리보기, 정리 실행, 삭제/보호/실패 결과. 선택 프로필만이 아니라 **현재 프로젝트 Logs 전체** 대상임을 명시한다.
- 실제 GPG/플러그인 구현이 없는 항목은 작동하는 옵션처럼 추가하지 않는다. 향후 등록된 옵션은 같은 정의에서 노출한다.

## 실행·보안·로그 정리 계약

1. 외부 앱 → 숨김 PowerShell 호스트 → Unity batchmode → 기존 실행기. 요청별 ID로 상태와 결과를 연결한다. 임의 명령 문자열을 조합하지 않고 인자를 분리한다.
2. 옵션을 등록부에서 검증하고 전체 입력을 확인한 뒤 저장한다. 저장 중 실패하면 부분 성공을 성공으로 보고하지 않고 원상복구 또는 명시적 복구 필요 상태를 반환한다.
3. 비밀번호를 명령행, 일반 JSON, 결과, 로그에 넣지 않는다. 2단계에서는 공통 DPAPI 컨텍스트와 암호화 전달을 구현·검증한다. 1단계는 저장 여부만 조회하며 실제 비밀번호를 읽거나 출력하지 않는다.
4. 취소는 기존 실행기가 허용하는 안전한 지점에서 처리한다. Unity 동기 빌드 도중 즉시 중단을 보장하지 않는다. 앱 종료를 Unity 강제 종료로 연결하지 않는다.
5. 정리는 기존 `Clean-Logs.ps1`을 재사용한다. `Build`, `ContentData`, `Library/MatchBuildTool` 및 로그 밖 경로는 삭제 대상이 아니다. 링크·잠금 파일·미완료 요청·실행 중 로그를 보호한다.
6. 기존 정리기는 프로젝트 사용 중이면 전체 정리를 `Busy`로 생략한다. 이를 유지하며 실행 중인 로그를 제외한 나머지까지 굳이 동시에 지우지 않는다. UI가 이를 오류나 성공으로 오인하지 않게 표시한다.
7. 미리보기 이후 실행 때 잠금·보관 기간을 다시 검사한다. 후보 목록이 삭제 권한을 대신하지 않는다. 자동 정리는 기존 빌드 전 7일 정책을 유지하며 수동 보관 기간 변경은 해당 실행에만 적용한다.

## 검증과 한계

- UI/CLI 설정 해석 일치, 비정상 입력 무변경, v1 호환, 실행 중 보호, 경로에 공백·한글 포함, 도메인 재로드·앱 재시작을 단계별로 검사한다.
- Windows 앱에서 Android/Windows 제품을 우선 검증한다. iOS 프로필 정보는 제공하지만 Windows 앱만으로 macOS Xcode 서명·아카이브를 완료한다고 안내하지 않는다.
- 1단계 연결 계약은 구현·검증 완료했다. 외부 WPF UI와 실행·취소 확장은 2단계다.
