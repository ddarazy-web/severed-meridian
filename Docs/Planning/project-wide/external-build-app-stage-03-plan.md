# Windows 외부 빌드 앱 3단계 — 운영 검증과 배포 준비

2026-10-16 · 현 작업 정리 완료. 사용자가 200% 배율·물리 모니터 분리 검사를 미검증으로 남기도록 요청했다. 전체 운영 검증 완료로 판정하지 않으며, 미완료 체크 항목은 후속 검증으로 유지한다. 3단계 진행 기록의 작업 정리 절을 참조한다.

> 구현자는 `superpowers:executing-plans`로 아래 세 작업 묶음을 검증한다. 실제 제품 빌드·실제 자격 증명 사용·배포는 이 문서만으로 승인되지 않는다.

**Goal:** 2단계 외부 앱을 재시작·중단·실제 Windows 환경에서 안전하게 운영하고 배포 가능한 형태로 준비한다.

**Architecture:** WPF는 요청과 상태를 관리하고 기존 PowerShell/Unity Runner가 실행한다. 별도 빌드 엔진이나 설정 원본을 만들지 않는다.

**Tech Stack:** `Tools/BuildApp`, 기존 JSON v2 호스트·Runner, Windows DPAPI. 패키징 전에 .NET 대상 버전과 지원 기간을 확인한다.

**Spec:** [통합 계획](external-build-app-integration-plan.md) · [2단계 기록](../../Verification/project-wide/external-build-app-stage-02-progress.md) · [목표](../../Goals/project-wide/external-build-app-stage-03-goal.md)

## 공통 제약

- 기존 변경 보존. 커밋·푸시·HTML 갱신 금지. 질문은 제한시간 없는 일반 채팅.
- 실제 빌드/서명/배포 승인 전에는 모의 실행·복제 프로필·임시 암호·임시 로그만 사용한다.
- 앱을 닫거나 통신 오류가 나도 Unity를 강제 종료하거나 자동 재빌드하지 않는다.
- `Library/MatchBuildApp`의 진행 기록과 `Library/MatchBuildTool`의 Runner 기록은 역할이 다르다. UI 기록만으로 실행기 상태를 덮어쓰지 않는다.

## 작업 1 — 중단·재접속·정리

대상: `Tools/BuildApp/BuildToolClient.cs`, `BuildWorkspaceViewModel.cs`, `WorkspacePreferences.cs`, `Tools/Build/BuildToolHost.ps1`, 기존 Runner 상태 조회 경계. 검사: `Tools/Testing/BuildApp.Tests`, `ExternalBuildAppHost.Tests.ps1`.

- [x] 호스트 실행 중 앱 강제 종료, 호스트 종료 후 결과 누락, Unity 재로드, 손상된 진행 파일을 임시 fixture로 재현한다.
- [x] 재실행 시 기존 요청을 읽어 실행 중/완료/확인 필요로 구분한다. 새 빌드를 자동 시작하지 않는다. 기존 Runner가 복구를 요구하면 기존 빌드 도구로 연결한다.
- [x] 정상 종료·실패·강제 종료 후 일회성 암호화 전달 파일을 정리할 기준을 만든다. 살아 있는 요청/잠금이 있으면 삭제하지 않는다. 요청 기록 보관 범위와 실패 안내를 명시한다.
- [x] 안전한 취소, 동기 빌드 중 취소 대기, 완료 직전 취소, 재실행의 중복 호출 방지를 모의 Runner로 확인한다. 동기 호출 중 강제 취소는 제공하지 않으며 결과 수신 뒤 늦은 취소가 성공 결과를 덮어쓰지 않음을 검사했다.

완료 증거: 실행 API 호출 횟수, 남은 요청/암호화 파일, 보존된 설정, 재실행 화면의 상태가 일치한다.

## 작업 2 — 실제 Windows 사용성과 패키징

대상: `Tools/BuildApp/MainWindow.xaml(.cs)`, `WorkspacePreferences.cs`, `BuildApp.csproj`, Markdown 안내 및 필요한 배포 스크립트.

- [x] 현재 지원되는 .NET 런타임과 배포 조건을 확인해 대상 버전 유지/변경을 결정한다. 임의 SDK 설치는 하지 않는다.
- [ ] 100%/150%/200% 실제 OS 배율, 작은 작업 영역, 다중 모니터 이동·분리, 최대화 복원을 확인한다. 2단계의 확대 렌더링 검사와 실제 OS 검사를 구분한다.
- [x] 키보드만으로 프로필·버전·옵션·서명·로그 화면을 이용할 수 있는지 확인한다. 한글·공백 경로, 자동 스크롤, 오류 문구를 확인했다. 2026-10-16 검사 전용 실행기에서 제품과 같은 MainWindow 및 FakeClient로 저장·재조회까지 검증했다. 실제 서명·제품 빌드 검증과 구분한다.
- [x] 로컬 배포 폴더에서 실행되는 패키지와 필요한 런타임/Unity 조건을 정리한다. 프로젝트 선택으로 실행하며 저장소 개발 경로를 하드코딩하지 않는다.
- [ ] 도움말, 결과/로그 폴더 열기, 마지막 작업 위치 기억을 배포 폴더 실행에서 검사한다. 공개 배포는 하지 않는다.

## 작업 3 — 승인된 실제 빌드 비교와 인수인계

- [ ] 실행할 제품, APK/AAB 등 옵션, 디버그 여부, 출력 위치, 서명 사용 범위를 구체적으로 제시해 실제 실행 승인을 받는다. 승인 전에는 이 항목을 미검증으로 남긴다.
- [ ] 승인 범위에서 외부 앱과 기존 Unity 도구/BAT의 버전·옵션·산출물을 비교한다. 기존 산출물 파일 존재만으로 성공 판정하지 않는다.
- [ ] 첫 실행의 프로필 전환·후처리·설정 복원과 재실행을 확인한다. 실제 비밀번호나 암호문을 결과 문서에 남기지 않는다.
- [ ] 실제 사용자 로그 삭제는 별도 요청 없이는 하지 않는다. 정리 동작은 임시 fixture로 확인한다.
- [ ] 완료/미검증/지원 한계를 Markdown 진행 기록에 남긴다. 승인되지 않은 실제 실행이 남으면 전체 운영 검증 완료로 표시하지 않는다.

## 우선 실패 조건

앱 재시작으로 중복 빌드, Unity 시작으로 통신 폴더 삭제, 살아 있는 요청의 암호화 파일 삭제, 결과와 요청 ID 불일치, 디스플레이 변경으로 창 접근 불가를 각각 재현 가능한 검사로 유지한다.
