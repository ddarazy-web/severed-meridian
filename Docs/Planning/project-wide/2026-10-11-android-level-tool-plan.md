## 기존 계획과 관계

- [게임·제작 도구 분리 가이드](2026-10-08-game-and-authoring-products-plan.md)의 제품 경계를 확장한다.
- [Windows 레벨툴 UI 개선 가이드](level-tool-ui-overhaul-plan.md)의 기존 기능·공통 명령을 유지한다. Android 대응 완료와 Windows UI 후속 단계 완료를 혼동하지 않는다.
- 이번에는 통합 계획 하나만 작성한다. 실행할 단계 직전에 해당 단계의 상세 계획·목표·완료 조건·복사 가능한 목표 명령문을 작성한다.
- 소스 구현, APK/Player/Addressables 빌드, 커밋·푸시, HTML 매뉴얼 갱신은 이번 계획 작성에 포함하지 않는다. 이전 커밋·푸시 승인은 일회성이었다.
- 기존 빌드 금지 요청을 유지한다. 최종 Android 실행 파일과 실기기 검증은 빌드에 대한 별도 요청/승인이 있어야 진행하며, 그 전에는 실기기 검증 완료로 보고하지 않는다.

## 계획 수립 당시 확인한 구조

1. 실제 씬 레벨툴은 런타임 UI Toolkit을 사용하며 JSON 작업 세션과 게임 시험을 공유한다. 별도의 Android 편집 엔진을 다시 만들 필요는 없다.
2. `LevelToolScreen.Board.cs`는 PointerDown에서 즉시 선택·배치하고, Shift로 영역 선택, 더블클릭으로 교체한다. 그대로 두면 롱터치·두 손가락 확대 전에 배치가 실행될 수 있다.
3. `LevelToolScreen.ConnectionOverlay.cs`의 연결점은 12 UI 단위 크기다. 모바일에서는 그림 크기와 별개로 넓은 터치 판정과 확대가 필요하다.
4. `LevelToolScreen.Layout.cs`와 USS는 좌우 패널을 둔 PC 구조다. 휴대폰에서는 접이식 패널과 모바일용 배율이 필요하다.
5. `LevelToolFolderAccess.cs`는 드라이브·디렉터리를 직접 탐색한다. Android 외부 문서 선택 결과를 일반 Windows 경로처럼 넘길 수 없다.
6. 제품 정의는 Android 게임과 Windows 레벨툴을 포함한 네 제품이다. 제품 검색이 심볼만 기준인 곳이 있어 동일 레벨툴 심볼을 다른 플랫폼에 추가할 때 선택·콘텐츠 경로를 함께 수정해야 한다.
7. Windows 네이티브 창 제어는 Windows 실행 파일에만 적용한다. Android에는 1280×800 최소 OS 창 크기나 16:10 강제 비율을 적용하지 않는다.

## 권장 접근과 대안

**권장: 같은 씬·명령·JSON을 공유하고 화면과 플랫폼 경계만 조정한다.** 기존 UI Toolkit과 편집 검증을 활용하며 PC와 모바일에서 편집 결과가 달라지지 않게 한다.

- Windows UI를 그대로 축소: 초기 작업은 적지만 휴대폰에서 버튼·글씨·보드가 작고 화면 키보드 사용이 어렵다. 채택하지 않는다.
- 모바일 레벨툴을 별도 프로젝트·별도 편집 로직으로 재작성: 화면은 자유롭지만 기능·버그 수정이 두 벌로 갈라진다. 현재 범위에는 채택하지 않는다.

## 제안하는 화면·조작 계약

### 태블릿과 휴대폰

- 가로·세로 모두 지원한다. 레벨툴은 기기의 화면 비율을 사용하고, 회전 시 선택·배치 도구·입력 내용·팝업·Undo 이력을 유지한다.
- 장치 이름보다 실제 사용 가능한 화면 폭과 UI 배율에 따라 배치를 고른다. 접이식 기기·분할 화면도 같은 기준으로 대응한다.
- 넓은 태블릿 가로 화면: 왼쪽 레벨/소재, 중앙 보드, 오른쪽 속성 구조를 사용한다. 공간이 부족하면 패널을 접는다.
- 휴대폰과 좁은 화면: 보드를 기본 화면으로 두고 **레벨 / 소재 / 속성 / 더보기** 버튼으로 패널을 연다. 기본은 패널 한 개씩 열어 보드를 계속 가리지 않게 한다.
- 세로에서는 하단 패널, 가로의 좁은 화면에서는 옆쪽 패널을 사용한다. 패널 이동·스크롤·닫기는 선택 칸이나 문서를 변경하지 않는다.
- 저장, 실행 취소/다시 실행, 게임 시험, 현재 편집 층·도구 상태는 바로 접근 가능하게 한다. 자주 쓰는 버튼은 약 48dp에 준하는 터치 영역을 목표로 실기기에서 확인한다.
- Safe Area, 시스템 표시줄, 화면 키보드를 고려한다. 입력 필드는 키보드 위로 보이고 저장 전에 한국어 입력을 잃지 않아야 한다.
- 툴팁만으로 설명하지 않는다. Android에는 짧은 상태 안내와 도움말 버튼을 제공한다.

### 입력 대응

| 목적 | Windows | Android 기본안 |
|---|---|---|
| 한 칸 선택/현재 도구 실행 | 왼쪽 클릭 | 짧게 탭, 손을 뗄 때 확정 |
| 대상의 추가 작업 | 오른쪽 클릭/메뉴 | 롱터치 또는 선택 후 ‘작업’ 버튼 |
| 동일 층 요소 교체 | 기존 더블클릭 | ‘교체’ 명령/명시적 배치 옵션. 더블탭을 필수 조작으로 삼지 않음 |
| 여러 칸 선택 | Shift와 선택 명령 | ‘영역 선택’ 도구로 시작·끝 지정, ‘추가 선택’ 옵션으로 선택 누적 |
| 확대·축소 | 기존 확대 UI/후속 마우스 명령 | 두 손가락 핀치와 +/− 버튼 |
| 보드 이동 | 기존 스크롤/후속 이동 명령 | 두 손가락 드래그, 또는 ‘이동’ 도구에서 한 손가락 드래그 |
| 복사·잘라내기·붙여넣기·삭제 | 공통 편집 명령 | 선택 대상 작업 메뉴의 같은 명령 |
| 진행 중 작업 취소 | Esc/취소 버튼 | 취소 버튼 및 Android 뒤로가기 |

- 롱터치는 0.6초를 초기값으로 검증한다. 이동·두 번째 손가락·팝업 전환·앱 중단 시 취소한다. 범위 판정은 화면 픽셀 고정값이 아닌 UI 배율을 반영한다.
- 터치 시작 시 실제 문서를 수정하지 않는다. 짧은 탭, 롱터치, 이동, 다중 터치 중 무엇인지 결정된 뒤 해당 명령만 실행한다.
- 롱터치가 열어 놓은 메뉴 뒤에서 배치가 실행되거나 손을 떼면서 다시 실행되지 않게 한다.
- 두 손가락 조작으로 확대·이동할 때 첫 손가락이 배치를 발생시키지 않게 한다. 연속 편집은 임시 미리보기 후 한 번의 편집·Undo로 확정하는 방향으로 상세 설계한다.
- 메뉴는 현재 층·선택·편집 상태에 맞는 명령만 제공한다. 2×2 장애물은 하나의 개체로 처리하며 일부 칸을 별개 개체로 잘라 편집하지 않는다.
- 흐름·연결·모양·튜토리얼 대상 지정에도 동일한 입력 판정과 취소 규칙을 사용한다. 연결점은 그림보다 터치 영역을 넓히고, 겹치는 점은 확대 후 정확히 선택할 수 있게 한다.
- 씬 레벨툴의 현재 보드에는 오른쪽 클릭 처리가 없다. 기존 Unity EditorWindow의 문맥 메뉴와 앞으로 추가할 Windows 씬 메뉴를 공통 명령에 연결하고, Android 롱터치/작업 메뉴도 같은 명령을 호출한다.
- 기존 Windows 후속 계획에만 있고 아직 구현되지 않은 보드 복사·붙여넣기 등은 먼저 공통 명령으로 구현한다. Android와 Windows에 따로 작성하지 않는다.

### 데이터와 파일 접근

- 편집의 기본 작업 장소는 앱 내부 프로젝트 폴더다. 외부 문서를 직접 편집하는 방식은 초기 범위에 넣지 않는다.
- Windows와 Android의 제작 원본은 같은 JSON 형식이다. ScriptableObject를 Android 편집 저장소로 사용하지 않는다.
- 외부와 주고받는 기본 단위는 **프로젝트 ZIP**을 권장한다. ZIP 안에는 정상 저장본의 프로젝트 정보와 참조되는 레벨·블록·장애물·튜토리얼 JSON을 포함한다. 복구 임시 파일과 PC 절대 경로는 제외한다.
- Android의 시스템 파일 선택기로 가져오기/내보내기를 제공하고, 앱 내부로 가져온 사본을 편집한다. Windows에도 같은 패키지 가져오기/내보내기를 연결한다.
- 외부 파일의 `content://` URI는 파일 경로로 바꾸지 않는다. Android 어댑터가 스트림으로 읽고 쓰며 공통 JSON 저장소는 앱 내부 경로를 사용한다.
- 가져오기는 임시 위치에서 전체 형식·참조를 검증한 뒤 새 프로젝트로 등록한다. 오류·취소·앱 중단 시 현재 프로젝트를 덮지 않는다. ZIP 경로가 작업 폴더 밖으로 탈출하지 않게 검사한다.
- 편집본 저장과 외부 내보내기 성공은 구분해서 알린다. 전송을 취소해도 내부 저장본은 유지한다.
- 단일 레벨 JSON만으로 필요한 정의와 튜토리얼 참조가 갖춰지지 않을 수 있으므로, 처음에는 완전한 프로젝트 단위 전송을 우선한다.
- MemoryPack 시험·게임용 변환은 기존 공통 경로를 유지한다. JSON↔팩 결과를 PC/모바일에서 비교하고 동일 ID·참조·레벨 의미를 보존한다.

| 1. Android 제품·실행 기반 | 독립 앱 프로필/식별자, 제품 선택 경계, 도구 리소스 분리, 내부 프로젝트 시작·저장, Windows 전용 기능 격리 | Android 제품을 선택해 같은 LevelTool 씬과 공통 편집 로직을 실행할 준비가 됨 | 기존 네 프로필 보존, Android 게임/툴 분리, Windows 프로필 선택 유지, 내부 JSON 읽기·저장 |
| 2. 태블릿·휴대폰 화면 | 넓이에 따른 패널, 가로/세로, Safe Area, 모바일 UI 배율, 입력 키보드·팝업·도움말 | 좁은 휴대폰부터 넓은 태블릿까지 보드와 필수 메뉴를 사용할 수 있음 | 여러 폭/방향·키보드·회전에서 입력/선택/팝업 상태 보존, Windows 기존 화면 회귀 |
| 3. 터치 편집·공통 명령 | 탭/롱터치 판정, 명시적 교체, 영역/추가 선택, 확대/이동, 작업 메뉴, 필요한 공통 클립보드 명령 | 손가락만으로 일반/파워 블록·장애물·바닥·덮개를 선택·배치·교체·수정 가능 | 롱터치 전 배치 없음, 핀치로 편집 없음, 취소/Undo, 2×2·편집 층·참조 보존, 마우스 명령 결과 동일 |
| 4. 파일 전송·복구 | 공통 프로젝트 패키지, Android 시스템 파일 선택기, PC 가져오기/내보내기, 최근 프로젝트, 중단·재개·뒤로가기 | PC→Android→PC로 프로젝트를 왕복하고, 중단 후 다시 이어서 편집 가능 | 왕복 데이터 동일, 잘못된 ZIP/참조·취소·쓰기 실패 시 원본 보존, 외부 내보내기와 내부 저장 구분 |

5단계는 단순 테스트 단계가 아니다. 작은 연결점·튜토리얼 대상 선택·시험 화면처럼 기본 보드와 조작이 다른 기능을 마무리하고 전체 제작 흐름을 검수한다. 기능을 작은 작업으로 나누되 위 다섯 단계를 다시 수십 개의 독립 단계로 늘리지 않는다.

## 구조 변경 위치

- `Assets/Scripts/Features/Products/Editor/`: Android Level Editor 정의와 프로필 생성/선택/감사. `PRODUCT_LEVEL_EDITOR`는 공통 도구 심볼로 재사용하고 `UNITY_ANDROID`로 플랫폼을 구분하는 안을 우선한다. 심볼 단독 검색은 제품+대상 플랫폼 기준으로 바꾸며 Addressables 중간 결과 경로도 플랫폼을 포함해 격리한다.
- `Assets/Scenes/LevelTool.unity`, `Assets/Prefabs/UI/LevelTool/`, `Assets/UI/LevelTool/`: 같은 씬·UI 자산과 플랫폼별 배치 스타일을 사용한다. 모바일 전용 화면을 별도 편집 앱 로직으로 복제하지 않는다.
- `Assets/Scripts/Features/LevelTool/Runtime/`: 화면 배치·입력 판정·작업 메뉴·플랫폼 파일 진입을 책임별 파일로 추가하고, 기존 partial 화면 파일에 연결한다.
- `Assets/Scripts/Features/LevelAuthoring/Editing/`, `Storage/`: 공통 편집과 패키지 전송/검증. Android 경로·Java 호출을 편집 도메인이나 JSON 저장소에 넣지 않는다.
- Android 외부 문서 접근 어댑터/필요한 플러그인: 기존 의존성부터 조사하고 파일 선택·URI 스트림 경계에만 둔다. 특정 플러그인은 지금 선택·설치하지 않는다.
- `Tests/Editor/`, `Tests/Portable/`, `Tools/Testing/`: 기존 외부 테스트 위치와 검사 도구를 유지한다. 터치 시퀀스·레이아웃·프로필·데이터 왕복 검사를 추가하며 테스트를 제품 빌드에 상시 포함하지 않는다.

## 단계 진행과 완료 보고

- 단계 시작: 해당 단계 계획·목표·관찰 가능한 완료 조건을 제시한다. 새 UI 판단이 필요한 단계는 대표 태블릿/휴대폰 화면과 조작을 먼저 검토한다.
- 구현 후: 무엇을 변경했는지, 통과한 검사, 실기기/빌드 미검증 항목과 알려진 제한을 보고한다.
- 단계를 완료하면 다음 단계의 상세 계획·목표와 복사 가능한 목표 실행문을 작성한다. 다음 단계 구현을 자동 시작하지 않는다.
- 실제 Android 배포 파일을 만들지 않았으면 설치·파일 선택기·OS 뒤로가기·화면 키보드·중단 복구의 실기기 완료를 주장하지 않는다.
