# Android 레벨툴 2단계 — 태블릿·휴대폰 반응형 화면

2026-10-11 · 구현·자동 검사 완료. 실제 Android 검증 대기이며 전체 목표는 미완료다.

[통합 가이드](2026-10-11-android-level-tool-plan.md) · [목표·완료 조건](../../Goals/project-wide/android-level-tool-stage-02-goal.md) · [목표 실행문](../../Commands/project-wide/android-level-tool-stage-02-command.md)

**Goal:** 같은 LevelTool 씬과 편집 세션에서 휴대폰·태블릿의 사용 가능한 폭과 방향에 맞게 화면을 배치하고, 회전·패널 전환·키보드 표시 중 문서와 편집 상태를 보존한다.
**Architecture:** 편집 도메인과 JSON은 공유한다. Android 화면의 배치·배율·Safe Area 처리는 기존 UI Toolkit 화면에 연결하고, 문서 생성·세션 재진입과 분리한다. Windows 데스크톱 화면과 16:10 창 정책은 유지한다.
**Tech Stack:** 프로젝트의 Unity 6000.3.10f1, C#, 런타임 UI Toolkit, 기존 AuthoringToolWorkspace/AuthoringEditSession.
**Spec:** [5단계 통합 가이드](2026-10-11-android-level-tool-plan.md)의 2단계. 실제 APK·실기기 화면 키보드 검증은 별도 빌드 허가 없이 수행하지 않는다.

## 시작 전 전제와 범위

- 1단계의 Android 제품·내부 프로젝트 기반에 대한 진행 기록과 검증 결과를 먼저 확인한다. 실패하거나 미검증인 전제는 명시하며, 다음 단계 문서가 있다는 이유로 완료 처리하지 않는다.
- 포함: 폭에 따른 패널 배치, 가로/세로 전환, Safe Area, 모바일 배율·터치 영역, 기본 모달과 팝업의 화면 내 표시, 입력 키보드 대응, 짧은 상태 안내·도움말.
- 후속: 탭 확정·롱터치·핀치·보드 이동·영역 선택·작업 메뉴와 공통 클립보드 명령은 3단계, 외부 파일 선택기·ZIP·중단 복구는 4단계다.
- 고급 편집 화면도 진입·스크롤·닫기가 막히지 않도록 확인한다. 연결점과 튜토리얼 대상 지정, 시험 화면 전체를 모바일 전용으로 다시 설계하는 작업은 5단계에 남긴다.
- 질문은 제한시간 없는 일반 채팅으로 진행한다. 필요하면 하위 에이전트를 사용할 수 있으나 같은 Unity 프로젝트의 검사·에셋 변경·프로필 전환은 순차 실행한다.
- 커밋·푸시, Player/APK/Addressables 빌드, HTML 매뉴얼 갱신, SDK·플러그인 설치는 별도 새 요청 없이 하지 않는다.

## 화면 계약

배치 기준은 기기 모델이나 휴대폰/태블릿 이름이 아닌 **Safe Area와 UI 배율을 적용한 실제 사용 가능한 UI 폭**이다. 회전·분할 화면·접이식 화면의 폭 변경도 같은 계산을 사용한다. Windows의 기존 화면 폭 계산과 창 비율을 Android용 기준으로 바꾸지 않는다.

| 화면 조건 | 배치와 접근 |
|---|---|
| 넓은 화면 | 왼쪽 레벨/소재, 중앙 보드, 오른쪽 속성. 보드 최소 작업 공간을 확보할 수 있을 때만 양쪽 패널을 동시에 표시 |
| 좁은 세로 화면 | 보드를 기본으로 두고 레벨/소재/속성/더보기로 하단 패널을 열기. 기본적으로 한 패널씩 표시 |
| 좁은 가로 화면 | 같은 진입 버튼으로 옆쪽 패널 열기. 낮은 높이에서는 패널 내용과 명령 영역을 스크롤 가능하게 유지 |
| 키보드 표시 | 편집 중 필드와 확인/취소 접근을 확보. 키보드 높이 변화 자체가 문서 변경이나 세션 재생성을 유발하지 않음 |

전환 폭과 모바일 배율의 구체적인 값은 기존 USS·PanelSettings·패널 최소 크기를 조사하고 대표 화면에서 정한다. 임의의 단일 화면 픽셀 값으로 48dp를 보장했다고 주장하지 않는다. 약 48dp에 준하는 실용적인 누름 영역을 목표로 배율·판정 크기를 함께 확인하며, 아이콘 그림은 누름 영역과 별도로 유지할 수 있다. 좁은 화면에서 버튼을 줄여 넣기보다 명령 묶음·패널·스크롤로 공간을 확보한다.

저장, Undo/Redo, 게임 시험, 현재 편집 층과 도구 상태는 좁은 화면에서도 바로 접근하거나 확인할 수 있어야 한다. Android 도움말은 키보드 단축키와 마우스 툴팁만 요구하지 않으며, 아직 구현하지 않은 롱터치·핀치를 사용 가능하다고 안내하지 않는다.

## A. 기존 화면과 상태 수명 조사

- [x] `LevelToolScreen.Layout.cs`, USS/UXML, PanelSettings와 기본 모달·팝업 생성 경로를 확인한다. 화면 폭·배율·Safe Area의 좌표계와 갱신 시점을 기록한다.
- [x] 화면 재배치가 문서 로드, `Workspace.Create`, 세션 초기화, 선택 초기화, Undo 초기화를 호출하지 않도록 호출 관계를 확인한다.
- [x] 상태 소유 위치를 구분한다: 문서·dirty·Undo/Redo, 선택 칸·편집 층·도구, 열려 있는 패널·팝업, 필드의 미확정 문자열·포커스·커서/텍스트 선택. 기존 상태를 가능한 그대로 보존하는 최소 변경을 선택한다.
- [x] 대표 휴대폰 세로/가로와 넓은 태블릿 화면의 배치안을 기존 화면 구조로 제시하고, 작업 가능한 보드 크기와 명령 접근을 기준으로 전환 폭을 결정한다. 새로운 UI 판단이 결과를 크게 바꾸면 제한시간 없는 채팅으로 확인한다.

검증: 편집 중 화면 크기 변경의 기존 동작을 관찰해 문서·선택·입력 유실 여부를 기록한다. 이후 같은 시나리오를 회귀 검사로 사용한다.

## B. 배치·배율·Safe Area

- [x] Android 전용 반응형 배치를 기존 화면에 연결한다. 넓은 화면의 양쪽 패널과 좁은 화면의 단일 패널은 같은 기능·명령을 사용한다.
- [x] 패널 열기·닫기·스크롤·배치 전환만으로 선택 칸, 문서, dirty 상태, Undo/Redo가 변하지 않게 한다. 배치 전환 중 열린 패널의 의미를 유지한다.
- [x] 회전과 폭 변경 시 세션과 화면 상태를 보존한다. 가능하면 기존 VisualElement를 재사용하고, 필요한 재생성은 미확정 입력과 포커스 보존을 포함해 검증한다.
- [x] Safe Area를 올바른 UI 좌표로 변환해 루트 또는 필요한 오버레이에 적용한다. 이미 적용된 여백을 중복 적용하지 않으며 Android에 Windows 1280×800 최소 OS 창 크기·16:10 강제를 넣지 않는다.
- [x] 저장·Undo/Redo·게임 시험과 패널 진입 버튼의 누름 영역을 모바일 배율과 함께 조정한다. 작은 화면에서 버튼·텍스트가 겹치거나 보드가 사실상 사라지는 배치는 보완한다.
- [x] 메뉴·모달을 표시 영역 안에 제한하고 필요한 내용은 스크롤한다. 회전 전 좌표에 팝업을 고정하거나 필수 확인/취소를 화면 밖에 남기지 않는다.

검증: 폭 경계의 양쪽, 넓은/좁은 세로·가로, 낮은 높이, Safe Area 비대칭에서 명령·패널·팝업을 실제 표시해 접근을 확인한다. Windows 16:10 화면과 창 모드 전환도 기존 검사로 확인한다.

## C. 입력 키보드·상태 안내

- [x] 새 프로젝트 이름, 저장/사본 저장, 주요 속성 입력 등 기본 흐름의 입력 필드를 확인한다. 키보드와 겹치는 필드는 패널/모달 내 스크롤 또는 위치 조정으로 접근 가능하게 한다.
- [x] 회전·배치 전환·키보드 표시/숨김이 미확정 문자열을 저장 값으로 덮어쓰거나 필드 검증/편집 명령을 불필요하게 실행하지 않게 한다.
- [ ] 입력 중인 필드의 포커스·커서·텍스트 선택을 보존한다. 한국어 IME 조합 중에는 필드 제거·재생성으로 조합을 잃지 않도록 경로를 검토하고, 저장 확정과 조합 확정의 순서를 확인한다.
- [x] 키보드 표시 영역을 읽는 현재 Unity/API 경로와 지원 범위를 확인한다. Editor의 모의 키보드 영역만 통과했으면 Android OS 키보드·IME 완료로 표현하지 않는다.
- [x] 저장 상태·현재 층/도구·작업 결과를 짧게 안내하고 도움말 버튼을 제공한다. Android에서 지원하지 않는 Windows 창 기능이나 후속 터치 기능을 안내하지 않는다.

검증: 미저장 문서와 미확정 필드 문자열을 가진 채 회전·패널 전환·팝업 표시·키보드 영역 변경을 반복한다. 문서/dirty/Undo/선택 및 필드 값/포커스/커서가 유지되는지 확인하며, 한국어 실제 키보드 검증 여부는 별도 기록한다.

## D. 검증과 마감

- [x] 순수 배치 판정 검사에는 사용 폭·배율·Safe Area·방향·경계값을 넣고 기대 배치와 화면 내 경계를 확인한다. 구현과 같은 계산을 다시 적어 비교하는 검사만으로 완료하지 않는다.
- [x] 실제 UI Toolkit 화면에서 좁은/넓은 화면 전환과 팝업·입력 상태 유지 검사를 수행한다. 보드 편집→회전→Undo/Redo→저장→재열기 시 문서 의미가 유지되는지 확인한다.
- [x] Windows 기존 레이아웃·명령·16:10 창 동작과 Android 제품 선택·내부 저장의 관련 회귀 검사를 순차 실행한다. 정확한 기존 검사 진입점은 실행 전에 확인한다.
- [x] Android 타깃 스크립트 컴파일을 가능한 환경에서 검사한다. 모듈이 없으면 설치하지 않고 미검증으로 기록한다. APK와 Addressables 번들은 생성하지 않는다.
- [x] 임시 테스트 연결·활성 프로필·콘텐츠 선택을 복원한다. 결과를 `Docs/Verification/project-wide/android-level-tool-stage-02-progress.md`에 남기며 Editor/모의 영역 검사와 실기기 검사를 구분한다.
- [ ] 완료 후 변경·검증·미검증·알려진 제한을 보고하고 3단계 상세 계획·목표·복사용 실행문을 작성한다. 3단계 구현은 자동 시작하지 않는다. 실제 구현·검증 결과에 맞는 짧은 커밋 메시지만 마지막에 코드 블록으로 제공한다.

## 완료의 의미

Editor와 자동 검사로 입증한 반응형 배치·공통 상태 보존 범위는 명시할 수 있다. 실제 Android 설치·Safe Area·OS 키보드·한국어 IME를 검사하지 않았다면 해당 항목은 미검증으로 남긴다. 코드 구현 종료와 실기기 검수 완료를 구분하고, 미검증 조건을 체크 완료로 바꾸지 않는다.
