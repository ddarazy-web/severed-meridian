# 테스트 소스 분리 계획

**목표:** 테스트를 Assets 밖에서 관리하고 검사 시에만 임시 연결한다.

**승인 근거:** 사용자의 권장안 진행 요청. 빌드·커밋·패키지·asmdef 추가는 하지 않는다.

**구조:** Tests/Editor에 Features와 Systems 구분을 보존한다. Tools/Testing의 PowerShell 도구가 Assets/__ProjectTests/Editor로 임시 복사하고 실행 후 해제한다. 기존 namespace와 기본 Editor 어셈블리는 유지한다.

## 단계와 완료 조건

- [x] 1. 294개 C# 및 기존 테스트 데이터·폴더 메타를 분류하고 이동 전 SHA256을 확보한다. 테스트 외 소스는 변경하지 않는다.
- [x] 2. 연결·해제·실행 도구를 구현한다. 실파일 검증으로 중복 연결, 수정된 복사본, 알 수 없는 파일, 미소유 폴더 삭제를 막는지 확인한다.
- [x] 3. 테스트 소스와 .meta를 함께 이동하고 기존 fixture 경로 6곳만 새 원본 경로로 변경한다. 모든 이동 파일의 바이트·GUID 보존을 검사한다.
- [x] 4. Unity Editor 컴파일 및 대표 기존 검사 실행, 해제 후 컴파일을 확인한다. 현재 프로젝트가 열려 있으면 임의 종료하지 않고 해당 검증 제한을 보고한다.

## 검토 항목

- 모든 테스트는 Editor 아래에 연결해 런타임 어셈블리에 들어가지 않는다.
- .meta를 새로 만들지 않으며 기존 게임 에셋과 테스트 fixture는 변경하지 않는다.
- 기존 테스트 진입점은 유지한다. 기존 실행 명령은 먼저 Attach, 종료 후 Detach로 사용 가능하다.
- 임시 복사본 수정·추가 파일은 삭제하지 않고 복구 경로를 안내한다.
- 중단 후에는 Status로 소유 상태를 확인하고 Unity가 종료된 뒤 Detach한다.

독립 Unity 프로젝트와 독립 테스트 어셈블리는 이번 범위에서 만들지 않는다. 이전의 Unity 실행 증거는 과거 위치 기록으로 보존한다.
