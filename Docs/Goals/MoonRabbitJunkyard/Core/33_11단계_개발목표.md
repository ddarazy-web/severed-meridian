# 11단계 개발 목표 — 파워 단독 발동과 공통 피해 처리

- 작성일: 2026-09-27.
- 상태: 2026-09-27 구현·검증 및 완료 조건별 감사 완료.
- 상세 계획: [11단계 작업 계획](../../../Planning/MoonRabbitJunkyard/Core/32_11단계_파워발동과피해처리_작업계획.md).
- 선행: [10단계 개발 목표](31_10단계_개발목표.md) 완료. 선행 증거는 이번 실행 결과와 구분한다.

## Goal 목표

현재 Unity 프로젝트의 독립 실행 상태에 청소로켓·달폭탄의 단독 교환/제자리 발동, 기존 파워의 즉시 피격 연쇄, 매칭으로 생성된 새 파워의 턴 내 보호, 나무상자의 인접 매칭 및 직접 파워 피해를 구현한다. 기존 Match 실행 시험에서 결과와 이유를 확인하고 효과 처리 후 낙하 대기로 멈춘다. 원본 데이터와 기존 조회·매칭 계약을 보존하며 실제 Unity 조작, 정답 사례, 독립 프로세스 재현 및 회귀 검증으로 완료한다.

## 실행 지침

1. 상세 계획과 게임 규칙, 현재 소스를 대조한다. ponytail 및 프로젝트 Unity 지침을 적용하고 코드 변경 전 의존성·파일 책임·보존 기준을 기록한다.
2. 이 문서를 지정한 Goal 실행 요청은 상세 계획의 지원 범위와 구현 정책 제안을 포함한다. 확정 규칙과 충돌하는 내용은 임의로 바꾸지 않는다.
3. 10단계 완료 증거를 확인하되 과거 검사를 이번 결과에 합산하지 않는다. 다른 활성 Goal을 덮어쓰거나 중복 생성하지 않는다.
4. 스크립트는 `Assets/Scripts/Simulation`과 `Assets/Scripts/Editor/Levels`의 책임별 파일에 둔다. 게임명 폴더, 불필요한 패키지·asmdef·범용 프레임워크를 추가하지 않는다.
5. 일반 교환과 기존 매칭 생성은 보존한다. 청소로켓·달폭탄의 단독 발동 및 연쇄, 나무상자만 실행 지원을 확장한다. 직접 파워 조합과 나머지 장애물은 계획의 지원표대로 거절한다.
6. 피해 판단은 대상별 규칙으로 분리하고 읽기 전용 조회와 실제 적용이 공유한다. 범위 계산·장애물 반응·행동 실행을 하나의 거대한 매니저에 모으지 않는다.
7. 작업 사본에서 전체 결과를 완성한다. 늦게 발견한 미지원 파워까지 포함하여 거절 시 상태·이동 수·난수·직전 성공 결과를 보존한다. 성공은 수를 정확히 1 차감하고 한 번만 반영한다.
8. 기존 파워는 각각 한 번 즉시 연쇄 발동한다. 새 매칭 파워 보호와 상자 턴당 1 피해를 실제 적용한다. 효과 완료 후 낙하 대기에서 멈춘다.
9. 기존 `Match → 초기 보드 확인`의 실행 시험을 확장한다. 한국어 결과와 지원 한계를 표시하고 실제 게임 입력/연속 플레이 구현과 구분한다.
10. 정답 예제, 실제 Unity UI, 독립 프로세스 재현과 영향 범위 회귀를 검증한다. 검증하지 못한 항목은 완료 표시하지 않는다.

## 실행 기록 — Goal 실행 시 작성

### 착수와 작업 의존성

- 현재 코드와 선행 증거: 10단계 목표의 완료 기록과 BoardActionExecutor/MatchResolution, 실행 시험 화면을 확인했다. 기존 실행은 첫 매칭 후 낙하 대기이며 파워와 장애물은 거절한다. 선행 검사 수는 이번 결과에 합산하지 않는다.
- 규칙 대조와 적용 정책: 승인된 32번 계획의 지원표와 구현 정책을 적용한다. 작업 사본에 매칭→인접 상자 피해→단독 파워와 즉시 연쇄 순서로 적용하고 성공 시만 반영한다. 새 파워 보호를 미지원 종류 판정보다 먼저 적용한다.
- 작업 순서 및 파일 책임: T1 조사 → T2 DamageReaction(읽기 전용 대상 반응/턴 기록) → T3 PowerEffectResolution(범위·연쇄) → T4 BoardActionExecutor(원자적 실행) → T5 기존 Execution UI → T6 정답·실제 UI·독립 재현·회귀·감사. 상태와 인터페이스 의존성이 있어 순차 진행한다. MatchResolution 및 저장 정의는 기존 계약을 유지한다.
- 보존 기준과 임시 에셋 범위: Logs/PowerEffectVerification/baseline.json에 Scripts/Data/기획/Stories/ProjectSettings/Packages의 파일 해시를 기록했다. 검증 에셋은 Assets/__PowerEffectVerification_<guid> 범위로 생성하고 종료 후 정리한다. 기존 GUID/meta·v4·무관 Stories 변경은 보존한다.

### 구현과 사용법

- `Simulation/DamageReaction.cs`: 일반/파워/나무상자의 읽기 전용 반응·예상량·이유와 턴별 보호/발동/피해 기록. 상자 규칙은 별도 반응 메서드로 구분했다.
- `Simulation/PowerEffectResolution.cs`: 로켓/폭탄 범위, 명시적인 스택을 사용하는 즉시 연쇄, 반응 결과 적용과 효과 기록. 범용 등록 시스템이나 드론 매니저는 추가하지 않았다.
- `Simulation/BoardActionExecutor.cs`: `Swap`/`Activate` 입력을 현재 상태에서 검증하고 독립 작업 사본을 성공 시만 반영한다. 파워 교환의 매칭→신규 보호→인접 상자 피해→파워 연쇄 순서를 적용한다. 성공 후 `WaitingForFall`이며 턴 기록은 유지한다.
- `Editor/Levels/LevelInitialStateWindow.Execution.cs`와 `LevelInitialState.uss`: 제자리 발동 버튼, 입력별 활성 상태, 발동 종류/피해/보호 결과, 범위 내 변화 강조와 좁은 창 버튼 배치.
- `Editor/Levels/PowerEffectVerification.cs`와 `.UI.cs`: 정답 검사, 실제 에디터 이벤트, 화면 캡처, 독립 재현과 검증 에셋 정리. 기존 `BoardActionVerification`의 미지원 파워 사례는 이제 지원하는 로켓에서 아직 미지원인 드론으로 변경했다.
- 기존 `MatchResolution`, 저장 정의, 조회 알고리즘, 난수 구현은 변경하지 않았다. 새 파일의 `.meta`는 Unity가 생성했다.

1. `Match → 초기 보드 확인`에서 레벨과 시드를 지정한다.
2. `구성 목적`을 `시작 조건 구성`으로 선택하고 구성에 성공하면 `실행 시험`을 켠다.
3. 두 칸을 선택해 `교환 실행`, 또는 노출 로켓/폭탄 한 칸을 선택해 `제자리 발동`을 누른다. 일반 칸 제자리 입력과 미지원 조합은 이유를 표시하며 거절한다.
4. 오른쪽에서 매칭·생성, 발동 위치/종류, 상자 내구도 전후, 보호/중복 피해 억제를 확인한다.
5. 효과가 끝나면 낙하 대기로 멈춘다. `같은 시드로 초기화`로 반복한다. 제자리 버튼은 검증용이며 게임의 더블터치 입력 구현은 아니다.

재현 버전은 `board-action-power-effects-v2`, `power-effects-v1`이다. 기존 `match-resolution-v1`과 `System.Random/initial-state-v1`을 유지한다. 동일 정의·시드·입력·Unity/.NET 런타임에서 결과와 순서를 재현하며, 서로 다른 런타임의 난수 호환성은 보장하지 않는다.

### 검증과 완료 감사

- Unity 6000.3.10f1에서 최종 코드 컴파일과 모든 검증 실행이 성공했다. 최종 로그의 C# 컴파일 오류, 검증 실패, 실행 메서드 실패가 없음을 확인했다.

| 9: 즉시 연쇄 | 로켓→폭탄→로켓의 정확한 발동 좌표 순서와 각 1회 발동 검사. 스택은 자식 범위를 남은 부모 범위보다 먼저 처리 |

### 한계와 후속 작업

- 로켓·폭탄과 나무상자만 실행 지원한다. 모든 파워 조합, 드론/자석 발동, 다른 장애물은 완료 범위가 아니다.
- 낙하 대기 이후의 턴 진행·보충·자동 매칭·다음 턴 보호 해제·미션·승패는 실행하지 않는다. 턴 기록은 후속 실행까지 유지하지만 아직 후속 실행기는 없다.
- 4종 신규 파워 보호의 전체 종류 검사는 매칭 처리 직후 상태를 구성한 사례다. 실제 교환부터 처리하는 통합 사례는 로켓 생성으로 검증했다. 이를 전체 낙하 루프 검증으로 해석하지 않는다.
- 에디터 실행 시험이며 모바일 빌드·실기기·게임용 입력/애니메이션은 이번 범위에 없어 검증하지 않았다.
- 씬/프리팹, 저장 형식, 패키지와 플랫폼 설정 변경 및 Git 커밋은 하지 않았다.
