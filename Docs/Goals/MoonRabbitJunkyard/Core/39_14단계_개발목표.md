# 14단계 개발 목표 — 수거드론·무지개 자석 단독 발동

- 작성일: 2026-09-27.

- 상세 계획: [14단계 작업 계획](../../../Planning/MoonRabbitJunkyard/Core/38_14단계_드론과자석단독발동_작업계획.md).
- 선행: [13단계 개발 목표](37_13단계_개발목표.md) 완료. 실행 시 증거와 현재 소스를 다시 대조한다.

## Goal 목표

현재 Unity 프로젝트에서 수거드론·무지개 자석의 일반 블록과 교환/제자리 단독 발동 및 피격 연쇄를 구현한다. 색상 수집·나무상자 제거의 실제 미션 진행을 집계하여 드론이 남은 미션을 기준으로 목표를 추천·예약·재탐색하게 한다. 여러 드론은 동일 효과 단계의 목표 관리자와 예약을 공유한다. 기존 Match 실행 시험과 자동 연쇄에 연결하고 정답 사례·실제 UI·독립 재현·영향 회귀 및 완료 조건별 결과 기록까지 수행한다.

## 실행 지침

1. ponytail과 프로젝트 Unity 지침을 적용한다. 상세 계획·확정 규칙·현재 코드를 대조하고 순서·파일 책임·정책·검증/보존 기준을 착수 기록에 남긴다.
2. 이 문서를 지정한 실행 요청은 상세 계획의 구현 정책을 포함한다. 특히 매칭 생성 칸의 색상 수집 집계, 드론 요청/예약/착탄 순서와 한도를 명시한다. 확정 규칙과 충돌하면 임의로 바꾸지 않는다.
3. 13단계 완료 증거와 현재 소스를 확인하고 다른 활성 Goal을 덮어쓰지 않는다. 미완료 선행 조건은 사실대로 보고한다.
4. 스크립트는 Assets/Scripts 아래 기존 Simulation/Editor 구성별로 둔다. 원본 정의·v4·GUID/meta·무관 파일을 보존한다. 새 패키지·asmdef·게임명 폴더·범용 프레임워크를 추가하지 않는다.
5. 피해 반응과 미션 기여 계산은 대상 규칙에서 처리하고, 목표 관리자는 후보/예약 관리에 집중한다. 실제 피해와 사전 조회가 다른 규칙을 사용하지 않게 한다.
6. 기존 RuntimeMission을 실제 진행의 단일 원천으로 사용한다. 현재 지원하는 색상/상자 미션만 정확하게 집계하며 예약 예상량과 구분한다. 승패/보상은 구현하지 않는다.
7. 후보 조회는 순수하게 유지하고 변경 시 재평가한다. 선택과 예약은 원자적으로 처리한다. 다른 드론 예약과 예상 기여량을 반영하며 무효화 시 미션 후보부터 다시 찾는다.
8. + 타격 후 조준, 즉시 효과와 추가 착탄의 순서, 모든 드론 완료 뒤 정착을 지킨다. 실제 여러 드론 연쇄로 공유 예약을 검증한다.
9. 자석 교환 색은 입력에서 보존하고 제자리/피격 색은 실제 존재 색에서 선택한다. 일반 블록 없는 사용자 발동/피격 발동을 구분한다.
10. 현재 턴 보호·상자 피해 제한·원자적 실패·난수 재현·다음 수 전환을 유지한다. 지원 확대에 맞춰 행동 후보/종료 사유/UI를 함께 갱신한다.
11. 파워 조합은 15단계로 남긴다. 미지원 보드/미션을 일반 블록 동작으로 대체하지 않는다. 편집/저장 지원은 유지한다.
12. 실제 Unity에서 검증하고 조건별 증거·실패 수정·미지원/미검증 범위를 기록한다. 과거 검사 수를 이번 결과에 합산하거나 검증하지 않은 조건을 체크하지 않는다.

## 실행 기록 — Goal 실행 시 작성

### 착수

- 선행 증거/소스/규칙 대조: 13단계 최종 소스 해시와 착수 소스 불일치 0건. 04/11 문서와 38 계획의 단독 효과·예약·실제 진행 규칙을 기준으로 한다.
- 집계·색 선택·효과 순서 정책: 매칭 변환 칸의 원래 일반 색도 1개 수집. 자석은 교환 전 상대 색 보존, 무작위는 존재 색 단위. 즉시 타격/드론 요청 후 예약 순서 착탄, 모든 착탄 후 정착한다.
- 대상 규칙/목표 관리자/실행기 책임과 작업 순서: 미션 반응/집계 → 후보/예약 관리자 → 공통 효과 스케줄링 → 실행기/UI → 정답/실제 UI/독립 재현/회귀. 일반/상자 반응은 DamageReaction을 공유한다.
- 원본 보존 기준과 검증 에셋 소유 범위: Logs/TargetPowerVerification/baseline.json. Assets/Scripts의 Simulation 및 Editor/Levels만 구현 변경. 임시 검증 에셋은 검증기가 생성한 전용 경로만 정리한다. 15단계 문서 작성은 별도 사용자 요청이며 이번 구현 범위를 확대하지 않는다.

### 구현

- 변경 파일과 책임:
  - `Simulation/MissionProgressRules.cs`: 일반 색 소비/상자 완전 제거의 실제 진행량, 일반/상자별 미션 기여. 실제 타격과 같은 DamageReaction을 조회한다.
  - `Simulation/DroneTargetManager.cs`: 좌표순 후보 캐시, 미션 우선 무작위 선택/예약, 예상 완료·피해, 착탄 재검사/재탐색과 기록. 사라진 다른 예약은 예상 기여에서 즉시 제외하되 자기 착탄 때 해제한다.
  - `Simulation/PowerEffectResolution.cs`, `DamageReaction.cs`: 4종 단독/피격 효과, 즉시 타격 스택과 드론 요청/착탄 큐, 자석 색과 제거 전 색 기록, 턴 문맥 복사/보호.
  - `Simulation/BoardActionExecutor*.cs`: 교환 전 자석 색 보존, 지원 미션 검사, 원자적 작업 사본, 다음 행동 지원 판정.
  - `Editor/Levels/LevelInitialStateWindow*.cs`: 실제 미션 진행, 색 선택·예약·재탐색·착탄과 당시 예상 완료/피해 표시.
  - `Editor/Levels/TargetPowerVerification*.cs`: 정답 데이터, 실제 UI, 독립 재현, 보강 사례와 기존 회귀 실행. 이전 검증의 변경 기대값은 아래에 기록한다.
  - 경로는 모두 `Assets/Scripts` 아래이며 새 코드의 meta를 Unity에서 생성했다. 새 패키지/asmdef/게임명 폴더를 추가하지 않았다.
- Match 사용법 및 지원 범위: `Match > 초기 보드 확인` → 레벨 선택 → `시작 조건 구성` → `같은 시드로 구성` → `실행 시험`. 두 칸 선택 후 교환하거나 파워 한 칸 선택 후 제자리 발동한다. `낙하·공급 실행`/`자동 매칭 단계` 또는 `연쇄 끝까지`를 사용한다. 오른쪽 스크롤 영역에 실제 미션과 목표 기록을 표시한다. 일반 블록·파워 4종·나무상자 및 색상/상자 미션을 지원한다. 파워끼리 직접 교환은 계속 무비용 미지원이다.
- 알고리즘 버전: `board-action-targeting-v4`, `power-effects-targeting-v2`. 난수는 기존 `System.Random/initial-state-v1`을 유지한다. 동일 Unity/Mono·정의·시드·행동·코드 버전에서 재현하며 다른 난수 구현 간 일치를 보장하지 않는다.
- 후보 캐시·예약 수명: 한 효과 작업 사본에 관리자 하나. 보드/실제 미션/피해 변경 시 전체 후보 캐시 무효화, 다음 조회에서 재구성. 예약 필터는 매 요청 반영하며 조회는 실제 상태/난수/예약을 변경하지 않는다. 예약 기여는 현재 대상 반응으로 다시 평가한다. 요청 번호는 같은 턴에서 정착을 넘어 증가한다. 성공한 효과 단계 종료 시 예약 0개, 실패 시 관리자와 작업 사본 전체를 버린다.
- 한도와 순서: 즉시 타격은 기존 깊이 우선, 드론 `+`와 즉시 연쇄 후 요청/예약, 즉시 스택이 비면 예약 순서 착탄. 착탄 직전 1회 재평가/필요 시 재탐색하며 비동기 변경/재탐색 반복 루프를 만들지 않는다. 이벤트 상한 `max(1024, Cells.Count²×8)` 초과는 실패로 반환한다. 기존 자동 연쇄 한도/무진행 검사를 유지한다.
