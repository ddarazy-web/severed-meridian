## Goal 목표

현재 Unity 프로젝트의 공통 실행기와 Match 수동 시험에 2×2 발전기 충전, 완충 시 연결 장애물 제거, 직접 파괴에 따른 연결 해제와 자동 철거를 구현한다. 미션 집계·드론의 간접 기여와 본체 예약·활성 전선 및 충전 표시를 연결하고 실제 UI, 독립 재현, 영향 회귀, 원본 보존 감사로 검증한다.

## 실행 지침

1. 19단계 완료 감사와 최종 소스 해시, 현재 코드/Goal을 먼저 확인한다. 계획 시 2,214 PASS/0 FAIL·20조건·소스 차이0·활성 Goal 없음을 확인했다. 동일 목표면 재개하고 다른 활성 Goal을 덮어쓰지 않는다.
2. ponytail과 프로젝트 Unity 지침을 적용한다. 이 문서를 지정한 Goal 실행 요청은 상세 계획의 범위와 기술 설계에 대한 실행 승인이다.
3. T1→T6 순서로 진행한다. Scripts의 기존 구성에서 게임·수동 시험·향후 봇이 같은 실행 규칙을 사용하도록 한다.
4. 충전과 내구도 피해를 구분한다. 발전기의 생존은 실제 점유로 확인하고 불변 연결 정의에서 현재 활성 연결을 조회한다.
5. 전체 연쇄에서 본체당1회 충전, 완충 즉시 연결 대상 제거, 효과 종료 후 정착 순서를 유지한다. 마지막 연결 직접 파괴 시 충전 없이 자동 철거한다.
6. 본체 제거와 미션 집계를 공유하고 발전기/연결 제거로 먼지나 주변 장애물을 추가 파괴하지 않는다. 발전기 자체의 새 미션은 만들지 않는다.
7. 종류별 규칙에서 간접 기여를 조회한다. 드론 매니저는 캐시·추천·예약을 담당하며 충전 예약과 미션 완료 예측, 직접/간접 중복을 구분한다.
8. 실제 Match 화면과 독립 Unity 프로세스에서 검증한다. 화면 효과는 실행 순서/난수에 관여하지 않으며 편집 원본을 변경하지 않는다.
9. 회수·승패/섞기/라스트팡·아이템/부스터·봇·통계·난이도·출시 아트는 제외한다. 망치 입력 구현은23단계로 남긴다.
10. v4/GUID/meta·무관 파일을 보존한다. 기존 미지원 검사의 목적을 유지하고 실제 검사 결과·미검증 범위·알고리즘 버전·조건별 증거를 기록한다. 아래20조건이 검증되어야 완료다.

## 실행 기록 — 2026-09-27 완료

### 구현과 구조

- 19단계의 2,214 PASS/20조건과 소스 차이0을 확인하고 `Logs/GeneratorVerification/baseline-hashes.json`에 Scripts/Data/기획/Stories/Packages/ProjectSettings 기준을 저장했다. 기존 Stories 변경은 보존했다.
- `Assets/Scripts/Features/Obstacles/Runtime/GeneratorRules.cs`가 활성 연결·충전·완충 작동·연결 해제·자동 철거와 기록을 담당한다. 불변 연결 정의는 유지하고 실제 점유로 생존을 판단한다.
- `ObstacleDamageRules`의 공통 본체 제거를 직접 피해와 발전기가 공유한다. `DamageReaction`/`TurnEffectContext`는 충전 반응과 수당 이력을 분리한다. `PowerEffectResolution`은 완충을 현재 효과 안에서 처리하고 기존 정착으로 넘긴다.
- `MissionProgressRules`가 연결 대상의 간접 기여와 본체별 예상 완료를 계산한다. `DroneTargetManager`는 네 칸 단일 예약·후보 캐시·재탐색을 관리한다. 예상 충전과 예상 피해는 별도 수치이며 실제 미션은 예약으로 바뀌지 않는다.
- `BoardActionExecutor.Cascade`의 반복 상태 판정에 충전값/이력을 포함했다. 충전 진행을 무진행 상태로 오인하지 않는다.
- `Assets/Scripts/Features/LevelEditor/Editor/Presentation/Board/LevelGeneratorOverlay.cs`가 활성 전선, 색·모양 단자, 본체당3~5개 충전등과 짧은 빛을 그린다. 스크롤 좌표계를 공유하고 입력을 가로채지 않는다. 빛 종료 후 다시 그려 잔상을 지운다.
- 저장 형식 v4, 원본 에셋/GUID/meta, 패키지·어셈블리를 유지했다. 게임명 폴더나 별도 실행 엔진, 외부 이미지/패키지는 추가하지 않았다.

### 수정한 검증 실패와 한계

- 첫 실행은 샌드박스에서 Unity 초기화 전 멈춰 소유 프로세스만 정리하고 정상 권한으로 실행했다. 최초 컴파일에서 해당 Unity에 없는 `LineCap.Square`를 `Butt`로 수정했다.
- 첫 UI 시험은 대각선 채우기 후 로켓이 같은 칸에 남는다고 가정해 실패했다. 현재 보드의 실제 세로 로켓을 선택하도록 시험 입력을 고쳤으며 게임의 낙하 규칙은 바꾸지 않았다.
