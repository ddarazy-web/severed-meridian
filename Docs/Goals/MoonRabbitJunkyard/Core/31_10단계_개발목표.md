## Goal 목표

현재 Unity 프로젝트에서 장애물 없는 보드의 일반 교환을 검증하고, 첫 매칭의 패턴 선택·제거·파워 생성·이동 수 차감을 독립 실행 상태에 적용한다. 기존 Match 확인 화면에서 입력 방향과 결과 근거를 확인하며, 처리 후에는 낙하 대기로 멈춘다. 원본/v4와 기존 조회·시작 구성을 보존하고 실제 Unity 조작 및 독립 프로세스 재현을 검증한다.

## 실행 지침

1. 상세 계획, 확정 게임 규칙, 현재 구현을 대조한다. ponytail 및 프로젝트 Unity 지침을 따르고 코드 추가 전 작업 의존성·파일 책임·검증 방법을 아래에 기록한다.
2. 완료된 9단계 기록과 현재 소스를 대조하고 변경 영향에 필요한 회귀를 수행한다. 완료된 9단계 Goal을 다시 시작하지 않는다. 다른 활성 Goal이 있다면 중복 생성하거나 완료로 덮어쓰지 않는다.
3. 이 문서를 지정한 실행 요청은 상세 계획의 추천 범위와 구현 정책 제안을 포함한다. 확정 규칙과 충돌하는 사례는 임의로 변경하지 말고 제시한다.
4. `Assets/Scripts/Simulation`과 `Editor/Levels` 아래 책임별로 구성한다. 신규 게임명 폴더·패키지·asmdef·범용 프레임워크를 만들지 않는다.
5. 원본 LevelDefinition·v4·GUID/meta·저장 검증 정책과 8단계 원시 후보, 9단계 읽기 전용 조회 및 시작 구성 계약을 보존한다.
6. 실행 가능한 시작 상태와 일반↔일반 입력에 한정한다. 장애물·덮개·먼지·회수 부품이 있는 보드 및 파워 발동 입력은 실행 전에 미지원으로 거절한다. 읽기 전용 조회는 계속 제공한다.
7. 현재 상태로 재검증하고 거절 시 상태·수·난수를 유지한다. 성공은 한 번만 적용하고 이동 수를 1 차감한다. 패턴 선택 우선순위·동률 난수·생성 위치를 계획대로 처리한다.
8. 파워 생성 칸과 선택 패턴 외 블록을 정확히 보존한다. 결과에 제거/변환 사실과 새 파워의 턴 소속을 기록한다. 미션 진행이나 실제 보호 효과 완료를 주장하지 않는다.
9. 처리 후 낙하 대기로 멈추고 추가 행동을 막는다. 전체 턴 완료·승패·난이도 판정은 제외한다.
10. 실제 Unity 화면, 손으로 정한 정답 예제, 독립 프로세스 재현과 영향 범위 회귀를 검증한다. 이전 단계 검사 수를 이번 결과에 합산하지 않는다.

## 실행 기록 — Goal 실행 시 작성

### 착수와 작업 의존성

- 9단계 최종 소스 해시와 현재 소스가 동일함을 확인했다. 이전 331건의 완료 증거는 선행 증거로만 사용하며 10단계 검증에 합산하지 않는다.
- T1 규칙/보존 기준 → T2 실행 상태·난수 독립 복사 → T3 중첩 선택/교환 실행 → T4 기존 Match 화면 연결 → T5 정답 예제·실제 UI·독립 재현·8/9단계 회귀 → T6 완료 조건별 감사와 사용법 기록 순서다.
- 변경 책임은 Simulation의 상태/난수 및 새 MatchResolution/BoardActionExecutor, 기존 초기 확인 창의 실행 시험 partial/USS, Editor 검증 파일에 한정한다. 정의·GUID·v4·일반 레벨 편집기·패키지는 보존한다.
- 보존 기준은 `Logs/BoardActionVerification/baseline.json`, 검증 에셋은 `Assets/__BoardActionVerification_<guid>` 범위다.
- 연결된 겹침 그룹마다 하나를 선택하고 낮은 패턴 전용 칸은 남긴다. 실제 교환 방향의 도착 칸을 생성 위치로 사용하며 양쪽 독립 그룹은 각각 처리한다.
- 적용 전에 지원 범위/현재 상태를 재검증하고 작업 사본에서 결과를 완성한 뒤 반영한다. 거절은 실행 상태와 난수까지 보존한다. 성공 후에는 낙하 대기로 멈춘다.

### 구현과 사용법

1. **Match → 초기 보드 확인**에서 레벨과 시드를 지정하고 `구성 목적`을 `시작 조건 구성`으로 선택한다.
2. `같은 시드로 구성`으로 시작 조건을 통과하면 `실행 시험`을 켤 수 있다. 원시 후보 모드에서는 실행 시험을 켤 수 없다.
3. 일반 블록의 출발 칸, 도착 칸을 차례로 선택하고 `교환 실행`을 누른다. 한 칸만 선택하면 실행 버튼은 비활성이다. 같은 칸 재선택 또는 `선택 취소`로 선택을 지울 수 있다.
4. 유효 교환은 이동 수를 1 차감한다. 제거 칸은 분홍 테두리, 새 파워는 민트 테두리로 구분하며 오른쪽에서 입력 방향·선택 근거·처리 좌표·원래 색·난수 진행을 확인한다.
5. 결과는 **첫 매칭 처리 완료 · 낙하 대기**이며 추가 실행은 막힌다. `같은 시드로 초기화` 후 다시 실행 시험을 켜면 같은 결과를 확인할 수 있다. 실행 시험을 끄면 보존된 조회용 시작 보드로 돌아간다.
6. 레벨·시드·목적·원본 내용 변경 또는 창 종료 시 실행 시험 상태를 폐기한다. 원본 변경 직후 감지 주기보다 실행 버튼을 먼저 눌러도 입력 지문을 재확인해 이전 상태를 실행하지 않는다.
7. 장애물·덮개·먼지·회수 부품이 있는 보드와 파워 발동·조합은 이번 실행 범위 밖이라는 메시지로 거절한다. 일반 교환 규칙 위반과 미지원 이유를 구분한다.

### 구조와 알고리즘

```text
Assets/Scripts/
├─ Simulation/
│  ├─ BoardActionExecutor.cs          실행 소유권·재검증·교환·이동 수·낙하 대기
│  ├─ MatchResolution.cs              겹침 선택과 선택 패턴의 제거·변환
│  ├─ LevelRuntimeState.cs            실제 상태 독립 복사
│  └─ SimulationRandom.cs             현재 난수 진행 복사
└─ Editor/Levels/
   ├─ LevelInitialStateWindow.Execution.cs   실행 시험 UI
   ├─ LevelInitialStateWindow.cs / .Query.cs / LevelInitialState.uss
   └─ BoardActionVerification.cs / .UI.cs    데이터·실제 화면·재시작 검증
```

- `BoardActionExecutor`가 시작 상태를 독립 복사한다. 현재 상태의 교환 판정은 기존 `ActionQuery`/`StartConditionReport`를 재사용한다. 성공 후보를 작업 사본에서 완성한 다음 실행기의 상태로 교체한다. 거절은 실행 상태와 난수를 보존한다.
- 변경 가능한 셀·본체·미션·공급 커서를 복사하고 불변 정의·흐름은 공유한다. 원시 빌더로 다시 추첨해 복사본을 대체하지 않는다.
- 난수는 기존 `System.Random/initial-state-v1`을 유지한다. 실제 호출한 상한 목록을 기록하고 동일 호출을 새 로컬 난수에 재생해 복사한다. 복사는 누적 추출 수에 비례하는 비용이 있으며 System.Random 내부 필드나 전역 Unity 난수에 접근하지 않는다.
- 패턴 선택 버전은 `match-resolution-v1`, 실행 버전은 `board-action-first-match-v1`이다. 겹친 패턴의 연결 그룹을 안정 정렬하고 자석 > 폭탄 > 로켓 > 드론, 같은 우선순위에서는 긴 패턴을 선택한다. 완전 동률일 때만 난수를 한 번 소비한다.
- 선택한 패턴만 적용한다. 생성 위치는 해당 패턴 안의 교환 도착 칸이며, 양쪽 독립 패턴은 각각 생성한다. 하위 패턴의 전용 칸은 남긴다.
- 결과의 `MatchedBlockChange`는 제거/변환된 일반 블록의 원래 색을 모두 보관한다. 파워로 바뀐 블록도 빠지지 않는다. 새 파워는 `CreatedOnTurn`으로 이번 수 소속을 기록하며 낙하 대기에서 그 기록을 유지한다. 실제 피격 보호·미션 집계는 아직 수행하지 않는다.
- Editor는 실행 상태 내부 필드를 직접 변경하지 않고 실행기를 호출한다. 새 패키지·asmdef·게임명 폴더·범용 이벤트 시스템·저장 형식 변경은 없다.

### 검증에서 구분한 사항

- 직선 3/4/5, 폭탄 8방향, 2×2와 양쪽 독립 파워 생성은 시작 조건을 만족한 보드에서 실제 교환으로 검증한다.
- 직선 6개 이상이나 일부 복합 동률은 안정된 시작 보드의 단일 교환만으로 만들 수 없다. 해당 사례는 매칭 처리 단계에 직접 입력해 선택·실제 제거/변환을 검증한다. 이를 실제 플레이나 자동 낙하 연쇄 구현으로 표시하지 않는다.
- 실제 화면 확인 뒤 내부 enum 이름이 보이던 결과를 한국어로 바꾸고, 실행 후 이전 조회 목록을 숨겼다. 변경한 화면을 다시 실행해 확인했다.
- 최종 검사 수·회귀 결과·보존 감사는 아래 기록을 따른다.

### 최종 보존 감사와 한계

- [보존 변경 목록](../../../../Logs/BoardActionVerification/preservation-changes.txt)은 계획한 실행 상태/난수 복사와 초기 확인 UI, 이번 문서 변경만 포함한다. 기존 v4 정의·레벨 데이터·meta/GUID·Packages·ProjectSettings·일반 레벨 편집기에는 변경이 없다.
- 새 파일의 Unity meta가 생성됐고 기존 GUID는 유지됐다. 검증 소유 에셋 폴더와 대기 state.json, 검증 Unity 프로세스가 남지 않았다. 최종 소스 해시는 `Logs/BoardActionVerification/final-source-hashes.json`에 기록했다.
- 실제 파워 발동·연쇄·피격 보호·장애물 반응·낙하·공급·미션 집계·승패·봇은 미지원이다. 결과의 턴 기록을 실제 보호 기능의 완료로 간주하지 않는다.
- 이번 화면은 개발용 첫 매칭 실행 시험이다. 전체 한 수나 레벨 클리어 가능성을 검증한 것이 아니다.
- 동일 입력·시드·알고리즘·Unity/Mono 환경의 재현을 확인했다. Android/iOS 및 다른 런타임의 난수열·성능은 미검증이다.
