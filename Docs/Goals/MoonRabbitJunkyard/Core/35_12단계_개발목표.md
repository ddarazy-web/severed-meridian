## Goal 목표

현재 Unity 프로젝트에서 11단계의 효과 처리 후 상태를 입력받아 4방향 중력·대각선·직접 경로·합류·통로에 따른 낙하와 생성구별 일반/파워 기본 공급을 실행한다. 새 매칭 파워의 보호와 공급 커서를 정확히 유지하고, 모든 이동·공급이 멈추면 자동 매칭 대기로 정지한다. 기존 Match 실행 시험에서 경로와 공급 결과를 확인하며 실제 Unity 조작·정답 사례·독립 프로세스 재현·회귀 검증과 완료 기록까지 수행한다.

## 실행 지침

1. 계획과 확정 게임 규칙, 현재 구현을 대조한다. ponytail·프로젝트 Unity 지침을 적용하고 작업 순서·파일 책임·정책·검증 방법을 착수 기록에 남긴다.
2. 이 문서를 지정한 Goal 실행 요청은 계획의 지원 범위와 구현 정책 제안을 포함한다. 기존 확정 규칙과 충돌하면 임의로 바꾸지 않는다.
3. 11단계 완료 증거를 현재 소스와 대조한다. 과거 검사 수를 이번 결과에 합산하지 않으며 다른 활성 Goal을 덮어쓰지 않는다.
4. 스크립트는 `Assets/Scripts` 아래 기존 Simulation/Editor 구성별로 둔다. 원본 정의·v4·GUID/meta·저장 검증·조회 계약을 유지하고 불필요한 폴더·패키지·asmdef·범용 프레임워크를 추가하지 않는다.
5. 일반/파워 이동과 Random/Fixed 기본 공급을 구현한다. 고철/회수 부품 공급·유지 방식과 미지원 보드 요소는 부분 처리 전에 명시적으로 거절한다. 편집/저장 지원 자체를 제거하지 않는다.
6. 읽기 전용 후보 조회와 실제 이동을 분리한다. 후보 조회는 난수와 상태를 소비하지 않는다. 경쟁 해소와 공급에만 실행 난수를 사용한다.
7. 상태·커서·난수·보호의 작업 사본에 적용해 성공 시만 반영한다. 정착 실패는 효과 처리 직후 상태를 보존하며, 성공한 사용자 행동을 되돌리지 않는다.
8. 이동 수·턴·미션을 변경하지 않고 새 파워의 보호를 따라 이동시킨다. 공급 파워와 이전 보호 좌표에 보호가 잘못 붙지 않게 한다.
9. 정착 완료 후 자동 매칭 대기에서 멈춘다. 매칭 조회는 허용하되 제거·자동 연쇄·새 사용자 행동·승패는 실행하지 않는다.
10. 기존 Match 화면에 정착 버튼과 결과를 연결한다. 실제 Unity UI·독립 재현·변경 영향 회귀를 수행하고 검증하지 못한 항목은 완료로 표시하지 않는다.

## 실행 기록 — Goal 실행 시 작성

### 착수와 의존성

- 선행 증거 및 코드/규칙 대조: 11단계 최종 소스 해시와 현재 파일 불일치 0건. 효과 실행은 WaitingForFall에서 정지하며 흐름/공급은 정의 복사만 한다. LevelFlowRules의 통로→직접 경로→중력 우선 관계와 합류 검증을 대조했다.
- 경쟁·종료·보호 모델의 적용 정책: 승인된 계획의 묶음 이동→대각선→공급 순서를 따른다. 보호 좌표 집합을 독립 복사하고 이동 묶음별 원자적으로 재매핑한다. 소모된 파워의 좌표 기록은 효과 종료 후 정착 사본에서 비우며 상자 피해 기록은 유지한다. 별도 영구 ID는 추가하지 않는다.
- 파일 책임과 작업 순서: T1 조사 → T2 MovementQuery(읽기 전용 이동/흐름 검사) → T3 SettlementResolution(경쟁/이동) → T4 기본 공급·반복/종료 및 Executor 원자적 반영 → T5 기존 Execution UI → T6 검증·독립 재현·회귀·감사. 동일 상태 모델에 의존하므로 순차 진행한다.
- 보존 기준과 검증 에셋 범위: Logs/SettlementVerification/baseline.json. 검증 에셋은 Assets/__SettlementVerification_<guid>에만 만들고 완료 후 정리한다. 원본 정의·v4·기존 meta·무관 Stories 변경은 보존한다.

### 구현과 사용법

- 새 파일: `Assets/Scripts/Features/BoardFlow/Runtime/MovementQuery.cs`(읽기 전용 이동 후보/흐름 검사), `SettlementResolution.cs`(이동 경쟁·기본 공급·정착 반복/실패 보존), `Assets/Scripts/Editor/Levels/LevelInitialStateWindow.Settlement.cs`(정착 UI), `SettlementVerification.cs`, `SettlementVerification.UI.cs`, `SettlementVerification.Supplemental.cs`(정답·실제 UI·독립 재현·경계 검사). 신규 .meta는 Unity가 생성했다.
- 기존 변경: `BoardActionExecutor.cs`의 정착 명령/자동 매칭 대기, `DamageReaction.cs`의 문맥 복사/보호 좌표 이동, `LevelInitialStateWindow.Execution.cs`의 정착 버튼과 단계 안내. 기존 레벨 정의·RuntimeState·난수 구현·매칭/효과 알고리즘은 변경하지 않았다.
- 사용법: `Match → 초기 보드 확인`에서 시작 조건 구성 → 실행 시험 → 교환 또는 제자리 발동 → `낙하·공급 실행`. 상단 요약과 오른쪽 기록에서 이동/공급/빈칸/커서/난수/보호를 확인한다. 정착 매칭 버튼은 조회만 한다. 재시험은 `같은 시드로 초기화`를 누른다. [에디터 사용법](../../../Contents/MoonRabbitJunkyard/09_레벨에디터.md)에도 반영했다.
- 버전: `movement-query-v1`, `settlement-v1`. 기존 행동은 `board-action-power-effects-v2`, 난수는 `System.Random/initial-state-v1`. 동일 Unity 6000.3.10f1/Mono·레벨 정의·시드·입력·알고리즘 버전에서 재현한다. 다른 런타임의 System.Random 결과까지 보장하지 않는다.
- 내부 정착 한도: `max(1024, Cells.Count²×4)`. 10×10은 40,000묶음이며 정상 최장 직접 경로 100개 공급/4,950칸 이동(총 5,050기록)이 종료됨을 확인했다. 동일 상태·동일 난수 소비 횟수 재방문은 확정 반복, 난수 진행 반복은 한도 실패로 진단한다.
