2. 상세 계획과 최신 코드를 먼저 대조한다. 이 문서를 참조한 Goal 실행 요청은 상세 계획의 검수 및 재현된 결함 수정까지 포함한다. 이미 합의한 범위를 다시 묻지 않는다. 확정 게임 규칙 충돌은 근거를 확인하고 임의 변경하지 않는다.
3. 선행 결과는 참고 증거다. 이번 통합 인수 조건을 과거 통과 개수만으로 완료 처리하지 않는다. 테스트 개수나 파일 수를 목표로 삼지 않는다.
4. 기존 창·편집 로직·규칙 검사·검증 도구를 활용한다. 결함이 없으면 임의로 코드를 재설계하지 않는다. 새 프레임워크·패키지·게임명 폴더를 추가하지 않는다.
5. 스크립트는 `Assets/Scripts` 아래 구성별로 유지한다. 저장 모델은 v4를 보존하고 자동 정규화·형식 전환·원본 저장을 추가하지 않는다.

7. 임시 검수용 레벨을 사용하고 기존 사용자 레벨을 테스트 대상으로 수정하지 않는다. 소유한 임시 데이터만 정리한다. 씬·패키지·프로젝트 설정·무관한 문서는 변경하지 않는다.
8. Unity 검증 프로세스가 실행되는 동안 소스 변경으로 도메인 재로딩을 유발하지 않는다. 저장/재시작 비교는 독립 프로세스 완료까지 확인한다.

## 실제 사용 순서

1. **Match → 레벨 에디터**에서 새 레벨을 만들고 레벨 설정 탭에서 번호·이동 횟수·사용 색과 미션을 설정한다.
2. 왼쪽 배치 카테고리로 보드와 층별 요소를 구성하고 흐름 탭에서 중력·경로·통로·장치 연결을 설정한다. 경로와 전선은 완료를 눌러 확정한다.
3. 생성구를 선택해 공급 방식과 목록을 지정한다. 목록 맨 아래가 먼저 공급된다. 같은 종류 다중 선택은 공통 속성으로 편집한다.
4. 우클릭으로 설정/공급 목록을 복사하거나 기존 편집 작업을 실행한다. 공급 행을 우클릭하면 해당 행이 대상이다. 상단/하단 이동 한계에 해당하는 항목은 비활성화된다. 네이티브 메뉴가 열린 동안 배경 하이라이트의 다시 그리기는 늦을 수 있다.
5. **검사**로 오류를 확인한다. 오류를 클릭해 해당 층·칸·공급 항목·연결 또는 레벨 설정으로 이동한다. 예: 합류 오류는 유입 순서를 확정하고 재검사한다. 손상 데이터는 표시된 필드 경로와 기존 Inspector를 확인한다.
6. **저장**은 정상·미완성·오류 데이터를 보존한다. **복제**는 현재 미저장 내용까지 포함한 별도 번호/GUID의 사본을 만들며 원본을 강제 저장하지 않는다.
7. 레벨을 전환하면 미완료 입력과 선택 도구 상태를 초기화하고 안내도 함께 바뀐다. 속성/편집 변경은 기존 Undo/Redo를 사용한다. 복제 파일 자체 삭제는 Project 창에서 처리한다.

## 검사 범위와 제한

구조·공급 수량 검사 통과는 플레이/클리어 가능 판정이 아니다. 실제 생성·낙하·매칭·파워 효과·미션 실행, 테스트 플레이, 봇·난이도 분석은 구현하지 않았다. 오류를 자동으로 고치거나 데이터 형식을 자동 전환하지 않는다. 새 편집 기능·아트·씬·패키지는 추가하지 않았다.
