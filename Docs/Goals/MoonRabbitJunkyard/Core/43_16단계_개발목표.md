# 16단계 개발 목표 — 거미줄·먼지 반응과 미션 연동

- 작성일: 2026-09-27.
- 상태: 구현·검증 완료. 완료 조건 20개, 중복 제외 1,569개 검사 PASS.
- 상세 계획: [16단계 작업 계획](../../../Planning/MoonRabbitJunkyard/Core/42_16단계_거미줄과먼지_작업계획.md).
- 선행 문서: [15단계 개발 목표](41_15단계_개발목표.md).

## Goal 목표

기존 Unity Match 실행 시험에 거미줄과 먼지의 실제 반응을 추가한다. 내용물 보존, 층별 턴 피해 제한, 매칭 파워 대체 생성, 잔존 매칭 반복 방지, 먼지의 조건부 피해를 구현하고 파워 단독/조합 10종·낙하·미션·드론 예약에 연결한다. 실제 Unity 검증과 독립 재현, 영향 회귀, 완료 조건별 증거 기록까지 마친다.

## 실행 지침

1. 현재 Goal과 15단계 문서·검증 결과·최종 소스를 먼저 확인한다. 문서 작성 당시 15단계는 활성/미완료다. 같은 15단계 Goal이 남아 있으면 기존 승인 범위의 회귀·완료 감사를 먼저 마치고 실제 조건 충족 후 완료 처리한다. 다른 Goal을 덮어쓰지 않는다.
2. 15단계 완료 후 이 문서를 목표로 새 Goal을 생성한다. 이미 같은 16단계 목표가 활성화돼 있으면 이어서 실행하고 중복 생성하지 않는다.
3. ponytail과 프로젝트 Unity 지침, 게임 규칙 및 상세 계획을 적용한다. 실행 요청에는 계획의 세부 정책이 포함되며, 확정 기획과 충돌하면 먼저 근거를 확인한다.
4. 스크립트는 Assets/Scripts의 기존 Simulation/Editor 구성별로 분리한다. 규칙별 책임을 드러내고 공통 효과 실행과 목표 관리 경로를 재사용한다.
5. 거미줄 피해, 내용물 소비, 먼지 피해를 분리한다. 같은 좌표라도 층별 턴 피해 기록을 구별한다. 보존된 내용물을 수집 완료로 집계하지 않는다.
6. 피해받은 거미줄의 매칭 참여를 막지 않는다. 변화 없이 남은 동일 패턴만 재처리하지 않고 새 블록 유입에 의한 매칭은 허용한다.
7. 단독/조합 드론의 예상 피해·예상 완료·실제 완료를 구별한다. 예약 관리자에 장애물별 규칙을 몰아넣지 않는다.
8. 미지원 보드는 명확히 거절한다. 원본 레벨/v4/GUID/meta 및 무관 파일을 보존하고 새 패키지·asmdef·별도 실행 엔진은 추가하지 않는다.
9. 기타 장애물 실행, 승패, 라스트팡, 자동 섞기, 아이템/부스터, 봇, 난이도 분석, 신규 해금/공급 규칙, 런타임 아트·연출은 제외한다.
10. 실제 검증 결과만 완료 근거로 기록한다. 실패·미검증은 숨기지 않고, 선행 검사 수를 이번 통과 수로 합산하지 않는다.

### 실행 시 작성

- 선행 완료 증거·활성 Goal·최종 소스 대조: 15단계 completion-audit의 1,405 PASS/20조건 확인, 최종 소스 해시 불일치 0건. 16단계 Goal이 이미 활성화되어 중복 생성하지 않았다. 보존 기준은 `Logs/LayerVerification/baseline.json`이다.
- 책임 분리·정책 결정·알고리즘 버전: `LayerDamageRules.cs`의 WebRules/DustRules에 반응을 분리했다. 실행 `board-action-layers-v6`, 매칭 `match-resolution-layers-v3`, 파워 `power-effects-layers-v4`, 정착 `settlement-layers-v3`으로 갱신했다. 조회·시작 구성·저장 스키마는 유지한다.
- 층별 피해·잔존 패턴·자석 처리 순서: 계획의 세부 정책을 적용한다. 잔존 패턴 이력과 참여 블록 유입 이력은 다음 사용자 수에도 보존하되 피해/파워 보호는 새 턴에 초기화한다. 무관한 행동만으로 잔존 매칭이 다시 피해를 주지 않게 하기 위한 수명 분리다. 자석은 노출 대상 선변환 → 묶인 대상 덮개 피해 → 변환 파워 발동 순서다.
- 완료 조건별 검사/결과 경로: 아래 완료 감사 표 및 `Logs/LayerVerification`.
- 실제 UI·독립 재현·회귀 결과: 실제 유효 배치/4미션에서 UI 실행, 1000/680 폭 확인, 서로 다른 Unity 프로세스 재현과 8~15단계 영향 회귀를 통과했다.
- 실패 수정 및 기대값 변경 이유: 효과 단위 시험은 실행 상태에 층을 주입하므로 초기 미션 가용 수량과 달랐다. 미션 가용성 오류 때문에 첫 시험 구성을 수정했으며 제품 검증기는 완화하지 않았다. UI/재현용 레벨은 편집 API 배치·실제 레벨 검증·시작 조건을 모두 통과한다. 기존 거미줄/먼지 미지원 기대값은 지원 또는 교환 금지 기대값으로 갱신했고, 늦은 실패 주입은 여전히 미지원인 곰팡이로 교체했다.
- 원본 보존·임시 자원 정리: 착수 기준 330개 파일을 대조하고 기존 정의/v4/Board/Levels/에셋/GUID/meta/패키지/설정/스토리 파일을 보존했다. 감사 결과는 preservation-audit.json과 completion-audit.json, 최종 소스는 final-source-hashes.json에 기록한다.
- 미지원/미검증 범위: 상자·거미줄·먼지 외 장애물/회수 부품 실행, 색상/상자/거미줄/먼지 외 미션, 신규 공급 방식, 승패·라스트팡·자동 섞기·아이템/부스터·봇·난이도 분석·기기 빌드·런타임 연출은 이번 완료 범위에 포함하지 않는다.

모든 파일은 `Assets/Scripts`의 기존 기능 경계 안에 있다. 새 패키지·asmdef·저장 스키마·게임명 폴더·전역 관리자·별도 실행 엔진은 추가하지 않았다. Web/Dust 미션 규칙은 실제 반응을 조회하며 관리자가 피해 규칙을 복제하지 않는다.

`Match/초기 보드 확인`에서 레벨과 시드를 지정해 시작 조건을 구성하고 실행 시험을 켠다. 교환/파워 발동 후 단계 실행 또는 연쇄 끝까지 실행한다. 보드의 `줄숫자`는 덮개 내구도, `*숫자`는 먼지 내구도다. 우측 스크롤 기록에서 실제 미션, 보존/피해 결과와 드론 예상 예약을 구별해 확인한다. 원본 레벨은 실행으로 수정하지 않는다.

잔존 패턴은 패턴 종류·색·참여 좌표와 LastArrival 이력으로 구별한다. 같은 블록이 남은 패턴은 다음 사용자 수에서도 재처리하지 않는다. 새 유입·교환은 새로운 이력을 가지며 정상 매칭한다. 상자/거미줄/먼지 피해와 매칭 파워 보호는 새 턴에 초기화한다. 전체가 덮인 파워 생성 패턴은 생성 생략 이유를 기록하며, 그러한 고정 완성 패턴은 정상 시작 조건으로 허용되지 않음을 별도로 검증했다.
