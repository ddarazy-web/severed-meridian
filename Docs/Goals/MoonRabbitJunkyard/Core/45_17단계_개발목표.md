## Goal 목표

현재 Unity 프로젝트의 Match 실행 시험에서 고철 뭉치의 교환·낙하·피해·제거를 구현하고, 고정 공급 목록과 고철 개수 유지 공급을 연결한다. 이동하거나 새로 생성되는 고철의 본체 식별·내구도·턴 피해 기록을 정확히 유지한다. 고철 미션·드론 예약·실제 UI에 통합하고 독립 재현·영향 회귀·완료 감사까지 마친다.

2. ponytail과 프로젝트 Unity 지침, 확정 게임 규칙, 상세 계획을 적용한다. 이 문서 지정 실행 요청에는 계획의 세부 정책이 포함된다. 기존 계약과 충돌하면 근거를 기록하고 해결한다.
3. 스크립트는 Assets/Scripts의 기존 Simulation/Levels/Editor 구성별로 분리한다. 별도 게임명 폴더나 새 실행 엔진을 만들지 않는다.
4. 본체 식별과 작업 사본 → 이동/교환/피해 → 고정 공급 → 개수 유지 → 통합 검증 순서로 진행한다.
5. 본체 키를 이동 때 보존하고 제거된 키를 새 고철에 재사용하지 않는다. 최초 정의 좌표와 현재 점유 좌표를 혼동하지 않는다.
6. 교환/낙하에서 ObstacleIndex를 내용물과 함께 옮기고 먼지 등 바닥은 남긴다. 새 공급 본체는 실행 상태에만 추가한다.
7. 턴당 피해 제한은 본체에 적용하며 이동·예약 해제로 초기화하지 않는다. 완전 제거만 미션으로 집계하고 생성 때문에 목표 수량을 늘리지 않는다.
8. 고정 공급은 생성구별 순서·수량을, 유지 공급은 살아 있는 개수·부족량·추가 한도를 따르게 한다. 막힌 생성구는 소비 없이 기다린다.
9. 모든 변경과 실패에 동적 본체 목록·공급 커서/카운터·난수·미션·턴 문맥의 원자성을 유지한다. 조회는 상태를 바꾸지 않는다.
10. 원본/v4/GUID/meta·무관 파일과 기존 상자/거미줄/먼지/파워 동작을 보존한다. 새 패키지·asmdef·프레임워크는 추가하지 않는다.
11. 회수 부품·기타 장애물·승패·라스트팡·아이템/부스터·자동 섞기·봇·난이도 분석·런타임 연출은 제외한다.
12. 실제 검증 결과만 완료로 기록한다. 진단용 상태 주입 시험과 실제 유효 편집 레벨 시험을 구별하고, 기대값 변경 이유와 미검증 항목을 남긴다.

- Unity executeMethod 진입점: Levels.Editor.ScrapVerification.Data, Supplemental, Edges, Regression, Start(실제 창), Restart(다음 독립 프로세스). Start는 재현용 임시 에셋을 만들고 Restart는 비교 후 소유 에셋을 정리한다.
- 단위 시험에는 빈칸/상태 주입 정답 사례가 포함된다. 실제 UI 정의는 편집 API 및 레벨/시작 검증을 통과했고 원본 JSON/GUID/dirty/시작 상태 보존을 확인했다.
- 시험 수정: 목표0 금지 계약을 확인해 실행 성공 기대를 거절 기대로 수정했다. 마지막 수 후 상태는 기존 Stopped이므로 구체 NoMoves 대신 실제 추가 행동 거절을 검사했다. 보충 검증의 잘못된 PowerArea.Bomb 이름을 Blast3로 고친 뒤 컴파일을 통과했다.
- 기존 테스트의 ‘고철 미지원’ 기대를 지원으로 수정했다. 기존 UI 거절 fixture는 계속 미지원인 회수 부품으로 바꿨다. 기존 정착 보충 결과는 이 증거 폴더로 옮기고 과거 결과 파일은 복원했다.
