# 31단계 개발 목표 — 밸런스 기능의 개발 오류 검증

- 작성일: 2026-09-29.
- 상태: 개발 오류 검증 완료. 16개 조건별 증거는 진행 기록의 최종 개발 검증 결과에 정리했다. 2026-09-29 사용자 지시에 따라 개발 중 전체 20,000판 실행을 중단했다. 완료한 13개 구간 2,600판은 보존·독립 대조했고, 앞으로 오류 확인에 필요한 소규모 검사만 수행한다. [진행 기록](../../../Verification/MoonRabbitJunkyard/Core/89_31단계_검증진행기록.md)을 따른다.
- 계획: [31단계 작업 계획](../../../Planning/MoonRabbitJunkyard/Core/87_31단계_밸런스전체시험_작업계획.md).
- 선행: [30단계 완료 기록](../../../Handover/MoonRabbitJunkyard/86_30단계_완료검증과인수인계.md) 및 그 이후 추가한 맵 사용 현황·밸런스 시험·네 단계 난이도의 최신 코드와 검사 증거.

## 목표

사용자 최신 지시인 “개발중에는 20000판 모두 검사하지마. 오류가 있는지 정도만 진행하고, 실제 검증시에 그렇게 돌려”를 적용한다. 개발 중에는 기존 실측 기록과 소규모 실제 UI·오류 주입 검사로 저장·추천·제어·재조회 오류를 찾고 필요한 부분만 수정한다. 제품의 1~100회·두 봇 각 100판 기능은 유지한다. 실제 20,000판 전체 실행과 장시간 신뢰성 검증은 별도 최종 검증으로 이관하며, 이번 단계 완료를 전체 시험 완료로 표현하지 않는다.

## 실행 원칙

1. 현재 Goal과 실행 중 검사부터 확인한다. 같은 31단계 Goal은 이어가고, 다른 활성 Goal은 덮어쓰거나 임의 완료하지 않는다. 활성 Goal이 없고 이 단계가 미완료일 때만 생성한다.
2. 프로젝트 AGENTS와 unity-project-conventions·ponytail을 적용한다. 중요한 미확정 설계만 grill-me로 확인하며 이미 확정된 범위·판 수·난이도는 다시 묻지 않는다. deep-planning은 사용하지 않는다.
3. 원본 에셋·GUID/meta·사용자 변경·기존 시험 기록의 보존 기준을 먼저 확보한다. 오류 주입은 소유한 임시 사본에만 수행한다.
4. 계획 T1~T8을 따른다. 실제 UI 시작, 원시 판 독립 집계, 재조회·수명주기·성능 증거를 확보한다. 기존 통과 수를 신규 검사나 실제 판 수에 중복 합산하지 않는다.
5. 개발 중 20,000판을 자동 실행하거나 매 수정마다 반복하지 않는다. 기존 호환 실측을 재사용하고 새 실행은 재현·경계·제어 확인에 필요한 작은 표본으로 제한한다. 제품의 전체 시험 범위·표본 수를 축소하지 않으며, 완료한 횟수만 추천한다.
6. 기본·계획은 같은 100시드를 공유하고 숨은 데이터·분석 결과를 입력받지 않는다. 실제 게임과 공통 실행기를 유지한다.
7. 난이도는 쉬움·보통·어려움·매우 어려움 네 단계다. 60/40/20% 경계와 매우 어려움의 성공률 >0% 조건을 유지한다. 네 등급 모두가 실제로 나와야 한다는 완료 조건을 만들지 않는다.
8. 실패 조건을 보존하고 같은 조건으로 재현한다. 새 시드의 통과로 기존 실패 해결을 주장하지 않는다. 조건 변경 전후 결과를 섞거나 테스트를 약화하지 않는다.
9. 실행 중 Unity의 Assets 코드를 변경하지 않는다. 이미 확보한 호환 증거는 재사용하고, 수정 영향이나 미확인 조건이 있을 때만 반복 실행한다.
10. HTML 브라우저 배치 검수의 기존 후속 이관을 유지한다. 그 외 미검증 조건은 완료로 표시하지 않는다. 이번 목표는 출시·새 게임 기능·서버·결제로 확장하지 않는다.

## 완료 조건

- [x] 1. 선행 증거·현재 Goal·실행 프로세스·규칙 버전을 확인하고 보존 기준을 기록했다.
- [x] 2. 대표 레벨 선정 이유와 사본 정의·지문·시드·버전·결과 경로를 기록했다.
- [x] 3. 실제 UI로 시작한 소규모 시험 또는 호환하는 기존 완료 구간으로 개발 오류를 확인했고, 새로 실행한 판 수와 재사용 기록을 구분했다. 20,000판은 재실행하지 않았다.
- [x] 4. 확보한 완료 구간의 기본·계획 100판, 동일 시드, 이동 수 외 조건 동일, 누락·중복 없음을 독립 대조했다. 1·100회 경계는 작은 실행/구성 검사로 확인하고 전체 범위 실측과 구분했다.
- [x] 5. 원시 판 성공 수·정상/오류/중단 수와 저장 요약·진행률이 일치한다.
- [x] 6. 공통 네 단계와 반올림 전 경계가 통계·이력·밸런스 추천에 일치하고 매우 쉬움은 제공하지 않는다.
- [x] 7. 연속 실측 횟수만 범위로 표시하며 성공 0%·미완료·오류·추천 없음·추가 시험 필요를 올바르게 구분한다.
- [x] 8. 일시정지 후 재개/중지, 탭 복귀 시 자동 재개 금지, 다른 봇·수동 입력의 중복 실행 방지를 확인했다.
- [x] 9. 창 종료·재컴파일·Editor 재시작 후 완료한 횟수의 결과를 보존하고 중단 상태를 구분한다.
- [x] 10. 별도 사본의 저장 실패·손상·누락·버전 불일치 검사를 수행하고 오류를 정상 결과로 표시하지 않는다.
- [x] 11. 선택한 추천 횟수를 임시 레벨에 직접 적용·저장·다시 열어 확인하고, 시험 사본이 원본이나 등록 맵 사용 수를 바꾸지 않는다.
- [x] 12. 최소 창·긴 범위 표시·근거 펼치기·도움말·결과 폴더 접근을 실제 Unity 화면에서 확인했다.
- [x] 13. 개발 검사에서 관측한 실행 시간·저장 용량·파일 수·메모리·제어 응답·재조회 시간을 기록했다. 전체 20,000판 성능·장기 안정성은 미검증으로 이관했다.
- [x] 14. 발견 결함은 원인·실패 증거를 보존하여 최소 수정했고, 수정 영향에 맞는 회귀와 최종 컴파일을 통과했다.
- [x] 15. 사용자 변경·원본 데이터·GUID/meta·기존 기록 보존을 최종 대조했다.
- [x] 16. 조건별 증거·신규/재사용 검사·실제/합성 판 수·한국어 매뉴얼·남은 제한을 연결한 개발 검증 기록을 작성하고, 별도 실제 전체 검증의 실행 조건·남은 항목을 명시했다.
