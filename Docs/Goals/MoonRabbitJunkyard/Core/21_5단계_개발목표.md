## Goal 목표

현재 `C:/Projects/Git/ServeredMeridian` Unity 프로젝트에서 상세 계획의 포함 범위와 구현 제안에 따라 생성구·위치별 고정 공급·개수 유지·회수 부품·미션 편집을 완성한다. 생성구 공통 속성과 목록 복사/교체/추가/복제를 제공하고, 충돌·수량 부족 검사, Undo/Redo, 실제 Editor UI, 저장 및 별도 Unity 재시작 보존까지 검증한다. 완료 후 실제 변경·사용 방법·검증 증거를 이 문서에 기록한다.

## 실행 지침

1. 프로젝트 AGENTS와 `ponytail`, Unity 프로젝트 규칙 및 관련 UI Toolkit 스킬을 확인한다. 현재 사용자 변경을 보존한다.
2. 실행 전 상세 계획과 최신 게임 규칙, 실제 코드를 다시 대조한다. 확정 규칙을 변경하지 않는다. 상세 계획에 명시한 제안은 이 문서를 참조한 실행 요청의 범위로 취급한다. 실질적인 새 충돌만 확인한다.
3. 실행 작업의 선행 관계·수정 책임·완료 증거를 실행 기록에 정리하고 순차 진행한다. 작업 상태를 실제 결과에 맞춰 갱신한다.
4. 스크립트는 `Assets/Scripts` 아래 기능별로 분리한다. 기존 창·직렬화·Undo·검증 구조를 재사용한다. 게임명 중간 폴더·새 패키지·범용 프레임워크를 추가하지 않는다.
5. 메뉴는 **Match**, 왼쪽 탭과 한 줄 제목/드롭다운, 오른쪽 선택/레벨 설정, 패널 접기, USS 스타일을 유지한다. 목록이 길어져도 보드 공간을 침범하지 않는다.
6. 원본 검사와 실행 상태를 분리한다. 검사 중 자동 수정·공급 실행·목표량 보정을 하지 않는다. 불완전한 작업 상태도 저장할 수 있어야 한다.
7. v3 원본을 먼저 확보한다. v3→v4 전환으로 기존 흐름·연결·안정적 ID가 바뀌지 않아야 한다. v1/v2의 기존 오류 보존과 전환 회귀도 확인한다.
8. 실제 UI 조작과 별도 재시작을 확인한다. 미실행 검사를 통과로 기록하지 않는다. 필수 증거가 없으면 완료로 표시하지 않는다.
9. 검증용 에셋과 대기 상태를 정리하고 기존 meta·씬·패키지·프로젝트 설정·무관한 문서를 보존한다. 커밋·배포는 포함하지 않는다.

## 사용 순서

최종 사용법은 실제 Editor UI 검증 대상으로 작성했다. 검사 결과는 아래 증거 표와 실행 로그를 함께 확인한다.

1. **Match → 레벨 에디터**에서 레벨을 연다. 새 레벨은 상단 10칸에 일반 무작위 생성구가 있다. 구버전은 명시적으로 v4로 전환하며, 기존 흐름·연결은 보존하고 생성구·미션은 직접 설정한다.
2. 왼쪽 **배치 → 생성·회수**에서 생성구를 배치/삭제하거나 선택한다. **목록** 탭의 생성구 좌표를 눌러도 해당 위치와 속성을 선택한다. 기존 초기 블록과 생성구는 같은 칸에 둘 수 있다.
3. 오른쪽 **선택 속성 → 공급 방식 → 고정 목록**을 선택한다. 항목의 종류·수량과 필요한 색/로켓 방향/고철 내구도를 입력한다. 아래쪽 1번이 먼저 공급된다. 목록 핸들 드래그 또는 `↑ 나중에`/`↓ 먼저` 버튼으로 순서를 바꾼다.
4. **목록 복사** 후 다른 생성구에서 **교체 붙여넣기** 또는 **뒤에 추가**를 누른다. Ctrl/Cmd+클릭으로 여러 생성구를 선택하면 공통 속성만 수정하고 목록은 일괄 붙여넣기로 처리한다. 혼합 값은 별도 표시하며, 부적합 대상이 하나라도 있으면 전체 작업을 거절한다.
5. 고정 목록이 남은 상태에서는 다른 공급 방식으로 바꿀 수 없다. 명시적으로 **비우기** 후 전환한다. 고철·회수 유지 담당 생성구를 정하고 **레벨 설정 → 공급 유지 · 레벨 공통**에서 유지 목표 등을 입력한다. 고철 추가 한도는 모든 담당 생성구가 공유한다.
6. **배치 → 생성·회수 → 회수 부품**으로 최초 부품을 놓고 흐름 도구에서 도착 바닥을 지정한다. 블록·장애물·덮개와 겹치는 부품 배치는 거절한다.
7. **레벨 설정 → 미션**에서 목표를 1~4개 지정한다. 색 수집은 색마다 별도 미션이다. 곰팡이는 전부 제거이며, 폐가전은 2×2 본체 하나를 1개로 센다. 목표 아래 공급 수량 근거를 확인한다.
8. 상단 **검사**에서 오류를 확인하고 항목을 눌러 해당 칸/설정으로 이동한다. 오류가 있는 작업 중 데이터도 **저장**할 수 있다. 검사 통과는 실제 플레이 가능성·난이도를 보장하지 않는다.
