# 15단계 개발 목표 — 파워 블록 조합 10종

- 작성일: 2026-09-27.
- 상태: 구현·검증 완료. 20개 완료 조건, 중복 제외 1,405개 검사 PASS.
- 상세 계획: [15단계 작업 계획](../../../Planning/MoonRabbitJunkyard/Core/40_15단계_파워조합_작업계획.md).
- 선행 문서: [14단계 개발 목표](39_14단계_개발목표.md).

## Goal 목표

현재 Unity 프로젝트에서 두 파워 블록의 직접 교환으로 조합 10종을 실행한다. 14단계의 공통 피해·미션 집계·드론 목표 관리를 재사용하여 범위 조합, 드론의 범위 예약/재탐색, 자석의 일괄 변환과 즉시 발동을 구현한다. 기존 Match 실행 시험·낙하·자동 매칭·다음 수에 연결하고 실제 Unity 검증, 독립 재현, 영향 회귀 및 완료 조건별 기록까지 마친다.

## 실행 지침

1. 14단계는 문서 갱신 시 완료를 확인했다. 실행 시 현재 Goal과 14단계 문서·완료 증거·최종 해시·소스를 다시 대조한다. 다른 활성 Goal을 덮어쓰지 않으며 증거와 소스 차이가 있으면 영향부터 확인한다.
2. ponytail, Unity 프로젝트 지침, 확정 게임 규칙과 상세 계획을 적용한다. 이 문서를 지정한 실행 요청은 계획의 세부 정책 제안을 포함한다. 충돌은 임의로 확정하지 말고 근거를 밝힌다.
3. 하나의 목표 안에서 범위 조합 → 드론 조합 → 자석 조합 → 통합 검증 순서로 진행한다. 스크립트는 Assets/Scripts의 Simulation/Editor 구성별로 분리한다.
4. 효과 중심은 두 번째 선택 칸이다. 종류 정규화와 입력 방향을 분리하고 두 재료는 단독 발동 없이 조합으로 한 번씩 소비한다.
5. 직접 범위·변환·요청 구성만 조합 책임으로 두고 실제 피해, 미션, 보호, 즉시 연쇄는 기존 공통 처리를 사용한다.
6. 조합 드론은 도착 후 직접 범위를 조회/예약하며 추가 연쇄는 예측하지 않는다. 예상량과 실제량, 예약과 턴 피해 제한을 분리한다.
7. 자석은 대상 전체를 먼저 변환한다. 변환 파워는 보호 예외로 정확히 한 번씩 발동하고, 변환 전 일반 블록의 색은 한 번만 집계한다.
8. 상태·난수·미션·예약의 원자성과 재현을 유지한다. 모든 착탄과 즉시 효과 뒤에만 낙하로 넘어간다.
9. 원본 레벨/v4/GUID/meta와 무관한 파일을 보존한다. 새 패키지·asmdef·게임명 폴더·별도 실행 엔진을 추가하지 않는다.
10. 14단계 지원 보드/미션 범위를 유지한다. 기타 장애물·승패·라스트팡·아이템·봇·수익화·런타임 연출은 구현하지 않는다.
11. 실제 검증 결과만 완료 근거로 기록한다. 기존 검사의 기대값을 바꿨다면 규칙상 이유를 남긴다. 미완료/미검증을 통과로 처리하지 않는다.

- 14단계 최종 소스 해시와 현재 파일의 불일치 0건, 현재 활성 Goal 없음.
- 현재 한 칸 목표 관리와 실제 미션 집계의 구현 파일을 확인하여 상세 계획에 반영했다.
- 이 확인은 15단계 구현 또는 완료 검증이 아니다. 아래 착수/구현/감사는 Goal 실행 때 작성한다.

### 착수

- 선행 단계 완료 증거와 현재 소스 대조: 14단계 완료 감사 924 PASS/20조건, 최종 소스 해시 불일치 0건. 현재 Supports는 조합만 거절하며 단독 4종·실제 미션·한 칸 예약은 구현돼 있다.
- 활성 Goal 확인: 본 15단계 목표가 활성 상태임을 확인. 새 목표 중복 생성 없음.
- 정책·파일 책임·작업 순서: 40 문서의 세부 정책을 채택한다. PowerCombinationResolution은 조합/범위/선변환 구성, 공통 효과 실행기는 타격과 착탄, DroneTargetManager는 범위별 예상 기여/예약을 담당한다. 범위 조합 → 드론 조합 → 자석 조합 → Match/검증 순서로 구현한다.
- 보존 기준과 임시 에셋 소유 범위: Logs/CombinationVerification/baseline.json. 원본 정의/v4/meta/프로젝트 설정/무관 파일을 보존하고 검증 전용 소유 폴더만 정리한다.

### 구현

- `PowerCombinationResolution.cs`: 조합 10종의 종류·중심·직접 범위·드론 도착 범위와 일괄 변환을 구성한다. 중심은 두 번째 입력 좌표이며 재료는 두 개 모두 단독 발동 없이 소비한다.
- `BoardActionExecutor.cs`/`.Cascade.cs`: 직접 교환 분기에서 조합을 실행하고 성공 때만 상태·난수·이동 수·턴을 반영한다. 조합을 미지원 행동으로 제외하던 경로를 제거했다.
- `PowerEffectResolution.cs`: 기존 즉시 효과 스택과 드론 착탄 큐를 공유한다. 국소 타격과 그 피격 연쇄 뒤 드론을 요청하고, 모든 착탄 후 낙하한다. 변환 파워 전체를 먼저 구성하고 피격 선발동과 원래 발동 예약이 겹쳐도 한 번만 실행한다.
- `DroneTargetManager.cs`: Point/Horizontal/Vertical/Blast3별 후보 캐시와 조준 칸·직접 미션 범위 예약을 관리한다. 부분 소실 시 현재 기여만 계산하며 무효 착탄은 자기 예약을 해제하고 미션 → 일반 블록 → 없음 순으로 다시 찾는다. 실제 효과 범위는 예약 때문에 잘라내지 않는다. 추가 연쇄는 예약 예측에 포함하지 않는다.
- `DamageReaction.cs`의 턴 문맥은 조합 기록을 보존한다. 기존 실제 미션 집계, 신규 매칭 파워 보호 및 상자 턴당 1피해를 재사용한다. 변환 전 색은 변환 때 한 번만 집계한다.
- 버전: `board-action-combinations-v5`, `power-effects-combinations-v3`. 효과 한도는 `max(1024, 칸 수² × 8)`이고 새 사용자 옵션은 없다. 정착/자동 매칭 등 기존 알고리즘 버전은 유지한다.
- `Match/초기 보드 확인` → 레벨/시드로 시작 조건 구성 → 실행 시험 → 두 파워 선택 → 교환 실행. 우측에 조합·중심·선택 색·변환 방향·예약/착탄과 미션을 표시한다. 단계 실행 또는 연쇄 끝까지 실행 후 다음 수로 진행한다.
- 스크립트는 기존 `Assets/Scripts/Simulation`, `Assets/Scripts/Editor/Levels` 안에 배치했다. 새 패키지·asmdef·게임명 폴더·전역 관리자·별도 실행 엔진은 없다.
