## Goal 목표

현재 Unity 프로젝트의 정착 완료 상태에서 자동 매칭·기존 지원 효과·낙하와 기본 공급을 안정될 때까지 반복하고, 지원하는 다음 사용자 행동을 받을 수 있게 한다. 마지막 도착 기준 파워 생성, 같은 턴의 보호·피해 기록과 다음 턴 전환을 정확히 유지한다. 기존 Match 실행 시험에서 단계별/연쇄 전체 실행을 제공하고 정답 사례·실제 UI·독립 재현·회귀 검증 및 완료 감사를 기록한다.

## 실행 지침

1. ponytail과 프로젝트 Unity 지침을 적용하고 상세 계획·게임 규칙·현재 소스를 대조한다. 이 문서를 지정한 실행 요청은 계획의 구현 정책 제안을 포함한다.
2. 12단계 완료 증거를 먼저 확인한다. 미완료 또는 다른 활성 Goal이 있으면 이를 덮어쓰거나 완료로 표시하지 말고 선행 상태와 필요한 작업을 보고한다. 13단계의 검증을 선행 완료 증거로 대체하지 않는다.
3. 착수 시 작업 순서·파일 책임·도착 정보와 턴 문맥 소유자·보존 기준을 기록한다. 스크립트는 Assets/Scripts 아래 기존 구성별로 분리한다.
4. MatchQuery/MatchResolution/PowerEffectResolution/SettlementResolution을 연결한다. 자동 매칭 규칙을 UI나 별도 엔진에 복제하지 않는다.
5. 현재 점유자의 마지막 도착 정보를 사용하고 중간 통과 좌표, 서로 다른 정착 회차, 이력 없는 잔여 패턴을 구분한다. 동률 실행에만 난수를 소비한다.
6. 한 단계의 보드·난수·공급·보호·피해·도착 정보를 원자적으로 반영한다. 연쇄 전체 실행에서 실패하면 마지막 성공 단계에서 멈추고 실패 단계만 폐기한다.
7. 새 매칭 파워 보호와 상자 피해 기록을 한 턴 전체에 유지한다. 다음 유효 행동에서만 새 턴을 시작하고 이동 수를 한 번 차감한다.
8. 수 0에서도 연쇄를 끝내되 승패는 판정하지 않는다. 다음 수에 최초 보드의 빈칸 금지 조건을 강제하지 않는다.
9. 드론/자석 발동·조합·추가 장애물 등 미지원 요소는 명확히 거절한다. 자동 재배치·미션·승패·봇을 대신 구현하지 않는다.
10. 단계 실행과 끝까지 실행은 같은 코어를 사용한다. 기존 원본/시드/모드 변경과 창 종료 무효화를 보존한다.
11. 완료 조건별 증거와 실제 검사 수를 기록한다. 미검증 항목은 체크하지 않으며, Unity 에셋·meta·무관 파일을 보존한다.

## 실행 기록 — Goal 실행 시 작성

### 착수

- 선행 증거와 현재 소스 대조: 12단계 final-source-hashes.json의 전체 소스·meta와 현재 파일 불일치 0건. 12단계 완료 감사 24조건 및 최종 정답/UI/독립 재현 결과를 대조했다.
- 지원 범위·정책과 파일 책임: 기존 MatchResolution의 중첩 선택/적용을 재사용하고 자동 생성 위치 선택만 분리한다. BoardActionExecutor.Cascade 부분 클래스가 자동 단계·종료·회차 기록을 맡고 Editor는 동일 AdvanceCascade를 단계별/틱별로 호출한다. 12단계 지원표와 13단계 제외 범위를 유지한다.
- 도착 기록·턴 문맥 소유 및 작업 순서: TurnEffectContext에 일반 점유자의 마지막 도착(정착 회차, 묶음)을 실행 전용으로 보관한다. 작업 사본에서 이동·공급/제거와 함께 갱신하며 파워 보호·상자 피해를 누적한다. T1 선행 대조 → T2 위치 결정 → T3 문맥/피해 → T4 연쇄/다음 수 → T5 UI → T6 검증 순서다. 별도 영구 ID/스키마 변경은 없다.
- 원본 보존 기준과 검증 에셋 소유 범위: Logs/CascadeVerification/baseline.json. 임시 에셋은 Assets/__CascadeVerification_<guid>만 사용하고 소유 범위를 확인한 뒤 정리한다. 기존 사용자 Stories 변경과 모든 기존 meta를 보존한다.

### 구현

- 변경 파일과 책임: `Assets/Scripts/Features/PuzzlePlay/Runtime/Actions/BoardActionExecutor.Cascade.cs`가 자동 단계·연쇄 기록·종료 사유와 한도를 담당한다. 기존 `BoardActionExecutor.cs`는 다음 유효 행동의 문맥/수 전환, `MatchResolution.cs`는 공통 우선순위와 자동 생성 위치 선택, `DamageReaction.cs`의 TurnEffectContext는 도착/보호/피해 사본, `SettlementResolution.cs`는 도착 기록 갱신을 맡는다. 기존 정의·저장 스키마·패키지·asmdef는 변경하지 않았다.
- Editor: `LevelInitialStateWindow.Cascade.cs`에 단계/끝까지/중지와 결과 표시를 추가하고 기존 Execution/Settlement 부분 클래스에 연결했다. `LevelInitialStateWindow.cs`의 칸 상세는 초기 사본 대신 현재 실행 상태의 내구도·공급을 읽는다. `CascadeVerification.cs`, `.Edges.cs`, `.UI.cs`, `.Supplemental.cs`에 정답/실제 UI/독립 재현 검증을 둔다.
- Match 사용법: 시작 조건 구성 → 실행 시험 → 교환/제자리 발동 → 낙하·공급 실행 → 자동 매칭 단계. 중간 검토 없이 진행하려면 효과 이후 `연쇄 끝까지`를 누른다. 실행 중 같은 버튼은 `연쇄 실행 중지`로 바뀐다. 안정 후 다음 칸을 선택해 계속 조작한다. 같은 시드로 초기화는 새 시험을 시작한다. 자세한 사용법은 [레벨 에디터](../../../Contents/MoonRabbitJunkyard/09_레벨에디터.md)의 13단계를 따른다.
- 버전: 행동 `board-action-cascade-v3`, 패턴 적용 `match-resolution-v2`, 정착 `settlement-v2`. 이동 조회 `movement-query-v1`, 난수 `System.Random/initial-state-v1`은 유지했다. 동일 Unity 6000.3.10f1/Mono·정의·시드·행동 순서·버전이 재현 조건이다.
- 도착은 `(정착 회차 << 32) | 묶음 번호`의 실행 전용 값으로 보관한다. 초기 이력은 0이며 정착 회차는 직접 호출을 포함해 1부터 시작한다. 제거/변환 시 일반 도착 정보를 비우고 새 공급/이동은 현재 점유자의 도착으로 덮어쓴다.
- 내부 자동 매칭 한도는 `max(128, Cells.Count×4)`이며 10×10에서 400회다. 50회 정상 연쇄와 401번째 매칭을 남긴 한도 실패를 별도로 검증했다. 한도는 실패 진단이며 콘텐츠가 이를 넘어야 하면 별도 검토가 필요하다. 매 단계 성공을 반영하므로 실패 시 이전 성공 단계까지 취소하지 않는다.
- 발견/수정: 문맥 없이 정착을 호출할 때 회차가 0부터 시작하던 차이를 공통 복사 경로로 통일했다. 공통 패턴 선택의 새 동명 메서드가 기존 검증 도구의 reflection 조회와 충돌하여 내부 이름을 SelectCore로 분리했다. 실제 UI 검사에서 사용한 선택 취소 순서와 검증 좌표 비교 문법도 수정했다.

화면은 `step-wide.png`, `stable-wide.png`(1000×780), `stable-narrow.png`, `second-turn.png`(680×480)를 직접 확인했다. 실제 Unity 메뉴와 NavigationSubmitEvent로 조작했고, 연쇄 실행 중지/재개·다음 수·현재 상자 내구도 표시·변경 무효화·창 종료를 검사했다. 원본 변경으로 중지된 버튼의 문구도 `연쇄 끝까지`로 복원한다.

일반 교환/파워 입력부터 끝까지 잇는 통합 검사와 직접 중간 상태를 구성하는 정답 검사를 구분했다. 패턴별 위치 정답, 미지원 반응의 원자적 실패, 무진행 반복 진단은 직접 구성한 사례다. 반복 진단은 방문 기록을 구성하여 거절/보존을 검사했으며 자연 발생 순환 사례를 재현했다고 주장하지 않는다. 실제 긴 공급 사례는 50회 정상 연쇄 및 400회 한도 이후 실패를 검사했다.

초기 검증 실패도 해결 기록에 포함했다. 좌표 비교의 컴파일 오류, 테스트 선택 취소 순서, 다음 수 테스트에 의도치 않게 자석을 생성한 데이터는 검사 코드를 수정했다. 생성 자석에 다음 수 로켓이 닿을 때의 거절은 별도 올바른 미지원 보존 검사로 남겼다. 런타임에서는 문맥 없는 정착의 회차 초기화를 수정했고, 기존 검증 호출 호환성은 SelectCore 분리로 복구했다. 해당 실패 로그를 최종 PASS 증거에 포함하지 않았다.
