## 사용자에게 보일 결과

튜토리얼 안내문을 수정하거나 공유 구성을 적용할 때 멈추는 시간을 줄인다. 보드 선택·확대/축소는 셀과 이미지를 매번 새로 만들지 않고 반응하며, 배치·삭제 후 최신 결과를 보여준다. 저장 전에는 메모리 편집과 dirty 표시만 유지한다.

## 측정 목표

아래는 이번 단계의 제안 완료 기준이다. 이미 달성한 성능이나 전체 제품의 성능 보장을 뜻하지 않는다. 미달 시 값을 임의 완화하지 않고 남은 비용과 함께 보고한다.

| 조작 | 3단계 동기 중앙값 | 4단계 동기 중앙값 목표 |
| --- | ---: | ---: |
| 튜토리얼 수정 | 1,048.65ms | 525ms 이하 |
| 공유 적용 | 891.98ms | 450ms 이하 |
| 선택 | 220.35ms | 100ms 이하 |
| 줌 | 213.86ms | 100ms 이하 |
| 셀 배치 | 248.28ms | 150ms 이하 |
| 셀 삭제 | 242.26ms | 150ms 이하 |
| 이름 편집 | 100회 중앙값 64.94ms | 기존 정상 3회 중앙값 각각 100ms 이하 유지 |

- 동일 환경·입력·준비 조건의 정상 3회 각각에서 목표를 판정한다. 최대값도 공개하며 유리한 표본만 선택하지 않는다.
- 기본 38문서, 공유 시나리오는 준비 단계에서 흐름 1개를 더한 39문서를 유지한다. 고정 입력 해시는 3단계 기록과 대조한다.
- 동기 시간과 **명령 시작부터 후속 Editor update 2회 및 최신 표시/유효 geometry 확인까지**의 준비 관측값을 함께 기록한다. 이는 GPU 완료나 최초 표시 시간 측정이 아니다.
- 준비 관측값도 동일 실행의 변경 전보다 중앙값이 줄어야 한다. 지연 실행으로 동기 시간만 낮추면 미달이다.
- 30초·8GiB 보호를 유지한다. 지원하지 않는 할당 카운터는 null로 기록한다. 첫 진입/캐시 미적중은 별도로 기록한다.

## 기능·구조 완료 조건

- [x] 튜토리얼·공유 적용·보드 조작의 원인별 비용과 전후 측정이 있다.
- [x] 공유 사본은 적용 전 부모를 바꾸지 않으며 적용은 한 번의 원자적 편집으로 Undo/Redo된다. 취소·충돌·재진입·미확정 입력 동작이 유지된다.
- [x] 선택/줌만으로 문서 버전·dirty·Undo 이력이 바뀌지 않는다. 기존 셀·그림을 재사용하고 화면 좌표가 입력 좌표와 일치한다.
- [x] 배치/삭제, 2×2 장애물, 공급/흐름/연결선, 튜토리얼 강조, 비동기 이미지 완료 후 최신 내용이 맞는다.
- [x] 레벨/세션 전환·동일 ID 재로드·Undo/Redo·정의 변경·숨김 패널 재진입에서 캐시가 오래된 값을 표시하지 않는다.
- [x] 포커스·미확정 입력·스크롤을 보존한다. 실제 IME 검증 여부를 따로 보고한다.
- [x] 100회 편집 후 새 세션에서 이전 캐시·화면·임시 객체가 해제된다. 정상 이력 보존 메모리와 누수를 구분한다.
- [x] 편집 중 자동 프로젝트/복구 쓰기 0회, 명시적 저장과 데이터 전달 형식 유지.
- [x] 관련 컴파일·회귀 검사 통과, 보호 파일 보존, 검사 연결 해제 확인.
- [x] 제품 빌드·커밋·푸시·HTML 갱신 없이 결과와 간략한 커밋 메시지만 보고한다.

실기기 성능·물리 IME·최종 GPU 렌더는 실제 검증하지 않았다면 미검증으로 남긴다. 기존 780×360 높이 문제와 오프스크린 흰색 렌더 문제는 신규 회귀와 구분한다. 붙여넣기·저장 성능은 이번 완료 조건에 포함하지 않는다.
