# 복구 성능 개선 2단계 목표

상태: 계획 완료, 구현 미착수. [2단계 계획](../../../Planning/MoonRabbitJunkyard/LevelToolRecoveryPerformance/2026-10-19-stage02-plan.md)을 따른다.

## 완료 조건

- [ ] Session 내부 문서와 외부 가변 사본의 소유권/쓰기 경계를 기록한다.
- [ ] 과거 이력의 변경되지 않은 문서 사본을 줄이고 외부 참조 수정으로 상태가 오염되지 않음을 검사한다.
- [ ] Apply 실패/무변경·추가/삭제·저장/Discard·Fork/공유 사본·Undo/Redo의 의미를 유지한다.
- [ ] v1 직렬화/재구성의 불필요한 중간 트리 또는 문자열 왕복을 측정 근거로 줄인다.
- [ ] 기존 복구 파일·손상 거절·saved/current 구분·선택·미확정 입력·previous 보호를 유지한다.
- [ ] 같은 10회 입력 및 허용되는 30/60회 표본에서 시간·메모리·파일 크기·상태 동일성을 기록한다. 보호 종료/미실행/목표 미달을 구분한다.
- [ ] 관련 회귀·컴파일·사용자 자료 보존·diff 검사와 결과 보고를 마친다.
- [ ] 3단계 계획·목표·실행문을 작성하고 자동 구현하지 않는다.

## 복사 가능한 목표 실행문

```text
Docs/Planning/MoonRabbitJunkyard/LevelToolRecoveryPerformance/2026-10-19-stage02-plan.md와 Docs/Goals/MoonRabbitJunkyard/LevelToolRecoveryPerformance/2026-10-19-stage02-goal.md를 기준으로 2단계를 진행해. Session 내부 문서 소유권과 외부 가변 참조 격리를 먼저 검증하고, 변경되지 않은 이력 문서 사본 및 v1 직렬화·재구성의 중간 비용을 줄여. 기존 복구 형식, 전체 Undo/Redo, 저장 기준과 dirty, 미확정 입력, 공유 튜토리얼 사본과 이전 정상 복구본 보호를 유지해. 사용자 데이터와 이력은 보존하고 고유 시험 폴더에서만 검증해. 표본 30초/Unity 메모리 8GiB 보호 한도를 지키고 목표 미달이나 미검증을 숨기지 마. 제품 빌드·커밋·푸시·HTML 갱신·코드에 의한 프리팹 편집은 하지 마. 질문은 제한시간 없는 문답으로 해. 완료 후 변경·전후 측정·회귀 결과·남은 항목과 복사 가능한 커밋 메시지를 보고하고 3단계 상세 계획·목표·실행문을 작성해. 3단계 구현은 자동 시작하지 마.
```
