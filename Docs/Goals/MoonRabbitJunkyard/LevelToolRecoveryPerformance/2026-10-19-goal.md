# 레벨툴 대량 이력 복구 성능 개선 목표

상태: 1단계 구현·회귀·측정 완료. 2·3단계 미착수. 전체 성능 목표는 아직 미달이다. [계획서](../../../Planning/MoonRabbitJunkyard/LevelToolRecoveryPerformance/2026-10-19-plan.md)를 따른다.

## 목표

복구 저장·읽기의 중복 재구성과 이력 사본 비용을 줄이고, 이전 기록 호환성과 사용자 편집/Undo/Redo를 보존한다. 3단계로 진행하며 실행 명령은 우선 1단계만 승인한다.

## 1단계 완료 조건

- [x] 입력 고정·해시·구간별 비용과 기존 검증 호출 경로가 기록되어 있다.
- [x] 검증된 복원 자료의 불필요한 직렬화/재구성이 줄었다는 증거가 있다.
- [x] 같은 유효/손상 입력의 수락·거절 의미가 유지되고, 실패 시 기존 Workspace·세션·화면 상태가 보존된다.
- [x] 실제 임시 파일 검증·원자적 교체·이전 정상 복구본 보호·저장 순서·취소 보호가 유지된다.
- [x] 미확정 입력·공유 튜토리얼·선택·전체 Undo/Redo·dirty·저장 기준이 복원된다.
- [x] 소형 표본과 10회 표본의 시간/메모리/파일 크기를 전후 비교한다. 보호 종료는 실패/미완료로 표시한다.
- [x] 관련 회귀·컴파일·보호 파일 해시·diff 검사를 완료하고 결과를 보고한다.
- [x] 2단계 상세 계획·목표·복사 가능한 실행문을 측정 결과에 맞춰 작성한다. 2단계 구현은 자동 시작하지 않는다.

## 전체 완료 조건

- [x] 1단계 중복 검증/복원 비용 개선 완료.
- [ ] 2단계 내부 사본 공유의 오염 방지와 Undo/Redo/외부 참조 격리 검증 완료.
- [ ] 3단계 자동 저장·종료·실제 복원 통합 검증 완료.
- [ ] 동일 fixture의 10/30/60회 측정, 정상 표본 3회 중앙값/최댓값과 메모리 시작값/증가분을 기록한다.
- [ ] 제안 성능 목표(10회 복구 경로 합계 5초, 60회 15초, 10회 전체 프로세스 최대 4GiB)를 충족하거나 미달로 명시한다. 메인 스레드 100ms 지향 목표도 별도 판정한다. 측정 완료와 개선 목표 달성을 구분한다.
- [ ] 보호 한도 때문에 중단/미실행한 표본과 Android 실기기 미검증을 숨기지 않는다.
- [ ] v1 복구 및 작성 JSON/MemoryPack 호환성, 사용자 원본·정식 리소스·이력 보존을 확인한다.
- [ ] 제품 빌드·커밋·푸시·HTML 갱신·프리팹 편집 없이 결과와 간략한 커밋 메시지를 보고한다.

## 1단계 목표 실행 명령문

```text
Docs/Planning/MoonRabbitJunkyard/LevelToolRecoveryPerformance/2026-10-19-plan.md와 Docs/Goals/MoonRabbitJunkyard/LevelToolRecoveryPerformance/2026-10-19-goal.md를 기준으로 대량 이력 복구 성능 개선 1단계를 진행해. 먼저 같은 입력의 구간별 비용과 검증 경로를 확인하고, 복구 검증·읽기·화면 적용의 중복 재구성과 직렬화 왕복을 줄여. 기존 복구 v1 형식, Undo/Redo 전체 이력, 미확정 입력, 공유 튜토리얼 초안, 원자적 저장과 이전 정상 복구본 보호를 유지해. 사용자 원본·설정·정식 리소스·이력은 변경하거나 삭제하지 말고 고유 시험 폴더에서 검증해. 표본 30초/Unity 메모리 8GiB 보호 한도를 지키고 미완료 표본은 성공으로 보고하지 마. 제품 빌드·커밋·푸시·HTML 갱신·코드에 의한 프리팹 편집은 하지 마. 질문은 제한시간 없는 문답으로 해. 완료 후 수정 내용, 전후 측정, 회귀 결과, 미검증 항목과 복사 가능한 간략한 커밋 메시지를 보고하고, 2단계 상세 계획·목표·실행문을 작성해. 2단계 구현은 자동 시작하지 마.
```
