# 화면 갱신·문서 복사 성능 개선 — 목표와 실행문

상태: 1단계 완료(2026-10-20). 최종 100ms 목표는 미달이며 2·3단계는 미착수. [통합 계획·1단계 상세](../../../Planning/MoonRabbitJunkyard/LevelToolRecoveryPerformance/2026-10-20-edit-refresh-performance-plan.md).

## 전체 목표

편집마다 전체 화면을 다시 구성하고 전체 문서를 복사하는 비용을 줄인다. 수동 저장, 참조 격리, Undo/Redo, 공유 문서와 입력 보호는 유지한다. 3단계로 진행하되 이번 실행문은 **1단계만** 승인하는 명령이다.

최종 성능 목표는 같은 38문서 fixture의 정상 3회 측정 각각에서 이름 편집 10회의 동기 처리 중앙값 100ms 이하다. 현재 기준은 약 750~763ms이며 최대값과 Undo/Redo는 별도로 보고한다. 지연 화면 갱신 비용도 별도 관측해 비용을 숨기지 않는다. 기능 통과와 성능 목표 달성은 별도 판정하며 미달이면 전체 성능 개선 완료로 표현하지 않는다.

## 1단계 완료 조건 — 필요한 화면만 갱신

- [x] Refresh 호출부와 패널 의존성을 정리하고 무관한 패널 재구성의 재현 근거를 남긴다.
- [x] 선택·브러시·줌은 문서를 편집하지 않고, 레벨 이름 변경은 보드 셀·소재 패널을 재구성하지 않는다.
- [x] 전체 JSON 문자열 기반 보드 비교와 무변경 화면 갱신의 반복 전체 문서 조회를 제거한다.
- [x] 셀·공급·튜토리얼·공유 문서 적용, Undo/Redo, 같은 ID 재로드, 숨김 패널 재진입에서 최신 내용을 표시한다.
- [x] 새 세션·재로드에는 필요한 전체 갱신을 유지하고 이전 캐시와 자원을 해제한다.
- [x] 포커스·미확정 입력·스크롤·선택·저장 상태·실패 후 재시도·취소 동작을 보존한다.
- [x] 화면 이탈 성공 후 불필요한 Refresh를 줄이고 실패·취소 시 정상 화면으로 복귀한다.
- [x] 같은 입력의 정상 3회에서 재구성/조회 횟수 감소와 명령·화면 처리 중앙값 개선을 확인한다. 변동 범위로 개선을 판단할 수 없다면 추가 원인을 확인하고 미달로 보고한다. 1단계만으로 100ms를 달성했다고 가정하지 않는다.
- [x] 관련 컴파일·회귀와 네 화면 크기를 검증하고 자동 프로젝트/복구 쓰기 0회를 확인한다.
- [x] 검증 결과, 미검증 항목, 다음 2단계 계획·목표·복사 가능한 실행문, 실제 변경에 맞는 간략한 커밋 메시지를 보고한다. 커밋·푸시는 실행하지 않는다.

## 후속 단계 완료 조건

2단계: 단일 문서 편집에서 전체 문서 초안 복사를 제거한다. 다중 문서 원자성, 콜백 참조 격리, Undo/Redo 및 저장 기준 dirty 의미를 검사한다. 표시 캐시가 내부 수정 가능한 문서를 노출하지 않아야 한다.

3단계: 동일 입력 및 대표 조작의 성능·데이터 전달 회귀·반복 편집 메모리를 검증한다. 100ms 목표, 최대 지연, 저장 비용과 남은 병목을 구분하여 보고한다. 실제 Android/Windows 제품 성능은 제품 검사를 하지 않았다면 미검증으로 남긴다.
