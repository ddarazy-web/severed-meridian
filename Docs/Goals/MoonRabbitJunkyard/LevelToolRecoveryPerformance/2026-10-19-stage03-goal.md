# 복구 성능 개선 3단계 목표

상태: 3단계 검증 완료. 성능 목표는 미달이며 미검증 범위를 결과에 명시했다. 성능 목표 미달과 실제 화면 복구 결과는 [검증 기록](../../../Verification/MoonRabbitJunkyard/2026-10-19-level-tool-recovery-performance-stage03.md)에 구분해 기록한다. [3단계 계획](../../../Planning/MoonRabbitJunkyard/LevelToolRecoveryPerformance/2026-10-19-stage03-plan.md)을 따른다.

## 완료 조건

- [x] 고정 fixture/환경에서 정상 표본 3회의 중앙값·최댓값·메모리·파일 크기를 기록한다.
- [x] 10/30/60회 정상/중단/미실행 범위를 구분하고 30초/8GiB 보호 한도를 지킨다.
- [x] 실제 자동 기록의 메인 스레드 정지, 종료 Flush, 복구 화면 진입 시간을 측정한다.
- [x] 저장 중 편집·순서 역전·프로젝트 전환·취소·재활성화·종료의 상태와 콜백 수명주기를 검증한다.
- [x] 전체 UndoRedo·선택·dirty·미확정 입력·공유 초안·원본 및 previous 보호를 유지한다.
- [x] JSON/ZIP/MemoryPack/게임 시험의 관련 회귀와 컴파일·GUID·보호 해시·diff 감사를 완료한다.
- [x] 각 성능 목표의 달성/미달/미검증을 명시하고 실기기/제품 실행 파일 검증과 혼동하지 않는다.
- [x] 최종 결과·잔여 문제·복사 가능한 커밋 메시지를 보고한다. 추가 개선을 자동 시작하지 않는다.

## 목표 실행 명령문

완료 판정은 검사 수행과 결과 보고의 완료다. 5초/100ms/4GiB 성능 목표 달성을 뜻하지 않는다. 30회는 이전 보호 종료, 60회 및 실기기는 미검증이다. 콜백 수명주기는 실제 전환/재실행 회귀와 소스 감사 범위이며, 모든 지연 순서를 강제하거나 구독 수를 계측한 검사가 아니다.

```text
Docs/Planning/MoonRabbitJunkyard/LevelToolRecoveryPerformance/2026-10-19-stage03-plan.md와 Docs/Goals/MoonRabbitJunkyard/LevelToolRecoveryPerformance/2026-10-19-stage03-goal.md를 기준으로 3단계를 진행해. 같은 입력의 반복 성능과 실제 화면의 자동 저장·종료·복원을 검증하고, 메인 스레드 정지와 전체 시간·메모리를 구분해 측정해. 전체 Undo/Redo, 미확정 입력, 공유 초안, 기존 복구 v1과 이전 정상 복구본 보호를 유지해. 사용자 데이터와 이력은 보존하고 고유 시험 폴더에서만 검증해. 30초/8GiB 보호 한도를 지키고 중단된 큰 표본을 반복 강제 실행하지 마. 제품 빌드·커밋·푸시·HTML 갱신·코드에 의한 프리팹 편집은 하지 마. 질문은 제한시간 없는 문답으로 해. 완료 후 성능 목표별 달성/미달/미검증, 기능 회귀 결과, 남은 문제와 복사 가능한 커밋 메시지를 보고해. 추가 개선은 자동으로 시작하지 마.
```
