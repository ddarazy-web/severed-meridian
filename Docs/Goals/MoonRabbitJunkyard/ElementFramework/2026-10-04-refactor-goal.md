수백 종류를 공통 정의와 소수의 행동으로 추가하고, 기존 퍼즐 동작·데이터·표현·자동 플레이의 의미를 보존한다.

## 전체 완료 조건

- [x] 기존 행동을 사용하는 새 종류 3개를 정의·표현 데이터만으로 추가해 배치·피해·제거·미션·표시를 확인한다. 종류 enum·규칙 클래스·조건문 추가 없이 통과한다.
- [x] 새 고유 행동은 행동 구현·등록·검증과 정의로 추가한다. 교환·매칭·낙하·연쇄 실행기를 복제하지 않는다.
- [x] 정의 500개의 검색·선택·검증·저장·복원·ID 조회가 정상이다. 기본 보드 실행에 전체 카탈로그 반복 탐색이 들어가지 않는다.
- [x] 일부 종류만 사용하는 레벨은 불필요한 아틀라스·프리팹을 읽지 않는다. 공급·행동·효과의 생성 가능 관계도 준비 집합에 포함한다.
- [x] 상자·고철·회수캡슐·자물쇠·금속기둥 상자·발전기·거미줄·곰팡이·먼지와 네 파워의 기준 결과를 보존한다.
- [x] 동일 시드·행동 목록의 칸/본체 상태·내구도·충전·이동 횟수·미션·효과 기록이 기준과 일치한다. 식별자·표현의 의도적 차이는 따로 명시한다.
- [x] 에셋과 재생성 MemoryPack 입력이 같은 결과를 낸다. 50레벨 구간과 아틀라스 분할·Addressables 방식을 유지한다.
- [x] 원본 GUID·enum 숫자·위치·연결을 보존하고 변환 미리보기·백업·복구를 제공한다.
- [x] 중복·누락 ID, 미지원 행동, 충돌 정책, 포맷/카탈로그 불일치를 명확히 거절한다.
- [x] 에디터·게임·플레이 테스트가 동일 표현 정의를 조회한다.
- [x] 숨은 정보만 다른 두 상태의 봇 공개 관찰은 동일하다.
- [x] 풀 재사용·취소·씬 전환 뒤 표현 잔여 상태와 리소스 핸들 누수가 없다.
- [x] 새 종류를 위해 구형 종류별 분기를 수정하지 않는다. 필요한 구형 읽기는 호환 경계에 격리한다.
- [x] 카탈로그 에디터의 MVVM 시범에서 검색·선택·검사를 UI 없이 확인하고 Undo/Redo·구독 해제를 보존한다. 효과를 비교한 뒤 적용 범위를 결정하며 MVVM 전면 도입은 강제하지 않는다.
- [x] HUD 화면 의존을 줄일 때 실제 상태와 표시 상태를 혼동하지 않는다. 미션 숫자와 보드 연출의 기존 순서를 유지한다.
- [x] 드론은 미션/목표 프로필 키로 필요한 선택 정책만 연결한다. 비활성 정책은 호출하지 않고 같은 후보 검색은 재사용한다.
- [x] 후보 병합·범위 조준 중심·예약·충전·2×2 피해·캐시 갱신·착탄 재선정·동률 난수 선택이 기존 의미를 보존한다.
- [x] 공급으로 뒤늦게 생기는 목표를 인식하고 완료 미션 정책은 제외한다. 정책 누락을 일반 대체로 숨기지 않으며 선택 근거와 호출 횟수를 확인할 수 있다.
- [x] 모든 수량·조합의 드론이 상승·개별 시간 호버·돌진을 사용하고 원형 선회는 없다. 동시 상승·호버, 프로펠러 회전, 목표 예고 부재를 유지하며 연출 편차로 규칙 난수를 소비하지 않는다.
- [x] 돌진 중 목표 무효화 시 현재 위치에서 감속·호버하고 예약 해제·재선정 후 같은 위치에서 재돌진한다. 필요 시 호버를 연장하고 후보가 전혀 없으면 종료한다. 반복 무효화·일시정지·취소·풀 재사용 후 위치/예약 잔여 상태가 없다.

## 현재 검증 범위와 한계

현재 운영은 통합 가이드의 큰 구간1~5를 완료한 상태다. 아래 초기7구간 표는 과거 참고이며 현재 실행 번호와 다르다. 원본 전체 변환·디스크 팩 재생성·후속 구현은 자동으로 수행하지 않았다.

빌드를 하지 않으므로 Android/iOS IL2CPP와 실제 Addressables 번들 검증은 완료로 표시하지 않는다. Editor에서 가능한 메모리 직렬화·리소스·게임 동작을 먼저 검사한다. 성능 수치는 측정 후 기록하며 확인하지 않은 FPS·메모리 상한을 약속하지 않는다.
