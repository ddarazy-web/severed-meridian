# 1단계 목표 — 월드 보드 표시

> 2026-10-01 변경: 현재 보드는 **9×9(81칸)**이다. 아래 10×10·100칸 계획과 검증 수치는 당시 기록으로 보존하며 9×9 검증 결과가 아니다. 현재 크기·표시·데이터 전환 기준은 [9×9 보드 결정](../../../Decisions/MoonRabbitJunkyard/2026-10-01-nine-by-nine-board.md)을 따른다.

상태: 1단계 구현·Unity Editor 검증 완료 (2026-09-30)

## 목표

ServeredMeridian의 독립 게임 씬에서 기존 레벨 데이터를 읽어, 확정된 블록·장애물 이미지를 월드 공간에 표시한다. 보드는 SpriteRenderer로 구성하며 게임용 프리팹을 기능별로 분리한다. 이번 단계는 정적 표시 기반을 완성하는 단계다.

상위 계획: [전체 5단계](../../../Planning/MoonRabbitJunkyard/WorldGameScreen/2026-09-30-world-game-screen.md)
실행 계획: [1단계 작업 순서](../../../Planning/MoonRabbitJunkyard/WorldGameScreen/stage-01-world-board-plan.md)

## 포함 범위

- `Assets/Scenes/PuzzleGame.unity` 독립 씬, 전용 카메라와 보드 표시 진입점.
- `Assets/Prefabs/Game/Puzzle` 아래 보드·칸·장애물·장치 등 실제 책임별 프리팹. 카메라 또는 부트스트랩은 불필요하게 개별 프리팹으로 나누지 않는다.
- 10×10 기준 좌표, 비활성 칸 숨김, 작은 맵에서도 동일한 논리 셀 크기 유지.
- 일반 블록, 가로/세로 로켓, 폭탄, 드론, 자석, 현재 확정된 장애물과 내구도/충전 상태별 이미지.
- 덮개, 먼지, 2×2 장애물, 벽, 포털, 회수 장치 및 레벨에 정의된 장치 연결선 표시.
- Addressables 아틀라스 로드와 해제. 기존 종류별 분할을 유지하고 개별 PNG 로드나 전체 통합 아틀라스로 전환하지 않는다.
- 초기 맵에 없던 파워 블록이 상태 갱신으로 추가되어도 표시 가능한 이미지 준비.
- 일반 실행은 기존 MemoryPack 로더와 레벨 번호를 사용한다. 게임 씬/프리팹에 LevelDefinition 에셋을 직렬화 참조하지 않는다.

## 제외 범위

교환·터치 입력, 매칭·연쇄 실행, 이동 수·승패 연결은 2단계다. 레벨 에디터의 게임 플레이 버튼과 미저장 맵 전달은 3단계다. 목업의 HUD·팝업·가로/세로 UI 배치는 4단계다. 이번에는 UI 프리팹이나 효과 애니메이션을 만들지 않는다. 기존 이미지와 저장 형식, 게임 규칙을 변경하지 않는다.

## 완료 판정

- [x] Unity 컴파일 오류가 없다.
- [x] 독립 씬을 Play Mode로 실행하면 MemoryPack의 지정 레벨이 월드에 표시된다.
- [x] 일반·파워·장애물·지형·장치의 대표 상태가 이미지로 표시되며 누락 에셋을 조용히 색 블록으로 대체하지 않는다.
- [x] 2×2 장애물은 한 개의 이미지로 올바른 크기/위치에 표시된다. 덮개·먼지·장치의 앞뒤 순서가 의도에 맞는다.
- [x] 초기 로켓 없는 상태에서 로켓 있는 상태로 다시 그리는 검사에서 가로/세로 이미지가 나타난다. 실제 매칭 실행은 요구하지 않는다.
- [x] 상태 재표시 및 씬 재진입 시 오브젝트가 중복되지 않고, 종료·로드 중 종료 시 리소스 누수나 파괴된 객체 접근 오류가 없다.
- [x] 게임 씬과 프리팹에 레벨 에셋 직접 참조가 없으며 기존 편집 보드·플레이 테스트 기능이 유지된다.
- [x] 보드 전체와 대표 장애물/장치 화면 캡처, 수행한 검증 결과, 미검증 사항을 기록한다.

## 현재 작업물 인계

이전 초안 C# 3개는 컴파일 오류로 제거되었다. 완성 코드로 간주하거나 복구해서 재사용하지 않는다. 목업 폰트와 라이선스는 유지되어 있지만 이 단계의 필수 의존성은 아니다. 기존 사용자 변경과 `.meta`/GUID를 보존한다. 구현이 끝나도 자동으로 2단계에 진입하거나 커밋하지 않는다.
