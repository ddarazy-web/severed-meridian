# 7단계 제거·낙하·채움 — 목표 및 완료 조건

상태: 구현·Editor 검증 완료 (2026-10-01).

## 목표

게임 화면에서 교환 뒤 블록이 즉시 바뀌는 대신, 제거 → 기존 블록 이동·새 블록 공급 → 착지 → 다음 매칭의 흐름이 보이게 한다. 규칙 실행 결과와 난수 소비는 그대로 유지하고 화면만 기록에 맞춰 재생한다.

## 시작 시점 근거

- 6단계 교환 재생은 완료됐다. 현재 `PuzzleGameSession.Presentation.cs`는 교환 완료 시 Draw를 호출하고, 다음 Update에서 연쇄를 진행한다.
- `PuzzleGameSession.Advance`는 `AdvanceCascade()` 결과를 즉시 그린다. `CascadeStepResult.Settlement.Records`에는 Batch, Kind, Source, Target, Content, Color, Direction, ObstacleIndex가 있다. 정착은 작업 사본을 계산한 뒤 최종 상태를 반영하므로, 최종 상태만 그리면 이동 과정이 사라진다.
- 9×9 보드, 2×2 장애물 확대, 가로 로켓 중앙 보정·12% 확대가 현재 기준이다. 공통 `BoardArtworkLayout` 보정을 이동 중에도 유지한다.

## 확정 범위와 동작

1. 유효 교환의 기존 0.15초 이동이 끝난 뒤 제거 대상만 약 0.12초 동안 축소·투명화한다. 무효 교환 왕복은 그대로 유지한다. 생성된 파워 블록은 제거된 일반 블록과 구분하여 해당 위치에 표시한다.
2. 정착 기록을 Batch 오름차순으로 재생한다. 같은 Batch의 출발 표시를 모두 확보한 뒤 이동시켜 덮어쓰기·블록 복제를 막는다. 좌표와 기록 순서를 이용하고 저장용 블록 ID를 추가하지 않는다.
3. 중력·대각선·지정 경로는 실제 기록의 Source→Target을 따른다. 한 구간 기본 0.12초, 긴 구간은 거리에 따라 늘리되 0.24초 이내로 둔다. 포털은 입구에서 사라지고 출구에서 나타나며 사이의 칸을 직선으로 가로지르지 않는다.
4. 공급 블록은 해당 공급 칸의 유입 방향 반대쪽 약 0.5칸에서 들어온다(기본 0.16초). 보드 상단으로 고정하지 않는다. 공급 Kind의 Source가 생성 위치와 같을 수 있으므로 일반 낙하로 오인하지 않는다. 공급원이 보드 내부에 있으면 해당 칸 주변으로 표시를 제한해 장애물·비활성 칸을 통과하는 모습이 생기지 않게 한다.
5. 최종 착지는 약 0.06초의 작은 반응으로 마무리한다. 여러 구간을 연속 이동하는 블록에는 매 구간 착지를 넣지 않는다. 시간 값은 기존 직렬화 설정 방식으로 조정 가능하게 하되 새 사용자 옵션 화면은 만들지 않는다.
6. 바닥·먼지·덮개·벽·포털 장치·2×2 고정 본체는 따라 이동하지 않는다. 일반/파워 블록, 이동 가능한 고철·회수 부품은 실제 규칙대로 움직인다. 회수 부품은 기록과 회수 결과에 맞춰 사라지며 다시 나타나지 않는다.
7. 교환·파워 탭·아이템·자동 매칭 뒤의 제거와 정착을 같은 표시 경계에 연결한다. 파워 공격 궤적·폭발·드론 비행·장애물 타격 상세 연출은 8단계다. 이번에는 그 결과의 기본 제거·교체·낙하가 누락되지 않게 한다. 섞기와 초기 보드 등 이동 기록 없는 결과는 정확한 최종 표시를 유지하며 가짜 경로를 추정하지 않는다.
8. 재생 중 입력·아이템·다음 연쇄를 차단한다. HUD와 승패 팝업은 해당 결과의 재생이 끝난 뒤 반영한다. 일시정지는 진행 시간을 멈추고, 다시하기·실패·씬 종료는 표시 객체와 잠금을 정리한다.

## 완료 조건

조건별 실제 실행 결과는 [최종 검증 기록](../../../Verification/MoonRabbitJunkyard/WorldGameScreen/stage-07-progress.md)의 완료 조건 대조표에 연결했다. 플레이어/콘텐츠 빌드와 실기기 검증은 이 완료 판정에 포함하지 않는다.

- [x] 실제 게임 씬에서 유효 교환 → 제거 → 공급 포함 정착 → 자동 연쇄 순서와 각 중간 프레임을 확인한다.
- [x] 세로·가로 중력, 대각선, 지정 경로, 포털, 내부 공급원, 같은 Batch의 여러 이동, 한 블록의 여러 Batch 이동을 검사한다. 사라짐·복제·순간이동·잘림이 없다.
- [x] 파워 생성/발동, 이동 가능한 고철·회수 부품, 회수 도착, 고정 2×2·덮개·벽, 공급 소진 후 남는 빈칸을 검사한다. 채울 수 없는 칸을 임의로 채우지 않는다.
- [x] 동일 레벨·시드·입력의 직접 실행기와 최종 보드, 이동 수, 난수 소비, 공급 커서, 미션·회수·승패 결과가 같다. 재생 속도·pause는 결과를 바꾸지 않는다.
- [x] 단계 재생 전에는 다음 연쇄와 결과 UI가 진행되지 않으며 완료 후 입력이 정상 복원된다. 기록 없는 단계와 정착 거절도 잠금이 남지 않는다.
- [x] 일시정지·재개, 회전, 재생 중 다시하기 5회, 씬 종료·재진입에서 오래된 콜백·위치·색/알파·축척·렌더 순서가 남지 않는다.
- [x] 실제 가로 1280×720·세로 450×800에서 시작/중간/착지/연쇄 후 연속 캡처 또는 영상을 확인한다. 정적 이미지 한 장으로 이동 검증을 대체하지 않는다.
- [x] 관련 기존 교환·입력·UI·월드 보드 검사와 새 재생 검사를 통과한다. Asset 사본/MemoryPack 진입을 모두 확인한다.
- [x] 검증 기록과 사용 안내를 각 분류 폴더에 작성하고 완료 조건별 증거를 연결한다. 미검증 기기 항목을 명시한다.

## 제약과 제외

ServeredMeridian만 수정한다. 기존 dirty 작업·9×9 데이터·50레벨 MemoryPack·Addressables 아틀라스·GUID를 보존한다. 새 이미지, 패키지, 레벨 저장 형식, 일반화된 타임라인 시스템은 추가하지 않는다. 새 게임 프리팹이 필요할 때만 `Assets/Prefabs/Game/Puzzle`을 사용하고 UI는 `Assets/Prefabs/UI/Puzzle`로 구분한다.

**플레이어·Addressables 콘텐츠 빌드와 이를 내부 호출하는 검사도 금지한다.** 기존 리소스로 Editor 컴파일·Play Mode 검증만 한다. 번들이 없으면 빌드로 우회하지 않고 제한을 보고한다. 사용자 Editor 강제 종료, 미저장 씬·원본 레벨 자동 저장, 자동 커밋·푸시를 하지 않는다. 8단계 파워 상세 효과, 9단계 소리·진동·미션 비행은 범위 밖이다.
