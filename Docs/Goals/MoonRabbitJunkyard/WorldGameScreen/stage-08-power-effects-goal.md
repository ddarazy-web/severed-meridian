# 8단계 파워·장애물 상세 연출 — 목표 및 완료 조건

상태: 구현·Editor 검증 완료 (2026-10-01). 완료 조건별 근거는 검증 기록의 최종 감사 표를 따른다. 플레이어·Addressables 콘텐츠 빌드와 실기기 검증은 수행하지 않았다.

[계획](../../../Planning/MoonRabbitJunkyard/WorldGameScreen/stage-08-power-effects-plan.md) · [목표 명령문](../../../Commands/MoonRabbitJunkyard/WorldGameScreen/stage-08-goal-command.md)

## 목표

게임 화면에서 파워의 출발·이동·타격과 장애물의 손상·제거를 구분해 보여준다. 이미 계산한 규칙 결과를 재생하며, 공격 도착 → 해당 대상 반응 → 전체 효과 완료 → 동시 낙하·공급 → 다음 연쇄를 연결한다.

## 시작 기준

1~7단계 완료 상태를 유지한다. 최신 기준은 [신규 공급 대각선 결정](../../../Decisions/MoonRabbitJunkyard/2026-10-01-fresh-supply-diagonal.md), [동시 낙하 검증](../../../Verification/MoonRabbitJunkyard/WorldGameScreen/2026-10-01-simultaneous-fall.md), [7단계 사용 안내](../../../Guides/MoonRabbitJunkyard/WorldGameScreen/stage-07-settlement-usage.md)다. 이전 7단계 문서의 Batch 간 순차 재생·공급 0.5칸 시작 설명보다 최신 동시 낙하 구현과 사용 안내가 우선한다.

확인한 코드에서 `EffectRecord`는 Source/Target/Cause/Response/Content, 내구도·덮개·먼지 전후 값, HitGroup, 충전 전후 값을 제공한다. 이것이 발사 주체·조합·드론 착탄 순서를 모두 설명한다고 가정하지 않는다. 기록 목록 순서나 HitGroup을 곧바로 화면 시간으로 쓰지 않는다.

## 확정 범위

| 대상 | 화면 동작 |
| --- | --- |
| 청소로켓 | 대기 중 불꽃 없음. 발사 때만 기존 4프레임·궤적을 사용하고 기록된 가로/세로 양방향 타격을 도착 시 표시. 비활성 칸·벽 통과는 현 규칙 유지 |
| 수집 드론 | 기존 4프레임 프로펠러를 반복하며 발동 시 이륙·표적 표시·비행·착탄. 화면에서 표적을 다시 선택하거나 난수를 소비하지 않음 |
| 달 폭탄 | 기존 8프레임 폭발, 기록된 범위·피해만 표시. 주변을 먼저 지우지 않음 |
| 무지개 자석 | 기존 흡인·변환 이미지로 실제 선택 색·대상을 표시. 변환된 파워의 후속 발동 순서 유지 |
| 파워 조합·연쇄 발동 | 지원 중인 모든 조합을 기존 규칙대로 표현. 원인 공격이 도착한 뒤 다음 파워 발동. 독립된 공격은 함께 재생 가능 |
| 파워 생성·일반 매칭 | 기존 생성·5색 매칭 효과를 연결하고, 생성 파워를 일반 제거 대상으로 잘못 숨기지 않음 |
| 장애물·덮개·먼지 | 기록의 반응·전후 값에 맞춰 타격, 단계 변경, 제거를 표시. 나무·금속·거미줄·먼지·곰팡이 효과와 발전기 충전 이미지를 재사용 |

2×2 본체는 한 객체로 반응하며 점유 네 칸 때문에 같은 손상을 네 번 재생하지 않는다. 같은 턴의 별도 유효 타격은 합쳐서 누락하지 않는다. 무효·차단·보호 반응을 손상으로 표시하지 않는다. 고정 레이어를 낙하시키지 않는다.

초기 연출 값: 일반 효과 4프레임은 프레임당 0.05초, 폭발 8프레임은 0.03초, 로켓 발사 준비 0.06초와 비행 0.06초/칸(0.12~0.36초), 드론 로터 프레임당 0.06초와 비행 0.30~0.55초, 자석 흡인·변환 묶음 0.35초. 같은 타격에서 오버레이와 반응은 겹쳐 재생해 불필요한 직렬 대기를 줄인다. 실제 캡처로 조정한 값은 사용 안내에 남긴다. 시간·프레임률 변경은 규칙 결과에 영향을 주지 않는다.

## 보존 및 제외

- 9×9, 2×2 장애물 확대, 가로 로켓 중앙 보정·12% 확대, 스와이프와 UI 입력 경계를 보존한다.
- 기존 블록과 신규 공급 블록의 동시 낙하·대기열, 신규 공급만 대각선 허용, 예정된 상단 공급 우선 처리를 보존한다.
- Addressables의 분리된 아틀라스를 필요한 종류별로 로드·해제한다. 개별 텍스처 직접 로드나 거대 통합 아틀라스로 우회하지 않는다.
- 소리·진동·미션 수집 비행·승패 상세 연출은 9단계다. 신규 이미지 생성, 패키지 설치, 규칙/난이도/저장 스키마 변경은 하지 않는다.
- 빌드 금지: 플레이어·Addressables 콘텐츠 및 이를 내부 실행하는 검사 포함. 기존 번들에 이미지가 없으면 누락을 기록하고 빌드로 해결하지 않는다. Editor 직접 에셋 검사는 번들 검증과 구분한다.
- 새 게임 효과 프리팹이 필요하면 `Assets/Prefabs/Game/Puzzle/Effects/`에 기능별로 둔다. UI 프리팹은 `Assets/Prefabs/UI/Puzzle/`로 구분하며 이번 단계에서 불필요하게 추가하지 않는다.

## 완료 조건

- [x] 재생기 초안의 미정의 `BuildClips` 호출을 실제 효과 구성 구현으로 해결하고, 현재 전체 소스의 Editor 컴파일 성공을 확인한다. 과거 검사 결과로 대체하지 않는다.
- [x] 네 파워의 단독 발동·매칭 유발 발동, 지원 조합 전체, 연쇄·마지막 파워 처리에서 빠진 효과가 없다.
- [x] 공격 전·도착 직전·타격·단계 변경·완료 프레임을 확인한다. 발사 전 로켓 불꽃, 조기 제거, 드론 재추첨, 파워 중복 발동이 없다.
- [x] 1×1/2×2 손상·파괴, 덮개/먼지, 발전기 충전, 같은 대상 반복 타격을 기록과 대조한다.
- [x] 직접 실행기와 애니메이션 세션의 최종 보드·난수·이동 수·공급 커서·미션·회수·승패가 같다.
- [x] 재생 중 입력·아이템·다음 연쇄·결과 UI 조기 표시를 막고 pause/resume, 회전, 다시하기 5회, 실패, 씬 종료/재진입 시 잔상·잠금·객체 누적이 없다.
- [x] 동시 낙하·신규 대각선·기존 스와이프 회귀가 통과한다. 가로 1280×720·세로 450×800의 실제 게임 씬 중간 프레임 증거를 확인한다.
- [x] 아틀라스 취소·해제와 필요 효과 준비를 확인한다. Asset 사본/MemoryPack 진입을 보존하고, 확인하지 못한 번들·실기기 항목을 명시한다.
- [x] 검증 기록·사용 안내·목차를 갱신한다. 실행하지 못한 필수 항목은 미완료로 남기며 문서 작성만으로 완료 처리하지 않는다.
