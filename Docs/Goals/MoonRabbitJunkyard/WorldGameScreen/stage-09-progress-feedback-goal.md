# 9단계 목표·완료 조건 — 미션 수집·진행·승패 피드백

상태: 5개 작업·15개 완료 조건 구현 및 Editor 검증 완료 (2026-10-01). [실행·검증 기록](../../../Verification/MoonRabbitJunkyard/WorldGameScreen/stage-09-progress.md). 새 검사 349 PASS·관련 회귀 1,526 PASS, 독립 리뷰 수정 후 전체 재검사 통과. 빌드·실기기 검증은 수행하지 않았다.

[작업 계획](../../../Planning/MoonRabbitJunkyard/WorldGameScreen/stage-09-progress-feedback-plan.md) · [목표 명령문](../../../Commands/MoonRabbitJunkyard/WorldGameScreen/stage-09-goal-command.md)

## 목표

실제 미션 진행을 수집 비행과 HUD 반응으로 전달하고, 이동 수·연쇄·시작·라스트팡·승패를 기존 규칙의 확정 시점에 맞춰 표시한다. 보드 규칙과 결과를 바꾸지 않으며 표시 수치가 실제 상태와 일치해야 한다.

## 현재 근거와 보존 기준

- 착수 전 `PuzzleHudView.Refresh`는 `session.IsPresenting`이면 갱신을 건너뛰었다. 현재는 표시 진행을 별도로 전달하여 연출 중에도 HUD를 갱신한다. `PuzzleMissionView`와 `PuzzleResultView`의 기존 수치·결과 화면을 보완하며 중복 HUD나 결과 패널을 만들지 않는다.
- 8단계 완료 기록과 최신 사용 안내를 함께 읽는다. 과거 완료 검사 수를 9단계 실적으로 사용하지 않는다.
- 최신 드론 기준: 일반 3기 이하는 생성점에서 0.55초 동안 0.65칸 상승, 최소 0.45초 대기 후 곡선 돌파. 로켓·폭탄·자석 조합 및 4기 이상은 기존 대형 선회. 표적 예고는 숨긴다.
- 낙하·신규 공급은 저장된 이동 시간 / 1.44. 동시 낙하·신규 공급 대기열, 기존 블록 대각선 이동 금지와 예정된 상단 공급 우선을 유지한다.
- 9×9, 블록·2×2 장애물 크기, 가로 로켓 보정, 스와이프 최상위 표시, 공격 범위 중첩에 따른 2×2 피해, 50레벨 MemoryPack·Asset 시험 경로, 필요한 종류만 읽는 Addressables와 객체 재사용을 보존한다.

## 이번 단계 결정

| 항목 | 적용 기준 |
| --- | --- |
| 미션 수집 | 실제 진행 증가에만 반응. 색·장애물·덮개·먼지·회수 등 각 규칙의 미션 갱신 근거를 조사한다. 원점이 확실하면 월드→HUD 수집 비행, 확실하지 않으면 HUD 반응만 사용한다 |
| 수치 | 규칙 진행과 표시 진행을 분리한다. 비행 도착에 맞춰 표시 진행만 갱신하고 완료 경계에서 실제 값으로 일치시킨다. 같은 변화의 이중 집계 금지 |
| 수집량 | 한 번에 많은 수집은 미션별 묶음으로 표시한다. 화면에 동시에 보이는 수집 객체는 최대 8개로 제한하되 실제 증가량은 전부 반영한다 |
| 타이밍 | 수집 비행 초기값 0.25~0.40초, HUD 강조 0.15초. 보드 피해·낙하와 겹쳐 재생하고 보드 진행을 직렬로 지연하지 않는다 |
| 진행 피드백 | 실제 이동 소비에만 이동 수 강조, 실제 새 매칭 라운드에만 연쇄 강조. 중력 Batch나 표시 프레임 수를 연쇄로 세지 않는다 |
| 시작·종료 | 준비 완료 뒤 짧은 시작 표시. 라스트팡 시작/종료는 실행기 상태를 따른다. 최종 승패 패널은 보드와 수집 표시가 정리된 뒤 한 번만 표시한다 |
| 시간·수명 | 기존 세션 표시 시간과 pause 경계를 사용한다. 회전 시 수집 목적지를 다시 투영한다. 취소·다시하기·종료 시 수집·강조·입력 잠금과 풀 소유권을 정리한다 |

새 수집 UI 프리팹이 필요하면 `Assets/Prefabs/UI/Puzzle/Feedback` 아래 기능별로 생성한다. 월드 게임 효과가 필요하면 `Assets/Prefabs/Game/Puzzle/Effects`로 분리한다. 기존 이미지·미션 아이콘을 재사용하고 새 이미지·패키지·음원 생성은 하지 않는다.

소리은 별도 10단계, 전체 속도·성능·안정화는 11단계다. 광고·과금·인벤토리·새 미션·레벨 생성·저장 DTO 변경·플랫폼 설정 변경은 제외한다.

## 완료 조건

- [x] 1. 현재 코드·dirty 작업과 선행 검증을 기록하고 최신 드론·낙하 동작을 보존한다.
- [x] 2. 지원 미션 전체의 실제 진행 변경 지점과 표시 원점의 근거를 표로 남긴다.
- [x] 3. 규칙을 재실행하지 않고 행동·파워·연쇄·회수·라스트팡의 실제 미션 변화만 전달한다.
- [x] 4. 진행 증가가 0인 무효 교환·보호·무효 타격에는 수집이나 완료 반응이 없다.
- [x] 5. 표시 진행은 비행 도착과 맞고 최종 실제 진행과 일치한다. 중복 미션과 한 공격의 복수 미션도 이중 집계하지 않는다.
- [x] 6. 많은 수집은 동시에 최대 8개 표시 객체로 처리하고 증가량을 누락하지 않는다. 동작 후 풀 개수가 반복마다 증가하지 않는다.
- [x] 7. 미션 달성 시점에 완료 표시가 한 번만 나타난다. 초과 진행·목표 0·초기 달성 상태는 규칙 상태에 맞게 표시한다.
- [x] 8. 이동 수 강조는 실제 이동 소비에만, 연쇄 강조는 실제 새 매칭 라운드에만 나타난다.
- [x] 9. 시작 표시와 라스트팡이 입력·상태 경계에 맞고 최종 결과 패널이 조기에 열리지 않는다.
- [x] 10. 일시정지 중 수집·HUD·시작/종료 표시 시간이 멈추고 재개 후 자연스럽게 이어진다.
- [x] 11. 가로·세로·안전 영역 변화에 수집 도착점이 실제 미션 아이콘을 따라가며 UI 터치가 보드 조작을 일으키지 않는다.
- [x] 12. 다시하기·준비 취소·실패·씬 종료/재진입에서 잔상·늦은 콜백·자원 누수·입력 잠금 잔류가 없다.
- [x] 13. 실제 게임 씬의 Asset/MemoryPack 맵에서 최종 보드·미션·이동 수·공급·난수·승패가 직접 실행기와 같다.
- [x] 14. 6~8단계의 영향받는 스와이프·낙하·파워 검사와 Editor 진입 회귀를 통과하고 중간 프레임 캡처를 남긴다.
- [x] 15. 조건별 증거·실제 검사 수·미검증 항목·사용법·변경 파일 책임을 문서화한다. 새 완료 수치와 과거 이력을 구분한다.

플레이어·Addressables 콘텐츠 빌드와 이를 내부 호출하는 검사도 금지한다. 원본 레벨·씬·무관 변경을 보존하고 사용자 에디터를 강제 종료하지 않는다. 자동 커밋·푸시·다음 단계 실행은 하지 않는다. 빌드·실기기 미검증을 Editor 검사 완료로 대체하지 않는다.
