# 네이티브 레벨툴 UX 1단계 목표

상태: 2026-10-22 구현 및 Editor 검증 완료. Android 실기기 검증은 미실시.

## 목표

Android·Windows에서 처음 사용하는 사람이 프로젝트 생성→빈 프로젝트→첫 9×9 레벨 편집을 명확한 화면 안내로 진행하고, 기존 작업을 잃지 않고 프로젝트·레벨을 열 수 있다.

## 완료 조건

- [x] 프로젝트 미선택 시 새 프로젝트/열기/ZIP 가져오기/최근 프로젝트가 구분되어 보인다.
- [x] 이름을 지정해 프로젝트를 만들면 레벨은 0개이며 ‘첫 레벨 만들기’가 보인다. 저장 후 다시 열어도 오류가 없다.
- [x] 첫 레벨은 기본 번호 1과 이름 제안을 제공하고, ‘만들고 편집하기’를 누르면 9×9 보드가 열린다.
- [x] 기존 프로젝트는 미사용 번호를 제안하며, 현재 레벨 복제 시 보드·미션·이동 횟수·튜토리얼과 원본을 보존한다.
- [x] 레벨 없는 상태에서 선택 ID·Max 계산·보드/시험 접근 오류가 발생하지 않는다.
- [x] 기존 편집 버튼·프로젝트별 최근 편집 20개·검색을 유지하고, 행 선택만으로 편집 레벨이 바뀌지 않는다.
- [x] 레벨 전환 시 세 버튼을 제공하고 현재 레벨만 버리기를 선택해도 다른 레벨·공유 데이터 변경은 남는다. 계속 편집은 입력 중 내용까지 보존한다.
- [x] 프로젝트 전환은 전체 작업 경계를 별도로 안내하며 취소·파일 접근 실패·반복 입력에서 기존 작업을 잃지 않는다.
- [x] 레벨 변경은 dirty로 표시되고 명시적 저장 전 실제 레벨 파일을 매번 쓰지 않는다.
- [x] 최근 경로 누락과 빈 목록에 이해 가능한 안내 및 다시 열기/만들기 동작이 있다.
- [x] 작은 화면·키보드·회전 환경에서 신규 화면의 확인/취소 버튼이 접근 가능하다. Windows 단축키와 기존 창 정책을 훼손하지 않는다.
- [x] 1,000개 이상 목록 검사에서 목록 표시를 위한 전체 레벨 JSON 읽기가 추가되지 않는다.
- [x] 관련 자동 검사·컴파일·UI 증거와 원본 데이터 보존 결과를 기록한다. 실기기 미검증은 별도 표시하고 통과로 간주하지 않는다.
- [x] 임시 검사 사본은 정리하고 실제 데이터·검사 결과는 보존한다.
- [x] 변경/검증/제약 보고, 2단계 계획·목표·복사용 실행문, 간략한 커밋 메시지를 제공한다. 실제 커밋·푸시는 하지 않는다.
