# 게임·제작 도구 분리 1단계 — 목표·완료 조건

> 2026-10-08 · 개발·검증 완료
> 문서 작성 완료와 아래 개발 목표 달성은 별개다.

## 목표

현재 Unity 레벨 에디터가 공통 플레이 진입을 사용하도록 연결하고, 독립 Windows 도구가 같은 경로를 재사용할 기반을 만든다. 기존 게임 규칙·보드 연출·편집 동작과 학습 기록 호환성을 유지하며 시험 실행의 입력·저장을 격리한다.

[작업 계획](../../Planning/project-wide/game-authoring-stage-01-plan.md) · [실행 명령문](../../Commands/project-wide/game-authoring-stage-01-command.md)

## 완료 조건

- [x] G1. 제작/시험 기능, Editor 의존, 저장/외부 서비스의 실제 경로와 담당 단계가 문서화되어 있다.
- [x] G2. Runtime 공통 진입이 레벨 사본·시드·표현·튜토리얼 정책을 받아 실행하며 UnityEditor API를 요구하지 않는다.
- [x] G3. 기존 Asset/MemoryPack 게임 진입과 튜토리얼 Automatic/Always/Never가 유지된다.
- [x] G4. 동일 입력·시드·행동에서 기준 보드·정산·이동 수·미션·튜토리얼 결과가 일치한다.
- [x] G5. 시험 플레이가 실제 연결된 정식 진행·아이템·튜토리얼 저장을 변경하지 않으며 불필요한 서비스 초기화를 호출하지 않는다. 미구현 서비스는 검사 완료로 표시하지 않는다.
- [x] G6. 시험 전후 원본 데이터, 미저장 편집 상태, 선택 및 씬 복귀가 보존된다.
- [x] G7. 실패·취소·중복 시작·반복 실행의 사본 소유권과 이벤트/리소스 정리가 검증된다.
- [x] G8. 대표 런타임 UI 시제품 확인으로 도구 UI 기술과 최소 어셈블리 경계를 결정하고 근거·후속 적용 위치를 남겼다.
- [x] G9. 기존 네 프로필과 GUID·전역 설정이 의도 없이 바뀌지 않았고 검사 후 테스트 연결을 해제했다.
- [x] G10. 검증 기록·남은 제약·2단계 계획/목표/실행문을 작성하고 결과를 보고했다.

## 범위 밖

JSON 원본 전환, 전체 편집기 이식, 독립 도구 실행 씬 완성, Steam/모바일 서비스 신규 개발, 전 제품 빌드·기기 실행, 전체 콘텐츠 분리. 레벨툴 프로필에 씬이 없다는 사실을 숨기거나 임시 시제품으로 완료 처리하지 않는다.

## 수행 규칙

필요한 하위 에이전트 사용 가능. 커밋·푸시와 Player/Addressables 빌드는 금지한다. HTML 매뉴얼은 요청 전까지 갱신하지 않는다. 질문은 제한시간 없는 일반 채팅 문답으로 진행한다. 완료 보고에는 실제 변경, 검증 결과, 남은 항목, 다음 실행문, 복사 가능한 커밋 메시지를 포함한다.

모든 필수 완료 조건에 근거가 있을 때만 1단계를 완료 처리한다. Unity 실행 등 환경 제약으로 미검증이 남으면 부분 완료로 보고한다. 사용자에게 목표 실행문을 제시하는 것만으로 자동 목표를 시작하지 않는다.

완료 증거: [1단계 구현·검증 기록](../../Verification/project-wide/game-authoring-stage-01-progress.md). G1은 의존 조사, G2~G5·G7은 공통 세션 검사, G6은 에디터 12가지 왕복, G8은 Runtime UI 시제품, G9는 설정/프로필 diff와 연결 해제, G10은 2단계 문서 및 최종 보고를 근거로 판정했다.
