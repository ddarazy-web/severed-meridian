# Windows 외부 빌드 앱 1단계 — 목표·완료 조건

2026-10-16 · 구현·검증 완료. 상세 근거는 1단계 진행 기록 참조.

[통합 계획](../../Planning/project-wide/external-build-app-integration-plan.md) · [단계 계획](../../Planning/project-wide/external-build-app-stage-01-plan.md) · [복사용 실행문](../../Commands/project-wide/external-build-app-stage-01-command.md)

## 목표

외부 Windows UI가 기존 Unity 빌드 도구와 같은 설정을 조회·저장하고 안전하게 로그 정리를 요청할 수 있는 연결부를 제공한다. 이 단계는 외부 앱 화면 완성이 아니다.

## 완료 조건

- [x] 다섯 등록 제품의 실제 버전, 지원 필드, 저장 옵션과 적용 옵션을 조회한다.
- [x] 플랫폼/옵션 등록부를 재사용하며 외부 UI용 플랫폼 switch나 설정 원본을 중복 생성하지 않는다.
- [x] 조회·검사는 프로필/옵션을 변경하지 않고 실제 빌드를 호출하지 않는다.
- [x] 명시적 저장만 버전/옵션을 변경하며 검증 실패·revision 충돌 시 기존 값이 보존된다.
- [x] 성공 저장값이 Unity UI·외부 재조회·프로필 재로드에 동일하게 반영된다.
- [x] 기존 BAT v1 list/check/build 요청 해석과 종료 코드가 유지된다. build 호환 검사는 모의 실행으로 한다.
- [x] 프로젝트 사용 중·동시 실행·미완료 작업·결과 없는 종료를 식별한다.
- [x] 비밀번호를 읽거나 일반 JSON·명령행·로그에 노출하지 않는다.
- [x] 로그 미리보기에서 후보와 용량을 표시하고 실행 결과에서 삭제·보호·실패·Busy를 구별한다.
- [x] 로그 정리는 기존 보관/잠금/링크 보호를 유지하고 프로젝트 Logs 밖을 삭제하지 않는다.
- [x] 임시 fixture로 회귀를 통과하고 원본 프로필·사용자 옵션·실제 로그를 보존한다.
- [x] Unity 컴파일과 관련 검사를 완료하거나 미검증 사유를 명확하게 기록한다.
- [x] 실제 Player/Addressables 빌드, 커밋·푸시, HTML 매뉴얼 갱신을 하지 않는다.
- [x] 변경·검증·한계를 보고하고 2단계 계획·목표·실행문을 작성한다. 자동으로 2단계 구현하지 않는다.

## 완료 증거

재실행 시 기존 체크 표시만으로 현재 상태를 통과 처리하지 않는다. 변경한 부분의 검사 결과와 재사용한 기존 증거를 구분하여 기록하며, 이미 완료한 기능을 새로 구현했다고 보고하지 않는다.

구현 후 `Docs/Verification/project-wide/external-build-app-stage-01-progress.md`에 검사명·실행 방법·결과·미검증을 남긴다. 체크 항목은 1단계 진행 기록의 검사 결과와 범위에 따라 완료 판정했다.
