# 게임·제작 도구 분리 2단계 — 목표·완료 조건

> 2026-10-08 · 후속 목표 / 개발 미착수
> 1단계 완료 여부는 해당 검증 기록을 따른다. 문서 생성은 2단계 착수가 아니다.

## 목표

기존 SO 제작 원본을 보존하면서 대상 콘텐츠를 Unity와 독립적인 JSON으로 읽고 쓴다. 공유 튜토리얼·안정 ID·기획 출처를 보존하고 기존 공통 퍼즐 시험 경로에서 실행 동등성을 확인한다.

[계획서](../../Planning/project-wide/game-authoring-stage-02-plan.md) · [실행문](../../Commands/project-wide/game-authoring-stage-02-command.md)

## 완료 조건

- [ ] G1. 실제 제작 타입·필드·파일·참조 목록, JSON 대응표와 제외 항목이 있다.
- [ ] G2. project/level/element/catalog/visual/tutorialFlow/tutorialSample/shape 각각 내보내기·읽기·저장·왕복 검사를 통과했다. 모든 기존 프로필·표현·출처·순서 의미가 보존된다.
- [ ] G3. 문서/요소/배치/단계/조건/파라미터/완료 ID가 원래 의미대로 보존되며 GUID 대응표 재사용으로 재내보내기 ID가 안정적이다.
- [ ] G4. 같은 흐름을 사용하는 두 레벨의 flowId와 각각의 bindings, completionId/previousLevelNumbers, 공유/독립 복사 의미가 보존된다. 실행 팩 역변환을 사용하지 않았다.
- [ ] G5. 버전·누락/null/빈 목록·미지원 필드/키·중복 ID/번호·참조·경로 오류를 검출한다. 상위 버전 저장·루트 탈출을 차단하고 한글 경로를 처리한다.
- [ ] G6. UnityEngine/UnityEditor 참조 없이 실제 동일 문서·파서·검증·저장 소스를 실행한 결과가 있다.
- [ ] G7. JSON은 Assets 밖 시험 폴더에만 생성했다. 원본 SO/메타/dirty, 기존 팩/Addressables/프로필이 불변이고 50레벨 팩 정책·기본 실행 경로가 유지된다.
- [ ] G8. 원자 저장·해시 충돌·쓰기/검증/교체 실패·중단 복구를 검사했다. 이전 정상 파일이 읽히며 부분 스냅샷을 성공 결과로 취급하지 않는다.
- [ ] G9. JSON 입력은 PuzzlePlayRequest/CreateTest 경로를 사용하며 실행 사본이 격리된다. 동일 시드/행동에서 보드·정산·이동 수·미션·튜토리얼·공급/파워 결과가 일치한다.
- [ ] G10. 실패·취소·반복 실행의 임시 객체를 정리하고 정식 학습/진행 저장 불변을 확인했다.
- [ ] G11. 검증 기록·제약을 남기고 테스트 연결을 해제했다. 3단계 계획·목표·실행문을 작성하고 결과를 보고했다.

## 범위와 운영

이번에는 JSON 시험 변환 기반만 구현한다. 3단계 공통 편집/JSON 연결, 4단계 공통 레벨툴 씬 시범, 5단계 동등성 확인 후 Unity 기본 편집도 같은 씬으로 전환, 6단계 전체 JSON 정식화·제품 파이프라인 순서다. 기존 EditorWindow의 중복 편집 UI는 영구 유지하지 않는다.

필요하면 하위 에이전트를 사용한다. 커밋·푸시·Player/Addressables 빌드는 금지한다. HTML 매뉴얼은 요청 전까지 변경하지 않는다. 질문은 제한시간 없는 일반 채팅으로 충분히 설명한다.

모든 항목에 실제 증거가 있어야 완료다. 독립 실행환경/Unity 검사 미실행은 미완료로 남긴다. 실제 구현·검증 완료 후 마지막 보고에서만 변경 내용에 맞는 복사용 커밋 메시지를 제공한다.
