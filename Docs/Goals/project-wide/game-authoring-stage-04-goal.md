# 게임·제작 도구 분리 4단계 — 목표·완료 조건

> 2026-10-09 구현·검증 완료. 검증 범위와 후속 UX 항목은 4단계 검증 기록을 따른다.

**목표:** 공통 레벨툴 씬에서 JSON 기본 편집과 실제 게임 시험을 반복할 수 있다.

[계획서](../../Planning/project-wide/game-authoring-stage-04-plan.md) · [실행문](../../Commands/project-wide/game-authoring-stage-04-command.md)

- [x] G1. 3단계 검증과 의존 경계를 확인하고 기본판/5단계 기능 범위를 표시했다.
- [x] G2. 실행용 레벨툴 씬과 기존 Unity 메뉴 진입이 있으며 기존 씬·작업을 보존한다.
- [x] G3. 작업 폴더·레벨 선택·새로 만들기·복제·저장·사본·재열기가 Editor API 없이 동작한다.
- [x] G4. 외부 충돌·실패·미지원·복구·미저장 세 선택에서 자료 유실이 없다.
- [x] G5. 9×9 보드 기본 편집과 2×2·층 교체·기본 미션·공급·단일 Undo/Redo를 공통 API로 처리한다.
- [x] G6. 실행용 카탈로그로 이미지를 표시하고 누락 원인을 알려준다. 지원하지 않는 필드도 보존한다.
- [x] G7. 현재 편집 사본으로 실제 퍼즐을 시험하고 정식 진행/보상을 변경하지 않는다.
- [x] G8. 시험 종료·실패·취소 후 선택·스크롤·폴더·미저장·이력 복원 및 자원 해제를 확인했다.
- [x] G9. 기존 SO 창과 게임 입력/팩/프로필 동작을 보존했으며 실행용 코드에 UnityEditor 의존이 없다.
- [x] G10. 실제 검사와 남은 제한을 보고하고 5단계 계획/목표/실행문, 완료 내용에 맞는 복사용 커밋 메시지를 제공했다.

커밋·푸시·Player/Addressables 빌드·요청 전 HTML 갱신 금지. 필요하면 하위 에이전트 사용. 질문은 일반 채팅 문답. 빌드하지 않은 exe를 검증 완료로 표현하지 않는다.
