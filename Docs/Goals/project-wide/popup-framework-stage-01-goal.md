## 목표

공통 팝업 관리 API와 씬 표시 영역을 만들고, 고유 핸들·중첩 순서·최상위 입력·포커스·차단/정지 요청을 검사 가능한 형태로 제공한다. 기존 게임 팝업의 실제 전환과 선택적 씬 복원은 이번 목표에 포함하지 않는다.

## 완료 조건

- [x] 1. A→B→C에서 B만 제거하면 A→C·Top=C·Count=2이며, 닫힌 핸들 재사용/재닫기로 다른 인스턴스를 제거하지 않는다.
- [x] 2. 단일 종류 재열기는 같은 핸들/Count 유지·맨 위 이동·새 내용 갱신, 복수 허용 종류만 별도 핸들이다.
- [x] 3. 미지/중복 ID·누락 프리팹·내용 적용 실패를 거부하고 기존 순서/내용을 보존하며 후보를 정리한다.
- [x] 4. 실제 EventSystem 포인터/Submit/Cancel에서 최상위만 반응한다. 아래 팝업과 일반 UI/보드 시험 연결에는 입력이 누출되지 않는다.
- [x] 5. 취소 입력 한 번으로 한 팝업만 닫는다. 닫기 금지 최상위의 입력도 아래에 전달하지 않는다. 콜백 중 닫기/재열기의 순서가 일관적이다.
- [x] 6. 최상위 변경 시 이전 유효 선택/기본 선택으로 포커스를 복원한다. 4개 화면 크기/안전 영역과 실제 버튼 raycast가 유효하다.
- [x] 7. 팝업 차단/정지 요청을 별도 제공하며 마지막 요청 종료까지 정지를 유지한다. 외부 차단/정지 합성은 유지되고 Time.timeScale은 바뀌지 않는다.
- [x] 8. host 비활성/파괴/Detach 반복/재연결에서 남은 뷰·구독과 임시 자원이 없다.
- [x] 9. 마지막 변경의 Data/RunInputScene·필요 영향 검사·독립 리뷰 관련 수정·원본/GUID/diff 감사를 증거로 기록한다. 미검증 물리 Android 입력은 구분한다.

## 증거와 제한

결과는 `Logs/PopupFramework/data-results.txt`, `input-results.txt`와 실제 프로세스 종료 코드, UI 캡처를 사용한다. 조건별 증거는 [1단계 검증 기록](../../Verification/project-wide/popup-framework-stage-01.md)에 기록한다. 기존 검사 진입점과 중간 검증 기록은 있으나 마지막 변경 후 전체 8회 검사 97 PASS/0 FAIL/exit0과 리뷰 수정·보존 감사를 확인했다.

1단계가 완료되었으므로 같은 목표를 반복 생성하거나 구현하지 않는다. 후속 단계는 별도 요청이 필요하다.

기존 게임 규칙/레벨/씬/프리팹/이미지/GUID·사용자 dirty를 보존한다. 빌드·커밋·푸시·사용자 Unity 종료·자동 씬 저장·새 패키지/asmdef/DI·풀링을 하지 않는다. 2단계 복원과 3단계 관리 도구/기존 팝업 전환은 시작하지 않는다.
