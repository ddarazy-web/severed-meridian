# 제품 빌드 도구 1단계 — 목표·완료 조건

2026-10-15 최초 목표 · 2026-10-16 상태: 구현·자동 검사 완료. 실제 제품 빌드는 미수행.

이번 요청은 기존 목표 문서의 정리다. 아래 완료 표시는 연결된 과거 검증 기록의 결과이며, 현재 작업 폴더 전체를 새로 검증했다는 뜻이 아니다. 재실행 시 기존 충족 항목은 유지하고 누락만 확인한다. 후속 단계 코드가 존재한다는 이유로 1단계 기능으로 축소하거나 원복하지 않는다.

[통합 계획](../../Planning/project-wide/2026-10-15-build-tool-plan.md) · [1단계 계획](../../Planning/project-wide/build-tool-stage-01-plan.md) · [복사용 목표 실행문](../../Commands/project-wide/build-tool-stage-01-command.md)

## 목표

`Match → Build → 빌드 도구`에서 실제 Build Profile과 연결된 제품 정보를 조회하고 플랫폼별 준비 상태·오류를 확인할 수 있게 한다. **목록 선택과 사전 검사는 활성 프로필·플랫폼·원본 프로젝트 설정을 바꾸지 않는다.**

## 완료 조건

### 화면·정보

- [x] 지정 메뉴에서 동일 UI Toolkit 창을 열 수 있다. 기존 제품 선택 메뉴는 유지된다.
- [x] 실제 프로필 에셋을 발견하고 기존 다섯 제품을 표시한다. 프로필 GUID로 식별하며 심볼 하나만으로 두 레벨툴을 혼동하지 않는다.
- [x] 플랫폼·앱 식별자·시작 씬·제품 심볼·출력 위치·현재 활성 여부를 확인할 수 있다. 제품 정의를 UI에 중복 상수로 만들지 않는다.
- [x] 미등록·복제·설정 오류·읽기 실패 항목은 이유와 다음 행동을 표시하고 다른 정상 항목을 사용할 수 있다.
- [x] 새로고침·선택 검사·창 재열기가 동작하며 삭제된 선택·잘못된 로컬 기록을 안전하게 처리한다.
- [x] 빌드 버튼은 실행되지 않는 상태이고 2단계 예정임을 설명한다. 아직 없는 실제 SDK 옵션을 동작하는 것처럼 표시하지 않는다.

### 구조·판정

- [x] 공통 사전 검사와 Android/iOS/Windows 조회 처리가 분리되고 등록표로 연결된다. UI·공통 조정 코드에 플랫폼별 switch를 계속 추가하는 방식이 아니다.
- [x] 동일 플랫폼의 게임·레벨툴은 동일 플랫폼 처리기를 사용하고 제품 차이는 기존 프로필로 판단한다.
- [x] 아직 사용하지 않는 실행·후처리·옵션용 빈 계층을 구현하지 않는다. 실제 단계 확장은 통합 계획의 후속 단계로 남긴다.
- [x] 비활성 대상, 미설치 모듈, 검사하지 못한 SDK·컴파일·서명 환경을 구분하고 ‘미확인’을 준비 완료로 표시하지 않는다.
- [x] 없는 PlayerSettings나 제품 정의를 조회 과정에서 자동 생성·보정하지 않는다.

### 무변경·검증

- [x] 선택·갱신·사전 검사 전후 활성 Build Profile·활성 플랫폼·출력 설정·프로필 및 전역 PlayerSettings가 동일하다.
- [x] Addressables 프로필·Library/보고서/content-state 경로·도구 UI 그룹 포함·관련 설정 에셋이 동일하다. 개인 로컬 선택 기록 외에는 조회 때문에 파일을 저장하지 않는다.
- [x] 원본 수정 없이 정상·오류·등록 누락과 UI 조작을 검사하고 Unity 컴파일 결과를 확보한다.
- [x] 테스트는 외부 `Tests`와 기존 연결 도구를 사용하고 완료 후 임시 연결·자신의 임시 자료를 정리한다.
- [x] 실행 결과를 `Docs/Verification/project-wide/build-tool-stage-01-progress.md`에 작성한다. 못한 검사는 이유와 함께 미완료로 남긴다.
- [x] 2단계 계획·목표·복사용 실행문과 완료 보고를 제공하되 다음 단계는 자동 구현하지 않는다.
- [x] Player/APK/AAB/iOS 출력·Addressables 번들 생성·커밋·푸시·HTML 매뉴얼 갱신·SDK 설치를 하지 않는다.

## 사용자 확인 시나리오

1. 메뉴로 창을 열고 Android Game에서 Windows Level Editor로 목록 선택을 바꾼다.
2. 상세 정보가 바뀌지만 Unity 활성 플랫폼·프로필·콘텐츠 설정은 그대로인지 확인한다.
3. ‘사전 검사’를 누르면 오류·주의·미확인을 구분해 보여주며 빌드나 설정 자동 수정은 하지 않는다.
4. 프로필 정보가 잘못됐을 때 문제 항목과 수정 위치가 보이고 다른 프로필을 계속 선택할 수 있다.
5. 창을 다시 열면 마지막 유효 선택을 복원한다. 이 기억이 제품 프로필 자체를 수정하지 않는다.

## 검증 경계

최초 목표 작성 당시 체크박스는 미완료였으며, 현재 표시는 2026-10-16 실제 구현·검사 결과를 반영한다. 근거와 미검증 범위는 [진행 기록](../../Verification/project-wide/build-tool-stage-01-progress.md)을 따른다. 1단계 통과는 실제 제품 빌드 성공이나 SDK ON/OFF 검증 완료가 아니다. 실제 빌드 금지는 후속 문서에 실행 코드가 등장하더라도 별도 승인 전까지 유지한다.
