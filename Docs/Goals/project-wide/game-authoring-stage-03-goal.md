# 게임·제작 도구 분리 3단계 — 목표·완료 조건

> 후속 목표 · 구현 미착수. 2단계 완료 확인 및 별도 실행 요청 후 진행한다.

**목표:** 기존 Unity 레벨 에디터에서 선택한 JSON 작업 폴더를 직접 편집·저장·시험하며, 이후 공통 레벨툴 씬에서도 사용할 편집 기능을 확보한다.

[계획서](../../Planning/project-wide/game-authoring-stage-03-plan.md) · [실행문](../../Commands/project-wide/game-authoring-stage-03-command.md)

- [ ] G1. 기존 기능과 변경/저장 호출 위치를 대조한 범위표가 있다. 필수 기능을 말없이 생략하지 않았다.
- [ ] G2. 공통 편집 세션이 문서·선택·변경 이력·미저장 상태를 소유하며 공통 API에 SO/SerializedObject/UnityEditor 의존이 없다.
- [ ] G3. 배치·층별 교체·이동·복제·영역 선택·삭제·2×2·연결/흐름·미션·공급을 공통 기능으로 편집할 수 있다. ID/점유/참조 규칙이 보존된다.
- [ ] G4. Undo/Redo가 한 동작씩 정확히 적용되고 실패/취소가 부분 변경을 남기지 않는다. 기존 SO 모드도 회귀 검사를 통과했다.
- [ ] G5. 창에서 SO/JSON 및 저장 대상·미저장 상태를 구분한다. JSON 폴더 열기/레벨 선택/새로 만들기/복제/저장/재열기가 동작한다.
- [ ] G6. 공통 튜토리얼·레벨별 bindings·샘플·모양이 JSON 작업 폴더에 저장되며 공유 수정과 독립 복사의 영향이 명확하다.
- [ ] G7. 외부 수정·저장 실패·미지원 문서·이전 정상본 복구를 처리하고 미저장 상태의 저장/버리기/취소가 내용 유실 없이 동작한다.
- [ ] G8. 실제 게임 시험은 현재 편집 스냅샷과 CreateTest 문맥을 사용한다. 보드/튜토리얼/공급/파워 결과가 동일하며 정식 저장에 영향을 주지 않는다.
- [ ] G9. 시험 종료/실패/취소 후 선택·미저장·변경 이력·작업 폴더가 유지되고 임시 객체가 정리된다.
- [ ] G10. 50레벨 팩·Addressables·프로필·기본 정식 입력은 유지했다. JSON 모드에서 옛 SO로 잘못 시험/배포하지 않는다.
- [ ] G11. 실제 UI와 자동 검증 결과·제약을 기록하고 테스트 연결을 해제했다. 4단계 계획/목표/실행문과 마지막 복사용 커밋 메시지를 제공했다.

이번에는 공통 레벨툴 씬/독립 실행 UI/전체 원본 이관을 구현하지 않는다. 공통 씬은 4단계 시범, 5단계 기능 동등성 확인 후 Unity의 기본 편집 화면으로도 채택한다.

커밋·푸시·Player/Addressables 빌드·요청 전 HTML 매뉴얼 수정 금지. 필요 시 하위 에이전트 사용 가능. 질문은 제한시간 없는 일반 채팅 문답으로 진행한다. 검사하지 못한 항목은 완료로 표현하지 않는다.
