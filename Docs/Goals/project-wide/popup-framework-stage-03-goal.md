# 팝업 프레임워크 3단계 목표·완료 조건

작성일: 2026-10-03. 상태: 3단계 구현·검증·독립 리뷰 처리와 12개 완료 조건 감사 완료. 1~2단계 보존, 다른 단계 미착수.

[계획](../../Planning/project-wide/popup-framework-stage-03-plan.md) · [복사용 명령문](../../Commands/project-wide/popup-framework-stage-03-command.md) · [설계](../../Systems/project-wide/2026-10-02-popup-framework-design.md)

## 목표

하나의 관리 창에서 등록·정책·실행 순서·입력 권한·복원 대기를 확인하고 템플릿으로 새 팝업을 추가한다. 기존 일시정지·결과·설명을 공통 관리 API로 전환해 중첩/중간 제거/최상위 입력과 선택적 복원을 실제 게임 연결에서도 검증한다.

## 선행 조건

현재 2단계는 [최종 검증·리뷰 처리와 보존 감사](../../Verification/project-wide/popup-framework-stage-02.md)를 완료했다. 실행 시 현재 상태에서도 이 증거와 동작이 유지되는지 확인하며 재구현하지 않는다.

확인할 항목은 캡처 중 Host 종료 정리, 이동 예제 입력 차단 해제, 복원 후 현재 명령 수신과 최종 회귀/보존 감사다. 회귀가 발견되면 관련 문제만 해결한 뒤 실제 게임 전환을 시작한다. 다른 미완료 목표가 활성 상태라면 목표를 중복 생성하지 않는다.

## 완료 조건

- [x] 1. 2단계 완료 증거와 처리된 리뷰를 현재 코드에서 확인한다. 이번 작업 시작 HEAD/status/원본 해시/GUID를 기록하고 기존 변경을 보존한다(Task 1).
- [x] 2. `Tools/Popup/관리`, `템플릿 생성`, `등록 검사`가 동작한다. 등록의 중복/빈 ID·누락 프리팹·RectTransform/CanvasGroup 누락을 항목별 진단하고 잘못된 등록을 거부한다(Task 1).
- [x] 3. catalog 편집은 Undo·명시적 저장으로 동작한다. 선택한 실행 Host의 순서/Top/Count/정지/보관/pending 조회가 실제 서비스와 일치하고, 조회·시험 열기/닫기·창 종료가 원본 설정/다른 Host에 영향을 주지 않는다(Task 1).
- [x] 4. 템플릿의 State/View/프리팹을 생성하고 실제 컴파일·등록·열기·값 캡처/복사·닫기를 통과한다. 잘못된 이름/경로·출력 충돌은 생성 전 거부하며 기존 파일을 덮어쓰지 않는다(Task 1).
- [x] 5. 세 게임 팝업이 catalog와 Binding을 통해 동작한다. 단일 인스턴스/Restorable 정책, pause만 정지 요청, pause/description 취소 가능·result 취소 불가가 적용된다. 반복 Refresh가 목록/최상위를 바꾸지 않는다(Task 2).
- [x] 6. 설명→pause 중첩과 중간 설명 제거가 나머지 순서를 보존한다. 최상위만 클릭/Submit/Cancel을 받으며 아래 팝업·보드 스와이프·일반 HUD/아이템 호출은 0이다. 닫기 한 입력은 한 번만 처리한다(Task 2).
- [x] 7. 결과/로딩/전환 차단과 외부 정지를 팝업 요청과 독립 합성한다. 마지막 팝업 종료가 다른 차단/정지를 해제하지 않는다. 기존 오디오·연출 정지 흐름과 Time.timeScale을 보존한다(Task 2~3).
- [x] 8. 기존 재개/Retry/Next/설명 표시와 MemoryPack/Asset 안내·실패/취소·전환 잠금이 유지된다. 재시작/Next 성공은 새 논리 문맥, 실패/취소는 이전 문맥이며 연속 입력은 명령1·늦은 이전 명령0이다(Task 3).
- [x] 9. 실제 시험 씬 왕복에서 같은 문맥에 명시 복원하고 새 현재 Binding 수신1·이전 수신0을 확인한다. 복원 중 Retry/Next/보상/결과음0, 캡처/후보 실패·화면 종료 후 뷰/구독/요청 정리와 재시도 정책을 검증한다(Task 3).
- [x] 10. 지정 UI 프리팹의 디자인·기존 GUID를 보존하고 설명 분리/Host/Binding 연결만 적용한다. 두 기존 생성 도구를 임시 복사본에 재실행해 Next와 공통 연결이 보존된다(Task 2).
- [x] 11. 마지막 변경 후 도구/게임/1~2단계 및 관련 Stage13/UI/오디오/입력 검사에서 FAIL0·실제 exit0이다. 네 화면 크기·비영점 안전 영역의 새 캡처/포커스/raycast를 확인하고 물리 Android 미검증을 구분한다(Task 3).
- [x] 12. 독립 리뷰 관련 처리·조건별 검증 문서·사용 안내와 색인을 갱신한다. HEAD/diff/GUID/원본 보존 및 소유 자원 정리를 감사한다. 빌드/커밋/푸시 없이 3단계만 완료한다(Task 3).

## 증거와 제외

최종 검사 22회/2,781 PASS·FAIL0·실제 exit0와 수정 소스37 해시 불변을 확인했다. 독립 리뷰 중요 항목3개와 재판정한 진단 항목1개는 모두 실제 RED→GREEN 및 전체 회귀를 통과했다. 네 화면/안전 영역·원본1,825개·GUID·소유 자원 감사를 완료했다. 조건별 직접 증거는 [최종 검증](../../Verification/project-wide/popup-framework-stage-03.md)에 있다. 물리 Android는 미검증이다.

## 마무리 실행의 목표와 판정

마무리 실행 목표는 **3단계 최종 검수·완료 판정**이다. 계획의 마무리 작업 A(증거 대조/리뷰) → B(관련 검증/화면) → C(보존 감사/문서/판정)를 직접 순차 수행했다. 기존 활성 목표를 유지하며 새 4단계를 설정하지 않는다.

- [x] A. 현재 소스와 기존 증거를 대조하고 최종 독립 리뷰 및 관련 결함 처리를 기록한다.
- [x] B. 마지막 변경에 적용 가능한 FAIL0·실제 exit0와 네 화면/안전 영역 증거를 확정한다.
- [x] C. 원본/GUID/소유 자원 감사와 위 12개 조건별 증거를 모두 확정한다.

위 세 항목은 작업 순서이며 기존 12개 완료 조건을 대체하지 않는다. 과거 실패는 원장/리뷰 이력에 보존하며 현재 같은 게임 묶음9회는 모두 통과한다. 문서 정리만이 아니라 실제 실패 재현·수정·마지막 소스 검사·감사로 완료 판정했다.

게임 세션 영속화·디스크/앱 재실행 복원·새 왕복 게임 기능·구매/보상 기능·새 Addressables 정책/패키지/asmdef/DI/풀링·UI 디자인 재작업·게임 규칙/레벨/이미지 변경·사용자 Unity 종료/씬 자동 저장은 제외한다.
