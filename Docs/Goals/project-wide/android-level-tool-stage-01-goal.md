# Android 레벨툴 1단계 — 목표·완료 조건

상태: 구현·자동 검사 완료. 검증 근거와 미검증 범위는 진행 기록 참조.

[통합 가이드](../../Planning/project-wide/2026-10-11-android-level-tool-plan.md) · [상세 계획](../../Planning/project-wide/android-level-tool-stage-01-plan.md) · [목표 실행문](../../Commands/project-wide/android-level-tool-stage-01-command.md)

## 목표

기존 Android 게임과 별도의 레벨툴 제품을 구성하고, 같은 LevelTool 씬과 공통 편집 로직으로 앱 내부 JSON 프로젝트를 생성·저장·다시 여는 기반을 완성한다. 이번 단계 완료는 Android 모바일 UX나 실제 설치 완료를 뜻하지 않는다.

이번 문서 정리는 구현 재시작이 아니다. 아래 완료 표시는 기존 진행 기록의 판정을 유지한 것이며, 이번 요청에서 검사를 새로 통과했다는 뜻은 아니다. 재실행 시 현재 소스와 기록을 대조해 부족한 항목만 보완한다. 커밋·푸시는 금지하며 다른 단계의 변경 사항도 보존한다.

## 완료 조건

- [x] `Android Level Editor` 프로필이 Android 타깃·LevelTool 씬·`PRODUCT_LEVEL_EDITOR`·전용 앱 이름/식별자를 갖는다. 출력 경로만 설정하며 APK는 생성하지 않는다.
- [x] Android 레벨툴과 Windows 레벨툴은 같은 도구 심볼을 사용해도 정확히 선택된다. 기존 네 제품 선택·시작 씬·앱 설정을 보존한다.
- [x] 전역 PlayerSettings에 제품 심볼이나 레벨툴용 설정을 덮어쓰지 않는다. Windows 창 설정은 Windows 도구에만 적용한다.
- [x] 다섯 제품의 Addressables 출력·초기화/카탈로그·Library·content-state·보고서 경로가 제품/플랫폼별로 구분된다. 실제 번들은 생성하지 않는다.
- [x] 전용 Level Tool UI 그룹은 두 레벨툴에만 포함되며 세 게임에서는 제외된다. 제품 선택/재로드/감사 판정이 일치한다.
- [x] Android 내부 `LevelTool/Projects`에서 새 프로젝트·열기·저장·사본 저장이 가능하며 PC 드라이브나 외부 파일 경로를 요구하지 않는다.
- [x] 최초 기본 프로젝트를 생성하고 다음에는 동일 저장본을 연다. 기존/손상/부분 생성 데이터를 자동 덮어쓰지 않는다.
- [x] 기본 프로젝트 진입이 기존 세션·명시적 인계·미저장 복구 선택을 덮어쓰지 않는다. 컴포넌트 재활성화에서도 편집본·선택·Undo를 유지한다.
- [x] 프로젝트 이름 중복·상위 경로 이동·손상 JSON·쓰기 실패·작업 취소에서 원본/현재 세션이 보존된다.
- [x] 일반 블록·2×2 장애물의 공통 편집 후 JSON 저장→재열기에서 데이터·ID·참조가 유지되고, 같은 자료로 게임 시험 요청을 만들 수 있다.
- [x] Android 타깃 스크립트 컴파일과 Windows 기존 제품/명령 검사를 통과한다. Android 모듈이 없으면 이 조건을 미완료로 남기고 이유를 보고한다.
- [x] Android에서 Windows 네이티브 창 코드가 실행되지 않는다. Unity 에디터 창에도 영향을 주지 않는다.
- [x] 테스트는 외부 Tests에서 운영하며 검사 후 임시 연결과 변경한 프로필·콘텐츠 선택을 복원한다.
- [x] 변경·검증·미검증·제약을 진행 기록에 남기고, 2단계 계획·목표·복사용 실행문을 제공한다. 다음 단계는 자동 구현하지 않는다.
- [x] 커밋·푸시·Player/APK/Addressables 빌드·HTML 매뉴얼 갱신 없이 작업한다. 실제 구현·검증 완료 후에만 짧은 커밋 메시지를 코드 블록으로 제공한다.

## 후속 단계와 구분

반응형 화면은 2단계, 롱터치·터치 편집은 3단계, 외부 프로젝트 전송과 Android 중단/재개는 4단계, 고급 편집·실기기 제작 흐름 검수는 5단계다. 각 후속 항목을 이번 단계의 완료 근거로 주장하지 않는다.
