상태: 3단계 구현·자동 검증 완료. 아래 체크는 구현 및 Editor 자동 검사 범위다. 실제 Android 터치·OS 뒤로가기·dp·한글 IME는 미검증이며 Android 전체 출시 검수 완료를 뜻하지 않는다. [검증 근거](../../Verification/project-wide/android-level-tool-stage-03-progress.md).

## 목표

Android에서 일반/파워 블록·장애물·바닥·덮개를 터치로 선택·배치·교체·수정하고 Windows와 같은 공통 편집 명령·JSON·Undo를 사용한다. 롱터치와 이동·확대가 의도하지 않은 보드 편집을 발생시키지 않는다.

## 완료 조건

- [x] 터치 PointerDown에서 문서를 변경하지 않고 짧은 탭의 PointerUp에서 한 번만 확정한다.
- [x] 롱터치로 작업 메뉴를 열며 누르는 동안과 손을 뗄 때 배치하지 않는다. 0.6초 초기값과 배율을 반영한 이동 기준을 검증한다.
- [x] 이동·두 번째 손가락·팝업 전환·캡처 상실·회전·앱 중단에서 미확정 조작을 취소한다. 남은 손가락을 새 탭으로 처리하지 않는다.
- [x] 핀치·두 손가락 드래그·이동 도구·+/−가 문서·dirty·Undo를 변경하지 않으며 확대 후 보이는 칸과 편집 대상이 일치한다.
- [x] 영역 선택·추가 선택·명시적 교체를 키보드 Shift와 더블탭 없이 사용한다. 진행 중 선택의 시작/끝·취소 상태를 확인할 수 있다.
- [x] 2×2 장애물은 점유 칸과 범위 선택에서 하나의 개체로 처리하고 복사·삭제·붙여넣기도 전체 개체 단위로 수행한다.
- [x] 롱터치와 작업 버튼의 메뉴가 현재 층·선택·클립보드에 맞는 같은 명령을 제공하며 팝업 뒤의 보드로 입력이 관통하지 않는다.
- [x] 일반/파워 블록·장애물·바닥·덮개의 편집과 복사·잘라내기·붙여넣기·삭제를 공통 명령으로 제공한다. Windows 씬/관련 EditorWindow 메뉴도 같은 편집 의미를 사용한다.
- [x] 잘못된 경계·충돌·참조 및 잘라내기 자료 확보 실패에서 원본을 보존한다. 붙여넣기는 전체 검증 후 확정하며 개체 ID·정의 참조 계약을 지킨다.
- [x] 확정 편집 하나가 하나의 Undo로 되돌아가고 취소/미리보기는 Undo를 추가하지 않는다. Undo/Redo에서 문서·참조가 유지된다.
- [x] 같은 초기 JSON·선택·명령의 터치/Windows 결과를 비교하고 편집→Undo/Redo→내부 저장→재열기를 검사한다. JSON 스키마·Windows 기존 조작·16:10 화면을 보존한다.
- [x] 2단계 반응형 패널·팝업·회전에서 확정 선택·도구·세션·Undo 유지 검사를 통과한다.
- [x] 입력 판정 검사와 실제 UI 콜백·메뉴 연결 검사를 모두 수행하고 실제 Android 터치·OS 뒤로가기의 미검증은 따로 기록한다.
- [x] 가능한 환경의 Android 타깃 컴파일을 확인한다. 모듈 부재·실패는 미완료로 기록하고 설치·APK/번들 빌드를 하지 않는다.
- [x] Unity 작업을 순차 실행하고 임시 테스트 연결·프로필·콘텐츠 선택을 복원한다. 변경·검증·미검증·제약을 진행 기록에 남긴다.
- [x] 커밋·푸시·Player/APK/Addressables 빌드·HTML 매뉴얼 갱신 없이 작업하며 질문은 제한시간 없는 일반 채팅으로 진행한다.
- [x] 완료 후 4단계 계획·목표·복사용 실행문을 제공하고 자동 구현하지 않는다.

## 후속 범위

외부 파일·프로젝트 ZIP·최근 프로젝트·중단 복구는 4단계, 정밀 연결점·튜토리얼 대상 지정·시험 흐름과 최종 실기기 검수는 5단계다. 이번 단계의 진행 중 조작 취소를 앱 전체 복구 완료로 표현하지 않는다.
