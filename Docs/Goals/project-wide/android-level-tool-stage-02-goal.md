# Android 레벨툴 2단계 — 목표·완료 조건

상태: 구현·자동 검사 완료. 실제 Android dp·키보드/한글 IME 검증 대기이며 전체 목표는 미완료다.

[통합 가이드](../../Planning/project-wide/2026-10-11-android-level-tool-plan.md) · [상세 계획](../../Planning/project-wide/android-level-tool-stage-02-plan.md) · [목표 실행문](../../Commands/project-wide/android-level-tool-stage-02-command.md)

## 목표

Android 레벨툴의 같은 씬·문서·편집 세션을 유지하면서 휴대폰과 태블릿의 실제 사용 가능한 폭에 맞는 화면을 제공한다. 가로/세로·Safe Area·키보드에 대응하고 회전·재배치로 작업 내용과 입력 상태를 잃지 않는다.

## 완료 조건

- [x] 장치 이름 대신 Safe Area와 모바일 UI 배율을 반영한 사용 가능한 폭으로 배치를 선택한다. 경계 양쪽과 분할 화면에 준하는 폭 변경을 검사한다.
- [x] 넓은 화면에서는 보드와 양쪽 패널, 좁은 세로에서는 하단 패널, 좁은 가로에서는 옆쪽 패널을 사용할 수 있다. 좁은 화면의 기본 패널은 한 개씩 표시한다.
- [x] 레벨/소재/속성/더보기 진입과 저장·Undo/Redo·게임 시험, 현재 층/도구 상태를 좁은 화면에서도 사용할 수 있다.
- [x] 회전·패널 전환·재배치가 문서·dirty·세션·Undo/Redo·선택 칸·편집 층·도구를 보존한다. UI 전환만으로 편집 명령을 만들지 않는다.
- [x] 열린 패널·팝업의 의미와 미확정 필드 문자열·포커스·커서/텍스트 선택을 회전과 재배치에서 유지한다.
- [x] Safe Area 안에 주요 명령과 팝업을 표시하고 중복 여백을 적용하지 않는다. 작은 화면과 낮은 높이에서도 필수 확인/취소에 접근한다.
- [ ] 자주 쓰는 버튼은 약 48dp에 준하는 누름 영역을 목표로 배율과 함께 확인한다. UI 단위나 화면 픽셀만으로 실제 dp 검증 완료를 주장하지 않는다.
- [ ] 키보드 표시 중 입력 필드·확인/취소에 접근하며 입력 내용을 잃지 않는다. 실제 Android 키보드와 한국어 IME 검증은 별도 항목으로 기록하고, 미검증이면 완료 표시하지 않는다.
- [x] 짧은 상태 안내와 도움말로 현재 지원하는 조작을 설명한다. 미구현 롱터치·핀치나 Windows 전용 창 기능을 Android 지원 기능으로 안내하지 않는다.
- [x] 고급 화면의 기본 진입·스크롤·닫기 접근을 확인한다. 고급 연결점·대상 지정·시험 화면 전체의 모바일 완성은 5단계로 남긴다.
- [x] 실제 UI 화면의 대표 폭/방향 검사와 편집→회전→Undo/Redo→저장→재열기 검사를 통과한다. 순수 배치 계산 검사만으로 상태 보존 완료를 주장하지 않는다.
- [x] Windows 기존 데스크톱 UI·16:10 창 정책과 관련 명령·제품/저장 동작의 회귀 검사를 통과한다. Android에 Windows 최소 창 크기/비율을 적용하지 않는다.
- [x] 가능한 환경에서 Android 타깃 스크립트 컴파일을 검사한다. 모듈 부재·컴파일 실패는 해당 조건의 미완료로 기록한다.
- [x] 외부 Tests 검사와 Unity 작업을 순차 실행하고 임시 연결·활성 프로필·콘텐츠 선택을 복원한다.
- [x] 진행 기록에서 구현·통과 검사·실기기 미검증·제약을 구분한다. 완료 후 3단계 계획·목표·복사용 실행문을 작성하고 자동 구현하지 않는다.
- [x] 커밋·푸시·Player/APK/Addressables 빌드·HTML 매뉴얼 갱신은 별도 새 요청 없이 하지 않는다. 질문은 제한시간 없는 일반 채팅으로 진행한다.

## 후속 단계와 구분

터치 제스처·롱터치·보드 작업 메뉴는 3단계, 외부 파일 선택기·프로젝트 전송·중단 복구는 4단계, 고급 편집과 전체 실기기 제작 흐름은 5단계다. 빌드 허가 없이 가능한 Editor/자동 검사와 실제 Android OS 검증의 완료 범위를 구분한다.
