# 레벨툴 UI 개선 1단계 — 목표·완료 조건

> 2026-10-09 · 구현·Unity 검증 완료. 물리 IME·호스트 키·독립 OS 창은 아래 미검증 범위를 확인한다.

**목표:** 실제 레벨툴 씬에서 목업 형태의 화면과 공통 메뉴·단축키·도움말을 사용하고, 기존 제작/시험/자료 보호 기능을 유지한다.

## 완료 조건

- [x] G1. 기존 모든 제작/시험/기록/복구 기능과 새 화면 위치의 대응표가 있으며 누락 없이 접근 가능하다.
- [x] G2. LevelTool 씬에 상단 메뉴·작업 탭, 좌측 레벨/소재, 중앙 보드, 우측 속성, 하단 검사/상태 구조가 실제로 동작한다. HTML 목업을 제품처럼 표시하지 않는다.
- [x] G3. 레벨·작업 폴더·미저장·복구·공유 사본 상태와 저장/Undo/Redo/게임 시험의 실제 가용성이 표시된다.
- [x] G4. 1366×768·1920×1080·1280×800에서 기본/검사 펼침/모달 화면이 사용 가능하고, 1024×768에서도 패널 접기/스크롤로 필수 기능에 도달한다. 보기 상태 변경은 문서 dirty/Undo를 만들지 않는다.
- [x] G5. 메뉴·버튼·1단계 단축키가 같은 명령/가용성/설명을 사용하며 도움말에서 한국어 검색과 적용 범위를 확인할 수 있다.
- [x] G6. Ctrl+O/S/Shift+S/Z/Y/Shift+Z, F1/F5, Esc, 보드 포커스 Shift+Space가 명시된 문맥에서 한 번씩 동작한다. Unity 호스트 제한은 실제 근거와 메뉴 대안으로 구분한다.
- [x] G7. 텍스트·숫자·IME 입력, 기본 텍스트 복사/붙여넣기/Undo, Tab 이동이 보존된다. 지연 입력 후 저장은 마지막 값이 반영되고 잘못된 값/조합 중에는 손실 없이 보류된다.
- [x] G8. 최상위 모달/메뉴·튜토리얼 대상 지정·공유 사본·busy·시험 중 입력 우선순위와 제한이 유지된다. 닫기/취소·반복 키·재활성화가 중복 편집/저장/시험을 일으키지 않는다.
- [x] G9. Windows Level Editor 프로필만 크기 조절 가능한 창 모드와 기본 1280×800으로 설정된다. 다른 프로필·전역 설정·GUID는 보존되며 실제 OS 실행 미검증을 명시한다.
- [x] G10. 기존 기능 및 실제 게임 시험 왕복에서 원본·미저장·선택·이력·입력 포커스·스크롤 보호를 검증하고, 저장 오류/취소/충돌 시 잘못된 성공 표시가 없다.
- [x] G11. 검사 로그·스크린샷·UX 개선점·남은 제한을 기록하고 테스트 연결을 해제했다. 커밋·푸시·빌드·HTML 변경을 하지 않았다.
- [x] G12. 완료 보고와 2단계 계획·목표·복사용 실행문을 작성했다. 커밋 메시지는 실제 구현/검증 완료 후에만 제공하고 다음 단계 구현은 자동 시작하지 않았다.

## 후속 범위 구분

완료 근거는 [검증 기록](../../Verification/project-wide/level-tool-ui-stage-01-progress.md)에 있다. G6/G7의 입력 검증은 Unity Play Mode 이벤트와 실제 텍스트 편집 컨트롤 기준이다. 물리 한국어 IME 조합, Unity 호스트의 키 선점, 독립 Windows 창 조절은 실기 확인이 남아 있으며 통과로 주장하지 않는다. 보드 클립보드는 다음 단계다.

보드 요소 복사/잘라내기/붙여넣기와 확대/팬 키는 2단계다. 1단계에서는 입력 필드의 기본 텍스트 클립보드 동작을 유지하며, 아직 없는 보드 명령이 된다고 표시하지 않는다. 튜토리얼 상세 UX는 3단계, 시험/기록 마감·독립 도구 F11은 4단계다. 기존 기능을 없애도 된다는 뜻이 아니다.

실제 Windows Player의 창 조절·최대화·OS 스냅과 배포 실행은 빌드 승인 후의 검증이다. 설정/Editor UI 검사만으로 해당 동작까지 통과했다고 보고하지 않는다.

목표 실행 요청에 따라 1단계를 완료했다. 필요한 하위 에이전트 사용 가능. 질문은 제한시간 없는 일반 채팅으로 한다. 근거가 없는 체크박스를 완료로 표시하지 않는다.
