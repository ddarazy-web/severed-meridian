## 측정 환경과 해석

Unity 6000.3.10f1, Windows 11, RTX 3060 Ti. 배치 Editor 640×480, 별도 GUI Editor 2340×1080. Editor·UI·검사 코드 비용을 포함한다. 기기 RSS·제품 메모리·Android 실행 속도가 아니다.

3단계는 신규 병목을 확정하지 못했으며 성능 개선율을 주장하지 않는다. 기준/최종 파일은 측정 보완 전후 기록이다. 실제 동시 로딩 개선은 2단계 보고서를 참고한다.

- 게임 round0은 새 Play의 첫 진입, round1~3은 같은 레벨 반복, 이후 1/2/15 순환.
- `firstGameCameraMs=-1`은 배치 Editor에서 렌더 경계를 관찰하지 못했다는 의미다. 0ms가 아니다.
- 스레드 할당 카운터는 미지원으로 -1. 프레임 GC는 계측과 UI 비용을 포함하므로 순수 목록 할당으로 해석하지 않는다.
- 메모리 피크는 Editor 업데이트별 샘플이며 프레임 사이 순간 피크나 강제 GC 후 생존 객체량이 아니다.

## 최종 기능·자원 검사 요약

아래 항목은 당시 검사 결과를 요약한 것이다. 일회성 PASS 로그·경계/정적 감사 원본은 이번 정리에서 제거했다.

- 15/1천/1만 목록의 셀 수 상한·인스턴스 재사용·마지막 항목 선택 통과. 선택 전 로비 읽기는 세대/인덱스만 확인.
- 메모리 fixture 1→2→51→1에서 같은 구간 재사용·구간 교체·퇴출 구간 재읽기 확인. 공통/세대는 한 번 읽고 Dispose 후 팩 참조 해제.
- 대표 장애물·고정/랜덤/유지 공급·미션의 자원 계획과 실제 Sprite 준비 일치. 무관한 곰팡이/거미줄/생성기 주소 제외, 재준비 추가 주소 0, Dispose 핸들 반환.
- 실제 게임 팩 실패→재선택, 진입 취소, 재시작, 다음 전환 취소→정상 다음, 최종 복귀 통과. 다음 전환의 승리 조건만 메모리 fixture로 구성함.
- 실패/취소/복귀 후 세션·작업 캐시 0. 재시작·다음 전환 중 세션 1·캐시 9, 이전 artwork AtlasCount 0. 취소된 다음 전환은 현재 레벨/아틀라스 보존.
- 별도 경계 검사 네이티브 메모리: 재시작 290,893,679→290,893,398B, 다음 290,893,398→290,915,849B. 아틀라스 전체 조사 포함이므로 정상 왕복과 직접 비교하지 않음.
- 정적 의존성 감사: 로비 폰트 원본 2,447,400B, 게임 폰트 원본 6,220,984B. 해당 의존성 폐쇄에 게임 팩·아틀라스·음원 파일 없음. 제품 압축 크기나 FontEngine 사용량이 아님.
- 아틀라스 별도 조사: 9개 주소·89개 Sprite, Editor RGBA32 텍스처 보고값 합계 약 104MiB. Blocks/폭탄/드론/자석/파워생성/로켓 약 8MiB씩, 바닥/매칭/파워블록 약 16MiB씩. Android 텍스처·VRAM·번들 크기 아님. 조회용 Sprite는 제거함.
- 최종 정상 왕복 실행 `211624-145` exit 0. 최종 감사 시 검사 runner 종료·사본 Detach, 사용자 작업 보존 확인. 실행 전체의 원본 데이터 전후 해시가 없어 미추적 파일 전체 불변성을 새로 인증하지 않음.
- 런타임 변경은 로비 복원/읽기 해제 시간 계측뿐이며 폰트·팩·아틀라스 정책을 바꾸지 않음.

## 미검증과 후속 판단

제품 빌드·Android 실기기 검사는 당시 미승인·미실행. 실제 프로세스 시작/첫 화면, 기기 RSS·압축 자원, 세로/가로·뒤로가기·백그라운드 복귀·로딩 중 입력은 별도 검증 대상이다. Editor GUI의 높은 FontEngine 수치나 렌더 예외치를 Android 병목으로 단정하지 않는다.

당시 변경 소스의 diff 검사는 통과했지만 기존 씬/프리팹 YAML까지 전체 clean인 것은 아니다. 커밋·푸시·HTML 갱신과 제품 빌드를 하지 않았다.
