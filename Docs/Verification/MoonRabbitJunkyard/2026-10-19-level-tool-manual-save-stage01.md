## 조사 결과

- 자동 기록은 Update만이 아니라 Focus/Pause/파일 전송/Storage/Leave/OnDisable에 연결돼 있다. 기록 호출과 불필요한 전체 이력 Export를 함께 제거해야 한다.
- 현재 명령은 이탈 메뉴보다 먼저 CommitCommandInput을 실행한다. 잘못된 숫자가 있을 때 버리기까지 막히지 않도록 선택 후 저장하는 경우에만 입력 검증을 수행할 경계가 필요하다.
- 기존 Session.IsDirty만으로는 미확정 문자열과 공유 튜토리얼 사본을 감지하지 못한다. UI 입력 상태와 문서 dirty를 함께 판단하되 전체 이력 직렬화로 판정하지 않는다.
- 과거 v1 파일과 ToolDraftStore 검증 경계는 보존한다. 새 실행에서 자동 읽기/쓰기하지 않고 사용자가 선택한 경우에만 읽는다.

## 검증 범위의 한계

- 실제 Android 기기, 배포 실행 파일, 물리 키보드의 한글 IME 조합 상태는 검사하지 않았다. 한글 원문·미확정 필드·키 이벤트는 Unity Play Mode에서 검사했다.
- 반복 성능 수치와 모바일/Windows 전체 화면 UX 표본은 후속 2·3단계 범위다. 모든 UI 지연이 해결되었다거나 특정 ms 목표를 달성했다고 주장하지 않는다.
- 강제 종료 시 미저장 작업 유실은 수동 저장 정책의 의도된 제한이다. 자동 저장/복구를 우회적으로 추가하지 않았다.
- 제품 빌드·커밋·푸시·HTML 갱신·프리팹/씬 원본 편집·하위 에이전트 실행은 하지 않았다.
