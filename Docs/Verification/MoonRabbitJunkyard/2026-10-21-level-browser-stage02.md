# 레벨 탐색 2단계 진행·측정 기록

상태: **2단계 완료 (2026-10-21)**. 사용자 승인한 목록 전용 읽기·선택 지연 읽기·참조형 복구 v2와 남은 렌더 UI 검사를 완료했다. 아래는 시간순 진단 이력이므로 중간의 대기·미완료 문구를 현재 상태로 해석하지 않는다. 최종 범위와 한계는 문서 끝의 완료 감사를 따른다.

## 기준과 제약

- 기준 커밋 `e0e147b`(1단계 완료), 시작 시 작업 트리는 깨끗했다. 사용자가 만든 커밋을 기준으로 삼으며 이번 작업은 커밋·푸시하지 않는다.
- 제품 빌드·HTML 매뉴얼 갱신 금지. 실제 제작 데이터는 읽기만 한다.
- 측정 원본은 `ProjectSettings/AuthoringSource.json`이 가리키는 채택된 JSON 프로젝트다. 37개 멤버 문서 약 4.4MB. 원본 해시와 문서 구성은 각 결과에 기록한다.
- `LevelBrowserDocumentPerformanceVerification`은 별도 GUID 폴더에 실제 레벨 구성을 반복한 검사본을 만든다. 메타데이터만 검사하는 1단계와 다르다.

- 먼저 Run100으로 측정 도구의 안전성을 확인한다. **100개 검사는 요청한 1천/1만 검사를 대체하지 않는다.** 현재 실행 `125704-299`, 도구 세션42365.
- GC 할당 카운터가 동작하지 않는 런타임은 allocatedBytes를 null로 남긴다. 0으로 보고하지 않는다. managed heap과 working set도 함께 기록한다.

### 화면·검색 메타데이터 경계 중간 결과

- 이전 목표 턴은 소스 변경과 통과 검증이 있는 진행이었다. 이번에는 남아 있던 전체 화면 본문 준비 경로를 변경했다.
- `ContentDocumentInfo`는 번호·이름·ID·종류만 제공한다. 디스크 본문 핸들은 수집 시 얻은 정보를 유지하므로 목록 준비를 위해 본문을 다시 읽지 않는다. 메모리 편집 문서는 현재 게시 버전의 값을 제공한다.
- 편집 세션의 불변 문서 사전마다 `ContentVersion`을 부여한다. 보드 선택·줌처럼 문서가 바뀌지 않은 갱신은 전체 ID 순회·정렬을 하지 않는다. Undo로 기존 상태로 돌아가면 동일 버전을 다시 사용한다.
- 화면 캐시에는 선택 레벨 본문 하나와 공유 문서만 보관한다. 검색 인덱스에는 모든 레벨의 메타데이터가 들어간다. 새 레벨 번호, 여러 레벨 시험 목록, 모양 목록, 요소 정의 조회에서도 불필요한 전체 본문 복사를 제거했다.
