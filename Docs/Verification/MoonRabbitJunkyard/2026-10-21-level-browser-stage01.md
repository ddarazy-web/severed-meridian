### 성능 범위

- Windows, Unity 6000.3.10f1, 현재 PC에서 측정했다. 워밍업을 제외한 정상 3회 기록을 보존했다.
- 1만 건 **목록 메타데이터** 검색 중앙값 0.068/0.065/0.228ms, p95 4.959/4.836/6.205ms, 최댓값 6.751/6.740/9.830ms. 목표 중앙값 200ms 이내 충족. 검색 입력 debounce 180ms는 별도다.
- 1천 건 중앙값 0.099/0.398/0.060ms. 데이터 변경 없는 검색에서 정렬 재구성은 없다.
- 데스크톱 1280×800/1920×1080의 생성 행은 7개/6개로 40개 이하. 1만 번째 항목도 같은 행을 재사용한다.
- 두 실제 문서의 열기 요청은 중앙값 49.863/48.283/52.389ms. 최근 기록 쓰기·동기 화면 갱신 호출을 포함하며 다음 프레임 렌더링 완료 시간은 제외한다.
- 전체 1만 문서 프로젝트 열기·전환·메모리 성능은 2단계에서 측정한다. 이번 메타데이터 검사로 이를 입증했다고 판단하지 않는다.

### 구조와 안전 경계

`LevelBrowserIndex`가 목록 정보와 검색을 담당하고, 화면은 가상 행만 바인딩한다. 기존 레벨을 여는 진입점은 `RequestOpenLevel`로 모아 저장/취소/부분 취소 규칙을 공유한다. `RecentLevelStore`는 사용자 도구 설정 영역에만 기록하며 콘텐츠·ZIP 저장소에 문서를 추가하지 않는다.

부분 취소는 현재 레벨의 저장 후 변경만 제거한다. 저장 이전의 공유 생성·연결 같은 원자적 Undo는 보존한다. 복구 형식의 선택 필드 `beforeSave`로 이 경계를 유지한다. 기존 기록에서 필드가 없으면 기존 형식으로 읽으며, 참조가 깨지는 부분 취소는 기존 상태를 변경하기 전에 거부한다.

### 화면·제한

휴대폰에서 패널 높이가 0인 가상 목록을 발견하여 모바일 바깥 스크롤의 높이를 제한하고, 하단 탐색과 중복된 탭을 숨겼다. 최근 목록/현재 찾기를 한 줄로 배치했다. 360×780과 800×1280에서 검증했다. 실제 Android OS 입력·IME·물리 기기 검증은 수행하지 않았다.

기존 모바일 검사 스크립트의 일부 캡처는 변경 전에도 흰 영역을 출력한다. 이를 정상 시각 확인의 증거로 사용하지 않았다. 복제한 PanelSettings로 촬영한 이번 전용 검사 캡처에서는 새 목록의 글자·버튼·보드 표시를 직접 확인했다.
