## 구현과 사용

`Match → 플레이 테스트 → 기본 봇 시험 → 새 봇 시험`을 누른다. 준비가 끝나면 `한 수 진행` 또는 `한 판 실행`을 사용한다. `중지`는 현재 행동의 낙하·연쇄를 끝내고 멈춘다. `수동 시험 새로`는 봇 세션을 폐기하고 기존 수동 시험을 준비한다.

봇은 일반 교환·파워 교환·조합·제자리 발동 중 공개된 유효 후보를 선택한다. 실제 처리는 수동 플레이와 같은 `BoardActionExecutor`가 담당한다. 봇 시험에서는 아이템·부스터를 사용하지 않는다. 실행 이유와 진행 횟수, 성공·이동 소진·막힘·오류·사용자 중지를 화면에서 구분한다.

스크립트는 `Assets/Scripts/Features/AutoPlay/` 내부의 다음 책임으로 나뉜다.

| 위치 | 책임 |
|---|---|
| Runtime/Observation | 원본과 참조를 공유하지 않는 공개 값 계약 |
| Runtime/Strategy | 공개 정보의 미션 기여·파워·범위 평가와 결정적 동점 처리 |
| Runtime/Execution | 공개 값 변환, 한 판의 실행기 소유, 명령 재검증, 안정 경계와 진단 기록 |
| Editor/Presentation | 기존 Match 패널의 버튼·표시·갱신 및 정리 |
| Editor/Tests | 경계·전략·실행·UI·재로드·통합 검증 |

흐름은 `공통 실행 상태 → 공개 값 복사 → 전략 선택 → 실행 세션 검증 → 공통 실행기 → 화면`이다. 실행 기록과 시드는 전략으로 되돌리지 않는다. 새 패키지·asmdef·별도 게임 엔진은 추가하지 않았다.

## 검증 중 수정과 보존

- 라스트팡 처리 오류가 성공 Outcome에 가려지는 문제를 세션에서 수정했다. 공통 게임 규칙이나 성공 기록은 바꾸지 않았다. 실제 실행기의 처리 한도를 주입한 실패 재현과 수정 후 검사, 실제 UI 오류 표시를 확인했다.
- 수동 UI의 과거 680×480 스크롤 검사에서는 현재 탭 최소 크기로 인해 보드가 전부 보여 스크롤이 처음부터 0이었다. 오류 메시지에서 전후 `(0,0)`을 확인했다. 검사 소유 보드 뷰 높이를 제한해 실제 넘침을 만든 뒤 탭 왕복 보존을 검사하고 높이 제한을 복원했다. 제품 창 크기 정책은 바꾸지 않았다.
- 새 봇 시험은 무작위 시드이므로 특정 정상 종료 상태를 매번 보장하지 않는다. 실제 새 시험 버튼의 준비/새 시드는 따로 검사하고, 행동/종료 UI 사례에는 독립 재현의 시드 771 세션을 검사 코드에서만 주입했다. 제품에 테스트 분기나 시드 옵션을 추가하지 않았다. 재배치 한도 오류는 별도 세션 검사에서 같은 수동 명령열과 비교한다.
- 기존 파일 변경 6개는 `LevelEditorHelp.cs`, `LevelInitialStatePanel.cs`, `.Manual.cs`, `.Query.cs`, `LevelInitialState.uss`, `ManualPlayIntegrationVerification.cs`다. 기준의 나머지 499개는 동일하다. 기존 레벨·등록 맵·GUID/meta·ProjectSettings·패키지 파일은 변경하지 않았다. 새 AutoPlay 스크립트와 Unity 생성 meta는 함께 보관한다.
- 사용자의 `.codex/AGENTS.md` 변경, 삭제 예정 스킬, 기존 문서/등록 맵 작업은 되돌리지 않았다. 플랫폼 설정이나 SDK 변경은 없다.

## 평가 범위와 남는 한계

기본 전략은 완료량 8점·내구도/충전 진행 1점을 우선 비교하고 파워·직접 범위·고정 좌표 순서를 사용한다. 드론 도착·자석 무작위 색/방향·새 공급·추가 연쇄를 미리 실행하지 않는다. 겹친 매칭의 동률 공통 칸만 계산하므로 독립 매칭의 추가 기여는 과소평가할 수 있다.

회수의 경우 공개 도착 칸으로 직접 교환하는 기여를 평가한다. 아래 칸 제거만으로 회수가 된다고 가정하지 않는다. 레벨마다 중력/직접 경로를 지정할 수 있고 그 제작 설정은 공개 관찰에 없기 때문이다. 이는 계획서의 “관찰로 판단할 수 없는 항목은 보수적으로 평가” 기준을 적용한 범위이며, 회수 낙하 자체는 공통 실행기로 검증했다. 여러 수의 경로 탐색이나 성공률 최적화는 수행하지 않는다.

정보 경계는 같은 프로세스 안의 구조적 분리이며 악성 코드의 리플렉션까지 막는 보안 샌드박스가 아니다. 재현은 검증한 Unity/런타임 버전의 같은 입력 조건에 대한 증거다. 모든 가능한 레벨·시드·장애물 조합의 성공이나 동일한 인간 체감 난이도를 보장하지 않는다.

HTML 설명서는 기존 스타일을 사용하며 상대 링크·앵커·이미지 경로를 검사했다. 이번 작업에서 HTML 브라우저 렌더링은 확인하지 않았다. Unity 화면 캡처와 실제 UI 검증은 수행했다.

**26~30단계의 계획 전략·반복 실행·집계 통계·난이도 추천·전체 통합 검수는 이번 완료 범위가 아니다.**
