## 최신 사용자 변경 — 개발 중 전체 실행 중단

사용자가 “개발중에는 20000판 모두 검사하지마. 오류가 있는지 정도만 진행하고, 실제 검증시에 그렇게 돌려”라고 지시했다. 이를 반영하여 87·88번 문서의 T1~T8과 16개 완료 조건 중 전체 실측 요구를 개발 오류 검사와 후속 실제 검증으로 분리했다. 제품의 1~100회·각 전략 100판 기능은 축소하지 않는다.

전용 Unity PID 42956에 정상 창 종료를 요청했으나 MainWindow 종료 요청이 불가능했다(`CloseMainWindow=False`). 실행 명령이 `Stage31BalanceVerification.Full`인 소유 프로세스임을 다시 확인하고 해당 프로세스만 종료했다. 다른 Unity는 종료하지 않았다. 메모리·감사 관찰 프로세스도 대상 종료 후 종료된 것을 확인했다. `terminal.txt`의 정상 완료가 없으며 사용자 요청에 따른 중단이다. 이를 실행 오류 해결이나 전체 성공으로 해석하지 않는다.

중단 후 독립 감사에서 **13개 완료 구간·2,600판**이 통과했다. 진행 중인 14회 구간은 미완료이며 추천 표본으로 합치지 않는다. 전체 시험을 다시 시작하지 않고 해당 기록으로 조회·저장 오류·추천 검사를 수행한다. 준비했던 추가 400판 수명주기 검사도 실행 전에 기존 완료 구간 재사용과 작은 실행 제어 검사로 줄인다. 준비 코드의 컴파일 통과는 그대로 이력에 남기되 아직 실행한 검사로 세지 않는다.

## T4 독립 대조

`Logs/Stage31Workflow/Audit-Records.ps1`은 원시 JSON을 PowerShell로 읽는다. 제품의 집계 함수를 호출하지 않고 판 파일 200개, 시드·전략·순번·종료 종류·이동 횟수 합계·정의의 이동 수 외 불변, 성공 수·네 등급을 대조한다. `-Partial`은 완료된 횟수만 확인하며 전체 완료로 표시하지 않는다. 첫 부분 감사에서 1개 횟수 200판을 확인했다.

감사 범위를 보강하여 대표 JSON과 요약 정의의 동일성, SHA-256 지문, 시작 시점의 시드·버전 불변, 각 횟수 묶음의 실행 버전과 지문도 확인한다. UI 범위 계산기를 호출하지 않고 별도 PowerShell 계산으로 연속 실측 범위를 만들어 `partial-ranges.json` 또는 `full-ranges.json`에 남긴다. 보강한 검사에서 완료된 6개 횟수 1,200판이 통과했고 중간 실측 범위는 쉬움 2~6회·어려움 1회였다. 다른 등급의 부재는 아직 전체 시험의 ‘추천 없음’으로 판정하지 않는다.

전체 종료 후 `-Partial` 없이 실행하여 100개 횟수·20,000판과 완료 상태를 확인해야 한다. 이전 부분 감사는 전체 검증으로 대체되지 않는다.

`Watch-Audit.ps1` 관찰 프로세스도 시작했다(`audit-process.txt`). Unity PID 42956이 실제로 살아 있는 동안 완료 횟수 10개 단위로 부분 감사를 수행하고, `terminal.txt`의 `completed`를 확인하면 전체 감사를 수행한다. 결과는 `audit-watch.txt`와 독립 집계 JSON/CSV에 남긴다. 파일 오류나 종료 기록 누락을 별도로 남기며, 게임 프로세스를 중지·재시작하거나 Assets를 수정하지 않는다. 관찰 스크립트 시작 자체는 전체 감사 통과 증거가 아니다.

T5 저장 오류 검사 코드는 `Logs/Stage31Workflow/Stage31StorageVerification.cs`에 준비했다. 실제 완료된 첫 200판만 새 검사 디렉터리로 복사하고 요약/정의/성공 수/등급 변경, 판·묶음 누락과 손상을 주입할 예정이다. 아직 Assets에 넣거나 컴파일·실행하지 않았으므로 통과 증거가 아니다. 전체 시험 중 재컴파일을 피하기 위한 준비 파일이다.

후속 준비에서 전용 사본의 파일 독점 잠금을 이용한 저장 실패 검사도 추가했다. 확정 요약의 기존 바이트 보존, 실제 세션 제어 저장 실패 시 오류 상태와 실행 중지 여부를 확인할 코드이며 역시 실행 전이다. OS 권한이나 사용자 파일의 속성은 변경하지 않는다.

`Stage31LifecycleVerification.cs`도 Assets 밖에 준비했다. 전체 시험 후 실제 UI에서 별도 200판씩 두 번 진행하여 창 닫기·다시 열기, 실제 도메인 재로드, 별도 Editor 프로세스 재시작을 확인하도록 작성했다. 검사 중 최근 결과 포인터는 저장·복원하고 사용자 레벨이 아닌 기존 검사 소유 대표 에셋을 사용한다. 코드 준비만 완료했으며 컴파일·실행·통과 증거는 아직 없다. 예정된 별도 400판은 전체 시험 20,000판에 포함하지 않는다.

이후 두 준비 검사 파일의 **별도 컴파일**을 확인했다. 기존 Unity Editor 어셈블리의 rsp 입력을 복사하고 DLL·참조 DLL 출력만 `Logs/Stage31Workflow/staged-compile`로 변경하여 Unity 제공 Roslyn으로 컴파일했다. 종료 코드 0, 진단 출력 없음(`exit-code.txt`, `results.txt`, `staged.rsp`). Assets·Library의 컴파일 산출물은 바꾸지 않아 실행 중 Unity 재로드를 유발하지 않았다. 이는 준비 코드의 컴파일 증거이며, 오류 주입·창 종료·재로드·재시작 검사의 실제 실행 통과나 최종 Unity 컴파일을 뜻하지 않는다.

T6의 `Stage31ApplyVerification.cs`를 추가 준비하고 같은 별도 컴파일에서 종료 코드 0을 확인했다(`apply-compile.txt`, `apply-exit-code.txt`). 실제 전체 완료 기록에서 추천값을 고르고 검사 소유 에셋의 실제 이동 수 입력·Ctrl+S·디스크 독립 재조회·창 재열기를 확인하도록 작성했다. 등록 모양의 사용 파일 목록도 대조한다. 100개 메모리 사본은 저장 파일 집계 경계 검사이며 자동 플레이 판 수가 아니다. 기존 등록 모양과 일치하면 재사용하고 이번 검사에서 새로 등록한 모양만 정리한다. 이 검사 역시 실제 실행 전이다.

`Check-Manual.ps1`로 변경된 난이도 HTML의 링크·이미지·문단 연결 22개를 정적 검사하여 실패 0개를 확인했다. 근거는 `manual-links.json`이다. 이는 브라우저 렌더링·배치 검증과 구분하며, 최종 안내 수정이 있으면 변경된 경로를 다시 확인한다.

공통 실행기·흐름·봇 런타임의 시작 시점 대비 해시 대조는 `runtime-preservation.json`에 기록했다. 봇 실행은 `Observe()`가 만든 공개 관찰 값을 기본/계획 전략에 전달하며, 밸런스 분석은 별도 요약을 읽는다. 이 코드 대조는 선행 관찰 경계 검사를 새로 실행했다는 뜻이 아니다.

## 남은 감사

### 소규모 저장 오류 재현과 수정

전체 실행 중단 후 `Stage31StorageVerification`을 실제 Unity batchmode에서 실행했다. 새 자동 플레이 없이 보존된 첫 완료 구간 200판의 사본만 사용했다. 최초 검사에서 예외 포착에 `InvalidDataException`이 빠져 조기 종료한 이력은 `storage-baseline-first.txt`에 보존했다. 검사 코드만 보완한 재실행은 `storage-baseline-results.txt`에 9 PASS / 7 FAIL을 남겼다. 제품 실패는 대표 정의·지문 불일치, 성공 수 변조, 등급 변조, 원시 판 누락·손상, 묶음 요약 누락, 존재하지 않는 묶음 ID를 정상 결과로 수락한 7개 사례다.

`BotMoveBalanceStore`의 요약 검사를 보강하고 `BotMoveBalanceReader`에서 기존 `BotAnalysisReader`로 원시 판·시드·버전·정의·성공 수·등급을 대조하도록 수정했다. 조회 중 원본 기록은 변경하지 않는다. `BotMoveBalancePanel`은 UI 갱신 사이에 나누어 읽고 확인 중·실패 상태에서 추천을 표시하지 않는다. 화면 생성자에서 많은 파일을 한 번에 읽지 않도록 동기 검사용 Load와 화면용 OpenReader를 구분했다.

같은 실제 사본과 오류 주입 사례로 `storage-fixed-unity.log` 및 `storage-results.txt`의 **16 PASS / 0 FAIL**을 확인했다. 지속 잠금의 저장 실패·기존 바이트 보존·제어 오류 상태도 통과했다. 이 실행은 새로운 플레이 0판이며 실제 UI의 분할 조회·버전 안내·수명주기 검사는 아직 남아 있다. 이전 합성 범위 검사는 원시 기록 없는 요약을 정상 실측으로 수락하지 않도록 기대를 조정했고, 해당 기존 통합 검사는 아직 재실행하지 않았다.
