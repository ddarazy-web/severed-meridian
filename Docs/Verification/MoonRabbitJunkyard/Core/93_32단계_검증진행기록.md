# 32단계 구현·검증 진행 기록

- 시작/완료: 2026-09-29. 상태: 구현·소규모 검증 및 아래 13조건 감사 완료.
- 목표: [32단계 개발 목표](../../../Goals/MoonRabbitJunkyard/Core/92_32단계_개발목표.md).
- 증거 폴더: `Logs/Stage32Verification`.

## 보존 기준과 조사

기존 세 저장소의 파일 경로·크기·수정 시각을 `records-before.csv`, 기존 에셋과 meta의 SHA-256을 `assets-before.csv`로 확보했다. 기존 사용자 변경은 유지한다. 저장 테스트는 `owned-*`, UI 테스트는 `ui-owned-*` 임시 폴더를 사용한다. 사용자의 실제 기록을 삭제 대상으로 삼지 않는다.

세 종류의 저장소는 `Library/Match/AutoPlay`, `MoveBalance`, `MultiLevelTests`다. 여러 레벨 실행은 하위 레벨 기록을 소유하므로 최상위 실행만 개수로 세고 중첩 결과를 함께 처리한다. 기존 여러 레벨 저장소는 최근 실행만 읽었다. 기존 분석 잠금은 실제 진행 중 상태 중심이어서 삭제에는 재개 가능한 상태도 확인하는 별도 조건을 연결했다.

## 구현

- 기존 `MultiLevelTestStore`에 ID 조회와 요약 목록 열거를 추가했다. 최근 포인터를 바꾸지 않고 손상된 항목을 분리한다.
- `MultiLevelTestPanel.History`에서 지난 실행 선택·오류 표시·결과 교체를 제공한다.
- `TestRecordPaths`는 절대 경로와 상위 정션/링크를 검사한다.
- `TestRecordCleanup`은 세 종류의 소유 파일을 갱신 단위로 처리한다. 알 수 없는 파일을 보존하며 하위 삭제 실패 시 실행 요약을 남긴다.
- `TestRecordManagement`는 확인 창, 공유 잠금, 진행/실패 표시를 담당한다. 기존 두 화면에 연결하고 삭제 전후 저장 결과 참조를 정리한다.
- 기존 게임 규칙·봇 전략·네 난이도·시험 표본 수·패키지·저장 형식은 변경하지 않았다.

## 초기 검사 당시 남은 감사

실제 UI 목록/잠금/삭제 후 상태, 링크 우회 재현, 변경 영향 회귀, 캡처 육안 확인, 최종 데이터 보존 대조와 13조건 증거 매핑이 남아 있다. 20,000판 전체 실행·장기 시험·모바일 빌드는 수행하지 않는다. HTML 브라우저 배치 검수는 기존 승인에 따라 후속 이관을 유지한다.

## 중간 검사에서 수정한 사항

- 실제 정션을 생성한 검사로 하위 폴더뿐 아니라 저장 루트 자체의 링크 우회를 거절했다. 최근 포인터의 `.tmp` 파일도 쓰기 전에 경로 검사하도록 보완했다.
- 없는 저장소의 `latest.txt`를 삭제하려 하면 불필요한 경로 오류가 나왔다. 캡처에서 발견해 존재하는 포인터만 삭제하도록 수정하고 자동 검사에 추가했다.
- 기존 `BotBatchStore.LoadLatest`는 화면을 열 때도 요약을 다시 저장했다. 통합창 확인 중 기존 요약 한 파일의 수정 시각이 변경된 것을 보존 대조에서 발견했다. 화면에서는 `persistRecovery=false`로 읽도록 변경했고 임시 사본으로 내용·수정 시각 보존을 확인했다. 기존 복구 호출의 기본 동작은 유지한다.
- 최초 기록 보존 목록의 시각이 한국어·초 단위로 저장돼 단순 DateTime 변환과 문화권 문자열 비교가 실패했다. 한국어 문화권으로 파싱해 같은 초 단위로 비교하도록 정정했다. 에셋/meta는 SHA-256으로 대조한다. 잘못된 초기 비교 결과는 완료 증거로 쓰지 않는다.
- UI 검사 두 건은 직접 세션 주입 후 표시 갱신, 내보내기 종료 후 버튼 갱신을 기다리지 않아 실패했다. 실제 표시 경로/실제 버튼 상태를 기다리도록 검사 코드를 수정했다. 실패 기록을 보존했다.
- 사용자 추가 요청에 따라 기존 Match 통합창의 `지난 시험 조회`, `새 시험 실행`, 하단 `기록 관리 · 전체 삭제`를 분리했다. 별도 제품 창은 추가하지 않는다. 임시 UI 검사 창은 테스트 코드에서만 생성한다.

## 최종 검사

- 저장·경계 검사: **29 PASS / 0 FAIL**, `storage-results.txt`, `storage-readonly-final.log`. 빈 저장소, 실제 정션, 확인 취소, 부분 실패, 300개 합성 실행의 분할 삭제, 읽기 전용 복원을 포함한다.
- 실제 UI 동작: **30 PASS / 0 FAIL**, `ui-final-results.txt`, `ui-tab-lock-final.log`. 기존 통합창의 연결을 확인하고, 제품 패널에 임시 저장소를 주입해 삭제를 검사했다. 원본 실측 사본을 조회했으며 게임을 새로 실행하지 않았다.
- 실제 통합창 배치: **6 PASS / 0 FAIL**, `layout-results.txt`, `layout-final.log`. 1000×760 최소 창에서 조회·결과·조작 영역과 구분 제목, 결과·이력의 기록 관리 영역을 확인했다. 제품 창의 캡처 두 장을 매뉴얼에 반영했다.
- 최종 합계 **65개 검사 통과**. 이전 실패/재시도 횟수를 합산하지 않았다. 신규 실제 플레이 **0판**, 20,000판 실행 없음. 큰 기록 삭제 검사는 합성 요약 300개이며 밸런스 실측으로 집계하지 않는다.
- 실제 통합창 캡처: `test-history-integrated.png`, `test-record-management-integrated.png`. 임시 기록 삭제 완료 캡처: `test-records-deleted.png`. 모두 육안 확인했다. HTML 내부 링크·이미지·스타일 경로 477개를 확인했고 오류는 0개다(`manual-links.txt`).

## 기존 데이터 보존 결과

기존 시험 파일 **2,050개**의 경로·크기는 유지됐고, 실제 기록 삭제는 없다. 기존 에셋/meta **22개**는 시작 시점 SHA-256과 동일하다.

단, UI 검증 초기에 기존 조회 함수가 `AutoPlay/2cc18dfbc51a48adb4c1e854d0c74dc8/batch.json`을 다시 저장해 수정 시각이 바뀌었다. 이 파일은 같은 크기로 남아 있으며 삭제되지 않았다. 시작 시 기록 본문 해시는 확보하지 않았으므로 그 시점과 바이트 단위 동일성을 주장하지 않는다. 이 부작용을 없앤 뒤 기존 2,050개 파일의 본문 해시를 확보했고, 최종 UI·배치 검사 후 **본문 해시 변화 0개**를 확인했다. 수정 시각을 인위적으로 되돌려 숨기지 않았다. 근거는 `preservation-results.txt`, `records-content-audit-before.csv`, `content-preservation-results.txt`다.

## 사용 경로와 남은 제한

`Match → 통합 작업창 → 여러 레벨 시험`에서 위쪽 `지난 시험 조회`를 사용한다. 새 시험은 별도 `새 시험 실행` 영역에서 시작한다. `결과·이력`과 `여러 레벨 시험` 아래쪽의 `기록 관리 · 전체 삭제`를 펼치면 동일한 전체 삭제 기능을 사용할 수 있다. 실제 사용자가 확인 창에서 동의한 때에만 삭제한다.

HTML 브라우저 배치 검수, 20,000판 실측, 여러 레벨 장시간 시험, 모바일 빌드는 이번 완료 범위에 포함하지 않는다. 개별 삭제·휴지통·CSV 비교표·중단 시험 이어 실행도 추가하지 않았다.
