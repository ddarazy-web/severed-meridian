## 구현 결과

기존 Match 결과·이력의 통계 위쪽과 이력 비교에 예상 난이도 또는 보류 이유를 표시한다. 대표 전략·두 성공률·정상 판 수·같은 시드 쌍·기준 버전과 펼칠 수 있는 근거를 제공한다. 사례 확인은 대표 전략의 저장 기록으로 이동하며 새 게임이나 재생을 자동 시작하지 않는다.

`AutoPlay/Runtime/Analysis/BotDifficultyRules.cs`는 기존 통계만 읽는 순수 평가다. `AutoPlay/Editor/Presentation/LevelAnalysisPanel.Difficulty.cs`가 표현을 담당한다. `BotAnalysisReader`는 사본의 최초 이동 수와 정합성 문제를 전달하며, 과거 통계 조회와 현재 기준 추천 가능 여부를 분리한다. 봇·공통 게임 규칙·원시 기록 저장 형식은 변경하지 않았다.

기준은 `bot-difficulty-v1`: 두 전략 중 높은 성공률, 동률이면 기본. 반올림 전 80/60/40/20% 경계를 사용한다. 오류·손상·비호환·미완료·표본 부족·양쪽 성공 0은 보류한다. 이동 수 누락 시 성공률 등급이 가능해도 이동 여유 태그는 보류한다. 무작위 영향 태그는 인과 근거 부족으로 표시하지 않는다.

`final-counts.txt`와 각 결과 파일을 대조했다. 위는 검사 발생 횟수다. 대표 레벨의 신규 플레이는 800판이며, 별도 게임플레이 회귀는 성공 2사례·즉시 중단 1사례다. 기존 200판 저장 행동 재생은 신규 봇 플레이로 세지 않았다. 합성 경계 입력과 10,000회 순수 계산 역시 실제 플레이가 아니다. 선행 28단계의 1,005회 결과를 가져와 더하지 않았다.

컴파일은 실제 Unity 실행 과정에서 확인했다. 영향 소스·문서의 diff 공백 검사, 신규 스크립트 meta, 검사 소유 임시 에셋 정리와 원본 보존을 확인했다. HTML 네 페이지의 정적 링크·앵커·이미지·CSS 경로 검사는 최종 이미지 추가 후 다시 통과했다.

## 실제 시험과 측정 해석

새로 실행한 800판은 기본 수집, 한 수 도전, 상자+거미줄, 기본 수집 새 시드의 네 묶음이다. 두 전략이 같은 100개 시드를 쓰므로 독립 200표본으로 합산하지 않는다. 원시 정의·시드·엔진/전략 버전·행동은 각 묶음의 JSON에 보존되어 있다.

등급은 매우 쉬움 / 보통 / 매우 쉬움 / 매우 쉬움이다. 한 수 도전만 이동 여유 부족 태그가 붙었다. 계획 요구 태그는 실제 표본에서 발생하지 않았고 합성 경계 검사로 검증했다. 모든 등급을 얻기 위해 실제 결과를 선택하거나 폐기하지 않았다. 세 정의와 사람 평가 부재로 초기 구간을 재보정할 근거가 부족하여 기준을 유지했다.

실제 묶음 소요 시간은 약 13.60~613.47초, 단일 Advance 최대 관찰은 약 41.10~46.20ms였다. 순수 추천 10,000회는 약 9.95ms. UI의 기록 읽기부터 표시 검사까지는 약 1.68~2.63초였으며 검사 대기·Editor 스케줄링을 포함한다. 이는 이 PC에서 관찰한 값이며 프레임 예산·최대 지연 보장이나 인간 체감 난이도 검증이 아니다.

## 실패 이력과 제한

첫 복합 정의는 내부 블록 없는 거미줄 배치가 거절되어 실행 전에 중단됐다. 시험 정의를 수정하고 배치 결과 검사를 추가했다. 완료된 두 묶음은 보존했고 남은 시험만 실행했다. `runs-first-attempt.txt`에 실패를 남겼다.

첫 UI 시도는 내보내기 완료 파일 확인에서 실패했다. `difficulty-ui-first-attempt.txt`를 보존하고 화면 상태 메시지를 검사에 포함했다. 다음 시도와 최종 연속 3회는 모두 통과했다. 최초 원인은 확정하지 못했으므로 수정 완료라고 주장하지 않는다. 같은 원본의 보관·다시 열기·원시 값 보존 회귀도 통과했다.

실제 화면 캡처는 Unity 창에서 얻었다. HTML 내부 링크·앵커·자산은 정적 검사했으며 브라우저 렌더링·인간 체감 보정은 미검증이다. 과거 저장 기록을 새 기준으로 계산할 뿐 당시 저장하지 않은 등급을 복원했다고 표현하지 않는다.
