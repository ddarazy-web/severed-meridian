## 구현 범위

공개 값에서 새 가정 상태와 별도 난수를 만들고 기존 공통 실행기로 두 수를 살펴본다. 첫 행동만 실제 세션에 제출하고 이후 새 관찰로 다시 계획한다. Match에서 기본/계획 전략, 새 시험, 같은 조건 재시험, 한 수/한 판, 중지와 선택 이유를 제공한다.

반복 실행·통계·난이도 추천은 구현하지 않았다. 27단계 계획·목표 문서는 별도 사용자 요청으로 작성했으며 실행한 기능에 포함하지 않는다.

## 최종 집계와 버전

**3,750 PASS / 0 FAIL** — 신규 191개 + 기존 기능 회귀 3,559개. `final-counts.txt`에서 실제 검사 행만 집계했다. 독립 준비 수 재현과 전체 판 재현은 각각 고유 검사 2개만 더했고 반복 실행된 기존 검사 행은 다시 세지 않았다. 엔진 회귀 16개 묶음의 요약 행도 제외했다. HTML 링크 검사 354개는 별도 정적 검사로, Unity PASS 수에 더하지 않았다.

최종 버전은 계획 `planning-bot-v2`, 가정 `public-assumption-v1`, 세션 `bot-session-v3`, 기존 기본 전략 `basic-bot-v1`, 관찰 v1, 공통 실행기 `board-action-items-v13`이다. 보조 평가를 추가한 뒤 계획/준비 수/실제 판/독립 재현/예산·흐름 경계와 실제 계획·기본 UI를 다시 검사했다. 공통 규칙과 기본 평가 로직은 그 보완에서 변경하지 않았다.

계산 기본값은 깊이 2수·첫/둘째 후보 각 6개·표본 3개·작업 한도 4,096·분기 후속 한도 128로 유지했다. 정상 10×10 판에서 3개 공통 표본과 둘째 행동 108회가 끝나고 실제 한 수를 실행했으므로, 작은 사례만 통과한 값으로 발표하지 않는다. 전체 100칸 시드 771의 한 수는 약 9.92초, 최대 단일 처리 약 104ms였다. 인위적인 가정 재배치 한도 사례는 약 3.56초/최대 353ms였다. 측정은 UI 대기 제외이며 플랫폼 전체 성능 보장이 아니다.

검증 도중 검사 데이터의 무작위 장애물 ID, 곰팡이 내구도, 한도 사례의 덮개 조건, 계약 예외 문구를 실제 규칙에 맞게 수정하고 해당 검사를 재실행했다. 제품 동작을 테스트에 맞춰 약화하거나 실패 사례를 통과 집계에 포함하지 않았다.

## 검증 범위와 제한

테스트용 Unity를 순차 실행했고 사용자 프로젝트 프로세스를 종료하지 않았다. 이전 단계의 증거 파일을 보존하며 이번 결과는 별도 폴더에 수집했다. 공통 회귀의 요약 PASS 16행과 독립 재현에서 반복 실행한 기존 검사는 중복 가산하지 않는다.

계획 결과는 공개 정보에 기반한 가정이다. 알 수 없는 특수 공급·중력·합류는 실제 설정과 다를 수 있고 가정이 유효하지 않으면 기본 전략으로 전환한다. 실제 판의 오류와 가정의 한계를 구분한다. 봇 성공률이 사람의 체감 난이도라는 주장은 하지 않는다.

Windows Unity 6000.3.10f1의 전용 프로세스에서 검증했다. 모바일 기기 성능·출시용 게임 화면은 이번 범위가 아니다. HTML은 실제 UI 캡처와 코드 대조, 상대경로/앵커 정적 검사를 수행했다. 현재 브라우저 접근 제약으로 새 HTML의 브라우저 렌더 검증은 수행하지 못했으며, 이를 실제 Unity UI 검증과 구분한다.
