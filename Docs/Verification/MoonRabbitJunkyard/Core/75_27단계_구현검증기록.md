- 기준: [작업 계획](../../../Planning/MoonRabbitJunkyard/Core/71_27단계_반복실행과제어_작업계획.md), [26단계 완료 검증](74_26단계_완료검증.md).
- 증거: 프로젝트의 `Logs/BotBatchVerification/`. 아래 파일명은 이 폴더를 기준으로 한다.

## 사용할 수 있는 기능

Match → 플레이 테스트 → 봇 시험에서 전략별 횟수를 지정하고 **새 반복 시험**을 시작한다. 기본값은 기본·계획 봇 각각 100판, 합계 200판이다. 입력은 1~10,000회이며 한 번에는 한 판만 실행한다.

같은 시드마다 기본→계획 순서로 실행하고 각 판은 독립된 세션으로 시작한다. **일시정지·재개·반복 중지**, 전략별 완료 수·현재 판·진행률·최소 결과 요약을 제공한다. 저장된 조건으로 재시험할 수 있으며 원본이나 규칙 버전이 달라지면 차이를 표시한다. 상세 통계·사례 재생·난이도 추천은 이번 단계의 구현 범위가 아니다.

## 소유권과 파일 구조

| 위치 | 책임 |
|---|---|
| `AutoPlay/Runtime/Execution/BotBatchSession.cs` | 레벨 값 사본, 시드 묶음, 현재 한 판의 소유·순차 실행·제어 |
| `AutoPlay/Runtime/Execution/BotBatchRecord.cs` | 묶음 요약과 판별 종료·이동·미션·행동 기록의 저장용 값 |
| `AutoPlay/Editor/Storage/BotBatchStore.cs` | 판 파일·묶음 요약의 원자적 저장, 완료 기록 복구, 손상 감지 |
| `AutoPlay/Editor/Presentation/LevelInitialStatePanel.Batch.cs` | 기존 Match 화면의 실행 조작·진행 표시·수명 연결 |
| `AutoPlay/Editor/Tests/BotBatch*Verification*.cs` | 핵심 제어·실제 UI·재로드·경계·200판·독립 재현 검사 |

모든 경로의 앞부분은 `Assets/Scripts/Features/`다. 기존 `BotPlaySession`, 공개 관찰, 기본·계획 전략, 공통 게임 실행기를 그대로 재사용한다. 실제 시드·난수 진단·시험 기록은 전략 입력으로 넘기지 않는다. 화면은 실행 관리자를 통해 제어하고 게임 규칙을 복제하지 않는다.

일시정지는 후속 `Advance` 호출을 막으며 검색·계획·연쇄 객체를 유지한다. 기존 한 판 시험의 `RequestStop`과 혼용하지 않는다. 반복 중지는 미완료 판만 중단하고 완료 기록을 보존한다. 라스트팡까지 끝나기 전에는 성공 판 기록을 확정하지 않는다.

기록은 `Library/Match/AutoPlay`에 저장한다. 레벨 정의는 묶음에 한 번만 저장하고, 한 판의 상세 행동 기록은 파일에 남긴 후 실행 객체를 해제한다. 판 파일을 먼저 확정하므로 요약 교체 전 종료는 판 파일을 다시 세어 복구한다. 손상·누락·중복 기록은 오류로 알린다. 파일 교체의 일시적 IOException은 같은 원자 교체만 최대 세 번 추가 재시도하며 총 대기는 70ms다. 지속 실패는 중단하고 기존 파일을 삭제하지 않는다.

## 최종 검사 집계

**1,050 PASS / 0 FAIL** — 신규 고유 검사 127개 + 이번에 실제 재실행한 기존 기능 회귀 923개.

| 신규 검사 | 수 |
|---|---:|
| 핵심 제어·저장·파일 잠금 | 30 |
| 실제 Match UI·최소 크기·도움말 | 21 |
| 실제 도메인 재로드 | 9 |
| 처리 경계·오류 분류 | 59 |
| 기본 200판 부하 | 6 |
| 독립 200판 재현의 고유 검사 | 2 |
| 합계 | 127 |

`final-counts.txt`에 채택한 결과 파일과 수를 기록했다. 독립 재현의 8개 중 첫 부하와 중복되는 6개는 다시 세지 않았다. UI·핵심·경계의 중간 실행, 개별 연결 검사의 중복, 이전 단계 검사 수를 더하지 않았다. 내부 링크·앵커·이미지 360개 정적 검사는 Unity 검사 수와 별도다.

회귀는 기존 공개 관찰·기본 전략·한 판 세션·독립 한 판 재현·통합·경계·기본 UI/재로드·수동 UI/재시작·저장·맵 목록·발전기/통로/낙하경로/합류·레이아웃·계획 전략/UI를 포함한다. 공통 게임 규칙 코드는 변경하지 않았다.

## 측정과 버전

| 항목 | 첫 200판 | 독립 재현 200판 |
|---|---:|---:|
| 총 실행 시간 | 58.64초 | 61.35초 |
| Advance 호출 | 36,993회 | 36,993회 |
| 최대 단일 Advance | 1,042ms | 1,046ms |
| 일시정지·재개 | 없음 | 291회 |
| 최대 일시정지 저장 호출 | 해당 없음 | 42.2ms |
| 별도 중지 호출 | 11.4ms | 11.3ms |
| 관리 메모리 시작 / 최고 / 수집 후 | 약 639 / 746 / 637MB | 약 639 / 750 / 638MB |

조건은 4×4 활성 영역, 3수, 색 수집 목표 100, 100개 시드, 기본·계획 두 전략이다. 정상 패배·막힘도 정상 시험 결과다. 메모리는 Editor 전체 관리 메모리이고 순수 기능 사용량이 아니다. 측정값을 모든 레벨의 보장값으로 해석하지 않는다. 10×10 계획 비용은 26단계의 별도 측정에 기록되어 있다.

UI는 한 번에 약 8ms의 작업 묶음을 처리하지만 단일 Advance가 더 길면 그 호출이 끝나야 입력을 받는다. 따라서 순간적으로 약 1초 지연이 관찰됐으며, 즉각 응답 또는 최대 지연 보장을 하지 않는다. 전략의 깊이·표본 수를 줄여 측정치를 좋게 만들지 않았다.

저장 형식은 1, 기본 `basic-bot-v1`, 계획 `planning-bot-v2`, 공개 관찰 `bot-observation-v1`, 가정 `public-assumption-v1`, 세션 `bot-session-v3`, 공통 실행기 `board-action-items-v13`이다. 현재 소스 해시는 `final-source-hashes.json`에 남겼다.

## 보존과 검증 중 수정

원본 데이터·기존 meta/GUID·프로젝트 설정·패키지를 보존했다. 기존 C# 변경은 봇 화면, 수동 화면 세 부분, 도움말 연결의 다섯 파일이다. 기능별 새 코드와 짝 meta를 추가했고 임시 에셋 폴더를 정리했다. 전용 검증 프로세스는 모두 종료했다. 다른 프로젝트의 사용자 Unity는 종료하지 않았다. 커밋은 하지 않았다.

검증 중 반복 파일 교체 실패를 발견해 동일 포인터의 불필요한 쓰기를 제거하고 제한된 원자 교체 재시도를 적용했다. 실제 잠금이 지속되는 경우에는 오류를 유지하고 이전 파일이 보존되는 것을 확인했다. 일시정지 직후 화면이 비는 문제도 발견하여 멈춘 보드를 즉시 갱신하도록 수정했다.

첫 재로드 검사는 검사 준비 코드의 버튼 갱신 순서 오류로 중단되어 수정 후 재실행했다. 첫 연결 회귀의 노란색 강조 검사가 한 번 실패했으나 제품 코드를 바꾸지 않은 별도 검사와 최종 전체 연결 검사에서 통과했다. 최초 실패는 보존했고, 원인이 확정되지 않은 일시적인 UI 검사 실패로 기록한다. 실패 실행은 최종 통과 수에 넣지 않았다.

## 사용법과 제한

- [반복 시험 HTML 안내](../../../MoonRabbitJunkyard/Manual/play.html#batch), [매뉴얼 시작](../../../MoonRabbitJunkyard/Manual/index.html), [실제 화면](../../../MoonRabbitJunkyard/Manual/images/batch-bot-test.png).
- 실제 Unity 화면은 직접 확인했다. HTML 브라우저 열람은 도구 보안 정책이 `file://`를 차단하여 수행하지 못했고 우회하지 않았다. 상대 링크·앵커·이미지 경로 360개는 검사했다. HTML의 넓은/좁은 브라우저 화면 및 복사 폴더의 오프라인 열람은 미검증이다.
- Library 삭제 시 로컬 시험 기록도 사라진다. 진행 중 판의 프로세스 재시작 복원, 장기 내보내기, 상세 분석·난이도 추천은 이번 단계에서 제공하지 않는다.
