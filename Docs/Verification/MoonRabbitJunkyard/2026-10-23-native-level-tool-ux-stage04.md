# 네이티브 레벨툴 UX 4단계 — 시험·저장·통합 검증

상태: 2026-10-23 구현·Editor 검사·독립 최종 검토·종료 감사 완료. 승인된 Editor 범위에서 전체 4단계를 마쳤다. 제품 빌드와 실기기 검증은 제외했다.

## 변경 결과

- 게임 시험 준비 창에 실제 JSON/MemoryPack 원본과 취소 버튼을 표시한다. 준비 취소·Android 뒤로가기·Escape는 편집으로 돌아오며 미저장 내용과 Undo/Redo를 보존한다.
- 실행 중 복귀 버튼에도 시험 원본을 표시한다. 시작 실패는 원인, 편집 복귀, 현재 레벨 검사, 같은 원본 재시도로 연결한다. 정식 진행 기록과 시험 기록은 분리한다.
- 명시적 JSON 저장은 완료 결과와 실제 프로젝트 위치를 안내한다. 저장 상태 창은 저장됨/메모리 변경을 구분하고 최근 파일 작업 결과를 다시 보여준다.
- ZIP 결과는 JSON 저장과 구분한다. 파일 선택 취소·전송 실패 시 유지되는 내부 저장본과 다음 동작을 안내한다. Windows 파일 스트림 경로만 실제 경로로 표시하며 Android 문서 제공자의 경로를 추측하거나 클라우드 동기화 완료를 주장하지 않는다.
- 기존 저장 계약, 지연 목록, 공유 데이터, 수동 저장 원칙은 유지한다. 새로운 데이터 형식이나 자동 저장은 추가하지 않았다.

## 실행 증거

Unity 6000.3.10f1의 Windows Editor와 격리 프로젝트를 사용했다. 제품 빌드·설치나 실제 Android 실행 결과가 아니다. [최종 검사 발췌](NativeLevelToolStage04/verification-results.txt).

상세 실행 로그는 `Logs/TestHarness/<실행>-Run.log`에 남긴다. 실패 상황을 의도적으로 주입하는 검사이므로 전체 로그에 오류 문구가 없다는 의미가 아니다. 검사 중 발견한 과거 테스트의 즉시 편집 세션/튜토리얼 필드 가정은 현재 목록 우선·명시적 작성 시작 흐름에 맞췄으며, 제품 동작을 과거 테스트에 맞춰 되돌리지 않았다.

ZIP 손상·잘림·동일 이름 충돌은 [1단계 보고](2026-10-22-native-level-tool-ux-stage01.md)의 `stage4-package` 54개 검사와 `Logs/NativeStartChecks/package-final.txt`를 대조했다. 해당 저장 구현은 이번에 변경하지 않았다. 이 부분은 이번 재실행과 구분하며, 이번 전송 UI 회귀는 읽기 실패/닫기 실패/외부 충돌에서 원본·초안을 보존함을 재확인했다.

## 하나로 연결한 제작 흐름

실제 UI 명령으로 새 프로젝트 → 첫 레벨 → 제공되는 3매칭 샘플 → 튜토리얼 작성 시작 → 안내문 수정 → 게임 시험의 안내된 교환 실행/조건 완료 → 편집 복귀 → 작성 완료 → 명시적 JSON 저장 → ZIP 내보내기 → 다른 내부 프로젝트로 가져오기 → 목록에서 해당 레벨 편집을 검사했다.

시험 복귀 전후 편집 상태가 동일하고, 작성 완료만으로 파일 저장이 되지 않으며, 가져온 레벨의 안내문과 저장 상태가 유지되는 것을 확인했다. 원래 프로젝트의 JSON도 유지했다. ZIP 파일 선택기는 격리 메모리 스트림으로 대체했으며 실제 Android SAF/외부 앱 공유 검증으로 해석하지 않는다.

## 전체 4단계 감사

| 단계 | 기존 완료 증거와 이번 연결 확인 |
|---|---|
| 1. 프로젝트·첫 레벨 | [1단계 보고](2026-10-22-native-level-tool-ux-stage01.md)의 시작·빈 목록·전환 보존. 이번 통합 검사에서 새 프로젝트/첫 레벨/가져온 목록의 명시적 편집 재확인 |
| 2. 보드 중심 편집 | [2단계 보고](2026-10-22-native-level-tool-ux-stage02.md)의 소재·우클릭/롱터치·보드 전용 줌·패널·단축키. 이번 시험 복귀의 선택/줌/패널 보존, 갱신/대량 목록 검사와 연결 |
| 3. 미션·튜토리얼 조립 | [3단계 보고](2026-10-23-native-level-tool-ux-stage03.md)의 조립·필수값·전체 취소·공유 경계. 이번 실제 공유 시험/3매칭/작성 완료와 파일 저장 분리 재확인 |
| 4. 시험·저장·인계 | 위 회귀·화면·통합 흐름·대량 파일 검사와 독립 최종 검토 완료. 승인 범위 충족 |

이 감사는 기존 단계의 최종 증거와 이번 영향을 받는 회귀를 연결한다. 모든 기존 테스트를 다시 실행했다는 의미가 아니다.

## 독립 검토와 판단

새 읽기 전용 검토자가 4단계 소스·계획·검사 증거를 확인했으며 Critical/Important 결함은 발견하지 않았다. 재검토 요청이나 커밋은 하지 않았다.

- 경미한 검증 한계: 새로 길어진 게임의 `JSON/MemoryPack 시험 · 편집 복귀` 문구를 5개 화면 크기마다 별도로 확인하지 않았다. 이번 5개 크기 검사는 오류·저장 팝업 기준이며 이를 게임 화면 전체의 검증으로 확대하지 않는다. 원본 표시·게임 복귀 동작은 실제 시험 검사로 확인했다.
- 검토자가 판단을 보류한 실기기·제품 빌드·외부 클라우드 동기화는 승인 범위 밖이다. 앞 단계 독립 구현은 기존 완료 증거를 사용하고 4단계 연결 부위만 재확인했다. 보고서·정리는 검토 이후 아래 종료 감사로 완료했다.
- 작업 판단: 기존 미커밋 작업 브랜치를 유지하고 격리 검사 사본으로 검증했다. 기존 단계 변경을 되돌리거나 제품 검증 결과로 과장하지 않기 위한 선택이다. 따라서 최종 통합 실행 파일과 실제 기기 조작은 별도 검증이 필요하다.

## 보존·제한

실제 제작 데이터 대신 소유한 검사 사본을 사용했다. 이번 ZIP 검사에서 남은 3개 GUID 저장소는 위치·링크·내용을 확인해 제거했으며 결과 로그는 보존했다. NativeDelivery·대량 목록·갱신 검사 사본은 각 검사 종료 시 제거한다. `Assets/Data`, `ContentData`, `ProjectSettings`, `Packages`에서 이번 작업의 Git 변경은 없음을 확인했다. 원본 전체의 실행 전후 해시 감사를 새로 수행한 것은 아니다.

제품 빌드·설치, 실제 Android SAF/키보드/기기 밀도/터치, Windows 제품 실행 파일·운영체제 창 조작은 미검증이다. 커밋·푸시·HTML 매뉴얼 갱신은 하지 않았다. 최종 완료 후 추가 작업을 자동 시작하지 않는다.
