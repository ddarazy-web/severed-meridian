## 구현 선택과 확인 한계

- 계획의 별도 TutorialLegacyConversion 편집 도구 대신, 읽을 때 구형 결과를 공통 조건 상태로 해석하는 TutorialLegacyConditionAdapter와 변경 전후 추적 검사를 사용했다. 실제 에셋 변환 저장 도구나 원본 덮어쓰기는 만들지 않았다.
- 중첩 공유 흐름은 데이터 구조에서 지원하지 않아 참조 순환 자체를 구성할 수 없다.
- 실제 모바일 기기 성능/터치 검증은 하지 않았다. 가로·세로 확인은 Windows Unity 게임 화면 검사다.
- HTML 매뉴얼은 사용자 추가 지시 전에 작성한 내용만 유지한다. 별도 브라우저 시각 검증이나 후속 갱신은 하지 않았다. 이후 HTML 갱신은 별도 요청이 필요하다.
- 일부 Unity 검사 종료 로그에 JobTempAlloc 경고가 있었다. 통과한 기능 검사나 빈 게임 예외 기록을 네이티브 할당 경고까지 없다는 뜻으로 해석하지 않는다.
- 후속 작업은 사용자 제작 과정 점검이다. 실제 튜토리얼 콘텐츠를 대신 만들거나 추가 구현을 자동 시작하지 않는다.
