## 출발점과 검증 계약

- 시작 시 작업 트리는 깨끗했다. 앞 단계의 구현·검증이 현재 HEAD에 포함되어 있다.
- 제품 빌드·커밋·푸시·HTML 갱신·하위 에이전트는 사용하지 않는다.
- 2단계의 이름 편집 정상 3회(중앙값 62.35/64.85/63.50ms), JSON/ZIP/MemoryPack/게임 시험, 저장 실패·재시도·복구 사본 보존 증거는 런타임 소스가 바뀌지 않는 한 재사용한다.
- 기존 `LevelToolManualSavePerformanceVerification`을 partial로 나누고 `.Extended.cs`에 대표 조작·반복 편집 검사를 추가한다. 제품 런타임의 계측 구조를 새로 만들지 않는다.
- 기준 38문서의 격리 작업 폴더를 만든 뒤 파일 쓰기를 감시한다. 공유 구성 적용만은 기준 입력에 공유 문서 하나를 추가한 39문서 조건이며, 준비 시간은 조작 시간과 구분한다.
- 표시 준비 시간은 명령 시작부터 두 번의 후속 Editor update와 부착된 패널·유효한 보드 geometry·최신 표시 문서 확인 시점까지다. GPU 렌더 완료나 실기기 화면 반응 시간으로 부르지 않는다.
- 100회 편집은 10회 묶음마다 관리 힙·working set·Undo 수·UI 요소 수·LevelDefinition 수를 기록한다. GC는 묶음 사이의 메모리 관찰 구간에만 강제하며 편집 명령 시간에 포함하지 않는다.
- 표본/묶음 30초·working set 8GiB 보호를 유지한다. 지원되지 않는 누적 할당값은 null이다.

## 잔여 비용·미검증·후속 후보

1. 튜토리얼 약 1.05초, 공유 적용 약 0.89초: `TutorialDraftEditing`과 튜토리얼 패널의 임시 그래프 구성·전체 패널 재생성을 우선 분석할 가치가 있다. 그래프 단독 구성도 약 289ms다.
2. 선택·줌·셀 편집 약 214~248ms: 문서 조회는 이미 줄었지만 `LevelToolBoardView.Refresh`는 보드 셀과 그림 표시를 다시 구성한다. 선택 표시와 크기 변경만 갱신하는 후속안을 검토할 수 있다.

## 변경·검토 범위

신규 검사는 기존 성능 검사 클래스의 partial 파일로 분리했다. 제품 코드·씬·프리팹·설정·사용자 데이터·HTML을 바꾸지 않는다. 메모리에서만 편집하고 파일 쓰기 감시는 격리 프로젝트와 복구 폴더에 한정한다. 검사 로그와 측정 결과는 별도 Logs 경로에 남긴다.

최종 diff에서 제품 소스·ProjectSettings·Packages·씬·프리팹·HTML 변경이 없음을 확인했다. 검사 연결은 해제됐고 고정 입력 해시가 유지됐다. 신규 meta는 고유한 32자리 GUID다. 문서 링크와 `git diff --check`는 통과했고 Git의 줄바꿈 정규화 안내만 있다. 후속 최적화는 자동 착수하지 않는다.
