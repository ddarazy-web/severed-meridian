### 남은 항목

- **사용자 요청으로 미검증 보류:** 200% OS 배율, 물리 모니터 분리. 프로필 목록의 실물 휠 검증도 기존 사용자 요청대로 보류.

- 외부 앱은 빌드 전 자동 로그 정리를 끄고, BAT는 `-PreserveLogs`로 기존 로그를 보존한다. 자동 설정 복원은 제품 전환 및 Unity 직렬화로 남은 4개 파일 변경을 이번 검증 후 수동 정리했으므로 완전 자동 복원으로 판정하지 않는다.

- 장기 배포 전 지원 중인 .NET 런타임 버전·패치 및 대상 PC 설치 조건을 재확인한다. 현재 패키지는 런타임을 포함하지 않는다.

## 후속 키보드 검사 (2026-10-16)

사용자가 실제 빌드·실제 비밀번호 없이 남은 키보드 검사를 승인했다. `BuildApp.Tests --keyboard-fixture` 모드는 제품과 동일한 MainWindow를 열고 FakeClient만 주입한다. 실제 Unity/호스트/DPAPI 전송 클라이언트를 만들지 않으며, 별도 임시 프로젝트·환경설정과 메모리의 가짜 프로필을 사용한다. 검사창을 닫으면 비밀번호를 제외한 메타데이터와 요청 종류를 기록한다.

### 발견한 문제와 수정

- 실제 키보드로 Alias 목록을 선택한 뒤 저장하면 ComboBox의 ItemsSource 초기화가 양방향 Text 바인딩을 통해 Alias를 비웠다. 이전 검사는 Alias 문자열을 직접 대입해 이 선택 상태를 놓쳤다. 목록을 갱신한 **후** 저장된 Alias를 복원하도록 수정했다. 실제 저장 원본 삭제와 화면 선택값 초기화를 구분한다.
- 밝은 Alias 펼침 목록에 전역 밝은 글자색이 적용되어 항목이 흐렸다. 항목 템플릿에 어두운 글자색을 지정하고 실제 펼친 화면에서 확인했다.
- 선택된 ComboBox 항목의 저장 후 복원 회귀 검사를 추가했다. `Logs/ExternalBuildStage03/keyboard-regression.txt`: WPF 검사 98개 통과, 컴파일 오류·경고 0.

### 키보드만으로 확인한 흐름

1. Tab·Shift+Tab으로 항목 순회, Space로 체크박스 변경, 한글·공백이 포함된 가짜 Keystore 경로 입력. 실제 파일은 열지 않음.
2. 임시 문자열 입력 → Enter로 가짜 Alias 조회 → Alt+Down·방향키·Enter로 선택 → Enter로 메모리 내 서명 저장. 수정 후 Alias와 저장 표시 유지, 입력 비밀번호 제거 확인.
3. Ctrl+A·Backspace로 버전을 비운 뒤 Ctrl+S: 오류 표시와 저장 차단. 이어 버전 `9.8.7`, 코드 `42`, 디버그 ON 입력 후 Ctrl+S 저장 및 F5 재조회로 유지 확인.
4. F6 가짜 사전 검사, 방향키·Ctrl+Tab으로 로그/복구 탭 이동. 보관 기간 `14` 입력 후 Enter로 가짜 후보 미리보기 및 복구 상태 확인. 삭제 실행 없음.
5. 미저장 옵션 변경 후 F5의 확인창에서 Escape로 취소하여 입력 유지. 다시 F5→Enter로 저장 원본 복원. 프로필 방향키 왕복 후 서명 값 유지. Alt+F4 정상 종료.

최소 창 1000×700에서 OS 키 입력으로 실행했고, 화면 포커스·자동 스크롤·오류·저장 결과를 관찰했다. 마우스 클릭으로 필드를 선택하거나 ViewModel에 값을 직접 넣지 않았다. 문자 입력은 컴퓨터 사용 도구의 type_text를 사용했다.

검사 결과: `Logs/ExternalBuildStage03/Keyboard-20261016-191711/한글 프로젝트 경로/keyboard-result.json`. 저장된 버전·코드·디버그·Alias·보관 기간 및 dirty=false를 별도 검증했다. 기록된 요청은 settings, signing-aliases, save-signing, save-settings, check, cleanup-preview뿐이며 **build/cleanup 요청은 0회**다. 검사 전 실패 재현 기록은 `Keyboard-20261016-191105`에 있다. 실제 Assets/ProjectSettings/UserSettings 변경은 없었다.

최신 로컬 패키지는 `Build/BuildApp/20261016-192650`. 이번 키보드 검사는 동일 소스의 검사 전용 실행기에서 수행했으며, 새 패키지의 실제 Unity 저장·서명 성공을 의미하지 않는다. 200% 배율·물리 모니터 분리는 기존 보류 결정을 유지한다. 커밋·푸시·HTML 갱신·사용자 로그 삭제 없음.

## 판단 기록

- Ruling: 작업 복구는 요청 기록과 프로세스 PID+시작 시각, 기존 실행 잠금을 함께 확인한다. PID 재사용을 살아 있는 원래 작업으로 오인하지 않기 위해서다. 확인할 수 없는 소유 기록은 보수적으로 보호하며, 이 경우 수동 확인이 필요하다.
- Ruling: 정상/실패 전송 정리는 기존 경로를 유지하고, 중단 후 잔여 암호화 파일 정리는 명시적 버튼으로 제공한다. 24시간 유예와 잠금을 적용한다. 자동 정리 범위를 넓히지 않는 대신 강제 종료 잔여 파일은 다음 확인까지 남을 수 있다.
- Ruling: 중단 기록의 검토 완료 표시는 외부 요청에만 남긴다. Unity Runner 기록은 변경하지 않는다. 미완료 Runner는 기존 `Match → Build → 빌드 도구`에서 확인해야 하며, 외부 앱은 새 실행을 막는다.
- Ruling: 현재 설치된 SDK 8.0.400으로 net8.0-windows 로컬 검증 패키지를 준비한다. SDK를 임의 설치하지 않는다. .NET 8 지원 종료는 2026-11-10이므로 장기 배포 전 .NET 10 SDK/Desktop Runtime 전환을 검토해야 한다. 설치된 Desktop Runtime 8.0.8은 최신 패치가 아니며, 이 패키지는 런타임을 포함하지 않는다. [Microsoft 지원 정책](https://dotnet.microsoft.com/en-us/platform/support/policy), [지원 종료 안내](https://devblogs.microsoft.com/dotnet/dotnet-8-9-end-of-support/).

## 현재 구현과 증거

- `BuildRecovery`: 이전 요청의 완료/누락/손상/사용 중 상태 표시, Runner 기록 보호, 사용자 확인 표시, 오래된 일회성 암호화 파일 정리.
- 클라이언트/호스트/Unity 소유 프로세스 기록을 추가했다. 앱이 중간에 종료되어도 다른 프로세스가 사용하는 암호화 파일을 삭제하지 않는다.
- 이전 작업/복구 탭과 3초 간격 읽기 전용 상태 확인을 추가했다. 자동 재빌드는 하지 않는다.
- 복구 검사를 먼저 추가하고 `BuildRecovery` 없음으로 실패를 확인했다. 구현 후 기존 검사와 함께 58개 통과했다.
- 별도 임시 앱 프로세스를 강제 종료하는 검사 추가 후 63개 통과. 실제 Unity 실행 대신 임시 PowerShell 호스트를 사용했으며, 부모 종료 후 호스트 생존·파일 보호·완료 조회·종료 후 정리·요청 1회만 생성됨을 확인했다.
- 기존 호스트 v1 회귀와 v2 호스트 검사가 통과했다.
- `WindowPlacement`: 물리 좌표 저장과 모니터별 작업 영역 복원, PerMonitorV2 manifest 추가. 순수 배치 검사를 먼저 추가해 실패 확인 후 구현했다. 실제 모니터 창 이동·재실행·최대화 검사는 진행 중이다.
- `Publish-Local.ps1`: 기존 출력 폴더를 덮어쓰지 않는 로컬 WPF 게시 스크립트와 파일 SHA256 manifest를 추가했다. 제품 빌드나 공개 업로드를 호출하지 않는다. 패키지 검증은 아직 진행 전이다.
