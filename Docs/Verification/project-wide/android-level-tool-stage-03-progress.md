# Android 레벨툴 3단계 — 진행 기록

2026-10-11 · **3단계 구현·자동 검증 완료.** 실제 Android 검사는 사용자 요청으로 제외했으며 미검증으로 남긴다. 아래 초기 실패 기록은 수정 과정의 이력이고, 최종 판정은 마지막 표를 기준으로 한다.

## 승인과 범위

- 사용자의 “실기기 말고 다음 진행해”에 따라 2단계 실제 Android dp·키보드·한글 IME 검증은 미검증으로 남기고 3단계를 진행한다.
- 커밋·푸시·Player/APK/Addressables 빌드·HTML 매뉴얼 갱신은 계속 금지한다.
- 실기기 검증은 후속 최종 검수로 남긴다. Editor 이벤트 재생을 실제 기기 결과로 표시하지 않는다.

## 작업과 검증

1. 터치 판정/취소: 현재 셀 PointerDown 즉시 편집 경로를 확인했다. 탭 PointerUp 확정과 롱터치·이동·다중 포인터 취소를 실제 UI 이벤트로 검증한다.
2. 확대/이동/선택: 기존 ScrollView와 셀 크기를 사용한다. 화면 변환은 문서와 Undo를 변경하지 않아야 한다.
3. 공통 명령: 같은 세션의 깊은 복사 클립보드와 전체 개체 단위 명령을 구현한다. 기존 배치 검증과 Apply 원자성을 재사용한다.
4. 통합 검사/보고: Unity 검사는 순차 실행하고 결과·미검증·다음 문서를 기록한다.

## 결정 기록

- 기존 `work` 체크아웃과 진행 중 변경을 유지한다. 새 체크아웃으로 기존 1·2단계 변경을 누락하지 않는다.
- 긴 계획의 공통 명령·검사 소스 작업은 독립 에이전트와 분담한다. Unity 실행은 주 에이전트만 수행한다.
- 연결점 입력도 공통 터치 판정을 통과시킨다. 작은 연결점의 최종 터치 크기 개선은 5단계 범위다.

- `LevelToolTouchVerification.RunTap`: 최초 실제 UI 검사에서 PointerDown이 문서/dirty/Undo를 바꾸는 실패를 확인했다 (`20261011-103355-275-Run.log`). 변경 후 탭 확정·한 번의 Undo·Redo ID 보존 검사가 통과했다 (`103833-514`, `104154-930`, exit 0).
- 전체 터치 검사 `104019-684`는 초기 탭 확정에서 실패했다. 좁은 재검사는 통과했으므로 아직 전체 통과로 간주하지 않는다. 좌표·포인터 상태를 기록해 추가 조사한다.
- 공통 클립보드 이식형 검사 310개 통과. 독립 검토에서 전체 프로젝트의 미완성 초안까지 붙여넣기를 막는 문제가 확인돼 국소 검증으로 수정/검사 중이다.
- 추가 독립 검토: 팝업 필드 기본 키 편집, 명시하지 않은 교체, 다중 터치 후 이동/중단된 포인터 상태 복구를 확인해야 한다. 완료 전 실제 UI 회귀 검사를 수행한다.
- 초기 새 테스트의 타입 충돌과 이번 새 소스의 메타 형식 오류를 수정했다. 컴파일 실패로 생성된 임시 폴더 메타만 소유 기록을 확인해 폴더 표시를 보정했고 연결을 해제했다. 기존 에셋 GUID는 바꾸지 않았다.

### 추가 확인과 수정

- 공통 선택 명령은 이식형 검사 315개를 통과했다 (`Logs/GameAuthoringStage02/stage03-selection-resolver-green.txt`, exit 0). 붙여넣기는 해당 선택과 참조만 검증해 무관한 미완성 초안에 막히지 않으며, 화면에서 실제 사용 중인 기본/사용자 정의를 조회한다.
- 기존 JSON EditorWindow의 실제 메뉴 검사에서 ‘요소 복사’ 누락을 재현했다 (`105035-156`). 공통 명령 연결 후 복사 독립성, 전체 본체 붙여넣기, 새 ID, Undo/Redo, 다른 층 보존, 잘라내기, 새 세션의 클립보드 초기화가 통과했다 (`105938-851`, exit 0).
- 2×2 전체 선택에서 내구도 필드가 사라지는 문제를 재현했다 (`105226-519`). 개체 기준 속성 표시로 수정했고 네 점유 칸 선택, 실제 작업 메뉴→속성 패널→내구도 수정과 한 번의 Undo가 통과했다 (`105830-853`, exit 0).
- 앱 중단/포커스 상실 후 이전 Up이 오지 않아도 새 터치를 받는 경로는 추가 검사에서 통과했다. 캡처 상실 검사에 있던 setter 없는 속성 사용은 공개 이벤트 생성 API로 교정했다. 해당 전체 검사는 재실행 중이다.
- 명시하지 않은 동일 정의 교체 방지와 팝업 필드 키 전달은 부분 검사에서 확인했으며, UI 배치/포커스 이후 동작까지 검증하도록 테스트 단계를 분리했다. 아직 전체 통과로 표시하지 않는다.
- 확대 중심의 실제 레이아웃 오차와 2×2→1×1 메뉴 교체를 독립 검토로 추적하고 있다. 확대는 스크롤 전 좌표를 보관하고 레이아웃 후 제한된 횟수로 보정한다. 후자는 재현 검사 후 원본 개체 단위로 수정한다.

### 통합 재검사

- 핀치 중심: 정수 격자·스크롤 폭·레이아웃 후 보정으로 실제 중심 `(220, 446)`과 결과가 일치했다 (`111127-901`, exit 0).
- 추가 손가락: 2·3번 포인터의 캡처 누락을 재현하고 모두 캡처하도록 수정했다. 문서 루트 밖에서 모든 손가락을 뗀 뒤 새 탭과 한 번의 Undo가 통과했다 (`111210-152`, exit 0).
- 2×2→1×1 실제 메뉴 교체: 원본 기준 칸의 개체 하나만 생성되고 한 번의 Undo로 기존 ID가 복원됐다 (`111240-146`, exit 0).
- 팝업 실제 키 입력: Delete/Ctrl+A/C/X/V 기본 필드 편집과 보드 JSON/Undo 보존이 통과했다 (`111312-464`, exit 0). Delete 재현에는 Unity의 실제 키 맵과 같은 FunctionKey 플래그를 사용했다.
- 클립보드 층: Block 복사 후 Dust에서 실제 붙여넣기 버튼이 비활성화되고, Block으로 돌아가면 실제 메뉴 붙여넣기와 Undo가 통과했다 (`111351-306`, exit 0).
- 전체 터치 UI 흐름: 탭·롱터치·이동·다중 터치·영역/추가 선택·확대·취소·회전·기존 마우스·작업 메뉴·Undo·저장/재열기가 통과했다 (`111426-555`, exit 0).
- 최종 검토에서 작은 핀치 이동의 누적 확대량을 보존해야 하는 항목이 추가됐다. 이 좁은 수정과 Windows/2단계 관련 회귀 검사까지 마친 뒤 완료를 판정한다.

### 최종 수정 근거

- 작은 핀치 40회에서 확대량이 매번 반올림되어 사라지는 실패를 재현했다 (`111812-057`). 소수점 확대량을 누적하고 그리는 격자만 반올림하도록 수정했다. 축소된 보드의 스크롤 한계를 넘는 중심 유지 요구는 검사에서 제거하고, 양 축에 스크롤 여유가 있는 실제 레이아웃에서 확대량·중심·문서·Undo를 확인했다 (`112111-927`, exit 0). 일반 핀치 중심과 전체 터치도 통과했다 (`112150-507`, `112225-114`, exit 0).
- 모바일 초기 Safe Area 검사는 한 번 실패했다 (`112324-378`). 진단을 추가한 전체 화면 재검사에서는 모든 경계가 정확히 일치하며 통과했다 (`112459-259`, exit 0). 제품 화면을 임의 변경하지 않고 검사에서 예약된 viewport 적용 완료와 후속 레이아웃 계산을 기다리도록 보강했다. 실제 경계 assertion은 그대로 유지한다.
- 갱신 캡처에서 도구 모음의 가로 스크롤바와 모바일 필드의 세로 배치가 버튼/체크박스 하단을 가리는 것을 확인했다. 도구 모음만 스크롤바를 숨기고 Toggle을 가로 배치했으며 좌우 스크롤은 유지했다. 독립 읽기 전용 검토에서 추가 문제는 발견하지 않았다. 해당 화면 수정의 회귀 검사는 순차 실행 중이다.
- 도구 모음 수정 후 전체 터치(`112819-261`), 모바일 전체 화면(`112928-235`), 숨겨진 입력의 저장/Undo(`113210-080`)가 통과했다. 배율 검사(`113300-240`)에서는 이전 패널 크기로 여백을 계산한 실패가 기록됐다: 실제 `(7.5,17.5,938,569.5)` 대 기대 `(6,12,942,579)`. 테스트의 targetTexture/scale 교체 뒤 실제 루트 크기가 갱신된 것을 확인하고 Safe Area를 적용하도록 순서를 수정했다. 제품의 매 프레임 viewport 갱신 동작은 변경하지 않았다.
- 수정한 배율 검사는 통과했다 (`113409-496`, exit 0). Windows 뷰포트 검사에서 ID가 누락된 초안의 선택 명령 상태를 조회하다 단축키 안내가 중단되는 예외를 재현했다 (`113524-713`). 화면 조회에서는 해당 형식 오류만 잡아 명령 비활성 사유/속성 안내로 표시하며 실제 편집 검증은 유지한다. 독립 검토 승인 후 관련 회귀를 순차 실행한다.
