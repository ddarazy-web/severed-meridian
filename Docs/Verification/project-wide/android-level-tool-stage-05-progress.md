## 요청 범위와 완료 기준

[실행문](../../Commands/project-wide/android-level-tool-stage-05-command.md), [계획](../../Planning/project-wide/android-level-tool-stage-05-plan.md), [목표](../../Goals/project-wide/android-level-tool-stage-05-goal.md)의 네 작업을 유지한다. 고급 터치 편집, 게임 시험/결과/복귀, 제작→저장→시험→ZIP 통합과 동일 seed의 JSON/MemoryPack 초기 보드·결과 비교, 관련 회귀를 실제 코드와 검사로 확인한다.

실기기·Player/APK/Addressables 빌드·커밋·푸시·HTML 갱신·SDK/플러그인 설치는 제외한다. 가능한 Android C# 스크립트 컴파일만 실행 파일 빌드와 구분한다. 기존 `work`와 1~4단계 미커밋 변경을 보존한다.

## 분담과 실행 경계

- 고급 편집: 흐름/연결/모양/튜토리얼 화면과 터치 확정·취소를 조사한다. 파일 소유권을 확정한 후 수정한다.
- 시험·결과: 봇/여러 레벨/기록 화면의 모바일 접근성과 수명주기를 조사한다.
- 통합 검사: 기존 JSON/팩 게임 시험과 ZIP 검사를 대조하고 부족한 통합 증거를 외부 Tests에 추가한다.
- 주 에이전트: Play/BoardTouch/모바일 공통 경계, 문서, 독립 검토와 Unity 순차 실행을 맡는다.

Ruling: 기존 기능을 플랫폼별로 복제하지 않고 공통 UI·편집·게임 로직을 유지한다 — 같은 문서와 실행 결과를 보존하기 위해 — 새 UX는 실제 부족한 부분에만 적용한다.

## 초기 확인

- 4단계 보고는 공통 401개·화면 13케이스·ZIP 게임 정의/팩 입력 비교·관련 회귀·Android C# 컴파일을 기록한다. 해당 결과를 5단계의 고급 편집/실제 게임 결과 증거로 확대 해석하지 않는다.

- 현재 `HandleAndroidBack`은 `playRoot != null`이면 반환한다. 실제 시험 중 팝업/복귀의 Back 소유권과 검사 방법을 조사한다.
- 계획·목표의 각 완료 조건은 아직 미완료이며, 새 로그와 실제 코드 증거에 따라 갱신한다.

## 최종 수정 범위와 독립 검토

- 고급 지정은 영역 선택 도구보다 우선하고, 지정 중 롱터치는 기존 선택을 변경하지 않고 현재 터치만 취소한다. 외곽 전선 정점처럼 배경 셀이 없는 터치도 같은 계약을 적용한다.
- 전선 정점의 모바일 선택 영역은 48×48 UI 단위이며 표시점은 12×12를 유지한다. 실제 좌표에서 가장 가까운 정점을 선택하고 배경 블록 이동/배치를 차단한다. 전선 시작 시 기존 물체 이동 도구를 해제한다.
- 게임 시험 Back은 공통 팝업 취소/일시정지에 연결한다. 툴 handler와 EventSystem이 같은 프레임에 함께 입력을 처리해도 최상위 한 창만 처리한다. 복귀 버튼은 모바일 안전 영역에 배치하고 생성 시에만 UI 스킨을 적용한다.
- 기록 삭제 확인창을 Back/Escape로 취소한 뒤 다음 조회·시험이 잠기지 않도록 공통 닫기와 확인 취소를 연결한다. 실제 삭제 승인은 확인 플래그를 먼저 해제한다.
- 화면 재구성의 포커스 복원은 음수 hierarchy 인덱스를 조회하지 않는다. 기존 공통 편집/게임 로직과 데이터 규칙은 유지한다.
- 독립 에이전트 최종 제품 검토에서 추가 구체적 결함이나 범위 확대는 발견하지 못했다. 실행 성공 여부는 아래 최종 로그로 별도 확인한다.
