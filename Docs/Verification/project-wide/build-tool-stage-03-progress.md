# 제품 빌드 도구 3단계 — 구현·검증 기록

계획: `Docs/Planning/project-wide/build-tool-stage-03-plan.md` · 2026-10-16 · 구현·모의/재로드/조회 회귀 검사 완료

## 확정 범위와 판단

- 기존 `work` 작업 폴더의 미커밋 1/2단계 변경을 보존한다. 커밋·푸시·실제 Player/Addressables 빌드·SDK 설치·HTML 매뉴얼 갱신은 하지 않는다.
- Ruling: 실제 SDK가 지정되지 않았으므로 운영 옵션 등록표는 비워 두고 테스트에서만 옵션·설정 접근자를 주입한다. 가짜 GPG/플러그인 체크박스를 노출하지 않는다. 실제 SDK별 ON/OFF 기능은 이번 완료 범위가 아니다.
- Ruling: 옵션 처리기와 설정 접근자를 명시적으로 등록한다. 설정 접근자는 읽기·쓰기뿐 아니라 변경 **전** 예상 프로필 지문 계산을 제공해야 한다. 변경 후 실제 지문을 무조건 새 기준으로 삼지 않는다. 실제 SDK의 프로필 설정 어댑터는 파일·메모리 직렬화까지 반영한 정확한 예상 지문을 제공해야 하며 불일치는 중단한다.
- Ruling: 일반 설정 키는 옵션 한 개가 소유한다. 공유 심볼은 공통 소유자가 옵션들의 최종 ON/OFF를 합산한다. 옵션 외부 기능이 쓰는 공통 SDK 심볼은 접근자의 ProtectedSymbols로 보호한다. 실제 SDK 연결 때 해당 의존성을 조사해야 한다.
- Ruling: 옵션 처리는 PrepareCompilation→프로필 선택/재컴파일 대기→BeforeBuild→Player→AfterBuild→Cleanup 순서다. AfterBuild는 성공한 Player 결과가 있을 때만 실행하며, 후처리 실패는 Player 결과를 보존한 전체 작업 실패다.
- Ruling: 각 설정 변경을 원래 값·예상값·변경 전/후 예상 지문과 함께 먼저 기록한다. 중단된 단계는 처리기가 다시 진입할 수 있으므로 설정 변경은 Context.Apply를 사용하고, 그 외 출력 처리는 재진입 시 실제 산출물을 대조하는 멱등 방식으로 작성한다.
- Ruling: 설정 접근자 등록 코드는 신뢰하는 프로젝트 코드다. 임의의 SDK 쓰기를 자동 추론하거나 범용적으로 차단하는 보안 샌드박스는 만들지 않는다. 제품 필수 설정 키와 PRODUCT_ 심볼은 일반 옵션 등록에서 거절한다.

## 책임과 확장 위치

| 코드 | 책임 |
|---|---|
| `BuildToolOptions.cs` | 정의·처리기·설정 접근자 등록, 대상 필터링, 기본값·의존/충돌·설정 소유권 검증 |
| `BuildToolOptionState.cs` | 확정 값·시작/완료 단계·변경 기록, 적용/재진입 판정·역순 비교 복원·개인 선택 저장 |
| `BuildToolRunner`·`BuildToolRequest` | 기존 요청에 옵션 확정, 컴파일 준비·전후처리와 별도 후처리 상태, 실패·로그 오류에서도 옵션/백엔드 정리 |
| `UnityProfileBuildBackend` | 실행 직전 원본 지문 대신 확정된 예상 적용 지문과 대조. 기존 실제 빌드 경계 유지 |
| `MatchBuildToolWindow.Options` | 지원 제품의 체크박스·기본값·툴팁·미지원 기록 안내·의존/충돌 오류 표시 |
| 기존 창·실행 UI | GUID별 개인 선택을 유지하며 선택 변경으로 옵션을 지우지 않음. 확인 대화상자·결과에 확정 옵션과 후처리 오류 표시 |

개인 설정은 기존 `UserSettings/MatchBuildTool.json`의 `options[profileGuid][optionId]`에 저장한다. 실행 값은 별도의 요청 기록으로 복사하며 UI 조작과 분리한다. 완료한 단계는 다시 실행하지 않고 에디터 재시작은 자동 재개하지 않는다.

## 독립 검토와 수정

executing-plans의 최종 검토 요구에 따라 새 컨텍스트의 읽기 전용 검토를 수행했다. 검토자는 소스 수정·Unity·검사·실제 빌드·커밋을 하지 않았다. P2 3건을 채택했다.

1. 후처리 완료 전 재시작한 요청은 Player 성공 결과만으로 전체 성공을 확정할 수 없다. 명시적 정리 때 후처리 완료 기록을 검사하고 미완료면 후처리 오류와 전체 실패를 남긴다.
2. 다음 단계가 같은 설정 키를 다시 바꿀 때 이전 적용값을 실제값과 대조한다. 프로필 지문에 포함되지 않는 플러그인 설정도 외부 변경을 새 원본으로 받아들이지 않는다.
3. 동일 키를 여러 단계에서 변경한 뒤 복원 기록 저장이 실패하면 실제 설정은 이미 최종 원본일 수 있다. 정리 재진입 때 해당 키의 최초 원본까지 함께 대조하여 불필요한 외부 충돌·영구 잠금을 방지한다. 실제 저널 파일에 공유 잠금을 유지하여 복원 중 저장 실패를 재현한 검사로 확인했다.

후처리 전에 컴파일 오류가 발생하면 후처리를 실행하지 않고 실패·정리하도록 함께 보완했다. 모든 수정은 위 RED→GREEN 로그에 포함된다. 재검토를 반복하지 않고 구체 지적에 대한 한 번의 수정·회귀 검증으로 정리한다.

## 새 SDK 옵션을 추가하는 위치

1. 실제 SDK의 지원 제품·플랫폼, ON/OFF 제외 범위와 공유 의존성부터 조사한다. 단순 호출 중지와 바이너리 제외를 구분한다.
2. `IBuildToolOptionHandler`에 안정 ID·버전·설명·기본값·대상·의존/충돌·소유 설정 키를 등록한다. 처리 로직을 바꾸면 버전을 올린다.
3. `BuildToolOptionSetting`에 실제 읽기/쓰기·변경 전 예상 지문 계산을 등록한다. 패키지 설치·제거 대신 SDK가 지원하는 포함/심볼/설정 수단을 사용한다. 제품 필수 설정을 일반 옵션 소유 키로 우회하지 않는다.
4. 각 단계에서 `BuildToolOptionContext.Apply(key, value)`로 변경한다. OFF도 명시 처리한다. 공유 심볼은 `Definition.Symbols`에 선언하고, 외부 기능의 필수 심볼은 공통 접근자의 `ProtectedSymbols`로 보호한다.
5. `BuildToolOptions.Default`의 명시적 등록표에 실제 처리기와 접근자를 연결한다. 테스트 전용 처리기는 외부 Tests에만 둔다. 실패·재로드·ON→OFF·다른 제품의 영향을 검사한 후 별도 승인된 실제 빌드로 SDK별 산출물을 검증한다.

`Cleanup` 콜백은 시도된 옵션에만 전달한다. 등록 설정의 복원은 공통 엔진이 기록의 역순으로 수행하며, 콜백에서 같은 설정을 중복 복원하지 않는다. 공통 복원과 별개의 정리가 필요하면 재진입 가능한 처리로 작성한다. 최종 출력에 적용한 후처리는 삭제·원복하지 않는다.

## 미검증과 다음 실제 작업

- 실제 Player/APK/AAB/iOS·Addressables 빌드와 실제 플랫폼 전환/컴파일, SDK 바이너리 포함·제외, Gradle/Manifest/네이티브 플러그인 설정, 서명·스토어 로그인·실기 실행은 미수행이다.
- 실제 SDK용 설정 접근자·예상 지문 계산·콜백 시점은 아직 제공하지 않았다. 공통 구조에 SDK별 어댑터를 등록할 수 있게 했으며, 다음 작업은 대상 SDK와 지원 제품·플랫폼·기본 ON/OFF·제외 범위를 정한 뒤 실제 어댑터를 추가하는 것이다.
- SDK 어댑터가 원본 프로젝트를 바꾸면 Context.Apply와 정확한 변경 전 예상 지문을 사용한다. 출력 파일을 바꾸는 후처리는 성공한 Player 결과와 실제 산출물을 대조하고 재진입 가능하게 작성해야 한다.
- 옵션 추가는 중앙 플랫폼 switch를 늘리는 방식이 아니다. 기존 ProductDefinition 및 등록된 플랫폼 처리기를 재사용하며 실제 SDK 조사 없이 자동 설치·제거 기능을 추가하지 않는다.

3단계는 위 공통 구조와 허용된 검증 범위에서 완료다. 새 SDK 연동이나 후속 구현은 자동 진행하지 않았다. 커밋·푸시·HTML 매뉴얼 갱신·씬/프리팹 재작성도 하지 않았다.
