## 소유권과 흐름

`BotPlaySession → BotObservationBuilder → BotObservation → PlanningSearch → PlanningBranch → 가정용 BoardActionExecutor` 순서로 처리한다. 최종 첫 행동은 `BotPlaySession`이 현재 관찰 후보인지 다시 검증하여 실제 실행기에 제출한다.

| 영역 | 소유 데이터 | 접근 제한 |
|---|---|---|
| 실제 세션 | 실제 실행기·시드·공급·기록 | 전략에 세션이나 State를 전달하지 않음 |
| 공개 관찰 | 칸·본체·현재 미션·유효 조작·공개 벽/통로/도착의 값 복사 | 실제 정의·난수·공급 커서·진단 기록 없음 |
| 탐색 정책 | 공개 입력·기본 순위·표본 점수·작업 진행 | Unity·실제 상태 형식에 의존하지 않음 |
| 가정 어댑터 | 공개 값에서 새로 구성한 상태·난수·가정 실행기 | 실제 판을 복사해 비밀 필드를 지우는 방식 사용 안 함 |
| Match 화면 | 전략 선택·갱신 호출·출력 | 실제 세션을 실행 경계로만 사용, 계획 중 수동 조작 금지 |

기존 규칙 엔진을 복제하지 않았다. 값으로 현재 상태를 구성하는 내부 생성자와 안정된 상태에서 이어가는 내부 실행기 생성자를 추가했다. 원래 레벨 정의에서 시작하는 생성 경로는 유지한다. 가정 분기 복사는 처음부터 공개 값으로 만든 가정 상태 안에서만 수행한다.

## 공개 값과 가정값

공개된 빈칸·남은 이동·장애물 현재 내구도·충전·자물쇠 색·연결·덮개·먼지·미션 잔여량을 유지한다. 원래 미션의 누적 진행 대신 현재 잔여량을 가정 미션의 시작 목표로 사용하므로 이후 감소량이 중복 집계되지 않는다. 내부 장애물 ID는 좌표 기반 공개 키에서 새로 만들며 실제 ID를 읽지 않는다.

모르는 중력은 아래 방향, 공급은 게임의 일반 5색, 숨은 곰팡이 내용은 일반 블록 표본으로 가정한다. 가정 생성구는 활성 세로 구간의 윗칸이며 벽과 비활성 칸으로 구간을 나누고 통로 출구는 제외한다. 실제 생성구·고정 공급·고철/회수 유지 공급을 복원한 것으로 주장하지 않는다. 공개 벽·통로·도착은 유지한다. 직접 경로·합류 우선순위가 필요한데 공개 값만으로 유효한 흐름을 구성하지 못하면 가정 처리 불가로 기록한다.

가정 난수의 시작값은 정렬된 공개 값의 정수 해시와 표본 번호로 만든다. 현재 시간·실제 시드·실제 정의 지문·프로세스별 GetHashCode를 쓰지 않는다. 실제 난수 객체와 가정 난수 객체도 다르다. 숨은 내용 표본과 공급용 난수의 상관성은 단순 모델의 한계이며 현실의 확률 추정치로 해석하지 않는다.

## 비교 정책

- 버전: 공개 관찰 v1, 기본 전략 v1, 계획 `planning-bot-v2`, 가정 `public-assumption-v1`, 세션 `bot-session-v3`. 공통 실행기는 `board-action-items-v13`.
- 첫 후보 최대 6개, 둘째 후보 최대 6개, 가정 표본 3개. 기본 전략의 최선 후보를 포함한다.
- 총 작업 한도 4,096, 한 분기의 후속 처리 한도 128. 한 작업은 구성/명령/공통 후속 단계/결과 집계 중 하나다. 공통 단계 내부에도 기존 처리 한도가 적용된다.
- 주 가치: 가정 승리 1,000,000,000 + 현재까지 줄인 목표 수 × 10,000 − 사용 이동 수 × 10. 첫 수와 둘째 수의 진행을 따로 더하지 않는다. 최종 비교는 주 가치 × 1,000에 둘째 행동의 파워 가치 × 101 + 직접 범위 칸 수를 더한다. 첫 행동에서 종료되면 둘째 행동 보조값은 없다. 보조값은 최대 605로 이동 비용이나 목표 진행의 우선순위를 뒤집지 않는다. v2에서 이 둘째 행동 보조 평가를 반영했다.
- 같은 표본에서 모든 첫 후보의 계산이 끝난 묶음만 합산한다. 한 분기가 실패하면 그 표본 묶음 전체를 제외한다. 미완성 표본의 일부 점수를 후보 간 비교에 쓰지 않는다.
- 동점은 첫 후보의 기존 기본 평가와 행동 종류·좌표 순서를 따른다. 완료한 공통 표본이 없으면 기본 전략으로 전환하고 이유를 남긴다.
- 가정에서 승리가 정해지면 선택에 불필요한 라스트팡 보너스는 계산하지 않는다. 실제 판은 기존 라스트팡까지 처리한다.
- 선택한 첫 행동만 제출한다. 둘째 행동은 예약하지 않으며 실제 결과의 새 관찰로 다시 탐색한다.

가정 실패는 실제 패배가 아니다. 잘못된 후보 계약·지원하지 않는 실행 경계의 예외는 가정 실패로 숨기지 않고 실제 세션 오류로 드러낸다. 계획이 기본 전략보다 항상 유리하다는 보장은 없다.

## 취소와 화면

계획 계산 중 중지는 계산을 버리고 실제 이동·난수·상태를 유지한다. 실제 행동이 제출되면 기존 한 판 세션의 낙하·연쇄 완료 경계까지 처리하고 멈춘다. 탭 이탈도 같은 규칙이다. 원본 수정·레벨 변경·창 종료·도메인 재로드는 계획과 과거 관찰을 폐기한다.

전략 선택만 바꾸면 현재 판의 전략은 바뀌지 않는다. ‘새 봇 시험’은 새 시드, ‘같은 조건으로 다시’는 현재 정의 지문이 같은 동안 직전 시드를 사용한다. 두 버튼은 이전 세션을 폐기하고 새 세션을 만든다. 화면에 ‘새 시작 조건’ 또는 ‘직전과 같은 시작 조건’을 표시한다. 원본 변경·재로드 후 과거 비교 버튼은 사용할 수 없다. 실행 코드 변경에 따른 실제 도메인 재로드도 이 조건을 폐기하므로 과거 게임 버전의 조건을 이어 쓰지 않는다.

## 현재 증거와 한계

`Logs/BotPlanningVerification`의 계획·준비 수·전체 판 재현·경계·UI·재로드 보고서를 사용한다. 준비 수 사례는 5×5의 내구도 2 상자이며 첫 행동은 목표를 끝내지 못하고 둘째 가정 행동에서 제거한다. 전체 실제 판은 4×4의 3행동 이동 수 소진과 5×5의 2행동 성공을 수동 명령 및 별도 Unity 프로세스와 대조했다.

실제 UI 캡처 `planning-ui.png`에서 760×860 창의 전략 선택·버튼·설명과 보드 접근성을 확인했다. 재로드 검사는 같은 프로세스의 정적 상태 초기화와 미저장 원본/디스크/GUID 보존까지 확인했다.

10×10의 인위적인 한도 경계 사례는 가정 재배치 한도 256에 도달해 세 표본을 제외하고 기본 선택으로 전환한다. 최종 측정은 102작업, 약 3.56초, 가장 긴 단일 작업 약 353ms였다. 이 사례와 구분하여, 정상 시작 조건을 통과한 100칸 판도 검사했다. 시드 771에서 가정 표본 3개·둘째 행동 108개를 비교해 실제 한 수를 완료했고 약 9.92초, 최대 단일 처리 약 104ms였다. 작은 실제 두 판은 약 0.67초와 1.49초였다. 모두 UI 대기를 제외한 전용 프로세스 수치다. 모든 레벨에서 일정한 응답 시간이나 성공률을 보장하지 않는다. 공통 실행 한 단계 내부 처리는 아직 더 작게 쪼개지지 않았으므로 순간적인 지연이 생길 수 있다.

공통 규칙의 기존 16개 검사 묶음은 2,684 PASS / 0 FAIL이다. 이후 기존 기본 봇·수동·저장·맵 목록·연결·통로·경로·합류·탭 배치 회귀도 완료했다. 전체 중복 없는 합계는 신규 191개와 회귀 3,559개, 총 3,750 PASS / 0 FAIL이다. 시작 시 보존 해시 537개와 비교했을 때 요청 관련 기존 코드 8개만 달랐으며 설정·패키지·에셋·기존 메타 파일 변경은 없다.

대표 흐름·회수 가정, 제출 후 중지와 코드 오류 경계까지 완료했다. HTML의 새 절차·캡처·상대 링크는 반영·검사했으며 브라우저 접근 제약으로 새 HTML의 브라우저 렌더 검증은 수행하지 못했다. 실제 Unity UI 검사와 혼동하지 않는다.
