## 기존 조작 조회 감사

`ActionQuery.Find`는 벽·이동 제한·매칭·파워 조건을 읽고 실제 조작을 하지 않는다. `BoardQueryView.ColorAt`과 `HasMagnetTarget`은 곰팡이 아래를 제외한다. 덮인 칸은 조작 후보가 될 수 없으며, 생 `ActionCandidate` 대신 좌표·종류·복사된 매칭 패턴만 전달한다.

`MatchResolution.Select`는 겹친 패턴의 동률을 실제 난수로 해소한다. 따라서 전략에서 호출하면 안 된다. 관찰의 매칭 목록은 후보 목록이며 모든 칸이 제거된다는 보장이 아니다. 기본 전략 평가에서 겹침·무작위 결과를 구분해야 한다.

## 기본 전략과 한 판 실행 — 1차 구현

폴더는 `AutoPlay/Runtime/Observation`(공개 값), `Strategy`(평가), `Execution`(실제 상태 변환·진행·기록), `Editor/Presentation`(Match 연결), `Editor/Tests`(검증)로 나뉜다. 새 패키지나 별도 규칙 엔진은 추가하지 않았다.

- `BasicBotStrategy` 버전 `basic-bot-v1`: 미션 완료량 8점, 확인 가능한 내구도/충전 진행 1점 → 파워 가치 → 직접 범위 → 종류·행·열 순으로 비교한다. 종류별 피해 조건을 `BotMissionEvaluation`에서 평가한다.
- 매칭은 가장 높은 종류·길이의 후보를 비교한다. 동률의 공통 칸만 평가하며 실제 난수로 선택하지 않는다. 독립 매칭 그룹의 추가 기여는 과소평가할 수 있다.
- 드론 도착, 자석의 무작위 색/방향, 새 공급과 추가 연쇄를 미리 실행하지 않는다. 회수는 도착 칸으로 직접 교환하는 기여만 계산한다. 공개되지 않은 중력 경로를 가정하지 않는다. 회수 경로 정리 평가의 범위는 통합 검수 때 추가 확인해야 한다.
- 거미줄은 내용물 색과 먼지 소비를 막지만 매칭 인접 피해는 전달한다. 금고는 일반 매칭에 무피해, 자물쇠는 인접 색 조건을 적용한다. 폐가전은 직접 범위의 명중 칸 수를 최대 4까지 반영한다. 발전기와 직접 파괴가 같은 본체를 완료하면 하나만 센다.
- `BotPlaySession` 버전 `bot-session-v1`: `StartingBoardSearch`로 값 사본을 구성하고 `BoardActionExecutor`를 독점 소유한다. 검색은 호출당 128개 배정, 실행은 호출당 한 행동 또는 한 연쇄 단계다. Match에서 최대 0.05초 간격으로 한 단계씩 호출하며 실제 버튼·탭 이탈·중지 검사를 수행했다.
- 관찰 객체의 동일성과 후보 소속을 확인한 뒤 공통 실행기로 재검증한다. 과거 관찰, 위조 후보, 중복 입력, 연쇄 중 입력과 폐기 후 입력은 거절한다.
- 한 수 실행은 안정 상태까지 진행한다. 중지는 처리 중 행동의 낙하·연쇄를 끝낸 뒤 멈추며, 명시적으로 실행을 누르기 전에는 진행하지 않는다. 원본 변경·레벨 변경·창 종료·실제 코드 재로드는 실행기와 관찰을 폐기한다. 탭 복귀 뒤 자동 재개되지 않는 것도 실제 UI에서 확인했다.
- 진단 기록의 시드·정의 지문·난수 추출 수는 실행 세션에만 있다. 전략은 `BotObservation` 외에 기록을 받지 않는다.
