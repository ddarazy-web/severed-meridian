## 목적과 범위

런타임 uGUI 팝업의 열기·닫기·중첩·입력·선택적 씬 복원을 공통으로 관리한다. 등록과 템플릿으로 추가 패턴을 통일하고 기존 일시정지·결과·설명 팝업을 전환한다. Unity Editor 자체 대화상자와 UI Toolkit 드롭다운은 대상이 아니다.

기존 프리팹 디자인과 게임 규칙은 유지한다. 관리 컴포넌트 연결과 설명 팝업 분리는 전환 범위에 포함한다. 플레이어/Addressables 콘텐츠 빌드·커밋·푸시는 수행하지 않는다.

## 확인한 현재 구조

- `Assets/Scripts/Features/GameScreen/Runtime/UI/PuzzleScreenView.cs`가 개별 팝업 활성화와 보드 입력 차단을 처리한다.
- `PuzzlePauseView`는 재개·재시작, `PuzzleResultView`는 재시작·다음 레벨과 전환 잠금을 연결한다. 설명은 화면 내부 버튼으로 표시한다.
- `PuzzleGameSession.SetPaused`는 연출·오디오 정지를 처리한다. 공통 시스템이 `Time.timeScale`로 대체하지 않는다.
- `PuzzleBoardInput.SetUIBlocked`는 단일 bool이므로 결과·로딩·팝업 등 차단 이유는 게임 화면에서 합성해야 한다.
- `PuzzleUIAssets`와 `PuzzleLevelTransitionAssets` 생성 도구도 전환된 프리팹 연결을 보존해야 한다.

## 합의한 정책

| 항목 | 결정 |
| --- | --- |
| 중첩 입력 | 아래 팝업은 보이며 최상위만 클릭·터치·키·뒤로가기 입력 수신 |
| 중간 제거 | 고유 핸들로 지정한 것만 제거, 나머지 순서 유지 |
| 같은 종류 | 기본은 기존 것을 맨 위로 이동, 지정한 종류만 복수 인스턴스 허용 |
| 일시정지 | 입력 차단과 분리, 팝업별 요청, 마지막 요청 종료 시 팝업 소유 정지만 해제 |
| 복원 시점 | 원래 씬에 돌아왔을 때만 복원, 다른 씬에서는 표시하지 않음 |
| 복원 선택 | 복원 가능 팝업 지정 + 씬 이동 호출자가 이번 이동의 보관 여부 결정 |
| 유효성 | 씬과 연결된 게임 문맥이 일치해야 복원, 다르면 폐기 |
| 관리 도구 | 등록·정책·런타임 순서/입력 권한/복원 대기 조회·시험 열기/닫기·템플릿 생성 |
| 기존 전환 | 일시정지·결과·설명 팝업 포함 |

이하 구체 계약은 합의한 정책을 실행 가능한 형태로 정리한 제안이다. 문서 승인 전에는 구현하지 않는다.

## 구조와 소유권

```text
Assets/Scripts/Systems/Popup/
  Runtime/   관리·등록·표시·복원 계약
  Editor/    관리 창·등록 검증·템플릿 생성·검증
Assets/Scripts/Features/GameScreen/Runtime/UI/
  기존 세 팝업의 뷰와 게임 연결
Assets/Prefabs/UI/Popup/
  공통 표시 영역과 템플릿
Assets/Prefabs/UI/Puzzle/
  게임 전용 팝업
```

폴더는 파일이 필요할 때 생성한다. 새 asmdef·DI·UI 렌더링 프레임워크를 도입하지 않는다. 타입명은 제안이며 구현 계획에서 기존 관례에 맞춰 확정한다.

| 구성 | 책임 |
| --- | --- |
| PopupService | 인스턴스·순서·중복·최상위 권한·열기/닫기·보관/복원 진입점 |
| PopupHost | 씬 Canvas/안전 영역 표시·EventSystem 포커스·씬 종료 시 표시 정리 |
| PopupCatalog | 종류 ID·프리팹·중복·정지·뒤로가기·복원 가능 정책 |
| PopupView | 자기 내용 표시·상태 캡처/적용·최상위 입력 |
| PopupSnapshotStore | 씬/문맥별 순서와 값 데이터 보관·성공/무효화 시 소비 |
| 게임 연결 | 현재 세션 연결·문맥 제공·입력 차단/정지 이유 합성 |

서비스와 보관 데이터만 앱 실행 중 유지한다. 씬 Canvas·EventSystem·팝업 객체·게임 세션 참조는 씬 간 유지하지 않는다. 표시 영역은 명시적으로 등록/해제하며 준비 완료 전 복원하지 않는다. 한 활성 표시 영역을 관리하고 여러 동시 화면은 이번 범위에서 일반화하지 않는다.

## 열기·닫기·입력

열기는 종류와 내용 데이터를 받아 핸들을 반환한다. 단일 종류를 다시 열면 핸들을 유지하고 맨 위로 이동한다. 명시적인 새 내용이 있으면 갱신한다. 복수 허용 종류는 새 핸들을 발급한다. 닫기는 핸들 기준이며 이미 닫힌 핸들로 다른 팝업을 제거하지 않는다.

순서 변경 시 입력·차단·정지 상태를 함께 갱신한다. 최상위 외 CanvasGroup은 입력을 차단하고 키는 최상위에 한 번만 전달한다. 미처리 키나 닫기 금지 뒤로가기도 아래로 전달하지 않는다. ESC/Android 뒤로가기는 같은 취소 동작으로 연결하고 Enter 등은 팝업에 정의된 동작만 실행한다. 입력 한 번으로 여러 팝업을 연속 닫지 않는다.

열기 시 보드 제스처와 기존 UI 선택을 취소한다. 닫히면 아래 팝업의 저장된 유효 선택에 포커스를 복귀시키고 없으면 기본 선택을 사용한다. 공통 배경 클릭 자동 닫기는 추가하지 않으며 기존 설명의 명시적 닫기 동작은 유지한다.

## 입력 차단·정지

팝업이 하나라도 있으면 보드와 일반 UI 입력을 막는다. 결과·로딩·외부 중단과 OR로 합성하며 팝업 종료가 다른 차단을 해제하지 않는다.

정지 요청은 해당 팝업이 살아 있는 동안 최상위 여부와 무관하게 유지한다. 중간 제거도 집계에 반영하고 마지막 요청이 사라질 때 팝업 소유 정지만 해제한다. 외부 정지·백그라운드 상태는 건드리지 않는다. 기존 SetPaused와 연출/오디오를 게임 연결에서 보존하며 프레임워크는 게임 타입에 의존하지 않는다.

## 선택적 씬 복원

1. 이동 호출자가 떠날 씬/문맥과 이번 이동의 보관 여부를 지정한다. 보관하지 않으면 그 문맥의 오래된 보관 상태도 폐기한다.
2. 보관 시 복원 가능 인스턴스만 아래→위 순서로 캡처한다. 제외된 팝업을 뺀 나머지 상대 순서를 유지한다.
3. 캡처 완료 후 표시를 정리한다. 씬 이동 실패 시 기존 표시/입력/정지 소유권을 유지하거나 복구할 수 있도록 이동 결과를 연결한다.
4. 원래 씬의 새 표시 영역과 기능 연결이 준비되면 명시적으로 복원을 요청한다. 씬 이름만으로 자동 복원하지 않는다.
5. 씬 키와 기능이 제공하는 문맥 키를 검증한다. 게임 문맥은 레벨 번호와 논리 플레이 세션 식별자를 포함한다. 새 게임·재시작·다음 레벨은 다른 문맥이다.
6. 새 뷰의 데이터 적용과 현재 기능 연결을 모두 완료한 뒤 순서와 입력을 활성화한다. 부분 복원 상태는 조작할 수 없다.
7. 성공하면 보관 상태를 소비한다. 문맥 변경은 폐기한다. 복원 실패는 후보를 모두 정리하고 오류를 보고한다. 자동 반복 없이 명시적 재시도/폐기 전까지 데이터를 유지하며 게임 자체 차단은 보존한다.

복원 데이터는 종류·인스턴스 식별자·내용·입력값·선택·탭·스크롤·포커스 식별자다. Unity 오브젝트·delegate·진행 중 요청·취소 토큰·구독은 저장하지 않는다. 새 인스턴스에서 기존 외부 핸들은 무효이며 복원 결과가 새 핸들을 제공한다. 새 기능 연결은 어댑터가 담당한다. 구매·재시작·다음 레벨을 자동 실행하지 않으며 결과 복원이 승리 사운드/보상을 재실행하지 않는다.

앱 실행 중 메모리 보관만 제안한다. 앱 재실행 복원·디스크 저장·게임 진행 데이터 저장은 제외한다. 동일 문맥의 게임을 유지하며 왕복하는 기능은 게임 측 책임이다. 현재 게임 세션을 프레임워크가 영속화하지 않는다. 복원 자체는 두 시험 씬과 동일한 논리 문맥으로 검증한다.

## 관리 도구·추가 패턴·리소스

카탈로그에서 종류 ID·프리팹·정책을 편집하고 중복 ID·누락 프리팹·필수 컴포넌트 누락을 검증한다. Play Mode에서 핸들·종류·순서·최상위·정지 요청·복원 대기를 조회하고 시험 열기/닫기를 제공한다. 시험 상태를 원본 설정에 자동 저장하지 않는다.

추가 절차는 템플릿 생성 → 내용/상태 코드 작성 → 프리팹 연결 → 등록 → 검증이다. 기본 뷰/상태 예제를 제공하고 기존 파일을 덮어쓰지 않는다. 임의 타입 이름 문자열을 실행하는 방식은 사용하지 않는다.

기존 게임 UI의 직접 프리팹 참조를 유지한다. 새 Addressables 그룹·콘텐츠 빌드·모든 팝업 선로딩·풀링은 추가하지 않는다. 닫힌 뷰와 씬 종료 시 구독/리소스를 정리하며 보관 데이터는 에셋 핸들을 소유하지 않는다.

## 기존 팝업 전환

| 종류 | 보존할 동작 |
| --- | --- |
| 일시정지 | 정지 요청·해당 핸들 닫기로 재개·기존 재시작 연결 |
| 결과 | Outcome 표시·재시작/다음 레벨 잠금·오류 내용 갱신·결과 자체 보드 차단 |
| 설명 | 미션 설명·기존 눌러서 닫기·입력 차단 |

세 종류는 단일 인스턴스로 등록한다. 결과는 임의 뒤로가기로 닫지 않는 정책을 제안한다. 일시정지/설명은 뒤로가기로 닫을 수 있도록 제안한다. 복원 가능 여부는 명시적으로 등록하며 문맥 검증을 우회하지 않는다. 재시작/다음 레벨은 이전 문맥의 보관 상태를 무효화한다. Refresh가 닫힌 팝업을 반복 생성하거나 중첩 순서를 덮어쓰지 않게 한다. 기존 생성 도구를 재실행해도 공통 연결과 다음 레벨 버튼이 보존되어야 한다.

## 작업 분할과 완료 조건

상세 구현 계획과 별도 목표/완료 조건 문서는 설계 승인 후 작성한다.

| 단계 | 범위 | 관찰할 완료 조건 |
| --- | --- | --- |
| 1 | 관리·등록·표시·최상위 입력·정지 소유권 | A→B→C에서 B 제거 후 A→C와 C만 입력, 중복 정책, 키당 한 동작, 외부 차단/정지 보존 |
| 2 | 보관·문맥·복원 | 두 씬 왕복 내용/순서 복원, 미선택/문맥 변경은 복원 없음, 이동/복원 실패 정리, 명령/사운드 재실행 없음 |
| 3 | 도구·템플릿·기존 전환 | 템플릿으로 새 시험 팝업 추가, 등록 오류 검출, 런타임 조회, 기존 세 팝업과 재시작/다음 레벨 회귀 통과 |

EventSystem 포커스·마우스·터치·취소 입력, 화면 비율/안전 영역, 씬 종료/비활성화와 구독 정리를 Editor에서 검증한다. 기존 관련 검사는 영향 범위에 따라 선별한다. Android 물리 뒤로가기와 실기기 터치는 실제 수행 여부를 구분하고 미검증을 완료로 표현하지 않는다. 무관한 패키지·레벨·아틀라스·게임 규칙·GUID 변경이 없음을 diff로 확인한다.

## 다음 절차

설계서 검토/승인 → 상세 계획·별도 목표/완료 조건·복사용 목표 명령문 작성 → 계획 검토/실행 방식 선택 → 구현/검증. 이 문서는 구현 완료 기록이 아니다.
