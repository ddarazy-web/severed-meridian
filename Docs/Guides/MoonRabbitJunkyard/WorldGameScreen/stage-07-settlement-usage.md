# 7단계 제거·낙하·채움 사용 안내

[목표·완료 조건](../../../Goals/MoonRabbitJunkyard/WorldGameScreen/stage-07-settlement-goal.md) · [검증 기록](../../../Verification/MoonRabbitJunkyard/WorldGameScreen/stage-07-progress.md)

## 게임에서 확인

레벨 에디터에서 맵과 입력 소스(Asset 사본 또는 MemoryPack)를 고른 뒤 **게임 플레이**로 실행한다. 기존 스와이프, 두 칸 탭 교환, 파워 탭, 시험용 아이템 조작을 그대로 사용한다.

유효 교환 뒤 제거될 블록이 짧게 줄어들며 사라지고, 남은 블록과 공급 블록이 기록된 경로로 이동한다. 채움과 착지가 끝난 뒤 다음 자동 매칭이 이어진다. 잘못된 교환은 기존처럼 돌아온다. 제거·채움 중에는 보드와 아이템을 추가 조작할 수 없다.

포털은 입구에서 사라진 뒤 출구에서 나타난다. 공급원은 지정 경로가 있으면 그 방향을, 그렇지 않으면 해당 칸의 중력을 따른다. 공급되는 모습은 생성 칸 안에서 드러나므로 내부 생성구도 주변 장애물을 뚫고 나타나지 않는다. 고정 공급 목록이 끝나면 규칙상 남는 빈칸을 그대로 둔다.

일시정지는 현재 재생 위치를 유지하고, 재개하면 이어서 움직인다. 다시하기는 진행 중 연출을 정리하고 같은 초기 레벨·시드로 돌아간다. 화면 방향을 바꾸어도 보드 좌표를 기준으로 움직인다.

2026-10-01 변경: 대각선 채움은 이번 정착에서 공급원이 새로 만든 블록에만 허용한다. 기존 블록과 매칭으로 만든 파워는 대각선으로 이동하지 않는다. 상단에서 내려올 블록과 추가 공급을 먼저 처리하고, 그래도 채울 수 없는 칸에 신규 공급 블록이 대각선으로 들어간다. 다음 연쇄의 정착에는 신규 자격을 넘기지 않는다. 편집기 플레이 테스트와 게임 화면에 같은 규칙이 적용된다.

게임 화면의 낙하는 아래 블록의 도착을 기다리지 않고 뒤 블록도 함께 출발한다. 신규 공급 블록도 시작부터 공급구 바깥 대기열에 준비되어 이어서 내려오며, 내부 생성구에서는 대상 칸 안으로 들어온 부분만 보인다. 칸마다 낙하 속도를 다시 올리지 않고 연속 이동한다. 통로·경로·회수 순서와 최종 보드는 기존 규칙 기록을 유지하고, 모든 이동이 끝나면 착지한 뒤 다음 매칭을 진행한다.

## 표시 기준

9×9 보드, 2×2 장애물 확대, 가로 청소로켓의 중앙 보정·12% 확대를 유지한다. 바닥·덮개·먼지·벽·포털 장치와 2×2 본체는 낙하하지 않는다. 움직일 수 있는 고철·회수 부품은 규칙에 따라 이동하고 도착한 회수 부품은 사라진다.

세션 Inspector의 초기 연출 시간은 Swap 0.15초, Removal 0.12초, Fall 0.12초, Supply 0.16초, Landing 0.06초다. 긴 이동 구간은 거리를 반영하되 0.24초까지다. 사용자 옵션 메뉴는 추가하지 않았다. 시간 변경은 표시 속도만 바꾸며 게임 규칙이나 난수 결과를 바꾸지 않는다.

## 개발 검증

빌드 없이 `GameScreen.Editor.PuzzleSettlementAnimationVerification.Run`은 경로·상태 검사를, `RunScene`은 기존 게임 씬의 화면·반복 재시작·씬 재진입 검사를 실행한다. 두 진입점은 검사용이며 Play Mode로 들어가고 검사 결과를 `Logs/PuzzleSettlementAnimationVerification/`에 남긴다. **미저장 씬을 저장하지 않고 검사를 거절**한다. 별도 자동화 Editor에서 실행하는 경우 같은 프로젝트가 이미 열려 있지 않은지 먼저 확인한다.

기존 리소스가 준비된 프로젝트에서만 실행한다. 이 단계는 플레이어·Addressables 콘텐츠 빌드를 실행하거나 번들 누락을 빌드로 보완하지 않는다. 기존 사용자 Editor를 강제 종료하지 않는다.

파워 공격 궤적·폭발·드론 비행 등 상세 효과는 8단계, 소리·진동·미션 수집 비행은 9단계 범위다. 현재는 파워/아이템의 기본 제거·교체와 이후 정착을 보여준다. 실제 모바일 기기 성능과 터치 감각은 별도 확인 대상이다.
