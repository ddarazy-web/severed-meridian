## 실행과 동작

레벨 에디터에서 맵과 Asset/MemoryPack 입력을 선택하고 `게임 플레이`로 실행한다. 기존 스와이프와 파워 탭을 그대로 사용한다.

교환이 끝나면 필요한 효과 아틀라스를 준비하고, 실제 규칙 기록에 따라 파워의 발사·이동·타격을 재생한다. 대상의 내구도·덮개·먼지와 본체 제거는 해당 타격 시점에 바뀐다. 전체 효과가 끝난 뒤 기존 동시 낙하·신규 공급 대기열·착지·다음 연쇄가 이어진다. 준비와 재생 중에는 추가 입력·아이템·결과 패널 표시를 막는다.

| 대상 | 표시 |
| --- | --- |
| 청소로켓 | 불꽃 없는 대기 본체에서 발사 프레임으로 전환하고 양방향 이동·궤적·타격을 표시한다. 가로/세로와 십자·넓은 십자 조합을 실제 범위대로 표시한다 |
| 수집 드론 | 임의의 공중 위치까지 휘어 이동하고 서로 분리된 다양한 크기의 원 궤도를 선회한다. 프로펠러 4컷을 반복하며, 표적 예고 표시 없이 현재 위치에서 가속하는 곡선으로 돌진한다. 착탄 뒤 탑재 파워를 이어서 표시한다 |
| 폭탄·자석 | 기록된 폭발 범위, 선택 대상의 흡인과 파워 변환을 표시한다. 화면에서 다시 추첨하지 않는다 |
| 일반 매칭·파워 생성 | 일반 블록을 축소·투명화하고 5색 매칭 및 파워 생성 효과를 표시한다. 직접 매칭의 거미줄·먼지 변화도 반영한다 |
| 장애물 | 실제 손상마다 단계 이미지를 갱신한다. 2×2는 본체 한 개로 표현하고 별도 유효 타격은 보존한다. 발전기 완충과 마지막 연결 대상 제거에 따른 철거도 같은 타격에 반영한다 |

## 현재 표시 시간

- 일반 블록 축소·투명화: 0.12초. 일반 효과 4컷은 기본 0.20초, 폭발 8컷은 0.24초.
- 로켓 발사 준비: 0.06초. 한 방향 전체 비행은 거리 × 0.06초를 0.12~0.36초로 제한한다. 각 칸의 도착 시간은 그 방향의 거리 비율로 계산한다. 같은 본체의 실제 반복 손상은 물리 접촉 이후 최소 0.06초 간격으로 구분한다. 본체 단계 표시 간격이 로켓의 비행·착탄 시간을 바꾸지는 않는다.
- 드론 로터: 컷당 0.06초 반복. 출발점에서 1.4~2.6칸 거리의 임의 공중 위치를 선택하고 가장자리에서는 보드 안쪽으로 보정한다(최소 이동 거리 1.2칸). 혼잡하면 겹치지 않는 위치를 더 넓게 탐색한다. 이동은 0.32초, 전체 대기는 최소 0.72초다. 선회 반경 0.18~0.45칸·주기 0.65~1.05초·시계/반시계 방향·시작 각도를 개별 선택한다. 궤도 중심 간격은 두 반경의 합 + 0.96칸 이상 확보한다. 돌진은 거리 × 0.045초를 0.18~0.38초로 제한하며 곡선을 따라 가속한다. 선행 공격 종료 대기는 실제 발사 기록에 따른다. 실제 표적 재탐색이 있었다면 추가 0.18초 선회 후 새 표적으로 출발한다.
- 자석 흡인·변환: 0.35초. 변환 후 후속 파워가 발사된다.

시간은 표시 전용이다. 피해, 표적, 난수, 이동 수, 공급과 미션 계산을 재실행하지 않는다. 일시정지 중에는 준비가 완료돼도 표시 시간이 진행되지 않는다.

공중 위치와 선회는 표적 좌표를 사용하지 않는 표시 전용 난수로 선택한다. 게임 규칙 난수와 Unity 전역 난수를 소비하지 않는다. 드론 표적 표시는 재생하지 않는다.

## 리소스와 제한

기존 `Assets/Textures/PowerBlocks`와 `Effects` 이미지를 분리된 Addressables 아틀라스에서 읽는다. 사용한 효과 종류만 준비하며 세션 종료·재시작 시 아틀라스 소유권을 반환한다. 로드 취소 후 늦게 완료된 이전 요청은 새 세션을 갱신하지 않는다. 효과 객체는 기존 게임 장식 프리팹을 사용해 보드 아래에서 재사용한다.

드론은 512 시트 한 장을 Single Sprite로 아틀라스에 포함하고 사분면 마스크로 4컷을 표시한다. 가로 로켓의 발사 3·4컷에는 원본 본체 위치 차이를 보정하며, 이동 본체를 궤적보다 앞에 그린다. 이미지 보정이 어렵다면 본체 크기·중심·방향을 고정해 재생성할 수 있다는 사용자 지시가 우선한다. 이미지 크기는 2의 거듭제곱을 유지한다.

플레이어 및 Addressables 콘텐츠 빌드는 실행하지 않았다. Editor Play Mode 확인을 새 번들·실기기 검증으로 해석하면 안 된다. 필요한 이미지가 현재 배포 번들에 없다면 빌드를 임의 실행하거나 개별 텍스처 로드로 우회하지 않는다.

## 검사 진입점

네 단독 파워와 아래 10개 지원 조합을 모두 검사한다. 번호는 규칙 열거형과 검사 fixture에 대응한다.

| 조합 번호 | 조합 | Run/RunScene fixture |
| --- | --- | --- |
| 0 | 로켓 + 로켓 | 4 |
| 1 | 로켓 + 폭탄 | 5 |
| 2 | 로켓 + 드론 | 6 |
| 3 | 폭탄 + 폭탄 | 7 |
| 4 | 폭탄 + 드론 | 8 |
| 5 | 드론 + 드론 | 9 |
| 6 | 자석 + 로켓 | 10 |
| 7 | 자석 + 폭탄 | 11 |
| 8 | 자석 + 드론 | 12 |
| 9 | 자석 + 자석 | 13 |

- `GameScreen.Editor.PuzzlePowerAnimationVerification.Data`: 표시 기록·시간표·간접 제거 기록.
- `GameScreen.Editor.PuzzlePowerAnimationVerification.Run`: 실제 아틀라스와 보드의 중간 프레임·장애물·기본 세션 검사.
- `GameScreen.Editor.PuzzlePowerAnimationVerification.RunScene`: 실제 씬의 네 파워·10개 조합, 직접 실행기 동등성, pause/회전/취소/재시작 검사.

검사는 미저장 씬을 보존하며 결과와 캡처는 `Logs/Stage08`에 남긴다. 전체 회귀의 진입점·최신 결과와 미검증 항목은 검증 기록을 따른다. 소리·진동·미션 수집 비행·승패 상세 연출은 다음 단계다.
