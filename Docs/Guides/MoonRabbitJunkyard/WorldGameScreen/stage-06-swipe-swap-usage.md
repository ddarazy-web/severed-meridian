# 6단계 스와이프·교환 연출 사용 안내

[목표·완료 조건](../../../Goals/MoonRabbitJunkyard/WorldGameScreen/stage-06-swipe-swap-goal.md) · [검증 기록](../../../Verification/MoonRabbitJunkyard/WorldGameScreen/stage-06-progress.md)

## 게임에서 확인하기

2026-10-01 표시 순서 보완: 이동 가능한 블록을 누르면 주변 블록보다 앞에 표시한다. 손을 놓거나 입력을 취소하면 교환 진행 중에도 원래 순서로 복원한다. [검증 기록](../../../Verification/MoonRabbitJunkyard/WorldGameScreen/2026-10-01-swipe-sorting.md).

1. ServeredMeridian의 레벨 에디터에서 맵과 입력 소스(에셋 또는 MemoryPack)를 선택하고 `게임 플레이`로 실행한다. 기존 게임 씬 진입 방식을 그대로 사용한다.
2. 블록을 누른 채 상하좌우로 민다. 처음에는 블록이 조금 따라오고, 칸 너비의 약 1/4을 넘으면 **손을 떼기 전에 한 칸 교환**한다. 한 번 누른 상태에서는 한 번만 교환된다.
3. 매칭이 생기면 교환을 마친 뒤 매칭 결과가 표시된다. 매칭이 없으면 두 블록이 갔다가 돌아온다. 실패에는 이동 수를 소비하지 않는다.
4. 벽·고정 장애물·덮인 블록은 통과할 수 없다. 기존 규칙이 허용하는 고철·회수 부품과 파워 블록은 같은 교환 연출을 사용한다.
5. 기존 두 칸 탭 교환, 파워 한 번 탭 발동, 아이템 대상 선택도 사용할 수 있다. 교환·복귀 중 추가 보드 입력과 아이템 사용은 잠시 잠긴다.
6. 일시정지하면 교환도 멈추고 재개 시 이어진다. 다시하기는 진행 중 연출을 정리하고 같은 판을 다시 준비한다.

적용 대상은 **게임 씬의 월드 보드**다. 레벨을 배치·수정하는 편집 보드의 동작은 바뀌지 않는다. 교환 뒤 제거·낙하·채움은 아직 기존 즉시 표시이며 7단계 대상이다. 파워의 비행·폭발 등 상세 연출은 8단계 대상이다.

## 속도와 구조

PuzzleGameSession의 `Swap Seconds` 초기값은 0.15초다. 무효 교환은 이동과 복귀에 각각 이 시간을 쓴다. 입력 임계값은 보드 기준 0.25칸이고 화면 좌표 변환의 미세 반올림 오차만 허용한다. 기기 해상도에 따라 픽셀 임계값을 따로 두지 않는다.

게임 규칙은 기존 BoardActionExecutor가 한 번 계산한다. PuzzleBoardSwapPlayback은 점유자 그림만 움직이며, 완료 후 세션이 결과를 표시하고 다음 연쇄를 진행한다. 바닥·덮개·먼지는 칸에 남는다. 별도 이미지·패키지·프리팹 생성이나 레벨 데이터 마이그레이션은 필요하지 않다.

## Editor 검사와 제한

- `Tools > Match > 스와이프 교환 연출 검증`: 입력 경계, 중간 위치, 왕복, 파워/장애물, 재시작과 소유 자원 반환을 검사한다.
- `Tools > Match > 게임 화면 스와이프 검증`: 실제 게임 씬의 가로/세로 입력, HUD 반영 시점, 유효/무효 교환 연속 화면을 검사한다.
- 검사 전 미저장 씬을 보존한다. 검사는 Play Mode를 사용하며 원본 레벨을 저장하지 않는다. 로그와 화면은 `Logs/PuzzleSwipeSwapVerification/`에 기록된다.
- **플레이어·Addressables 콘텐츠 빌드는 실행하지 않는다.** 이 단계의 결과는 Editor Play Mode 검증이다. Android/iOS 실기기 터치·프레임 속도 검증을 대신하지 않는다.
