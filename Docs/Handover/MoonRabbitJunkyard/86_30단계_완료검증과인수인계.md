## 변경과 실패 이력

제품 결함은 난이도 카드의 **사례 확인**을 눌렀을 때 목록 갱신이 첫 선택을 지워 재생 버튼이 꺼지는 문제였다. `LevelAnalysisPanel.Difficulty.cs`에서 두 필터를 알림 없이 함께 바꾸고 한 번 갱신한 뒤 첫 사례를 선택한다. 예약 작업이 실행될 때 다른 기록/페이지로 바뀌었으면 선택하지 않는다. 수정 전 재현과 수정 후 실제 재생 증거를 모두 보존했다.

공통 편집·공급 검사의 과거 `보드 내부 스크롤 필수` 기대를 현재 계약인 `독립 창 최소 크기 확대 + 좁은 영역의 바깥 스크롤`로 갱신했다. 합격을 위해 제품 규칙을 완화하지 않았다. 추가 도킹 검사는 실제 DockArea를 사용했다. 처음에는 EditorWindow.position이 도킹을 해제해 실패했으며, 도킹 호스트 영역을 줄이는 방식으로 검사를 수정했다. 결과 화면의 초기 캡처가 읽기 중이었던 점도 기록하고 화면 갱신 후 다시 캡처했다.

검사 코드의 네임스페이스 누락/변수 이름 충돌, 일시적으로 되돌린 편집값의 dirty 기대 오류, 결과 폴더 오기는 제품 결함 수에 포함하지 않는다. 실패 기록을 삭제하거나 최종 PASS 파일로 덮어 없애지 않았다.

## 검사 수와 실행 기록

보관 취소의 임시 폴더 정리·원본 내부 내보내기 거절은 변경하지 않은 저장 코드와 `Logs/BotAnalysisVerification/core-results.txt`의 기존 실행 증거를 재사용했다. 30단계에는 보관 완료·동시 대상 생성·쓰기 실패·재열기 경계를 새로 실행했으며, 재사용한 취소 검사를 신규 횟수에 추가하지 않았다.

`final-counts.json`의 22개 최종 검사 결과에 있는 PASS/FAIL 행만 합산했다. 기본 구성의 최초 실패 파일과 재실행 전 실패 파일, 대기열 요약, 정적 링크 검사, 이전 단계 회귀 수를 중복 합산하지 않았다.

대표 신규 자동 플레이는 **600판**이며 결과는 기본 수집 성공 197/200, 통로·공급 180/200, 발전기·상자 196/200이다. 세 묶음 모두 두 전략 각각 100판, 실행 오류 0건이다. `new-batch-inventory.json`의 별도 실행 제어 검사에는 정상 종료 3판과 중단 기록 1판이 추가로 있으며 대표 평가 표본에 합치지 않는다. 저장 행동 재생은 새 자동 플레이가 아니다. 10×10 단일 조작 검사는 완주 판 수가 아니다. 합성 20,000판은 기존 판을 복제한 읽기 부하이며 실제 플레이로 세지 않는다.

기존 29단계 800판은 과거 증거다. 30단계 반복 시험으로 다시 세지 않았다. 버전은 기록 형식 1, board-action-items-v13, bot-session-v3, basic-bot-v1, planning-bot-v2, bot-observation-v1, public-assumption-v1, starting-board-dfs-v1, 평가 기준 bot-difficulty-v1이다.

## 데이터 보존

기존 739개 기준 파일에서 의도한 제품 UI 1개, 검사 2개와 관련 문서만 변경됐다. 공통 게임 실행기·봇 전략·공개 관찰·사용자 레벨·등록 맵·ProjectSettings·Packages는 변경되지 않았다. 신규 검사 파일과 Unity가 생성한 meta는 함께 둔다. 기존 시험 기록 812개는 최종 SHA-256 대조에서 변경 0개다. 검사 소유 임시 Assets 폴더는 정리했으며 도킹 검사 전 UserSettings 레이아웃도 동일 해시로 복원했다. 기존 사용자 수정과 미추적 파일은 되돌리지 않았다. 커밋은 수행하지 않았다.

## 제작자 사용 순서

1. **Match → 통합 작업창 → 레벨 편집**에서 레벨을 고르거나 맵 모양 목록으로 새 파일을 만든다.
2. 블록·장애물·공급·미션·연결을 편집하고 검사한다. 이름 변경 후에도 같은 에셋 참조가 유지된다. Ctrl+S로 저장하고 제목의 미저장 표시를 확인한다.
3. **플레이 테스트**로 시작 구성과 직접 조작을 확인한다. 시험은 원본 사본을 사용한다.
4. **새 반복 시험**으로 두 전략 각각 100판을 실행한다. 탭을 떠나면 일시정지하며 복귀 후 재개를 누른다. 중지 시 완료 기록은 남는다.
5. **결과·이력**에서 성공률·보류 사유·버전·과거 사본 안내를 읽는다. **사례 확인 → 재생 준비 → 자동 재생**으로 저장 행동을 확인한다.
6. 수정 후 새 시험을 만들고 이력 비교에서 정의·시드·규칙 차이를 확인한다. **같은 조건 재시험**은 이전 사본과 시드를 재사용하므로 현재 수정 내용을 시험하는 버튼과 구분한다.
7. 계속 보관할 결과는 보관 폴더로 내보낸다. Library의 로컬 기록은 Library 삭제 시 없어질 수 있다.

상세 절차는 [HTML 전체 작업 순서](../../MoonRabbitJunkyard/Manual/workflow.html), [분석·재생·보관](../../MoonRabbitJunkyard/Manual/analysis.html), [난이도 해석](../../MoonRabbitJunkyard/Manual/difficulty.html)에 있다. 후속 이관 항목은 이 HTML을 실제 브라우저의 넓은/좁은 창에서 열어 목차 이동·이미지·줄바꿈·가독성을 확인하는 일이다. 별도 후속 Goal을 자동 생성하지 않는다.
