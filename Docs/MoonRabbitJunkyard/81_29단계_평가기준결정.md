# 29단계 평가 기준 결정 — ADR-29-01

- 작성일: 2026-09-29.
- 상태: 실제 대표 레벨 검토 후 초기 기준 유지. [29단계 완료 기록](84_29단계_구현검증기록.md)에서 최종 증거를 확인한다. 아래 진행 설명은 각 시점의 이력이다.
- 근거: [29단계 작업 계획](78_29단계_난이도추천_작업계획.md).
- 선행: 28단계 20조건과 1,005 PASS / 0 FAIL 확인. 이 횟수를 29단계 실적으로 합산하지 않는다.

## 결정

1. AutoPlay/Runtime/Analysis/BotDifficultyRules는 기존 집계만 읽는 순수 계산이다. 파일·Editor·봇 실행을 호출하거나 원본을 수정하지 않는다.
2. 초기 버전은 bot-difficulty-v1이다. 대표는 두 전략 중 높은 성공률이며 동률이면 기본을 선택한다. 두 전략을 독립 200판으로 합산하지 않는다.
3. 초기 구간은 80/60/40/20%이고 반올림 전 판정한다. 양쪽 정상 종료 100판 이상, 예정 묶음 완료, 정상 시드 쌍 완전성이 필요하다.
4. 입력·버전 문제, 오류, 미완료·중단, 표본 부족, 양쪽 성공 0은 보류한다. 복수 이유를 함께 표시한다.
5. 계획 요구는 정상 쌍 100개 이상, 계획만 성공−기본만 성공 비율 20%p 이상, 서로 다른 결과 20쌍 이상에서만 표시한다.
6. 이동 여유 부족은 대표 성공 20판 이상, 성공 판의 남은 이동 수가 모두 기록되어 있고 중앙값이 최초의 10% 이하인 경우다. 이동 수 누락은 태그를 보류하되 성공률 입력이 충분하면 등급을 계산한다.
7. 무작위 영향은 시작 보드·봇 선택·공급의 영향을 분리할 자료가 없어 표시하지 않는다.
8. 항상 현재 기준의 재계산임을 명시한다. 과거에 저장하지 않은 등급을 당시 등급으로 표시하지 않으며 저장 형식도 바꾸지 않는다.
9. 통계 위쪽 요약과 접을 수 있는 근거를 제공한다. 이력 비교에도 같은 기준을 적용하고 대표 전략을 표시한다.
10. 재생과 평가의 호환성은 다르다. 평가는 기본/계획·관찰·가정 버전까지 현재 지원 버전과 같아야 한다. 비호환 기록의 기존 통계 조회는 유지한다.

## 대안과 한계

기본 전략만 쓰면 계획 전략이 찾은 풀이를 놓치고, 두 전략 평균은 봇 구성 비율에 영향을 받는다. 높은 쪽을 쓰면 이를 줄이지만 낙관적인 추정이 될 수 있어 두 성공률과 대표 전략을 함께 표시한다. 인간 체감 난이도나 태그의 인과관계를 검증한 값이 아니다.

대표 레벨 3개와 한 레벨의 새 시드 재시험 후 초기 기준의 유지·수정 이유를 기록한다. 원하는 등급이 나오도록 기록을 꾸미지 않는다.

## 현재 증거

- Logs/BotDifficultyVerification/baseline-hashes.json 및 baseline-status.txt에 사용자/선행 변경을 보존 기준으로 저장했다.
- core-results.txt: 합성 표본 29 PASS / 0 FAIL. 등급 경계 전후, 표본 부족, 성공 0, 전략 역전, 태그 경계, 이동 수 누락, 중단/입력/버전 보류와 입력 불변을 검사했다.
- 합성 표본은 실제 플레이가 아니다. 실제 UI와 대표 레벨 실행·회귀·완료 감사는 진행할 작업이다.

## 추가 검증 진행 기록

- 분석 화면 회귀를 새 추천 카드가 포함된 상태로 다시 실행했다. `Logs/BotDifficultyVerification/analysis-ui-results.txt`에 결과를 보존했다. 실제 보류 화면을 확인하고 `Manual/images/difficulty-hold.png`에 보관했다. 이는 성공 등급·모든 태그 UI 검증을 대신하지 않는다.
- 실제 기본 수집 레벨 200판: 기본 95/100, 계획 98/100 성공, 매우 쉬움. 실행 약 93.38초.
- 실제 한 수 도전 레벨 200판: 기본 46/100, 계획 47/100 성공, 보통·이동 여유 부족. 실행 약 13.60초.
- 복합 레벨의 첫 시도는 내부 블록 없이 거미줄을 배치한 시험 코드 때문에 정합성 검사에서 거부되었다. 실제 게임 실행 오류나 패배가 아니다. 시험 정의에 내부 블록과 배치 성공 검사를 추가했다. 첫 실패 기록은 `runs-first-attempt.txt`로 보존하며 완료된 두 묶음을 다시 실행하지 않는다.
- 복합 레벨과 기본 수집의 새 시드 재시험은 진행 중이다. 원시 기록 위치는 `Logs/BotDifficultyVerification/runs-path.txt`, 진행 상태는 `runs-progress.txt`, 완료 집계는 `runs-results.txt`에서 확인한다. 모두 이 단계에서 새로 실행한 실제 게임이며 합성 표본과 분리한다.
- 위 결과만으로 기준을 보정하거나 인간 체감과의 일치를 주장하지 않는다. 대표 시험 완료 후 기준 유지·변경 여부와 새 시드 변동을 검토한다.
- `manual-links.txt`: 수정한 HTML 네 페이지의 내부 링크·앵커·이미지·CSS 경로 정적 검사 통과. 브라우저 렌더링 확인과는 구분한다.
- `protected-files.txt`: 29단계 시작 기준의 원본 레벨·등록 맵·설정·패키지 34개 파일 해시 일치. 최종 완료 전 다시 대조한다.
- 남은 검증용 UI·경계 검사 소스는 실행 중인 Unity의 재컴파일을 피하기 위해 임시로 `Logs/BotDifficultyVerification/BotDifficultyVerification.UI.cs`, `BotDifficultyVerification.Edges.cs`에 준비했다. 아직 컴파일·실행하지 않았으므로 검사 실적에 포함하지 않는다. 현재 반복 시험 종료 확인 후 기능의 Editor/Tests 폴더로 옮겨 실행한다.

## 실제 시험 완료와 기준 검토

위 진행 기록 이후 네 묶음, 실제 800판이 모두 완료되었다. `runs-results.txt`는 최종 실행 집계, `independent-rates.txt`는 PowerShell로 원시 판 기록을 따로 집계한 대조 증거다. 결과를 골라 버리거나 추가 시드로 대체하지 않았다.

| 구성 | 기본 성공 | 계획 성공 | 예상 등급 | 태그 | 소요 시간 |
|---|---:|---:|---|---|---:|
| 기본 수집 | 95/100 | 98/100 | 매우 쉬움 | 없음 | 93.38초 |
| 한 수 도전 | 46/100 | 47/100 | 보통 | 이동 여유 부족 | 13.60초 |
| 상자와 거미줄 | 88/100 | 97/100 | 매우 쉬움 | 없음 | 613.47초 |
| 기본 수집 새 시드 | 94/100 | 99/100 | 매우 쉬움 | 없음 | 155.08초 |

기본 수집의 두 기록은 정의 지문이 같고 시드 묶음은 다르다. 성공률이 기본 −1%p, 계획 +1%p 변했지만 등급·태그는 같았다. 한 수 도전의 성공 판 남은 이동 중앙값은 양쪽 0, 복합 구성은 기본 3·계획 4였다. 복합 구성이라는 이유만으로 어려움을 강제하지 않는다.

초기 80/60/40/20 구간과 태그 기준은 유지한다. 세 정의만으로 경계를 재보정할 근거가 부족하고 인간 평가 자료도 없기 때문이다. 이번 실제 기록에서는 계획 요구 태그가 발생하지 않았으며 그 경계는 합성 검사로 확인한다. 기록 실행 시간은 이 PC의 관찰값이지 성능 보장값이 아니다.

경계 검사를 기능의 Editor/Tests 폴더에 옮겨 Unity에서 실행했다. `edges-results.txt`: 10 PASS / 0 FAIL. 전부 오류·전략 누락·시드 불일치·미실행·일시정지·중단·잘못된 이동 수를 보류하고 동일 입력 10,000회 결과 일치를 확인했다. 순수 추천 10,000회 약 9.95ms이며 파일 읽기·화면 표시는 포함하지 않는다. UI 검사는 별도 실행 중이며 최종 감사는 아직 완료하지 않았다.

## UI와 정합성 보완

- 저장 사본의 정합성 오류를 `BotAnalysisReader.DefinitionIssue`로 별도 보유하고 난이도 보류에 전달한다. 기존 통계 읽기는 유지한다. 지문 일치만으로 잘못된 레벨 정의를 추천하지 않는다.
- `difficulty-ui-results.txt`: 실제 Unity 창 62 PASS / 0 FAIL. 네 실제 기록의 등급·표본·근거 펼치기·대표 사례·탭 이동·새 시드 비교, 내보내기, 과거 전략 버전, 잘못된 정의, 손상·누락 보류를 확인했다. `difficulty-success-0.png`, `difficulty-success-1.png`는 실제 창 캡처다.
- 첫 UI 시도는 내보내기 완료 파일 확인에서 실패했다. `difficulty-ui-first-attempt.txt`에 보존했다. 화면 오류 메시지를 기록하도록 검사를 보강한 재실행은 통과했지만 최초 원인은 확정하지 않았다. 최종 감사에서 관련 회귀와 재현 여부를 추가 확인한다.
- 추천 카드에 두 전략의 정확한 성공률을 함께 표시했다. 성공 사례 매뉴얼 캡처를 추가했으며 영향받는 기존 분석 로더·통계 회귀를 실행 중이다. 20조건 완료 처리는 아직 하지 않았다.
