## 목표와 범위

Match 수동 시험에서 고물 망치·자리 바꾸기·섞기와 시작 부스터 세 종류를 사용할 수 있게 한다. 게임과 시험이 같은 공통 실행기를 사용하며 Editor가 보드를 직접 고치지 않는다. 시험에서는 수량을 무제한으로 제공하되, 실제 사용 성공·배치 완료와 취소·대기·실패를 기록으로 구분한다.

실제 인벤토리, 주문 해금, 5분 무한 사용 타이머, 광고·결제·보상 반환·영구 저장은 구현하지 않는다. 시험용 무제한을 출시 게임의 해금·비용 규칙 변경으로 해석하지 않는다. 24단계 전체 수동 통합, 봇·통계와 새 장애물도 제외한다.

## 현재 코드와 변경 책임

22단계 완료 코드와 최종 증거를 기준으로 한다. `board-action-ending-v12`, `shuffle-v1`, `settlement-recovery-v8`, `recovery-v1`을 이어받는다. 착수 시 이후 변경 여부를 다시 확인하고 새 기준 해시를 확보한다. 22단계 `final-source-hashes.json`은 비교 근거이며 현재 파일을 과거 상태로 되돌리는 용도로 사용하지 않는다.

필요하면 실행기 partial 파일을 아이템·부스터 책임으로 나눈다. 파일명·새 타입은 구현 시 실제 규모에 맞춰 정하고 빈 인터페이스·별도 엔진·새 asmdef·패키지는 만들지 않는다. 레벨 정의에 시험 선택값을 저장하지 않는다. 보드 사본, 행동 기록, 부스터 대기열은 각 플레이 세션에 귀속한다.

## 확정 규칙의 실행 계약

### 게임 중 아이템

세 아이템 모두 안정된 미종료 보드에서만 실행한다. 이동 수를 소비하지 않지만 성공한 사용과 전체 후속 연쇄를 독립된 한 수로 처리한다. 이전 수의 파워 보호·피해 제한을 갱신하고, 새 파워 보호와 본체별 피해 제한은 유지한다. **곰팡이는 아이템 사용 뒤 확산하지 않는다.** 턴 번호를 0으로 속이는 대신 이동 수 소비 여부 또는 행동 원인을 실행 문맥에 표현한다.

| 아이템 | 처리 |
|---|---|
| 고물 망치 | 한 칸 직접 타격. 일반 제거, 노출 파워 발동, 장애물 1피해. 덮개 제거 타격은 내용물을 보존한다. 금고·색깔 자물쇠에도 직접 피해, 폐가전은 공유 내구도 1피해, 발전기는 기존 한 수 충전 제한 적용. 회수 부품·빈칸 등 효과 없는 대상은 거절한다. |
| 자리 바꾸기 | 상하좌우의 이동 가능한 두 블록을 벽을 넘지 않고 교환. 매칭이 없어도 유지한다. 파워끼리도 위치만 교환한다. 고철·회수 부품의 기존 이동 조건을 적용하고 고정 장애물·덮인 블록·빈칸은 제외한다. 완성된 일반 매칭은 정상 처리한다. |
| 섞기 | 확인 후 공통 재배치 실행. 일반·파워만 섞고 방향·수량·제외 대상·바닥·공급을 보존한다. 완성 매칭 없음과 유효 행동 존재를 검사한다. 실패 후보는 커밋하지 않는다. |

망치 직접 타격은 먼지를 손상시키지 않는다. 망치로 발동한 파워나 이후 정상 매칭의 먼지 처리는 기존 규칙을 따른다. 일반 제거를 공통 함수로 합치면서 이 원인 차이를 잃지 않도록 한다.

선택·취소·잘못된 대상·섞기 실패에는 사용 성공 기록과 비용 발생 기록을 남기지 않고 보드·이동 수·턴·실행 난수를 보존한다. 실패 진단은 별도 표시한다. 아이템 섞기 실패를 자동 재배치의 진행 불가 종료로 연결하지 않는다. 불가능 증명과 탐색 한도도 구분한다.

효과가 시작된 뒤 후속 연쇄 오류는 미실행 취소와 다르다. 실행된 사용 기록을 유지하고 22단계의 실행 중단 진단으로 처리하며 성공한 척 되돌리지 않는다. 성공·이동 수 소진·진행 불가·라스트팡 중에는 새 아이템을 받지 않는다.

### 시작 부스터

- 청소로켓 → 달 폭탄 → 무지개 자석 순서로 종류별 최대 1개를 선택한다. 드론은 제외한다.
- 시작 보드 구성과 초기 정규화 뒤 입력을 받기 전에, 교체 가능한 일반 블록을 무작위로 골라 파워로 바꾼다. 덮인 블록·장애물·회수 부품·기존 파워는 제외한다.
- 배치는 수집·피해·발동·이동 수 소비가 아니다. 로켓 방향은 실제 배치 순간 무작위로 정한다.
- 후보가 부족하면 나머지는 순서대로 대기한다. 후속 연쇄와 낙하가 끝난 안정 경계에서 다시 시도한다. 후보가 없으면 난수를 불필요하게 소비하지 않는다.
- 종료 조건이 충족되면 판 종료를 우선한다. 대기 부스터로 패배를 연장하거나 라스트팡 도중 새로 배치하지 않는다. 판이 계속될 경우 대기 부스터를 배치한 다음 유효 행동·자동 재배치를 판단한다.
- 실제 배치된 항목만 배치 완료로 기록한다. 종료까지 대기한 항목은 미사용이다. Editor는 무제한 시험 표시를 하고 실제 인벤토리를 차감하지 않는다.
- 재시작 화면은 선택을 초기화한다. 같은 선택·시드·행동으로 재현하면 배치 위치·방향·대기 해소·난수 결과가 같아야 한다.

초기 정규화·종료 판정·부스터 배치 순서는 22단계 완료 코드에 맞춰 한 안정 경계에서 조정한다. 부스터 배치와 사용자 행동을 중복 호출하는 별도 Editor 처리 루프는 만들지 않는다.

22단계 실행기는 생성 시 초기 도착 회수를 정규화하며, 안정 경계에서 성공·소진·행동 조회·자동 재배치를 처리한다. 따라서 부스터 선택은 실행 세션을 만들 때 전달하고, 세션 생성 후 Editor가 뒤늦게 보드를 수정하는 방식은 사용하지 않는다. 일반 턴은 기존 곰팡이 판정 → 성공/소진 → 대기 부스터 배치 → 행동 조회/자동 재배치 순서를 유지한다. 아이템 턴은 같은 경계를 쓰되 곰팡이 확산만 생략한다. 부스터를 배치하지 않은 기존 호출과 재현 결과도 보존한다.

## Match 화면

시작 전 부스터 선택은 세 칸 한 줄, 플레이 중 아이템도 세 버튼 한 줄을 기본으로 한다. 기존 메뉴 시작점 `Match`와 창 구성을 유지하고 ‘시험용 · 수량 무제한’을 표시한다. 부스터 선택은 플레이 시작 후 잠그고 대기/배치 상태를 보여준다.

아이템 선택 중 다른 아이템 버튼은 흐리게 비활성화한다. 일반 교환·파워 직접 발동·연쇄 실행과 충돌하지 않도록 입력 모드를 하나만 유지한다. 취소 버튼 또는 같은 아이템 버튼으로 취소하고, 잘못된 대상은 선택 상태를 유지한다. 자리 바꾸기의 첫 칸과 교환 가능한 이웃을 강조하며 첫 칸 재선택은 첫 선택만 해제한다. 인접하지 않은 이동 가능 칸은 새 첫 선택으로 바꾼다.

망치는 대상 클릭 즉시, 섞기는 확인 후 실행한다. 선택 중 일시정지는 제공하지 않는다. 창 비활성화·편집 복귀·재시작·레벨 변경 시 대상 선택을 해제한다. 이는 Editor 수명 처리이며 실제 기기 홈 전환·앱 복구 구현은 아니다.

기존 Editor 검증 방식을 재사용한다. 각 아이템의 정상·잘못된 대상·취소, 아이템 후 성공과 라스트팡, 파워 보호, 아이템 후 곰팡이 미확산, 자리 바꾸기로 회수 도착, 부스터 대기 해소와 종료 우선 순서를 포함한다. 보드/미션/공급 커서/난수/행동·배치 기록을 비교한다. UI 검증과 코드 단위 검증을 혼동하지 않는다.

최신 연결 포트·이동통로·낙하 경로·합류 컨텍스트 초기화 회귀를 유지한다. 결과에는 수행하지 못한 검증을 명시하고 임시 검증 에셋만 정리한다. 이번 문서 작성은 구현 또는 Goal 실행을 뜻하지 않는다.

선행 완료 근거는 `Logs/RoundEndVerification/final-counts.txt`, `preservation-audit.txt`, `final-source-hashes.json`과 22단계 목표 문서다. 23단계에서는 별도 증거 경로를 사용하고 이전 단계의 완료 기록을 덮어쓰지 않는다.
