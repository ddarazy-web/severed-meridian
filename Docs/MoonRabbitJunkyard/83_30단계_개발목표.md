- 계획: [30단계 작업 계획](82_30단계_전체통합검수_작업계획.md).

## 목표

Match 창에서 편집·저장·수동 플레이·자동 반복 시험·통계와 난이도 확인·사례 재생·이력 비교까지 연결하여 검수한다. 재현된 결함을 필요한 범위에서 수정하고, 제작자가 사용할 수 있는 절차와 제한 사항을 근거와 함께 남긴다.

## 실행 원칙

1. 현재 Goal과 29단계 완료 증거를 먼저 확인한다. 같은 30단계 Goal이면 이어가고 다른 활성 Goal은 덮어쓰거나 임의 완료 처리하지 않는다. 선행 미완료 시 남은 조건을 보고하고 30단계 실행에 착수하지 않는다.
2. ponytail·프로젝트 Unity 지침을 적용하고 중요한 설계 충돌만 grill-me로 확인한다. deep-planning은 사용하지 않는다.
3. 작업 전 사용자 변경·원본 레벨·등록 맵·기존 기록·설정의 보존 기준을 확보한다. 임시 복사본으로 파괴적 오류 상황을 검사한다.
4. 기존 검사와 실제 작업창을 사용한다. 공통 실행기와 봇 관찰 경계를 보존하며 통합 검수를 이유로 새 기능·패키지·대규모 구조 변경을 추가하지 않는다.
5. 계획의 대표 3개 레벨과 최소 한 레벨의 신규 100시드×두 전략 실행을 충족한다. 재사용 기록의 정의·버전 호환성을 확인하고 실제 판 수와 합성 검사를 구분한다.
6. 결함은 원인과 영향 범위를 먼저 확인하고 최소 수정 후 재현 검사와 관련 회귀를 실행한다. 기존 판정 기준을 테스트 통과 목적으로 완화하지 않는다.
7. 29단계의 난이도 기준을 재설계하거나 인간 체감 난이도 검증 완료로 표현하지 않는다. 과거 결과·현재 편집·현재 기준 재계산을 구분한다.
8. 실제 UI·저장·재로드·성능의 증거를 남긴다. 검증 불가 항목은 실패와 구분하되 완료로 처리하지 않는다.
9. 한국어 주석·HTML 매뉴얼·기능별 검증표·제작자 인수인계를 갱신한다.
10. 이번에는 30단계만 진행한다. 출시·실제 게임 UI·서버·결제 등 후속 개발로 확대하지 않는다.
