## 공통 구조와 유지할 조건

- 게임과 수동/자동 시험은 현재 `Assets/Scripts/Features/PuzzlePlay/Runtime`의 같은 규칙 실행기를 사용한다(기존 `Assets/Scripts/Simulation`에서 기능별로 이동). 모드마다 별도 매칭·낙하 엔진을 작성하지 않는다.
- Editor는 화면·입력을 담당하고 봇은 행동 선택만 담당한다. 공개 관찰 데이터에는 숨은 색/파워, 공급 목록, 실제 시드/난수 상태를 넣지 않는다. 내부 진단 기록은 분석기에만 전달한다.
- 계획 전략도 실제 실행 상태 전체를 복제해 미래 난수를 훔쳐보는 방식을 금지한다. 공개 정보에서 만든 가정 상태와 별도의 가정 난수를 사용한다.
- 일반/고속 테스트의 규칙 결과는 같아야 한다. 고속은 연출 대기만 생략한다. 연쇄 단계 실행을 곧바로 사용자용 실시간 연출이라고 표현하지 않는다.
- 레벨 원본 사본, 정의 지문·알고리즘/전략 버전·시드·행동 기록으로 재현한다. 레벨 수정 시 이전 통계를 현재 결과로 표시하지 않는다.
- 신규 묶음은 중복 없는 새 시드들로 구성하며 두 전략에 같은 묶음을 사용한다. 재검사는 저장된 묶음을 재사용한다.
- 기본 화면에는 실행·일시정지/재개·중지·진행률·요약 결과를 우선한다. 전략 파라미터를 레벨마다 다수 조정하게 하지 않는다.
- 승패를 명확히 집계한다. 사용자 중지, 처리 한도, 미지원 규칙, 데이터 오류를 일반 패배나 어려운 레벨로 집계하지 않는다.
- 중지 시 완료된 판을 보존하고 미완료 판은 별도 표시한다. 구체적 중지 경계·기록 보관 한도·탐색 예산은 해당 단계 설계에서 확정한다.
- 5단계 난이도 임계값과 원인 태그 기준은 아직 미정이다. 임의 숫자를 검증된 인간 체감 난이도로 발표하지 않는다.

## 완료 게이트

1. **수동 완료(24):** 확정된 편집 요소를 실제로 플레이할 수 있고, 아이템/부스터·승패·막힘·재시작·원본 보존을 검사한다. 미지원 요소를 조용히 무시하지 않는다.
2. **봇 완료(27):** 두 전략의 정보 접근 제한과 공통 조작 검증, 동일 시드 비교, 중단 제어가 실제 실행으로 입증된다.
3. **평가 완료(30):** 통계가 원시 판 기록과 일치하고 오류/중단/과거 버전을 구분하며, 추천 근거와 사례 재생이 연결된다.

무작위 레벨 생성/구성 추천, 상점·광고·결제, 주문 화면, 출시용 런타임 화면/아트, 서버 동기화와 실제 기기 앱 복구 구현은 별도 범위다. 앱 복구를 위한 규칙 상태의 재현 가능성은 보존한다.
