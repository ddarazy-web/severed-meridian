## 첫 실행과 재검사

- workflow-before-refresh.txt: 저장·dirty·이름 변경·복제·메뉴 이동 일시정지 검사까지 통과. 두 레벨 완료 조건에서 실패했다.
- 원인: 검사 시작 때 만든 창의 시험 목록이 이후 복제한 레벨을 포함하지 않았다. 제품에는 선택 도구 → 레벨 목록 새로고침 명령이 있으므로 검사에서 이 사용 순서를 수행하고 두 개 선택을 선검증하도록 보완했다. 제품 코드는 변경하지 않았다.
- 최초 실행 실제 2판. 동일 흐름 재검사 4판을 추가하므로 성공 시 신규 누적 6판이다. 실패를 숨기거나 4판으로 보고하지 않는다.
- 첫 전용 Unity 프로세스 139424 종료를 확인한 뒤 재검사 프로세스 151688을 시작했다.

- 메뉴 및 임시 기록 회귀는 별도 전용 프로세스로 진행하며 새 플레이는 없다.

## T4 실제 배치와 재로드 검사 진행

- Presentation 검사에서 실제 DockArea 다섯 화면의 스크롤/끝 영역 접근, 각 화면 최소 크기 메뉴/탭 접근, 중복 이름 거절, 입력 포커스 상태 Ctrl+S가 통과했다.
- 최초 검사 코드의 text 속성 직접 대입은 컴파일 실패하여 reflection으로 입력 텍스트를 설정하도록 고쳤다. 제품 변경은 없다. 실패 로그: presentation-compile-failure.log.
- 실제 도메인 재로드는 Unity 로그에서 완료됐으나 delayCall 후속 검사 결과가 기록되지 않았다. 프로세스 110456은 응답 중이며 별도 모달이 없는 것을 확인한 뒤 검증 전용 프로세스만 종료했다. presentation-reload-callback-stall.log와 presentation-before-reload.txt에 보존했다. 이 재로드 결과는 완료 증거로 세지 않는다.
- 기존 재로드 검사의 직접 EditorApplication.update 등록 방식으로 변경해 재실행했다. 결과는 아직 감사 전이다. 추가 게임은 0판.
- 중단된 Presentation 검사가 만든 Assets/__Stage33Presentation_* 임시 폴더는 마지막 Unity 검사에서 소유 범위를 확인하고 정리해야 한다.

## T4 재로드 재검사 통과

- presentation-results.txt에서 실제 같은 프로세스 도메인 재로드, 중단 기록 보존, 자동 실행 없음, 중단 기록 조회와 창 재열기를 확인했다. 프로세스 151496 정상 종료.
- 실제 메뉴 팝업 검사의 ShowMenu reflection 가정은 현재 Unity ToolbarMenu API와 맞지 않았다. 제품 결함이 아닌 검사 진입점 오류이며 menu-capture-api-failure.txt에 보존했다. 실제 NavigationSubmit 이벤트 방식으로 검사를 변경했다.
- 실제 메뉴 캡처·검사 소유 잔여 폴더 정리·최종 보존 대조·문서 링크 감사가 남아 있다.

## 실제 메뉴 표시 확인 방식

- ToolbarMenu는 Windows 네이티브 #32768 메뉴를 연다. Unity EditorWindow 팝업 목록에서 찾는 검사는 이 구현에 맞지 않았다.
- 검증 프로세스 148004의 메뉴 HWND 14617326 소유권을 확인하고 PrintWindow로 해당 메뉴만 캡처했다. open-menu-native.png를 직접 열어 새 레벨, 저장, 복제, 이름 변경, 등록한 맵 모양, 레벨 데이터 검사 표시를 확인했다. 미선택 명령 비활성도 화면에서 확인했다.
- 네이티브 메뉴는 이벤트 호출을 반환시키지 않아 자동 검사 타임아웃이 발생했다. 이 검사 실패를 제품 오류/자동 통과로 바꾸지 않는다. 부적절한 EditorWindow 팝업 가정의 검사 코드는 제거하고 메뉴 표시 증거는 실제 캡처의 수동 시각 검수로 분리했다.
- 최종 화면/임시 정리 코드에 경로 문자 이스케이프 컴파일 오류가 한 번 발생해 DirectorySeparatorChar로 수정했다. 실패 로그 final-ui-compile-failure.log 보존.

### 남은 제한

HTML 브라우저 배치 검수는 기존 사용자 승인대로 후속 이관한다. 정적 경로 검사는 완료했으나 브라우저 렌더링 완료를 뜻하지 않는다. 이번 단계는 메뉴 변경 구간의 제작 흐름 검수이며 전체 20,000판 밸런스, 사람의 체감 난이도, 모바일/IL2CPP 빌드를 검증하지 않았다. 33단계 이후 작업은 자동 시작하지 않는다.
