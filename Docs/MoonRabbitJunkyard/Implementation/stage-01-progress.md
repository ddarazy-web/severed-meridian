# 1단계 실행 기록

계획: [stage-01-world-board-plan.md](stage-01-world-board-plan.md)

- 작업 1: 기존 데이터·이미지·목업 확인. 레벨 팩은 `Assets/Data/LevelPacks/levels-000001.bytes`, 실행 레벨은 1. BoardEdge는 A/B, 배선 좌표는 셀 중심이 아닌 격자 꼭짓점이다.
- 작업 2: 완료. 파워 매핑 검사 RED(런타임 매핑 없음) → GREEN(8개 종류/방향 조합이 실제 이미지 경로로 해석됨). Unity 컴파일 및 비동기 로드/해제 검사 성공.
- 작업 3: 월드 코드와 프리팹 4개 생성. 배치 초기의 미저장 빈 씬 때문에 Additive 생성이 실패해 해당 배치 초기 상태에서만 Single 생성하도록 수정. 재실행 성공. 사용자 편집 씬에는 기존 Additive 방식을 유지한다.
- 작업 4~5: 완료. MemoryPack 단독 씬 로드와 실제 번들 Play Mode 통합 검사 174개 PASS, 실패 0. 기존 편집/플레이 테스트 회귀 22개 PASS.

## 실행 판단

- 기존 작업 경로와 무커밋 지시를 우선하여 현재 `work` 브랜치에서 진행한다. 별도 체크아웃/자동 커밋은 하지 않는다.
- 이미지 매핑을 순수 경로 계산과 아틀라스 소유권으로 분리했다. 기존 Editor 코드를 런타임에 의존시키지 않고 비교·검증 가능하게 한다.
- 이 단계는 초기 상태 표시이므로 LevelStateBuilder를 사용한다. 플레이 가능한 시작판 탐색과 게임 규칙 실행은 2단계에 남긴다.
- 기존 아틀라스 로더는 취소 인수를 받지 않으므로 진행 중 로드를 완료한 다음 소유 핸들을 해제한다. 종료 후 화면 적용은 하지 않는다.

검증 로그: `Logs/WorldBoardVerification-*`, `Logs/WorldBoard-generate*`, `Logs/WorldBoard-play.log`, `Logs/WorldBoardVerification/` (로컬 산출물).

## 독립 검토 및 수정

- 독립 검토에서 배선 PNG의 투명 여백 때문에 선분 사이 틈을 발견했다. 알파 영역을 측정한 검사가 0.928125칸으로 실패함을 확인한 뒤 가로/세로 크기를 각각 1.2/1.25로 보정했다. 벽도 같은 검사로 1.18/1.38로 보정했다. 꺾인 배선과 연속 벽의 가시 길이가 1칸 이상임을 최종 검사와 캡처로 확인했다.
- 검토에서 지적한 실제 로드 중 객체 파괴와 경계 좌표 검증 빈틈을 추가 검사로 보완했다.
- 초기 캡처에서 잘못된 텍스처가 보인 적이 있었으나 이후 실행과 최종 번들 실행에서 재현되지 않았다. 스프라이트/텍스처 이름 진단, 실제 색상 픽셀 검사, 최종 캡처를 확인했다. 최초 현상의 원인을 확정하거나 별도의 제품 코드 수정으로 해결했다고 주장하지 않는다.
- Edit Mode 회귀 검사의 완료가 늦어 프로세스 상태를 확인했으나 자체 완료되어 22개 PASS를 기록했다. Play Mode 대체 경로는 사용하지 않았고 임시 코드를 제거했다.
- 일부 배치 프로세스는 검사 결과를 저장한 뒤 Mono 종료 단계에 남아 프로젝트 잠금을 유지했다. 해당 실행의 명령행/로그를 확인해 소유한 검사 프로세스만 정리했다. 이를 테스트 실패나 다른 Unity 프로젝트의 문제로 해석하지 않는다.

## 남은 범위

모바일 실기기와 플레이어 빌드는 미검증이다. 입력·매칭·승패 연결, 에디터 실행 버튼, HUD와 효과 연출은 후속 단계다. 현재 정적 상태의 초기 매칭 여부는 플레이 가능 판정으로 취급하지 않는다. 상세 사용법은 [사용 문서](stage-01-world-board-usage.md)를 참조한다.
