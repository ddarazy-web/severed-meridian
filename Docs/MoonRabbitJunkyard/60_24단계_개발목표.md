## 최종 구현과 검증 범위

`LevelInitialStateWindow.Manual.cs`가 기본 플레이 진입·시작·요약·상세 진단·재시작·편집 복귀를 담당한다. 기존 Execution/Items의 명령 뒤 자동 연쇄를 예약하며, Query와 창 수명 처리에서 오래된 주기 작업을 해제한다. LevelEditorWindow에 진입 버튼을 추가하고 기존 USS에 해당 모드 스타일만 보완했다.

공통 Simulation 소스의 기준 해시는 그대로다. 새 규칙 엔진·저장 형식·asmdef·패키지를 도입하지 않았다. Unity 6000.3.10f1에서 검증했으며 공통 실행기 버전은 `board-action-items-v13`, `power-effects-items-v9`, `settlement-recovery-v8`, `shuffle-v1`, `recovery-v1`을 유지한다. 최종 파일 지문은 final-source-hashes.json에 기록한다.

검증 코드는 ManualPlayIntegrationVerification.cs(UI/재현), .Reload.cs(실제 도메인 재로드), .Regression.cs(기존 검사 호출/새 증거 기록)로 분리했다. 테스트용 에셋만 저장·삭제하며 사용자 에셋을 강제로 저장하지 않는다.

화면: manual-wide.png, manual-narrow.png, manual-scrolled.png, manual-result.png. 화면 검토 후 중복 결과·진단 문구를 줄이고, 기본 화면에서 시작 후 부스터 선택줄을 숨기되 배치/대기 표시를 유지했다. 상세 진단에서는 기존 단계별 실행과 검사 정보를 확인할 수 있다. 680×480에서는 보드를 스크롤한다.

실제 UI 조작은 Unity UI Toolkit 이벤트와 보드 버튼을 사용했다. 도메인 재로드는 RequestScriptReload 후 정적 상태 초기화 및 같은 PID를 확인했다. 독립 프로세스 재현은 별도 검사이며 실제 앱 강제 종료 복구를 뜻하지 않는다. 지원 요소별 검사는 대표 정상/경계 사례이지 모든 배치의 전수 검사나 인간 체감 난이도 검증은 아니다.

출시용 아트·애니메이션·런타임 화면·앱 복구·광고/결제·재화·봇·통계·난이도 평가·25단계는 구현하지 않았다. 다음 작업은 로드맵의 25단계 봇 관찰 경계와 기본 전략이며 별도 요청으로 진행한다.
