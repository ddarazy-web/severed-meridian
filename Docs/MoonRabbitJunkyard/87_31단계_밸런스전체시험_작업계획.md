# 31단계 작업 계획 — 밸런스 기능의 개발 오류 검증

- 작성일: 2026-09-29.
- 상태: 개발 오류 검증 완료. 최종 증거는 89번 기록을 따른다. 2026-09-29 사용자 지시에 따라 개발 중 20,000판 실행은 중단하고 소규모 오류 확인으로 변경했다. 제품 기능의 전체 범위는 유지하며 실제 전체 실행은 최종 검증으로 이관한다. [검증 진행 기록](89_31단계_검증진행기록.md)을 따른다.
- 목표 문서: [31단계 개발 목표](88_31단계_개발목표.md).
- 선행: [30단계 완료 기록](86_30단계_완료검증과인수인계.md), [자동 플레이·밸런스 기획](10_자동플레이와난이도분석.md), [현재 사용 방법](Manual/difficulty.html#move-balance).

## 이번 단계가 필요한 이유

30단계 이후 등록 맵 사용 현황·미사용 삭제, 이동 횟수별 밸런스 시험, 난이도 네 단계 통일을 추가했다. 개발 중에는 저장·추천·제어·재조회에 오류가 있는지 작은 검사로 확인한다. 이미 실행한 13개 완료 구간 2,600판을 재사용하여 불필요한 반복 실행을 줄인다. 사용자의 최신 지시가 초기의 전체 시험 필수 조건을 대체한다.

기존 증거는 실행 시 다시 대조한다. 아래 수치를 새 검증 실적으로 합산하지 않는다.

| 현재 확인된 내용 | 증거 | 남은 확인 |
|---|---|---|
| 밸런스 기능 33개, 기존 반복 UI 21개, 당시 난이도 경계 29개 검사 | `Logs/BalanceVerification` | 개발 중 저장·재조회 오류 확인. 전체 범위는 최종 검증 |
| 검증용 레벨의 이동 1·2회, 각각 실제 200판 및 31단계 보존 구간 | 같은 폴더의 `actual-root.txt`, `Logs/Stage31Workflow` | 기존 완료 구간 재사용·미완료 상태 구분 |
| 네 단계 통일 후 경계·보류 검사 31개 | `Logs/FourGradeVerification` | 최종 기준으로 전체 결과·이력 화면 대조 |
| 등록 맵 사용 현황·삭제와 관련 저장 회귀 | `Logs/ShapeUsageVerification` | 밸런스 사본이 맵 사용 수와 원본을 변경하지 않는지 |

기존 실패 기록도 보존한다. 요약 저장의 일시 파일 잠금은 제한 재시도로 보완했다. 기존 반복 UI 검사에서는 특정 시드의 재배치 탐색 한도가 발생했다. 새 시드 재시험의 통과만으로 그 엔진 문제까지 해결됐다고 판단하지 않는다.

## 유지할 확정 규칙

- 제품의 밸런스 기능은 이동 횟수 **1~100회 전체**, 횟수마다 기본·계획 각 100판, 총 **20,000판**을 유지한다. **개발 검사에서 이를 매번 실행하지 않는다.** 실제 전체 시험은 별도 최종 검증에서만 실행한다.
- 한 시험 안에서는 같은 100개 시드를 모든 횟수·두 전략에 사용한다. 새 시험은 새 시드 묶음을 만든다.
- 원본 레벨을 보존하고 사본의 이동 횟수만 바꾼다. 봇은 공통 게임 실행기와 공개 관찰 정보만 사용한다.
- 공통 난이도는 **쉬움 ≥60%, 보통 ≥40% 및 <60%, 어려움 ≥20% 및 <40%, 매우 어려움 >0% 및 <20%**다. 두 전략 중 높은 성공률을 기준으로 한다. 매우 쉬움은 제공하지 않는다.
- 성공 0%·오류·미완료는 추천에서 제외한다. 같은 등급의 연속 정수만 범위로 표시한다. 네 등급을 모두 얻으려고 맵이나 결과를 조정하지 않는다.
- 일시정지 후 재개·중지가 가능하다. 탭 복귀는 자동 재개하지 않는다. 창 종료·재컴파일은 중단 기록과 완료된 횟수 결과를 남긴다. 진행 중 게임의 재시작 복원은 이번 범위에 추가하지 않는다.
- 추천은 제작자가 선택하는 참고값이다. 원본 자동 적용, 사람의 체감 난이도 보정, 새 봇 전략·장애물·게임 화면·서버·결제는 제외한다.

## 실행 순서와 확인 방법

| 순서 | 작업 | 종료 판단 |
|---|---|---|
| T1 | 현재 Goal·실행 중 Unity·최신 규칙·선행 증거 확인, 사용자 파일 보존 기준 확보 | 실행 중 시험을 중복 시작하지 않으며 파일·GUID·기존 기록의 비교 기준 확보 |
| T2 | 대표 레벨 사본과 작은 오류 재현 사례 선정 | 맵·미션·공급 구성, 선정 이유, 원본 경로와 사본 지문 기록 |
| T3 | 기존 UI 실측을 재사용하고 부족한 동작만 작은 사례로 검사 | 완료 구간 재사용 근거, 필요한 새 판 수·목적 기록. 20,000판 재실행 없음 |
| T4 | 보존된 완료 구간 원시 기록과 네 등급·범위를 대조 | 완료 구간별 두 전략 100판, 동일 시드, 이동 수 외 조건 동일. 1·100회 경계는 작은 별도 검사로 확인 |
| T5 | 별도 작은 시험에서 일시정지·중지·탭 이동·닫기·재컴파일·재시작·저장 오류 확인 | 중간/완료/오류 구분, 입력 잠금, 완료 결과 보존 및 재조회 |
| T6 | 실측 결과 중 하나로 임시 레벨 이동 수를 선택·저장하고 다시 열기 | 추천을 선택한 제작 흐름과 dirty·저장·맵 사용 현황 연결 확인 |
| T7 | 실제 최소 창·도움말·개발 검사 비용·관련 회귀 검사 | 필수 버튼과 추천 접근, 관측 비용 기록, 영향 범위 회귀. 전체 성능은 후속 이관 |
| T8 | 발견 결함 최소 수정, 검증표·매뉴얼·인수인계 작성 | 목표 조건별 증거 및 남은 한계를 구분하고 보존 기준 최종 일치 |

## 대표 시험과 오류 처리

대표는 정상적인 공급과 명확한 미션을 갖춘 검증용 레벨의 사본을 사용한다. 기존 정의·실측 기록이 적합하면 재사용한다. 한 레벨의 성공은 모든 장애물 조합의 완전성을 의미하지 않는다. 장애물·연결·공급별 영향은 기존 호환 검사와 필요한 작은 추가 시험으로 보완한다. 저장 오류 주입·조회·범위 계산에 새로운 자동 플레이를 요구하지 않는다. 실행 제어는 필요한 몇 행동만 진행하고, 완료 구간 보존은 기존 실측 사본을 우선 재사용한다.

개발 검사에서도 정의 JSON·지문·시드·실행/전략/평가 버전·결과 경로를 기록한다. 확보한 완료 묶음의 각 200개 원시 판과 수량을 대조한다. 실패·중단을 정상 패배에 섞거나 일부 기록을 전체 완료로 표시하지 않는다. 1·100회 경계와 누락·중복은 작은 구성/실행 검사 및 합성 범위 검사로 확인하며 전체 실측과 구분한다.

실행 오류가 나면 실패 시드와 정의를 보존하고 같은 조건으로 원인을 재현한다. 정합성 문제, 엔진 탐색 한도, 저장 실패, UI 문제를 구분한다. 필요한 수정 후 영향 검사를 수행하며, 실행 조건이나 판정을 바꾼 경우 이전 부분 결과를 새 조건의 전체 결과에 합치지 않는다. 성공할 때까지 시드를 골라 실패를 숨기거나, 검사 통과를 위해 탐색 한도·등급 기준을 임의로 완화하지 않는다.

개발 중 전체 시험을 자동 재시작하지 않는다. 검사 프로세스 상태를 확인하고 중복 Unity 실행을 피한다. 오류 주입은 별도 사본·저장소에 수행한다. 완료한 호환 검사는 변경 영향이나 증거 부족이 있을 때만 다시 실행한다.

## 결과 재조회·성능·문서

`Library/Match/MoveBalance`의 요약과 원시 기록을 종료 전후 비교한다. Library 정리 시 함께 사라지는 로컬 기록이라는 현재 한계를 명시하고, 검증 증거는 완료 보고서에서 추적 가능한 위치로 보존한다. 새로운 클라우드 저장이나 범용 보관 기능을 만들지 않는다.

개발 검사에서 관측한 시간, 요약/원시 파일 수와 용량, 메모리, 일시정지·중지 응답과 재조회 시간을 기록한다. 일부 실행의 측정값을 전체 20,000판 성능으로 일반화하지 않는다. 측정으로 드러난 문제만 필요한 범위에서 수정한다.

코드는 `Assets/Scripts/Features/<기능>/<역할>`에 배치한다. `AutoPlay/Runtime/Analysis`, `Editor/Application`, `Editor/Storage`, `Editor/Presentation`, `Editor/Tests`의 책임을 유지하며 복잡한 처리에는 한국어 주석을 보강한다.

HTML 안내의 내용·상대 링크·도움말 경로와 실제 Unity 화면은 검증한다. **HTML 브라우저 배치 검수는 기존 사용자 승인에 따라 별도 후속 항목으로 유지**한다. 접근 차단을 우회하지 않으며 이를 이번 단계의 완료 검증으로 표시하지 않는다.

## 산출물

- 조건별 실행 증거를 연결한 31단계 진행·완료 기록.
- 대표 정의·시드·버전과 재사용한 실제 완료 구간, 필요한 작은 신규 검사, 독립 집계표와 네 난이도 표시 검증.
- 실패 재현·수정·회귀 기록, 전체 결과와 별도 중단/오류 검사의 구분.
- 실제 UI 캡처, 성능 측정, 원본 보존 대조, 한국어 사용 안내와 남은 제한.

이 문서 작성만으로 위 산출물이 확보됐다고 표시하지 않는다.

## 별도 최종 검증으로 이관

실제 전체 검증을 진행할 때 대표 레벨의 1~100회, 두 봇 각 100판씩 20,000판을 실행하고 100개 완료 묶음·원시 기록·추천 범위·전체 소요 시간·장기 메모리를 확인한다. 이번 중단 기록을 전체 완료로 합치거나 개발 Goal에서 전체 시험을 자동 재개하지 않는다. 이번 단계 완료는 개발 오류 검증 완료이며, 전체 실측 완료와 별개다.
