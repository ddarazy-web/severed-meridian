## 목적과 확정 범위

쌓인 로컬 시험 기록을 정리하고, 여러 레벨 시험의 이전 실행 결과를 다시 선택해 확인할 수 있게 한다. 사용자는 2026-09-29에 전체 삭제 대상으로 **반복 시험·이동 횟수 추천·여러 레벨 시험의 세 종류**를 선택했다. 레벨 원본과 따로 내보낸 파일은 유지한다.

이번 단계는 기존 통합 작업창을 확장한다. 새 창이나 탭을 만들지 않고, 기록 목록과 삭제 동작을 기존 결과·이력 및 여러 레벨 시험 화면에 연결한다. 삭제는 사용자 확인 창에서 대상과 범위를 보여준 뒤 실행한다. 계획 작성이나 개발 검사 과정에서 사용자의 실제 기록을 지우지 않는다.

2026-09-29 추가 요청: 기존 툴에 통합하고 기능을 확실히 구분한다. 여러 레벨 시험은 `지난 시험 조회`와 `새 시험 실행` 제목으로 구분하고, 삭제는 두 기존 탭 아래쪽의 접을 수 있는 `기록 관리 · 전체 삭제` 영역에 배치한다. 별도 제품 창이나 메뉴는 추가하지 않는다.

## 현재 코드에서 확인한 내용

| 기록 종류 | 저장 위치 | 현재 구조 |
|---|---|---|
| 단독 반복 시험 | `Library/Match/AutoPlay` | `BotBatchStore`, `BotAnalysisArchive`와 기존 이력 화면 사용 |
| 단독 이동 횟수 추천 | `Library/Match/MoveBalance` | 실행별 결과와 하위 반복 시험, 최근 기록 포인터 사용 |
| 여러 레벨 시험 | `Library/Match/MultiLevelTests` | 실행별 `queue.json`, 레벨 순번별 하위 결과, `latest.txt` 사용 |

`MultiLevelTestStore.Load()`는 현재 최근 실행만 읽는다. 이전 실행 폴더는 보존되지만 선택 목록이 없다. 한 여러 레벨 실행에 속한 반복/추천 결과는 해당 실행 폴더의 하위 기록이며 별도 최상위 실행으로 중복 집계하지 않는다.

기존 `IsAnalysisBlocked`는 실제 진행 중 상태 중심이다. 삭제 잠금에는 이를 그대로 쓰지 않고 `HasPendingTest`, `CanContinue` 등 재개 가능한 일시정지 상태까지 확인해야 한다.

## 화면과 동작

### 지난 여러 레벨 시험

- 여러 레벨 시험 탭에 `지난 시험` 목록과 `새로고침`을 제공한다. 실행 시각·시험 종류·레벨 수·상태로 구분하며 최근 순서로 표시한다.
- 처음 열면 기존처럼 최근 실행을 선택한다. 이전 실행을 선택하면 그 실행의 레벨별 결과와 추천 횟수를 기존 상세 화면으로 보여준다.
- 이력 조회는 시험 시작·자동 재개·레벨 원본 수정·최근 저장 포인터 변경을 일으키지 않는다.
- 실행 중이거나 재개 가능한 시험이 있으면 다른 실행으로의 전환을 잠그고 이유를 표시한다. 중지/완료 후 조회할 수 있다.
- 손상·누락·버전 불일치 기록은 오류를 표시하고 다른 정상 기록 조회를 계속 허용한다. 창 재열기 후 중단 기록을 자동 재개하지 않는 기존 정책을 유지한다.

### 기록 전체 삭제

- 기존 결과·이력 화면의 기록 관리 영역에 `시험 기록 전체 삭제`를 둔다. 여러 레벨 시험에서도 같은 동작에 접근할 수 있게 한다.
- 확인 창에는 세 종류별 실행 수와 전체 삭제 범위를 표시한다. 레벨 원본과 내보낸 파일은 유지되며 되돌리기 기능이 없다는 점을 짧게 알린다. 취소가 기본 선택이다.
- 삭제 단위는 세 저장 위치의 프로그램 소유 기록이다. 사용자가 임의로 연 외부 결과 폴더를 삭제 대상으로 삼지 않는다.
- 실행·일시정지·재개 대기·결과 내보내기 중에는 삭제를 막는다. 삭제가 시작되면 신규 시험 시작과 중복 삭제를 막는다.
- 목록 읽기·상세 분석·사례 재생을 중단하고 삭제 후 선택, 비교 결과, 캐시, 진행 표시를 실제 남은 파일에 맞춰 초기화한다.
- 빈 목록에서는 삭제를 비활성화한다. 일부 삭제 실패 시 삭제한 수와 실패한 수·이유를 표시하고 실패 기록을 다시 조회할 수 있게 한다.
- `latest.txt`가 삭제된 실행을 가리키지 않게 정리한다. 남은 유효 기록이 있다면 가장 최근 실행으로 복구하고, 없다면 포인터를 제거한다. 동일 시각은 실행 ID로 순서를 고정한다.

이번에는 개별 기록 삭제, 휴지통/복원, 자동 보관 기간, CSV 비교표, 중단 시험 이어 실행을 추가하지 않는다.

## 구현 구조와 보존 원칙

- `Assets/Scripts/Features/AutoPlay/Editor/Storage`: 실행 목록 조회와 소유 기록 삭제. 기존 저장 형식과 저장 클래스를 우선 재사용한다.
- 같은 기능의 `Application`: 필요한 삭제 수명주기와 시험 상태 조정. 실제 책임이 생길 때만 파일을 추가한다.
- 같은 기능의 `Presentation`: 기존 기록/여러 레벨 화면, 확인 창, 오류 표시와 도움말.
- 같은 기능의 `Tests`: 임시 저장 루트를 사용한 저장·삭제·화면 검사.
- 통합 창은 화면 연결과 공통 사용 중 상태를 전달한다. 게임 규칙·봇 전략·난이도 기준은 변경하지 않는다.
- 경로를 절대 경로로 정규화하고 허용된 저장 루트 내부인지 확인한다. 상위 경로 이동, 심볼릭 링크/정션 등을 따라 외부 파일을 지우지 않는다. 알 수 없는 파일은 임의 삭제하지 말고 남긴 항목으로 알린다.
- 큰 기록을 열거·삭제할 때 한 번에 모든 원시 판을 읽거나 Editor를 오래 멈추지 않는다. 진행 상태를 표시하며 기존 갱신 예산 방식을 재사용한다.
- MemoryPack 전환, 패키지 변경, 새 범용 매니저나 저장 프레임워크 도입은 포함하지 않는다. 한국어 주석으로 경로 검증·상태 잠금·부분 실패 처리 이유를 설명한다.

## 작업 순서와 검증

| 작업 | 구현 내용 | 확인 방법 |
|---|---|---|
| T1 현황과 보존 기준 | 관련 저장/화면 호출부, 시험·읽기·내보내기 수명주기 확인 | 기존 원본과 기록 목록을 읽기 전용으로 확보 |
| T2 지난 실행 조회 | 여러 레벨 실행 목록과 ID로 조회하는 기능 | 정상/중단/손상 기록이 섞인 임시 목록, 정렬·최근 선택 검사 |
| T3 전체 삭제 | 세 루트 소유권, 포인터, 부분 실패, 상태 잠금 | 임시 루트에서 취소·성공·파일 잠금·외부 경로 거절 검사 |
| T4 화면 연결 | 목록 선택, 확인 창, 빈 상태, 캐시/비교/재생 정리 | 실제 Unity 창에서 전환·일시정지 잠금·삭제 후 재조회 확인 |
| T5 회귀와 사용 안내 | 관련 회귀 검사, 한국어 HTML 도움말·검증 기록 | 컴파일, 링크/앵커 확인, 원본·기존 기록 보존 대조 |

검사는 소유한 임시 기록과 기존 기록의 사본으로 한다. 합성 기록은 실제 플레이 결과로 보고하지 않는다. 동작 확인에 새 플레이가 필요하면 작은 표본만 실행하고 판 수를 기록한다. **20,000판 전체 실행이나 여러 레벨 장시간 시험은 이번 단계에서 실행하지 않는다.**

HTML 안내는 `Manual/analysis.html`, `Manual/difficulty.html`의 관련 항목을 갱신하고 `i` 도움말에서 해당 위치로 연결한다. 브라우저 배치 검수는 기존 승인대로 후속 이관하며, 정적 링크 확인과 실제 Unity 화면 검사는 별도로 기록한다.

## 제외 및 완료 보고

실제 사용자 기록 삭제, 전체 밸런스 실측, 사람의 체감 난이도 검증, 모바일 빌드, 무작위 레벨 생성과 게임 출시 기능은 이번 범위가 아니다. 완료 보고에는 조건별 증거, 실제/합성/재사용 검사 구분, 보존 결과와 미검증 항목을 남긴다.
