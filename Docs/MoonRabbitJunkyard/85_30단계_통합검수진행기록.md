## 보존 기준과 증거

`Logs/LevelWorkflowVerification/baseline-hashes.json`에 소스·에셋·설정·패키지·문서 739개 파일을 기록했다. `baseline-status.txt`에 기존 수정·미추적 파일을 남겼다. `record-baseline.json`에는 기존 기본 저장소와 29단계 대표 기록의 812개 파일 해시를 기록했다. 선행 구현과 사용자 에셋도 이번 단계의 보존 대상이다.

실제 UI 검수는 검사 소유 `Assets/__LevelWorkflow_<고유값>` 에셋을 사용한다. 새로운 시험은 별도 Logs 하위 저장소를 주입해 기존 기록에 추가하거나 기존 최근 기록 포인터를 변경하지 않는다. 기존 패널 초기화의 읽기/복구 동작이 실제로 파일을 변경하는지도 최종 해시로 대조한다.

## 대표 레벨 선정

1. 기본 매칭·수집: 29단계 기본 수집의 정의를 임시 에셋으로 가져온다. 인스펙터에서 이동 수를 편집·저장하고 이름을 바꾼 뒤 수동 아이템 조작·재시작·새 반복 시험·추천·사례 재생까지 이어간다. 기존 시드와 기록은 새 실행에 사용하지 않는다.
2. 흐름·공급: 이동통로/낙하 경로와 지정 공급을 포함하는 유효한 정의를 구성한다. 편집 UI에서 연결·공급을 변경한 값이 저장과 실행에 전달되는지 확인한다. 세부 정의와 시드는 구성 후 기록한다.
3. 복합 장애물·연결: 발전기와 대상 장치가 연결된 유효한 정의를 구성한다. 연결 후보·전선과 장애물·미션이 실제 플레이에 반영되는지 확인한다. 세부 정의와 시드는 구성 후 기록한다.

최소 각 전략 100판 완료 기록을 확보한다. 세 정의의 개별 연결 목적이 다르므로 모든 장애물을 한 보드에 넣지 않는다. 원하는 난이도 등급을 얻기 위한 결과 선별은 하지 않는다. 29단계 기록 재사용 시 신규 실행과 분리해 표기한다.

## 확인한 문서 차이와 처리 방향

09번 기획에는 통합 창이 세 탭인 시점의 설명이 남아 있지만 현재 구현은 결과·이력을 포함한 네 탭이다. 10번 기획의 기준 미정·시간 미측정 문구는 후속 29단계 결정 및 측정 기록보다 오래됐다. 새 설계로 해석하지 않고 최종 인수인계에서 최신 문서와 구현을 연결한다. 봇 반복 시험의 탭 복귀는 자동 재개하지 않으며 수동 연쇄의 재개 규칙과 구분해야 한다.

자동 맵 생성·새 장애물·서버·결제·실제 게임 UI·출시 검증·인간 체감 보정은 이번 범위 밖이다. HTML 브라우저 렌더링과 운영체제 클립보드의 기존 검증 한계는 통합 검수에서 재확인하며 확인하지 못한 기능을 완료로 표시하지 않는다.

## 실행 이력

- 첫 검증 코드 컴파일에서 `Simulation` 네임스페이스가 누락된 오류를 수정했다. 게임 기능 결함이 아니라 이번 검사 코드 오류이며 `basic-compile-first.log`에 보존했다. 컴파일 실패한 검사 소유 프로세스만 종료하고 재실행했다.
- `LevelWorkflowVerification.Basic`은 실제 UI 이벤트로 편집·Ctrl+S·이름 변경·수동 조작·신규 반복 시험·결과 조회·사례 재생을 연결한다. 완료 증거가 나오기 전까지 통과로 세지 않는다.
- 첫 UI 시도는 이동 수를 7로 바꾼 직후 6으로 되돌리는 절차에서 dirty 기대값이 맞지 않았다. `basic-first-results.txt`에 보존했다. 실제 변경값 7을 유지하고 저장하는 절차로 수정한 재실행은 편집·저장·이름 변경·수동 조작·재시작을 지나 신규 200판을 진행 중이다. 원인을 제품 결함으로 확정하거나 수정했다고 주장하지 않는다.
- 현재 검사 프로세스의 신규 실행 상태는 `basic-progress.txt`, 완료 결과는 `basic-results.txt`에 기록한다. 완료 전에는 이전 실패 파일이 남아 있으므로 프로세스와 진행 파일의 현재 상태를 함께 확인한다.
- 기본 구성의 실제 UI 신규 200판은 두 전략 각각 100판, 오류 0으로 완료됐다. `basic-record.txt`가 원시 묶음을 가리킨다. 결과 조회·같은 정의 안내·난이도 표시는 통과했으나 사례 이동 뒤 첫 사례 선택이 지워져 재생 버튼이 비활성화되는 연결 결함을 발견했다.
- `case-selection-before.txt`: 별도 새 Unity 프로세스로 같은 기록을 열어 `index=-1`, 사례 100판, 재생 비활성을 재현했다. 반복 시험을 다시 실행하지 않았다.
- 수정: `LevelAnalysisPanel.Difficulty.cs`에서 두 필터 값을 알림 없이 함께 변경하고 목록 갱신을 한 번만 수행한다. 목록 갱신 뒤 첫 사례를 선택하며, 그 사이 기록/화면을 바꿨으면 선택하지 않는다. `basic-result-check-results.txt`에서 첫 사례 선택·재생 버튼 활성·실제 저장 행동 완전 재생을 확인했다. 다른 필터·기록 이동에 대한 영향 회귀는 계속 진행한다.
- 흐름 대표 구성은 5×5 활성 보드, 각 열 상단 공급, 한 생성구의 랜덤 파워 1개 후 일반 공급, (4,0) 통로 입구→(2,4) 출구(0부터 세는 좌표)를 사용한다. 실제 드래그로 출구를 정하고 합류 후보를 명시한 뒤 저장·수동 조작·UI 반복 시험으로 연결한다. 실행 결과 확인 전에는 통과로 세지 않는다.

## 후속 확인과 남은 증거

- `flow-results.txt`: 이동통로 드래그·합류 정합성·실제 인스펙터 편집·Ctrl+S·이름/GUID·수동 조작·재시작·일시정지/탭 복귀·신규 200판·난이도·실제 사례 재생·원본 보존·임시 에셋 정리가 모두 PASS다. 기본 구성 200판과 별개의 신규 실행이다.
- 발전기 구성은 현재 실행 프로세스 PID 57704를 조회하여 살아 있음을 확인했다. 완료 여부는 `connections-results.txt`와 원시 묶음으로 판정한다. 진행 파일의 마지막 숫자가 199에서 끝나더라도 완료 결과와 대조하기 전에는 실패로 판단하거나 재실행하지 않는다.
- `records-preserved.txt`: 기존 812개 기록을 SHA-256으로 재대조했고 변경 0개다. `current-baseline-differences.txt`의 제품 소스 변경은 사례 선택 결함 수정 파일 하나이며 기존 공통 실행기·전략·관찰 코드에는 변경이 없다. 최종 감사 때 다시 대조한다.
- `manual-links.txt`: 현재 HTML의 파일·이미지·문서 내 위치 링크 448개를 검사했고 없는 대상은 0개다. 이 검사는 브라우저 렌더링이나 실제 클릭을 대신하지 않는다.
- 기존 `LevelWorkspaceLayoutVerification`은 편집·수동·초기 배치 3개 탭과 좁은 컨테이너의 스크롤을 검사한다. 네 번째 결과 탭과 실제 도킹 자체를 이 검사만으로 검증했다고 표시하지 않는다. 난이도 화면 검사 및 별도 실제 창 증거로 부족한 범위를 보완해야 한다.
- `run-remaining.ps1`에는 공통 편집/재시작, 공급/재시작, 연결·통로·경로·합류, 수동 플레이/재시작/재로드, 봇 제어/재로드, 합성 20,000판 조회 검사를 준비했다. 스크립트 작성은 검사 통과가 아니며 실행 결과를 각각 연결한다. 기존 대기열과 동시 실행하지 않는다.

## 영향 회귀와 검사 갱신

- `shape-results.txt` 49 PASS, `save-results.txt` 15 PASS, `layout-results.txt` 324 PASS, `difficulty-results.txt` 67 PASS이며 각 신규 실행에 FAIL은 없다. 이 수치는 검사 발생 횟수이며 신규 게임 판 수가 아니다.
