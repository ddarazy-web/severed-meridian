## 목표와 현재 상태

Match 수동 시험과 공통 실행기에 고정 장애물 세 종류의 피해·파괴·미션·드론 예약을 연결한다. 폐가전의 공유 내구도와 반복 타격을 정확하게 처리하고, 색깔 자물쇠의 인접 색 조건 및 자석 예외를 실제 실행에 적용한다.

계획 시 18단계 감사에서 2,045 PASS/20조건을 확인했고, 최종 소스 해시와 현재 `Assets/Scripts`의 차이는 0이었다. 활성 Goal은 없다. 실행 시 이 기준을 다시 확인한다.

착수 전 확인한 코드와 구현 간격:

- `ObstaclePlacementDefinition`에 세 종류·색·내구도가 있고 `LevelPlacementRules`에 2×2 점유와 내구도 상한이 있다. 저장 모델을 새로 만들 필요가 없다.
- `RuntimeObstacle`의 내구도와 셀의 `ObstacleIndex`로 본체 공유가 가능하다. 현재 피해·실행·정착은 상자/고철 외 본체를 거절한다.
- `PowerEffectResolution`은 피해 시 턴당 피격 이력을 등록하고, 파괴 시 맞은 셀만 비운다. 폐가전은 네 칸 동시 제거가 필요하다.
- 인접 매칭 피해는 변경 칸 목록을 순회한다. 매칭 직후에는 색/내용물이 바뀌므로 원래 색을 사용해야 하고, 평탄화된 변경 목록만으로는 서로 별개의 매칭을 구분하기 어렵다.
- 드론의 현재 예상 진행량은 칸별 기여 합산이다. 공유 내구도 2에 서로 다른 두 칸의 1피해가 예약된 경우를 본체 제거 예정 1개로 계산해야 한다.
- 초기 보드 창에 장애물명·내구도·자물쇠 색의 기본 표시가 있다. 이를 확장하고 별도 플레이 창을 만들지 않는다.

## 범위와 선택

| 접근 | 장점 | 한계/선택 |
|---|---|---|
| 종류별 지원 플래그만 해제 | 가장 작은 변경 | 인접 색·반복 피해·네 칸 제거·예약 합산이 틀리므로 제외 |
| 기존 실행기에 타격 단위와 본체 단위 규칙 추가 | 기존 게임/시험 규칙 재사용, 필요한 의미만 보강 | 채택. 매칭→효과→미션→예약 호출부를 함께 검증 |
| 범용 이벤트/장애물 플러그인 프레임워크 신설 | 임의 규칙 확장 가능 | 이번 요구보다 크므로 제외 |

19단계 내부는 금고 → 자물쇠 → 폐가전 → 드론/화면 → 통합 순서로 진행한다. 한 종류만 구현한 상태를 19단계 완료로 보고하지 않는다. 발전기·연결 대상 자동 제거는 20단계, 회수는 21단계, 실제 승패·섞기·라스트팡은 22단계다. 망치 등 아이템 입력/비용/사용 턴은 23단계에 연결하며 이번에 가짜 아이템 동작을 만들지 않는다. 봇·통계·난이도, 장애물 등장 레벨, 아트 제작과 앱 복구도 제외한다.

## 적용할 게임 규칙

### 금고

- 고정 1칸, 내구도 1~5. 일반 매칭으로 손상되지 않고 파워 직접 타격으로만 피해를 받는다.
- 한 수의 전체 연쇄에서 본체당 최대 1피해. 다음 수에는 다시 피해 가능하다.
- 파괴하면 빈칸이 되고 기존 낙하/공급으로 채운다. 내부 보상이나 고정 장애물을 새로 공급하지 않는다.
- 미션은 완전히 파괴한 본체당 1개. 드론은 해당 미션이 남고 이번 수 피해받지 않은 금고를 후보로 삼는다.

### 색깔 자물쇠

- 고정 1칸, 내구도 1~3, 지정 색 유지. 같은 색 일반 블록의 상하좌우 인접 매칭 또는 색과 무관한 파워 직접 타격으로 피해를 받는다.
- 매칭 참여 칸이 파워 생성 칸으로 남아도 인접 피해를 인정한다. 원래 일반 블록의 색과 선택된 유효 매칭을 기준으로 한다.
- 벽 너머 인접 피해는 차단한다. 한 수 전체 최대 1피해, 제거 미션은 색을 구분하지 않고 본체당 1개다.
- 자석의 색 제거는 자물쇠를 직접 색 대상으로 고르지 않는다. 같은 색 인접 일반 블록을 실제 제거했을 때만 자물쇠에 인접 피해를 준다. 덮개 때문에 실제 제거되지 않은 블록은 이 예외의 근거가 아니다.
- 자석+파워의 색 변환만으로 인접 피해를 주지 않는다. 이후 직접 파워 타격은 정상 처리한다. 자석+자석은 색 제거가 아닌 전체 직접 타격이다.
- 다른 파워가 옆 일반 블록을 제거한 사실만으로 색 인접 피해를 주지 않는다. 드론 직접 타격에는 색 조건이 없다.

### 대형 폐가전

- 고정 2×2, 공유 내구도 1~9. 내구도가 남으면 네 칸 모두를 막고, 파괴 시 네 칸을 함께 비우며 바닥 먼지는 보존한다.
- 파워 개별 타격은 맞은 서로 다른 칸마다 1피해, 한 타격 최대 4피해다. 이후 별도 효과/연쇄는 같은 칸도 다시 타격한다. 턴 전체 4피해 제한을 두지 않는다.
- 일반 매칭 하나는 벽 없는 상하좌우로 접한 폐가전 칸마다 1피해다. 같은 매칭에서 같은 폐가전 칸에 여러 블록이 접해도 한 번만 계산한다.
- 한 교환의 서로 별개 매칭과 이후 자동 매칭은 별도 타격이다. 선택에서 제외된 겹침 패턴을 추가 피해로 세지 않는다.
- 로켓 두 칸 관통 2피해 후 폭탄 네 칸 4피해는 합계 6피해다. 자석+자석은 본체에 4피해다. 로켓은 파괴 여부와 무관하게 끝까지 관통한다.
- 제거 미션은 본체당 1개. 내구도는 음수가 되지 않고 파괴 후 남은 타격은 같은 본체를 다시 집계하지 않는다.
- 드론은 네 칸을 개별 후보로 사용한다. 동시 예약의 같은 칸 중복은 막고 다른 칸은 허용한다. 착탄 뒤 본체가 남으면 다시 후보가 된다.

## 구현 정책과 책임

아래는 실행을 위한 기술 설계안이다. 이 계획을 지정한 Goal 실행 요청 시 해당 범위로 구현하며, 실제 코드와 충돌하면 근거를 기록하고 필요한 최소 변경을 한다.

1. **규칙 소유권:** `Assets/Scripts/Simulation` 안에서 대상 반응과 본체 피해 적용을 책임별로 분리한다. 금고/자물쇠/폐가전 규칙은 피해 조회와 실제 실행이 함께 사용한다. 드론 매니저에 장애물별 손상 로직을 넣지 않는다. 새 게임명 폴더·패키지·asmdef는 만들지 않는다.
2. **타격 문맥:** 인접 매칭에 원래 색과 매칭 식별을 전달한다. 한 선택된 `MatchDecision`은 한 매칭 타격, 각 파워의 개별 발동/조합 직접 범위는 한 파워 타격으로 식별한다. 이후 발동한 파워·각 드론 착탄은 새 타격이다. 같은 타격의 범위 중복만 제거하고 별도 타격은 합치지 않는다. 조합 효과의 기존 범위/발동 순서를 보존한다.
3. **사본과 기록:** 타격 식별은 실제 실행 순서에서 결정적으로 발급하고 필요한 이력은 `TurnEffectContext`의 복사·다음 수 초기화·실패 원자성에 포함한다. 피해 조회/예약이 실제 이력이나 난수를 소비해서는 안 된다. 목적 없는 범용 이벤트 버스를 만들지 않는다.
4. **적용:** 단일 칸과 여러 칸 본체 모두 내구도/완전 파괴/미션 반영의 소유자를 명확히 한다. 폐가전 제거는 같은 `ObstacleIndex`를 가진 네 칸을 처리한다. 나머지 본체 인덱스와 정의를 재정렬하지 않는다. 제거된 본체에 재차 미션을 지급하지 않는다.
5. **예약 계산:** 실제 내구도와 예약 예상 피해는 분리한다. 미션 기여는 본체별로 합산하며 금고/자물쇠는 턴당 1피해, 폐가전은 예약된 서로 다른 칸/직접 범위의 허용 피해를 적용한다. 본체 내구도 2에 1피해 두 개가 예약되면 제거 예정 1개로 계산한다. 미션 목표가 이미 예약으로 충족되면 과도한 추가 예약을 피한다. 범위 겹침과 미션 완료를 여러 칸에서 중복 집계하지 않는다.
6. **예약 수명:** 본체 타격/파괴 후 후보 캐시를 무효화하고 다음 조회에 재평가한다. 일부 내구도 감소 시 기존 예약의 유효 기여를 재계산한다. 목표 소실 시 미션부터 재탐색하고 없을 때 일반 블록을 선택한다. 해제는 실제 피해 제한을 초기화하지 않는다.
7. **지원 경계:** 실행·정착·미션 지원을 세 종류까지 일치시킨다. 발전기/연결 실행·회수는 미지원으로 명시적으로 거절한다. 정적 본체는 교환·낙하하지 않으며 파괴한 칸만 기존 정착 경로로 채운다.
8. **표시:** 기존 `Match > 초기 보드 확인`에서 본체 ID/범위·공유 내구도·자물쇠 색·타격별 피해·예약 예상/실제 미션을 확인한다. 색 외 토끼 번호/표식을 같이 쓴다. 여러 칸은 같은 본체임을 구분하고 부분 파괴처럼 표시하지 않는다. 제작용 표시는 텍스트와 기존 스타일로 구현하며 출시용 나사/막대 아트는 만들지 않는다.
9. **호환성:** v4·원본 에셋/GUID/meta·기존 편집 UI를 보존한다. 결과가 바뀌는 실행/효과/정착 알고리즘 버전을 갱신하고 재현 기록에 포함한다. 기존 검증에서 세 종류를 미지원 사례로 사용한 곳은 실제 미지원 요소로 교체하되 검사 목적을 유지한다.

## 실행 순서와 완료 증거

| 작업 | 선행 | 출력과 검증 |
|---|---|---|
| T1 기준 확보 | 없음 | 18단계 감사·해시·현재 Goal·원본 보존 목록, 규칙별 정답 사례 |
| T2 금고·자물쇠 | T1 | 조회/실제 피해·색/벽/자석 예외·턴 제한·미션 테스트 |
| T3 폐가전과 타격 단위 | T2 | 공유 내구도·매칭 구분·범위 중복·반복 피해·네 칸 제거 |
| T4 드론 예약 | T3 | 본체별 누적 예상·범위 중복·재탐색·해제·실제 결과 대조 |
| T5 Match 통합 | T4 | 유효 레벨의 직접 조작·단계/끝까지·정착·내구도/색 표시 |
| T6 재현·회귀·감사 | T5 | 독립 Unity 재생·8~18 영향 회귀·원본 보존·조건별 기록 |

공통 효과 처리와 문맥을 함께 수정하므로 순차 진행한다. 각 작업은 해당 정답 사례를 통과한 뒤 다음으로 넘어간다.

필수 사례:

- 금고 내구도1~5, 자물쇠1~3/레벨 사용 색 전체, 폐가전1~9. 고정/교환 불가·벽·파괴 후 정착·미션 없음/있음 모두 확인한다.
- 자물쇠 일치/불일치 색, 파워 생성 칸, 자석 직접/피격/교환 발동, 거미줄에 남은 색 블록과 곰팡이에 숨은 블록, 자석 색 변환/전체 타격의 구분.
- 폐가전 로켓2+폭탄4, 한 매칭의 동일 칸 중복 접촉, 한 수의 별개 두 매칭, 후속 연쇄 재피해, 여러 파워의 겹친 타격, 내구도보다 큰 피해, 먼지 중첩 및 네 칸 동시 제거.
- 일반 드론의 서로 다른 칸 예약, 내구도2/예약1+1의 제거 예상1, 범위 예약과 본체 중복 집계, 취소/부분 피해/완전 소실 후 재계산·미션 우선 재탐색·일반 대체.
- 신규 파워 보호·기존 상자/고철 턴 제한·거미줄/먼지·곰팡이 턴 종료·색 미션·난수·공급 순서 회귀. 파워10조합과 혼합 장애물에서 전체 실행 확인.
- 실제 Match UI에서 1000/680폭, 교환/발동→낙하→자동 매칭→다음 수, 단계/끝까지 결과 일치, 같은 시드 초기화, 레벨/시드/모드 변경·창 닫기 해제.
- 실패 시 상태/미션/난수/타격/예약 원자성, 동일 정의·시드·행동·버전의 별도 Unity 프로세스 전체 재현. 원본 수정/dirty 여부·v4·GUID/meta 보존.

실제 수행한 증거만 완료로 기록한다. 테스트 개수는 목표가 아니며 조건 누락을 높은 PASS 수로 대신하지 않는다. 완료 후 20단계 자동 실행은 하지 않는다.
