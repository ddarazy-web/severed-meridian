- 상세 계획: [21단계 작업 계획](53_21단계_회수부품과도착공급_작업계획.md).

## Goal 목표

현재 Unity 프로젝트의 공통 실행기와 Match 수동 시험에서 회수 부품의 교환·불파괴·이동, 도착 즉시 회수, 회수 미션, 고정/유지 공급과 드론의 간접 기여를 구현한다. 기존 게임 규칙과 편집 데이터를 보존하고 실제 UI·독립 재현·영향 회귀로 아래 완료 조건을 검증한다.

## 실행 지침

1. 현재 Goal 상태와 소스·완료 기록을 확인한다. 같은 목표가 활성 상태면 이어서 진행하고 다른 활성 Goal을 덮어쓰지 않는다. 문서 작성 요청만으로 이 Goal을 시작하지 않는다.
2. ponytail과 프로젝트 Unity 지침을 적용한다. 이 문서를 지정한 Goal 실행 요청은 상세 계획의 범위와 기술 설계에 대한 실행 승인이다.
3. 20단계 이후의 발전기/통로 연결, 후보 강조, 낙하 경로 드래그, 합류 우선순위 편집을 현재 기준에 포함한다. 과거 소스 해시로 되돌리지 않는다.
4. 계획의 T1→T6을 수행한다. Scripts 아래 기존 구성별로 배치하고 게임·수동 시험·향후 봇의 실행 규칙을 공유한다.
5. 미지원 차단을 제거하는 데 그치지 말고 조회·실행·피해·정착·공급·미션·드론을 일치시킨다. 저장 v4/GUID/meta와 무관 파일을 보존한다.
6. 실제 회수와 간접 기여 예측을 구분한다. 드론 예약만으로 회수 미션을 줄이거나 미래 난수/연쇄를 읽지 않는다.
7. 실제 Match 조작과 독립 Unity 프로세스 재현을 검증한다. 미지원 실패 검사의 목적을 유지하며 실패를 숨기거나 미검증 항목을 완료로 표시하지 않는다.
8. 아래 20조건의 증거와 실제 집계를 기록한 뒤에만 완료한다. 22단계 이후로 자동 확장하지 않는다.

### 구현 책임과 버전

- `Assets/Scripts/Features/Missions/Runtime/RecoveryRules.cs`: 회수·부족분·직접 방해 요소의 간접 기여. 버전 `recovery-v1`.
- `LevelRuntimeState.cs`: 불변 회수 기록과 사본 이력. `MovementQuery.cs`: 기존 이동 대상에 부품 포함, `movement-query-recovery-v3`.
- `BoardActionExecutor.cs`: 초기 정규화를 검증된 정착 사본으로 반영, 유효 교환 후 회수. `board-action-recovery-v11`. Cascade는 회수 진행이 반복 판정에서 누락되지 않도록 기록한다.
- `SettlementResolution.cs`: 이동 묶음 직후 회수, 고정/유지 공급, 실패 원자성. `settlement-recovery-v8`.
- `DamageReaction.cs`, `MissionProgressRules.cs`, `PowerEffectResolution.cs`: 불파괴·미션 지원·간접 기여의 실제 완료와 예측 분리. 기존 드론 매니저의 조회/추천/예약 관리 경계를 보존했다.
- `Assets/Scripts/Editor/Levels/LevelInitialStateWindow` 관련 파일: 도착 도형/회수 요약/공급 및 연쇄 기록. 실행 로직은 Simulation에만 있다.
- `RecoveryVerification`의 본체/Edges/UI/Regression 파일: 검증 책임별 분리. 기존 회귀의 회수 미지원 기대값을 현재 지원으로 갱신하고 실제 미지원 종류 검사는 유지했다.

새 패키지·asmdef·저장 형식을 만들지 않았다. [보존 감사](../../Logs/RecoveryVerification/preservation-audit.txt)에서 레벨 에셋, 기존 meta/GUID, Packages, ProjectSettings, 무관 Stories가 착수 기준과 같음을 확인했다. 새 스크립트에는 Unity가 생성한 meta가 있다. `Assets/__RecoveryVerification_*` 임시 에셋은 독립 재현 후 삭제했다. 최종 파일 해시는 `final-source-hashes.json`에 보관한다.

### 발견·수정과 남은 범위

회수를 미지원으로 가정하던 회귀 실패는 지원 확대에 맞게 수정했다. 미지원 실패 원자성은 잘못된 미션/장애물/공급 종류를 주입해 계속 검사한다. 검증 코드의 누락 네임스페이스와 내부 생성자 접근으로 발생한 컴파일 실패, 잘못된 검증용 공급 설정은 수정 후 모두 재실행했다. 첫 UI 검증에서 대각선 채우기가 공급 경로를 먼저 채워 연속 회수가 일어나지 않았으며, 해당 시나리오는 명시 경로로 구성하고 대각선은 별도 12시드 검사로 분리했다.

드론의 간접 조회는 현재 다음 이동의 직접 방해 요소만 예측하며, 발전기 충전도 실제 회수 완료로 계산하지 않는다. 미래 공급·추가 연쇄·실제 난수를 미리 실행하지 않는다. 판 승리·자동 재배치·라스트팡은 22단계, 아이템/부스터 입력은 23단계이며 실행하지 않았다. 봇·통계·난이도 분석·출시 화면·기기 앱 복구도 이번 완료 범위가 아니다.
