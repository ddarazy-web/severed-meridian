## 구현 경계와 결정

- 집계: AutoPlay/Runtime/Analysis/BotBatchStatistics.cs. 판별 요약에서 순수 계산한다. 오류·중단·미실행을 정상 종료와 구분하고 성공률 분모는 정상 종료만 사용한다.
- 재생: 같은 폴더의 BotRecordReplay.cs. 저장 정의와 시드로 보드를 준비한 뒤 저장 행동을 공통 실행기에 제출한다. 봇 전략을 생성하거나 새 행동을 고르지 않는다.
- 읽기: AutoPlay/Editor/Storage/BotAnalysisReader.cs. 파일을 하나씩 검증하며 행동 배열은 필요할 때 다시 읽는다. 누락 이동 수는 -1로 구분해 화면에는 기록 없음으로 표시한다.
- 보관: BotAnalysisArchive.cs. 새로운 임시 폴더에 완성한 뒤 최종 폴더로 이동한다. 기존 대상은 덮어쓰지 않으며 조회는 원본을 다시 저장하지 않는다.
- 화면: AutoPlay/Editor/Presentation/LevelAnalysisPanel*.cs. Match의 네 번째 결과·이력 탭에 통계, 사례·재생, 이력 비교를 둔다.
- 원본 연결용 GUID/이름과 시작 검색 버전은 기존 기록 형식에 선택 필드로 추가했다. 과거 기록에 GUID가 없으면 같은 원본이라고 추정하지 않는다. 재생의 근거는 항상 저장 정의다.
- 재생 호환 조건은 기록 형식·게임 실행기·행동 기록 세션·시작 검색 버전이다. 전략 버전 차이는 이미 저장한 명령의 재생을 막지 않는다. 반면 두 시험의 같은 시드 결과 비교에는 전략·가정 버전까지 함께 대조한다.
- 오류/중단은 완료 행동까지만 부분 재생한다. 기록되지 않은 처리 중 상태의 완전 복구를 주장하지 않는다. 첫 불일치에서 멈추고 행동 위치를 알린다.
- 탭 이동은 재생을 일시정지하고 복귀 시 자동 재개하지 않는다. 원본 변경·창 종료·재로드는 재생 사본을 정리한다. 실행 중 시험의 재생 시작/보관은 막는다.

200판은 **27단계에서 실제 실행해 저장한 4×4·3수 레벨의 기록을 재사용**했다. 이번에 새로 200판을 실행한 것이 아니다. 독립 프로세스 대조의 원시 근거는 core-proof.txt, core-process.txt, source-path.txt다. 정상 재생 200판만으로 성공·라스트팡·모든 장애물 사례까지 검증했다고 확대하지 않는다.

첫 경계 검사 실행은 보관 사본 준비 실패로 중단됐다. 당시 예외 메시지를 출력하지 못해 원인을 확정하지 못했다. 진단 메시지를 추가한 다음 실행에서는 15조건 모두 통과했다. 이후 core, 실제 재로드, UI 내보내기에서도 정상 완료했다. 제품 코드 수정으로 해결된 오류라고 주장하지 않으며 저장 실패는 성공으로 표시하지 않는다.

## 수정·재검증 경과와 알려진 한계

- 삭제 직후 GUID 조회가 과거 경로를 반환하는 문제를 실제 파일 존재 확인으로 수정했다. 이후 실제 재로드와 원본 삭제 후 재생까지 22조건이 통과했다.
- 재로드 검증기의 delayCall 재개가 이어지지 않은 실행은 미완료로 남겼다. 그 검증 프로세스만 종료하고, 기존 재로드 검사처럼 update 이벤트에 직접 등록하도록 바꾼 후 새 프로세스에서 실제 도메인 재로드를 완료했다. 중단된 검사를 통과 수에 합산하지 않는다.
- Unity ReadScreenPixel이 바탕화면을 반환하여 Windows PrintWindow로 검증 소유 창만 캡처하도록 변경했다. 실제 통계·재생 화면에서 최소 크기의 버튼·필터·본문과 보드 스크롤을 확인했다. 매뉴얼에는 정상 창 캡처만 포함했다.
- [결과·이력 HTML 안내](Manual/analysis.html)를 추가하고 index/play에서 연결했다. 갱신한 세 페이지의 내부 링크·앵커·로컬 자산 127개를 검사했다. 브라우저의 로컬 파일 열기 제한 때문에 브라우저 렌더링은 미검증이며 이를 우회하는 서버를 만들지 않았다.
- 출시용 게임 화면·기기별 동작·29단계 난이도 추천은 이번 범위가 아니다. 이번 화면은 기존 시험 보드의 단계 표시를 공유하며 부드러운 게임 연출을 새로 구현한 것이 아니다.
- 보호 대상 348개(사용자 레벨·등록 맵, 기존 meta, ProjectSettings, Packages)를 시작 기준 해시와 비교해 변경 0개를 확인했다. 근거: preserved-current.txt. 전체 시작 기준과 달라진 기존 파일은 이번 통합에 필요한 C# 6개뿐이며 changed-from-baseline.txt에 목록이 있다. 신규 스크립트의 meta 존재와 변경 범위도 확인했다.
- 이전 전체 공급 UI 검사의 OS 클립보드 문제는 이번에 해결했다고 주장하지 않는다. 공급 코드 자체는 시작 기준과 동일하며 이번에는 실제 랜덤 파워 공급·저장 재생과 수동 플레이의 영향 범위를 검증했다.
