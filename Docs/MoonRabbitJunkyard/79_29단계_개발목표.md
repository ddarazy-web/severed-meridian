# 29단계 개발 목표 — 예상 난이도 추천

- 작성일: 2026-09-29.
- 상태: 29단계 완료. [완료 기록](84_29단계_구현검증기록.md)의 조건별 증거와 445 PASS / 0 FAIL을 대조했다.
- 계획: [29단계 작업 계획](78_29단계_난이도추천_작업계획.md).
- 선행: [28단계 개발 목표](77_28단계_개발목표.md)의 완료 증거 확인. 작성 시점에는 28단계 Goal이 활성 상태이고 완료 체크가 미확정이다.

## 목표

검증된 반복 시험 기록으로 매우 쉬움·쉬움·보통·어려움·매우 어려움의 예상 난이도와 수치 근거를 보여준다. 오류·표본 부족·성공 사례 없음은 판단 보류로 구분한다. 기존 Match 결과·이력 화면, 통계, 사례 재생을 재사용하고 원본 레벨을 자동 변경하지 않는다.

## 실행 원칙

1. 현재 Goal과 28단계 완료 증거를 먼저 확인한다. 다른 활성 Goal을 덮어쓰거나 완료로 바꾸지 않는다. 선행 미완료 시 남은 조건을 보고하고 29단계 구현에 착수하지 않는다.
2. 프로젝트 Unity 지침과 ponytail을 적용한다. 중요한 미확정 설계만 grill-me로 한 번에 하나씩 확인한다. deep-planning은 사용하지 않는다.
3. 계획의 임계값·최소 표본·태그 수치는 초기 제안이다. 실제 기록 검토와 근거를 통해 적용 기준을 기록하고 인간 체감의 검증된 기준으로 발표하지 않는다.
4. 기존 통계를 입력으로 사용한다. 오류·중단·미실행을 정상 패배로 넣거나 두 전략의 같은 시드를 독립 200표본으로 취급하지 않는다.
5. 분석 결과를 봇 입력으로 전달하지 않는다. 공통 게임 실행기·봇 전략·원본 레벨·기존 기록을 변경하지 않는다.
6. 평가 로직은 AutoPlay 기능 내부에서 UI와 분리한다. 불필요한 프레임워크·패키지·레벨별 옵션 없이 기준과 버전을 한 곳에서 관리한다.
7. 현재 기준의 재계산과 과거 실행 조건을 구분한다. 현재 편집 내용과 다른 정의의 추천을 현재 레벨의 결과로 표시하지 않는다.
8. 등급·보류·근거·태그를 실제 Unity 화면에서 확인하고 쉬운 한국어 도움말과 HTML 매뉴얼을 갱신한다.
9. 수기·합성 표본과 실제 시험 기록을 구분해 검증한다. 기존 검증 수를 재사용하지 않고 미검증 한계를 명시한다.
10. 기존 생성구 파워블록, 등록 맵 이름 변경, 사용자 에셋과 모든 선행 변경을 보존한다. 이번에는 29단계만 구현한다.
