## 목표와 현재 근거

공통 실행기에 판의 결과와 종료 순서를 연결한다. Match 수동 시험에서 목표 달성, 이동 수 소진, 재배치 불가, 실행 오류를 구분하고, 성공 이후 라스트팡까지 확인할 수 있게 한다.

착수 당시 `BoardActionExecutor.Cascade.cs`는 정착 후 `MovesExhausted`, `NeedsShuffle`, `Stable`을 반환하면서 승패 판정과 재배치를 미지원으로 표시했다. 이번 단계에서 기존 매칭·피해·낙하·공급 실행 경로 위에 판정과 후속 처리를 연결했다. 별도 시뮬레이터를 만들지 않았다. 아래 내용은 실행한 작업 계획이며 최종 구현·검증 결과는 목표 문서에 기록한다.

### 21단계에서 이어받는 경계

- 실행기는 초기 도착 부품이 있으면 생성 시 정착을 수행한다. 초기 정착/자동 매칭 이후 목표 달성도 판정하되, 읽기 전용 `LevelStateBuilder`와 원시 후보에는 승패·라스트팡을 실행하지 않는다.
- `RecoveryRules`의 실제 회수/남은 목표/유지 부족분, 고정 공급 커서, 회수 이력과 드론 간접 기여를 보존한다. 목표를 달성한 순간 진행 중인 정착을 잘라내지 않는다.
- 기존 검사에는 목표 완료 후에도 다음 행동을 허용하거나 마지막 수를 무조건 `MovesExhausted`로 기대하는 21단계 경계가 있다. 새 승패 계약에 따라 기대 결과를 갱신하되 회수·공급·피해·난수·사본 보존 검사는 유지한다.
- 기준 증거는 `Logs/RecoveryVerification/final-counts.txt`, `final-source-hashes.json`, `preservation-audit.txt`와 목표 문서다. 새 작업 기준을 다시 기록하며 과거 해시로 현재 파일을 되돌리지 않는다.

## 범위

- 안정된 보드에서의 성공/이동 수 소진/행동 없음 판정과 종료 결과 보존.
- 일반 블록·파워 블록의 자동 재배치와 실패 이유 기록.
- 성공 확정 이후 남은 이동 수의 로켓 변환, 파워 발동, 정상 낙하·공급·자동 매칭을 포함한 라스트팡.
- Match 화면의 결과·진행 상태·라스트팡 건너뛰기·재시작 표시.
- 같은 시드 재현, 단계/끝까지 실행 일치, 실제 UI 및 기존 규칙 회귀 검증.

아이템/부스터 입력은 23단계, 수동 플레이 전체 통합은 24단계다. 광고 이어하기, 실제 재화 지급/환불, 앱 저장·강제 종료 복구, 출시용 결과 화면·연출은 이번 범위에서 제외한다. 결과와 후속 보상 처리의 경계를 남기되 빈 경제 시스템이나 앱 저장 프레임워크를 만들지 않는다.

## 판정 순서

1. 유효한 행동 이후 파워 효과·회수·낙하·공급·자동 매칭을 끝까지 처리한다. 처리 중 미션 수치만 보고 조기 종료하지 않는다.
2. 기존 곰팡이 턴 종료 규칙을 적용한다. 목표 완료 시 확산 생략 등 기존 조건을 보존하고 초기 정착·라스트팡을 새 사용자 턴으로 계산하지 않는다.
3. 정상 정착 후 모든 유효 미션이 완료되었으면 성공을 한 번 확정한다. 마지막 이동으로 이동 수가 0이 된 경우에도 성공이 우선한다.
4. 미션이 남았고 이동 수가 0이면 이동 수 소진으로 종료한다.
5. 이동 수가 남았으면 공통 행동 조회로 유효한 교환 또는 파워 발동 가능 여부를 확인한다. 행동이 있으면 다음 입력을 허용하고, 없으면 자동 재배치를 시도한다.
6. 재배치로 조건을 충족하면 입력 대기로 돌아간다. 증명된 재배치 불가는 진행 불가, 처리 예산 소진·미지원·잘못된 데이터·반복 오류는 실행 중단으로 구분한다.

미션이 없는 잘못된 데이터가 빈 목록의 `All` 판정으로 성공하지 않도록 기존 데이터 검증을 거친다. 초기 회수 등 실행 초기화가 끝난 뒤에도 같은 판정 경계를 사용한다. 종료 후 교환·발동 입력은 상태와 난수를 변경하지 않고 거절한다.

## 자동 재배치

- 이동 가능한 일반 블록과 파워 블록의 위치만 바꾼다. 개수·색·파워 종류·청소로켓 방향을 보존한다.
- 장애물, 회수 부품, 거미줄/곰팡이와 덮인 내용물은 제외한다. 먼지 등 바닥, 벽, 경로, 생성구·공급 커서는 원래 칸에 남긴다.
- 벽으로 분리된 구역 사이에도 대상 블록을 재배치할 수 있다. 기존 비활성 칸이나 제외 대상 칸을 새 배치 칸으로 사용하지 않는다.
- 성공 조건은 즉시 완성된 매칭이 없으며 유효한 교환 또는 발동 가능한 파워가 하나 이상 있는 것이다. 일반 매칭뿐 아니라 2×2 등 지원하는 모든 매칭을 조회한다.
- 이동 수를 소비하거나 파워를 발동하지 않는다. 곰팡이 확산·회수·공급을 재배치의 부수 효과로 실행하지 않는다.
- 사본에서 후보를 검사하고 성공 배치만 커밋한다. 실패한 배치를 보드에 남기지 않으며 시도 수·난수 소비와 종료 이유를 기록한다.

### 탐색 비용과 판정의 구분

무작위 시도 몇 번이 실패했다는 이유만으로 불가능하다고 단정하지 않는다. 기존 시드 난수를 사용한 제한된 후보 탐색과 간단한 불가능 조건 확인부터 구현한다. 작은 배치는 완전 탐색으로 검증할 수 있지만, 10×10 전수 탐색은 하지 않는다. 예산 내 배치를 찾지 못하고 불가능성도 증명하지 못했다면 `탐색 한도`로 중단하고 일반 패배/진행 불가 통계에 포함하지 않는다. 시도 예산은 구현 시 재현 가능한 상수와 검증 근거로 기록하며 사용자 설정은 추가하지 않는다.

이 구분은 잘못된 난이도 통계를 막기 위한 기술적 중단 정책이다. 이후 실제 플레이에서 이 한도가 자주 발생하면 구성적 배치 알고리즘을 개선한다. 검증되지 않은 탐색을 무제한으로 돌리지 않는다.

## 라스트팡

- 성공 결과를 먼저 고정하고 라스트팡 상태로 전환한다. 남은 이동 수와 성공 당시 미션을 보존하며 반복 호출로 성공 기록이 중복 생성되지 않게 한다.
- 남은 이동 수만큼, 변환 가능한 일반 블록을 중복 없이 무작위 선택해 청소로켓으로 바꾼다. 방향도 시드 난수로 정한다. 후보가 부족하면 가능한 수만 변환하며 부족분을 나중 공급까지 기다려 추가 변환하지 않는다.
- 거미줄에 묶인 블록과 곰팡이로 숨은 내용물은 직접 변환·일괄 발동 대상에서 제외한다. 기존 덮개 피해 및 이후 별도 타격 반응을 보존한다.
- 기존 파워와 변환한 로켓을 공통 파워 실행 경로로 발동한다. 낙하·공급·자동 매칭·새 파워 생성을 정상 처리한다.
- 새 파워는 현재 효과와 정착이 끝난 뒤 다시 발동한다. 일반 플레이의 새 파워 보호를 전역으로 제거하지 않고 라스트팡 경계에서만 처리한다.
- 발동할 파워와 처리할 연쇄가 없으면 결과 표시로 진행한다. 자동 재배치나 새 사용자 턴은 시작하지 않는다.
- 건너뛰기는 연출/후속 계산을 종료하고 이미 확정된 성공 결과를 보여준다. 건너뛰기 전후 최종 보드가 같을 필요는 없지만 성공·보상 자격은 같아야 한다.
- 반복/처리 한도에 도달해도 이미 확정한 성공을 패배로 바꾸지 않는다. 라스트팡 진단 실패를 별도로 기록하고 결과 표시로 종료한다.

실제 별 지급은 구현하지 않는다. 성공 확정 기록과 라스트팡 진행 기록을 구분해 향후 보상 서비스가 라스트팡 결과에 의존하지 않도록 한다. 앱 재실행 복구까지 검증했다고 표현하지 않는다.

## 작업 순서와 검증

| 작업 | 내용 | 확인할 증거 |
|---|---|---|
| T1 | 21단계 완료 확인, 현재 호출부·기획 대조, 원본 기준 확보 | 완료 기록, 현재 해시/변경 목록, 판정 순서 메모 |
| T2 | 결과 모델과 안정 상태의 종료 판정 연결 | 마지막 수 성공/실패, 동적 미션·초기 정착, 종료 후 입력 거절 |
| T3 | 자동 재배치와 실패 구분 | 대상/제외 보존, 성공 조건, 불가능/한도, 사본·난수 재현 |
| T4 | 성공 이후 라스트팡 연결 | 변환 상한, 방향, 덮개, 새 파워 재발동, 건너뛰기/오류 후 성공 유지 |
| T5 | Match 결과와 조작 반영 | 실제 입력·1000/680폭·스크롤·재시작·창 수명 검증 |
| T6 | 통합 회귀와 증거 기록 | 독립 Unity 재현, 단계/끝까지 일치, 기존 규칙·편집 회귀 |

의존은 T1→T2→T3→T4→T5→T6이다. T2~T4마다 좁은 재현 검사를 먼저 통과시킨 뒤 다음 작업으로 진행한다. 최종에는 회수/공급, 곰팡이, 발전기, 드론 예약, 파워 보호와 연결·통로·낙하 경로·합류 컨텍스트 메뉴를 포함해 영향 회귀를 확인한다.

실행 전후 레벨 원본·직렬화 형식·GUID/meta·패키지와 무관 변경을 비교한다. 현재 단계의 새 검사와 재실행 회귀를 구분하고 중복 집계를 하지 않는다. 실제 UI를 실행하지 못했다면 미검증으로 남기며 문서 작성이나 컴파일만으로 완료하지 않는다.
