## 확인한 현재 상태

27단계는 반복 시험·실행 제어·판별 기록 저장을 완료했다. `BotBatchRecord`는 정의 사본·지문·시드 묶음·버전·결과 수를, `BotBatchGame`은 전략·종료 종류·사용/남은 이동 수·잔여 미션·행동과 난수 소비 기록을 보유한다. `BotBatchStore`는 `Library/Match/AutoPlay`에 저장하고 직전 묶음을 복구한다. 현재 화면은 반복 시험과 최소 결과 요약을 제공한다. 상세 분석과 사용자용 사례 재생은 아직 별도 구현 대상이다.

27단계 이후 생성구 랜덤 파워블록과 등록 맵 이름 변경을 추가했다. 이 변경과 사용자의 레벨·등록 맵 에셋을 보존한다. 착수 시 최신 코드와 기록 형식을 다시 확인하며, 과거 문서의 검사 수를 이번 단계 실적으로 합산하지 않는다. 이전 전체 공급 UI 검사는 OS 클립보드 읽기 실패로 끝까지 수행하지 못했으므로 전체 회귀 완료로 인용하지 않는다.

## 목표와 제외 범위

제작자가 반복 시험 결과에서 **어느 전략이 얼마나 성공했는지, 실패 시 무엇이 남았는지**를 확인하고, 실제 기록을 재생해 레벨을 수정할 수 있게 한다. 이전 결과와 현재 레벨의 차이를 표시하고 기록을 파일로 보관할 수 있게 한다.

포함: 전략별 통계, 종료 이유와 잔여 미션, 성공·실패 사례 선택과 단계 재생, 시험 이력 조회, 수정 전후 비교, 기록 내보내기·다시 열기.

제외: 5단계 난이도 등급·원인 태그 임계값·인간 체감 난이도 보정(29단계), 전체 제작 흐름 종합 검수(30단계), 자동 맵 생성, 봇 전략 변경, 서버·외부 분석 서비스, 새 그래프 패키지, 출시용 연출. 기존 실행기의 단계 표시를 활용하며 새로운 게임 화면을 만들지 않는다.

## 집계 규칙 — 계획 기본안

원시 판 기록을 기준으로 집계한다. 저장된 요약과 불일치하면 복구 가능한 원인과 손상을 구분하며, 누락을 정상 패배로 채우지 않는다. 아래 산식을 구현 기준으로 사용하고 실제 저장 필드의 의미와 대조한다.

| 항목 | 계산·표시 기준 |
|---|---|
| 정상 종료 수 | 성공 + 이동 수 소진 + 정상 막힘. 오류·사용자 중단·중단된 실행·미실행은 제외 |
| 성공률 | 성공 / 정상 종료 수 × 100. 분모도 함께 표시. 정상 종료 0판이면 `계산할 기록 없음` |
| 진행 범위 | 전략별 예정·정상 종료·오류·중단·미실행 수를 분리. 중지된 묶음은 `일부 실행` |
| 성공 판 이동 수 | 성공 판만 대상으로 사용/남은 이동 수 평균·중앙값·최솟값·최댓값과 표본 수. 성공 0판이면 값 없음 |
| 실패 판 잔여 미션 | 정상 패배만 대상으로 미션 항목별 남은 양 평균·최댓값·남은 판 수. 성공·오류·중단과 혼합하지 않음 |
| 종료 이유 | 이동 수 소진·정상 막힘·실행 오류·사용자 중단 등 실제 기록의 종료 종류와 설명. 오류는 패배 원인으로 합산하지 않음 |
| 같은 시드 전략 비교 | 양쪽 모두 정상 종료한 시드 쌍만 비교. 둘 다 성공 / 기본만 성공 / 계획만 성공 / 둘 다 실패와 제외된 쌍 수 표시 |

사용 이동 수는 기록의 실제 이동 수 소비량이다. 더블터치 등 이동 수를 소비하지 않는 행동이 있으므로 행동 기록 개수로 대체하지 않는다. 승리 후 라스트팡의 표시용 잔여 수와 기록된 이동 수의 의미도 착수 시 확인한다.

미션은 정의의 항목 순서와 종류·색을 함께 대조한다. 다른 정의의 미션이나 같은 종류의 서로 다른 항목을 임의로 합치지 않는다. 곰팡이처럼 목표량이 증가하는 미션은 남은 실제 수량을 보여주며 최초 목표로 나눈 임의 달성률은 만들지 않는다. 기존 기록으로 계산할 수 없는 값은 0이 아니라 `기록 없음`으로 표시한다.

종료 이유와 해결되지 않은 목표는 관측 사실이다. 상자가 남았다는 이유만으로 상자를 실패의 원인으로 단정하거나 성공률 차이를 `계획 요구`, `무작위 영향 큼`으로 자동 분류하지 않는다. 통계적 신뢰도·난이도 임계값은 29단계에서 다룬다.

예: 성공 3, 이동 소진 2, 막힘 1, 오류 1, 중단 1, 미실행 2이면 예정 10판, 정상 종료 6판, 성공률 50%다. 성공 0/정상 종료 0은 0%가 아니다. 이처럼 손으로 계산할 수 있는 표본을 검증 기준으로 둔다.

## 사례 재생

1. 선택한 묶음의 판 목록에서 전략·시드 순번·종료 종류·이동 수·잔여 미션을 확인한다. 성공/실패/오류/중단 필터를 제공하고 목록 순서는 안정적으로 유지한다. 자동으로 선정한 한 사례만 보여주지 않는다.
2. 사례를 선택하면 저장된 정의 사본과 시드로 시작 상태를 구성한다. 현재 레벨을 대신 사용하거나 봇에게 행동을 다시 선택시키지 않는다.
3. 기록한 교환·파워 발동을 공통 게임 실행기에 순서대로 제출한다. 효과·낙하·자동 매칭·턴 종료·라스트팡도 같은 실행 경로로 처리한다.
4. 처음부터, 다음 행동, 자동 재생, 일시정지, 재생 닫기를 제공한다. 다음 행동은 해당 행동의 후속 처리까지 진행한다. 중간 처리도 기존 보드 표시를 통해 확인할 수 있게 한다. 임의 시점 탐색·되감기 엔진은 만들지 않는다.
5. 각 행동의 유효성·이동 수 전후·난수 소비와 최종 종료 종류·잔여 미션을 저장 기록과 대조한다. 불일치 시 최초 불일치 위치와 이유를 표시하고 멈춘다.
6. 오류·중단 사례는 기록된 유효 행동 범위까지만 재생한다. 정상 종료까지의 완전 재현과 구분하고 기록하지 않은 중간 상태를 복원했다고 주장하지 않는다.

현재 엔진·기록 형식으로 정확히 재생할 수 없는 과거 기록은 통계 조회만 허용하고 이유를 표시한다. 전략 버전 차이는 기록된 행동을 재생하는 것과 전략을 다시 실행하는 것에서 의미가 다르므로, 저장 필드와 호출부에 근거해 호환 조건을 명시한다. 과거 엔진 코드를 따로 유지하는 기능은 넣지 않는다.

재생은 독립된 사본을 소유한다. 편집 원본·시험 기록·실행 중인 봇 세션을 변경하지 않는다. 반복 시험 중에는 재생 시작을 막고 먼저 일시정지 또는 중지하도록 안내한다. 재생을 닫아도 반복 시험을 자동 재개하지 않는다. 탭 이동·레벨 변경·창 종료·도메인 재로드 시 소유한 재생 자원만 정리하고 원본 기록은 유지한다.

## 분석 이력과 비교

직전 묶음 하나뿐 아니라 저장된 묶음 목록을 읽고 실행 시각·레벨 식별 정보·정의 지문·전략/규칙 버전·실행 상태를 표시한다. 레벨 파일 이름 변경과 내용 수정은 구분한다. 현재 레벨 연결은 가능한 경우 에셋 GUID를 보조 정보로 사용하되, 재생 근거는 저장한 정의 사본으로 유지한다. 이전 기록에 GUID가 없으면 같은 파일의 이력이라고 추정하지 말고 사용자가 직접 선택하게 한다.

이력에서 두 묶음을 선택해 전략별 표를 나란히 본다. 정의가 다르면 `수정 전/후`, 시드 묶음이 다르면 `다른 시드`, 버전이 다르면 `다른 규칙/전략`을 명시한다. 변경된 정의끼리 비교하는 것은 허용하되 같은 조건 재현이라고 표시하지 않는다. 같은 시드 쌍의 비교는 공통 시드와 호환 버전, 양쪽 정상 종료 기록에 한정하고 제외 수를 함께 표시한다. 묶음별 기본/계획 전략 통계도 서로 섞지 않는다.

지문이 현재 편집 내용과 다르면 과거 결과임을 표시한다. 현재 원본이 삭제되어도 저장된 사본의 조회·호환 재생이 가능해야 한다. 이름이나 레벨 번호만으로 기록을 합치거나 과거 결과를 현재 결과로 교체하지 않는다.

기존 로컬 캐시의 자동 삭제·보관 개수 제한은 이번에 추가하지 않는다. 목록은 필요한 요약부터 읽고 상세 행동은 사례 선택 시 읽어 메모리에 모든 판 상태를 올리지 않는다. 대량 파일 목록과 집계도 UI를 장시간 막지 않도록 나눠 처리한다.

## 파일 보관 — 계획 기본안

`Library/Match/AutoPlay`는 임시 로컬 캐시라는 안내를 유지한다. 제작자가 선택한 폴더에 **정의·메타데이터·시드·판 기록을 포함한 JSON 묶음**을 내보내고 다시 열 수 있게 한다. 기존 파일 형식을 재사용하고 ZIP 라이브러리·데이터베이스는 추가하지 않는다. 기본 화면에 보관 한도 같은 설정은 늘리지 않는다.

내보내기는 확정된 판 기록의 한 시점 사본이다. 실행 중에는 먼저 일시정지하거나 종료하도록 하며 원본 폴더와 기존 보관 파일을 덮어쓰지 않는다. 저장 실패 시 성공으로 표시하지 않고 기존 기록을 보존한다. 다시 열기는 형식·버전·묶음 ID·판 순번/시드/전략의 일치·중복/누락을 검사한다. 파일 안의 경로를 신뢰해 지정 폴더 밖을 읽거나 쓰지 않는다. 보관 파일을 여는 것만으로 현재 시험이나 편집 레벨을 교체하지 않는다.

## 구조와 화면

`Assets/Scripts/Features/AutoPlay` 내부에 집계, 재생, 기록 읽기/보관, Editor 표시의 책임을 나눈다. 실제로 필요한 파일만 만들고 기존 `BotBatchRecord`, `BotBatchStore`, 공통 실행기와 보드 표시를 우선 재사용한다. 정확한 클래스 이름은 착수 시 확정한다. 집계는 판 기록을 읽는 순수 로직, 재생은 실행 상태 소유, 저장은 Editor 파일 처리, UI는 선택·진행 표시를 담당한다. 분석기의 비공개 기록을 봇 관찰 입력으로 전달하지 않는다.

기존 Match 통합 창 안에 결과/이력 영역을 배치한다. 처음에는 두 전략의 요약 표, 이후 종료 이유·미션·사례·이력을 탭이나 접기 항목으로 구분한다. 필요 이상의 그래프나 전략 설정을 추가하지 않는다. 최소 창 크기에서도 실행/재생 제어가 가려지지 않게 하고 긴 표는 스크롤한다. `i` 도움말·툴팁·해당 HTML 설명서 링크와 쉬운 한국어를 적용한다.

실제 200판 저장 기록으로 집계를 대조한다. 기존 27단계 기록을 재사용할 경우 해당 기록의 버전·정의·완전성을 검증하고, 이를 신규 200판 실행이라고 보고하지 않는다. 기록이 없거나 호환되지 않으면 대표 레벨을 새로 실행한다. 성공·실패·오류 등 필요한 경계는 별도 작은 사례로 보충한다. 기본 200판과 기록 수가 큰 표본의 조회·필터·상세 로딩을 측정하고 화면 지연과 메모리를 남긴다.

테스트 개수 자체를 목표로 삼지 않는다. 집계 검증은 UI에서 같은 함수를 다시 호출한 결과가 아닌 독립적인 기대값과 비교한다. 변경에 영향받는 기존 반복 실행·수동 시험·저장/dirty·등록 맵·파워 공급·도움말을 검증한다. 사용자 Unity를 종료하거나 같은 프로젝트를 중복 실행하지 않는다. 검증이 막히면 미검증 조건과 사유를 기록하고 전체 완료로 표시하지 않는다.

위의 UI 배치·보관 방식은 이 단계의 구현 기본안이다. 기존 확정 기획과 충돌하거나 중요한 해석 차이가 발견된 경우에만 grill-me로 해당 쟁점 하나를 확인한다. 문서 작성만으로 기능 구현이나 Goal 실행을 시작하지 않는다.
