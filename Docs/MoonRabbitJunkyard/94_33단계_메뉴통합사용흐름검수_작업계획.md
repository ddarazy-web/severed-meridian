# 33단계 작업 계획 — 메뉴 통합 후 사용 흐름 검수

> 실행 담당: `superpowers:executing-plans`를 적용해 T1~T5를 순서대로 진행한다. 별도 요청 없이 에이전트를 분리하거나 커밋하지 않는다.

- 작성일: 2026-09-29.
- 상태: 2026-09-29 실행·검수 완료. [최종 검증 기록](96_33단계_검증진행기록.md). 아래 계획은 실행 시 기준을 보존한다.
- 목표: 새 상단 메뉴에서 레벨 편집→시험→결과 조회를 이어서 사용하고, 저장·일시정지·기록 보호가 기존 규칙대로 동작하는지 확인한다.
- 구조: 기존 통합 창과 각 기능의 화면·실행기를 사용한다. 검수에서 재현된 문제만 해당 기능 내부에서 수정한다.
- 기술: Unity 6000.3.10f1, C#, Editor UI Toolkit.
- 명세: 사용자의 상단 카테고리 메뉴·자주 쓰는 페이지 탭 분리 요청, [32단계 목표](92_32단계_개발목표.md), [현재 메뉴 안내](Manual/index.html#workspace-menus).
- 목표 문서: [33단계 개발 목표](95_33단계_개발목표.md).

## 선정 이유와 현재 확인 범위

32단계 기록 관리는 완료됐다. 이후 레벨/시험/기록/도움말 메뉴와 네 작업 탭을 적용하고, 여러 레벨 시험을 준비·결과 카드로 나눴다. 기존 `WorkspaceMenuVerification` 16개와 `TestRecordUiVerification` 30개 검사는 통과했다. 증거는 `Logs/WorkspaceUxVerification`에 있다.

이 결과는 메뉴 배치와 기록 회귀의 증거다. 모든 메뉴 명령을 레벨이 선택된 상태에서 실행하거나, 실제 소규모 시험과 편집을 연속 수행한 전체 흐름의 완료 증거로 확대하지 않는다. 33단계는 이 변경 구간을 집중 검수한다. 이미 끝난 30단계 전체 규칙 검사를 처음부터 반복하지 않는다.

## 유지할 기준

- 상단 메뉴: 레벨 / 시험 / 기록 / 도움말.
- 작업 탭: 레벨 편집 / 플레이 테스트 / 여러 레벨 시험 / 결과·이력. 초기 보드·진단은 시험 메뉴에서 연다.
- 메뉴와 기존 버튼이 같은 동작을 제공하면 같은 처리 경로를 사용한다. 메뉴용 게임 규칙이나 저장 로직을 복제하지 않는다.
- 탭 이동에 따른 시험 일시정지·재개 정책은 기존 실행기별 계약을 따른다. 자동으로 시험을 새로 시작하지 않는다.
- 스크립트는 `Assets/Scripts/Features`의 기능 내부 역할별 폴더에 둔다. 새 추상화·패키지·범용 메뉴 프레임워크는 추가하지 않는다.
- 사용자 에셋·GUID/meta·실측 기록을 보존한다. 생성/저장/이름 변경/삭제 검사는 임시 레벨과 임시 기록으로 한다.
- 개발 중 20,000판 시험을 실행하지 않는다. 실제 신규 플레이는 연속 흐름 확인에 필요한 작은 표본으로 제한하고 정확한 판 수를 기록한다.
- 난이도 네 단계, 봇 관찰 경계, 1~100회 제품 추천 범위는 변경하지 않는다.
- HTML 브라우저 배치 검수는 기존 사용자 승인대로 후속 이관한다. 실제 Unity 화면과 문서 링크 검사는 이번 범위다.

## 우선 확인할 다섯 상황

1. 레벨 미선택: 저장·복제·이름 변경·검사가 실행되지 않으며 새 레벨과 맵 목록은 접근 가능하다.
2. 입력 중 저장: 메뉴 저장과 편집 화면 Ctrl+S가 입력값을 올바르게 반영하고 dirty 표시를 해제한다.
3. 시험 중 메뉴 이동: 일시정지와 다른 시험 잠금이 탭 이동 때와 같고 중복 실행되지 않는다.
4. 지난 기록 조회: 조회만으로 원본·최근 포인터가 바뀌거나 시험이 자동 재개되지 않는다.
5. 작은 창·재열기: 메뉴·도움말·필수 조작이 가려지지 않으며 닫힌 시험이 자동 실행되지 않는다.

## 작업과 검증 순서

### T1 — 기준과 검사 범위 확정

- [x] 32단계 완료 기록·메뉴 변경 증거·현재 코드의 차이를 확인한다.
- [x] 기존 레벨·등록 맵·기록의 파일 목록과 해시를 검사 전에 확보한다. 토큰이나 사용자 민감 정보는 로그에 남기지 않는다.
- [x] 위 다섯 상황을 기존 검사의 어느 항목이 담당하는지 연결하고, 빠진 시나리오만 추가한다.

결과: 중복 없는 검사 목록과 보존 기준. 기존 통과 개수를 새 실행 결과로 재계산하지 않는다.

### T2 — 레벨 메뉴에서 편집 완료까지

- [x] 임시 레벨로 새 레벨→선택→값 변경→메뉴 저장→재조회 흐름을 확인한다.
- [x] 입력 중 Ctrl+S, dirty 표시, 이름 변경·복제·등록 맵 목록 열기/닫기와 취소를 확인한다.
- [x] 레벨 미선택 시 메뉴 상태를 확인한다. 잘못된 이름과 중복 이름은 원본을 덮어쓰지 않아야 한다.
- [x] 실패는 재현 조건과 검사 결과를 먼저 남긴 뒤 관련 코드만 고치고 동일 조건으로 재검사한다.

결과: 메뉴와 기존 편집 동작이 같은 저장·취소 계약을 따른다.

### T3 — 시험과 결과의 연속 사용

- [x] 임시 레벨 두 개로 반복 시험을 두 전략 각 1판씩 수행한다(계획 표본 총 4판). 표본 부족을 정상 난이도 판정처럼 표시하지 않는다.
- [x] 실행 중 메뉴 이동→일시정지→복귀→재개/중지, 다른 시험 시작 잠금을 확인한다. 시점 제어가 필요하면 소유한 검사용 세션을 사용하고 실측과 구분한다.
- [x] 레벨별 결과→판별 통계→지난 여러 레벨 시험→기록 관리 이동을 확인한다.
- [x] 추천 결과 화면은 기존 완료 기록의 사본으로 확인하고 신규 1~100회 전체 시험은 하지 않는다.
- [x] 삭제 메뉴의 취소·실행 잠금·삭제 후 갱신은 임시 루트로만 검증한다.

결과: 시험 소유권·상태·현재 결과가 화면 이동으로 혼동되지 않는다. 실제 판 수와 기록 사본 검사를 분리해 보고한다.

### T4 — 최소 창·재열기·도움말

- [x] 각 탭의 실제 최소 크기와 좁게 도킹한 상태에서 메뉴·필수 버튼·도움말에 접근 가능한지 확인한다.
- [x] 메뉴를 실제로 펼친 화면과 준비/결과 카드 화면을 캡처한다. 코드상 명령 호출과 실제 메뉴 표시 확인을 구분한다.
- [x] 창 재열기·스크립트 재로드 후 중단 상태와 기록 조회를 확인한다. 자동 재개를 추가하지 않는다.
- [x] 현재 화면 사용법과 각 도움말의 HTML 파일·앵커를 검사한다.

결과: 화면 크기·탭·메뉴·재열기에서 필수 조작이 유지된다.

- [x] `96_33단계_검증진행기록.md`에 완료 조건별 증거, 실패와 수정, 실제 판 수, 합성/사본 사용, 남은 제한을 기록한다.

기본 검증 명령은 Unity 실행 인수 `-projectPath C:/Projects/Git/ServeredMeridian -executeMethod Levels.Editor.WorkspaceMenuVerification.Start -logFile <이번 실행의 별도 로그>`다. 이 진입점은 기록 UI 검사도 연쇄 실행하므로 별도 중복 실행하지 않는다. 나머지 검사는 T1에서 확인한 진입점으로 필요한 것만 실행한다. 컴파일 오류·검사 FAIL이 없어야 하며, 실제 UI·보존 증거도 함께 충족해야 한다.

## 제외 범위

새 게임 기능, 새 탭, 봇 전략 변경, 난이도 임계값 변경, 전체 밸런스 실측, 모바일/IL2CPP 빌드, 저장 형식 전환, 패키지 업그레이드, 사용자 실제 기록 삭제, 커밋은 포함하지 않는다. 실패가 없으면 제품 소스를 바꾸지 않고 검증·안내 정리로 완료한다.
