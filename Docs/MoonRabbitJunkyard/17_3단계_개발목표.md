아래 Goal 실행문을 제출하면 연결된 계획의 포함 범위와 세부 조작·모델·호환성 제안을 승인한 것으로 진행한다. 문서 작성·열람만으로 Goal이나 구현을 시작하지 않는다.

7. 사용자 파일과 무관한 변경을 보존하고 임시 검증 에셋을 정리한다. 커밋·배포·4단계 구현은 포함하지 않는다.

### 사용 방법과 제한

1. **Match → 레벨 에디터**를 열고 레벨을 선택하거나 **새 레벨**을 누른다. 기존 Inspector의 **보드 편집 창 열기**도 같은 창을 연다.
2. 버전 1 에셋은 **3단계 형식으로 전환**을 누른다. 전환은 현재 에셋 하나에만 적용되며 Undo가 가능하다. 디스크 반영은 **저장**으로 확정한다. 예상 밖 신규 데이터가 있으면 전환을 거절하므로 원본 Inspector에서 먼저 확인한다.
3. 왼쪽 카테고리 드롭다운에서 배치할 종류를 골라 클릭/드래그한다. 편집 층은 자동으로 바뀐다. 신규 내구도는 1, 발전기 충전은 3, 로켓은 가로가 기본이며 오른쪽 속성에서 변경한다.
4. **선택** 도구로 요소를 선택한다. 자물쇠 색은 레벨 사용 색 중에서, 로켓 방향은 제거할 가로/세로 줄로 지정한다. 같은 칸의 다른 요소는 편집 층을 바꾸어 선택한다.
5. 거미줄/곰팡이는 먼저 배치된 일반/파워 블록 위에 놓는다. 덮개 안의 일반 블록을 지우면 덮개가 남고 내부 블록 없음 오류가 된다. 블록을 다시 배치하면 해결된다.
6. 먼지는 바닥에 따로 남는다. 보드의 황갈색 우측 아래 숫자가 먼지 내구도이며 안쪽 밝은/보라색 윤곽은 덮개다. 마우스를 올리면 먼지와 본체 기준 좌표 등의 설명을 볼 수 있다.
7. 폐가전·발전기는 왼쪽 위 기준 칸에 네 칸 미리보기를 확인하고 클릭한다. 드래그로 여러 본체를 설치하지 않는다. 네 칸 중 어디를 선택해도 같은 공유 속성을 편집한다.
8. 2×2 본체를 선택하고 **2×2 본체 이동**을 누른 다음 목적지 왼쪽 위 칸을 클릭한다. 충돌·비활성·보드 밖이면 원위치를 유지한다. Esc·포커스 상실·저장·도구 전환으로 대기 중 이동을 취소한다.
9. **현재 층 지우기** 또는 **선택한 층의 요소 삭제**는 그 층만 지운다. 2×2는 본체 전체가 지워지며 아래 먼지는 남는다. 다른 종류로 바꿀 때는 명시적으로 해당 층을 지우고 새로 배치한다.
10. **검사** 후 오류 항목을 누르면 관련 층·칸·본체로 이동한다. 같은 층의 중복 기록은 보드에서 임의 삭제하지 않으므로 **기존 Inspector에서 확인**을 눌러 원본 목록을 수정한다. 오류 상태도 저장할 수 있다.
11. **현재 사용 중인 장애물**에서 종류를 펼치면 배치 좌표·내구도/충전량을 확인할 수 있다. 항목을 누르면 해당 층과 위치를 선택한다. 배치·삭제·Undo/Redo·외부 수정 시 실제 데이터로 갱신하며, 2×2는 본체 하나로 센다.

발전기는 본체와 필요 충전량까지 지원한다. 전선·연결·게임 피해/낙하·미션·플레이 가능 판정은 지원하지 않으며 4단계나 게임 실행 로직은 시작하지 않았다. 그림은 모두 편집용 임시 기호이며 게임 아트가 아니다.

### 검증 중 발견해 수정한 내용

- Unity `Color32`에서 UI 스타일 색으로의 명시적 변환 누락을 수정하고 재컴파일했다.
- 기존 Inspector 검사에서 필드 개수 6개를 고정하던 전제를, 기존 필드와 신규 세 목록이 모두 있는지 검사하도록 변경했다. 기존 속성 입력·Undo·저장 검사는 유지했다.
- 2단계 검증의 지원 버전 복원을 현재 버전 상수로 바꾸고, 표시 오버레이 추가 후에도 실제 보드 칸 100개를 검사하도록 대상을 명확히 했다.
- 실제 캡처에서 발견한 좁은 층 선택 입력과 덮개/먼지 표식 겹침을 수정했다. 넓은 창과 좁은 창을 다시 캡처하여 확인했다.
- 일부만 겹친 2×2 본체는 다른 점유 칸에서도 임의 삭제/이동하지 않도록 막았다.
- 목록 순서가 바뀐 직후 오래된 이동/삭제 버튼이 다른 항목을 조작하지 않도록 원본 상태를 재확인한다. 오류 클릭은 층·도구·속성을 함께 갱신한다.

### 재현 명령

현재 프로젝트를 연 Editor를 닫은 상태에서 실행한다. 첫 명령의 Editor 프로세스가 종료된 다음 재시작 검증을 실행한다. UI 검증은 실제 창을 생성하고 스스로 종료하므로 `-quit`·`-nographics`를 붙이지 않는다.

```powershell
$stage3Check = Start-Process -FilePath 'C:/Program Files/Unity/Hub/Editor/6000.3.10f1/Editor/Unity.exe' -ArgumentList '-projectPath C:/Projects/Git/ServeredMeridian -executeMethod Levels.Editor.LevelObstacleVerification.Start -logFile Logs/LevelObstacleVerification/ui-editor.log' -WindowStyle Hidden -PassThru
Wait-Process -Id $stage3Check.Id

& 'C:/Users/ddara/AppData/Local/Unity/bin/unity.exe' run 'C:/Projects/Git/ServeredMeridian' --editor-path 'C:/Program Files/Unity/Hub/Editor/6000.3.10f1/Editor/Unity.exe' --format json -- -nographics -executeMethod Levels.Editor.LevelObstacleVerification.Restart -logFile Logs/LevelObstacleVerification/ui-restart.log
```

데이터만 확인하려면 첫 실행을 CLI `run`의 `-executeMethod Levels.Editor.LevelObstacleVerification.Prepare`로 대체할 수 있다. 이어서 `Restart`로 마무리한다. 실제 UI 확인을 데이터 검사만으로 대체하여 완료 처리하지 않는다.
