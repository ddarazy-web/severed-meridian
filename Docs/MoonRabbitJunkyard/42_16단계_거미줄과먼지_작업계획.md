## 목표와 계획 작성 당시 상태

Match 실행 시험에서 거미줄과 먼지가 있는 보드를 교환·매칭·파워 단독/조합·낙하·자동 연쇄까지 실행하고, 색상/상자/거미줄/먼지 미션의 실제 진행과 드론 예약을 확인한다. 전체 장애물을 한 번에 구현하지 않고 **덮개 → 내용물 → 바닥**의 처리 관계를 먼저 완성한다.

문서 작성 시 15단계 Goal은 활성 상태이고 목표 문서는 구현 진행 중이다. 조합 구현과 데이터/UI/독립 재현/보충 검사 결과 파일은 있지만 최종 완료 감사와 회귀 완료 증거는 아직 확인되지 않았다. 따라서 15단계 완료를 가정하지 않는다. 16단계 실행 요청 시 기존 Goal 상태와 증거부터 확인하고, 미완료라면 기존 15단계 목표를 먼저 마무리한다. 이 문서 작성 자체는 기존 Goal의 완료·취소·변경을 뜻하지 않는다.

현재 소스에서 확인한 사항:

- `RuntimeCell`에는 Cover/CoverDurability/DustDurability가 있고 초기 상태 구성도 지원한다. 편집 데이터나 저장 스키마를 새로 만들 필요가 없다.
- `MatchQuery`는 거미줄 안의 일반 블록을 매칭에 포함하고, `ActionQuery`와 `MovementQuery`는 덮개가 있는 내용물의 이동을 막는다.
- 실행기·정착기·피해 판정은 아직 덮개/먼지 보드를 미지원으로 거절한다. 허용 조건만 바꾸면 `MatchResolution.Apply`가 안의 블록까지 지워 버리므로 실제 처리부터 바꿔야 한다.
- `MissionProgressRules`는 색상/상자만 처리한다. `DroneTargetManager`는 직접 도착 범위별 후보와 예약을 관리하지만 거미줄 피해와 먼지의 조건부 피해를 구별하도록 확장해야 한다.
- 이번 확인의 기준 버전은 `board-action-combinations-v5`, `power-effects-combinations-v3`, `match-resolution-v2`다. 착수 시 15단계 최종 버전과 소스를 다시 대조한다.

## 범위와 접근

| 대안 | 장점 | 비용·한계 | 선택 |
|---|---|---|---|
| 거미줄만 추가 | 가장 작은 변경 | 먼지와 겹칠 때의 처리 계약 검증이 뒤로 밀림 | 대안 |
| 거미줄·먼지를 함께 추가 | 내용물 보존과 조건부 바닥 피해를 실제 중첩 사례로 검증 | 반복 매칭·변환·예약까지 영향 확인 필요 | 채택 계획 |
| 모든 장애물과 승패를 동시에 추가 | 지원 폭이 넓음 | 확산·공급·발전기·대형 본체까지 변경되어 오류 원인 분리가 어려움 | 제외 |

지원 범위는 기존 일반 블록·파워 4종·나무상자에 거미줄·먼지를 더한다. 지원 미션은 색상/나무상자/거미줄/먼지, 한 레벨 1~4개라는 기존 규칙을 유지한다. 고철·곰팡이·금고·자물쇠·대형 폐가전·발전기·회수 부품의 실행은 후속 단계다. 승패, 라스트팡, 자동 섞기, 아이템, 부스터, 봇, 난이도 분석, 해금 레벨, 신규 공급 방식, 런타임 연출과 아트는 제외한다. 기존에 편집 가능한 미지원 항목을 삭제하지 않는다.

## 확정 규칙

### 거미줄

- 내구도 1~3. 안의 일반/파워 블록은 교환·낙하·직접 발동하지 못한다. 일반 블록의 색 매칭 참여는 허용한다.
- 해당 칸의 매칭 참여 또는 파워 직접 타격은 덮개에 1피해를 주고 내용물을 보존한다. 인접 매칭만으로는 손상되지 않는다.
- 턴 전체에서 거미줄당 최대 1피해. 벗겨지는 타격은 내용물 제거·파워 발동까지 함께 수행하지 않는다. 이후 별도 타격은 노출된 내용물에 정상 적용한다.
- 피해받은 거미줄 블록도 새 블록 유입으로 생긴 새 매칭에 다시 참여한다. 변화 없이 남은 같은 매칭의 무한 처리는 금지한다.
- 파워 생성 예정 칸이 덮여 있으면 같은 선택 매칭의 노출된 칸 중 맨해튼 거리가 가장 가까운 칸으로 옮긴다. 동률은 실행 사본의 난수로 결정한다. 파워 우선순위 및 제외 패턴 규칙은 유지한다.
- 무지개 자석의 색 대상에 포함하지만 안의 블록을 제거하거나 변환하지 않고 거미줄만 손상한다. 매칭 생성 파워 보호와 기존 파워의 별도 피격 발동을 유지한다.

### 먼지

- 내구도 1~3. 바닥 좌표에 고정되며 교환·낙하·공급으로 이동하거나 복사되지 않는다.
- 위의 일반 블록이 매칭/파워로 실제 제거되거나 매칭·자석 조합으로 파워로 변환될 때만 1피해. 턴당 먼지 한 칸 최대 1피해다.
- 빈칸, 파워, 상자 위의 직접 파워 타격과 인접 매칭은 먼지를 손상하지 않는다. 거미줄만 손상되어 내용물이 남아도 먼지는 그대로다.
- 일반 블록 제거 한 번으로 색상 수집과 먼지 제거가 함께 진행될 수 있다. 이후 변환 파워의 폭발로 중복 집계하지 않는다.
- 거미줄/먼지는 완전히 제거된 한 칸당 해당 미션 1개로 집계한다. 단순 내구도 감소를 완료 수량으로 세지 않는다.

### 드론

- 기존 종류별 규칙 조회 구조를 확장한다. 관리자는 후보 추천·예약·해제를 맡고 피해/미션 규칙을 자체 복제하지 않는다.
- 색상 수집은 바로 수집할 노출된 목표색을 우선하고, 없으면 묶인 목표색의 거미줄 피해를 후보로 삼는다. 아직 색을 수집하지 않았으므로 예상 색상 완료량은 0이다. 다른 장애물 미션보다 무조건 우선하는 전역 순위를 추가하지 않는다.
- 거미줄 제거 미션이면 안에 파워가 있어도 후보가 된다. 먼지는 일반 블록을 실제 제거할 수 있는 칸만 후보이며 거미줄에 가려진 칸은 제외한다.
- 단독/범위 드론 모두 실제 직접 효과로 가능한 기여를 계산한다. 같은 칸의 색상과 먼지 기여는 서로 다른 미션에 각각 반영하되 같은 대상의 예약을 중복하지 않는다.
- 내구도 변화, 덮개 소실, 내용물 변화, 미션 완료 때 캐시와 기존 예약 기여를 재평가한다. 자기 예약 해제 후 미션부터 다시 찾고, 없으면 일반 블록, 그것도 없으면 종료한다.

## 실행 정책과 책임

아래는 구현 세부 정책이다. 이 문서를 지정한 실행 요청에 포함하며, 기존 확정 규칙과 충돌하면 근거를 기록하고 해결한다.

1. **층별 피해 기록:** 같은 좌표의 상자/거미줄/먼지 피해 한도를 서로 구별한다. 기존 상자 인덱스 기록을 보존하고 거미줄·먼지의 턴 기록은 별도 관리한다. 턴 종료 전 정착·재탐색으로 기록을 초기화하지 않는다.
2. **실제 결과 기반 집계:** 매칭 참여, 일반 블록 소비/변환, 덮개 피해, 바닥 피해를 구별한다. 거미줄에 막혀 내용물이 남은 변화를 일반 블록 소비로 기록하지 않는다. 조회는 상태·난수·진행량을 바꾸지 않는다.
3. **반복 매칭:** 처리한 패턴의 좌표/색과 참여 블록의 유입 이력을 기준으로 변화 없는 잔존 패턴만 생략한다. 무관한 칸 변화나 다른 패턴 처리로 동일 패턴을 재실행하지 않는다. 같은 색 새 블록 유입은 새 매칭으로 인정한다. 기존 LastArrival를 우선 재사용하고 전역 블록 ID 체계는 실제 필요 없으면 도입하지 않는다. 일반적인 연쇄 한도 초과와 정상적인 잔존 패턴 생략을 구별한다.
4. **파워 생성 대체:** 생성 대체 후보는 선택된 패턴 안에서만 고른다. 후보 1개는 선택 난수를 쓰지 않는다. 전부 덮인 예외는 내용물을 보존하고 거미줄 피해만 처리하며 파워 생성을 생략하고 이유를 기록하는 것으로 제안한다. 정상 시작 보드에서 도달 가능한지도 검사한다.
5. **자석 조합:** 선택 색 좌표를 노출/거미줄로 나누고, 노출된 대상은 모두 선변환한다. 묶인 대상은 변환 목록에서 제외하고 덮개 피해만 적용한다. 그 뒤 변환 파워를 발동한다. 묶인 일반 블록만 있어도 색 대상은 존재하므로 무조건 '대상 없음'으로 거절하지 않는다. 실제 변환되는 로켓만 방향 난수를 사용한다.
6. **지원 경계:** 실행·정착·미션·행동 가능 판정의 허용 범위를 함께 맞춘다. 미지원 종류가 섞인 보드는 행동 전에 이유와 함께 거절하며 일부만 실행하지 않는다.
7. **원자성:** 작업 사본의 상태·미션·난수·턴 피해·처리 패턴·예약을 함께 반영/폐기한다. 실패 전 성공한 별도 단계까지 되돌리지 않는다. 독립 재현에 영향을 주는 알고리즘 버전은 갱신한다.

| 위치 | 변경 책임 |
|---|---|
| `Assets/Scripts/Features/Obstacles/Runtime/DamageReaction.cs` 및 필요한 거미줄/먼지 규칙 파일 | 층별 반응, 턴 피해 제한, 조회와 실행의 공통 의미 |
| `MatchResolution.cs`, `PowerEffectResolution.cs`, `PowerCombinationResolution.cs` | 내용물 보존, 대체 생성, 실제 소비/변환과 먼지 피해 연결 |
| `BoardActionExecutor*.cs`, `SettlementResolution.cs` | 지원 경계, 잔존 매칭 처리, 안정화·턴 문맥과 원자성 |
| `MissionProgressRules.cs`, `DroneTargetManager.cs` | 종류별 기여 조회, 실제 완료 집계, 범위 예약 재평가 |
| `ActionQuery.cs`, `MatchQuery.cs`, `MovementQuery.cs` | 기존 이동/매칭 의미 보존 및 실행 지원과 일치 확인 |
| `Assets/Scripts/Editor/Levels` | 기존 Match 창에 내구도·피해/보존 이유·미션·예약 결과 표시, 검증 |

거미줄/먼지별 반응·미션 책임은 명확히 분리하되 범용 플러그인 등록기나 별도 실행 엔진은 만들지 않는다. 파일 분리는 실제 책임 경계만 따른다. 새 패키지·asmdef·게임명 폴더는 추가하지 않는다. 기존 레벨 정의/v4/GUID/meta를 보존하고 스키마 변경이 필요하다고 판단되면 먼저 근거를 확인한다. 씬·프리팹·플랫폼 설정 수정은 필요하지 않다.

## 작업 순서

| 순서 | 작업 | 선행 | 검증 |
|---|---|---|---|
| 1 | 15단계 완료 감사·최종 소스 확인, 보존 기준 확보 | 기존 Goal 완료 | 현재 버전/해시/미완료 목록 |
| 2 | 층별 반응·실제 소비 결과와 턴 기록 | 1 | 내구도 1~3, 덮개/내용물/바닥 중첩 정답표 |
| 3 | 매칭·대체 생성·잔존 패턴 처리 | 2 | 반복 없이 안정화, 새 유입 재매칭, 파워 보호 |
| 4 | 단독 파워·조합 10종·정착 연결 | 2~3 | 자석 비변환, 별도 피격, 먼지 고정 |
| 5 | 미션·드론 범위 예약 확장 | 4 | 실제/예상 구분, 부분 소실·재탐색 |
| 6 | Match 통합·재현·영향 회귀·완료 기록 | 5 | 실제 UI, 독립 프로세스, 원본 보존 |

공통 실행 경로를 함께 변경하므로 순차 진행한다. 단계별 정답 사례를 확보하고 구현 후 검증한다. 실패한 사례는 원인을 수정하고 영향 범위를 재검사한다.

## 검증 시나리오

- 거미줄 내구도 1/2/3 × 일반/파워: 이동 금지, 매칭 참여, 인접 피해 없음, 직접 피해, 한 턴 제한, 다음 턴 재피해.
- 거미줄 제거 타격과 뒤이은 별도 타격을 구별하고 색 집계·파워 발동·먼지 피해 시점 확인.
- 파워 생성 대체의 최단거리/동률/후보 없음, 선택 패턴 밖으로 생성되지 않음, 동일 시드 결과.
