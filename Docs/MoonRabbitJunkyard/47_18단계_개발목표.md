## Goal 목표

현재 Unity 프로젝트의 공통 실행 로직과 Match 수동 시험에 곰팡이 덮개 제거·내용물 보존·동적 제거 미션·드론 목표·전체 연쇄 후 확산을 구현한다. 자석의 숨은 색 제외를 모든 실행 경로에 적용하고, 확산의 턴당 단일 실행과 미션 달성/마지막 이동 순서를 보장한다. 실제 UI·독립 재현·영향 회귀 및 완료 조건별 감사까지 완료한다.

## 실행 지침

1. 현재 Goal, 17단계 목표/완료 감사/최종 소스 해시와 실제 코드를 다시 확인한다. 같은 18단계 Goal이면 이어서 실행하며 다른 활성 Goal을 덮어쓰지 않는다. 계획 시 17단계1,872 PASS/20조건·소스 차이0·활성 Goal 없음을 확인했다.
2. ponytail과 프로젝트 Unity 지침, 상세 계획의 정책을 적용한다. 사용자가 이 문서를 지정해 실행을 요청하면 그 범위와 구현 제안을 승인한 것으로 진행한다.
3. Scripts의 기존 Simulation/Levels/Editor 책임을 유지한다. 게임/수동/자동 시험용 매칭 로직을 따로 만들지 않는다.
4. 제거·미션·자석 → 턴 종료 확산 → 드론/화면 → 통합/재현/회귀 순서로 진행한다.
5. ‘이번 수 실제 곰팡이 제거’와 ‘확산/종료 이미 처리’를 실행 상태로 관리하고 사본·다음 수·실패 시 일관성을 보장한다. 조회와 예약은 실제 피해/제거 기록을 변경하지 않는다.
6. 후보 중복을 제거하고 같은 시드/행동에서 같은 확산을 재현한다. 모든 미션 달성은 확산보다 먼저 확인하고 마지막 수 미달성은 확산까지 수행한다.
7. 숨은 일반 색·파워·로켓 방향을 보존한다. 사용자용 실행 화면에서는 가리며, 제작용 원본 편집과 내부 진단을 공개 관찰과 혼동하지 않는다.
8. 원본/v4/GUID/meta·기존 1~17단계 동작·무관 파일을 보존한다. 새 패키지·asmdef·게임명 폴더는 만들지 않는다.
9. 다른 장애물/회수/승패 화면·라스트팡·실제 재배치/아이템/부스터/봇/분석/런타임 연출/앱 복구 구현은 제외한다. 관련 후속 순서만 로드맵에 유지한다.
10. 실제 수행한 검증만 완료로 기록한다. 기존 테스트 기대 변경 이유, 실패 수정, 남은 제한과 조건별 증거를 남기고 소유 임시 자원을 정리한다.

#### 수정한 검증 문제

- UI 검사 초기 컴파일에서 빠진 Reflection 네임스페이스를 보완했다.
- 통로 후보 제외 사례의 합류 설정을 유효한 편집 데이터로 수정했다.
- 곰팡이 지원에 따라 기존 ‘곰팡이 미지원’ 기대를 새 지원 기대 또는 금고/회수 등 실제 미지원 대상으로 변경했다. 실패 보존 검사의 취지는 유지했다.
- 조합 보충 검사가 자동 매칭 단계를 직접 주입하면서 누락한 턴 문맥을 보완했다. 실제 실행 경로는 턴 문맥을 생성한다. 재검사433 PASS.
- 잘못된 장애물 인덱스를 주입한 실패 사례는 파생 개수 조회 자체가 예외를 내므로 원시 셀/본체/미션/공급/난수/턴 기록으로 스냅샷을 비교하도록 수정했다. 종료의 원자성은 실제 예외 발생 뒤 검증했다.

#### 사용 방법과 한계

`Match > 초기 보드 확인`에서 곰팡이가 포함된 유효 레벨을 선택하고 실행 시험을 켠다. 교환/제자리 발동 후 낙하·자동 매칭 단계를 진행하거나 ‘연쇄 끝까지’를 사용하면 턴 종료 확산과 사유를 볼 수 있다. 같은 시드 초기화로 재현할 수 있다. 680폭에서는 버튼이 줄바꿈되고 보드 일부는 스크롤로 확인한다.

이 단계는 공통 규칙과 제작용 수동 시험의 곰팡이 지원 완료다. 나머지 고정 장애물·발전기·회수, 실제 승패 화면·자동 섞기·라스트팡, 아이템/부스터, 봇·통계·난이도 추천, 출시용 연출 및 실제 기기 앱 복구는 구현하지 않았다. 전체 미션 달성 시 확산을 생략하지만 승리 화면이나 보상 처리는 후속이다.
