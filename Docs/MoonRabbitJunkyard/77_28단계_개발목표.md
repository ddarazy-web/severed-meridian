# 28단계 개발 목표 — 통계·사례 재생·분석 이력

- 작성일: 2026-09-29.
- 상태: 구현·검증 완료. [조건별 증거·검사 집계·한계](80_28단계_구현검증기록.md)를 확인했다.
- 상세 계획: [28단계 작업 계획](76_28단계_통계와사례재생_작업계획.md).
- 선행: [27단계 완료 검증](75_27단계_구현검증기록.md)의 20개 조건 완료.
- 이 문서는 별도 Goal 실행 요청 시 사용한다. 작성만으로 Goal을 생성하거나 실행하지 않는다.

## Goal 목표

Match에서 반복 시험의 전략별 성공률·이동 수·잔여 미션·종료 이유를 확인하고 저장된 행동으로 사례를 재생한다. 분석 이력을 현재 레벨과 구분하며 수정 전후 결과 비교와 기록 내보내기·다시 열기를 제공한다. 기존 공개 관찰 경계·게임 공통 실행기·반복 제어·사용자 데이터를 보존하고 원시 기록 대조·재현·UI·영향 회귀로 검증한다.

## 실행 지침

1. 현재 Goal과 27단계 완료 증거를 확인한다. 같은 28단계 Goal은 이어서 진행하고 다른 활성 Goal을 덮어쓰지 않는다. 선행 완료를 확인할 수 없으면 남은 조건을 보고한다.
2. ponytail·프로젝트 Unity 지침을 적용하고 미확정 핵심 쟁점만 grill-me로 확인한다. deep-planning은 사용하지 않는다. 코드로 확인할 내용을 반복 질문하지 않는다.
3. 계획 T1→T6 순서로 진행한다. 기존 기록/저장/보드 표시/게임 실행기를 재사용하고 스크립트는 기능 안에서 역할별로 나눈다. 복잡한 분모·호환성·재생 순서·수명 처리에 한국어 주석을 작성한다.
4. 정상 종료를 성공률 분모로 사용하고 오류·중단·미실행과 구분한다. 0판·기록 없음·일부 실행을 숨기지 않는다. 행동 수와 사용 이동 수를 혼동하지 않는다.
5. 기록된 종료 이유와 잔여 미션을 관측 사실로 표시한다. 실패의 인과관계·난이도 등급·원인 태그를 임의로 확정하지 않는다.
6. 저장된 정의·시드·행동으로 재생하며 봇을 다시 판단시키지 않는다. 기록과 최초 불일치가 생기면 중지하고 이유를 알린다. 호환되지 않는 과거 기록과 중단 사례를 완전 재현으로 표시하지 않는다.
7. 수정 전후·다른 시드·다른 버전을 구분해 비교하고 원본 수정/이름 변경/삭제 후에도 이력을 오인시키지 않는다. 로컬 캐시 한계와 파일 보관 방법을 안내한다.
8. 최소 크기의 실제 Match 화면, 일시정지된 시험과 재생의 소유권, 탭 이동·닫기·재로드, 저장 실패·손상을 검증한다. 기록 조회나 재생이 원본/기존 결과를 수정하지 않아야 한다.
9. 실제 200판 기록과 수기 표본, 독립 재생, 영향 회귀 및 부하 측정을 수행한다. 기존 기록 재사용과 새 실행을 구분하며 이전 단계 검사 수를 재사용하지 않는다. 검증 제한은 명시한다.
10. 최근 생성구 파워블록·등록 맵 이름 변경 및 사용자 에셋을 보존하고 HTML 매뉴얼·툴팁·완료 증거를 갱신한다. 이번에는 28단계만 구현하고 29~30단계는 시작하지 않는다.
