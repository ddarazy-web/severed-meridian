# 12단계 작업 계획 — 낙하와 기본 공급

- 작성일: 2026-09-27.

## 목표와 현재 구현

11단계는 교환·첫 매칭·로켓/폭탄 효과와 상자 피해를 처리하고 `WaitingForFall`에서 멈춘다. 중력·경로·합류·통로와 생성구 정의는 실행 상태에 복사돼 있지만 실제 이동과 공급에는 사용되지 않는다. 고정 목록에는 소비 커서가 있으며 새 매칭 파워 보호는 현재 좌표 집합으로 관리한다.

12단계에서는 효과 처리 후 기존 블록을 이동하고 지정 생성구에서 새 블록을 공급한다. 더 이상 가능한 이동과 공급이 없으면 자동 매칭 판정 대기에서 멈춘다. 빈칸이 남아도 공급 경로가 없으면 정상적인 정착 결과다. 화면에서 이동 경로·생성 순서·공급 소비·남은 빈칸을 확인할 수 있게 한다.

## 범위 선택

| 대안 | 장점 | 한계 | 선택 |
|---|---|---|---|
| 아래 방향 낙하만 구현 | 가장 작다 | 이미 편집 가능한 구역 중력·대각선·경로를 시험할 수 없다 | 제외 |
| 낙하부터 모든 공급·자동 연쇄·승패까지 구현 | 연속 플레이에 가깝다 | 장애물 수명·회수 미션·자동 생성 위치까지 한 번에 결합된다 | 후속 단계로 분리 |
| 모든 이동 방식 + 일반/파워 기본 공급, 정착 후 정지 | 에디터의 흐름 설정을 실제로 검증할 수 있다 | 아직 전체 턴은 끝나지 않는다 | 채택 |

## 포함 범위와 지원표

- 상·하·좌·우 중력과 기본 아래 방향, 직선 우선 낙하.
- 같은 중력 방향 구역의 대각선 채우기 및 양쪽 후보의 무작위 선택.
- 직접 경로·끝칸, 합류 우선순위, 단방향 통로 입구/출구와 대기.
- 벽·비활성 칸·고정 나무상자에 의한 이동 제한.
- 생성구의 일반 블록 무작위 공급, 고정 목록의 일반/파워 공급과 목록 소진 처리.
- 이동하는 새 파워의 보호 유지, 공급된 파워는 보호하지 않는 구분.
- 효과 완료 상태에서 명시적으로 낙하·공급을 시험하는 기존 Match 화면 확장.

| 대상/설정 | 12단계 지원 |
|---|---|
| 일반 블록, 청소로켓·달폭탄·수거드론·무지개 자석 | 이동과 공급 지원. 드론/자석 발동은 계속 미지원 |
| 나무상자 1~6 | 고정 점유자로 유지. 이미 파괴된 자리에는 유입 가능 |
| 빈칸·비활성 칸·벽·중력·경로·합류·통로 | 확정된 이동 규칙 지원 |
| Random 생성구 | 레벨에서 선택한 색 안에서 균등 공급 |
| Fixed 생성구 | RandomNormal/FixedNormal/파워 4종. 수량·순서·로켓 방향 보존 |
| Fixed 소진 후 Stop/Random | 공급 중단 또는 선택 색 무작위 공급 |
| MaintainScrap/MaintainRecovery, 고철·회수 부품 고정 공급 | 이번 정착 실행은 미지원. 잔여 목록 전체를 사전 검사해 부분 소비 전에 거절 |
| 거미줄·곰팡이·먼지·나무상자 외 장애물·회수 부품 | 기존 실행 제한 유지. 해당 요소가 있는 보드의 정착 실행 거절 |
| 회수 도착 바닥 | 데이터 보존. 일반/파워는 그 칸의 이동 규칙을 따르며 회수·미션 진행은 하지 않음 |

고철은 런타임 본체 생성과 내구도 관리, 회수 부품은 즉시 회수와 미션/개수 유지가 필요하므로 이번 기본 공급에 섞지 않는다. 미지원 설정을 일반 블록으로 대체하거나 건너뛰어서는 안 된다. 편집·저장 기능과 초기 상태 구성에는 기존 지원 범위를 그대로 유지한다.

## 확정 규칙

1. 바닥과 점유자를 분리한다. 이동해도 벽·중력·경로·먼지 등의 바닥 설정은 원래 칸에 남는다.
2. 직선 낙하가 우선이다. 대각선 공급자 자신의 직선 목적지가 비어 있으면 먼저 직선으로 간다. 대각선은 출발/도착의 중력 방향이 같고 직접 경로 구역이 아닐 때만 가능하다.
3. 아래 방향 기준 왼쪽 위/오른쪽 위 공급이며 다른 중력에서는 회전 적용한다. 목적지의 두 공급자, 공급자의 두 목적지가 모두 가능하면 무작위로 선택한다.
4. 대각선 벽 검사는 가로→세로 또는 세로→가로 중 하나 이상의 벽 없는 경로가 있어야 한다. 이는 벽 검사이며 중간 칸 점유와 목적지/구역 조건을 혼동하지 않는다.
5. 직선은 다른 중력 구역에 진입할 수 있고 진입 후 해당 칸 규칙을 따른다. 비활성 칸은 건너뛰지 않는다.
6. 직접 경로는 지정한 다음 칸만 따른다. 끝칸에서는 멈추며 밖으로 사라지지 않는다. 합류는 제작자 우선순위대로 가능한 공급원을 고른다.
7. 통로 입구는 출구 이동이 우선이다. 출구가 막히면 일반/대각선 이동으로 탈출하지 않는다. 통로 유입도 합류 우선순위에 포함한다.
8. 생성은 지정 생성구에서만 한다. 생성구가 차 있으면 기다리고 기존 블록이 유입될 수 있으면 먼저 받는다. 중력 변경이 새 생성구를 만들지 않는다.
9. 고정 목록은 해당 생성구에서만 순서대로 소비한다. 최초 보드 구성에는 쓰지 않으며 빈칸 보충부터 소비한다. 목록 소진 후 정책을 따른다.
10. 이번 턴 매칭 생성 파워는 이동해도 보호된다. 생성구에서 공급한 파워에는 이 보호를 붙이지 않는다.
11. 낙하·보충 중 매칭하지 않는다. 모든 블록이 자리 잡은 뒤 판정한다. 추가 이동 횟수는 차감하지 않는다.

## 구현 정책 제안

다음은 이동 경쟁과 정착 실행 경계를 구체화하는 제안이다. 이 계획을 지정한 Goal 요청에 포함하며, 확정 규칙 또는 기존 편집 검증과 충돌하면 근거를 기록하고 해결한다.

### 실행 경계와 반영

- 기존 교환/발동은 효과 완료 후 `WaitingForFall`에 도달하는 동작을 유지한다. 별도의 정착 명령으로 낙하·공급을 실행한다.
- 성공하면 `WaitingForAutomaticMatch`에 해당하는 명확한 상태로 전환한다. `Ready`로 돌아가거나 다음 사용자 교환을 받지 않는다. 이동이 없더라도 판정 대기로 전환한다.
- 정착 명령은 시작 조건을 다시 요구하지 않는다. 효과 후 빈칸이 있는 정상 상태를 입력으로 받는다. 대신 단계·지원 요소·흐름/공급 정합성을 검사한다.
- 작업 사본에 상태·공급 커서·난수·턴 보호를 함께 복사하고 성공 시만 반영한다. 실패나 반복 입력은 정착 직전 상태 및 직전 행동 결과를 보존한다. 이미 성공한 사용자 교환까지 취소하는 것은 아니다.
- 매칭·피해·미션·턴 수·남은 이동 수는 변경하지 않는다. 정착 후 `MatchQuery`로 패턴을 읽어 표시할 수 있지만 제거·파워 생성은 하지 않는다.

### 이동 한 묶음과 경쟁 처리

- 현재 스냅샷에서 한 칸 이동 후보를 계산한다. 목적지는 그 스냅샷에서 빈 활성 칸이어야 한다. 한 블록과 한 목적지는 한 묶음에 각각 한 번만 사용하며 동시에 반영한다. 앞 이동으로 비워진 칸은 다음 묶음에서 사용한다.
- 통로/직접 경로/직선 중력을 일차 이동으로 취급하고 기존 정의의 우선 관계를 따른다. 합류 후보는 지정 순서대로 선택하며, 막힌 우선 후보 다음에는 실제로 이동 가능한 후보를 확인한다.
- 일차 이동이 가능한 동안 이를 먼저 반복한다. 더 이상 일차 이동이 없으면 대각선 후보를 계산한다. 대각선 이동 후에는 다시 일차 이동부터 확인한다.
- 대각선 후보의 경쟁 연결마다 목적지 후보 순서와 공급자 후보 순서를 난수로 정한다. 선택된 공급자·목적지를 제거하며 유효한 이동을 배정한다. 후보가 하나면 난수를 소비하지 않는다. 배열/사전 순회 순서에 따라 결과가 바뀌지 않도록 기준 좌표 순서를 고정한다.
- 위 무작위 배정은 모든 가능한 전역 배치의 균등 추출을 약속하는 알고리즘이 아니다. 두 공급자/두 목적지의 단순 경쟁에서 각각 선택 가능하고 재현 가능한지 검증한다.
- 현재 가능한 기존 블록 이동을 모두 처리한 후, 빈 생성구마다 한 개씩 공급한다. 생성구는 행·열 오름차순으로 처리한다. 다시 이동부터 반복한다. 미래에 생성될 블록까지 예상해 현재 대각선 이동을 막는 탐색은 하지 않는다.
- 공급은 블록이 실제로 놓일 때만 목록 커서/수량/난수를 소비한다. 막힌 생성구 조회는 소비하지 않는다. 고정 색/고정 파워도 불필요한 난수를 소비하지 않는다.

### 종료와 진단

- 이동도 공급도 불가능하면 정착 완료다. 막힌 빈칸을 직접 생성으로 채우거나 장애물을 통과시키지 않는다.
- 기존 흐름 검증에서 순환을 차단한다. 대각선까지 포함한 실행이 끝나지 않는 경우를 위해 내부 처리 한도와 반복 상태 진단을 둔다. 한도 도달은 성공이 아닌 실패이며 사본 전체를 폐기한다. 사용자 설정 옵션으로 노출하지 않는다.
- 한도는 보드 크기와 최악 경로에 근거해 정하고 정상적인 10×10 긴 경로·다중 생성구가 거절되지 않는 정답 사례로 검증한다. 무작위 상태 때문에 종료하지 않는 상황도 단순 상태 비교만으로 놓치지 않는다.

### 이동 상태와 모델링

- 일반/파워의 종류·색·로켓 방향과 매칭 생성 턴 정보는 점유자와 함께 이동한다. 보호를 예전 좌표에 남기지 않는다.
- 현재 좌표 집합 기반 보호는 이동 때 원자적으로 재매핑하거나 점유자 메타데이터로 관리한다. 둘 중 최소 변경으로 단일 진실 원천을 유지하는 방식을 착수 기록에 확정한다. 보드 전체에 불필요한 영구 ID 체계를 만들지 않는다.
- 이미 소모된 파워의 발동 기록은 그 자리에 새로 공급된 다른 파워를 막아서는 안 된다. 기존 상자 피해 기록은 같은 턴 동안 유지하며 정착을 새 턴으로 취급하지 않는다.
- 다음 자동 매칭의 생성 위치 결정을 위해 이동/공급의 묶음 번호와 도착 칸을 결과로 남긴다. 동시 도착은 같은 번호를 사용한다. 자동 매칭 위치 선정 자체는 다음 단계다.

## 파일 책임과 의존성

| 구성 | 책임 |
|---|---|
| `Assets/Scripts/Simulation`의 이동 후보 규칙 | 읽기 전용 직선/경로/통로/대각선 후보와 불가 이유 |
| 같은 폴더의 정착 실행 | 경쟁 해소·이동/공급 반복·종료·결과 기록 |
| 기존 RuntimeState/TurnEffectContext | 점유자 상태와 보호의 이동, 독립 사본, 공급 커서 유지 |
| 기존 BoardActionExecutor | 단계 검사와 정착 명령의 원자적 반영 |
| `Assets/Scripts/Editor/Levels` 기존 실행 시험 | 정착 버튼·결과·정착 후 매칭 조회 |
| 기존 Editor 검증 방식 | 정답 사례·UI·독립 재현·회귀 |

`LevelFlowRules.Next/Graph/Sources`와 저장 검증을 먼저 대조한다. 런타임에서 Editor API나 원본 ScriptableObject를 조작하지 않는다. 저장 정의와 실행 상태를 연결하려고 매번 임시 에셋을 만들지 않는다. 실제 공유 가능한 계산만 재사용하며 범용 그래프 프레임워크·DI·새 패키지/asmdef는 추가하지 않는다. 세부 파일명은 착수 시 확정한다.

## 에디터 사용 흐름

1. 기존처럼 시작 조건을 구성하고 교환 또는 단독 파워 발동을 실행한다.
2. `낙하 대기`에서만 `낙하·공급 실행` 버튼을 사용할 수 있다.
3. 결과에서 이동 출발/도착, 직선/대각선/경로/통로 구분, 생성구별 공급 종류와 커서 변화, 난수 소비, 남은 빈칸을 확인한다.
4. 완료 표시는 `정착 완료 · 자동 매칭 대기`로 한다. 매칭 후보를 조회/강조해도 보드를 다시 변경하지 않는다.
5. 동일 시드 초기화로 교환/발동과 정착을 다시 재현한다. 원본·시드·모드·레벨 변경/창 종료의 기존 무효화 동작을 유지한다.

긴 이동 기록은 스크롤/접기 형태로 제공하고 요약과 실행 버튼의 접근성을 우선한다. 이미지·런타임 애니메이션·새 창은 필요하지 않다.

## 작업 순서와 검증

| 순서 | 작업 | 검증 기준 |
|---|---|---|
| T1 | 11단계 증거, 흐름 검증, 모델/보호와 공급 구조 대조 | 지원표·정책·파일 책임·보존 기준 확정 |
| T2 | 읽기 전용 이동 후보 | 4방향·벽·비활성·상자·경로·합류·통로 정답 |
| T3 | 대각선 경쟁 및 이동 적용 | 양쪽 후보 선택 가능, 중복 이동/점유 없음, 보호 이동 |
| T4 | 기본 공급과 정착 반복 | 지정 위치/목록 소비/소진/기존 유입 우선/종료/실패 보존 |
| T5 | 실행 단계·UI 연결 | 실제 버튼/결과/초기화/좁은 창 접근 |
| T6 | 독립 재현·회귀·완료 감사 | 전체 상태·커서·난수·이동 순서 재현과 원본 보존 |

T1→T2→T3→T4→T5→T6 순서다. 코어 정답이 확인된 뒤 UI에 연결한다.

### 필수 정답 사례

- 아래 기본 낙하와 4방향 회전, 다른 중력 구역 직선 진입, 긴 빈 구간의 차례 낙하.
- 대각선 양쪽 공급/목적지 경쟁, 공급자 자신의 직선 우선, 다른 방향·직접 경로 구역의 대각선 금지, 벽의 두 우회 중 하나/둘 다 차단.
- 비활성 칸 건너뛰기 금지와 옆 채우기, 남은 상자의 고정 점유와 파괴 후 빈자리 유입, 막힌 빈칸 유지.
- 위쪽을 포함한 직접 경로와 끝칸, 합류 우선 후보가 비었거나 막힌 경우, 다른 중력 구역의 합류.
- 통로 정상 이동/출구 점유 대기/입구 우회 금지/합류 우선순위. 실제 좌표 바닥과 점유자 속성 보존.
- 생성구 기존 유입 우선, 미지정 칸 생성 없음, 여러 생성구의 독립 고정 목록과 수량 커서, Stop/Random 소진 정책, 고정 공급 파워 4종과 로켓 방향.
- 선택 색 3~5종 범위와 난수 사용, 조회/막힌 공급의 난수 무소비, 같은 시드 결정성 및 단순 대각선 경쟁의 양쪽 선택 사례.
- 이동한 새 매칭 파워만 보호, 예전 보호 칸/새 공급 파워에 보호가 붙지 않음, 기존 상자 턴별 피해 기록 보존.
- 마지막 이동 수 0에서도 정착 가능. 수/턴/미션 무변경. 자동 매칭이 만들어져도 판정 대기로 멈춤.
- 긴 정상 경로 종료, 순환/비정상 반복 실패 진단, 미지원 공급 사전 거절과 상태·커서·난수·보호 원자적 보존.
- 실제 Unity UI와 독립 프로세스 재현, 8~11단계의 변경 영향 회귀, 원본 JSON/dirty·v4·GUID/meta·무관 파일 보존과 임시 데이터 정리.

예상 좌표·공급 순서·종료 상태는 손으로 정한 정답으로 검사한다. 복잡한 중간 상태를 직접 구성한 검사와 실제 교환→효과→정착 통합 검사를 구분한다. 과거 단계의 검사 수를 이번 결과에 더하지 않는다.

## 제외 범위와 다음 단계

자동 매칭 처리·연쇄 반복·다음 플레이어 수 허용, 드론/자석 발동·파워 조합, 추가 장애물 반응, 고철/회수 공급·즉시 회수·미션/승패·라스트팡, 저장 복구·봇·난이도 분석·랜덤 레벨 추천은 제외한다.

다음 단계 후보는 정착 결과의 도착 기록을 이용하는 자동 매칭과 턴 반복이다. 12단계 완료만으로 전체 플레이나 난이도 평가가 가능하다고 표현하지 않는다.
