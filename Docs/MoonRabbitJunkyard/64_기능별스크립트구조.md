# 기능별 스크립트 구조

작성일: 2026-09-28

## 변경 이유와 범위

기존 `Board`, `Levels`, `Simulation`, `Editor/Levels`에는 기능과 실행 환경, 화면, 검증이 섞여 있었다. 파일을 찾기 쉽도록 `Assets/Scripts/Features` 아래에 기능을 먼저 구분하고, 기능 내부에서 실제 존재하는 역할을 구분했다.

정리 범위는 프로젝트 소유 스크립트·스타일·검증 자료 199개다. 외부 패키지·라이브러리, 저장된 레벨 파일과 등록 모양 에셋은 이동하지 않았다. 기존 미커밋 변경도 파일과 함께 보존했다.

## 현재 구조

```text
Assets/Scripts/Features/
  Board/           보드·칸·좌표
  Levels/          레벨 데이터·검사·에셋 저장
  Matching/        매칭 조회·우선순위
  PowerBlocks/     파워 효과·조합·드론 목표
  Obstacles/       장애물·덮개·먼지·발전기
  BoardFlow/       중력·경로·연결·낙하
  BlockSupply/     생성구·공급 목록·유지 수량
  Missions/        목표·진행·부품 회수
  PuzzlePlay/      실행 상태·시작 구성·사용자 행동·연쇄·종료
  LevelEditor/     통합 작업창·보드 표시·편집 도구
  ShapeCatalog/    등록 모양·중복 검사·사용 기록
  PlayTesting/     수동 플레이·초기 진단 화면
```

각 기능 안에는 필요한 역할만 둔다. `Data`는 저장 값, `Rules`는 구성 규칙, `Validation`은 전체 검사, `Runtime`은 게임과 테스트가 공유하는 실행 로직이다. `Editor` 내부의 `Application`은 편집 명령, `Presentation`은 화면·입력, `Persistence`는 파일 저장, `Inspection`은 Inspector, `Styles`는 스타일, `Tests`는 검증 코드다.

전체 파일 탐색 안내와 예시는 [스크립트 README](../../Assets/Scripts/Features/README.md)를 따른다.

## 유지한 호환성

- 모든 이동 파일의 `.meta` 199개와 기존 폴더 `.meta` 6개를 함께 이동했다. GUID와 메타 내용은 바꾸지 않았다.
- 타입·네임스페이스·직렬화 필드 이름과 Unity 기본 어셈블리는 유지했다. 새 asmdef나 의존성은 추가하지 않았다.
- 에디터 전용 C#은 `Editor` 아래에 유지했다. 검증도 `Editor/Tests`에 있어 플레이어 빌드에 들어가지 않는다.
- partial 클래스의 파일은 같은 소유 기능에 모았다. 통합 작업창 화면은 `LevelEditor`에, 모양 등록 처리는 `ShapeCatalog`에 둔다.
- 파일 이동으로 기존 의존 관계가 새 아키텍처로 분리되었다고 간주하지 않는다. 이번 변경은 기능·역할별 탐색 구조 정리다.

실제 코드 내용 수정은 7개 파일의 스타일 또는 테스트 자료 경로 교체뿐이다. 나머지 이동 파일은 이동 전후 해시가 같다. 이동표·해시·GUID 검증 기록은 `Logs/ScriptStructureVerification`에 있다.

## 검증

공통 실행 로직 16개 검사 묶음, 총 2,684개를 이동 전후 각각 실행하여 같은 결과로 통과했다. Unity 컴파일도 통과했다. 추가로 이동된 구버전 공급 자료 77개, 별도 프로세스 재시작 7개, 모양 등록 UI 38개, 파일 이름 변경·플레이 진입 38개를 통과했다. 이동 후 총 2,844개 PASS이며 모든 검증 프로세스의 종료 코드는 0이다.

기존 기획 문서의 구체적인 파일 경로는 현재 위치로 갱신했다. 과거의 폴더 트리와 단계 기록은 당시 구현 이력으로 남기며, 현재 구조는 이 문서와 스크립트 README를 기준으로 한다.
