# 여러 레벨 시험과 요청 패키지 설치

- 적용일: 2026-09-29. Unity 6000.3.10f1 / Windows Editor.
- 사용자 확인: 현재 이동 횟수의 반복 시험과 난이도별 이동 횟수 추천 시험을 모두 지원한다.
- 개발 검증은 실제 4판만 추가했다. 20,000판 전체 실행은 하지 않았다.

## 사용 방법

`Match → 통합 작업창 → 여러 레벨 시험`에서 저장 레벨을 Ctrl/Shift로 여러 개 선택한다. 전체 선택, 선택 해제, Project 선택 가져오기도 제공한다. 시작 전 선택 개수와 예정 판 수를 표시한다.

- 반복 시험: 현재 이동 횟수로 두 전략을 실행한다. 기본값은 전략별 100판이며 판 수를 지정할 수 있다. 오른쪽 레벨 결과를 선택하면 성공 수와 현재 횟수의 예상 난이도가 나온다. 표본 부족은 판단 보류다. `판별 통계·사례 열기`는 기존 결과·이력 탭으로 연결된다.
- 추천 시험: 각 레벨마다 기존 1~100회 × 두 전략 각 100판을 실행한다. 오른쪽에서 선택한 레벨의 쉬움·보통·어려움·매우 어려움별 이동 횟수와 성공 수를 표시한다. 중간 결과는 완료한 횟수만 추천한다.
- 선택 목록 순서대로 한 레벨씩 실행한다. 오류 레벨은 오류를 남기고 다음 레벨로 넘어간다. 시작 순간의 사본을 사용하며 원본에 자동 적용하지 않는다.
- 일시정지 후 재개/중지가 가능하다. 다른 탭으로 가면 일시정지하고 돌아와도 자동 재개하지 않는다. 재개 가능한 일괄 시험이 있으면 다른 보드 시험을 잠근다.
- 창 종료/재컴파일은 남은 실행을 중단하고 완료 기록을 보존한다. 다시 열면 최근 목록을 보여주지만 자동 재개하지 않는다.
- `Library/Match/MultiLevelTests` 아래 실행 ID/레벨 순번별로 결과를 분리한다. 새 시험은 새 목록을 보여주고 이전 폴더를 보존한다. Library 정리 전 필요한 결과를 복사한다.

[한국어 HTML 안내](Manual/difficulty.html#multi-level)에 실제 화면, 절차, 도움말 링크와 변경 이력을 추가했다.

## 기능별 코드

- `AutoPlay/Editor/Storage/MultiLevelTestStore.cs`: 실행 목록·레벨 사본·상태·결과 ID의 보관. 이전 프로세스의 진행 상태는 중단으로 읽는다.
- `AutoPlay/Editor/Application/MultiLevelTestSession.cs`: 기존 반복/밸런스 실행기를 한 레벨씩 소유하고 제어한다. 게임 규칙이나 봇 전략을 복제하지 않는다.
- `AutoPlay/Editor/Presentation/MultiLevelTestPanel.cs`: 선택·제어·레벨별 조회. 기존 원시 기록 읽기와 네 단계 평가/범위 계산을 재사용한다.
- 통합 창에 다섯 번째 탭을 추가하고 기존 시험의 일시정지 상태까지 중복 실행 차단에 포함했다.

## 설치 패키지

| 패키지 | 고정 버전 | 설치 방식 |
|---|---|---|
| [MemoryPack](https://github.com/Cysharp/MemoryPack) | 1.21.4 | NuGet 본체/Core/Generator + 공식 Unity Git 확장 |
| [ZString](https://github.com/Cysharp/ZString) | 2.6.0 | 공식 UPM Git 패키지 |
| [UniTask](https://github.com/Cysharp/UniTask) | 2.5.11 | 공식 UPM Git 패키지 |
| NuGetForUnity | 4.5.0 | MemoryPack 설치·복원에 사용하는 Editor 도구 |

Unity PackageManager Client API를 사용했으며 manifest/lock에 버전과 해시가 고정되어 있다. NuGet 정의는 `Assets/NuGet.config`, `Assets/packages.config`, 내려받은 본체·생성기는 `Assets/Packages`에 있다. 기존 게임 기록 형식 변경이나 직렬화 데이터 마이그레이션은 포함하지 않았다.

공식 안내에 따라 Unsafe 의존성을 확인했고 NuGet 설치기가 Unity 제공 어셈블리를 사용했다. MemoryPack 생성기가 만든 코드의 직렬화/역직렬화 왕복, ZString 문자열 생성, UniTask 완료 값 처리를 실제 Editor에서 통과했다. Android/iOS/IL2CPP 플레이어 빌드는 이번 검사에 포함하지 않았다.

## 검증

증거: `Logs/MultiLevelVerification`.

- `results.txt`: 12개 통과, 실패 0. 설치된 세 패키지, 세 레벨 선택 사본, 일시정지, 오류 레벨 후 다음 레벨 진행, 개별 원시 판 기록, 원본 불변, 재조회, 추천 모드 중지.
- 실제 신규 플레이는 유효한 두 레벨 × 두 전략 × 1판 = 4판. 잘못된 레벨은 구성 오류로 제외한다. 추천 모드는 시작/중지 구성만 확인하고 게임을 진행하지 않았다.
- `ui-results.txt`, `ui-fixed.log`: 23개 통과, 실패 0. 실제 통합창의 다중 선택, 두 레벨의 서로 다른 추천, 작은 표본 판단 보류, 통계·사례 탭 연결, 일시정지/재개/중지, 탭 전환 잠금, 창 재열기.
- UI 추천 조회는 기존 완료 기록 사본을 사용했다. 사본 읽기는 신규 플레이가 아니다.
- `ui-button-before-fix.txt`: 조회 완료 직후 상세 버튼이 늦게 켜지는 실패를 보존했다. 결과 본문과 버튼 상태를 동시에 갱신하도록 고친 뒤 같은 조건으로 통과했다.
- `multi-level.png`: 실제 최소 창 화면. 목록 제목·예정 판 수·레벨별 추천·버튼을 확인했다.
- HTML 상대 링크·그림·도움말 27개 정적 검사 통과. 브라우저 배치 검수는 기존 후속 이관을 유지한다.
- 최종 Unity 컴파일과 `git diff --check` 통과. 검사 전 기본 일괄 기록 포인터를 복원했고 검사 소유 에셋을 정리했다. 사용자 레벨이나 기존 시험 기록을 삭제하지 않았다.

일괄 추천의 전체 장시간 실행과 다양한 맵의 난이도 품질은 실제 최종 검증에서 확인한다. 이번 작은 개발 검사를 전체 레벨/20,000판 실측 완료로 해석하지 않는다.
