## 목표

제작자가 독립적인 레벨 에셋을 생성하고 기본 Inspector에서 편집·저장·재로딩할 수 있는 데이터 기반을 구현한다. 잘못된 데이터도 손실 없이 보존하면서 오류의 원인과 위치를 확인할 수 있어야 한다.

이 문서를 참조하여 아래 실행문을 제출하면 해당 범위의 구현과 검증을 승인한 것으로 진행한다. 세부 파일명과 API는 계획서의 책임 분리를 유지하는 범위에서 현재 코드에 맞게 조정한다.

## 먼저 확인할 문서와 상태

1. 적용되는 `AGENTS.md`와 Unity 프로젝트 규칙을 읽는다.
2. [1단계 작업 계획](12_1단계_레벨데이터기반_작업계획.md)을 읽고, 필요한 계약을 [게임 규칙](04_게임규칙.md)과 [레벨 에디터](09_레벨에디터.md)에서 확인한다.
3. 현재 소스·패키지·Unity 버전·사용자 변경 사항을 확인한다. 계획서 작성 당시의 프로젝트 상태를 현재 상태로 단정하지 않는다.
4. 구현 순서와 각 단계의 검증 방법을 간단히 정리한 뒤 작업한다.

## 구현 범위

- 레벨별 ScriptableObject와 직렬화 가능한 하위 데이터.
- 레벨 번호, 저장 형식 버전, 이동 횟수, 다섯 종류 중 사용할 3~5종의 색 식별자.
- 기본 10×10 보드와 활성·비활성 칸, 일관된 행·열 좌표.
- 활성 빈칸, 고정 색 일반 블록, 무작위 일반 블록을 구분하는 초기 배치.
- 독립 에셋 생성, 기본 Inspector 편집, 저장과 재로딩.
- 원본을 변경하지 않는 데이터 검사와 위치를 포함한 오류 표시.
- 레벨 번호 중복 검사와 기본 Inspector의 Undo/Redo.

전용 보드 편집 창, 장애물 효과, 중력·공급·미션 편집, 퍼즐 실행, 봇, 난이도 분석은 이번 범위에 포함하지 않는다. 완료 후 2단계를 자동으로 시작하지 않는다.

## 구현 원칙

- 스크립트는 `Assets/Scripts` 바로 아래 `Board`, `Levels`, `Editor/Levels`처럼 기능별로 구성한다. `MoonRabbitJunkyard` 중간 폴더를 만들지 않는다.
- 레벨 에셋의 기본 위치는 `Assets/Data/Levels`로 한다.
- 저장할 레벨 정의, 플레이 중 상태, 편집 화면 상태를 구분한다. 후자의 두 상태를 위한 빈 기반 구조는 만들지 않는다.
- Unity 기본 직렬화와 에셋 기능을 우선하며 불필요한 추상화, 별도 저장 프레임워크, 새 패키지 또는 어셈블리를 추가하지 않는다.
- Editor API는 Editor 영역에만 둔다. 데이터 검사기는 에셋 검색 API에 의존하지 않는다.
- 읽기·검사 과정에서 데이터를 자동 삭제·정규화하거나 무작위 색을 확정하지 않는다.
- 비활성 칸의 배치와 오류 데이터도 보존한다. 구조 검사 통과를 플레이 가능성 검증으로 표시하지 않는다.
- 기존 사용자 변경과 관련 없는 파일을 보존한다. 커밋이나 배포는 이번 목표에 포함하지 않는다.

### 사용 방법

1. Unity에서 **Assets → Create → 퍼즐 → 레벨 데이터**를 실행한다. `Assets/Data/Levels`에 독립 에셋이 생긴다.
2. Inspector에서 레벨 번호·이동 횟수·사용 종류를 편집한다. 보드의 칸 목록은 행 우선이며 각 칸에 행·열 좌표가 표시된다.
3. 초기 일반 블록 배치 목록에 항목을 추가하고 좌표와 고정/무작위 유형을 선택한다. 고정 색은 고정 유형에서만 사용한다. 배치가 없는 활성 칸은 빈칸이다.
4. **데이터 검사**로 오류와 필드 위치를 확인한다. 다른 레벨을 편집한 뒤에도 번호 중복을 다시 검사한다. 검사 결과는 마지막 실행 시점을 기준으로 한다.
5. **레벨 저장**으로 저장한다. 오류 상태도 저장되며 칸을 비활성화해도 배치를 지우지 않는다. Project 창에서 에셋을 다시 선택하면 Inspector로 다시 편집할 수 있다.

### 다음 단계 연결점과 범위

- 저장 원본은 `LevelDefinition` 하나이며 Unity GUID로 식별한다. 레벨 번호·이름·경로 변경은 에셋 식별을 대체하지 않는다.
- 후속 편집 도구는 `SerializedObject`/`SerializedProperty`로 편집해 Unity Undo와 저장 흐름을 사용한다. 읽기는 모델의 속성을 사용한다. `Board.TryGetCell`은 오류 상태의 누락 칸을 안전하게 조회한다.
- `InitialBlockKind.RandomNormal`은 색 미확정 상태이고 `FixedColor`가 null이다. 무작위 유형으로 바꾸기 전의 고정 색 필드는 손실 방지를 위해 저장하되 사용하지 않는다.
- 오류의 `PropertyPath`와 `Coordinate`를 후속 화면의 위치 이동·강조에 연결할 수 있다. 에셋 집합의 번호 중복 검사는 Editor 측에 남긴다.
- 현재 Inspector는 목록 기반이다. 보드 그리기, 장애물, 공급, 게임 실행과 봇은 구현하지 않았다. 2단계는 시작하지 않았다.
- 화면의 최종 시각 디자인은 검증 범위가 아니다. 이번 UI 검증은 배치 Editor의 실제 패널·바인딩·입력 이벤트를 대상으로 했다.

```powershell
& 'C:/Users/ddara/AppData/Local/Unity/bin/unity.exe' run 'C:/Projects/Git/ServeredMeridian' --editor-path 'C:/Program Files/Unity/Hub/Editor/6000.3.10f1/Editor/Unity.exe' --format json -- -nographics -executeMethod Levels.Editor.LevelDefinitionVerification.PrepareAndVerify -logFile 'Logs/LevelDataVerification/prepare-editor.log'
& 'C:/Users/ddara/AppData/Local/Unity/bin/unity.exe' run 'C:/Projects/Git/ServeredMeridian' --editor-path 'C:/Program Files/Unity/Hub/Editor/6000.3.10f1/Editor/Unity.exe' --format json -- -nographics -executeMethod Levels.Editor.LevelDefinitionVerification.VerifyAfterRestartAndCleanup -logFile 'Logs/LevelDataVerification/restart-editor.log'
```
