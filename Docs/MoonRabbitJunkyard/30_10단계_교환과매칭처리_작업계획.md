## 목표

기존 Match 확인 화면에서 일반 블록 두 칸을 순서대로 선택하고, 교환으로 완성한 첫 매칭을 실제 실행 상태에 반영한다. 제거된 칸, 생성된 파워 블록, 선택한 패턴과 제외한 패턴을 확인한다.

이번 단계는 **장애물 없는 보드의 일반 교환 → 첫 매칭 처리 → 낙하 대기**까지다. 전체 한 수나 실제 레벨 플레이 완료를 뜻하지 않는다. 제거 후 빈칸을 그대로 보여주고 추가 조작을 막는다. 다시 시험할 때는 같은 시드로 시작 상태를 재구성한다.

파워 발동·장애물 반응·낙하를 생략한 상태에서 계속 조작하게 하면 잘못된 게임 규칙을 검증하게 된다. 따라서 지원 경계를 명시하고, 미지원 행동은 변경 전에 거절한다.

## 현재 확인한 사실과 선행 조건

- 8단계에는 독립 실행 상태, 시드 난수, 원시 후보 구성, Match 초기 보드 확인 창이 있다.
- 9단계의 `MatchQuery`, `ActionQuery`, `StartingBoardBuilder`와 화면 연결 코드가 존재한다.
- 9단계는 구현과 완료 조건별 증거 감사를 마쳤다. 최종 9단계 검사 246건과 독립 재현 10건, 기존 8단계 회귀 75건이 통과했다. 상세 로그와 보존 감사는 29번 목표 문서에 기록돼 있다.
- 실행 상태의 점유자와 색은 내부 변경이 가능하지만, 현재 조회 코드는 실제 교환·제거를 실행하지 않는다.
- 10단계는 완료된 9단계 코드를 기반으로 착수한다. 착수 시 완료 이후 변경 여부를 확인하고 필요한 회귀만 수행한다. 9단계 Goal을 다시 시작하거나 기존 검사 수를 10단계 결과에 합산하지 않는다.

새 범용 턴 프레임워크나 매니저를 만들지 않는다. 기존 조회를 판정 근거로 사용하고, 패턴 선택과 실행 상태 변경만 책임을 나눈다.

## 지원 범위

| 대상 | 이번 처리 |
| --- | --- |
| 시작 조건을 통과한 독립 보드 | 실행 시험 가능 |
| 전체/부분 고정 일반 블록 | 초기 고정은 이동 잠금이 아니므로 교환 가능 |
| 일반 ↔ 일반 | 기존 ActionQuery로 검증한 뒤 실행 |
| 직선 3/4/5 이상, ㄱ·ㄴ·T, 2×2 | 첫 매칭 제거 및 파워 생성 |
| 기존 노출 파워 | 그대로 보존. 파워를 포함한 교환·제자리 발동은 실행 미지원 |
| 비활성 칸·벽 | 기존 교환·매칭 연결 제약 유지 |
| 중력·경로·통로·생성구 설정 | 보존. 이번에는 이동·공급하지 않음 |
| 장애물·덮개·먼지·회수 부품이 있는 보드 | 실행 시험 미지원. 기존 읽기 전용 조회는 유지 |
| 미션 | 정의·진행값 보존. 제거 사실을 결과에 기록하되 미션 진행·승패 판정하지 않음 |

장애물 제한은 **이번 도구의 실행 지원 범위**이며 게임 규칙이나 레벨 저장 검증을 변경하지 않는다. 나무상자 인접 피해, 먼지 제거, 회수 도착 등을 조용히 무시한 채 실행 성공을 반환하지 않는다. 원시 후보는 기존대로 조회할 수 있으나 실행 시험에는 사용하지 않는다.

## 실행 계약

1. 시작 조건 구성이 성공한 상태에서 별도의 실행 시험을 연다. 원본 LevelDefinition과 조회용 시작 스냅샷은 보존하며 작업 상태만 변경한다. 복사가 필요하면 실제 상태를 복사하며 원시 빌더로 다시 뽑아 대체하지 않는다.
2. 첫 칸은 이동 출발, 두 번째 칸은 도착이다. 자동 행동 목록을 사용하더라도 실행 요청에는 방향을 보존한다.
3. 실행 시 현재 상태를 기준으로 다시 판정한다. 이전 조회 결과 객체만 믿고 실행하지 않는다.
4. 준비 상태, 남은 이동 수, 지원 보드/행동, 교환 유효성을 모두 검사한 뒤 변경한다. 거절은 칸·수·난수·미션·공급을 바꾸지 않는다. 게임 규칙상 불가와 이번 단계 미지원을 구분한다.
5. 교환과 선택 패턴 처리 전체를 한 번 적용한다. 유효 교환은 이동 수를 정확히 1 차감한다. 동시에 두 패턴이 완성되어도 2회를 소비하지 않는다.
6. 일반 3매칭은 선택 좌표를 비운다. 파워 패턴은 생성 칸을 해당 파워로 바꾸고 나머지 선택 좌표를 비운다. 빈칸/파워에 이전 일반 색이나 불필요한 점유자 필드를 남기지 않는다.
7. 처리 후 상태는 `낙하 대기`다. 이동 수가 0이어도 패배로 판정하지 않으며, 추가 교환·발동을 거절한다. 이번 단계에서 턴 완료·보드 안정·클리어를 선언하지 않는다.
8. 결과에는 입력 방향, 처리 전후 이동 수, 선택/제외 패턴, 제거 좌표와 원래 색, 생성 좌표·파워·로켓 방향, 난수 추출 전후 값을 보관한다. 일반 블록에서 파워로 변환된 사실도 별도로 남겨 향후 수집 집계에서 빠지지 않게 한다. 범용 이벤트 버스는 만들지 않는다.

## 패턴 선택과 생성 위치

### 확정 규칙 유지

- 우선순위: 무지개 자석 > 달 폭탄 > 청소로켓 > 수거 드론. 같은 우선순위면 구성 블록 수가 많은 패턴, 수까지 같으면 무작위 선택.
- 직선 6개 이상은 최대 연속 구간 하나에서 자석 하나만 생성한다.
- 선택한 패턴에 속한 칸만 처리한다. 자석 직선과 드론 2×2가 겹쳐 자석을 선택하면 직선 밖의 드론 전용 칸은 남긴다.
- 4개 가로 매칭은 세로 로켓, 세로 매칭은 가로 로켓이다. 신규 파워는 일반 색을 가지지 않는다.
- 직접 교환은 해당 패턴을 완성한 교환 블록의 도착 칸에 생성한다. 양쪽의 독립 패턴은 각 블록의 도착 칸에 하나씩 생성한다.
- 새 파워는 이번 수의 후속 연쇄 전체에서 보호해야 한다. 이번 결과에 생성 사실과 턴 소속을 남기고, 낙하 대기에서 보호를 해제하지 않는다. 실제 피격 보호 검증은 효과 구현 단계로 남긴다.

### 구현 정책 제안

아래는 기존 문서가 알고리즘까지 지정하지 않은 부분을 구체화한 제안이다. 이 계획을 지정한 Goal 실행 요청 시 적용하고, 확정 규칙과 모순이 발견되면 구현 전에 해당 사례를 제시한다.

- **겹침 그룹:** 구성 칸을 공유하는 패턴을 연결 그룹으로 묶는다. A-B, B-C가 겹치면 같은 그룹으로 처리한다. 그룹 안에서 우선 패턴 하나를 선택하고 낮은 패턴의 잔여 칸을 같은 처리에서 다시 매칭하지 않는다. 그룹끼리 떨어진 패턴은 각각 처리한다.
- **일반 3매칭 중복:** 파워 패턴에 포함되는 하위 직선 3개를 별도 제거로 처리하지 않는다. 파워가 없는 독립 3매칭은 정상 처리한다. 손으로 만든 교차/사슬 예제로 이 정책의 실제 선택 좌표를 문서화한다.
- **생성 위치 후보:** 선택 패턴에 포함되는 교환 도착 좌표만 후보로 삼는다. 두 좌표가 모두 후보라면 사용자가 지정한 두 번째 칸을 우선한다. 후보가 없다면 임의 좌표에 생성하지 말고 계약 위반으로 적용 전에 거절한다.
- **난수:** 패턴 및 그룹을 좌표 기반으로 안정 정렬한 다음 동률 후보가 둘 이상일 때만 실행 상태 난수를 사용한다. 조회·목록 강조·실패 입력은 난수를 소비하지 않는다. 후보 하나에 불필요한 추출을 하지 않는다.

자동 낙하의 최종 도착 칸, 동시 도착 난수, 거미줄 생성 위치 대체는 이번 실행 대상에 없으므로 임의 대체 규칙을 만들지 않는다. 후속 단계에서 이동 이력과 피해 처리를 연결한다.

## 코드 책임 제안

| 경로 | 책임 |
| --- | --- |
| `Assets/Scripts/Simulation/MatchResolution.cs` | 중첩 그룹, 선택 근거, 제거/변환 결정과 결과 값 |
| `Assets/Scripts/Simulation/BoardActionExecutor.cs` | 현재 상태 재검증, 지원 경계, 교환·수 차감·첫 매칭 적용, 낙하 대기 상태 |
| 기존 `LevelRuntimeState`/`SimulationRandom` | 필요한 최소 작업 상태 복사·실행 소유권·난수 연결 |
| 기존 `MatchQuery`/`ActionQuery` | 판정 재사용. 읽기 전용 계약 유지 |
| 기존 `Editor/Levels/LevelInitialStateWindow` partial 및 USS | 실행 시험, 입력 방향, 결과 강조, 초기화·오래된 결과 폐기 |
| `Editor/Levels`의 전용 검증 코드 | 정답 예제, 상태 보존, 실제 화면, 독립 프로세스 재현 |

파일명은 역할 제안이다. 작은 결과 타입마다 파일/폴더를 늘리지 않는다. Editor가 런타임 내부 필드를 직접 조작하지 않으며 실행 코드는 Editor API를 참조하지 않는다. 새 패키지·asmdef·게임명 폴더·DI 계층·저장 형식 변경은 없다.

## 화면과 조작

- 진입 메뉴는 기존 **Match → 초기 보드 확인**을 유지한다.
- 기존 조회와 구분되는 `실행 시험` 영역을 둔다. 기존 결과 목록을 클릭했다고 즉시 교환하지 않는다.
- 두 칸 선택 → 출발/도착 표시 → `교환 실행` 버튼의 짧은 동선으로 구성한다. 같은 칸을 재선택하거나 선택을 취소할 수 있다.
- 실행 결과에는 제거 칸/생성 파워 강조, 선택 근거, 남은 이동 수와 `첫 매칭 처리 완료 · 낙하 대기`를 표시한다. `낙하·파워 발동·장애물·미션 판정 미지원`을 함께 안내한다.
- `같은 시드로 초기화`는 시작 상태·선택·실행 결과·난수 진행을 재구성한다. 별도 Undo 저장소나 무제한 실행 이력은 도입하지 않는다.
- 레벨/시드/모드/미저장 정의 변경 시 실행 상태와 이전 성공 표시를 폐기한다. 창 종료 후 지연 결과를 적용하지 않는다.
- 입력과 버튼은 가능하면 한 줄에 배치하고 상세 결과는 접을 수 있게 한다. 1000×780 및 680×480에서 두 칸 선택·실행·초기화·끝칸·진단 접근을 확인한다.

## 구현 순서 제안과 검증

1. **선행 확인:** 9단계 완료 증거와 현재 소스 비교. 원본/사용자 파일 해시 및 임시 에셋 소유 경로 기록.
2. **패턴 선택:** 손으로 지정한 패턴·중첩·사슬 겹침·동률 정답 예제와 선택 좌표를 검증. 확정 규칙과 제안 정책을 구분해 기록.
3. **실행:** 일반 교환, 독립 양쪽 매칭, 파워 생성과 색 제거, 수 차감, 무효 입력 무변경, 낙하 대기 재입력 차단을 검증.
4. **화면:** 실제 Unity 조작으로 실행·거절·초기화·변경 폐기 및 좁은 창을 확인.
5. **재현과 회귀:** 동일 정의/시드/입력 방향/알고리즘 버전의 결과·난수 진행을 독립 Unity 프로세스에서 비교. 8단계 원시 후보와 9단계 읽기 전용 조회/시작 구성의 영향 범위 회귀.
6. **감사:** 원본 JSON/dirty·GUID/meta·v4·미션·공급·무관 파일 보존과 임시 데이터/검증 프로세스 정리. 실제 검증 결과와 사용법 기록.

필수 예제는 3/4/5/6+ 양 방향, ㄱ·ㄴ·T 각 방향, 독립 2×2, 자석+드론 중첩, 같은 우선순위의 길이 차이/완전 동률, 양쪽 독립 생성, 벽/비활성/같은 색/비인접/빈칸/이동 수 0, 파워 입력 미지원, 장애물 계층별 미지원, 거절 전후 전체 상태·난수 일치다. 결과를 같은 구현으로 다시 계산한 비교만으로 정답을 주장하지 않는다.

실제 효과가 없으므로 기존 파워 연쇄 발동·신규 파워 피격 보호의 완성, 장애물 해결, 난이도·클리어 가능성은 검증했다고 표시하지 않는다.

## 후속 단계

다음은 파워 발동과 피해 처리, 낙하·생성구 공급과 자동 매칭, 미션·승패의 연결 순서로 세분화한다. 드론 목표 조회/예약과 봇은 필요한 실행 규칙이 갖춰진 뒤 연결한다. 이번 문서는 그 단계 번호나 완료 일정을 확정하지 않는다.

문서 작성만으로 Goal 생성·기존 Goal 완료·코드 구현을 수행하지 않는다. Goal 실행 시 상세 작업 의존성과 수정 파일 책임을 기록한다.
