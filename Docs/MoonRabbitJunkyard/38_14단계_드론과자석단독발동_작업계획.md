## 목표와 현재 상태

수거드론·무지개 자석을 일반 블록과 교환하거나 제자리에서 발동하고, 기존 파워에 맞았을 때도 단독 효과로 연쇄 발동하도록 한다. 드론은 남은 미션을 기준으로 추가 목표를 선택하며 여러 드론이 후보와 예약을 공유한다. 기존 자동 매칭·정착·다음 사용자 수 흐름에 연결한다.

착수 전 13단계 완료 감사와 최종 소스 해시를 대조한 결과 불일치 0건이었다. 당시 `BoardActionExecutor.Supports`는 드론/자석과 파워 조합을 거절하고, `DamageReaction`도 두 파워의 피격 발동을 미지원으로 반환했다. `PowerEffectResolution`은 로켓/폭탄의 즉시 타격 스택만 처리했고 `RuntimeMission.Progress`와 제거 전 색상 기록을 실행에 연결하는 작업이 필요했다. 아래 계획을 구현한 최종 상태는 목표 문서의 완료 감사를 참조한다.

드론의 남은 미션 판단을 위해 **색상 수집·나무상자 제거의 진행량 집계**가 이번 단계의 최소 선행 기능이다. 이것 없이 시작 시 목표 수량만 참조하면 이미 완료한 목표를 계속 조준한다. 진행량 집계는 포함하되 클리어·실패·보상 판정은 후속으로 남긴다.

## 범위 선택

| 대안 | 이점 | 문제 | 판단 |
|---|---|---|---|
| 드론은 일반 블록 무작위, 자석만 구현 | 작고 빠름 | 미션 우선·공유 예약 요구를 만족하지 못함 | 제외 |
| 현재 지원 대상의 실제 진행량 + 드론/자석 단독 효과 | 목표 판단과 연쇄를 실제로 검증 가능 | 색상/상자 미션으로 시험 범위 제한 | 채택 |
| 모든 장애물·미션·파워 조합까지 구현 | 전체 효과 검증 가능 | 목표 규칙과 조합이 한꺼번에 결합됨 | 후속 분리 |

| 항목 | 14단계 |

| 색상 수집, 나무상자 제거 미션 | 실제 진행량·남은 수량 및 드론 기여도 조회 지원 |
| 드론 추가 타격 | 한 칸 목표, 후보 재사용·재평가·선택/예약·해제·재탐색 |
| 자석 | 교환 색 지정, 제자리/피격 시 현재 존재 색 무작위, 대상 없는 피격 소모 |
| 기존 중력·경로·통로·기본 공급 | 12~13단계 지원 유지 |

| 그 외 미션 | 이번 실행 시험에서 명시적으로 미지원 처리. 임의로 완료하거나 무작위 대체하지 않음 |

전체 확정 규칙의 거미줄 우선순위·곰팡이 은폐·발전기 전체 예약·폐가전 중간 피해 합산·조합 드론 범위 예약은 문서 11에 그대로 남긴다. 이번에 미지원 대상을 가짜 구현하거나 확정 규칙을 삭제하지 않는다. 후속 대상 규칙을 추가할 때 필요한 경계만 유지하고 빈 구현체는 만들지 않는다.

## 확정 규칙

1. 수거드론은 발동 칸 중심 `+` 5칸을 먼저 타격하고 추가 목표 한 칸을 타격한다. 보드 밖/비활성 칸은 무시하며 벽은 파워 범위를 막지 않는다.
2. 유효한 남은 미션 후보를 우선하고 후보 중 무작위 선택한다. 색상 미션과 장애물 미션 사이에 새로운 우선순위를 만들지 않는다.
3. 미션 후보가 없으면 타격 가능한 일반 블록 중 무작위 선택한다. 일반 블록도 없으면 추가 타격 없이 종료한다. 아무 파워/장애물을 무작위 대체 목표로 삼지 않는다.
4. 다른 드론의 예약 칸과 이번 수에 이미 피해받은 나무상자는 후보에서 제외한다. 선택과 예약은 하나의 동작이다.
5. 예약 목표가 사라지거나 유효하지 않으면 기존 예약을 해제하고 **미션 후보부터 다시 찾는다**. 그다음 일반 블록, 마지막으로 추가 타격 없음 순서다.
6. 예약의 예상 기여와 실제 미션 진행은 별개다. 예약 해제는 상자의 턴당 피해 기록을 초기화하지 않는다.
7. 자석을 일반 블록과 교환하면 교환한 일반 블록의 색을 선택한다. 제자리/피격 발동은 실제 보드에 있는 일반 블록 색 중 무작위다.
8. 일반 블록이 없으면 자석의 사용자 단독 발동은 불가하고 이동 수를 소비하지 않는다. 피격 자석은 추가 효과 없이 소모한다.
9. 기존 파워는 피격 시 단독 효과로 즉시 발동하며 한 번만 소모한다. 파워들이 연쇄로 함께 맞아도 전용 조합 효과를 만들지 않는다.
10. 이번 수의 매칭 생성 파워 보호, 공급 파워 비보호, 상자 턴당 1피해, 마지막 수의 전체 연쇄 완료를 유지한다.
11. 모든 즉시 효과와 드론의 추가 타격이 끝난 뒤 낙하·공급한다. 드론 타격을 다음 사용자 수로 예약하지 않는다.
12. 나무상자 제거 미션은 내구도가 0이 된 한 칸을 1개로 센다. 내구도 감소만으로 완료 수량을 줄이지 않는다.

## 구현 정책 제안

다음 세부 정책은 이 계획을 지정한 Goal 실행 요청에 포함한다. 기존 확정 규칙과 충돌하면 근거를 기록하고 해결한다.

### 실제 미션 진행과 예상 기여

- 기존 RuntimeMission을 단일 실제 진행량으로 사용한다. 목표 매니저에 별도의 실제 완료 카운터를 만들지 않는다.
- 일반 매칭/파워 제거에서 소비된 일반 달토끼의 원래 색을 집계한다. **매칭으로 파워가 되는 칸도 일반 달토끼 1개를 소비한 것으로 집계**하는 정책을 제안한다. 이 항목은 기존 문서의 명시 확정값과 구분하며 실행 시 정책으로 기록한다.
- 이동·교환 자체·공급·조회·예약 등록만으로 진행량을 올리지 않는다. 기존 파워 소모도 색상 수집이 아니다.
- 각 일반 점유자의 실제 소비와 상자의 양수→0 전환을 한 번만 반영한다. 겹친 타격·기존 매칭 결과와 효과 결과의 중복 집계를 막는다. 진행 표시는 목표 수량까지로 제한한다.
- 제거 전 색과 내구도 전환을 기존 변경/효과 기록에서 전달한다. 실제 피해 적용과 같은 시점에 집계하여 다음 드론 요청이 최신 남은 목표를 읽게 한다. 범용 이벤트 버스는 추가하지 않는다.
- 상자 내구도 2 이상의 1피해도 유효한 미션 도움으로 조회한다. 다만 예상 완전 제거 수는 0이며, 내구도 1의 예약만 제거 예정 1개로 센다. 이미 예약만으로 남은 목표가 충족될 경우 해당 미션 후보를 추가 추천하지 않는다.
- 이번 효과 중 목표 수량을 채워도 승리로 판을 종료하지 않는다. 실제 진행량은 드론 추천과 검수에 사용하고 UI에 `승패 판정 미지원`을 유지한다.

### 반응·미션 조회와 목표 매니저

- `DamageReaction`의 실제 대상 반응을 재사용한다. 일반 블록과 상자의 기여도 계산은 대상/미션 규칙 쪽에 두고, 목표 매니저는 후보·예약만 관리한다.
- 일반 블록 규칙과 상자 규칙을 구분해 조회할 수 있게 한다. 현재 두 대상에 필요한 구체 타입/분기만 사용하며 모든 장애물을 담는 거대 매니저나 범용 플러그인 등록 체계는 만들지 않는다.
- 첫 후보 요청에서 보드를 읽고, 보드/실제 미션/턴 피해 상태가 같으면 후보 정보를 재사용한다. 예약 필터는 요청마다 최신 상태를 반영한다.
- 실제 제거·내구도/피해 기록·미션 변경 시 캐시를 무효화한다. 다음 요청 시 전체 재평가한다. 한 번만 조회한 목록을 한 턴 내내 고정하지 않는다.
- 조회는 보드·미션·난수·예약을 변경하지 않는다. 실제 선택/등록에서만 실행 난수를 소비한다. 후보 순서는 좌표 기준으로 정하고 단일 후보는 난수를 소비하지 않는다.
- 매니저는 효과 처리 작업 사본에 종속된다. 모든 드론이 같은 인스턴스를 공유하되 전역 singleton이나 봇이 접근하는 서비스로 만들지 않는다.
- 요청/예약에는 안정적인 요청 번호, 조준 칸, 대상 반응, 예상 기여량을 남긴다. 같은 칸이 다른 점유자로 바뀌는 경우에도 예약 유효성을 재확인한다. 영구 블록 ID는 필요할 때만 검토한다.

### 효과 처리 순서와 예약 수명

- 기존 즉시 타격 스택과 별도로 이번 효과 단계의 드론 추가 타격 대기를 관리한다. 이는 애니메이션/실시간 비행 시스템이 아니다.
- 드론이 발동하면 먼저 소모 등록하고 `+` 타격을 처리한다. 해당 국소 효과와 그 즉시 연쇄가 끝난 뒤 현재 상태에서 목표를 요청/예약한다.
- 예약한 드론을 즉시 맞혀 예약을 지우는 방식만 사용하면 여러 드론의 공유 예약을 검증할 수 없다. 즉시 타격과 목표 요청을 진행하면서 추가 타격 예약을 유지하고, 즉시 타격 스택이 비면 예약 순서대로 착탄을 처리한다.
- 착탄 직전 목표/미션 기여/다른 예약을 재검사한다. 중간 파괴나 목표 완료로 무효화되면 미션부터 재탐색한다. 다른 예약의 예상 기여를 유지하며 자기 기존 예약의 기여만 되돌린다.
- 착탄으로 발생한 기존 파워는 즉시 처리하고, 그 이후 다음 착탄을 진행한다. 새 드론 요청도 같은 관리자를 사용한다. 예약 대기까지 모두 비어야 낙하로 전환한다.
- 예약 완료/취소/재탐색과 예상 기여량 변화를 결과에 기록한다. 성공한 효과 종료에 미해제 예약이 없어야 한다.
- 실제 + 연쇄로 드론 두 대 이상을 발동하는 통합 사례를 포함한다. 15단계 조합을 가짜로 넣어서 예약 검사를 대신하지 않는다.

### 자석의 색 선택과 제거

- 일반 블록과의 교환 입력에서 상대 블록의 색을 보존해 발동 문맥에 전달한다. 교환 후 첫 매칭으로 해당 블록이 사라져도 다른 색을 다시 무작위 선택하지 않는다. 어느 쪽 좌표를 먼저 선택했는지도 결과를 바꾸지 않는다.
- 제자리/피격 발동 시점에 실제 존재하는 색의 중복 없는 목록을 만들고 균등 선택한다. 블록 수에 비례해 색을 뽑지 않는다. 색 하나면 난수를 쓰지 않는다.
- 선택 색의 일반 블록만 타격한다. 파워 블록에 생성 당시 색을 부여하거나 상자를 직접 색 제거 대상으로 삼지 않는다. 벽/거리/구역은 색 제거를 막지 않는다.
- 14단계 실행 지원표에 따라 거미줄/곰팡이 보드는 사전 거절한다. 나중에 지원할 때 거미줄은 색 선택 포함·안의 블록 보존, 곰팡이는 색 선택/효과 제외라는 확정 규칙을 적용한다.
- 동일 자석의 중복 피격은 한 번만 발동한다. 일반 블록 없는 피격 자석의 소모도 별도 결과로 기록한다. 보호된 새 자석은 소모하지 않는다.

### 원자성·난수·상태 연결

- 사용자 행동 및 자동 효과 단계는 보드·미션·난수·턴 문맥·목표 관리자/예약을 작업 사본에서 처리한다. 실패하면 해당 단계의 변경과 예약을 모두 버린다.
- 앞서 성공한 연쇄 단계는 보존한다. 거절한 직접 파워 조합과 대상 없는 자석 입력은 수/턴/난수를 소비하지 않는다.
- `Supports`·행동 후보·종료 사유·UI 안내에서 드론/자석 단독 발동을 지원하도록 함께 갱신한다. 조합은 계속 거절한다.
- 이벤트 수/재탐색의 내부 한도와 무진행 진단을 둔다. 한도 초과는 실패이며 성공·후속 낙하로 처리하지 않는다. 사용자 옵션을 추가하지 않는다.
- 효과 시작 순서·타격 순서·후보 좌표 순서·예약/착탄 순서를 고정하여 동일 정의/시드/행동/버전에서 재현한다.

## 작업 순서와 책임

| 작업 | 의존 | 책임/변경 영역 | 검증 기준 |
|---|---|---|---|
| T1 선행 대조 | 없음 | 13단계 증거·규칙·현재 소스·보존 기준 | 범위/정책/파일 책임 기록 |
| T2 진행량과 반응 조회 | T1 | Simulation의 기존 변경 기록·미션 기여 규칙 | 색상/상자 정확 집계·조회 무변경 |
| T3 드론 목표 관리 | T2 | 후보 캐시·추천·예약·예상 기여 | 재사용/무효화·중복 방지·해제·재탐색 |
| T4 단독 효과 통합 | T3 | PowerEffectResolution·DamageReaction·발동 문맥 | + 후 조준·착탄 연쇄·자석 색·원자성 |

기본 순서는 T1→T2→T3→T4→T5→T6이다. 스크립트는 `Assets/Scripts/Simulation`과 `Assets/Scripts/Editor/Levels` 아래 책임별로 분리한다. 새 게임명 폴더·패키지·asmdef·별도 실행 엔진을 만들지 않는다. 에셋 v4와 기존 GUID/meta를 보존한다. 구체 파일명은 착수 시 확정한다.

## Match 사용 흐름

기존 창의 교환/제자리 발동과 단계/연쇄 끝까지 실행을 그대로 사용한다. 오른쪽에 선택 색, 드론의 + 타격/후보 이유/예약/해제/재탐색/추가 타격, 실제 미션 진행과 예상 기여를 구분해 표시한다. 예약을 완료 보상이나 실제 진행으로 표시하지 않는다. 긴 기록은 접기/스크롤로 제공하며 새 설정 화면이나 비행 애니메이션은 만들지 않는다.

## 필수 검증

- 드론 교환 양방향/제자리/피격, + 가장자리·비활성·벽, 국소 파괴 후 목표 선정, 추가 타격 1칸과 목표 없음 종료.
- 실제 + 연쇄로 여러 드론 요청·예약 공유, 같은 칸 제외, 미션 수량보다 드론이 많은 경우 일반 블록 대체, 일반 블록도 없는 경우 종료.
- 목표 상실 시 다른 미션 후보부터 재탐색하고 없을 때만 일반 블록 선택. 예약 취소/완료 후 예상 기여 반환, 턴 피해 제한 유지.
- 캐시 재사용 횟수와 상태 변경 후 재평가를 검사하되 증분 최적화는 하지 않음. 조회 반복의 상태/난수/예약 무변경.
- 색상/상자 후보 동등 무작위, 상자 내구도 2의 기여와 내구도 1의 제거 예정 구분, 이미 피해받은 상자 제외.
- 실제 매칭·변환·로켓/폭탄·드론 +/착탄·자석 제거의 색상 집계, 상자 완전 제거만 집계, 중복 타격 무중복·미션 완료 후 후보 갱신.
- 자석 교환 상대 색 보존과 좌표 선택 방향, 제자리/피격의 실제 존재 색 선택, 색별 개수 불균등 보드에서 색 단위 선택, 단일 색 무난수.
- 일반 블록 없는 사용자 자석 거절/피격 자석 소모, 보호된 새 자석 유지, 색 제거가 파워/상자를 직접 제거하지 않음.
- 기존 파워 4종의 혼합 피격 연쇄·중복 소모 방지·예약까지 끝난 후 정착, 새 매칭 파워 보호/공급 파워 비보호·같은 턴 피해 제한.
- 두 파워 직접 교환은 미지원·무비용, 미지원 보드/미션 사전 거절, 단계 후반 실패 시 보드/미션/난수/예약 보존과 앞선 성공 단계 유지.
- 마지막 수/다음 수, 단계별과 끝까지 실행 일치, 실제 Match UI 1000/680 폭·원본/시드/모드/레벨 변경·창 종료 해제.
- 동일 정의/시드/여러 행동/버전의 목표 선택·예약·착탄·색 선택·미션·전체 상태를 독립 Unity 프로세스에서 재현.
- Unity 컴파일과 8~13단계 영향 회귀. 미션 집계와 지원 확대 때문에 바뀐 기존 기대값은 새 규칙 근거를 남겨 갱신하며 보존 검사를 제거하지 않음.
- 원본 정의/dirty/v4/GUID/meta·무관 파일 보존, 소유 임시 에셋·프로세스 정리, 완료 조건별 증거와 한계 기록.
