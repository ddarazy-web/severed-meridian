# 달 토끼 고물상 — 자동 플레이와 난이도 분석

- 확정된 기획과 후속 결정 사항을 정리한 문서이며 구현·실행·난이도 검증 완료를 의미하지 않는다.
- 실제 퍼즐 판정은 [게임 규칙](04_게임규칙.md), 제작 흐름은 [레벨 에디터](09_레벨에디터.md)를 따른다.
- 2026-09-29 구현 상태: 29단계까지 완료 기록이 있으며 30단계 전체 통합 검수는 진행 중이다. [29단계 검증](84_29단계_구현검증기록.md)과 [30단계 진행 기록](85_30단계_통합검수진행기록.md)을 기획 자체와 구분하여 읽는다.

## 우선 개발 범위

- 제작자가 맵·장애물·미션·이동 횟수·공급 구성을 직접 만든다.
- 정합성 검사를 통과한 레벨을 자동 플레이하고 기록을 분석해 예상 난이도와 판단 근거를 추천한다.
- 초기 범위는 직접 만든 레벨의 평가다. 무작위 레벨 후보 생성과 자동 구성 추천은 후순위로 미룬다. 전체·부분 생성의 세부 범위는 현재 개발 대상으로 확정하지 않는다.
- 자동 난이도 평가는 부스터·게임 중 아이템·광고 이어하기 없이 진행한다. 수동 에디터 테스트의 아이템 무제한 사용과 별개다.
- 자동 플레이 결과는 예상 난이도의 근거이며 실제 사람의 체감 난이도를 확정하는 값은 아니다.

## 이동 횟수별 밸런스 추천 — 2026-09-29 추가 결정

- 사용자가 만든 레벨의 사본을 대상으로 **이동 횟수 1~100회 전부** 시험한다. 각 횟수마다 기본·계획 전략 각 100판, 총 20,000판이다. 자동 확장·30개 후보 제한 대신 전체 범위 시험을 선택했다.
- 한 시험에서는 모든 횟수에 동일한 새 시드 100개를 사용한다. 새 시험을 시작하면 새 시드를 만든다. 원본 레벨, 미션, 장애물, 공급과 봇 관찰 조건은 바꾸지 않는다.
- 두 전략 중 높은 성공률을 기준으로 쉬움 ≥60%, 보통 ≥40% 및 <60%, 어려움 ≥20% 및 <40%, 매우 어려움 >0% 및 <20%로 추천한다. 후속 사용자 결정에 따라 결과·이력과 이동 횟수 추천을 모두 네 단계로 통일한다. 매우 쉬움은 제공하지 않으며 60% 이상을 모두 쉬움으로 판정한다. 공통 평가 버전은 `bot-difficulty-v2`다.
- 실제 200판을 완료한 이동 횟수만 추천에 포함한다. 연속된 횟수만 범위로 묶으며 미시험·다른 난이도를 건너뛰어 범위를 만들지 않는다. 성공 0%·오류·미완료는 추천에서 제외한다.
- 전체 완료 전에는 중간 결과다. 없는 단계는 `추가 시험 필요`, 전체 완료 후에도 없는 단계는 `추천 없음 (1~100회 시험 결과)`으로 표시한다. 네 난이도 모두가 반드시 존재한다고 가정하지 않는다.
- 일시정지 후 중지·재개가 가능하다. 탭 이동은 일시정지하고 복귀 시 자동 재개하지 않는다. 창 종료·재컴파일은 중단으로 남기며 진행 중 게임은 복원하지 않는다. 완료한 횟수별 결과와 원시 판 기록은 프로젝트 로컬에 보관한다.
- 결과를 보고 제작자가 원본의 이동 횟수를 직접 선택한다. 자동 적용은 하지 않는다. [사용 방법](Manual/difficulty.html#move-balance)을 참고한다.
- 구조: `AutoPlay/Runtime/Analysis`는 결과 데이터와 범위 계산, `AutoPlay/Editor/Application`은 기존 `BotBatchSession` 순차 실행, `Editor/Storage`는 요약·원시 기록, `Editor/Presentation`은 시작·중지·추천 표시를 담당한다. 실제 매칭·게임 판정과 봇 전략을 복제하지 않는다.

검증: `Logs/BalanceVerification`에 기록했다. 새 기능 33개, 기존 반복 UI 21개, 난이도 경계 29개 검사 통과. 새 기능의 성공한 실행 검증은 임시 레벨의 이동 1·2회 각각 200판(총 400판)이며, 전체 20,000판을 실행한 결과는 아니다. 100개 횟수의 범위 계산과 전체 완료/손상 저장 판정은 합성 표본으로 별도 검사했다. 실제 화면에서 좁은 창의 필수 조작과 추천 노출을 확인했고 원본 레벨·등록 맵 6개 파일 해시를 보존했다. 첫 검증에서 발견한 Windows 파일 교체 잠금은 기존 제한 재시도를 재사용하여 해결했다. 기존 반복 UI 첫 실행은 특정 시드의 재배치 탐색 한도로 실패하여 원시 기록을 보존했고, 게임 규칙 변경 없이 재시험하여 UI 검사를 통과했다. HTML 브라우저 배치 검수는 기존 합의에 따라 후속 항목으로 남긴다.

## 봇 전략

- 기본 전략과 계획 전략을 함께 실행하여 비교한다.
- 기본 전략은 당장 미션을 진행하거나 파워 블록을 만드는 수를 평가한다.
- 계획 전략은 공개 정보로 만든 가정에서 두 수를 탐색한다. 가정·표본·계산 한도는 [26단계 탐색 경계](73_26단계_가정탐색경계.md)를 따른다. 실제 숨은 공급이나 미래 난수를 읽지 않는다.
- 전략별 결과 차이를 활용해 즉시 선택으로 풀리는지, 앞을 내다보는 판단이 중요한지 분석한다. 전략을 사람의 실력 등급과 동일시하지 않는다.

## 관찰 조건과 구조적 분리

- 플레이 봇은 플레이어에게 공개된 정보만 관찰하고 동일한 조작 규칙으로 플레이한다.
- 숨겨진 공급 목록·곰팡이 내부·실제 미래 난수 결과를 조회할 수 없다. 공개 정보로 추론하는 것은 허용한다.
- 계획 전략이 미래 공급을 탐색할 때도 실제 비공개 결과를 사용하지 않고 가능한 경우를 가정한다.
- 별도 프로그램이나 프로세스로 실행하는 방식이 아니라 Unity 안에서 구조와 로직을 분리한다.
- 게임 실행부는 실제 상태·규칙을 관리하고 조작을 실행한다. 관찰 정보 제공부는 공개 정보만 봇에 전달한다. 봇은 관찰 정보로 판단한 조작 요청을 반환한다. 분석기는 내부 기록을 받아 통계와 난이도를 평가한다.
- 봇은 게임 내부 상태를 직접 참조하거나 수정하지 않는다. 분석기가 기록한 내부 상태도 봇에게 전달하지 않는다.
- 봇을 교체하거나 제거해도 게임 규칙과 기록·분석 기능은 유지한다.
- 봇의 조작 요청은 사용자 입력과 동일한 검증·실행 경로를 거친다. 봇 전용으로 조작 비용·유효성·게임 결과를 우회하지 않는다.
- 구체적인 관찰 데이터와 조작 요청의 구조는 후속 설계 사항이다.

## 실행과 비교 조건

- 일반 실행과 고속 테스트를 지원한다. 고속 테스트는 연출만 생략하며 효과·낙하·매칭·피해 처리 순서와 실제 게임 결과를 유지한다.
- 개별 사례는 연출을 켜고 확인할 수 있다.
- 기본 전략과 계획 전략은 같은 시작 조건·난수 시드 묶음으로 테스트한다. 시드는 실행기만 관리하며 봇에는 공개하지 않는다.
- 같은 조건 묶음은 비교와 재현을 위한 기준이다. 전략의 행동이 달라지면 이후 보드 상태도 달라질 수 있다.
- 반복 횟수는 전략별 기본 100회, 두 전략 합계 200회이며 제작자가 변경할 수 있다.
- 한 테스트 묶음 안에서는 서로 다른 시드를 사용하고 두 전략에 같은 묶음을 적용한다. 새 테스트는 새로운 시드 묶음으로 실행한다. 수정 전후 비교·동일 조건 재검사·사례 재생은 저장한 시드를 재사용한다.
- 진행률을 표시하고 중지와 일시정지를 모두 지원한다. 일시정지는 진행 상태를 보존해 재개할 수 있는 기능이며 중지와 구분한다.
- 중지한 경우 완료된 판의 기록을 보존하고 결과에 ‘일부 실행’을 표시하여 예정 횟수를 모두 완료한 분석과 구분한다. 진행 중인 판의 정지 시점과 중지 시 처리 세부 사항은 후속 결정 사항이다.
- 테스트 소요 시간은 [29단계 검증](84_29단계_구현검증기록.md)과 [30단계 진행 기록](85_30단계_통합검수진행기록.md)에 실행 조건과 함께 기록한다. 보드 구성·전략·시드·일시정지에 따라 달라지므로 단일 고정 시간으로 보장하지 않는다.

## 기본 분석 항목과 난이도 표시

- 성공한 판은 클리어까지 사용한 이동 수·남은 이동 수를 분석한다. 실패한 판은 종료 원인·미션별 남은 목표량을 분석한다.
- 공통으로 전략별 성공률과 무작위 조건에 따른 결과 편차를 비교한다. 성공한 판의 평균만으로 난이도를 판단하지 않는다.
- 예상 난이도는 매우 쉬움·쉬움·보통·어려움·매우 어려움의 5단계와 근거 수치를 함께 표시한다. 현재 초기 기준과 버전은 [29단계 평가 기준](81_29단계_평가기준결정.md)을 따른다. 인간 체감 난이도로 보정된 기준이라는 뜻은 아니다.
- 플레이 실패와 정합성 문제·실행 오류를 구분한다. 모든 시도가 실패해도 매우 어려움 또는 해결 불가능으로 단정하지 않는다.
- 정합성·실행 오류가 있으면 ‘난이도 판단 보류’를 표시한다. 정상 종료한 판의 통계는 참고용으로 제공하고 오류 수정 후 재검사하도록 안내한다.
- 근거가 있는 경우 원인 태그를 함께 표시한다. ‘계획 요구’는 계획 전략이 기본 전략보다 뚜렷하게 유리한 경우, ‘무작위 영향 큼’은 공급 조건별 결과 차이가 큰 경우, ‘이동 여유 부족’은 성공한 판도 남은 이동 수가 적은 경우를 설명한다. 수치 기준은 추후 조정하며 근거가 부족하면 표시하지 않는다.
- 결과 신뢰도 표시, 세부 실패 분류, 화면 배치와 구체적인 산정 식은 후속 결정 사항이다.
- 실제 플레이 기록으로 자동 평가 기준을 보정하는 방법은 추후 검토한다.

## 사례 재생과 분석 이력

- 대표 성공·실패 사례를 선택해 행동 순서대로 재생할 수 있다. 이를 위해 레벨 상태·난수 시드·봇의 행동 기록을 함께 보관한다.
- 레벨을 수정하면 기존 분석을 수정 전 버전의 결과로 표시한다. 새 분석과 비교할 수 있도록 이력을 유지하며 과거 성공률을 현재 레벨 결과로 표시하지 않는다.
- 보관 한도·정리 방식과 상세 기록 형식은 아직 정하지 않았다.
