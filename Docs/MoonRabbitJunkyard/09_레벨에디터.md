### 맵 모양 목록과 도움말

이전의 고정 10종 추천 대신 **사용자 등록형 목록**을 사용한다. 레벨을 저장하고 창 위쪽 **맵 모양 목록 → 현재 레벨 모양 등록**을 누른다. 10×10 활성 칸 위치가 같은 모양은 중복 안내하며 기존 기록을 유지한다. 등록 당시 원본 레벨 이름·번호와 장애물 종류·개수를 독립적으로 보관한다.

목록에서 모양을 고르고 **이 모양으로 새 레벨 만들기**를 누르면 활성 칸과 기본 생성구만 새 파일에 적용한다. 장애물 사용 기록은 참고용이며 자동 배치하지 않는다. 원본 수정·삭제 후에도 등록 기록은 유지한다. 등록 파일은 `Assets/Editor/LevelShapes`에 저장한다. 현재 방식은 [등록형 모양 목록 설계 결정](63_등록형맵모양목록_설계결정.md)을 따른다.

메뉴 제목 옆 **!** 아이콘에 마우스를 올리면 툴팁, 클릭하면 해당 설명서 문단을 연다. 제목의 기존 편집 동작은 유지한다. 사용 순서는 [맵 모양 목록 안내](Manual/recommendations.html)를 따른다.

## 화면 구성

### 통합 작업창

`Match/통합 작업창` 한 곳에서 **레벨 편집 / 플레이 테스트 / 초기 보드·진단 / 결과·이력** 네 탭을 사용한다. 기존 메뉴도 같은 창의 해당 탭으로 연결된다. 상단 레벨 선택은 모든 탭에 공통 적용한다. 옆의 **맵 모양 목록**은 별도 목록을 펼치는 버튼이다.

탭 이동으로 편집 선택·스크롤이나 플레이 상태가 사라지지 않는다. 떠난 수동 시험의 검색·자동 연쇄는 일시정지하며 돌아오면 재개한다. 봇 반복 시험은 탭 복귀만으로 자동 재개하지 않으며 사용자가 재개 버튼을 누른다. 아이템 선택과 미완료 드래그는 해제한다. 원본을 수정하거나 다른 레벨을 선택하면 기존 시험은 무효화되어 다시 구성해야 한다. 창 닫기·스크립트 재컴파일 후에는 시험을 다시 시작하며 이미 저장된 판 기록은 결과·이력에서 확인한다. 자세한 구조와 상태 규칙은 [통합 작업창 설계 결정](61_Match통합작업창_설계결정.md)과 [반복 실행 목표](72_27단계_개발목표.md)를 따른다.

### 수동 플레이 테스트 — 24단계 사용 흐름

레벨 에디터 상단 **플레이 테스트**를 누르면 현재 레벨의 미저장 내용까지 시험용 사본으로 구성한다. 기존 시험이 유효하면 해당 상태로 복귀한다. 원본 에셋을 강제로 저장하지 않는다. 별도 진입점은 `Match/플레이 테스트`이며, 레벨이 없으면 창 상단에서 레벨을 지정한 뒤 **검사·구성**을 누른다.

1. 시작 조건을 통과하면 부스터를 선택하고 **시작**한다. 현재 레벨 번호·시드·남은 이동·미션을 기본 화면에서 확인한다.
2. 보드의 두 칸을 선택해 **교환 실행**, 파워 한 칸을 선택해 **제자리 발동**한다. 정상 행동과 아이템 뒤에는 낙하·공급·연쇄가 자동 진행된다. 처리 중에는 새 행동을 받지 않는다.
3. 망치·자리 바꾸기·섞기는 시험용 무제한이다. 섞기는 확인 후 사용한다. 시작 부스터는 시작 후 바꿀 수 없고, 실제 배치와 남은 대기를 표시한다.
4. **상세 진단 · 단계 실행**을 열면 자동 진행을 멈추고 기존 한 단계 처리와 조회를 사용할 수 있다. 다시 접으면 남아 있는 연쇄를 자동 진행한다. 기본 모드와 같은 실행기를 사용한다.
5. 성공·이동 수 소진·진행 불가·실행 오류를 구분해 표시한다. 라스트팡을 처리하거나 건너뛰어도 성공 결과는 유지한다.
6. **같은 시드로 다시** 또는 **새 시드로 다시**는 시작 전 화면으로 돌아가며 부스터 선택을 초기화한다. 동일 재현에는 동일한 시드뿐 아니라 같은 부스터 선택과 조작도 필요하다.
7. **편집으로 돌아가기**는 편집 탭으로 이동하며 시험 세션을 보관하고 자동 처리를 일시정지한다. 원본 변경·레벨 전환·창 재생성·도메인 재로드 후에는 이전 시험을 이어가지 않고 다시 시작한다.

기존 `Match/초기 보드 확인`은 원시 후보와 단계별 진단 용도로 유지한다. 이 화면은 에디터용 규칙 시험이며 출시용 UI나 실제 앱 복구 기능을 뜻하지 않는다. 검증 상태와 완료 증거는 [24단계 목표](60_24단계_개발목표.md)를 따른다. 아래 단계별 설명은 당시 구현 이력이다.

### 21단계 회수 부품 실행

`Match/초기 보드 확인`에서 레벨을 선택하고 `시작 조건 구성`으로 구성한 뒤 `실행 시험`을 켠다. 회수 부품은 `회수`, 도착 바닥은 `▽도착`으로 표시한다. 유효한 일반 교환 또는 파워 교환으로 부품을 움직이고 `낙하·공급 실행`/`연쇄 끝까지`로 회수 과정을 확인한다. 자석과 부품의 교환은 취소된다.

도착한 부품은 즉시 사라지고 회수 미션이 증가한다. 초기 도착 배치도 실행 시험 시작 시 처리하며 원시 후보와 레벨 에셋은 유지한다. 오른쪽에서 누적 회수·남은 목표·보드 부품·유지 부족분, 회수 위치와 처리 묶음, 생성구 목록 커서를 확인한다. 유지 공급은 남은 목표까지 필요한 수만 보충하고 나머지는 일반 블록을 공급한다. 고정 목록은 지정 생성구의 순서대로 소모한다.

드론은 부품 자체를 파괴하지 않고 다음 이동을 막는 블록/장애물 또는 발전기 충전의 간접 기여를 조회한다. 이는 회수 완료의 보장이 아니므로 예약만으로 회수 미션이 증가하지 않는다. 미션을 모두 달성해도 판 승리·라스트팡은 아직 실행하지 않는다. 아래의 12·13단계 설명은 당시 범위이며 현재 회수 지원과 검증 근거는 [21단계 목표](54_21단계_개발목표.md)를 따른다.

[4단계 작업 계획 — 흐름과 연결 편집](18_4단계_흐름과연결편집_작업계획.md)의 승인 범위도 구현·검증을 완료했다. [4단계 목표 문서](19_4단계_개발목표.md)에 당시 사용 방법과 총 524개 검증 증거를 기록했다.

[5단계 목표 문서](21_5단계_개발목표.md)의 생성구·위치별 공급 목록·유지 설정·회수 부품·미션 편집과 정적 수량 검사를 구현했다. 실제 UI와 별도 재시작, 기존 회귀를 합쳐 최종 669개 검사가 통과했다. 배치 탭의 **생성·회수**, 목록 탭의 **생성구**, 선택 속성의 공급 목록/공통 속성, 레벨 설정의 유지/미션을 사용한다. 기존 한 줄 메뉴와 USS 스타일은 유지한다. 실제 공급·낙하·퍼즐 실행·자동 플레이·난이도 분석은 후속 범위다.

[6단계 목표 문서](23_6단계_개발목표.md)의 층별 다중 선택·같은 종류 공통 속성·설정값 복사/붙여넣기·독립 레벨 복제도 구현했다. 현재 층의 선택 도구에서 Ctrl/Cmd+클릭으로 추가/해제하며, 설정 붙여넣기는 다른 종류를 제외한다. 복사·붙여넣기는 보드 대상 또는 선택 속성 영역의 우클릭 컨텍스트 메뉴를 사용한다. 이미 선택된 대상 우클릭은 다중 선택을 유지하고, 다른 대상 우클릭은 선택을 변경한다. 생성구는 공급 목록 복사·교체 붙여넣기·뒤에 추가를 제공하며 모든 대상 사전 검사 정책을 유지한다. 상단 **복제**는 미저장 내용을 포함한 사본을 새 번호/GUID로 만들며 원본은 저장하지 않는다. 최종 데이터/UI/재시작 및 기존 회귀는 중복 제외 682개 통과했다.

- 왼쪽 도구, 가운데 보드, 오른쪽 속성, 아래쪽 접이식 구조 검사로 구성한다. 전용 USS 스타일로 도구 영역과 보드 배경을 구분하고 저장·현재 탭에 강조색을 사용한다.
- 왼쪽은 **배치 / 흐름 / 목록** 탭이다. 배치에는 블록·장애물, 흐름에는 중력·경로·통로·지형과 연결 목록, 목록에는 현재 사용 중인 장애물을 표시한다. 탭 전환 시 미완료 입력은 취소하고 해당 화면의 선택 도구로 전환한다.
- 오른쪽은 **선택 속성 / 레벨 설정** 탭이다. 레벨 번호·이동 횟수·사용 색과 원본 Inspector 이동은 레벨 설정에서 다룬다. 보드에서 칸을 선택하면 선택 속성을 바로 보여준다.
- 상단에 레벨 에셋·새 레벨·저장·검사를 모은다. 제목 옆 **도구 / 속성** 체크로 각 패널을 접어 작은 창에서도 보드 공간을 확보한다. 패널을 접으면 진행 중 입력은 취소된다.
- 구조 검사 영역은 처음에는 접혀 있으며 검사를 실행하면 결과를 펼친다. 오류 개수는 접힌 제목에서도 확인할 수 있다. 하단 안내는 현재 작업 방법을 표시한다.
- 스타일·UX 개선 검증: 실제 Unity 창에서 탭 표시, 목록→선택 속성 전환, 패널 접기, 좁은 창 스크롤 및 기존 흐름·장애물 편집을 확인했다. 이번 회귀 검사는 흐름 216 + 재시작 16, 장애물 165 + 재시작 9로 **406개 통과, 실패 0개**다. 화면과 실행 로그는 `Logs/LevelEditorStyleVerification`에 보관한다. 이는 위 4단계 전체 검증과 별도의 이번 변경 검증 기록이다.
- 왼쪽은 선택·삭제 도구와 보드·일반 블록·파워 블록·장애물·덮개·바닥·장치 카테고리로 구분한다. 같은 카테고리의 종류는 드롭다운으로 선택하며 편집 층도 자동으로 바뀐다.
- 편집 층과 각 카테고리·흐름·지형의 제목과 드롭다운은 한 줄로 정렬한다. 오른쪽 선택 위치와 편집 층도 한 줄로 표시하며, 긴 안내와 오류 설명은 읽을 수 있도록 줄바꿈을 유지한다.
- 별도 **현재 사용 중인 장애물** 영역에는 현재 레벨에 배치된 장애물·덮개·먼지·장치만 종류별 개수로 표시한다. 펼치면 좌표와 내구도 또는 필요 충전량이 나오며 항목을 누르면 해당 위치를 선택해 오른쪽 속성에서 편집한다.
- 사용 목록은 레벨 배치 데이터에서 계산한다. 배치·삭제·속성 수정·Undo/Redo·레벨 전환 시 갱신하며 2×2는 본체 하나로 센다. 범위 밖 오류 기록도 숨기지 않고 원본 Inspector 수정 안내를 표시한다.
- 생성구를 선택하면 오른쪽에 공급 목록도 표시한다.

## 요소별 편집

- 바닥 기능·중력·먼지·블록/장애물·생성구를 각각 따로 편집한다. 한 요소를 수정해도 다른 요소는 유지한다.
- 함께 배치할 수 없는 조합은 오류로 표시한다.
- 한 칸 클릭과 드래그 연속 칠하기를 지원한다. 드래그 한 번은 실행 취소 한 단위로 묶으며 다시 실행도 지원한다.
- 대형 폐가전·발전기 같은 2×2 요소는 네 칸의 배치 미리보기를 보여주고 클릭한 칸을 왼쪽 위 기준으로 한 번에 설치한다. 드래그 연속 배치에서는 제외한다.
- 삭제는 현재 편집 요소에만 적용한다. 칸 전체 비우기는 별도 명령으로 구분한다.
- 2×2 요소는 어느 점유 칸을 선택해 삭제해도 본체 전체를 제거한다. 발전기 삭제 시 연결 전선도 삭제하지만 대상 장애물은 남긴다.
- 발전기나 연결 대상의 위치가 바뀌면 연결 관계는 유지하고 영향을 받는 전선에 경로 재지정이 필요하다고 표시한다.
- 칸을 비활성화해도 기존 배치를 자동 삭제하지 않고 오류로 표시한다. 다시 활성화하면 원래 구성을 유지한다.
- 2×2 요소 이동은 네 칸 모두 배치 가능한 위치에서만 허용한다. 보드 밖이나 다른 공간 점유 요소와 겹치는 위치에 놓으면 이동을 취소하고 원래 자리를 유지한다.
- 무작위 일반 블록도 별도 배치 항목으로 제공하고 `?`로 표시한다. 테스트 시작 시 레벨에서 사용하는 색으로 결정한다.

## 선택과 공통 인스펙터

- 같은 종류의 요소를 여러 개 선택하면 공통 인스펙터에서 일괄 편집한다.
- 값이 같으면 해당 값을, 서로 다르면 혼합 상태인 `—`를 표시한다.
- 수정한 항목만 선택 대상 전체에 적용하고 나머지 값은 유지한다. 예를 들어 서로 다른 내구도의 상자를 선택해 내구도를 3으로 수정하면 모두 3이 된다.
- 설정값 복사·붙여넣기는 같은 종류의 대상에만 적용한다. 다른 종류가 선택에 섞여 있으면 적용 가능한 대상에만 반영하고 제외 개수를 표시한다.
- 생성구 여러 개를 선택했을 때 공급 방식·유지 개수 등 공통 설정은 일괄 편집한다. 순서가 있는 공급 목록은 다중 편집 대신 복사·붙여넣기로 적용한다.

## 고정 공급 목록 편집

- 생성구를 선택하면 옆 패널에 공급 블록을 쌓아 표시한다. 맨 아래 블록부터 공급하며 드래그로 순서를 바꿀 수 있다.
- 목록 복사는 블록 종류·순서·수량·내구도·청소로켓 방향 등 설정을 포함한다.
- 다른 생성구에 붙여넣을 때 기존 목록 전체 교체와 기존 목록 뒤에 추가를 지원한다.
- 선택한 공급 항목을 목록 안에서 복제해 반복 배치할 수 있다.
- 보드의 블록 설정값을 다른 동일 종류의 블록에 복사하는 기능과 공급 목록·항목 복제 기능을 구분한다.

## 레벨 저장과 복제

- 레벨마다 독립된 Unity 데이터 에셋으로 저장하고 기존 레벨을 복제해 새 레벨을 만들 수 있다.
- 진행 순서는 에셋 파일명과 별도의 레벨 번호로 관리한다. 같은 번호가 중복되면 오류로 표시한다.
- 입구만 배치한 통로나 연결 미완료 발전기처럼 불완전한 편집 상태도 작업 중 저장할 수 있다.
- 오류 위치와 이유를 표시하며 필수 오류를 해결한 뒤에만 테스트 플레이를 허용한다. 개별 금지 조합과 검사 기준은 게임 규칙 문서를 따른다.
- 회수 미션에 도착 바닥이 없거나 최초 배치와 최대 추가 공급을 합쳐도 목표 수량이 부족하면 오류로 처리한다.
- 오류 목록을 클릭하면 해당 칸·연결 경로로 화면을 이동하고 강조한다.
- 시작 조건 검사는 고정 배치를 변경하지 않고 무작위 칸만 다시 생성한다. 고정 배치 때문에 시작 매칭 없음·유효한 첫 교환 조건을 충족할 수 없으면 오류로 표시한다.
- 레벨 사용 색상을 변경하면 고정 블록·공급 목록·색깔 자물쇠에 남은 미사용 색을 오류로 표시한다. 자동 변환하지 않는다.
- 미션 인스펙터에 목표 수량과 최초 배치·최대 추가 공급 수량을 함께 표시한다. 곰팡이는 고정 개수 입력 대신 기존의 전부 제거 목표로 구분한다.

## 테스트 플레이

- 편집 중인 레벨의 복사본에서 테스트한다. 블록 제거·공급 목록 소진 등 테스트 중 변화는 원본에 반영하지 않는다.
- 테스트 종료 시 원본 배치를 유지한 편집 화면으로 돌아온다.
- 재시작은 같은 무작위 조건으로 다시 하기와 새로운 무작위 조건으로 다시 하기를 지원한다.
- 같은 조건 재시작은 같은 조작으로 문제를 재현하기 위한 기능이며, 다른 조작에도 같은 결과를 강제하는 기능은 아니다.
- 수동 테스트에서는 부스터와 게임 중 아이템을 잠금·보유 수량 제한 없이 사용할 수 있다. 이동 횟수·미션·효과 등 실제 규칙은 유지한다. 자동 난이도 평가의 보조 수단 금지 조건과 구분한다.

## 편집 중 흐름 표시

- 중력 방향·경로·생성구·연결 관계의 기본 표시는 옅게 유지한다. 완전히 숨겼다가 나타내는 방식 대신 주기적으로 강조한다.
- 이동 방향을 따라 화살표나 빛이 흐르고 생성구는 짧게 강조된다.
- 블록의 이동 흐름과 발전기의 연결 관계를 번갈아 강조한다. 한꺼번에 강조해 복잡해지지 않게 한다.
- 강조 주기·지속 시간과 세부 연출 수치는 아직 정하지 않았다. 실제 게임 화면에 같은 편집용 표시를 적용하는지는 별도 사항이다.

## 후속 결정 사항

- 세부 창 크기, 다중 선택 조작, 단축키.
- Unity 내부 구현 방식과 에셋 데이터 구조, 테스트 실행 환경.
- 개별 오류와 경고의 표현 및 검사 범위 세부 사항.

## 검토용 레벨 — 에디터 개발 이후 사용

- 상자·거미줄 없이 중력·통로·생성·회수 흐름을 확인하는 검토용 레벨을 구상했다. 실제 실행·검증된 데이터가 아니며 제작은 에디터 개발 이후로 미룬다.
- 예시안은 10×10에서 왼쪽 위 5×5와 오른쪽 5×10을 활성화하고 좌우 사이에 고철 벽을 둔다. 왼쪽 1~4행은 아래, 5행은 오른쪽, 오른쪽 영역은 아래 중력을 사용한다.
- 제안 좌표는 통로 `(5,5) → (1,8)`, 도착 바닥 `(10,8)`, 초기 회수 부품 `(2,3)`, 추가 생성구 `(1,3)`이다. 좌표는 왼쪽 위부터 1로 세는 `(행, 열)`이다. 회수 목표 3개·동시 유지 1개를 예시로 삼았다.
- 왼쪽 5행 합류는 왼쪽에서 오는 블록을 먼저 받고 공급할 수 없으면 위쪽에서 받는 우선순위로 합의했다. 이 우선순위는 검토용 레벨 설정이며 모든 레벨의 기본값을 변경하지 않는다.

#### 연결형 오브젝트의 공통 편집 기준

앞으로 오브젝트 사이의 연결을 설정하는 기능은 발전기와 같은 연결점 드래그 방식으로 통일한다. 새 연결형 오브젝트를 추가할 때 적용하는 개발 기준이다.

- 오브젝트를 선택하면 연결점을 표시한다. 연결은 어느 쪽에서든 드래그를 시작할 수 있으며, 드래그 중 연결 가능한 상대의 점을 표시한다.
- 드래그 중 연결선을 미리 보여주고 유효 여부를 색으로 안내한다. 연결을 확정하면 양쪽 연결점과 연결선을 점등한다.
- 빈 곳에 놓기·Esc로 취소하고, 연결점이나 연결선의 우클릭 메뉴에서 해제한다. 생성·해제는 각각 Undo 한 번으로 되돌린다.
- 연결점 수, 허용 대상, 연결 개수 제한과 경로 제약은 오브젝트별 규칙을 따른다. 발전기의 연결점 3개나 전선의 벽 회피 규칙을 다른 종류에 일괄 적용하지 않는다. 어느 쪽에서 드래그하더라도 실제 연결 관계의 방향과 의미는 동일하다.
- 새로운 연결형 오브젝트 구현 시 기존 연결 조작을 재사용하도록 공통 입력·표시와 종류별 연결 검증·저장 처리를 분리한다. 종류마다 별도의 드래그 편집기를 복제하지 않는다.

현재 발전기와 이동 통로는 `LevelConnectionGraph`의 입력 캡처·취소·연결점 표시·해제 메뉴를 공유한다. 통로별 표시와 방향 판정은 별도 구성 파일에 두며, 종류별 검증·저장 API를 호출한다.

#### 이동 통로 연결점 드래그 편집

`흐름 → 흐름·통로 → 통로 입구`로 입구를 배치한 뒤 선택 도구로 선택한다. 원형 입구 점에서 출구로 쓸 활성 칸까지 드래그하면 통로가 연결된다. 미연결 입구가 있는 상태에서 출구로 쓸 칸을 먼저 선택하면 사각형 출구 후보 점이 나타나며, 이 점에서 미연결 입구로 드래그해도 된다.

- 원형은 입구, 사각형은 출구다. 드래그 방향과 관계없이 화살표는 실제 이동 방향인 입구 → 출구를 표시한다. 통로 연결선은 두 칸의 관계를 보여주며 발전기 전선처럼 벽을 우회하는 경로가 아니다.
- 미리보기는 노란색, 허용하지 않는 대상은 빨간색, 연결된 점과 선택한 통로의 선은 초록색이다. 같은 칸, 도착 바닥, 다른 통로와의 역할 중복 등은 기존 통로 규칙에 따라 거절한다.
- 드래그를 시작하면 연결 가능한 모든 칸을 초록색 테두리와 옅은 배경으로 강조한다. 입구에서 시작하면 유효한 출구 칸을, 출구에서 시작하면 연결 가능한 미연결 입구만 표시한다. 가리킨 후보는 노란색으로 강조하며, 연결 완료·취소·선택 또는 원본 변경 시 후보 표시를 지운다.
- 보드 밖·비활성 칸에 놓거나 Esc를 누르면 취소한다. 통로는 활성 칸 자체를 출구로 지정하므로 활성 칸에 놓으면 새 출구가 생긴다.
- 연결된 점 또는 선택한 통로의 선을 우클릭해 `연결 해제`하면 출구 연결만 지우고 입구는 유지한다. 연결을 바꿀 때는 먼저 해제한다. 연결·해제는 각각 Undo 한 번으로 되돌린다.
- 기존 `출구 지정 / 이동`, `출구만 삭제`, `통로 쌍 삭제` 버튼도 유지한다. 도구·선택·레벨 변경 시 진행 중 드래그를 취소한다.

2026-09-28 실제 Unity Editor에서 통로 양방향 드래그·후보 칸 강조 및 해제·방향 보존·포인터 적중·유효성 거절·취소·우클릭 해제·Undo/Redo·수동 출구 지정과 발전기 연결 회귀를 포함해 74개 검사가 통과했다. 결과와 화면 캡처는 `Logs/PortalGraphVerification`에 기록했다.

#### 발전기 연결점 드래그 편집

배치의 선택 도구 또는 흐름의 선택 도구에서 발전기를 선택하면 연결점 3개가 표시된다. 비어 있는 점에서 장애물의 연결점으로 드래그하면 전선 경로를 미리 볼 수 있다. 장애물을 먼저 선택하고 발전기 연결점으로 드래그하는 역방향 연결도 가능하다.

- 연결 가능한 대상은 나무상자·금고·색 자물쇠·대형 폐가전이다. 드래그 중 상대편 연결점이 표시된다.
- 드래그를 시작하면 실제 전선 경로를 만들 수 있는 상대 본체 전체를 초록색 테두리와 옅은 배경으로 강조한다. 발전기에서 시작하면 유효한 장애물을, 장애물에서 시작하면 연결 가능한 점이 있는 발전기를 표시한다. 점유된 대상이나 경로가 막힌 대상은 제외하며 가리킨 유효 연결점의 본체는 노란색으로 강조한다. 완료·취소 시 후보 강조를 지운다.
- 연결 가능한 점은 노란색, 연결할 수 없는 점은 빨간색으로 표시한다. 놓아서 연결을 확정하면 양쪽 점이 초록색으로 켜진다.
- 전선은 선택한 두 연결점을 잇도록 자동 생성하며 벽과 기존 전선을 피한다. 유효한 경로가 없으면 변경하지 않고 이유를 안내한다.
- 발전기는 최대 3개 대상에 연결되며, 장애물은 발전기 하나에만 연결된다. 기존 연결 규칙과 저장 형식을 그대로 사용한다.
- 빈 곳에 놓거나 Esc를 누르면 취소한다. 연결된 점 또는 선택 대상의 전선을 우클릭해 `연결 해제`를 선택할 수 있다. 연결 생성과 해제는 각각 Undo 한 번으로 되돌린다.
- 기존 수동 대상 지정과 전선 경로 편집도 계속 사용할 수 있다. 칠하기 도구에서는 연결점을 숨겨 배치를 방해하지 않는다.

2026-09-28 Unity Editor에서 양방향 포인터 드래그, 연결점 적중, 자동 우회, 취소, 컨텍스트 해제, Undo/Redo 및 수동 편집 회귀 등 30개 검사를 통과했다. 화면 캡처와 결과는 `Logs/ConnectionGraphVerification`에 기록했다.

발전기 후보 강조 추가 후 이동 통로를 포함한 공통 연결 검증은 81개 통과, 실패 0개다. 연결 불가 대상 제외·양방향 본체 강조·후보 표시 해제를 확인했으며 최신 결과와 화면은 `Logs/PortalGraphVerification`에 기록했다.

#### 직접 낙하 경로 드래그 편집

`흐름 → 흐름·통로 → 직접 경로`에서 시작 칸을 누른 채 인접 칸으로 드래그한다. 실제 지나간 칸을 순서대로 기록하며 마우스를 놓으면 경로 전체를 한 번에 확정한다. 빠른 드래그도 지나간 중간 칸을 기록한다.

- 현재 끝에서 연결 가능한 상하좌우 칸은 초록색으로, 그리는 경로와 방향 화살표는 노란색으로 표시한다. 마지막 칸의 밑줄은 끝 위치를 나타낸다.
- 벽·비활성 칸·중복 방문·기존 경로 덮어쓰기는 허용하지 않는다. 대각선 모서리 이동에 임의의 우회 경로를 만들지 않는다.
- 기존 경로 또는 통로 입구에 닿으면 합류 지점이 되며 이후 후보는 표시하지 않는다. 연결된 기존 흐름은 유지한다.
- 막힌 칸이나 보드 밖을 거쳤다면 마지막 유효 칸으로 돌아와야 이어 그릴 수 있다. 유효하지 않은 위치에 놓으면 미완료 경로 전체를 취소한다.
- Esc, 도구 전환, 원본 변경은 드래그를 취소한다. 확정된 경로 전체는 Undo 한 번으로 되돌릴 수 있다.
- 움직이지 않고 클릭하면 기존 클릭 입력으로 남는다. 여러 칸을 차례로 클릭한 뒤 `경로 완료 (Enter)`로 확정하는 방식과 Backspace 한 칸 취소도 유지한다. 한 칸짜리 끝 지점은 클릭 후 Enter로 지정한다.

2026-09-28 실제 Unity Editor에서 빠른 드래그·꺾인 경로·후보 강조·끝 칸·합류·벽/대각선/보드 밖 건너뛰기 거절·클릭 입력 보존·취소·Undo/Redo와 발전기/통로 연결 회귀를 포함한 101개 검사가 통과했다. 결과와 화면은 `Logs/PathDragVerification`에 기록했다.

#### 합류 우선순위 편집

선택 도구에서 둘 이상의 유입이 있는 합류 칸을 선택하면 해당 칸은 노란 테두리로, 유입 경로는 초록 화살표로 표시한다. 각 유입 칸의 번호는 우선순위이며 1번이 먼저다. 통로를 통한 유입도 표시한다.

- 오른쪽 `합류 우선순위` 목록의 핸들을 드래그해 순서를 바꾼다. 놓아서 재정렬을 확정하면 보드 번호도 함께 갱신된다. 기존 ↑↓ 버튼도 사용할 수 있다.
- 목록에서 우클릭하면 `합류 우선순위 초기화` 메뉴를 표시한다. 보드에서는 합류 칸의 우클릭 메뉴 `바닥·연결 → 합류 우선순위 초기화`를 사용한다. 우클릭하거나 메뉴를 여는 것만으로는 초기화하지 않는다.
- 초기화 메뉴를 선택하면 저장된 우선순위를 지우고 기본 유입 순서를 표시한다. 경로와 통로 연결은 유지한다.
- 재정렬과 초기화는 각각 Undo 한 번으로 복구한다. 드래그 중 Esc·포커스 이탈·선택/레벨 변경은 미완료 작업을 취소한다. 선택이 바뀐 후 예전 초기화 메뉴를 실행해도 이전 대상을 수정하지 않는다.

2026-09-28 Unity Editor에서 실제 목록 핸들 드래그·보드 번호 갱신·메뉴 열기 시 무변경·메뉴 선택 후 초기화·Undo/Redo·Esc 취소·오래된 메뉴 거절과 기존 연결/경로 회귀를 포함해 116개 검사가 통과했다. 결과와 화면은 `Logs/MergeEditingVerification`에 기록했다.

#### 기존 선택 메뉴

기존 버튼을 유지하면서 다음 작업을 컨텍스트 메뉴에서도 제공한다.

- 선택 요소: 현재 층 요소 삭제, 2×2 본체 이동, 회수 부품 삭제.
- 생성구: 선택 생성구 삭제, 고정 공급 목록 비우기.
- 고정 공급 목록: 항목 추가, 선택 항목 복제/삭제, 먼저·나중에 공급. 우클릭한 행이 대상이며 끝 위치의 불가능한 이동은 비활성화한다.
- 단일 칸의 바닥·연결 하위 메뉴: 중력 기본값 복원, 직접 경로 삭제, 합류 순서 초기화, 통로 출구 지정/삭제와 쌍 삭제, 도착 바닥 삭제, 발전기 대상 추가, 전선 재지정 및 연결 삭제. 해당 설정이 있는 경우만 표시한다.

다중 배치 선택에는 단일 대상 삭제/이동/바닥 작업을 제공하지 않는다. 메뉴 실행 전 선택과 원본을 재확인하며 기존 버튼의 콜백과 Undo를 공유한다.

### 7단계 통합 검수 완료

2026-09-27 신규 제작·오류 수정·연속 편집·복제·저장 및 독립 프로세스 재로딩을 검수했다. 실제 네이티브 메뉴와 1000×780/680×480 창을 확인했고, 통합/회귀/재시작 735개 검사가 통과했다. 레벨 전환 뒤 이전 경로 안내가 남는 문제는 현재 선택 안내를 초기화하도록 수정했다.

실제 사용 순서와 조건별 증거는 [7단계 개발 목표](25_7단계_개발목표.md)를 따른다. 구조 검사 완료는 플레이 가능 판정이 아니며 실제 게임 실행·봇·난이도 분석은 이번 단계 범위에 포함되지 않는다.

### 8단계 초기 보드 확인

Match → 초기 보드 확인에서 레벨과 시드를 지정해 원본과 분리된 초기 배치 후보를 읽기 전용으로 구성한다. 같은 시드 재구성과 새 시드 구성을 구분하며 미저장 정의 내용도 사용할 수 있다. 원본/시드가 바뀌면 이전 화면을 지우고 다시 구성한다. 칸 선택으로 본체·덮개·바닥·연결·공급 정보를 확인한다.

8단계 당시에는 초기 후보만 확인했으며 시작 매칭/유효 교환은 검사하지 않았다. 당시 구현/사용법/160개 검증 증거와 재현 범위는 [8단계 개발 목표](27_8단계_개발목표.md)에 기록했다. 현재 추가된 조회와 실행 시험은 아래를 따른다.

### 9~11단계 조회와 매칭·파워 실행 시험

[9단계](29_9단계_개발목표.md)는 매칭·가능 행동 조회와 시작 조건 구성을 제공한다. `구성 목적`에서 원시 후보 또는 시작 조건 구성을 선택하며, 목록을 눌러 해당 좌표를 강조할 수 있다.

[10단계](31_10단계_개발목표.md)는 시작 조건 구성 성공 후 `실행 시험`을 켜고 일반 블록 두 칸을 선택해 교환할 수 있다. 첫 매칭 제거·파워 생성과 이동 수 1회 차감 후 낙하 대기로 멈춘다. `같은 시드로 초기화`로 다시 시험한다. 10단계 당시에는 장애물 보드와 파워 발동을 지원하지 않았다. 당시 검사와 8·9단계 회귀 증거는 해당 목표 문서에 기록했다.

[11단계](33_11단계_개발목표.md)에서는 청소로켓·달폭탄의 일반 블록과의 교환 발동, 한 칸 선택 후 `제자리 발동`, 두 파워 종류 사이의 즉시 피격 연쇄를 지원한다. 나무상자의 인접 매칭/직접 파워 피해와 턴당 1 피해 제한, 새 매칭 파워의 보호를 처리하며 오른쪽 결과에서 발동·내구도·보호 이유를 확인할 수 있다. 직접 파워 조합, 드론·자석 발동, 나무상자 외 장애물은 미지원이다. 연쇄 중 미지원 파워를 만나면 해당 행동 전체를 취소한다. 효과 후에는 낙하 대기로 멈춘다. 11단계 당시에는 낙하·공급·미션·승패를 실행하지 않았으며, 현재 정착 실행은 아래를 따른다.

### 12단계 낙하와 기본 공급 시험

`Match → 초기 보드 확인`에서 시작 조건을 구성하고 `실행 시험`을 켠다. 교환 또는 제자리 발동을 완료하면 `낙하·공급 실행`을 누를 수 있다. 4방향 중력·대각선·직접 경로·합류·통로에 따라 이동하며 빈 생성구에서 일반/파워 블록을 공급한다.

상단에서 이동·공급·남은 빈칸·정착 후 매칭 수를 확인한다. 오른쪽 결과는 이동 묶음·출발/도착·공급 목록 커서·난수 전후와 파워 보호를 보여준다. 정착 매칭 버튼은 해당 칸을 강조하는 조회 기능이며 제거하지 않는다. 자세한 기록은 스크롤로 확인한다.

정착 명령이 성공하면 `정착 완료 · 자동 매칭 대기`에서 멈춘다. 마지막 이동 수가 0이어도 정착은 가능하다. 12단계 당시에는 자동 연쇄·다음 사용자 행동·미션·승패를 실행하지 않았으며, 현재 자동 연쇄와 다음 행동은 아래 13단계 기능을 사용한다. 경로가 없는 빈칸은 그대로 남을 수 있다. `같은 시드로 초기화`하면 처음부터 다시 시험할 수 있다.

나무상자 외 장애물·덮개·먼지·회수 부품, 고철/회수 공급·개수 유지는 이번 정착에서 미지원이다. 거절 시 효과 처리 직후 상태를 보존하며 이미 성공한 교환까지 되돌리지 않는다. 구현과 검증 근거는 [12단계 개발 목표](35_12단계_개발목표.md)를 따른다.

### 13단계 자동 매칭과 다음 수 시험

정착 후 `자동 매칭 단계`를 누르면 현재 매칭을 제거하고 새 파워 생성·상자 피해를 처리한 뒤 낙하 대기로 돌아간다. `낙하·공급 실행`과 번갈아 눌러 중간 상태를 살펴볼 수 있다. 효과 처리 후 `연쇄 끝까지`를 누르면 이 단계를 자동 반복한다. 실행 중 같은 버튼을 누르면 현재 완료한 단계에서 중지한다.

연쇄가 끝나고 지원 가능한 행동이 남아 있으면 `다음 행동 대기`가 된다. 다시 칸을 선택해 교환하거나 청소로켓·달폭탄을 발동할 수 있다. 오른쪽에서 이번 수의 연쇄 회차·선택 패턴·생성 위치·효과·이동/공급 요약·난수를 확인하며, 칸 상세에는 현재 내구도와 공급 커서가 표시된다.

마지막 수에서도 연쇄는 처리하지만 승패는 판정하지 않는다. 수 소진, 재배치 필요, 지원 가능한 행동 없음은 서로 다른 안내로 표시한다. 미지원 효과나 처리 한도 실패 시 마지막 성공 단계가 남으며, 실패한 단계의 일부 결과를 적용하지 않는다. 원본·레벨·시드·구성 모드 변경, 초기화, 창 종료 시 실행 예약을 해제한다.

현재 지원 대상은 일반 블록의 매칭, 청소로켓·달폭탄 발동, 나무상자와 기존 이동/기본 공급이다. 수거드론·무지개 자석은 생성과 낙하만 가능하며 직접/피격 발동과 조합은 미지원이다. 미션·승패·자동 재배치·추가 장애물·봇은 후속 범위다. [13단계 개발 목표](37_13단계_개발목표.md)에 구현과 검증 결과를 기록한다.
