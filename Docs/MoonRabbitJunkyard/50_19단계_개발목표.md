## Goal 목표

현재 Unity 프로젝트의 공통 실행기와 Match 수동 시험에 금고·색깔 자물쇠·대형 폐가전을 구현한다. 인접 매칭의 원래 색·매칭별 타격, 자석 색 제거 예외, 폐가전 반복 피해와 네 칸 동시 제거, 본체별 미션 및 드론의 누적 예약 예측을 정확하게 연결한다. 실제 UI·독립 재현·영향 회귀·완료 조건별 증거와 원본 보존 감사를 완료한다.

## 실행 지침

1. 18단계 완료 감사·최종 소스 해시·현재 코드·Goal부터 확인한다. 계획 시 2,045 PASS/20조건·소스 차이0·활성 Goal 없음을 확인했다. 동일 19단계 Goal이면 재개하고 다른 활성 Goal은 덮어쓰지 않는다.
2. ponytail과 프로젝트 Unity 지침을 적용한다. 이 문서를 지정한 실행 요청은 상세 계획의 범위와 기술 설계안에 대한 실행 승인으로 취급한다.
3. T1→T6 순서로 진행한다. Scripts의 기존 Simulation/Levels/Editor 구성을 사용하고 게임·수동/자동 시험용 규칙을 분리 구현하지 않는다.
4. 종류별 피해 규칙과 미션 기여를 조회/실행에서 공유한다. 매니저는 후보/예약을 관리하며 장애물 규칙을 독점하지 않는다.
5. 금고·자물쇠의 턴당 최대1피해와 폐가전의 개별 타격 최대4/턴 내 반복 피해를 구분한다. 선택되지 않은 매칭 패턴이나 범위 중복으로 추가 피해를 주지 않는다.
6. 자물쇠는 원래 매칭 색과 실제 자석 색 제거를 구분한다. 단순 변환·다른 파워의 옆 블록 제거를 자석 예외로 처리하지 않는다.
7. 폐가전의 실제/예상 피해를 본체별로 계산한다. 네 칸 공유 내구도·전체 제거·먼지 보존·미션1개·다른 칸 예약 및 누적 제거 예측을 함께 검증한다.
8. 실제 Match UI와 독립 Unity 프로세스에서 검증한다. 원본/사본·난수·타격 이력·예약 수명·실패 보존을 비교하고 알고리즘 버전을 기록한다.
9. 발전기/연결 실행·회수·실제 승패/섞기/라스트팡·아이템/부스터·봇/통계/난이도·출시 아트/앱 복구는 제외한다. 망치 입력은 후속 아이템 단계로 남긴다.
10. v4/GUID/meta와 무관 파일을 보존한다. 기대값 변경 이유와 실패 수정, 실제 결과 및 미검증 범위를 기록하고 임시 자원을 정리한다. 세 종류와 아래 조건이 모두 검증되어야 완료다.

- 착수 시 18단계 감사2,045 PASS/20조건과 최종 소스 해시 차이0을 확인했다. `Logs/FixedObstacleVerification/baseline-hashes.json`에 Scripts/Data/기획/Stories/Packages/ProjectSettings 기준을 저장했다. 기존 무관한 Stories 변경은 보존했다.
- 모든 규칙은 기존 `Assets/Scripts/Simulation`에서 처리한다. Editor는 입력/표시, 검증 코드는 `Assets/Scripts/Editor/Levels`에 두었다. 저장 형식 v4, 원본 에셋/GUID/meta, 패키지와 어셈블리 경계는 유지했다.

- 금고와 자물쇠는 본체당 턴1피해, 폐가전은 타격 번호/칸별 중복을 막되 별도 효과와 자동 매칭은 다시 피해를 준다. 작업 사본에 타격 이력을 복사하고 새 턴에 초기화한다.
- 인접 매칭은 변환 전 색을 전달한다. 자석이 일반 블록을 실제 제거한 경우에만 별도 인접 원인으로 자물쇠에 전달한다. 다른 파워 제거·자석 색 변환·숨은 곰팡이·내용물이 남은 거미줄은 이 예외로 손상시키지 않는다.
- 본체 파괴는 같은 ObstacleIndex를 가진 모든 칸을 비우고 미션을1회 집계한다. 먼지와 다른 본체는 유지한다.
- 드론은 다른 칸의 누적 피해로 제거 예정 여부를 계산한다. 목표가 여러 개여도 이미 제거 예정인 본체의 나머지 칸을 다시 예약하지 않는다. 예상 피해 규칙은 ObstacleDamageRules/MissionProgressRules에 두었고 매니저는 결과를 사용한다.
- 버전: `board-action-fixed-obstacles-v9`, `match-resolution-hit-groups-v4`, `power-effects-fixed-obstacles-v7`, `settlement-fixed-obstacles-v6`.

### 수정과 검증 중 발견 사항

- 평탄한 매칭 변경 목록에 타격 번호를 보존해 폐가전의 같은 매칭 중복 피해와 별개 매칭 피해를 구분했다.
- 본체 여러 칸의 예상 피해를 칸별 미션 완료량으로만 더하면 내구도2의 1+1 제거를 놓친다. 본체별로 합산하고 완전 제거 예정 본체의 추가 예약도 막았다.
- 테스트가 내부 Select를 직접 호출해 발생한 초기 컴파일 오류는 기존 Reflection 검사 방식으로 수정했다.
- 폭탄 드론이 주변 칸을 조준하면 범위 일부만 본체에 닿을 수 있으므로, 네 칸 타격 정답 사례는 본체만 조준 후보로 남겼다. 실제 후보가 넓은 혼합 레벨은 별도10조합/UI로 검사했다.
- 예약 요청은 후보 선택 난수를 소비하므로, ‘실제 보드/미션 보존’ 검사와 ‘순수 조회의 난수까지 보존’ 검사를 구분했다.
- 기존 금고 미지원 기대는 지원 범위 확장에 따라 발전기/회수 미션의 실제 미지원 사례로 바꿨다. 후반 실패 사례의 상태 보존 목적은 유지했다.
- 기존 회귀의 PowerEffectVerification.DataChecks가 이미 보충 검사를 호출하므로 중복 호출6개를 제거하고 파워 회귀95개를 다시 실행했다. 이전 단계의 보고서는 덮어쓰지 않았다.

### 사용 방법과 제한

`Match > 초기 보드 확인`에서 금고·자물쇠·폐가전을 배치한 유효 레벨을 선택하고 ‘실행 시험’을 켠다. 교환/제자리 발동 후 단계 버튼 또는 ‘연쇄 끝까지’로 실행한다. 자물쇠는 색과 토끼 번호, 폐가전은 네 칸에 같은 본체 번호와 공유 내구도를 표시한다. 상세 기록에서 타격 번호·피해 전후·예약 예상량과 실제 미션 진행을 구분할 수 있다. 680폭은 버튼 줄바꿈과 보드 스크롤을 사용한다.

19단계는 고정 장애물 세 종류의 공통 실행과 제작용 시험 지원이다. 발전기/연결 실행, 회수, 실제 승패 화면·자동 섞기·라스트팡, 아이템/부스터, 봇/통계/난이도 추천, 출시용 나사/막대 아트와 실제 기기 앱 복구는 후속 범위다. 이번에는 새 패키지·asmdef·게임명 폴더를 만들지 않았다.
